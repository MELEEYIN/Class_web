  • upper_bound（第一个 > x 的位置） —— 第一个 > x 的位置，和 lower_bound 配对使用

两个看起来很不一样的问题，答案是同一个。

  • 问题 A：给 n 个单调不减的数，m 次询问“x 第一次出现在哪个位置”。线性扫一遍是 O(nm)，n = 10⁶、m = 10⁵ 时 10¹¹ 次比较，TLE。
  • 问题 B：求“锯片最高能设到多少米，砍下的木材仍不少于 M”。从 0 逐个高度试是 O(N × maxH)，10⁶ × 4×10⁵ = 4×10¹¹ 次，TLE。

A 的答案是二分查找：有序 ⇒ 每次比较就能排除一半。B 的答案是二分答案：把“求最优”换成“判定可行”，可行的取值是一段连续的区间，而“是否可行”沿大小方向单调 ⇒ 也能每次砍掉一半。两者都是 O(log) 次判断，log₂10⁶ ≈ 20，log₂4×10⁵ ≈ 19。

二分的本质不是“找”，是“排除”：每一次判断都要让你能一次性丢掉一半候选。丢掉一半的前提是——候选是有序的。
例题 · 保龄球洛谷 P1918普及-去洛谷做这题 ↗

有 n 个位置排成一排，第 i 个位置上有 aᵢ 个瓶子。各个位置的瓶子数互不相同。

DL 想打倒恰好 m 个瓶子，就要选一个瓶子数正好是 m 的位置发球。给出 m，输出那个位置的编号；如果没有这样的位置，输出 0。

输入格式：第一行 n（1 ≤ n ≤ 10⁵）；第二行 n 个正整数 aᵢ（1 ≤ aᵢ ≤ 10⁹）；第三行 Q（1 ≤ Q ≤ 10⁵）；接下来 Q 行，每行一个正整数 m（1 ≤ m ≤ 10⁹）。

输出格式：共 Q 行，第 i 行是第 i 次询问的答案，无解输出 0。

输入： 4 3 4 1 2 3 3 4 5 输出： 1 2 0

这题的数组是乱序的，而二分要求有序——于是“先排序”成了第一步，但排序会打乱位置编号，所以还得把原编号一起带着。这种“值 + 原下标”的配对，是二分类题目的常客。先把标准库的两个查找函数彻底看清：它们只差一个符号，语义完全不同。

新函数拆解 · lower_bound（第一个 ≥ x 的位置）
lower_bound(首指针, 尾后指针, x) → 迭代器
组成含义 / 格式要求
首指针 a + 1搜索区间的左端，包含。
尾后指针 a + n + 1右端，不包含。它指向最后一个元素的下一个位置，所以盖住 a[1]..a[n] 要写 a + n + 1，不是 a + n。
x要找的数。要求 [首, 尾) 这段已按 < 排好序（单调不减即可，允许重复）。
返回值指向第一个“≥ x”的元素的迭代器；若区间里所有元素都 < x，返回尾后指针 a+n+1。
转成下标减去首地址就是 1-based 下标：int p = lower_bound(a + 1, a + n + 1, x) - a;，p 的取值是 1..n+1。
判存在两件事都要查：p <= n && a[p] == x。只查前者会把“第一个比 x 大的数”当成 x。
复杂度O(log n)，大约 ⌈log₂n⌉ 次比较，内部只用 operator<，不要求元素互不相同。
最小可运行示例
示例
int a[7] = {0, 1, 2, 2, 2, 5, 7};        // a[1..6] 是数据，a[0] 空着
int p = lower_bound(a + 1, a + 7, 2) - a;   // 第一个 >= 2  ->  p = 2
int q = lower_bound(a + 1, a + 7, 3) - a;   // 第一个 >= 3  ->  q = 5（a[5] = 5）
int r = lower_bound(a + 1, a + 7, 9) - a;   // 全都 < 9     ->  r = 7（尾后）
// r == 7 已经超出 a[6]，所以 a[r] 是越界读！必须先判 r <= 6
注意

lower_bound(a, a + n, x) 漏掉了 a[n]（右端不含）。这是最高频的错。

它不保证找到的是 x，只保证是第一个 ≥ x 的。想确认相等，必须自己再比一次。

新函数拆解 · upper_bound（第一个 > x 的位置）
upper_bound(首指针, 尾后指针, x) → 迭代器
组成含义 / 格式要求
和 lower_bound 的唯一区别把“≥”换成“>”。其余参数、返回值规则、复杂度完全相同。
位置关系两个函数把数组切成三段：[1, lo) 全都 < x，[lo, up) 全都 == x，[up, n] 全都 > x。
数个数up - lo 就是 x 出现的次数，x 不存在时结果是 0，不用额外判断。
判存在lo < up 等价于“x 在数组里”。这是最干净的写法。
x 比所有元素都大两者都返回 n+1。
x 比所有元素都小两者都返回 1。
最小可运行示例
示例
int lo = lower_bound(a + 1, a + n + 1, x) - a;   // 第一个 >= x
int up = upper_bound(a + 1, a + n + 1, x) - a;   // 第一个 >  x

int cnt = up - lo;            // x 出现的次数
bool has = (lo < up);         // x 是否出现
int le  = up - 1;             // 最后一个 <= x 的位置
注意

upper_bound 返回的是“最后一个 x 的后一位”，不是最后一个 x 本身，减 1 才是。

求“最后一个 ≤ x 的位置”用 upper_bound(...) - 1，比 lower_bound 加判断更省事。

例题怎么想：先排序，再在有序数组上二分

两个要求打架。二分查找要求下标递增时数值递增；题目给的 a 却是乱序的。所以第一步只能排序——代价 O(n log n)，n = 10⁵ 时约 1.7×10⁶ 次比较，可以接受。

排序的副作用。排完之后 a[i] 不再对应原来的第 i 个位置。而题目要输出的是原位置，所以必须把“值”和“原位置”绑在一起排：存 pair<值, 原位置>，按值排序，pair 的默认比较正好先比 first。

查找。对每次询问 m，用 lower_bound 找第一个值 ≥ m 的位置 p。题目保证瓶子数互不相同，所以要么 p 处的值正好等于 m（命中），要么根本不存在。

判存在这一步不能省。lower_bound 只保证“第一个 ≥ m”，若所有值都小于 m 它会返回尾后位置；若 p 处的值大于 m，那也不是答案。所以判断必须写成 p < n && v[p].first == m，两个条件缺一不可。

复杂度。排序 O(n log n)，每次询问 O(log n)，总共 O((n + Q) log n) ≈ 2×10⁶ 次比较。若每次询问都从头扫一遍，是 O(nQ) = 10¹⁰，必然 TLE。

为什么不用 map。map 当然能做（都是 O(log n)），但常数大、还要额外存下标；本题用“排序 + 二分”更直接，也顺便练了 lower_bound。

完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> v(n);        // (瓶子数, 原位置 1..n)
    for (int i = 0; i < n; ++i) {
        cin >> v[i].first;
        v[i].second = i + 1;            // 先把原位置记下来，排序后就找不回来了
    }

    sort(v.begin(), v.end());           // pair 默认按 first 排，值互不相同，顺序唯一

    int q;
    cin >> q;
    while (q--) {
        int m;
        cin >> m;
        int p = lower_bound(v.begin(), v.end(), make_pair(m, 0)) - v.begin();   // 第一个 >= m 的位置
        if (p < n && v[p].first == m) cout << v[p].second << "\n";              // 命中
        else                          cout << 0 << "\n";                        // 不存在
    }
    return 0;
}
逐行拆解
代码片段含义与理由
vector<pair<int, int>> v(n);把“值”和“原位置”绑成一个整体。若只排一个 int 数组，排序之后原位置就永久丢失了——这是本题最容易犯的结构性错误。
v[i].second = i + 1;记录原位置，用 1-based。这一行必须写在排序之前。
sort(v.begin(), v.end());pair 的 operator< 先比 first 再比 second，本题 first 互不相同，所以只按值排。若值可能相同，第二关键字就会影响顺序，那时要自己写比较函数。
lower_bound(v.begin(), v.end(), make_pair(m, 0))在有序区间上找第一个不小于 (m, 0) 的元素。make_pair(m, 0) 的 second 取 0 是因为所有位置都 ≥ 1——这样“第一个 first ≥ m 的元素”一定被选中。
- v.begin()迭代器相减得到偏移量。这里判 p < n 用的是 0-based 下标，和 vector 的下标一致。
p < n && v[p].first == m两个条件缺一不可：p < n 防止越界（lower_bound 可能返回尾后位置），first == m 防止把“第一个比 m 大的值”当成答案。
cout << v[p].second输出的是 second（原位置），不是 first、也不是 p。这是本题第二个易错点。
while (q--)询问可能一行一个、也可能挤在一行，用 cin >> 读天然兼容两种格式。

标准库好用，但比赛里经常需要变形：找“最后一个满足条件的”“最小的可行值”“答案在 long long 范围”。这些都得自己写二分。手写二分只有两种正确姿势，先把它们刻下来。

新函数拆解 · 手写二分（两种写法与 mid 取整铁律）
写法 A：while (lo <= hi) 闭区间 + ans 记录 写法 B：while (lo < hi) 半开区间 + 哨兵
组成含义 / 格式要求
写法 A：lo <= hi闭区间。区间里每个下标都可能是答案；lo == hi 时那个位置还没被检查，所以要用 <=。
写法 A：ans = midmid 满足条件，先记下来，再去左半边找“更靠前”的满足者。
写法 B：hi = n + 1半开区间 [lo, hi)。n+1 是“不存在”的哨兵，让答案域多一个合法取值，省掉 ans 变量。
写法 B：hi = midmid 本身可能就是答案，必须保留它，只把右端缩到 mid。
两者共同的：lo = mid + 1mid 一定不满足条件，整个左边（含 mid）都能排除，所以是 +1 不是 mid。
铁律 1更新式里出现 hi = mid（右边不 −1），mid 必须向下取整 (lo+hi)>>1。
铁律 2更新式里出现 lo = mid（左边不 +1），mid 必须向上取整 (lo+hi+1)>>1。
铁律 3两种写法不能混。混用是二分死循环的头号来源，而且它不报错，只是永远不结束。
最小可运行示例
示例
int a[9] = {0, 1, 2, 2, 2, 5, 7, 7, 9};    // a[1..8]

// 写法 B：找第一个 >= 2 的下标
int lo = 1, hi = 8 + 1;                       // 半开区间 [1, 9]
while (lo < hi) {
    int mid = (lo + hi) >> 1;                 // 向下取整
    if (a[mid] >= 2) hi = mid;                // mid 可能是答案，留着（不 -1）
    else             lo = mid + 1;            // mid 不可能是答案，扔掉
}
cout << lo << "\n";                           // 2

// 写法 A：同样的目标，另一种记录方式
int l = 1, r = 8, ans = -1;
while (l <= r) {
    int mid = (l + r) >> 1;
    if (a[mid] >= 2) { ans = mid; r = mid - 1; }
    else               l = mid + 1;
}
cout << ans << "\n";                          // 2
注意

写法 B 里 mid 永远小于 hi，所以 a[mid] 读不到哨兵 a[n+1]，哨兵是安全的。

lo + hi 可能溢出 int：hi 到 2×10⁹ 时两数相加变负数，mid 变负 → 数组越界 RE。改写成 lo + (hi - lo) / 2。

更新式mid 必须循环条件写错的症状
lo = mid + 1; hi = mid;向下 (lo+hi)>>1lo < hi向上取整时 hi = mid 不缩小 → 死循环 TLE
lo = mid; hi = mid - 1;向上 (lo+hi+1)>>1lo < hi向下取整时 lo = mid 不缩小 → 死循环 TLE
lo = mid + 1; hi = mid - 1;两种都对lo <= hi无（最稳的一套）
记法：谁不 ±1，mid 就朝另一边取整。hi = mid 配下取整，lo = mid 配上取整。记不住就统一用 lo = mid + 1 / hi = mid - 1 / while (lo <= hi)，再加一个 ans 变量。

二分查找是在数组上二分；二分答案是在答案的取值上二分。两者的代码骨架一模一样，区别只在于比较的对象：前者比 a[mid] 与 x，后者比 check(mid) 与 true。

  • 答案可枚举：答案是一个整数，且有明确的下界 lo 和上界 hi（或实数区间）。
  • 判定函数 check(v)：只回答“取 v 行不行”，不回答“v 是不是最优”。它必须与题目最优值无关，复杂度 O(n) 或更低。
  • 单调性：v 从小往大，check 的结果必须形如“真真…真假假…假”（或反过来）。只有这样才能用“比较结果”排除一半候选。
  • 收尾：解是“最后一个可行的”还是“第一个可行的”，决定 lo / hi / ans 谁被保留、最后返回谁。
例题 · EKO / 砍树洛谷 P1873普及/提高-去洛谷做这题 ↗

有 N 棵树，第 i 棵高 hᵢ 米。把锯片升到整数高度 H，所有高于 H 的部分被锯下，于是得到 Σ max(0, hᵢ − H) 米木材。求最大的整数 H，使得到的木材至少 M 米。

输入：第一行 N、M（1 ≤ N ≤ 10⁶，1 ≤ M ≤ 2×10⁹）；第二行 N 个整数表示树高（≤ 4×10⁵），保证所有树高之和大于 M。

输出：一行一个整数，即锯片能设置的最大高度。

输入： 4 20 20 15 10 17 输出： 10 （H = 10 时得到 10+5+0+7 = 22 ≥ 20；H = 11 时只有 19）
例题怎么想：先把 check 写出来，再去二分

不要一上来就写二分。先把题目里的“求最值”翻译成一句判断：锯片设成 H 时，木头够不够 M？这一个函数写完，二分部分就是模板。

check 函数：O(n)，与最优值无关
bool ok(int H) {
    long long sum = 0;
    for (int i = 1; i <= n; ++i)
        if (a[i] > H) sum += a[i] - H;   // 只有比锯片高的树贡献木材
    return sum >= M;
}

然后看单调方向：H 越大，每棵树贡献的非负差值越小，总和越小。所以“够 M”这个性质是前半段为真、后半段为假——H 从 0 增大时，先一直可行，某一米开始不可行，而且再也不会变回可行。

题目要最大的可行 H，也就是那个“真区间的右端点”。二分时 mid 可行就说明答案可能是它或者更大，于是 ans = mid 记下来、lo = mid + 1 往右试；mid 不可行就说明 mid 和它右边全废，hi = mid − 1。

复杂度：值域 ≤ 4×10⁵，二分开销 ⌈log₂(4×10⁵)⌉ = 19 次；每次 check 扫 n = 10⁶ 个数，总共 1.9×10⁷ 次加法。朴素枚举 H 是 4×10¹¹ 次，差 4 个数量级。

完整代码
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1000005;
int a[MAXN];
int n;
long long M;

// check(H)：锯片升到 H 米，能不能拿到至少 M 米木材
bool ok(int H) {
    long long sum = 0;
    for (int i = 1; i <= n; ++i) {
        if (a[i] > H) sum += a[i] - H;   // 高过锯片的部分才被锯下
        if (sum >= M) return true;       // 已经够了，后面不用看
    }
    return sum >= M;
}

int main() {
    ios::sync_with_stdio(false);   // 10⁶ 个读入，而且要被扫 19 遍
    cin.tie(nullptr);

    cin >> n >> M;
    int mx = 0;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
        if (a[i] > mx) mx = a[i];
    }

    int lo = 0, hi = mx, ans = 0;      // 答案一定在 [0, mx] 内
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;  // 与 (lo+hi)/2 等价，但不会溢出
        if (ok(mid)) { ans = mid; lo = mid + 1; }   // 可行：记下来，再试着升高
        else         { hi = mid - 1; }              // 不可行：只能降
    }
    cout << ans << "\n";
    return 0;
}
二分答案骨架拆解
代码片段含义与理由
bool ok(int H)判定函数独立成函数。这样二分部分与题目彻底分开，换题只改 ok。
if (a[i] > H) sum += a[i] - H;锯片以上的部分才被锯下。写成 a[i] - H 会把负贡献也算进去。
if (sum >= M) return true;早退。10⁶ × 4×10⁵ 最坏是 4×10¹¹，虽然 long long 装得下，但提前跳出能让 check 平均只扫一小段。
long long sum4×10¹¹ 超过 int 上限 2.1×10⁹。用 int 会溢出成负数，于是 check 永远返回 false，答案恒为 0。

二分查找的 6 种典型错法（含症状）

WA：偶尔少算一个。—— 区间右端写成 a + n，漏掉 a[n]。做“找第一个 ≥ x”时有时看不出问题（后面还有 a[p] == q 兜着），一改成计数 up - lo 就立刻错。凡是 n 个元素都要写 a + n + 1。

RE：随机崩或答案乱。—— 直接解引用返回值。所有元素都 < x 时它等于尾后指针，读它就是越过数组末尾。先判 p <= n。

WA：输出一个位置，正确答案是 −1。—— 只判了 p <= n，没判 a[p] == q。数组里有比 q 大的数时就会漏判。

TLE：程序不结束。—— 手写二分混用了 lo = mid 和 hi = mid - 1，或者 hi = mid 配了向上取整。区间长度不再缩小，循环永远跑。

WA：结果毫无规律。—— 忘了数组必须有序。二分在无序数组上不报错，只是每次都往错的方向排除。

TLE。—— n = 10⁶、m = 10⁵ 却没写 ios::sync_with_stdio(false)。

二分答案的 5 种典型错法（含症状）

WA：答案永远是 0 或上界。—— check 的方向写反了。验证方法：手算 check(lo) 与 check(hi)，确认一个真一个假；如果两个同真假，说明区间或方向错了。

WA：答案恒为 0，且怎么改区间都没用。—— check 里用 int 累加，4×10¹¹ 溢出成负数，于是永远“不够”。这一类 bug 只在最大数据上出现，小样例全过。

WA：总是差 1。—— 返回 lo / hi / ans 选错，或 ans 忘了在可行分支里更新。自查：把区间缩到长度 1，手推一遍 mid、赋值、返回，看是否正好落在答案上。

TLE：卡死不结束。—— while (lo < hi) 里写了 lo = mid 却没配上取整。

数学补给 · 二分为什么只要 log：判定树与不变式

n 个有序元素，每次比较把候选砍成一半：n → n/2 → n/4 → … → 1。需要 k 次使 n/2ᵏ ≤ 1，即 k ≥ log₂n。最坏比较次数精确地是 ⌈log₂(n+1)⌉。

n1010³10⁶10⁹
二分比较次数4102030
线性扫描次数10100010⁶10⁹

这就解释了为什么 n = 10⁶、m = 10⁵ 的查找题必须用二分：10⁵ × 20 = 2×10⁶ 次比较，而线性做法是 10¹¹ 次。

不变式（半开写法的正确性）：循环开始时，真答案一定落在 [lo, hi] 这一段里（把 n+1 当作“不存在”的合法答案）。

  • 若 a[mid] >= x：mid 满足条件，答案 ≤ mid，所以 hi = mid，答案仍在 [lo, mid] 内。
  • 否则 mid 一定不是答案，答案 > mid，所以 lo = mid + 1，答案仍在 [mid+1, hi] 内。
  • 又因为 mid = ⌊(lo+hi)/2⌋ < hi（只要 lo < hi），每次迭代区间长度都严格减小。长度有限且严格递减 ⇒ 必然终止；终止时 lo == hi，而答案还在这个只含一个元素的区间里 ⇒ lo 就是答案。∎

这段证明顺便解释了铁律：如果把 mid 改成上取整，hi = mid 在 hi = lo + 1 时会令 mid = hi，区间长度不减，证明的第三步就失效了——程序表现为死循环。

二分答案的总代价 = O(log(hi − lo) × cost(check))。P1873 是 19 × 10⁶ ≈ 2×10⁷，P1182 是 44 × 10⁵ ≈ 4×10⁶，都在 1 秒的余量内。这也提醒你：check 必须是 O(n) 级别的，如果 check 里再套一层 sort 或二分，复杂度会乘上 log，很可能就过不去了。

单调性是硬前提。形如“真真…真假假…假”的判定才可二分。如果判据是“总和恰好等于 M”，可行集合是散点，二分直接失效，只能枚举或换思路。拿到题先问自己：答案变大时，可行性是一直真然后一直假，还是会来回跳？

实数域：二分实数时不写 while (r - l > eps)，因为浮点误差可能让它永远不结束；固定循环 100 次，区间长度缩到 2⁻¹⁰⁰，精度早就够了。

挑战题 · 数列分段 Section II
洛谷 P1182普及/提高-去洛谷做这题 ↗

给出一个长度为 N 的正整数数列 A₁…AN，要把它分成 M 段（M ≤ N），每段必须连续。设每段内数字之和为 Si，求 max(Si) 的最小值。

输入：第一行两个正整数 N、M；第二行 N 个空格隔开的非负整数 Ai（1 ≤ N ≤ 10⁵，M ≤ N，Ai < 10⁸，答案不超过 10⁹）。

输出：一行一个正整数，即每段和最大值的最小值。

引导性提示（先只看这里）

题目问的是“最大值最小”，这是二分答案最典型的信号。先把“求最小”换成判断：给定一个上限 v，能不能分成不超过 M 段，使每段和都不超过 v？

判定一个 v 是否可行，从左往右贪心即可：能塞进当前段就塞，塞不下就另起一段。这样得到的段数是所有分法里最少的。

v 的取值下界不能随便设：某个 Ai 单独一段都超过 v 时，无论怎么分都不行，所以下界至少是 max(Ai)。

想看思路了？点开完整思路

二分答案 x = “每段和的上限”。问题变成：最小的可行 x 是多少。

check(x)：从左往右扫，cur 记当前段的和。若 cur + Ai ≤ x 就并进去；否则开新段（cnt++，cur = Ai）。最后 cnt ≤ M 就可行。

为什么贪心是最优的：任何合法分法的第一段右端点都不会超过贪心的第一段右端点（贪心尽量往右塞），归纳下去，贪心的段数 ≤ 任何分法的段数。所以“贪心段数 ≤ M”与“存在一种分法不超过 M 段”等价——这就是第 16 节的交换论证。

单调性：x 越大越容易分，check 形如“假假…假真真…真”。要求最小的可行值，所以真的时候 hi = mid（保留 mid），假的时候 lo = mid + 1。

下界 lo = max(Aᵢ)（否则单个元素都装不下），上界 hi = ΣAᵢ（全部塞进一段，一定可行）。答案是 lo 收敛到的位置，O(N log Σ) ≈ 10⁵ × 44 ≈ 4.4×10⁶。

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
int n, m;
long long a[MAXN];

// check(limit)：每段和都不超过 limit 时，最少要分成几段？不超过 m 段就可行
bool ok(long long limit) {
    int cnt = 1;              // 至少一段
    long long cur = 0;        // 当前这一段已经装了多少
    for (int i = 1; i <= n; ++i) {
        if (cur + a[i] <= limit) {
            cur += a[i];      // 塞得下就塞：段数越少越容易满足 "<= m"
        } else {
            ++cnt;            // 塞不下，a[i] 自己开一段
            cur = a[i];       // 注意不是 0，a[i] 已经在这一段里了
            if (cnt > m) return false;   // 段数只会增不会减，提前剪枝
        }
    }
    return cnt <= m;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m;
    long long lo = 0, hi = 0;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
        hi += a[i];              // 上界：全部放进一段，一定可行
        lo = max(lo, a[i]);      // 下界：至少要装得下最大的那个数
    }

    while (lo < hi) {            // 半开写法：答案域 [lo, hi]
        long long mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid;        // 可行：mid 可能就是答案，保留
        else         lo = mid + 1;    // 不可行：mid 及更小全部排除
    }
    cout << lo << "\n";          // 循环结束时 lo == hi == 最小的可行上限
    return 0;
}

挑战 2 · 聪明的质监员
洛谷 P1314提高+去洛谷做这题 ↗

有 n 个矿石，第 i 个的重量是 wᵢ、价值是 vᵢ。另有 m 个区间 [lᵢ, rᵢ] 和一个参数 W。

对第 i 个区间，挑出区间内所有重量 ≥ W 的矿石，记个数为 cntᵢ、价值和为 sumᵢ，该区间的检验值 yᵢ = cntᵢ × sumᵢ；总检验值 y = y₁ + y₂ + … + y_m。

再给定一个标准值 s。请你选一个整数 W，使 |y − s| 最小，输出这个最小值。

输入格式：第一行三个整数 n、m、s（1 ≤ n, m ≤ 2×10⁵，0 ≤ s ≤ 10¹²）；接下来 n 行，每行两个整数 wᵢ、vᵢ（0 ≤ wᵢ, vᵢ ≤ 10⁶）；接下来 m 行，每行两个整数 lᵢ、rᵢ（1 ≤ lᵢ ≤ rᵢ ≤ n）。

输出格式：一行一个整数，表示 |y − s| 的最小值。

样例：取 W = 4 时三个区间的检验值分别是 20、5、0，总检验值 25，|25 − 15| = 10；取 W = 5 时总检验值是 5，|5 − 15| = 10；再大或再小都更差，所以答案是 10。

样例
输入： 5 3 15 1 5 2 5 3 5 4 5 5 5 1 5 2 4 3 3 输出： 10
引导性提示（先只看这里）

W 越大，被选中的矿石越少，y 就越小——这个单调性说明可以二分 W。

但每次“给定 W 求 y”如果对每个区间都扫一遍，是 O(nm)。想想第 18 节的前缀和：能不能 O(n) 预处理、O(1) 取一个区间？

注意有两个量要同时求和：个数 cnt 与价值和 sum。开两个前缀和数组分别维护。

想看思路了？点开完整思路

第一步：单调性。固定 W，条件“wᵢ ≥ W”随 W 增大越来越难满足，所以 cntᵢ、sumᵢ 都不增，从而 y(W) 单调不增。于是 y 与 s 的大小关系只有一个分界点，可以二分。

第二步：O(n + m) 求 y(W)。对给定的 W 扫一遍矿石，把“满足 wᵢ ≥ W”的位置记 1：

{'kind': 'list', 'ordered': False, 'items': ['cnt[i] = cnt[i−1] + (w[i] ≥ W) —— 前缀个数；', 'sum[i] = sum[i−1] + (w[i] ≥ W ? v[i] : 0) —— 前缀价值和。']}

然后每个区间 O(1) 取值：c = cnt[r] − cnt[l−1]、t = sum[r] − sum[l−1]，累加 c × t 就是 y(W)。

第三步：二分找分界点。找最小的满足 y(W) ≤ s 的 W（记作 W*）。因为 y 单调不增，最接近 s 的答案只可能出现在 W* 与 W*−1 这两处，各算一次取较小的 |y − s|。

为什么只看这两个 W。W < W* 时 y > s 且随 W 增大而减小，所以 W*−1 是“y 仍大于 s”的那一侧里最接近的；W ≥ W* 时 y ≤ s 且随 W 增大而减小，所以 W* 是这一侧里最接近的。两侧各取端点即可。

量级与类型。cnt ≤ 2×10⁵，sum ≤ 2×10⁵ × 10⁶ = 2×10¹¹，相乘到 4×10¹⁶，再乘 m 会更大——必须全程 long long。s ≤ 10¹²，所以差值也可能很大。

复杂度。每次判定 O(n + m) = 4×10⁵，二分约 log₂(10⁶) ≈ 20 次，总计 8×10⁶，1 秒内完成。若每次判定都三分量暴力，是 O(nm) = 4×10¹⁰，必超时。

    long long y = 0;
    for (int i = 1; i <= m; ++i) {
        long long c = cnt[R[i]] - cnt[L[i] - 1];
        long long t = sumv[R[i]] - sumv[L[i] - 1];
        y += c * t;                     // 每个区间的检验值
    }
    return y;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m >> s;
    long long maxw = 0;
    for (int i = 1; i <= n; ++i) { cin >> w[i] >> v[i]; maxw = max(maxw, w[i]); }
    for (int i = 1; i <= m; ++i) cin >> L[i] >> R[i];

    // 找最小的 W 使 y(W) <= s
    int lo = 0, hi = (int)maxw + 1;
    while (lo < hi) {
        int mid = (lo + hi) / 2;
        if (calc(mid) <= s) hi = mid;
        else                lo = mid + 1;
    }

    long long ans = llabs(calc(lo) - s);                 // 分界点这一侧
    if (lo > 0) ans = min(ans, llabs(calc(lo - 1) - s)); // 另一侧
    cout << ans << "\n";
    return 0;
}
关键片段拆解
片段作用
long long cnt[], sumv[];两个前缀和数组。cnt 最大 2×10⁵，sumv 最大 2×10¹¹，所以 sumv 必须是 long long。
for (int i = 1; i <= n; ++i) { cnt[i] = cnt[i-1] + (take ? 1 : 0); ... }一次扫描同时算两个前缀和。判定条件 w[i] >= W 只算一次，避免重复比较。
long long c = cnt[R[i]] - cnt[L[i] - 1];区间和公式：前缀 [1, R] 减去前缀 [1, L−1]。注意是 L−1，写成 L 会多算一个元素。
y += c * t;每个区间的检验值 = 个数 × 价值和。两个数都是 long long，乘积不会溢出。
int lo = 0, hi = maxw + 1;W 的取值区间。hi 取 maxw+1 覆盖“一个矿石都不选”的情况（此时 y = 0）。
if (calc(mid) <= s) hi = mid; else lo = mid + 1;找“最小的满足 y ≤ s 的 W”。因为 y 单调不增，这个判定天然二分。
long long ans = llabs(calc(lo) - s);分界点本身。用 llabs 而不是 abs：参数是 long long，abs 可能只处理 int。
if (lo > 0) ans = min(ans, llabs(calc(lo - 1) - s));另一侧的端点。最接近 s 的答案一定在这两点之中，不必再枚举其他 W。
这题最容易错的地方
  • 前缀和用 int：sumv 到 2×10¹¹，直接溢出成负数，答案随机。
  • 区间取值写成 cnt[R] - cnt[L]：把 l 这个元素漏掉了，区间整体右移一格。
  • 只算分界点 W* 一侧：最接近 s 的可能在另一侧，答案偏大。
  • 把二分写成“找最大的 W 使 y ≥ s”：方向反了，边界处理容易错一个；写完之后一定要手算小数据验证。
