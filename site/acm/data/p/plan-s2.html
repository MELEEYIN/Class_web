这一章不教算法，教的是做算法题的肌肉记忆。很多人卡在入门，不是因为算法难，而是因为：不会估复杂度、不会调试、不知道自己在写什么。先把这五件事做完，后面每一章都会省力。

2.1 评测机制：你交上去的代码经历了什么

入门★★★★打地基

你把代码提交到洛谷，评测机会做这几件事：

  1. 编译：用固定的编译选项（通常是 g++ -O2 -std=c++14 或 c++17）编译你的代码。
  2. 逐点运行：把每组的输入文件喂给你的程序，拿走它输出的结果。
  3. 比对：把输出和标准答案逐字节比对（注意：多一个空格、少一个换行都算错）。
  4. 给出结论：下面是你会遇到的 8 种结果。
结果全称含义最常见的 3 个原因
ACAccepted通过—
WAWrong Answer答案错边界没判、多测没清空、取模漏了
TLETime Limit Exceeded超时复杂度算错、用了 endl、没关同步
MLEMemory Limit Exceeded超内存数组开太大（二维数组！）
RERuntime Error运行时错误数组越界、除零、爆栈、sqrt 负数
CECompile Error编译错误漏分号、变量名错、评测机 C++ 版本低
OLEOutput Limit Exceeded输出太多死循环里在输出
PEPresentation Error格式错误行末多了空格（部分评测机归入 WA）
💡 提示

本机测试 ≠ 评测结果。 你的电脑快、编译器新、栈大；评测机慢、编译器老、栈小。所以「本地过样例」只说明语法没错，不代表能过。

✅ 小结

先看结果类型，再定位问题。WA 查逻辑，TLE 查复杂度，RE 查越界——不同结果对应完全不同的排查方向。

2.2 复杂度分析：一分钟算出「能不能过」

入门★★★★打地基

复杂度分析不是数学，是手感。它要回答的唯一问题是：给我 n 的范围，我能不能在 1 秒内跑完？

第一步：只数循环和递归，不算具体指令

这里总共跑了 n× n = n^2 次，写作 O(n^2)。里面那句 sum += a[i][j] 是 1 次还是 3 次运算，不重要——因为 n 翻倍时总运算是 4 倍，跟系数无关。

第二步：只保留最高阶

O(3n^2 + 100n + 5000) = O(n^2)

理由：n 足够大时，n^2 会碾压所有低阶项。大 O 记号只看「涨得快不快」，不看具体是几倍。

第三步：跟 1 秒的运算上限对表

C++ 在 1 秒内大约能做 10^8 次简单运算（加减、比较、数组访问）。所以：

  • n = 10^5 时，O(n^2) 是 10^10 次 → 必然超时，必须换 O(nlog n)。
  • n = 10^5 时，O(nlog n) approx 1.7×10^6 次 → 很轻松。
⚠️ 注意

这条经验最重要：看到「两重循环跑 10^5」的题面，立刻放弃暴力方向，不要先写着试试。

六种最常见的循环形状

形状典型代码复杂度
单层线性for (i = 1; i <= n; ++i)O(n)
双层嵌套for (i) for (j)O(n^2)
每层折半for (i = n; i; i >>= 1)O(log n)
外层 n + 内层 logfor (i) { sort(...) }O(nlog n)
定长窗口for (i) for (j = i; j < i + k; ++j)（k 常数）O(nk) = O(n)

💡 提示

均摊分析：双指针的 while 看似嵌在 for 里像是 O(n^2)，但左指针 l 总共只右移 n 次，所以总步数是 2n——这就是「每个元素最多进出一次」的均摊思想。后面单调栈、单调队列、并查集全都靠它。

✅ 小结

先把 n 除以 10^8 得到预算，再数你的循环层数。 这一步要练到比想解法还快。

2.5 对拍：用随机数据证明自己是对的

入门★★★★打地基

为什么必须要对拍

「样例过了」什么都说明不了——样例通常只有一两组，而一道题的测试点有 20 组，专挑你没想到的边界。对拍是竞赛中唯一可靠的验证手段。

三份代码

  1. std.exe（正解）：你写的算法。
  2. brute.exe（暴力）：一个肯定对但很慢的版本（比如 O(n^2) 枚举所有情况）。它必须简单到你不会写错。
  3. gen.exe（生成器）：随机造数据。
💡 提示

rand() 最大只到 32767！要更大的随机数，写 (rand() << 15 | rand()) % MOD，或者用 mt19937：

``cpp mt19937 rng(time(0)); int x = rng() % 1000000; // 0 ~ 999999 ``

一键循环对拍（Windows）

新建 check.bat，和三个 exe 放在同一目录：

运行后它会一直跑，一旦两份输出不同就停下来，并把出错的数据留在 in.txt 里——直接拿这份数据单步调试，bug 立刻现形。

有了 bug 数据之后怎么用

把 in.txt 缩小一点（比如把 n 从 10 改成 3），再分别跑 brute 和 std，用第 1.15 节的「输出中间变量」看哪一步开始分叉。

✅ 小结

对拍 = 让程序自己告诉你哪里错了。 学会它，你的调试效率会提升一个数量级。

入门★★★★打地基

把「玄学错误」变成「查表」。评测机给的结果只有几种，每一种背后的原因都非常固定。

现象最可能的原因一行修复
小数据对，大数据错数组开小了上界 +5，线段树开 4n
部分点错，答案偏小int 溢出加 1LL *，答案用 long long
答案差 1边界含不含写反了画数轴，标清开闭区间
多测全错，单测对没清空全局数组每组开头 memset 或重新赋值
编译过但 RE数组越界 / 除零 / 爆栈开 -fsanitize=address 重跑
RE 且数据不大递归太深爆栈改迭代，或加 -Wl,--stack=268435456
TLE 但算法看着对常数太大换 '\n'、关同步、少用 STL
TLE 且数据小死循环检查 while 的终止条件是否会变
浮点题答案差一点判等方式错改成 fabs(a-b) < 1e-9
字符串题莫名 WA用了 s.size()-1转 (int)s.size() - 1
死循环 / 输出爆炸队列里重复入队标记访问的时机放对（入队时标记）
答案负数取模减法溢出(x % M + M) % M

三个「看起来没问题」的经典坑

  1. memset(a, 1, sizeof a) 不是把数组填成 1，而是把每个字节填成 0x01，得到 16843009。填 0 用 memset(a, 0, sizeof a)，填 -1 用 memset(a, -1, sizeof a)，其他值老老实实写循环。
  2. if (a & 1 == 1) 会被解析成 a & (1 == 1)，等于 a & 1——恰好正确，但 if (a & 2 == 2) 就完全错了。位运算一律加括号。
  3. while (cin >> n) 在本地手输数据时永远不结束，因为 Ctrl+Z 之前它一直在等输入。这是正常现象，不是 bug。
✅ 小结

错误是有限的，见一次记一次。 建议建一个自己的「错误字典」，把每次踩的坑记成「现象 → 原因 → 一行修复」。

2.7 离散化：把「很大的数」压成「很小的下标」

入门★★★★打地基

本质：当数值很大（比如到 10^9）但个数很少（比如 10^5）时，我们只关心它们的相对大小，不关心具体是多少。把「排序去重后的排名」当作新下标，值域就从 10^9 缩到 n。

🎨 生活类比

全班 50 个人的月考分数是 623、487、591……这些数字没法当数组下标。但你只关心「谁第几」——把分数换成名次 1、2、3，50 个格子就够了。

三步模板

什么时候必须用它

  • 树状数组 / 线段树的下标：结构大小取决于值域，10^9 开不下，必须先离散化。
  • 坐标压缩：平面几何里只保留关键坐标（端点、端点 ±1），把空间压到 O(n)。
  • 统计排名、逆序对、区间第 k 小。
⚠️ 注意

离散化之后只保留相对大小关系。如果要还原原值，b[a[i]] 就是答案。
