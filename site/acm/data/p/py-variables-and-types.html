  • 说出 0.1 + 0.2 不等于 0.3 的原因，并在需要精确时改用 Decimal；

3.1 变量是名字，不是盒子

C++ 里 int a = 1; int b = a; 会在栈上开出两块 4 字节，改 b 永远碰不到 a。Python 完全不是这样：赋值语句 b = a 只做一件事——在命名空间里记录"名字 b 指向对象 a 所指的那个对象"。

>>> a = [1, 2]
>>> b = a                 # b 是 a 的别名，不是副本
>>> b.append(3)
>>> a
[1, 2, 3]
>>> a is b
True

is 判断两个名字是不是同一个对象（比的是 id），== 判断内容是否相等。上面两次 append 只有一次真正发生，因为 a 和 b 根本就是同一个列表。

不可变对象看起来"安全"，其实原理一样，只是没人能改它：

>>> x = 10
>>> y = x
>>> y += 1                # int 不可变，+= 实际上是造了个新对象 11
>>> x, y
(10, 11)

所以判断影响的规则只有一条：改的是"对象的内容"还是"名字的指向"。

add_item 改了调用方的列表，rebind 没改——因为 lst = lst + ["新"] 只是让函数内部的这个名字改贴新对象，外面那个列表连碰都没被碰到。这是 Python 传参的全部机制，叫「按对象引用传递」：传的是名字所指的对象，不是对象副本。

把 Python 的参数当 C++ 的 & 引用：x = x + [1] 不会影响调用方，x.append(1) 会。想改调用方，要么原地改，要么 return 回去再赋给原变量。

3.2 六个内置类型先认清

type() 返回类型对象，isinstance() 判断"是不是这一类（含子类）"：

>>> type(42), type(4.2), type("4"), type(True), type(None)
(<class 'int'>, <class 'float'>, <class 'str'>, <class 'bool'>, <class 'NoneType'>)
>>> isinstance(True, int), isinstance(42, float)
(True, False)
类型 字面量 可变性 典型用途
int42、0xff、0b1010、1_000_000不可变计数、编号、大整数运算
float3.14、1e-5、float("inf")不可变物理量、概率、近似计算
boolTrue、False不可变条件、开关、sum() 计数
str'a'、"a"、f"{x}"不可变文本、路径、输出
NoneTypeNone不可变"没有值"的哨兵
complex1+2j不可变很少用，了解即可

数值类型之间会自动提升：int 混进 float 运算就变 float，bool 混进 int 就当 0/1。字符串不会自动变数字，"1" + 1 直接 TypeError。

3.3 整数：没有溢出，但有代价

C++ 的 int 32 位、long long 64 位，1e18 * 1e18 溢出成垃圾值；Python 的 int 用变长数组存，永远不会溢出，代价是大数运算变慢（内部按 30 位一"段"做长乘法）。

>>> 2 ** 100
1267650600228229401496703205376
>>> len(str(2 ** 200))
61
>>> 10 ** 30 // 7
142857142857142857142857142857

竞赛里 n ≤ 10^5 的阶乘、a^b mod p 直接算就行，不用手写高精度。唯一的硬限制是 3.11 起，str() 一个超过 4300 位的整数会抛 ValueError（防止有人拿 2**100000000 做 DoS），需要时先 sys.set_int_max_str_digits(0)。

最后两行是个高频陷阱：4 / 2 是 2.0 而不是 2。/ 永远返回 float，要整数结果必须写 //。

3.4 浮点：为什么 0.1 + 0.2 != 0.3

float 是 IEEE-754 双精度：1 位符号、11 位指数、52 位尾数，等价于 m / 2^k 形式的二进制小数。而 0.1 在二进制里是无限循环小数，只能截断存储，于是误差在加法里累积：

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> f"{0.1 + 0.2:.20f}"
'0.30000000000000004441'
>>> abs((0.1 + 0.2) - 0.3) < 1e-9        # 正确姿势：比误差
True

两条工程结论：

  1. 永远不要用 == 比较两个算出来的浮点数，用 abs(a - b) < eps（math.isclose(a, b) 更稳，它按相对误差判断）；
  2. 金额、分数这类必须精确的场景，用 Decimal（十进制）或 Fraction（有理数），并且 Decimal 一定要用字符串构造。
>>> from decimal import Decimal
>>> Decimal("0.1") + Decimal("0.2")
Decimal('0.3')
>>> Decimal(0.1)                        # 传 float 会把误差原样带进来
Decimal('0.1000000000000000055511151231257827021181583404541015625')
>>> from fractions import Fraction
>>> Fraction(1, 3) + Fraction(1, 6)
Fraction(1, 2)

顺带记住两个数：2**53 = 9007199254740992 是 float 能精确表示连续整数的上界，超过它相邻整数就共用同一个 float；round() 用的是"银行家舍入"（.5 取偶），所以 round(2.675, 2) 得 2.67，round(0.5) 得 0、round(1.5) 得 2。竞赛判题输出浮点通常要求 %.2f 或误差 ≤ 1e-6，正是为了绕开这些。

3.5 bool 是 int 的子类

True 就是 1，False 就是 0，bool 继承自 int。这带来一个实用技巧——布尔值求和就是计数：

>>> True + True
2
>>> sum([True, False, True, True])
3

但它也埋了坑：isinstance(True, int) 是 True，所以 1 == True、0 == False 都成立，{1: "a"}[True] 能取到 "a"。做"类型严格相等"判断时要用 type(x) is bool。

3.6 可变与不可变：决定"多个名字"会不会互相影响

类别 类型 能否原地改
不可变int float bool str tuple frozenset bytes None不能，任何"修改"都产生新对象
可变list dict set bytearray、绝大多数自定义类实例能，改的是同一块内存

不可变带来两个直接后果：可以作字典的键、可以放进集合（因为哈希值不会变），以及在函数里"改"它其实改不到调用方。

>>> {(1, 2): "点", "x": 1}[(1, 2)]
'点'
>>> d = {}
>>> try:
...     d[[1, 2]] = "线"
... except TypeError as e:
...     print(type(e).__name__, e)
TypeError cannot use 'list' as a dict key (unhashable type: 'list')

上面的 TypeError: unhashable type: 'list' 是新手最常见的报错之一，根因就是 list 可变、没有稳定哈希。把键换成 tuple(lst) 即可。

元组本身不可变，但里面装的若是可变对象，那个对象仍然能被改：

>>> t = (1, [2, 3])
>>> t[0] = 9
Traceback (most recent call last):
    ...
TypeError: 'tuple' object does not support item assignment
>>> t[1].append(9)
>>> t
(1, [2, 3, 9])

"不可变"约束的是这一层的引用关系，不是递归的深不可变。理解这一点，tuple 能不能当 dict 键就有了判断标准：(1, [2]) 不可哈希，(1, (2, 3)) 可以。

3.7 浅拷贝、深拷贝，与 [[0] * 3] * 3

b = a 是别名；a[:]、list(a)、a.copy()、copy.copy(a) 是浅拷贝：只复制最外层容器，里面的元素仍是共享的。copy.deepcopy(a) 才递归复制到底。

# 示例：examples/ch03_03_copy.py 的运行结果（完整源码见该文件）

看第一组：b[1].append(99) 之后 a 的内层列表也变成了 [2, 3, 99]，因为浅拷贝只复制了"指向内层列表的那根指针"。c 保持干净，因为 deepcopy 连内层一起复制了。再看最后两行：[[0] * 3] * 3 里三个"行"是同一个列表对象（乘法复制的是引用），改一行等于改三行；用推导式逐行新建才对。

二维数组/矩阵一律用 [[0] * m for _ in range(n)]。[[0] * m] * n 是 Python 教程里最高频的 bug 模板，判题时表现为"改了一个格子，一整列都变了"。

3.8 None：一个专门表示"没有"的对象

None 是 NoneType 的唯一实例，表示"这里没有值"。它不是 0、""、False，也不等于空容器。所有比较里只有 is None 是对的：

>>> x = None
>>> x is None
True
>>> not x
True
>>> x == 0
False

判断"函数有没有返回值/有没有找到"时，用 is None 而不是 == None：前者比 id（永远 O(1)），后者会调用可能被重载的 __eq__，而且 flake8 会直接报 E711。

>>> def find(xs, target):
...     for i, v in enumerate(xs):
...         if v == target:
...             return i
...     return None
>>> idx = find([3, 1, 4], 9)
>>> print(idx is None)
True
>>> print(idx == 0)          # 用索引真假判断的经典翻车点
False

如果 find 返回 0（第一个位置就命中），if not idx: 会把"找到了"误判成"没找到"。返回索引、又可能返回"没找到"时，一律 is None 判断，或者干脆用 if idx is not None:。

3.9 类型转换与真值判断

要记住的真值规则：空即假——0、0.0、""、[]、{}、()、set()、None 全为 False，其余为真。两个反直觉点：字符串 "0" 和 "False" 是非空字符串，真值为 True；-1 也是真值。

转换的坑集中在 int()：它只认"整数字面量"，int("3.5") 抛 ValueError，要先 int(float("3.5"))；int(3.99) 是截断（向零取整，得 3），而 int(-3.99) 得 -3，不是 C 语言里某些实现的向下取整。

bool("False") 是 True。从配置文件/命令行读到的 "False"、"0"、"no" 必须显式映射：s.strip().lower() in {"1", "true", "yes", "on"}。

3.13 练习

1.（预测输出） 不运行，写出结果，再跑一遍核对：

a = [1, 2, 3]
b = a
b += [4]
c = a[:]
c += [5]
print(a, b, c)

验收：能解释为什么 a 和 b 都变成 [1, 2, 3, 4]，而 c 是 [1, 2, 3, 4, 5]（提示：+= 对 list 走 __iadd__，是原地扩展）。

2.（修 bug） 下面代码本意是造一个 3×3 的零矩阵，然后把主对角线设为 1，但输出全错：

g = [[0] * 3] * 3
for i in range(3):
    g[i][i] = 1
print(g)

验收：改成正确写法，输出

[[1, 0, 0], [0, 1, 0], [0, 0, 1]]

3.（判断同一性） 写一个函数 same_object(a, b) -> bool，判断两个列表是不是同一个对象，并说明为什么不能用 == 代替。

验收：same_object(x, x) 为 True，same_object([1], [1]) 为 False。

4.（精确计算） 用 Decimal 计算 0.1 + 0.2、1.1 * 3，输出必须是 0.3 和 3.3；再打印 Decimal(0.1) 看看直接传 float 会带进什么。

验收：两个结果分别为 Decimal('0.3')、Decimal('3.3')，并能说出为什么必须用字符串构造。

5.（挑战） 实现 safe_int(s) -> int | None：接受 "42"、" 7 "、"3.9"（截断为 3）、"1e3"（1000），非法输入返回 None 而不抛异常。

验收：safe_int("3.9") == 3、safe_int("1e3") == 1000、safe_int("abc") is None、safe_int(None) is None，且全程不产生未捕获异常。

3.14 小结

  1. 变量是名字，赋值是贴标签：b = a 不复制数据，只有"改内容"才互相影响，"换指向"不影响别人。
  2. 可变性决定一切：list/dict/set 可变且共享，int/str/tuple 不可变所以安全；要独立副本就明确写 .copy() 或 deepcopy()。
  3. 数值要认清边界：int 不溢出、/ 返回 float、浮点不能用 == 比、要精确就 Decimal("0.1")。
