4.1 算术运算符：四种除法

>>> 7 / 2, 7 // 2, 7 % 2, divmod(7, 2)
(3.5, 3, 1, (3, 1))
>>> -7 // 2, -7 % 2, divmod(-7, 2)
(-4, 1, (-4, 1))
  • / 是真除法，永远返回 float，4 / 2 得 2.0（第 03 章强调过）；
  • // 是向下取整除法（floor），不是"截断"：-7 // 2 是 -4，不是 C 语言的 -3；
  • % 的结果符号跟除数一致：-7 % 3 == 2、7 % -3 == -2。所以 x % n 在 n > 0 时永远落在 [0, n)，这个性质让 % 成为环形下标、哈希、日期计算的可靠工具；
  • divmod(a, b) 一次给出 (a // b, a % b)，永不破坏 a == b * (a // b) + (a % b) 这条恒等式。
>>> -7 % 3, 7 % -3, 7 % 3
(2, -2, 1)
>>> 2 ** 3 ** 2
512
>>> 10 ** -2
0.01
>>> 7.0 // 2
3.0

** 是右结合：2 ** 3 ** 2 等于 2 ** 9。负指数给出浮点结果。// 只要有一个操作数是浮点，结果就是浮点。

两个细节值得记住：0 <= x <= 4 == 4 是链式比较，等价于 0 <= x and x <= 4 and 4 == 4，所以它不报错反而为真——链式比较里 == 和 < 可以混写，但可读性差，别这么写；1 << 2 + 3 得 32 而不是 20，因为算术运算符优先级高于移位，这种地方一律加括号。

4.2 and / or 返回操作数，不是布尔值

这是 C++ 程序员最容易翻车的一条：C++ 的 &&/|| 产出 bool，Python 的 and/or 产出决定结果的那个操作数。

>>> 0 or "默认值"
'默认值'
>>> 3 and 0
0
>>> 2 and 3
3
>>> not []
True

规则：

  • a and b：a 为假就返回 a，否则返回 b；
  • a or b：a 为真就返回 a，否则返回 b；
  • 两者都是短路的：右边可能根本不执行。

注意 check(-1) and check(9) and check(7) 只打印了一次 调用 check：第一个是假，后面两个被短路掉了。这就是 if 列表 and 列表[0] > 0: 之所以安全的原因。

两个实用模式：

  • 默认值：config.get("level") or "info"——但小心 0、""、False 也会被当成"没有值"而替换掉，需要区分时用 if x is None；
  • 守卫：name and name.upper()，None 时直接得 None，不会 AttributeError。

or 给默认值会吞掉合法的假值。count = user_input or 0 在 user_input == 0 时没问题；但 volume = config.get("volume") or 100 在用户明确设了 0 时会错误地变成 100。要保留 0，就写 v = config.get("volume"); volume = 100 if v is None else v。

4.3 ==、is、in：三种"相等"

运算符 比什么 典型误用
==值是否相等（走 __eq__）x == None（应 is None）
is是否同一个对象（比 id）a is 256（小整数缓存，随版本变）
in是否包含（走 __contains__）在 list 上做 10^5 次查询——O(n²)
 
>>> a = [1, 2]
>>> b = [1, 2]
>>> a == b, a is b
(True, False)
>>> p = int("256"); q = int("256")
>>> p is q, p == q
(True, True)
>>> r = int("300"); s = int("300")
>>> r is s, r == s
(False, True)

p is q 为真是小整数缓存（-5～256 的对象在解释器启动时就建好并复用）的结果，与"值相等"无关；换成 300 就立刻断言失败。所以永远不要用 is 比较数字，is 只用在三个场景：is None、is True/False（严格比较时）、x is y 判断同一对象。另外从 3.12 起，256 is 256 这种字面量写法会直接给 SyntaxWarning。

in 的复杂度差异必须背下来：

>>> 99999 in list(range(100000))
True
>>> 99999 in set(range(100000))
True

两行结果一样，但前者要逐个比 10 万次，后者一次哈希。n = 10^5 的题目里，if x in 已访问 用 list 就是 10^10 次比较，换 set 就是 10^5 次。

4.4 位运算与标志位

>>> 5 & 3, 5 | 3, 5 ^ 3
(1, 7, 6)
>>> ~5, -8 >> 1
(-6, -4)
>>> 1 << 10
1024
  • ^ 是异或，不是乘方（Python 的乘方是 **）——这是从 C++ 抄代码时的高频笔误；
  • ~x == -x - 1（补码），~5 == -6；
  • >> 对负数是算术右移（保留符号），-8 >> 1 == -4；
  • 位运算优先级低于比较和算术：x & 1 == 0 实际是 x & (1 == 0)，永远为 0。必须写 (x & 1) == 0。

标志位组合的经典写法（权限、状态、选项）：

>>> READ, WRITE, EXEC = 0b001, 0b010, 0b100
>>> perm = READ | WRITE
>>> perm & EXEC
0
>>> bool(perm & READ), bool(perm & EXEC)
(True, False)
>>> perm ^ READ          # 翻转某一位
2

在 Python 里也可以用 set 或 IntFlag 枚举达到同样目的，但位运算省内存、能塞进单个整数存数据库，竞赛里还能做状态压缩 DP。

4.5 增量赋值与解包

关键区别在 b += [3] 与 d = d + [3]：+= 对列表调用 __iadd__（原地 extend），所以 a is b 仍为真；+ 调用 __add__ 造新列表，d 改了指向，c 不受影响。给列表追加元素用 +=/append，给元组"追加"必然是重建。

a, b = b, a 是交换，因为右边先算成一个元组再解包，不存在 C++ swap 那种临时变量问题。

4.6 优先级速查

由高到低（只列常用的）：

**   →   +x -x ~x   →   * / // %   →   + -   →   << >>   →   &   →   ^   →   |   →
== != < <= > >= in, not in, is, is not   →   not   →   and   →   or   →   if-else（三目）→  = += :=

两条硬规矩：

  1. 位运算与比较混用必须加括号：(x & 1) == 0、(a | b) != 0；
  2. not 优先于 and/or，所以 not a and b 是 (not a) and b；想表达"不是（a 且 b）"要写 not (a and b)。

4.9 练习

1.（负数运算） 不用电脑，算出 -9 // 4、-9 % 4、divmod(-9, 4)、9 % -4，然后写代码验证。

验收：四个结果全对，并能用 a == b * (a // b) + (a % b) 自证。

2.（短路） 写 safe_get(d, key, default)：d 可能是 None，也可能是没有该键的 dict，两种情况都返回 default，且不能用 try/except。

验收：safe_get(None, "a", 1) == 1、safe_get({}, "a", 1) == 1、safe_get({"a": 0}, "a", 1) == 0（注意 0 不能被默认值吃掉）。

3.（位运算） 用位运算统计一个非负整数二进制里 1 的个数（不许用 bin().count()）。

验收：popcount(0) == 0、popcount(7) == 3、popcount(1023) == 10。

4.（变式） 实现 toggle(flags, bit) 与 has(flags, bit)：分别翻转某一位、判断某一位是否置位。

验收：has(toggle(0b101, 0b010), 0b010) is True，且 toggle 不修改原值。

5.（挑战） 写一个"运算符优先级自查表"程序：对 8 组表达式（每组含 &、==、<<、not、and、or、三目）打印"按优先级理解的结果"和"加括号后的结果"，两者相同才算通过。

验收：8 组全通过，且程序输出里能看出哪几组不加括号就会算错。

4.10 小结

  1. / 得浮点、// 向下取整、% 跟除数同号，三者由 divmod 统一保证恒等式。
  2. and/or 返回操作数，可用于默认值和短路守卫，但要小心吞掉 0/"" 这类合法假值。
  3. is 比身份、== 比值、in 比包含；in 用在 list 上是 O(n)，大规模查重必须用 set。
