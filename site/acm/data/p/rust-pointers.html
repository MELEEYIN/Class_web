普通引用只能借用，不能“拥有”。当需要共享所有权、堆分配或运行时借用检查时，就用智能指针：Box<T>、Rc<T>、RefCell<T>、Arc<T>。

一、Box：把数据放到堆上

let b = Box::new(5);          // 值在堆上，b 在栈上
println!("{}", *b);           // 解引用

// 典型用途：递归类型（否则大小无法确定）
enum List {
    Cons(i32, Box<List>),
    Nil,
}

二、Rc 与 RefCell

use std::rc::Rc;
use std::cell::RefCell;

let a = Rc::new(RefCell::new(vec![1, 2]));
let b = Rc::clone(&a);        // 引用计数 +1，不是深拷贝
b.borrow_mut().push(3);       // 运行时借用检查
println!("{:?}", a.borrow()); // [1, 2, 3]

println!("{}", Rc::strong_count(&a));   // 2
类型所有权可变性线程安全
Box<T>唯一编译期检查是（T: Send 时）
Rc<T>共享（单线程）不可变否
RefCell<T>唯一运行时检查否
Arc<T>共享（多线程）不可变是
Mutex<T>唯一加锁后可改是

常见组合：Rc<RefCell<T>> 解决单线程下的“多处共享 + 可变”；Arc<Mutex<T>> 是它在线程版的对偶。

三、常见坑

  1. 用 Rc 跨线程：编译直接拒绝（Rc 不是 Send），要换 Arc。
  2. RefCell 运行时 panic：already borrowed，说明同一作用域内同时存在 borrow() 和 borrow_mut()。
  3. 循环引用导致内存泄漏：Rc 计数永不归零，需要 Weak 打破环。
  4. 以为 Rc::clone 是深拷贝：它只增加计数，代价极小。
  5. 在 Mutex 上忘记 lock().unwrap()，拿到的是锁本身而不是数据。

四、小结
