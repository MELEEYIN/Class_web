这一章不写代码也能读完，但它决定你后面少踩多少坑：先搞清楚「计算机由什么组成 → 为什么需要编译器和语言 → C 处在什么位置 → 一行 hello.c 是怎么变成能跑的程序」。读完你应该能回答：为什么 C 语言既“古老”又“通用”，以及编译器版本为什么会让你抄来的代码报错。

一、计算机是怎么跑起来的

把一台电脑拆成两半看：硬件负责“能不能做”，软件负责“做什么”。

层级组成要点
主机 · CPU运算器（ALU）、控制器、寄存器、预取器、MMU运算速度以 ns 计；控制器取指令、运算器算数据；MMU 做虚拟内存映射
主机 · 内存ROM / RAM靠电信号存数据，断电即失；优点是快，缺点是不持久
外设 · 硬盘机械硬盘 / 固态靠磁信号（或闪存电荷）存数据，断电仍在；慢但持久
外设 · 输入输出键盘、鼠标、屏幕、打印机读入 / 写出，是程序和“人”打交道的唯一通道

硬件之上是软件，软件又分两层：系统软件（操作系统）和应用软件。操作系统的本质就是一个程序——它向下提供驱动程序管理硬件，向上给普通用户图形界面、给开发者系统调用（一组可以直接调用的函数）。

C 语言之所以“贴近底层”，是因为它几乎就长在「系统调用 + 内存」这一层：没有虚拟机、没有垃圾回收，你写什么它就执行什么。

二、为什么需要“语言”和“编译器”

CPU 只认识二进制指令（101100110 这种）。人看不懂，CPU 也不想看懂中文。中间必须有一层翻译，这一层就是编译器。

语言是分代的，每一代解决上一代的痛点：

阶段形态解决的问题 / 留下的问题
机器语言纯二进制指令CPU 直接执行，但人几乎无法维护
汇编语言助记符（mov、add）可读了，但不同 CPU 指令集不同，换个平台就要重写
C 语言接近自然语言 + 编译器同一份源码可以在不同平台编译出各自的指令，跨平台
C++ / Java / Python面向对象 / 虚拟机 / 解释器可维护性与工程规模，代价是抽象层更厚

所以有句话叫「机器生汇编，汇编生 B，B 生 C，C 生万物」：C 之后的绝大多数语言，其运行时或解释器本身就是用 C/C++ 写的。

三、C 的来历与标准

1972 年，贝尔实验室的 Dennis Ritchie 在 B 语言的基础上做出了 C，最初是为了重写 UNIX。之后它被广泛移植，各家实现逐渐分裂，于是有了标准化：

标准年份标志性内容
C89 / C901989 / 1990第一个正式标准（ANSI X3.159-1989，ISO 采纳为 C90），两者内容相同
C951995小修订，补宽字符等细节
C991999可变长数组、// 行注释、inline、long long、声明与语句可混写
C112011_Generic、_Static_assert、多线程、匿名结构体
C17 / C182018缺陷修复，不引入新特性
C232023nullptr、constexpr、typeof 等（各编译器支持程度不一）

标准不是强制约束。标准可以理解成“说明书”，但编译器厂商可以不遵守：微软的 MSVC 长期不支持某些 C99 特性，也会自作主张加语法。所以：

  • 你抄来的代码报错，第一嫌疑不是“写错了”，而是编译器版本 / 标准版本不支持；
  • 写之前先确认编译器：gcc --version，编译时显式加 -std=c11 之类的开关；
  • 常见编译器：GCC（Linux 默认，对标准支持最好）、Clang、MSVC（Windows / Visual Studio）、Intel C++、Borland C++（历史产物）。
本教程的所有示例都按 C11 写，用 gcc -std=c11 或 clang -std=c11 编译即可。

四、第一个程序

#include <stdio.h>          // 引入标准输入输出库，printf 的声明在这里

int main(void) {            // 程序入口，操作系统从这里开始执行
    printf("Hello, C!\n");  // \n 是换行，注意是反斜杠
    return 0;               // 返回 0 表示“正常结束”
}

逐行拆开看：

片段含义不写会怎样
#include <stdio.h>预处理指令，把头文件内容原地展开编译器不知道 printf 是什么，C99 起报错
int main(void)唯一的入口函数，返回整型状态码链接器找不到入口，直接失败
{ ... }函数体，语句用分号结尾少一个分号就编译不过
printf(...)格式化输出到标准输出—
return 0;把 0 交给操作系统，Shell 用 echo $? 能看到C99 起 main 默认返回 0，但显式写更好

五、从 .c 到可执行文件

gcc hello.c -o hello 这一条命令，实际做了四件事：

阶段做的事产物
预处理展开 #include、替换 #define、处理条件编译、删注释hello.i（纯 C 源码）
编译语法分析、优化，翻译成汇编hello.s
汇编把汇编翻译成机器指令hello.o（目标文件）
链接把目标文件和库（如 libc）拼起来，解析符号hello（可执行文件）

想亲眼看中间产物，可以分步执行：

gcc -E hello.c -o hello.i   # 只看预处理结果（文件会变得很长）
gcc -S hello.c -o hello.s   # 看生成的汇编
gcc -c hello.c -o hello.o   # 只到目标文件
gcc hello.o -o hello        # 手动链接

理解这四步的直接好处：以后遇到 undefined reference to 'xxx' 就知道是链接阶段缺东西（少写了 -lm、少编译了某个 .c），而 expected ';' 是编译阶段的语法问题——两类错误的排查方向完全不同。

六、常见坑（都是新手第一天会踩的）

  1. 中文标点：； （ “ 这些全角符号在代码里是非法的。报错常指向“莫名其妙的位置”，先怀疑标点。
  2. 忘记 #include <stdio.h>：现代编译器会直接报 implicit declaration of function 'printf'。
  3. 写成 void main()：某些旧教材这么写，但它不是标准形式；用 int main(void)。
  4. 路径 / 编码问题：源文件存成 GBK 而编译器按 UTF-8 读，中文注释会变乱码甚至报错；统一用 UTF-8。
  5. 不看返回值：程序“跑完没输出”时，先看 echo $?（Windows 下 echo %errorlevel%），再检查是不是根本没进 main。

七、小结

这一章的三个结论：① 计算机是「硬件 + 操作系统 + 程序」的三层结构，C 贴着最下面那层；② 语言的价值在于“可读 + 可移植”，编译器负责翻译；③ 标准是说明书不是法律，编译器和版本会决定你的代码能不能过。
