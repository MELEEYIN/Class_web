上一节留了一个尾巴：把 f(n) = f(n-1) + f(n-2) 直接写成递归，求 f(40) 要调用约 3×10⁸ 次。明明只有 40 个状态，为什么算了上亿次？因为 f(1) 被底下每一条分支各算了一遍——这叫重复计算，不是算法慢。

两种治法的方向刚好相反：

  • 记忆化搜索：还是递归，从上往下问，但每算出一个答案就记进表里；第二次问同一个状态，直接查表返回。
  • 递推：干脆从最小的开始往后填，先算 f[1]、f[2]，再拿它们拼出 f[3]……一张表填到底，中间不问任何人。
递归是“从上往下问”，递推是“从下往上填”。记忆化就是给前者配一本备忘录——同一个问题只回答一次。

四张卡：递推的三要素、记忆化的两种写法、滚动数组、卡特兰数。前两张是本节的主干。

>
新函数拆解 · 递推三要素：状态、转移、方向
f[边界] = 初值; // ① 边界 for (int i = 起点; i <= n; ++i) { // ③ 方向：保证用到的状态已经算好 f[i] = g(f[i-1], f[i-2], ...); // ② 转移 } cout << f[n]; // 答案在哪一格
组成含义 / 格式要求
状态 f[i]一句话说得清 f[i] 是什么。说不清就是没设计好，后面的方程一定是错的。例：f[i] = 走到第 i 级台阶的走法数。
转移方程不重不漏地列出 f[i] 的所有来源，再相加或取最值。来源的下标必须更小（或同下标但已算好）。
边界最小下标那几个答案，必须手算给出。漏了边界，f[1] 会去读 f[0]、f[-1] 这些垃圾值。
循环方向只看转移式里最大的下标。依赖 f[<i] 就 i 从小到大；依赖 f[>i] 就倒序；依赖“上一行同一列”就要调整嵌套顺序。写反了不会报错，只会算错，因为用到的还是 0。
答案是哪个是 f[n]，还是 max(f[1..n])，还是 f[n][m]？先写下来，再写输出。
量级先估 f[n] 最大能到多少，再决定 int / long long / 高精度。递推值的增长经常远超直觉。

long long f[50];                    // f[i] = 走到第 i 级台阶的走法数

为什么 i 必须从小到大：f[i] 要读 f[i-1]、f[i-2]，它们必须先算好。倒着写，读到的是数组初值 0，答案会整片变 0。

为什么边界给了两个：转移式同时用到前两项。用到几项就补几个边界，这是硬性对齐关系。

>
新函数拆解 · memo 数组：判断“算过没有”的两种写法
// 写法 A：哨兵值判空 long long f(int n) { if (memo[n]) return memo[n]; // 非哨兵值 = 已经算过 ... return memo[n] = 结果; // 存表 + 返回，一句搞定 } // 写法 B：另开一个 vis 数组专门记账 long long f(int n) { if (vis[n]) return memo[n]; // vis 为真才敢用 memo vis[n] = true; ... return memo[n] = 结果; }
组成含义 / 格式要求
写法 A 的前提任何合法答案都不等于哨兵值。答案恒正时，0 是最省事的哨兵（全局数组默认就是 0）。
写法 B语义最干净：vis[i] 为真就表示 memo[i] 有效，与答案的取值完全无关。代价是多一个 bool 数组，每格 1 字节。
写法 C（哨兵 −1）memset(memo, -1, sizeof memo) 之后判 memo[n] != -1。前提是答案不会是 −1。适合答案可能为 0 的情况。
memset 的硬限制按字节填充，只能填 0 和 −1（全 0 字节是 0，全 1 字节是 −1）。memset(memo, 0x3f, ...) 对 int 得到 0x3f3f3f3f，对 long long 得到 0x3f3f3f3f3f3f3f3f，两者数值天差地别。
return memo[n] = 结果一句做两件事。拆成两行时最容易漏掉存表那句——那时结果仍然正确，但每次都要重算，程序退化成普通递归，从 AC 变 TLE。
为什么快每个状态只算一次。状态数 S 乘单次转移代价 T，总复杂度 O(S·T)，与递归树的形状无关。
最小可运行示例
示例
long long memo[100];                   // 全局数组默认全 0

long long fib(int n) {
    if (n <= 2) return 1;              // 出口
    if (memo[n]) return memo[n];       // 算过 → 查表，O(1)
    return memo[n] = fib(n-1) + fib(n-2);   // 没算过 → 算完存表
}

// 调用次数从 3×10⁸ 降到 80 次以内（每个状态只真正算一次），深度仍然只有 40
注意

记忆化不改变递归的深度，只减少次数。所以它治得了 TLE，治不了爆栈。

状态必须是“参数决定”的。函数里如果有全局变量随调用改变，那 memo 的语义就崩了——同一个参数可能对应不同的答案，这时不能记忆化。

>
新函数拆解 · 滚动数组（把 O(n) 的空间压成 O(1)）
// f[i] 只用前两项 → 两个变量就够 long long a = f0, b = f1; for (int i = 2; i <= n; ++i) { long long c = a + b; // 先算出新值 a = b; b = c; // 再整体往后挪一格 } // 循环结束时 b 就是 f[n]
组成含义 / 格式要求
什么时候能用f[i] 只依赖固定常数个“最近”的项，不依赖更早的任意项。依赖几项就要留几格。
取模下标写法f[i % K]，K = 需要同时记住的项数。依赖前 3 项写 i % 3，是通用写法，K 大时比手写变量清爽。
顺序必须先读旧值、再覆盖。a = b; b = a + b; 这种写法是错的，第二句里的 a 已经被改写过了。
收益空间 O(n) → O(1)。n = 10⁸ 时这一步决定程序是 MLE 还是 AC。
代价历史值全丢，之后没法回答“f[k] 是多少（k < n）”。要输出整张表就不能滚动。
最小可运行示例
示例
// 斐波那契取模：f[1]=1, f[2]=1
long long a = 1, b = 1;
for (int i = 3; i <= n; ++i) { long long c = (a + b) % MOD; a = b; b = c; }
cout << b << "\n";      // b 就是 f[n]

// 依赖前 3 项时的通用写法
long long f[3] = {0, 0, 1};
for (int i = 3; i <= n; ++i) f[i % 3] = f[(i-1) % 3] + f[(i-2) % 3] + f[(i-3) % 3];
注意

f[i % K] 的 K 不能小于依赖的项数：依赖前 2 项就取 K = 2，依赖前 3 项就取 K = 3。之所以读到的是正确的旧值，是因为赋值右边先整体求值——(i-2) % 2 与 i % 2 是同一格，读的仍是覆盖前的内容。K 取小了一定错：依赖 3 项却写 i % 2，有两项会被折叠到同一格上。

滚动数组只是省空间，不改变时间复杂度——该算的 n 步一步都少不了。

f[0] = 1; f[n] = f[0]·f[n-1] + f[1]·f[n-2] + … + f[n-1]·f[0];
组成含义 / 格式要求
前几项1, 1, 2, 5, 14, 42, 132, 429, 1430, 4862, 16796 …（记到 5、14、42 就够用了）。
通项Cₙ = C(2n, n) / (n+1)。要取模时必须用逆元，n 大时不如用一阶递推。
一阶递推Cₙ = Cₙ₋₁ · (4n − 2) / (n + 1)。有除法，取模要用逆元；不取模时要保证整除。
什么时候会撞见n 个元素的出栈序列数、n 对括号的合法匹配数、n 个结点的二叉树形态数、凸 n+2 边形的三角剖分数、网格上不越过对角线的路径数。
增长有多快C₁₈ = 477638700 还装得进 int，C₁₉ = 1767263190，C₂₀ = 6564120420 就已经超出 int。n 一旦到 30 以上，只能靠 long long 或高精度。
复杂度按定义二重循环是 O(n²)，n ≤ 3000 都能过；n 到 10⁵ 必须换成一阶递推 O(n)。
最小可运行示例
示例
long long f[20];                 // 卡特兰数
f[0] = 1;                        // 边界：空序列只有 1 种
for (int i = 1; i < 10; ++i)
    for (int k = 0; k <= i - 1; ++k)
        f[i] += f[k] * f[i - 1 - k];
// f[0..9] = 1 1 2 5 14 42 132 429 1430 4862
注意

卡特兰数的转移是“卷积”：把所有可能的切分点 k 枚举一遍，两边方案数相乘再相加。所以它的循环方向必须是 i 从小到大，且内层枚举 k。

看到“1, 2, 5, 14, 42”这串数就条件反射：这是卡特兰数，别再从头推一遍。

例题 · 过河卒洛谷 P1002普及-去洛谷做这题 ↗

棋盘上 A 点有一个过河卒，坐标为 (0, 0)，要走到 B 点 (n, m)。卒每一步只能向下或向右走一格。

棋盘上 C 点有一匹对方的马，马所在的点和它一步能跳到的 8 个点统称控制点，卒不能经过。马不动，也不按回合走。

输入格式：一行四个正整数，依次是 B 点坐标 (n, m) 和马的坐标 (hx, hy)。

输出格式：一行一个整数，表示从 A 到 B 且不经过控制点的路径条数。

数据范围：1 ≤ n, m ≤ 20，0 ≤ 马的坐标 ≤ 20，保证起点不是控制点。

输入： 6 6 3 3 输出： 6
例题怎么想：把“路径”翻译成“最后一步从哪来”

状态。路径条数没法直接算，但可以按终点拆：定义 f[i][j] = 从 (0,0) 走到 (i,j) 且不经过任何控制点的路径条数。这一句话必须能独立说清，后面每格都只信它。

转移。走到 (i,j) 的最后一步只有两种可能：从上面 (i−1,j) 下来，或从左边 (i,j−1) 过来。这两类路径互不重叠（最后一步不同），合起来又覆盖了全部，所以 f[i][j] = f[i-1][j] + f[i][j-1]。这就是“不重不漏”的直接体现。

边界。f[0][0] = 1：一条路都不走也算一种走法，它是整条递推的地基。第一行只能从左边来、第一列只能从上边来，越界的那一项按 0 处理——代码里写成 i > 0 ? f[i-1][j] : 0，或者干脆把整个棋盘右移一格。

不可用的状态。马的控制点直接取 0。注意这一步必须在转移之前做完：先把 9 个格子标成“禁止”，之后每格照常算，被禁的格子本身是 0，它的贡献自然也是 0。

方向。转移只用到左和上，所以 i、j 都从小到大填。写反的话读到的是还没有值的 0，整张表全 0。

量级。没有马时路径数是 C(n+m, n)：n = m = 16 时 6.0×10⁸，n = m = 17 时 2.33×10⁹ —— 刚好越过 int 上限 2.147×10⁹。本题 n, m 到 20，答案 1.38×10¹¹，必须 long long。

完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

long long f[25][25];        // f[i][j]：从 (0,0) 到 (i,j) 的合法路径数
bool blk[25][25];           // 马的控制点
int dx[9] = {0, -2, -1, 1, 2, 2, 1, -1, -2};   // 马本身 + 8 个跳跃点，dx/dy 必须一一对应
int dy[9] = {0, 1, 2, 2, 1, -1, -2, -2, -1};

int main() {
    int n, m, hx, hy;
    cin >> n >> m >> hx >> hy;

    for (int k = 0; k < 9; ++k) {                 // 先标控制点，再算路径
        int x = hx + dx[k], y = hy + dy[k];
        if (x >= 0 && x <= n && y >= 0 && y <= m) blk[x][y] = true;
    }

    f[0][0] = 1;                                  // 边界：空路径算 1 条
    for (int i = 0; i <= n; ++i)
        for (int j = 0; j <= m; ++j) {
            if ((i == 0 && j == 0) || blk[i][j]) continue;   // 起点已给过值，控制点保持 0
            long long up   = (i > 0 ? f[i - 1][j] : 0);      // 越界的项按 0 算
            long long left = (j > 0 ? f[i][j - 1] : 0);
            f[i][j] = up + left;                             // 最后一步从上或从左
        }

    cout << f[n][m] << "\n";
    return 0;
}
逐行拆解
代码片段含义与理由
long long f[25][25];n, m ≤ 20，下标到 20，开 25 留余量。必须是 long long：n = m = 20 时答案是 1.38×10¹¹。
int dx[9] = {0, -2, ...};第 0 项 (0,0) 就是马自己，后面 8 项是它的跳跃点。dx 与 dy 必须一一对应，写乱一组就会多标或少标一个控制点。
if (x >= 0 && x <= n && y >= 0 && y <= m)马的控制点可能落在棋盘外（比如 hx = 0 时的 −2），落在外面的既不能标也不能越界写。
f[0][0] = 1;边界。写成 0 会让整张表全 0；而“空路径算一条”正是本题递推的起点。
if ((i == 0 && j == 0) || blk[i][j]) continue;两件事一起做：起点不重算；控制点什么都不做，于是它的值保持 0，往下、往右传的都是 0。
long long up = (i > 0 ? f[i - 1][j] : 0);越界项当 0。不写这个判断就会访问 f[-1][j]，C++ 不检查下标，读到的是随机内存。
f[i][j] = up + left;转移式只有两项。注意这里是“相加”而不是“取 max”：题目问方案数，不问最优值。
cout << f[n][m];答案是右下角这一格。i 对应 n（行、向下），j 对应 m（列、向右），读入顺序别写反。

同一个问题换个写法：把“从下往上填”换成“从上往下问 + 备忘录”，对照着看：

记忆化写法（对照）
long long memo[25][25];
bool vis[25][25];

long long dfs(int i, int j) {                 // 从 (0,0) 走到 (i,j) 的方案数
    if (blk[i][j]) return 0;                  // 控制点：一条合法路都走不到
    if (i == 0 && j == 0) return 1;           // 出口
    if (vis[i][j]) return memo[i][j];         // 算过就查表（答案可能是 0，所以另开 vis）
    long long res = 0;
    if (i > 0) res += dfs(i - 1, j);
    if (j > 0) res += dfs(i, j - 1);
    vis[i][j] = true;
    return memo[i][j] = res;                  // 存表 + 返回，一句做完
}
// main 里只写 cout << dfs(n, m);

两版都是 O(nm)，但差别不在速度，在“算了多少”。递推老老实实把 (n+1)×(m+1) 个格子全填一遍；记忆化只展开真正会问到的状态——如果大部分格子被马挡住，它能少算很多。反过来，记忆化的递归深度是 n + m ≤ 40，完全安全；一旦 n + m 到 10⁵，就只能写递推。

还有一个顺手的好处：记忆化的“状态”就是函数参数，改起来比改循环清爽。所以遇到“依赖顺序一眼看不出来”的题（比如只能向上或向右以外的走法），先用记忆化把答案写对，再考虑要不要改成递推。

递推与记忆化的 6 个典型错法（附症状）

WA，答案偏大：只把马自己标成控制点，忘了它的 8 个跳跃点。n = m = 6、马在 (3,3) 时答案会从 6 变成 12。

WA，输出负数：f 用了 int。n = m = 17 时路径数已经是 2.33×10⁹，越过 int 上限，屏幕上出现 −1961361076 这样的数。看到负号先查类型，别先怀疑转移式。

WA，整张表全 0：f[0][0] 没初始化，或者循环方向写成 i、j 从大到小——转移读到的都是还没填的 0。

RE / 莫名的 WA：越界项没处理，直接写 f[i-1][j] + f[i][j-1]。i = 0 时读 f[-1][j]，C++ 不查下标，读到的是随机内存。

RE：控制点标记时没判越界。马在 (0,0) 时 hx - 2 是 −2，写 blk[-2][...] 会踩到数组前面的内存。

WA，只有带马的数据错：把控制点判断写在转移之后。那一格已经被算出非 0 值，禁不掉，后续格子全被污染。

记忆化专属的三个坑

哨兵选错：某个合法答案恰好是 0，而你用 0 当“没算过”。结果是这个状态被反复重算，答案还是对的，只是慢——症状是 TLE 而不自知。改法：换 −1 当哨兵，或改用 vis 数组。

memset 填错：memset(memo, 0x3f, sizeof memo) 对 long long 得到的是 0x3f3f3f3f3f3f3f3f，判 != 0x3f3f3f3f 永远成立，等于没记忆化。判等式的两边必须是同一个值。

把全局变量也当成状态的输入：函数依赖一个会被改动的全局变量，那 memo 里存的就是过期答案。记忆化的前提是“参数相同 ⇒ 答案相同”。

数学补给 · 递推式的解：特征方程、组合通项、量级估算

线性递推可以机械地解出来。以 f[n] = f[n-1] + f[n-2] 为例，假设解是幂函数 f[n] = rⁿ，代入得 rⁿ = rⁿ⁻¹ + rⁿ⁻²，两边同除 rⁿ⁻²，得到特征方程

斐波那契的特征方程
r² = r + 1   即   r² − r − 1 = 0
r₁ = (1 + √5)/2 ≈ 1.618      r₂ = (1 − √5)/2 ≈ −0.618

通解是 f[n] = A·r₁ⁿ + B·r₂ⁿ。用 f[1] = f[2] = 1 定出 A = 1/√5、B = −1/√5，于是

闭式解
f[n] = ( r₁ⁿ − r₂ⁿ ) / √5        // 比内公式

它的用处不是让你去算 φⁿ，而是估量级：|r₂| < 1，所以 f[n] ≈ r₁ⁿ/√5，每项是前一项的 1.618 倍。查一下就知道 f[46] = 1836311903 还能装进 int，f[47] = 2971215073 就超了——这就是“数组该用 long long 还是 int”的第一个定量判据。

再看一个不是线性的例子：卡特兰数 f[n] = Σ f[k]·f[n-1-k]。它带卷积，没有特征方程，通项要从组合数来：Cₙ = (2n)! / (n!(n+1)!)。用斯特林公式 n! ≈ √(2πn)·(n/e)ⁿ 化简得

卡特兰数的增长阶
C_n  ≈  4ⁿ / ( n^(3/2) · √π )

n = 20 时：4²⁰ = 1.0995×10¹²，20^1.5 = 89.44，√π = 1.7725
          1.0995×10¹² / 158.5 ≈ 6.9×10⁹
实际 C₂₀ = 6564120420                       误差 6%

所以 C₁₈ = 477638700 还装得进 int，C₁₉ = 1767263190 也勉强，C₂₀ = 6564120420 就爆了。4ⁿ/n^1.5 这个形状说明它比 2ⁿ 快、比 4ⁿ 慢——凡是“括号匹配”“出栈序列”类的计数，答案都会迅速吃掉整型范围。

举一反三 · 想清楚这些再往下走
先自己写出答案，再点开核对——方向对不对，比答案本身更重要
  1. 上台阶（每步只能跨 1 级或 2 级）和“用 1×2 骨牌铺满 2×n 的棋盘”，答案为什么都是斐波那契？把两个问题的“最后一个动作”写出来对比，你会发现转移方程是同一句话。
    想好了？点开核对思路与解析
    两个问题的“最后一个动作”恰好是同一句话的二分类。上台阶：最后一步要么跨 1 级（前 n−1 级有 f[n−1] 种），要么跨 2 级（f[n−2]）；骨牌：最右边那列要么竖放一块（前 n−1 列 f[n−1] 种），要么横放两块（前 n−2 列 f[n−2] 种）。两类最后一步互不重叠、合起来覆盖全部，所以转移式都是 f[n] = f[n−1] + f[n−2]，边界都是 f[1] = 1、f[2] = 2。常见错路：硬背“骨牌就是斐波那契”——多一种砖（比如正文 P1990 的 L 型砖）转移式立刻就变，必须重新找“最后一个动作”，不能套旧式。
  2. 如果题目要求输出 f[1] 到 f[n] 的每一个值，滚动数组还能用吗？为什么？需要改回什么写法？
    想好了？点开核对思路与解析
    不能保持 O(1)。滚动数组把历史值覆盖掉了，而“输出 f[1] 到 f[n] 的每一个值”要求每个历史值事后都能读到，两者直接冲突；要输出整张表就必须回到“开 f[n] 数组、从小到大填完再输出”的写法，空间 O(n)。唯一的例外是“边算边打”：只是顺序输出、不需要事后回答“f[k] 是多少”时，仍然可以两个变量，算一个打一个。常见错路：题目给的是离线询问（先读完所有询问，每次问某个 f[k]），却还按“边算边打”用滚动变量——这时 f[k] 早被覆盖了，只能开数组。
  3. 卡特兰数按定义算是 O(n²)。若 n = 10⁵ 且要求对 10⁹+7 取模，O(n²) 会 TLE。用一阶递推 Cₙ = Cₙ₋₁·(4n−2)/(n+1) 怎么把它降到 O(n)？那个除法在取模下要怎么处理？
    想好了？点开核对思路与解析
    用一个变量 cur 从 C₀ = 1 递推到 Cₙ：每步 cur = cur * (4n−2) % MOD * inv(n+1) % MOD，O(n) 时间、O(1) 空间。取模下的除法要用逆元：MOD = 10⁹+7 是质数，而 n+1 ≤ 10⁵+1 < MOD 与它互质，所以逆元就是 pow(n+1, MOD−2, MOD)，也可以先 O(n) 递推出 1..n+1 的逆元：inv[i] = MOD − MOD/i * inv[MOD%i] % MOD。为什么不直接用定义：O(n²) 在 n = 10⁵ 时是 10¹⁰，必然 TLE。常见错路：直接写 (4n−2)/(n+1) 的整数除法——模意义下除不了；以及忘了逆元存在的前提是“模数为质数且分母不被它整除”。
  4. 什么样的递推不能用滚动数组？（提示：想想 f[i] 依赖 f[0..i-1] 全部，或者依赖“上一行整行”的情况。）
    想好了？点开核对思路与解析
    三类必须留在整表上：① f[i] 依赖 f[0..i−1] 的全部（卡特兰数的卷积、区间 DP、背包的“上一层整行”）；② 依赖的下标跨度不固定（f[i] 依赖 f[i−k]，k 由输入给出）；③ 答案要整张表而不是最后一格。共同点是“需要的旧值个数不是常数”，而滚动窗口只能装常数个。常见错路：以为二维 DP 压一维就叫滚动——f[i][j] 依赖 f[i−1][j] 与 f[i][j−1] 时，压成一维必须固定遍历方向（0/1 背包倒序），方向反了就是同一行重复使用，答案偏大；另一种是 f[i%K] 的 K 取小，依赖 3 项却写 i%2，两项被折叠到同一格。
  5. 记忆化搜索和递推算的是同一张表，什么情况下只能写记忆化？举一个“状态的依赖顺序不是下标从小到大”的例子。
    想好了？点开核对思路与解析
    两种情形只能写记忆化：① 状态空间里只有一小部分会被问到（稀疏状态），递推要把整张表填满，记忆化只展开真正访问到的；② 依赖顺序不是“下标从小到大”，写不出合法的循环顺序。具体例子：f[i][j] 同时依赖 f[i+1][j] 和 f[i][j−1]（一个往下、一个往左），行优先和列优先都不对；更典型的是图上 DP——状态是图的结点，依赖顺序由图给出，只能按拓扑序或记忆化递归。常见错路：以为记忆化能治爆栈——它只减少调用次数、不减少深度，深度 10⁶ 照样 RE。

挑战题 · 传球游戏
洛谷 P1057普及-去洛谷做这题 ↗

n 个同学站成一个圆圈，其中 1 号同学（小蛮）手里拿着球。每次可以把球传给左右相邻的一个同学。

传了 m 次之后，球又回到 1 号手里的传球方法有多少种？两种方法不同，当且仅当“接到球的同学按接球顺序组成的序列”不同。

输入格式：一行两个整数 n、m（3 ≤ n ≤ 30，1 ≤ m ≤ 30）。

输出格式：一行一个整数，表示方法数。例如 n = 3、m = 3 时只有 1→2→3→1 和 1→3→2→1 两种。

引导性提示（先只看这里）

按“传了几次”分层：传 j 次之后球在谁手里，这个信息足够推出传 j+1 次的情况。

球到 i 号手里的最后一次传球，只能来自它的左邻居或右邻居——这两类来源互不重叠。

圆圈的头尾是连着的：1 号的左邻居是 n 号，n 号的右邻居是 1 号。这两处不处理，边界答案一定是 0。

想看思路了？点开完整思路

状态。f[j][i] = 传了 j 次之后，球在 i 号同学手里的方法数。“传了几次”是阶段，“球在谁手里”是状态，两者合起来才描述得清一个中间局面。

转移。球能到 i 号，只可能是第 j 次传球时由 i 的左邻居 j−1 号传来，或由右邻居传来：f[j][i] = f[j-1][i-1] + f[j-1][i+1]。两类来源的最后一步不同，互不重叠；而任何一条合法序列的最后一步必然是其中之一，所以不缺。

环状下标。i = 1 时左邻居是 n，i = n 时右邻居是 1。写成 (i-2+n) % n + 1 和 i % n + 1 也行，但直接两个 if 更不容易错。

边界与方向。f[0][1] = 1（还没传，球在 1 号手里，这一种局面就是 1 条“空序列”），其余 f[0][i] = 0。j 必须从小到大：f[j] 只依赖 f[j-1]。

答案。f[m][1]。注意不是 f[m][*] 求和——题目只问回到 1 号的情况。

量级。每层最多把方案数翻 2 倍，m = 30 时不超过 2³⁰ ≈ 1.07×10⁹，int 勉强装得下；但方案数这类量随手就会越界，直接用 long long。复杂度 O(nm) ≤ 900。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

long long f[35][35];        // f[j][i]：传 j 次之后球在 i 号手里的方法数

int main() {
    int n, m;
    cin >> n >> m;

    f[0][1] = 1;                          // 边界：0 次传球，球在 1 号手里
    for (int j = 1; j <= m; ++j)
        for (int i = 1; i <= n; ++i) {
            int l = (i == 1 ? n : i - 1);  // 左邻居，环状
            int r = (i == n ? 1 : i + 1);  // 右邻居，环状
            f[j][i] = f[j - 1][l] + f[j - 1][r];
        }

    cout << f[m][1] << "\n";              // 传 m 次后回到 1 号
    return 0;
}
关键片段拆解
片段作用
long long f[35][35];n, m ≤ 30，两维都开 35 足够。j 表示次数、i 表示人，顺序别写反——f[j][i] 与 f[i][j] 在数值上完全不同。
f[0][1] = 1;边界就是“一次都没传”的局面：球在 1 号手里，这算 1 种方法（空序列）。其余 f[0][i] 由全局数组默认为 0，正好表示“一开始球不在 i 号手里”。
for (int j = 1; j <= m; ++j)外层是阶段，必须从小到大：f[j] 整层只依赖 f[j-1] 这一层。
int l = (i == 1 ? n : i - 1);环状边界的左邻居。漏掉这个判断，1 号的左邻居就成了 0 号，f[j][1] 会长期是 0 或少一半。
int r = (i == n ? 1 : i + 1);环状边界的右邻居。两处都要处理，只处理一处是最常见的 WA。
f[j][i] = f[j - 1][l] + f[j - 1][r];相加而不是取 max：题目问的是方案数。相加的两项对应“最后一步从左边来”和“从右边来”。
cout << f[m][1];答案是回到 1 号这一格。写成 f[m][0] 或对整行求和都不对。
这题最容易错的地方
  • 环状边界只处理了一半：1 号的左邻居没接回 n，或 n 号的右邻居没接回 1，边界答案必错。
  • 边界写成 f[0][1] = 0 或干脆不写，整张表全 0。
  • 答案写成 f[m][0]：数组下标 1..n 才是人，f[*][0] 永远是 0。
  • 把 f 开成 int 并顺手取模：本题不取模，m = 30 时答案接近 10⁹，再用 int 算中间量容易溢出。

挑战 2 · 覆盖墙壁
洛谷 P1990普及/提高-去洛谷做这题 ↗

有一堵长 N、宽 2 的墙（2×N 个格子），用两种砖去铺满：

① 直砖：1×2，竖放时占一列的上下两格，横放时占相邻两列各一格；

② L 型砖：占 3 格，形状是一列的上下两格 + 相邻一列的一格（可以旋转成 4 种朝向）。

两种砖都可以无限使用、可以混着铺、允许出现在任何位置。问 2×N 的墙有多少种铺满的方案。

因为答案很大，只要求输出方案数的最后 4 位：例如 N = 13 时方案数是 13465，只需输出 3465；如果答案不足 4 位就原样输出（N = 3 时输出 5，不加前导 0）。

输入格式：一行一个整数 N（1 ≤ N ≤ 10⁶）。输出格式：一行，方案数的最后 4 位。

样例
输入： 13 输出： 3465
引导性提示（先只看这里）

只记“前 i 列铺满了”不够用：L 型砖只占相邻一列的 1 格，铺到一半时边界上会凸出一格。

给这个“凸出一格”的局面也开一个状态。想想它怎么从“铺满”变过来、又怎么变回“铺满”。

任何一块砖最多横跨两列，所以铺到第 i 列时，边界上只可能有三种情况：第 i+1 列一格没占、占了一格、占了两格。第三种其实就是“前 i+1 列铺满”。

想看思路了？点开完整思路

为什么一个状态不够。直砖和 L 砖都能跨两列，铺到中途时第 i+1 列可能只被占了 1 格。这个“凸出一格”的局面不是“前 i 列铺满”，也不属于任何完整的后缀，必须单独记。

两个状态。A[i] = 前 i 列完全铺满的方案数；B[i] = 前 i 列完全铺满、且第 i+1 列恰好有 1 格被占（凸出一格）的方案数。上下对称，所以两种凸出方向合并成一个 B 计数，转移时用系数 2 补回来。

五条转移。看“用什么砖去补第 i+1 列”：① A[i] → A[i+1]：竖放一块直砖（1 种）；② A[i] → A[i+2]：两块横砖（1 种）；③ A[i] → B[i+1]：L 砖占满第 i+1 列两格、再伸一格到第 i+2 列（凸在上或凸在下，2 种）；④ B[i] → B[i+1]：横砖补上第 i+1 列剩下那格，同时伸进第 i+2 列（1 种）；⑤ B[i] → A[i+2]：L 砖补上第 i+1 列剩下那格、并占满第 i+2 列两格（1 种）。

合并写法。把五条按“从哪里来”整理：A[i] = A[i-1] + A[i-2] + B[i-2]，B[i] = 2·A[i-1] + B[i-1]。代码里用“往 i+1、i+2 加”的写法，省掉倒推的思考。

边界与答案。A[0] = 1（空墙有 1 种铺法，什么都不放），B[0] = 0（一列都没铺，不可能已经凸出）。逐列往后推，答案是 A[N]。

验证。A[1] = 1、A[2] = 2、A[3] = 5、A[13] = 13465，与题面给的数字一致。复杂度 O(N) 时间、O(N) 空间（可以滚到 O(1)）；N = 10⁶ 时约 10⁶ 次加法。

取模。转移只有加法和乘 2，所以每一步都能直接 % 10000，不必担心溢出。只在最后取模的话，中间值会涨到天文数字，long long 也装不下。

参考代码
#include <bits/stdc++.h>
using namespace std;

const int MOD = 10000;
int A[1000005];        // A[i]：前 i 列完全铺满的方案数
int B[1000005];        // B[i]：前 i 列铺满、且第 i+1 列凸出一格的方案数

int main() {
    int n;
    cin >> n;

    A[0] = 1;          // 空墙：1 种方案
    B[0] = 0;          // 一列都没铺，不可能已经凸出

    for (int i = 0; i <= n; ++i) {
        A[i + 1] = (A[i + 1] + A[i]) % MOD;                   // 竖放一块直砖
        A[i + 2] = (A[i + 2] + A[i] + B[i]) % MOD;            // 两块横砖，或用 L 砖补完凸出
        B[i + 1] = (B[i + 1] + 2 * A[i] + B[i]) % MOD;        // L 砖凸出一格（2 种朝向），或横砖延续凸出
    }

    cout << A[n] % MOD << "\n";   // 答案是“前 n 列铺满”，不是 B[n]
    return 0;
}
关键片段拆解
片段作用
int A[1000005], B[1000005];N ≤ 10⁶，两个数组各约 4MB，合计 8MB，必须放全局；放进 main 直接超栈。
A[0] = 1;边界：什么都不放也算 1 种方案，它是整条递推的地基。写成 0 会让整张表全 0。
A[i + 1] += A[i]竖放一块 1×2 直砖把第 i+1 列补满。第 i+1 列没被占用，所以来源只能是 A[i]。
A[i + 2] += A[i] + B[i]两个来源：A[i] 用两块横砖占掉 i+1、i+2 两列；B[i] 用一块 L 砖补掉凸出那格并占满 i+2 列。
B[i + 1] += 2 * A[i] + B[i]两个来源：A[i] 用 L 砖凸出一格（凸在上/凸在下，所以乘 2）；B[i] 用横砖把凸出延续到下一列。
% MOD 写在每一次加法上转移只有加法和乘 2，取模可以逐步下沉。只在最后取模时中间值会涨到 10 万位，long long 也装不住。
cout << A[n]答案是“前 n 列完全铺满”。输出 B[n] 是错的——B[n] 只铺满了前 n 列并且还多占了一格。
这题最容易错的地方
  • 只用一个状态：漏掉“凸出一格”，N = 3 时算出 4 而不是 5。
  • B 的系数写成 1：L 砖的两种朝向只算了一种，N = 13 时答案会变小。
  • 数组只开 10⁶ 而 i = n 时要写 A[n+2]，越界写会踩坏 B 或其它全局变量。
  • 只在最后取模：中间值远超 long long，结果是随机数。
  • 把答案写成 B[n]，或者忘了不足 4 位时不补前导 0（直接 % 10000 输出就自然满足要求）。
