这一章只做一件事：把 Rust 的工具链装好，并弄清 rustc、cargo、rustup 三者的分工。装完之后你能用一条命令创建、编译、运行项目，后面所有章节都靠它。

一、三个工具各管什么

工具职责你会用到的命令
rustup工具链管理器：装/切 Rust 版本、管理 targetrustup update、rustup show
rustc编译器本体：把单个 .rs 变成可执行文件rustc main.rs
cargo项目管理器：依赖、构建、测试、发布cargo new、cargo run、cargo add

日常只用 cargo，rustc 是它内部调用的。安装：

# Linux / macOS
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Windows：下载 rustup-init.exe 直接运行，需要 MSVC 生成工具
# 验证
rustc --version
cargo --version

二、第一个项目

cargo new hello_rust      # 创建项目（默认是 bin 类型，带 main 函数）
cd hello_rust
cargo run                 # 编译 + 运行，一步到位
cargo build --release     # 优化构建，产物在 target/release/

cargo new 会生成这样的结构：

hello_rust/
├── Cargo.toml        # 项目元信息与依赖
└── src/
    └── main.rs       # 入口文件

Cargo.toml 是最小可用的清单，依赖写在 [dependencies] 下：

[package]
name = "hello_rust"
version = "0.1.0"
edition = "2021"

[dependencies]
# rand = "0.8"        # 需要时取消注释，cargo build 会自动下载
edition 不是编译器版本，而是“语言规则的一次快照”（2015 / 2018 / 2021）。同一个编译器可以编译不同 edition 的代码，行为按 edition 决定。

三、Hello, world 的三个层次

// src/main.rs
fn main() {
    println!("Hello, world!");   // 注意是 println! 带感叹号，它是宏不是函数
}
写法含义
fn main()程序入口，每个可执行 crate 必须有且只有一个
println!宏，负责格式化并换行；{} 是占位符，如 println!("{} + {} = {}", 1, 2, 3)
;语句结束符；不带分号的表达式会作为返回值（第 5 章会反复用到）

四、常见坑

  1. 只装了 rustc 没装 cargo：用 rustup 装，别单独下编译器。
  2. Windows 上缺 MSVC 链接器：报 linker `link.exe` not found，装 Visual Studio Build Tools 的 C++ 组件。
  3. 把 println!() 写成 println()：宏必须带 !。
  4. 在 target/ 里改代码：那里是构建产物，改源码要动 src/。
  5. 忘记 --release：默认 debug 构建慢很多（但带调试断言），性能测试一律用 release。

五、小结

rustup 管版本，cargo 管项目，rustc 管单文件编译。下一章用 cargo 写一个真正的小程序——猜数字，把输入、解析、循环、随机数一次串起来。
