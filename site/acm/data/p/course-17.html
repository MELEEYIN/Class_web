本节出现的新函数 / 新语法（先看懂再用）
  • priority_queue（优先队列 / 堆） —— O(log n) 插入、O(1) 取最值；动态取最小的标配
  • greater<T>：把默认大根堆翻成小根堆 —— 小根堆的标准写法；三个模板参数缺一不可
  • 结构体重载 operator<（决定谁在堆顶） —— 自定义堆顶；方向与 sort 的 cmp 相反，最容易错

上一节的贪心按键值排序，一次 sort 就结束。这一节有两个新形状：①贪心的对象是一段区间，排序键从“值”换成“端点”；②贪心要用到“当前最小”，而集合在过程中不断变化，sort 不够了，需要堆。

区间问题的排序键只有那么几个：左端点、右端点、长度、性价比。选错键的代价是整个算法错，所以要逐个排除。
问题排序键每一步怎么决定复杂度
区间调度（最多不重叠区间）右端点 r 升序当前 l ≥ 上一个 r 就选它O(n log n)
区间选点（最少点打中所有区间）右端点 r 升序当前 l > 最后一个点，就在 r 处补一个点O(n log n)
区间覆盖（最少区间盖满 [1, T]）左端点 l 升序在能接上的区间里挑 r 最大的O(n log n)
分数背包（可切割）性价比 v/m 降序装得下就整堆拿，装不下就切一块O(n log n)
合并果子（哈夫曼）不排序，每次取最小的两个合并后把新堆放回集合O(n log n)

前四行还是“排一次序、扫一遍”。最后一行不一样：合并出的新堆要重新参与比较，集合是动态的，排一次序就废了。凡是“每步都要取当前最小/最大”的贪心，就用堆。

新函数拆解 · priority_queue（优先队列 / 堆）
priority_queue<int> q; // 默认大根堆 q.push(x); q.top(); q.pop(); q.size(); q.empty();
组成含义 / 格式要求
priority_queue<T>声明一个存放 T 的堆。默认是大根堆：top() 是最大值。
q.push(x)插入一个元素，O(log n)。堆自己维护顺序，不用再 sort。
q.top()读堆顶（当前最大/最小元素），O(1)。只读不删。
q.pop()删除堆顶，O(log n)。它不返回被删的值，想取值必须先 top()。
q.size() / q.empty()元素个数 / 是否为空。调用 top()、pop() 前必须保证非空。
最小可运行示例
示例
priority_queue<int> q;                 // 大根堆
for (int x : {3, 1, 4, 1, 5}) q.push(x);

while (!q.empty()) {
    cout << q.top() << ' ';            // 5 4 3 1 1
    q.pop();                           // 想取值就先 top() 再 pop()
}
注意

cout << q.pop() 直接编译错误：pop() 的返回类型是 void。

堆里元素的类型必须可比较：int、pair 可以，struct 必须重载 operator<。

新函数拆解 · greater<T>：把默认大根堆翻成小根堆
priority_queue<int, vector<int>, greater<int>> q; // 小根堆，top() 是最小值
组成含义 / 格式要求
三个模板参数①元素类型 int　②底层容器 vector<int>　③比较器 greater<int>。三个都要写，少一个就编译报错。
greater<int>来自 <functional>（bits 里已包含）。它表示“大的排在后面”，于是小的浮到堆顶。
为什么不能只写两个第二个参数位置固定是容器，把比较器塞进去会报一大串模板错误，错误信息往往指向 <bits/stl_queue.h>。
等价写法把 -x 存进大根堆再取负；只适合 long long（int 的 -x 会溢出）。
最小可运行示例
示例
priority_queue<int, vector<int>, greater<int>> q;   // 小根堆
for (int x : {3, 1, 4, 1, 5}) q.push(x);
while (!q.empty()) { cout << q.top() << ' '; q.pop(); }   // 1 1 3 4 5
注意

口诀：默认大根堆，加 greater 变小根堆。自定义优先级时别硬塞 greater，用 operator< 更清楚。

新函数拆解 · 结构体重载 operator<（决定谁在堆顶）
struct Node { int w; bool operator<(const Node &o) const { return w > o.w; } };
组成含义 / 格式要求
为什么写在结构体里priority_queue 用 operator< 比较元素。写在结构体里，堆就能直接拿来用。
const Node &o按引用传，避免拷贝；必须 const，因为堆内部用常量引用比较。
末尾的 const表示比较不修改自身。漏写会编译失败，报错位置在模板深处，很难读。
return w > o.woperator< 返回 true 表示 this 的优先级更低（排在 o 后面）。写 w > o.w，于是 w 小的反而在堆顶。
与 sort 的 cmp 方向相反cmp 回答“a 是否在前”，operator< 回答“this 是否在后”。同一个不等式，两处要反过来写，这是本节最高频的错误。
最小可运行示例
示例
struct Task {
    int w;
    // 想让 w 小的在堆顶 -> 写 w > o.w（与 sort 的 cmp 反着写）
    bool operator<(const Task &o) const { return w > o.w; }
};

priority_queue<Task> q;
q.push({3}); q.push({1}); q.push({4});
cout << q.top().w;                // 1
注意

口诀：cmp 写“谁在前”，operator< 写“谁在后”。堆顶永远是“比较意义下最大”的元素。

例题 · 凌乱的 yyy / 线段覆盖洛谷 P1803普及-去洛谷做这题 ↗

有 n 场比赛，第 i 场从 a_i 时刻开始、b_i 时刻结束。同一时刻只能参加一场，但一场可以在结束的同一时刻立刻开始另一场。求最多能参加多少场。

输入格式：第一行一个整数 n；接下来 n 行，每行两个整数 a_i、b_i。

输出格式：一行一个整数，表示最多参加的场数。

数据范围：1 ≤ n ≤ 10⁶，0 ≤ a_i < b_i ≤ 10⁶。

输入： 3 0 2 2 4 1 3 输出： 2
三个候选排序键，先排除两个错的

候选 ①：按开始时间 a_i 升序。反例：三场 [0,100]、[1,2]、[3,4]。先选 [0,100]，剩下两场都被它盖住，只能 1 场；最优是 [1,2] 和 [3,4]，2 场。错因：开始早不代表占得少。

候选 ②：按区间长度 b_i − a_i 升序。反例：[0,6]、[6,10]、[0,10]。最短的 [6,10] 先选，另两场都接不上，只能 1 场；最优是 [0,6] + [6,10] 共 2 场。错因：短区间可能卡在中间，把两边都切断。

候选 ③：按结束时间 b_i 升序。这个对。设排序后第一个区间是 I₁ = [l₁, r₁]，r₁ 是所有右端点里最小的。任取一个最优解，它的第一场是 J = [l_J, r_J]，必有 r_J ≥ r₁。把 J 换成 I₁：最优解的第二场 K 满足 l_K ≥ r_J ≥ r₁，所以 I₁ 与 K 不冲突，场数不变。于是存在一个最优解，第一场就是 I₁——贪心的第一步是安全的。删掉与 I₁ 冲突的区间，剩下问题同构，归纳即可。

落点是一句话：越早结束，剩下的时间越多，所以它不吃未来的资源——命中上一节的“交换不变差”。

贪心主体的 4 行
sort(a + 1, a + n + 1, cmp);        // cmp：右端点升序
int ans = 0, last = 0;
for (int i = 1; i <= n; ++i)
    if (a[i].l >= last) { ++ans; last = a[i].r; }   // 接得上就选，选了才更新

n 到 10⁶，数组必须开全局（放静态区），并且关掉 cin 同步。

完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

const int N = 1000005;
int n;
struct Seg { int l, r; } a[N];

// 唯一的贪心决策：按右端点升序
bool cmp(const Seg &x, const Seg &y) {
    if (x.r != y.r) return x.r < y.r;   // 主键：越早结束越优先
    return x.l < y.l;                   // 次键：保证严格弱序
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> a[i].l >> a[i].r;
    sort(a + 1, a + n + 1, cmp);        // O(n log n)，n = 10^6 也能过

    int ans = 0, last = 0;              // last = 上一场的结束时刻；时刻都 >= 0，初值 0 安全
    for (int i = 1; i <= n; ++i) {
        if (a[i].l >= last) {           // 接得上（等号不能少：t 结束、t 开始是允许的）
            ++ans;
            last = a[i].r;              // 只有真的选了才更新，这是贪心的"落子"
        }
    }
    cout << ans << '\n';
    return 0;
}
逐行拆解
代码片段含义与理由
struct Seg { int l, r; } a[N];把一场比赛存成区间。n 到 10⁶，数组开全局：局部数组放在栈上会直接爆栈（RE）。
if (x.r != y.r) return x.r < y.r;整个算法只有这一行在做决策。换成 x.l < y.l，得到的就是候选 ① 的错误算法。
int ans = 0, last = 0;last 是“已选区间中最晚的结束时刻”，初值 0 因为题目保证时刻非负，等价于“第一场随时能开始”。
if (a[i].l >= last)能接上就选。等号是关键：t 时刻结束的那场与 t 时刻开始的下一场不冲突。
last = a[i].r;选了才更新。更新的是 r 而不是 max(last, r)：按 r 升序后 a[i].r 一定 ≥ last。
cout << ans;答案是场数，不是总时长、不是总覆盖长度。别把 ++ans 写成 ans += a[i].r - a[i].l。
同一套排序，换一个判断：区间选点

经典模型：给定 n 个闭区间，选最少的点，使每个区间至少包含一个点。排序键一模一样——右端点升序。

维护最后一个放下的点 last（初值 −∞）。按 r 升序扫描，若 last 没落在当前区间 [l, r] 里就必须再放一个点；放哪里？放右端点 r，它最靠右，能顺带覆盖更多后面的区间。判断条件可以简化成一行 l > last：按 r 升序保证 last ≤ r，所以只要 l ≤ last，就必有 last ∈ [l, r]。

核心循环（与上一题只差 2 行）
// 接在"按右端点排序"之后，替代上一题的判断
int cnt = 0;
long long last = -1;                // 还没有放点；坐标 >= 0，-1 相当于 -inf
for (int i = 1; i <= n; ++i) {
    if (a[i].l > last) {            // 上一个点没打中这个区间
        ++cnt;
        last = a[i].r;              // 在右端点补一个点，覆盖尽量多的后续区间
    }
}
// cnt 就是最少点数

两题并排看：调度题问“能不能接上”（l ≥ 上一场的 r），选点题问“有没有被点到”（l > 最后一个点）。“越靠右越不吃未来资源”这一句同时支撑两个算法。

换一个排序键：分数背包按性价比

n 堆物品（重量 m_i、价值 v_i）和容量 T，每堆可以只取一部分，价值按比例算，求最大价值。这是“能切割”的背包，贪心成立；0/1 背包不能切，贪心不成立（上一节的反例库）。

排序键：性价比 v_i / m_i 降序。容量可看成 T 个 1 单位的格子，每个格子都该填“每单位最贵”的东西，所以贵的先拿满。能整堆拿就整堆拿，装不下就把剩余容量按比例切一块然后结束。

分数背包：把排序键从端点换成比值
#include <bits/stdc++.h>
using namespace std;

const int N = 105;
int n;
long long cap;                          // 剩余容量
struct Item { long long m, v; } a[N];

// 性价比 v/m 降序：交叉相乘代替除法，避开浮点误差
bool cmpRatio(const Item &x, const Item &y) {
    return x.v * y.m > y.v * x.m;       // v, m <= 10^6 时乘积 <= 10^12，long long 安全
}

int main() {
    cin >> n >> cap;
    for (int i = 1; i <= n; ++i) cin >> a[i].m >> a[i].v;
    sort(a + 1, a + n + 1, cmpRatio);

    double ans = 0;
    for (int i = 1; i <= n && cap > 0; ++i) {
        if (a[i].m <= cap) {            // 整堆装得下，全拿
            cap -= a[i].m;
            ans += a[i].v;
        } else {                        // 只剩部分空间，按比例切一块
            ans += 1.0 * a[i].v * cap / a[i].m;
            cap = 0;
        }
    }
    cout << fixed << setprecision(2) << ans << '\n';
    return 0;
}

不要写 x.v / x.m > y.v / y.m：double 比较有误差，可能把相等判成不等，而且 m = 0 时会除零。

例题 · 合并果子洛谷 P1090普及/提高-去洛谷做这题 ↗

有 n 堆果子，第 i 堆有 a_i 个。每次可以把两堆合并成一堆，消耗的体力等于两堆果子数之和。经过 n − 1 次合并后只剩一堆，求消耗的体力总和的最小值。

输入格式：第一行一个整数 n；第二行 n 个整数 a_1 … a_n。

输出格式：一行一个整数，即最小体力消耗。

数据范围：1 ≤ n ≤ 10⁴，1 ≤ a_i ≤ 2×10⁴，答案保证小于 2³¹。

输入： 3 1 2 9 输出： 15
为什么要每次取最小的两堆

先看清代价的结构：一堆果子被合并 d 次，它的数量就被算进总代价 d 次。所以重的应该少被合并（离根浅），轻的应该多被合并（离根深）。把每次合并画成一棵二叉树，总代价 = Σ a_i × 深度_i。

交换论证：最优树里最轻的两堆一定在最深层且互为兄弟。若最轻的叶子不在最深层，把它与最深的叶子交换，小权值下移、大权值上移，WPL 只会变小，与最优性矛盾。所以先合并最轻的两堆不损失最优性，剩下问题同构，归纳即可。

实现上有个关键点：合并出的新堆必须重新参与比较。排一次序就固定的做法是错的（1、2、9 合并出 3 之后，3 比 9 小，下一轮该先碰它）。集合动态变化，所以用堆：每次 top 两次、pop 两次、push 一次，n − 1 轮，总 O(n log n)。这是本课程第一次出现“贪心 + 数据结构”。

完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    // 三个模板参数：元素类型、底层容器、比较器。greater 表示小的优先 -> 小根堆
    priority_queue<int, vector<int>, greater<int>> q;
    for (int i = 0; i < n; ++i) {
        int w;
        cin >> w;
        q.push(w);
    }

    long long cost = 0;                 // 本题保证答案 < 2^31，但用 long long 不亏
    while (q.size() > 1) {              // 合并 n-1 次，剩 1 堆时结束
        int x = q.top(); q.pop();       // 当前最轻的两堆
        int y = q.top(); q.pop();
        cost += x + y;                  // 这次合并消耗的体力
        q.push(x + y);                  // 新堆放回集合，参与后面的合并
    }
    cout << cost << '\n';
    return 0;
}
逐行拆解
代码片段含义与理由
priority_queue<int, vector<int>, greater<int>> q;小根堆：top() 始终是最轻的一堆。用默认大根堆会先合并最大的两堆，答案偏大。
while (q.size() > 1)合并 n − 1 次，剩 1 堆时停。写成 while (!q.empty()) 会在最后一轮第二次 pop 时取空堆。
int x = q.top(); q.pop(); int y = q.top(); q.pop();连续取两个最小值。必须先 top 再 pop，两句不能合并（pop 没有返回值）。
cost += x + y;这次合并的体力消耗就是两堆之和，也是这棵子树的根权值。
q.push(x + y);新堆必须放回去。漏了这一行，下一轮会比较到已经不存在的旧值，答案偏离。
这一节的 5 个坑，每个都有具体症状

在空堆上 q.top() 或 q.pop()：未定义行为，通常 RE（段错误）。合并果子的循环条件必须是 q.size() > 1。

合并果子错用大根堆（漏写 greater）：每轮合并最大的两堆，样例 3 / 1 2 9 会输出 23 而不是 15 → WA。这种错最容易藏在“样例过了”的错觉后面，一定要用这组数据验证。

operator< 写成 return w < o.w; 以为是小根堆：堆顶其实是最大值 → WA，而且结构体题通常没有小样例能暴露它。

cmp 或 operator< 里用 <=、>=：破坏严格弱序，std::sort 可能越界写内存 → RE；开 -fsanitize 会报 invalid comparator。

区间调度按左端点或区间长度排序，用 [0,100]、[1,2]、[3,4] 或 [0,6]、[6,10]、[0,10] 一测就 WA；n = 10⁶ 时不关 cin 同步会 TLE，把 10⁶ 的数组开在 main 里会 RE（爆栈）。

数学补给 · 合并果子的代价 = 哈夫曼树的带权路径长度

把每次合并画成一个新结点，两个孩子是参与合并的两堆。n 堆最终合并成一棵树：叶子是原始堆，内部结点是合并出来的新堆，共 n − 1 个内部结点。某堆果子被合并 d 次，它的数量就在 d 个内部结点的权值里各出现一次，所以

总代价 = Σ（内部结点权值）= Σ a_i × d_i，d_i 是叶子的深度。这个量叫 带权路径长度 WPL，也就是哈夫曼编码里的平均码长项。例：a = 1, 2, 3, 4，合并 1+2 = 3、再合并 3+3 = 6、最后 6+4 = 10，总代价 19；检验深度：1、2 深度 3，3 深度 2，4 深度 1，1×3 + 2×3 + 3×2 + 4×1 = 19。

为什么“取最小的两堆”最优？最轻的两堆在最优树里一定是最深的一对兄弟；否则把它们与最深的叶子交换，小权值下移、大权值上移，WPL 严格变小，与最优性矛盾。

规模：n 堆合并 n − 1 次，每次堆操作 O(log n)，总 O(n log n)。树深最坏可到 n − 1，代价不能按 log n 估。P6033（n 到 10⁷）必须用 long long 并换 O(n) 做法。

  1. 如果每个区间带一个价值，要求“选出互不重叠的区间使总价值最大”，按右端点贪心还成立吗？先造一个反例（提示：一个很长但价值极高的区间），再想正确解法要什么工具（第 27、31 节）。
    想好了？点开核对思路与解析
    不成立。反例：A = [0,100] 价值 100，B = [1,2] 价值 1，C = [3,4] 价值 1。按右端点升序先选 B 再选 C，得 2；最优是只选 A 得 100。错因：带上价值以后“结束得早”不再等于“占用得少”，一个长区间可以一次换到极大收益，正文那条证明靠的是“每个区间收益相同”。正确工具是“按右端点排序 + 二分 + DP”：f[i] = max(f[i−1], f[p(i)] + v_i)，p(i) 用 upper_bound 找最后一个右端点 ≤ l_i 的区间（第 27 节），这就是第 31 节的加权区间调度。常见错路：改成按“价值 / 长度”排序想救回来——反例照样能造，两个中等价值区间就能压死一个比值更高的长区间。
  2. 合并果子如果改成“每次只能合并相邻的两堆”，每次取最小的相邻对还对吗？先手算 4 组数据找反例，再看第 33 节的区间 DP——这是“加一个限制，贪心就退化成 DP”的典型。
    想好了？点开核对思路与解析
    不对。反例 6 4 4 6：贪心先并中间两个 4（代价 8）得 6 8 6，再并 6+8（14）得 14 6，最后 20，合计 42；最优是先并 6+4 和 4+6（各 10），再 10+10 = 20，合计 40。错因：“相邻”把可交换的范围锁死了——交换两次合并的顺序会改变中间结果的相邻关系，上一节“交换不变差”的前提直接崩了。解法是区间 DP：f[l][r] = min over k of (f[l][k] + f[k+1][r]) + sum(l..r)，O(n³)，第 33 节。常见错路：以为“只在相邻里挑最小的”是原题加了个小限制——它其实把问题从排序贪心换成了另一类算法。
  3. 合并果子如果每次可以合并任意 3 堆，会多出什么麻烦？提示：每次减少 2 堆，要保证最后正好剩 1 堆，可能需要补几个 0 堆。补几个？
    想好了？点开核对思路与解析
    变成 k 叉哈夫曼：每次取最小的 3 堆合并，代价加三者之和，再把新堆放回堆里，O(n log n)。麻烦在于“每次少 2 堆”要求 (n−1) 能被 2 整除，否则最后剩 2 堆、没法按“合 3 堆”的规则收尾；标准做法是先补若干个权值为 0 的堆，补的个数是 (2 − (n−1) mod 2) mod 2，也就是 n 为偶数补 1 个、n 为奇数补 0 个。补 0 不影响最优性（0 最小、只会被最先合并），但让每个内部结点都恰好有 3 个孩子，深度与代价的对应关系才成立。常见错路：忘了补 0，最后硬把 2 堆并成 1 堆——那等于允许一个结点只有 2 个孩子，代价被算小。
  4. n = 10⁶ 个区间、时刻范围也只有 10⁶，除了 sort 还能怎么排？（提示：第 6 节的桶计数，按右端点扔进桶里，O(n + V)。）
    想好了？点开核对思路与解析
    可以按右端点扔进桶，用第 6 节的计数排序思想：开 V = 10⁶ 个桶，把区间挂到自己的 r 上，再从时刻 1 扫到 V，每到一个时刻就处理该时刻结束的所有区间，O(n + V) ≈ 2×10⁶。而 sort 是 O(n log n)，10⁶ 个区间约 2×10⁷ 次比较，桶排序快一个量级，代价是要开 10⁶ 大小的桶数组，还要处理“同一时刻多个区间”的挂链（前向星或 vector 数组）。注意桶只按右端点分，左端点完全不用管——两个区间算法的判断只用到 r 和 last。常见错路：把桶开成 int 而不是链表，同一时刻的多个区间互相覆盖只剩一个，答案偏小。
  5. 区间选点如果要求“每个区间至少包含 2 个点”，还能贪心吗？先试 [1,2] 这种短区间，看会不会放不下两个点。
    想好了？点开核对思路与解析
    还能贪，但要把“维护一个点”改成“维护最近放下的两个点 p1 ≤ p2”：若 p1 ≥ l，两个点都在区间里，跳过；若只有 p2 ≥ l，就在 r 处补一个点；若 p2 < l，就在 r−1 和 r 处各补一个。短区间放得下：[1,2] 的两个整数点 1、2 正好够，按上面的规则补 r−1、r 就能同时打中它。真正无解的是“只有一个整数点却要求两个点”的区间（如 [3,3]），要单独判掉，题面一般不会这么出。常见错路：把“每个区间 2 个点”当成“把单点版本跑两遍”——两遍之间不共享已放的点，第二遍会重新补，点数最多翻倍。

挑战题 · 建筑抢修
洛谷 P4053普及/提高-去洛谷做这题 ↗

有 N 个受损建筑，只有一个修理工。修第 i 个建筑需要 T1_i 秒，如果它在 T2_i 秒之内还没有修完就会报废。修理工一次只能修一个，求最多能抢修多少个建筑。

输入格式：第一行一个整数 N；接下来 N 行，每行两个整数 T1_i、T2_i。

输出格式：一行一个整数 S，表示最多能抢修的建筑数。

数据范围：1 ≤ N < 150000，1 ≤ T1_i < T2_i < 2³¹。

引导性提示（先只看这里）

报废时间早的建筑必须优先处理，否则一定来不及。先按 T2 升序排序，再想“排好序之后怎么决定修不修”。

如果某一刻发现总时间已经超过当前建筑的报废时间，说明前面选多了——该从已选的里面去掉一个，去掉哪个最划算？

去掉“最费时”的那个能让总时间降得最多，而建筑个数不变。用一个大根堆维护已选建筑的修复时间。

想看思路了？点开完整思路

排序。按报废时间 T2 升序。若存在一种方案能修 k 个，把它们按 T2 升序排列也不会违反任何报废时间。

依次处理每个建筑，维护：已选集合 S、总修复时间 sum、一个存 S 中所有 T1 的大根堆。

若 sum + T1_i ≤ T2_i：直接加入 S。它在 S 里最后修，前面已选建筑的完成时间不变，所以只要它自己赶得上，整个 S 仍然合法。

若 sum + T1_i > T2_i：加不进第 |S| + 1 个，最多只能保持 |S| 个。此时如果堆顶（S 里最费时的）> T1_i，就用当前建筑替换它：个数不变、sum 变小；而且当前建筑 T2 最大、排在最后，替换后每个前缀的完成时间都不会变大，合法性保住。若堆顶 ≤ T1_i，替换只会让 sum 更大，什么也不做。

最后答案就是堆的大小。复杂度 O(N log N)，N = 1.5×10⁵ 轻松过。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

const int N = 150005;
int n;
struct Build { int t1, t2; } a[N];

// 按报废时间升序：越早报废越先考虑
bool cmp(const Build &x, const Build &y) {
    if (x.t2 != y.t2) return x.t2 < y.t2;
    return x.t1 < y.t1;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> a[i].t1 >> a[i].t2;
    sort(a + 1, a + n + 1, cmp);

    priority_queue<int> q;      // 大根堆：已选建筑的修复时间，堆顶最费时
    long long sum = 0;          // 已选建筑的总耗时，最大约 1.5e5 * 2^31，必须 long long

    for (int i = 1; i <= n; ++i) {
        if (sum + a[i].t1 <= a[i].t2) {
            sum += a[i].t1;             // 赶得上，直接修
            q.push(a[i].t1);
        } else if (!q.empty() && q.top() > a[i].t1) {
            // 赶不上：用当前建筑换掉已选里最费时的那个，数量不变、总时间变小
            sum -= (long long)q.top() - a[i].t1;
            q.pop();
            q.push(a[i].t1);
        }
        // 否则当前建筑直接放弃：换了只会更慢
    }

    cout << q.size() << '\n';       // 堆里剩几个就是最多能修几个
    return 0;
}
关键片段拆解
片段作用
sort(a + 1, a + n + 1, cmp);按报废时间排序。这一步定下了“修的顺序就是处理顺序”，后面所有判断都基于这个顺序。
priority_queue<int> q;这里要的是大根堆：每次想知道“已选里最费时的是谁”，所以用默认的 priority_queue，不要加 greater。
if (sum + a[i].t1 <= a[i].t2)当前建筑排在这一批的最后修，只要它的完成时刻不超过自己的报废时间，前面已选的完成时刻都没变，整批仍合法。
sum -= (long long)q.top() - a[i].t1;先减后加写成一句。括号里显式转 long long，避免 int 减法在极端数据下出问题。
cout << q.size();答案不是 sum、不是 cnt，而是集合大小。q.size() 的类型是 size_t，直接输出没问题。
这题最容易错的地方
  • 用 int 存 sum：N = 1.5×10⁵、T1 接近 2³¹ 时总和远超 int → 溢出成负数，判断全乱，WA 一片。
  • 把替换条件写成 q.top() < a[i].t1（方向反了）：换成更费时的建筑，sum 变大，答案偏小 → WA。
  • 忘了先判空就 q.top()：第一栋建筑赶不上且堆为空时 RE。
  • 按 T1 或按 T2/T1 排序：必须按 T2 升序，其他键都能构造反例。
