Rust 的变量默认不可变，类型几乎都要明确写出来——这两条看起来“啰嗦”，其实是它能在编译期挡掉一大半 bug 的根源。这一章把变量、可变性、常量、遮蔽和基本类型一次讲清。

一、let 与 mut

fn main() {
    let x = 5;          // 不可变
    // x = 6;           // 编译错误：cannot assign twice to immutable variable

    let mut y = 5;      // 可变
    y = 6;              // OK
    println!("y = {}", y);
}
关键字能否重新赋值典型用途
let x否默认选择，能不可变就别可变
let mut x是累加器、读入缓冲、状态机
const MAX: u32 = 100;否，且编译期求值全局常量，名字惯例全大写
static G: &str = "hi";否，占用固定内存全局状态（可变 static 需要 unsafe）
const 和 let 的区别：const 必须标类型、只能在全局或函数内声明但不能遮蔽，且值在编译期就确定；let 可以在运行时计算，还能被同名新变量遮蔽。

二、遮蔽（shadowing）

let spaces = "   ";          // &str
let spaces = spaces.len();   // usize —— 同名新变量，类型也换了
println!("{}", spaces);      // 3

遮蔽不是“改值”，而是新建一个绑定把旧名字盖住：旧变量依然存在（直到作用域结束才释放），新变量可以有不同类型。这一点 mut 做不到：mut 只能改值，不能改类型。

三、标量类型

类别类型说明
整数i8/16/32/64/128、isize；u8…u128、usize默认 i32；isize/usize 随平台（64 位机器是 64 位），用于下标与长度
浮点f32、f64默认 f64，精度更高
布尔booltrue / false，不能与整数互转
字符char4 字节 Unicode 标量，'字'；与字符串 "字" 不同

整数溢出在 debug 构建会 panic，在 release 构建会按补码回绕——两边行为不一致是经典坑，需要明确回绕就用 wrapping_add，需要检测就用 checked_add。

四、复合类型

let tup: (i32, f64, u8) = (500, 6.4, 1);
let (a, b, c) = tup;              // 解构
println!("{}", tup.0);            // 也可以按下标

let arr = [1, 2, 3, 4, 5];        // 长度固定，类型 [i32; 5]
let zeros = [0; 10];              // 10 个 0
println!("{}", arr[0]);           // 越界会 panic（运行时检查）

Rust 的数组长度是类型的一部分（[i32; 5] 与 [i32; 6] 是不同类型），要动态长度请用 Vec<T>。

五、常见坑

  1. 以为 let 的变量“能改一次”：不能，必须 mut。
  2. 混用整数类型：let a: i32 = 1; let b: i64 = 2; a + b 直接编译失败，没有隐式提升，要 as 显式转换。
  3. as 转换是截断而非四舍五入：300.7 as u8 得到 44。
  4. 字符串下标：s[0] 不允许（UTF-8 变长），要用 s.chars().nth(0) 或切片 &s[0..1]（且必须落在字符边界）。
  5. 把 char 当成字节：char 是 4 字节 Unicode 标量，和 u8 不同。

六、小结

默认不可变 + 必须明确类型是 Rust 的两条地基。下一章讲函数与控制流，然后进入真正的分水岭：所有权。
