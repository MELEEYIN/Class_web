三种集合覆盖了绝大多数场景：Vec<T> 有序可变长、String 是 UTF-8 字节序列、HashMap<K,V> 做键值查找。它们的共同点是数据在堆上，所以赋值是移动而非复制。

一、Vec：能长大的数组

let mut v: Vec<i32> = Vec::new();
v.push(1); v.push(2);

let v2 = vec![1, 2, 3];            // 宏写法
println!("{}", v2[0]);             // 下标越界会 panic
match v2.get(5) {                  // 安全访问，返回 Option
    Some(x) => println!("{}", x),
    None => println!("越界"),
}

for x in &v2 { println!("{}", x); }   // 借用遍历
v2.iter().sum::<i32>();              // 迭代器求和
操作注意点
v[i]越界 panic，仅用于确定下标合法时
v.get(i)返回 Option<&T>，适合不确定
v.push(x)可能触发扩容（重新分配 + 搬数据）
for x in v消耗 v；for x in &v 只借用

二、String 与 &str

let mut s = String::from("hello");
s.push_str(" world");       // 追加 &str
s.push('!');                // 追加 char
let t = format!("{}-{}", s, 42);   // 不消耗 s

// 不能按下标取字符：UTF-8 变长
// let c = s[0];            // 编译错误
for ch in s.chars() { }     // 按 Unicode 标量遍历
for b in s.bytes() { }      // 按字节遍历

&str 是“借来的字符串切片”，String 是“拥有所有权的可变字符串”。函数参数优先用 &str，因为它能同时接受两者。

三、HashMap

use std::collections::HashMap;

let mut m = HashMap::new();
m.insert("a", 1);
m.insert("b", 2);

match m.get("a") {
    Some(v) => println!("{}", v),
    None => println!("没有"),
}

// 不存在才插入
m.entry("c").or_insert(3);

for (k, v) in &m { println!("{} = {}", k, v); }

entry(k).or_insert(v) 是统计词频的标准写法：只查一次哈希，避免了“先 get 再 insert”的两次查找。

四、常见坑

  1. s[0] 取字符：UTF-8 不定长，编译期就不允许；用 chars() 或 char_indices()。
  2. &s + "x"：+ 会消耗左边的 String，改用 push_str 或 format!。
  3. 遍历 HashMap 的顺序是随机的（每次运行都可能不同），别依赖顺序。
  4. 借用 v[0] 之后又 v.push：扩容会让旧引用失效，编译器会拦下来。
  5. 用 Vec<bool> 当标记数组时忘了清零，逻辑错得很难查。

五、小结

Vec 管顺序、String 管文本、HashMap 管查找。下一章讲错误处理——这两种集合的很多方法都返回 Option/Result，正好衔接。
