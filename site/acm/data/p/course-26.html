第 24 节的 DFS 回答的是“能不能走到”。这一节回答“最少几步”。两个问法只差一个字，算法完全不同：DFS 一次沿一条路走到黑，要比较“最少”就得把所有路径长度都试一遍，棋盘上路径数是指数级的；BFS 换一种走法，把距离相同的点攒成一批一起处理，谁先被算出来，谁的答案就是最短的。

BFS 只做一件事：把距离为 k 的点全部处理完，再处理距离为 k+1 的点。队列的先进先出，就是这个顺序的物理实现。

  • 入队即标记：q.push(v) 的下一句（甚至同一句）就写 dis[v] = dis[u] + 1。等出队才标记，同一个点会被好几个前驱各塞一次。
  • dis 初值 −1：−1 同时表示“没到过”。初值用 0 的话，源点（距离 0）和没访问的点分不清。

例题 · 回家洛谷 P2802普及-去洛谷做这题 ↗

小 H 在一个 n×m 的方格地图上，格子含义：0 障碍、1 空地、2 小 H 的出发点（也是空地）、3 家、4 有鼠标的空地。

小 H 初始有 6 点血量，每移动一格（上下左右）消耗 1 点；血量降到 0 就死了，即使这一格上有鼠标也救不回来。走到有鼠标的格子上会立刻把血量补满到 6（经过几次补几次）。

求回到家所需的最短时间（步数）；回不去输出 -1。

输入格式：第一行两个整数 n、m（1 ≤ n, m ≤ 9）；接下来 n 行，每行 m 个数字，数字之间没有空格。

输出格式：一行一个整数，最短步数；无法回家输出 -1。

输入： 5 5 21111 10101 11411 10111 11113 输出： 8
例题怎么想：先写熟模板，再想清楚“状态里该放什么”

先按第 26 节的标准模板问两句话。状态是什么？——这个问题不好答：只记 (行, 列) 不够。同一个格子，用 5 点血走到和用 2 点血走到，接下来能走的路完全不同。所以状态必须带上血量：(行, 列, 剩余血量)。

从状态能到哪些状态？——上下左右四个方向。走到 (nx, ny) 时血量 −1；若 −1 之后血量变成 0，这一步本身就不合法；若目标格是鼠标，血量立刻变回 6。每一步代价都是 1，所以用 BFS。

为什么不能只用 dis[x][y] = 步数 判重：那样第二次、第三次走到同一格都会被当成“到过了”而剪掉，可它们可能带着更多血量。正确做法是把“到过没到过”换成“到过时最多剩多少血”：best[x][y] 记到达这一格时见过的最大血量，新状态若血量不更大就剪掉。

带状态的 BFS 骨架
memset(best, -1, sizeof(best));      // ① -1 表示没到过
q.push({sx, sy, 6});  best[sx][sy] = 6;
while (!q.empty()) {                 // ③ 一层一层往外扩
    auto u = q.front(); q.pop();     //    u 里带 (x, y, hp, step)
    for (四个方向) {
        int hp = u.hp - 1;
        if (格子是障碍 || hp <= 0) continue;   // ② 转移的合法性
        if (格子是鼠标) hp = 6;                //    补满
        if (格子是家) 输出 u.step + 1 并结束;
        if (hp <= best[nx][ny]) continue;      // ④ 剪掉“血更少或相同”的重复状态
        best[nx][ny] = hp;  q.push({nx, ny, hp, u.step + 1});
    }
}

为什么这一步剪枝是安全的：同一格、步数更多、血量还更少的状态，在任何后续走法下都不可能更优——它被另一个状态全面压制。而“第一次走到家”依然是最短步数，因为 BFS 按步数非降地扩展。

规模：n, m ≤ 9，状态数 ≤ 81 × 7 种血量 = 567 个，BFS 秒出。真正难的不是复杂度，而是“想到把血量放进状态”。

完整代码
#include <bits/stdc++.h>
using namespace std;

int n, m, g[15][15];
int best[15][15];                    // best[x][y]：到达 (x,y) 时能保留的最大血量，-1 表示没到过
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

struct State { int x, y, hp, step; };

int main() {
    cin >> n >> m;
    int sx = 0, sy = 0;
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= m; ++j) {
            char c; cin >> c;
            g[i][j] = c - '0';
            if (g[i][j] == 2) { sx = i; sy = j; }
            best[i][j] = -1;
        }

    queue<State> q;
    q.push({sx, sy, 6, 0});
    best[sx][sy] = 6;                // ★ 入队的同一时刻标记，别等出队

    while (!q.empty()) {
        State u = q.front(); q.pop();
        for (int k = 0; k < 4; ++k) {
            int nx = u.x + dx[k], ny = u.y + dy[k];
            if (nx < 1 || nx > n || ny < 1 || ny > m) continue;   // 先判越界
            if (g[nx][ny] == 0) continue;                          // 障碍
            int hp = u.hp - 1;                                     // 走一格的代价
            if (hp <= 0) continue;                                 // 死在半路，这一步不合法
            if (g[nx][ny] == 4) hp = 6;                            // 鼠标：瞬间补满
            if (g[nx][ny] == 3) { cout << u.step + 1 << "\n"; return 0; }  // 第一次到家即最短
            if (hp <= best[nx][ny]) continue;                      // 血不更多 → 被别的状态压制
            best[nx][ny] = hp;
            q.push({nx, ny, hp, u.step + 1});
        }
    }
    cout << -1 << "\n";              // 队列空了还没到家
    return 0;
}

把“一个源点”改成“很多个源点”，代码只改一处：初始时把所有源点都 push 进队列、dis 都设 0，之后的过程一个字不动。

为什么这样是对的？想象棋盘外有一个虚拟的超级源点 S，它到每个真源点都有一条权为 1 的边。从 S 出发做 BFS，第一层恰好是全部真源点，第二层是“离某个源点 1 步”的格子……把 S 那一层去掉，剩下的就是多源 BFS。所以“每个格子到最近源点的距离”一次 BFS 就能算完，不需要对每个源点各跑一遍。

多源 BFS：只改初始化

while (k--) {
    int x, y;
    cin >> x >> y;

怎么判断该用多源

题目问的是“到最近的某个东西的距离”，而不是“到指定的那个东西的距离”。

典型场景：每个格子离最近的火源要烧多久、离最近的出口多远、多个起点的队伍同时出发什么时候会合。

如果对每个源点各跑一次 BFS，复杂度是 k × nm，k 一多就 TLE——这正是多源 BFS 存在的理由。

BFS 的三条铁律里，没有一条要求状态必须是格子。只要满足两件事就能用 BFS：状态数量有限、任意两个状态之间的转移代价都是 1。

比如电梯问题：状态是楼层号，转移只有“上 K[u] 层”和“下 K[u] 层”两条。把坐标 + 8 个方向换成楼层 + 2 个方向，模板一个字都不用改。

同一套骨架，换个状态
queue<int> q;                       // 状态只是一个整数，队列就存 int
q.push(A);
dis[A] = 0;

while (!q.empty()) {
    int u = q.front(); q.pop();
    int nxt[2] = { u + K[u], u - K[u] };        // 两条出边
    for (int t = 0; t < 2; ++t) {
        int v = nxt[t];
        if (v < 1 || v > N) continue;           // 出界：这个按钮失灵
        if (dis[v] != -1) continue;             // 已经用更少的步数到过
        dis[v] = dis[u] + 1;
        q.push(v);
    }
}

这就是 BFS 模板的价值：写熟一遍，之后每道题只填两件事——状态是什么、从状态能到哪些状态。其余部分（队列、标记、距离 +1）永远相同。

BFS 的 7 种典型错法（含症状）

WA：除源点外全是 −1。—— dis 没置 −1（全局数组默认 0），判重条件 dis != -1 对所有格子都成立，第一次扩展就全被跳过。

WA：答案偏大。—— 在出队时才标记。同一个格子被多个前驱各 push 一次，队列膨胀；如果 dis 又在 push 时被无条件覆盖，后写入的较大距离会盖掉先写入的最小值。标记要和 push 同时发生。

RE（内存吃光）或 TLE 死循环。—— 删掉判重那一行。棋盘有环，A→B→A 会无限入队，几秒内队列吃掉几十 MB 然后 RE。

RE：数组越界。—— 棋盘是 1-based 却写成 nx < 0，或者根本不判越界。数组开 405 时 n = 400 读到 dis[401][*] 不会立刻崩，症状是随机 WA。

WA：大片格子变成 −1。—— 方向数组少写了几组，或者 dx/dy 的正负号没配对（dx[k] 与 dy[k] 必须同属一个方向）。

TLE：多源题写成了单源循环。—— 对每个源点各跑一次 BFS，复杂度 k × nm。多源 BFS 只跑一次。

WA：每个格子都比正确答案少 1，源点变成 −1。—— push 了源点却忘了写 dis[sx][sy] = 0，于是第一层算出的是 −1 + 1 = 0，整张表跟着错位。

多源与状态抽象的 3 个坑

只 push 了第一个源点，后面的都当成普通点：答案只对第一个源点正确。

多源时忘了先 memset(dis, -1, ...)：dis 全是 0，判重把所有格子都当成“已到过”，BFS 一步都扩不出去，输出全 0。

状态维度估少了。若状态是 (行, 列, 朝向)，dis 必须开三维；只开二维会让不同朝向互相覆盖，答案偏小。

数学补给 · 队列里永远只有两种距离

BFS 的正确性可以压缩成两条断言，每条两三行就能证完。

断言 1：任意时刻，队列中元素的 dis 值单调不降，且最多只有两种取值：t 和 t+1。

证明：初始时队列里只有源点，dis = 0，成立。设当前队首 dis = t。出队后，我们把所有新点按 dis = t+1 压到队尾。原来队里的元素 dis ∈ {t, t+1}，新压入的是 t+1，所以队里仍是非降的，取值仍是至多两种。∎

断言 2：点 v 第一次被写入的 dis 值，就是 v 到源点的最短距离 d(v)。

证明（对 d 归纳）：d = 0 时只有源点，显然。设所有 d < k 的点都写对了，考察 d = k 的点 v。取最短路上紧挨着 v 的前驱 u，有 d(u) = k−1，由归纳假设 dis(u) 已正确写成 k−1。u 出队时会尝试扩展 v：若 v 还没被写过，就写入 k。若 v 在此之前已被某个点 w 写过，则 w 出队早于 u，由断言 1（队列非降）得 dis(w) ≤ k−1，所以写入值 ≤ k；另一方面，任何能到达 v 的点 x 都有 d(x) ≥ k−1（否则 v 的最短距离还能更小），所以写入值 ≥ k。两边夹住，dis(v) = k。∎

推论（复杂度）：每个状态最多入队一次、出队一次，每条转移边只被检查一次，所以是 O(V + E)。本题 V = n·m ≤ 160000，E = 8V，约 1.28×10⁶ 次检查。

边界在哪：断言 1 的归纳只用到“每次新增的距离恰好是 t+1”。若某条边权是 2，队列里就会出现 t+2，取值超过两种，“最近的一批先出队”不再成立，第一次到达也不再是最短。边权不全为 1 时要用 Dijkstra（第 42 节），只有 0 和 1 两种权时用 0-1 BFS（第 28 节）。

顺带一个字节运算：memset(dis, -1, ...) 之所以成立，是因为 −1 的补码是 32 个 1，4 个字节完全相同；0x3f3f3f3f = 1061109567 也满足“四字节相同”，而且它小于 2³⁰，两个相加不超过 int 上限，所以常被当无穷大用。

  3. 要求“从起点到终点的不同最短路径条数”，应该在 BFS 的哪一步累加？为什么不能简单地把邻居的 dis 相加？
    想好了？点开核对思路与解析
    在“扩展出一条边 u→v”时累加：若 v 还没被访问，cnt[v] = cnt[u]；若 v 已被访问且 dis[v] == dis[u] + 1，再 cnt[v] += cnt[u]。不能把邻居的 dis 相加——要加的是“到达邻居的最短路径条数”，而且必须限定这条边确实在最短路上，否则绕远的路径也会被算进来。常见错路：在出队时统计（此时 v 的 cnt 还没累加完，会少算）；以及忘了把源点的 cnt 初始化为 1（全 0 传下去，答案恒 0）。
  4. 如果边权只有 1 和 2 两种，BFS 还成立吗？上面断言 1 的归纳坏在哪一步？如果只有 0 和 1 两种呢，能不能用一个双端队列救回来？
    想好了？点开核对思路与解析
    边权 1 和 2 时普通 BFS 不成立。断言 1 的归纳坏在“新压入的距离恰好是 t + 1”这一步：权 2 的边会产生 t + 2，队列里出现三种取值，队头不再是最小，某个点可能先被 t + 2 标上、之后才被 t + 1 找到，第一次写入就不是最短路。两种补救：用 Dijkstra（优先队列），或者“拆点”——在权 2 的边中间插一个虚拟点、拆成两条权 1 边，普通 BFS 又成立。只有 0 和 1 时用双端队列就行：0 权 push_front、1 权 push_back，队列里的距离仍然只有 d 和 d+1 两种且非降，队头最小。常见错路：给权 2 的边也 push_back，以为“多走一步会自然修正”——不会，它直接破坏了队列的分层性质。
  5. 多源 BFS 与“从超级源点出发的 BFS”为什么等价？如果各个源点的初始距离不是 0 而是各不相同的值，还能一次 BFS 算完吗？
    想好了？点开核对思路与解析
    等价性靠“虚拟超级源点”：加一个 S，S 到每个真源点连一条权 1 的边，从 S 做 BFS 时第一层恰好是全部真源点，所以“把它们全部入队、dis 置 0”就等价于删掉 S 那一层，一次 BFS 得到“到最近源点的距离”。若各源点的初始距离不同（源点 i 的初始代价是 c_i），就不再等价——多源 BFS 要求所有源点在同一层；这时要用 Dijkstra（把 (c_i, i) 全部压进优先队列），或者把权值拆成 0/1 用双端队列。常见错路：把不同初始距离的源点一起 push 却不排序，离得近的源点反而后处理，答案偏大。
  6. 怎么在 BFS 里还原出一条具体的最短路径，而不只是它的长度？需要额外记录什么，从哪个点开始倒推？
    想好了？点开核对思路与解析
    多记一个 pre[x][y]：BFS 第一次访问 v 时把 u 的坐标写进去（单位权 BFS 里 dis 一旦确定就不会再变，不必更新）。走完后从终点沿 pre 一路倒推到起点，把坐标压栈再反转输出，就是一条最短路径；pre 指向的正是最短路上的前驱，因为 v 第一次被访问就是从最短路来的。常见错路：在 0-1 BFS 或 Dijkstra 里也照抄“只在第一次访问时写 pre”——那里的距离会被松弛改小，前驱必须跟着更新，否则还原出来的路径不是最短；另一种是倒推时忘了把起点也压进栈，输出少一个点。

挑战题 · 机器人搬重物
洛谷 P1126普及/提高-去洛谷做这题 ↗

储藏室是一个 N×M 的网格，每个格子 0 表示空地、1 表示障碍。机器人的形状是一个直径 1.6 米的球，它的中心永远停在格点上；因为直径比格子边长（1 米）大，所以它同时占着以该格点为中心的 4 个格子。

它接受的指令只有五种，每条指令都花 1 秒：向前移动 1 格（Creep）、2 格（Walk）、3 格（Run）、向左转 90°、向右转 90°。移动过程中不能撞到障碍，也不能离开储藏室。

给定起点坐标、起点朝向（N 北 / S 南 / E 东 / W 西）和终点坐标，求到达终点的最少秒数。终点的朝向任意。

输入格式：第一行 N、M（1 ≤ N, M ≤ 50）；接下来 N 行，每行 M 个 0/1，空格分隔；最后一行四个整数和一个字母，依次是起点的行、列、终点的行、列和起点朝向。

输出格式：一行一个整数，最少秒数；无法到达输出 -1。（坐标指的是格子坐标，机器人的中心在它的左上角格点上。）

引导性提示（先只看这里）

先算清楚“机器人站在哪个格点上是合法的”：它占着 4 个格子，这 4 个格子必须都是空地、而且都在储藏室里。

同一点朝不同方向，后续能做的事完全不同。所以状态不是“格点”，而是“格点 + 朝向”；把距离数组开成三维。

每条指令的代价都是 1 秒，所以是普通的 BFS，不是带权最短路。注意“走 2 格 / 3 格”也是 1 秒，但中间经过的格点必须全部合法。

想看思路了？点开完整思路

第一步：把“格点是否合法”预处理出来。格点 (i,j) 的合法性 = 它的 4 个相邻格子 (i,j)、(i+1,j)、(i,j+1)、(i+1,j+1) 都在 1..N × 1..M 内且都为空地。于是合法的 i 只能到 N−1、j 只能到 M−1——机器人永远碰不到最后一行、最后一列，因为它的“身体”伸不过去。

第二步：状态。(i, j, d)，d = 0/1/2/3 表示东、南、西、北。距离数组开 dist[55][55][4]，初值 −1。为什么必须带方向：站在同一点朝东和朝南，“左转之后能去哪”完全不同，用二维数组会把它们错误地合并。

第三步：转移（每条代价都是 1 秒）。① 左转 (i,j,(d+3)%4)；② 右转 (i,j,(d+1)%4)；③ 前进 k = 1,2,3 步，落点必须合法，而且中途经过的格点也必须合法——走到第 2 步就撞墙时，第 3 步根本无从谈起，所以 break 而不是 continue。

第四步：BFS 与答案。所有边权都是 1，一层一层扩就是最短路。答案要取 min(dist[tx][ty][0..3])；如果终点合法但四个方向都是 −1，说明到不了。

为什么“3 步只花 1 秒”不会破坏 BFS。BFS 只要求边权相等，不要求状态之间只差一格。把“前进 1/2/3 步”看成三条并列的边，它们的权都是 1，BFS 仍然正确。

量级。状态数 = 50×50×4 = 10⁴，每个状态最多 5 条出边，总操作 5×10⁴，同层 BFS 一次扫完，用时可以忽略。

易错的物理细节。起点和终点给的是“格子的左上角”，所以机器人中心就是 (sx, sy) 这个格点；而终点的朝向任意，所以要在四个方向里取最小。

#include <bits/stdc++.h>
using namespace std;

int n, m, a[55][55];
int dist[55][55][4];                 // 三维：格点 (i,j) + 朝向 d
int dx[4] = {0, 1, 0, -1};           // 0 东、1 南、2 西、3 北
int dy[4] = {1, 0, -1, 0};

bool ok(int x, int y) {              // 机器人中心在格点 (x,y) 是否合法
    if (x < 1 || x >= n || y < 1 || y >= m) return false;   // 身体必须完全在室内
    return !a[x][y] && !a[x + 1][y] && !a[x][y + 1] && !a[x + 1][y + 1];
}

int main() {
    cin >> n >> m;
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= m; ++j) cin >> a[i][j];

    int sx, sy, tx, ty; char c;
    cin >> sx >> sy >> tx >> ty >> c;
    int d0 = (c == 'E' ? 0 : c == 'S' ? 1 : c == 'W' ? 2 : 3);

    if (sx == tx && sy == ty) { cout << 0 << "\n"; return 0; }
    if (!ok(sx, sy)) { cout << -1 << "\n"; return 0; }

    memset(dist, -1, sizeof dist);
    queue<array<int, 3>> q;
    dist[sx][sy][d0] = 0;
    q.push({sx, sy, d0});

    while (!q.empty()) {
        auto u = q.front(); q.pop();
        int x = u[0], y = u[1], d = u[2];
        if (x == tx && y == ty) { cout << dist[x][y][d] << "\n"; return 0; }

        // 转向：每条 1 秒
        for (int nd : {(d + 1) % 4, (d + 3) % 4})
            if (dist[x][y][nd] == -1) {
                dist[x][y][nd] = dist[x][y][d] + 1;
                q.push({x, y, nd});
            }

        // 前进 1~3 步：中间任何一步不合法就 break
        for (int k = 1; k <= 3; ++k) {
            int nx = x + dx[d] * k, ny = y + dy[d] * k;
            if (!ok(nx, ny)) break;                       // 中途撞墙，更远的也走不到
            if (dist[nx][ny][d] == -1) {
                dist[nx][ny][d] = dist[x][y][d] + 1;
                q.push({nx, ny, d});
            }
        }
    }
    cout << -1 << "\n";
    return 0;
}

这题最容易错的地方
  • 忘了把“占 4 个格子”写进合法性判断：机器人会贴着障碍穿过去，答案偏小。
  • 距离数组只开二维：不同朝向互相覆盖，答案偏小或直接 −1。
  • 前进时用 continue 而不是 break：虽然不影响正确性，但会多算一批非法落点；反过来，若把 ok 只判落点、不判中途，答案就会错。
  • 朝向映射与 dx/dy 的顺序不一致（比如把 N 映射成 0）：所有移动方向整体错位。

一个 N×M 的玉米迷宫，格子的含义是：# 玉米（不可通行）、. 草地、@ 起点、= 出口、大写字母 A~Z 表示滑梯端点。

滑梯是成对的：两个相同字母的格子互为两端，踩到任意一端都会被瞬间送到另一端（传送本身不花时间，花时间的是“走进那一格”的 1 步）。

规矩：踩到滑梯就必须使用它；但不能连续使用两次——传送之后必须先用普通移动走至少一步，才能再次使用滑梯。所有草地移动各花 1 个时间单位。

输入格式：第一行 N、M（2 ≤ N, M ≤ 300）；接下来 N 行，每行 M 个字符，字符之间没有空格。

输出格式：一行一个整数，从起点到出口的最短时间。

样例：下面的迷宫最优解是先向右走上滑梯 W（1 秒），被传送到 (2,3)，再向右、向上两步到达出口，共 3 秒。###=## / #.W.## / #.#### / #.@W## / ######

样例
输入： 5 6 ###=## #.W.## #.#### #.@W## ###### 输出： 3
引导性提示（先只看这里）

每条普通移动花 1 个时间单位，滑梯不花额外时间——先按“无权最短路”想。

麻烦在于“传送后不能再传送”。光记 (行, 列) 不够，因为你站在滑梯端点时“刚刚传送过”和“走过来的”是两种不同的处境。

把“上一步是不是传送”也放进状态，距离数组就变成三维了。另外注意：站在滑梯端点上不能停留，踩到的瞬间就被送走。

想看思路了？点开完整思路

状态。(x, y, flag)：站在 (x,y)，flag = 1 表示“我是刚被传送过来的”，flag = 0 表示“我是走过来的”。dist[x][y][2] 记最短时间。

为什么必须加 flag。题面规定传送之后必须走一步才能再传送。若状态只有 (x,y)，“刚传送过来”和“走过来”就无法区分，程序会让奶牛连续两次穿滑梯，答案偏小。

转移。从 (x,y,flag) 出发走四个方向：

{'kind': 'list', 'ordered': False, 'items': ['目标格是 # 或越界 → 跳过；', '目标格是 = → 答案 = 当前时间 + 1，直接结束（第一次到达即最短）；', '目标格是滑梯端点：若 flag == 1（刚传送过）→ 这一步不合法，跳过；否则先花 1 秒走进去，再瞬间到另一端，得到状态 (另一端, 1)，时间 +1；', '其余格子（草地、起点）→ 状态 (nx, ny, 0)，时间 +1。']}

为什么不用把滑梯端点当普通格子入队。题面说“踩到滑梯必须使用”，所以滑梯格不是可停留的状态；能落脚的只有它的另一端，并且必须打上 flag = 1。

答案。BFS 按时间非降扩展，第一次生成 = 的那一步就是最短时间。所有边权都是 1（传送不额外花时间），所以普通队列就够，不需要优先队列。

            else if (g[i][j] >= 'A' && g[i][j] <= 'Z') {
                int c = g[i][j] - 'A';
                if (a1x[c] == 0) { a1x[c] = i; a1y[c] = j; }   // 第一次见：记第一端
                else            { a2x[c] = i; a2y[c] = j; }     // 第二次见：记第二端
            }
        }

    memset(dist, -1, sizeof dist);
    queue<array<int, 3>> q;              // (x, y, flag)
    dist[sx][sy][0] = 0;
    q.push({sx, sy, 0});

    while (!q.empty()) {
        auto u = q.front(); q.pop();
        int x = u[0], y = u[1], flag = u[2];

        for (int k = 0; k < 4; ++k) {
            int nx = x + dx[k], ny = y + dy[k];
            if (nx < 1 || nx > n || ny < 1 || ny > m) continue;
            if (g[nx][ny] == '#') continue;

            if (g[nx][ny] == '=') { cout << dist[x][y][flag] + 1 << "\n"; return 0; }

            if (g[nx][ny] >= 'A' && g[nx][ny] <= 'Z') {
                if (flag) continue;                       // 刚传送过，不能再传
                int c = g[nx][ny] - 'A';
                int ox = (nx == a1x[c] && ny == a1y[c]) ? a2x[c] : a1x[c];
                int oy = (nx == a1x[c] && ny == a1y[c]) ? a2y[c] : a1y[c];
                if (dist[ox][oy][1] == -1) {              // 落在另一端，flag 置 1
                    dist[ox][oy][1] = dist[x][y][flag] + 1;
                    q.push({ox, oy, 1});
                }
                continue;
            }

            if (dist[nx][ny][0] == -1) {                  // 普通格子：flag 清 0
                dist[nx][ny][0] = dist[x][y][flag] + 1;
                q.push({nx, ny, 0});
            }
        }
    }
    return 0;
}
关键片段拆解
片段作用
int a1x[26], a1y[26], a2x[26], a2y[26];读入时就把每个字母的两端坐标存好。坐标从 1 开始，所以 0 天然可以当“还没出现过”的标记。
if (a1x[c] == 0) { ... } else { ... }同一个字母一定出现且只出现两次，第一次见记第一端，第二次见记第二端。这样查“另一端在哪”就是两次数组访问。
int dist[305][305][2];第三维是 flag。少了它，“刚传送过来”和“走过来”被当成同一个状态，奶牛会连续穿两次滑梯。
if (g[nx][ny] == '=') { ... return 0; }第一次能走到出口就立刻输出。BFS 按时间非降扩展，这个值一定是最小值。
if (flag) continue;flag = 1 时踩上滑梯是违规动作。这一行就是“不能连续传送”这条规则的全部实现。
int ox = (nx == a1x[c] && ny == a1y[c]) ? a2x[c] : a1x[c];判断踩到的是哪一端，跳到另一端。两个坐标要分开算，写成一个表达式容易错。
dist[ox][oy][1] = dist[x][y][flag] + 1;时间只加 1：花时间的是“走进滑梯那一格”，传送本身不花时间。落点状态必须带 flag = 1。
dist[nx][ny][0] = ...普通格子把 flag 清 0。注意同一格 (nx,ny) 有两种 flag，各自记最短时间，互不覆盖。
这题最容易错的地方
  • 只开二维距离数组：连续传送无法禁止，答案偏小。
  • 把滑梯端点当普通格子入队：奶牛会“站在滑梯上不动”，违反“踩到就必须使用”的规则。
  • 传送时忘了把落点的 flag 置 1：下一个状态又允许传送，等于没有限制。
  • 把传送也算 1 秒：答案整体偏大。题面说移动一步花 1 个时间单位，传送是 0。
