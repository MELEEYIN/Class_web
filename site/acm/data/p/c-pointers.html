1. 指针和内存单元

  • 指针：地址！
  • 指针变量：用来存储地址的变量！
  • 内存单元：是计算机中内存最小的存储单位，内存单元大小为 1 字节（8 bit）。
  • 每个内存单元都有一个唯一的编号，这个编号称之为"地址"。

为什么需要指针

有四件事只有指针能做：

  1. 让函数修改调用者的变量。C 只有值传递，swap(a, b) 传不出去，只能传 &a, &b。
  2. 避免拷贝大块数据。传 struct 会整块复制，传它的地址只复制 8 字节。
  3. 描述"有没有"这件事。返回 NULL 表示查找失败，返回 -1 就和合法值混在一起了。
  4. 在运行期决定访问哪一块内存。数组下标也算，但链表、树这类结构必须靠指针串起来。

地址到底是什么

int a = 10;         假设 a 被分配在 0x7ffe1234 开始的地方
                    （int 占 4 字节，所以它占了 4 个内存单元）

地址:  0x7ffe1234  0x7ffe1235  0x7ffe1236  0x7ffe1237
内容:      0x0A        0x00        0x00        0x00    （小端序，低位在低地址）

&a  →  0x7ffe1234        ← 首字节的地址，就是"a 的地址"

要点：&a 拿到的是首字节地址，而 sizeof(int) 决定了从那里往后读几个字节。这两件事分别由"地址"和"类型"掌握 —— 指针必须同时携带这两样信息，所以指针有类型。

  • 32 位平台：地址是 32 位整数，可寻址 2³² = 4 GB，指针 4 字节。
  • 64 位平台：地址是 48 位有效（硬件实现），指针 8 字节。

2. 指针的定义和使用

*p 的作用：将 p 变量的内容取出，当成地址看待，找到该地址对应的内存空间。

  • 如果做左值：存储数据到空间中。
  • 如果做右值：取出空间中的内容。
int a = 10;
int *p = &a;    // int* p --- Windows 写法    int *p --- Linux 写法    int * p --- 看个人习惯

// int *p = &a;  展开后就是：
// int *p;
// p = &a;

a = 999;
printf("*p = %d\n", *p);    // 间接引用 —— 右值（解引用）

*p = 250;                   // 间接引用 —— 左值
printf("a = %d\n", a);

2.1 & 和 * 是一对互逆运算

&*p   ==  p     // 先解引用再取地址，回到原地
*&a   ==  a     // 先取地址再解引用，回到原值

**& 和 * 是同一件事的两个方向**。搞清楚当前在地址层面还是在数据层面，指针就不会绕晕。

数据层：   a  ──────────  10
           │              ↑
        &a │              │ *
           ↓              │
地址层：   p  ──────────  0x7ffe1234

2.2 同一个 *，两种完全不同的身份

最容易卡住的地方：

出现位置名称含义
int *p;类型的一部分声明"p 是一个 int * 类型的变量"
*p = 250;解引用运算符参与运算的操作符

所以：

int *p = &a;    // 这里的 * 只是类型标记，它没有"解引用"的意思

它等价于 int p; p = &a;。声明里的 只标记类型，不会访问内存。

推论：int *p = &a; 和 int *p; *p = a; 是完全不同的两件事，后者是野指针写入。

2.3 * 和 ++ 混写：p++ 与 ++p

先定优先级：

  • 后缀 ++：一级（最高）——它先和 p 结合。
  • 前缀 ++ 和一元 *：二级，两者同级，结合方向自右向左。

于是：

  • p++ → (p++)，后缀最紧，先算 p++。
  • ++p → (++p)，同级从右往左，先算 ++p。

区别出在前缀和后缀的返回值上：

写法表达式的值副作用何时生效
p++（后缀）自增前的 p取完值之后
++p（前缀）自增后的 p取值之前

两句话记住：后缀先给值、后自增；前缀先自增、后给值。

int arr[] = {10, 20, 30, 40};
int *p = arr;

int v = *p++;      // v = 10，p 变成 &arr[1]      —— 先取 10，再挪指针
int w = *++p;      // p 变成 &arr[2]，w = 30      —— 先挪指针，再取 30
int x = (*p)++;    // x = 30，arr[2] 变成 31      —— 指针不动，改数据
int y = ++*p;      // arr[2] 变成 32，y = 32      —— 同 ++(*p)

实测输出：

v = 10, *p = 20
w = 30, *p = 30
x = 30, *p = 31, arr[2] = 31
y = 32, *p = 32, arr[2] = 32

再看指针本身的位置（p - arr 越大越靠后）：

起始      : p = arr + 0
*p++ 之后 : v = 10, p = arr + 1   <- 取的是旧位置
*++p 之后 : w = 30, p = arr + 2   <- 取的是新位置

两次都是往后走一格。所以"前移/后移"区分不了这两个写法，差别只在 * 拿到的是哪个指针：p++ 用自增前的旧指针，++p 用自增后的新指针。

写法p 的变化取到哪一格等价于
*p++前进一格原位（旧的 p）*(p++)
*++p前进一格前进后的位置（新的 p）*(++p)
(*p)++不动数据 +1—
++*p不动数据 +1++(*p)
别在一条语句里混着写多个自增，比如 printf("%d %d", *p++, *p) —— 函数实参的求值顺序标准没有规定，结果因编译器而异。

3. 指针类型的大小

  • 指针算一种自定义数据类型（如 int *）。
  • 指针的大小与类型无关！只与当前使用的平台架构有关： 32 位平台：4 字节；64 位平台：8 字节。

原因是：指针里存的是地址编号，而地址编号的宽度由地址总线决定，跟"它指向什么类型"毫无关系。类型只影响"从那个地址往后读几个字节"（见第 8 节）。

int main(void)
{
    printf("int * 的大小：%zu\n", sizeof(int *));
    printf("short * 的大小：%zu\n", sizeof(short *));
    printf("char * 的大小：%zu\n", sizeof(char *));
    printf("long * 的大小：%zu\n", sizeof(long *));
    printf("long long * 的大小：%zu\n", sizeof(long long *));
}

sizeof 的两点注意

  1. sizeof 是运算符，不是函数。它在编译期就把结果算出来了，运行时没有函数调用开销。
  2. 它的返回类型是 size_t（无符号整数），对应格式符是 %zu。用 %u 打印会警告：
warning: format '%u' expects argument of type 'unsigned int',
         but argument 2 has type 'long long unsigned int'

%u 恰好也是 4 字节，在 32 位机上"看起来能用"，到 64 位机上就是错的。养成写 %zu 的习惯。

一条语句中定义多个变量

int a, b, c;            // 多个普通变量
int *p1, *p2, *p3;      // 多个指针变量：每个变量都要有自己的 *
int a, *b, *c, d;       // 定义整型变量 a、d，同时定义指针变量 b、c

陷阱在这里：

int *p1, p2;            // p1 是 int *，p2 是 int！不是两个指针

只修饰紧跟其后的那一个变量。想一次定义多个指针，要么每个都写 ，要么用 typedef（见第 12 节）。

4. 空指针和野指针

C 的坏指针分三类，名字不同，治法也不同。

类型含义典型来源
未初始化指针值是垃圾，指向哪完全随机int *p; 直接使用
野指针有值，但那不是一个有效地址int p = (int )10;
悬垂指针曾经有效，但所指的内存已经失效函数返回局部变量的地址

野指针

  1. 没有使用"有效"的地址给指针初始化。
  2. p 指针变量有值，但是该值不是一个有效的地址。
int *p;         // 没有给 p 指定一个有效地址
*p = 1000;      // 危险！

int *p = 10;    // 没有给 p 指定一个有效地址（而且这是类型不匹配，会警告）
*p = 1000;      // 危险！

为什么它不报错？ 编译器无法在编译期知道 p 里装的是什么。运行时你确实往某个地址写了 1000 —— 那块内存可能属于别的变量、程序的栈帧、甚至操作系统。后果分三种：

  • 什么都没发生（最糟，bug 潜伏下来了）
  • 程序立刻崩溃（最好查）
  • 数据被悄悄改坏，几百行之后才表现出异常（最难查）
【结论】编程时，杜绝野指针。

悬垂指针

指针本身的值还是那个地址，但那块内存已经作废了。看起来一切正常，最容易被忽略。

两个来源：

  1. 函数返回了局部变量的地址 —— 栈帧随函数返回被回收。完整讲解见 08 第 2 节「指针做函数返回值」。
  2. free 之后继续使用 —— 堆上的内存已归还。见 09 章。

本章只做概念归类，不重复展开。

空指针

NULL == 0 == '\0'
int *p = NULL;  // #define NULL ((void *)0)   定义一个空指针
*p = 1000;      // *p 所指向的内存空间，是一个"无效访问区域"
  • NULL 在 C 里通常定义为 ((void *)0)，就是"地址 0"。
  • 现代操作系统的地址 0 附近那一页被特意设为不可访问，让空指针解引用立刻崩溃。所以 *p 在这里必定段错误。
  • 判断空指针：
if (p != NULL) { ... }   // 明确
if (p) { ... }           // 简洁，等价
if (!p) { ... }          // 简洁版判空
NULL == 0 == '\0' 这个等式在数值上成立，但语义上不要混用：NULL 给指针，0 给整数，'\0' 给字符。混着写编译器不报错，读代码的人要骂人。

防御办法：四条

int *p = NULL;       // 1. 定义时就初始化，哪怕是 NULL
if (p != NULL)       // 2. 使用前判空
{
    *p = 100;
}
p = NULL;            // 3. 用完之后立即置空，防止再次误用
// 4. 不要让函数返回局部变量的地址

置空的意义：野指针是"有值但无效"，空指针是"明确无效"。置空后误用会立刻崩溃（好查），不至于随机改坏内存（难查）。

5. 泛型指针（万能指针 void *）

  • 可以接受任意一种变量的地址。
  • 但是，在使用时必须借助"强制类型转换"具体化数据类型。
  • void * 类型的大小：32 位 4 字节，64 位 8 字节。
int main(void)
{
    printf("void * 的大小：%zu\n", sizeof(void *));

    char ch = 'R';
    void *p;                    // 泛型指针（万能指针）
    p = &ch;
    printf("*p = %c\n", *(char *)p);    // 将 p 的类型由 void * 强转成 char *

    return EXIT_SUCCESS;
}

为什么必须强转

void * 只记住了"地址"，丢掉了"类型"，也就丢掉了"该读几个字节"这个信息。直接 *p 编译器无法决定读 1 字节还是 8 字节，所以：

*p;         // 【编译错误】dereferencing 'void *' pointer
p + 1;      // 【编译错误】算术运算要求知道步长，void 没有大小

必须 (char )p、(int )p 这样先"补回类型"。

常见用途

  1. 通用接口的参数。qsort 要能排任意类型，参数只能收 void *：
void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));
  1. 内存拷贝。memcpy(void *dest, const void *src, size_t n) —— 它按字节搬，根本不在乎类型。
  2. 你自己写的不关心具体类型的容器/回调。

C 和 C++ 的一个差异

void *v = &a;
int *p = v;         // C：允许，隐式转换
int *p = (int *)v;  // C++：必须显式强转，否则编译错误

C 允许 void * 自动转成任何指针类型；C++ 不允许。写跨语言的头文件时要按 C++ 的严格标准来。

6. const 关键字

const 的作用：把"不应该改"写进类型系统，交给编译器检查。

6.1 修饰变量

const int a = 20;   // a 为只读变量，不能修改
// a = 200;         // 【编译错误】assignment of read-only variable 'a'

a 是只读变量，不是"常量"。它仍然占内存、仍然有地址（&a 合法），只是这个变量名不允许作为赋值目标。10、'A' 这类常量连地址都不一定有。

想让"编译期常量"参与数组维度、case 标签，需要它同时是常量表达式；const int n = 5; int arr[n]; 在 C99 里是变长数组（VLA），不是常量数组。这一点和 C++ 不同。

6.2 修饰指针：四种组合

const 出现在 * 的哪一边，决定了它约束的是数据还是指针本身。

int a = 10;

const int *p1 = &a;         // ① 指向"只读 int"的指针（数据不能改，指针能改）
int const *p2 = &a;         // ② 与 ① 完全等价，只是 const 位置换了
int * const p3 = &a;        // ③ 常量指针（指针不能改，数据能改）
const int * const p4 = &a;  // ④ 两者都不能改
写法能否改 *p（数据）能否改 p（地址）读法
const int *p✗✓指向 const int 的指针
int const *p✗✓同上
int * const p✓✗const 的指针，指向 int
const int * const p✗✗const 的指针，指向 const int
const int *p = &a;
*p = 500;           // 【失败】想把 a 的值改为 500，不能改！
p = &b;             // 【成功】可以修改 p 变量的内容（地址）

int * const q = &a;
*q = 500;           // 【成功】数据可以改
q = &b;             // 【失败】q 是常量指针，不能改指向

怎么快速判断：从右往左读

从变量名开始，由内向外、从右往左读：

const int * p        →  p 是 指针，指向 const int
int * const p        →  p 是 const 指针，指向 int
const int * const p  →  p 是 const 指针，指向 const int

另一种等效口诀：**看 const 在 * 的左边还是右边** —— 在左边，锁住的是"*p（数据）"；在右边，锁住的是"p（指针）"。

  • const 在 * 左边 → 数据只读
  • const 在 * 右边 → 指针只读

顶层 const 与底层 const

  • 顶层 const：int * const p —— 修饰指针变量本身。
  • 底层 const：const int *p —— 修饰指针所指的对象。

为什么区分这个？因为赋值时，"底层 const"不允许被忽略：

const int *p1;
int *p2;
p2 = p1;        // 【编译错误】discards 'const' qualifier
// 否则就能绕过 const：*p2 = 100 就改掉了 const 数据

而顶层 const 可以随便拷：

int * const p3 = &a;
int *p4 = p3;   // 【合法】拷贝的是地址值，两个指针指向同一块内存

6.3 函数参数中的 const

常用做法：在函数内，限制指针所指向的内存空间为只读（不允许修改）。

// 只读地"看"一个数组，承诺不修改它
int sum(const int *arr, int n)
{
    int s = 0;
    for (int i = 0; i < n; i++)
        s += arr[i];
    // arr[0] = 999;    // 【编译错误】函数内改不了，调用者可以放心传进来
    return s;
}

这样写是为了接口契约：调用者看到 const int 就知道"我的数据不会被改"，可以放心把一个 const 数组、字面量数组传进去。参数写成 int 的只读函数，调用者就得先把数据复制一份。

6.4 【重要纠正】通过指针改 const 变量是未定义行为

很多老教材写"可以用指针绕过 const 修改它"，把它当成一个技巧。这是 UB。看实测：

const int a = 20;
int *p = (int *)&a;   // 不加强转会警告：discards 'const' qualifier
*p = 677;
printf("%d\n", a);

同一个程序，只改编译选项：

编译选项printf("%d", a)printf("%d", *p)
-O0677677
-O220677

同一份代码，两个答案。原因：const int a = 20 是编译器眼里的常量，-O2 下所有对 a 的读取都被直接替换成立即数 20，内存里那份改动它根本不去看。

如果 a 是全局 const，更直接 —— 它被放进只读数据段 .rodata：

const int g = 20;
int main(void) { int *p = (int *)&g; *p = 677; ... }
改写前 g = 20
Segmentation fault    ← 退出码 139
【结论】 const 变量一旦用指针强转去改，行为就是未定义的（UB）。-O0 下"成功了"只是巧合，换个编译器、换个优化级别就变。永远不要这么写。需要"可读可写"就根本别加 const。

7. 指针和数组

数组名

  • 数组名是地址常量。
  • 不可以被修改、赋值（=、+=、-=、*=、/=、%= 等带有副作用的运算符）。
int a[3] = {1, 2, 3};   // a 就是数组地址
int b[3];               // b 是常量
b = a;                  // 【不允许】因为 b 为地址常量

指针是变量，可以使用数组名给指针赋值。

int *p = a;             // a 就是数组地址，允许！！

int arr[] = {1, 3, 5, 7, 9};
int *p = arr;           // 使用数组地址给 p 指针变量初始化

取数组元素的等价写法

arr[0] == *(arr + 0) == p[0] == *(p + 0)
arr[1] == *(arr + 1) == p[1] == *(p + 1)
arr[2] == *(arr + 2) == p[2] == *(p + 2)
...
arr[N] == *(arr + N) == p[N] == *(p + N)

这两条能推出来，靠的是编译器把 arr[i] 定义成 *(arr + i)。于是还有个有趣的结果：

2[arr] == arr[2]        // 合法但不推荐！因为 *(2 + arr) 和 *(arr + 2) 一样

知道就行，别在代码里这么写。

指针和数组名的区别

  1. 指针是变量，数组名是常量。
  2. sizeof(指针) ——> 4 字节或 8 字节。
  3. sizeof(数组名) ——> 数组实际的字节数。

还有一条更隐蔽的差别：&arr 和 arr 的值相同，类型不同。

int arr[10];
// arr  的类型是 int *        （退化为指向首元素的指针）
// &arr 的类型是 int (*)[10]  （指向"整个数组"的数组指针）

printf("%zu\n", sizeof(arr));    // 40
printf("%zu\n", sizeof(&arr));   // 8

printf("%p\n", (void *)(arr + 1));   // 向后 +4 字节（一个 int）
printf("%p\n", (void *)(&arr + 1));  // 向后 +40 字节（一整个数组）

实测差值正好 40 字节。这就是第 8 节标题说的"&数组名 + 1：加过的是一个数组的总大小"。

数组名作函数参数

数组名传参时退化为指针、函数内 sizeof(arr) 只剩 8 字节、为什么要额外传元素个数 ——这些在 08 第 2 节「数组做函数参数」里已经讲透，本章不重复。

练习：用指针给空数组连续赋值，再用"指针挪移"打印

int main(void)
{
    int arr[10];
    int n = sizeof(arr) / sizeof(arr[0]);
    int *p = arr;               // p 指向 arr[0]
    printf("p = %p\n", p);

    // 使用指针，给空数组连续赋值
    for (size_t i = 0; i < n; i++)
    {
        // arr[i] = i + 10;
        *(p + i) = 10 + i;      // *(p + i) == arr[i]
    }
    // 循环结束时，p 依然指向 arr[0]
    printf("循环结束后：p = %p\n", p);

    // 使用"指针挪移"方法打印出这个数组
    for (size_t i = 0; i < n; i++)
    {
        printf("%d ", *p);
        p++;    // p = p + 1，一次加过一个 int 大小（一个数组元素）
    }
    printf("\n");

    // 循环结束时，p 指向数组尾元素的下一个内存（越界指针，不能解引用）
    printf("2 个 for 循环结束后：p = %p\n", p);

    return 0;
}
另一种更简洁的写法（用 *p 直接遍历，不再用下标）：
int arr[] = {1, 2, 3, 4, 5, 6, 7, 8, 9, 0};
int *p = arr;
int n = sizeof(arr) / sizeof(arr[0]);

for (size_t i = 0; i < n; i++)
{
    printf("%d ", *p);
    p++;    // 一次加过一个 int 大小（一个数组元素）
}
// 注意：p 值随循环不断变化，打印结束后 p 指向数组尾后位置，
// 再 *p 就是越界访问（尾后位置只能比较，不能解引用）

8. 指针的算术运算

数据类型对指针的作用

  1. 间接引用（解引用）：指针的数据类型，决定了从指针存储的地址开始，向后读取的字节数 （与指针本身存储空间无关）。
  2. 加减运算：指针的数据类型，决定了指针进行 +/- 操作时，向后/向前跳过的字节数。
int a = 0x12345678;
// int *p = &a;    ---  0x12345678
// short *p;       ---  0x5678
// char *p;        ---  0x78
p = &a;
printf("%#x\n", *p);
int *       +1   实际加过 4 字节
short *     +1   实际加过 2 字节
char *      +1   实际加过 1 字节
long long * +1   实际加过 8 字节

指针 ± 整数

  1. 普通指针变量 ± 整数
  2. 在数组中 ± 整数
  3. &数组名 + 1：加过的是一个数组的总大小
short arr[] = {1, 3, 5, 8, 12, 17, 19};
short *p = arr + 3;

p + 3;  // 向后（右）偏过 3 个元素，6 个字节
p - 2;  // 向前（左）偏过 2 个元素，4 个字节

合法范围：只能在数组里走

标准规定，指针只能指向：数组的某个元素，或者最后一个元素的下一位（尾后指针，one past the end）。

int arr[5];
int *p = arr;
p = arr + 4;    // 【合法】指向最后一个元素
p = arr + 5;    // 【合法】尾后指针，可以生成、可以比较，但绝不能解引用
p = arr + 6;    // 【未定义行为】连生成都是 UB
*p = 1;         // 对尾后指针解引用 → 【未定义行为】

这条规则的实际用途：for (p = arr; p != arr + 5; p++) 这种写法之所以能安全结束，就是因为"尾后指针"是合法的比较对象。但如果判断条件写成 p <= arr + 5，最后一次循环就会解引用尾后位置，越界。

指针的其他运算

运算是否允许
指针 * / %不允许！！！
指针 + 指针不允许，error！
指针 - 指针普通变量：语法允许但无实际意义；<br>数组：得到偏移过的元素个数
指针比较普通变量：语法允许但无实际意义；<br>数组：地址之间可以比大小，得到元素存储的先后顺序
int main(void)
{
    int a[] = {1, 2, 3, 4, 5, 6, 7, 8, 9, 0};
    int *p = a;         // 保存数组首地址
    p = &a[3];          // 修改 p 保存的地址
    printf("p - a = %d\n", p - a);      // ---- 3

    int *q = &a[8];
    printf("q - p = %d\n", q - p);      // ---- 5

    return 0;
}
为什么"指针 + 指针"不允许？因为两个地址相加没有任何物理意义（把两条街的门牌号加起来是什么？）。而"指针 − 指针"有意义：它问的是"两个位置之间隔了几个元素"。

p - q 的结果类型是 ptrdiff_t（有符号整数），打印用 %td。两个指针相减的前提是它们指向同一个数组，否则结果无定义。

9. 指针实现 strlen

借助数组实现

int myStrlen1(char str[])
{
    int i = 0;
    while (str[i] != '\0')
    {
        i++;
    }
    return i;
}

借助指针实现

int myStrlen2(char str[])
{
    char *p = str;
    while (*p != '\0')
    {
        p++;
    }
    return p - str;     // 返回元素个数
}

第二种写法利用了两个知识点：*p != '\0' 判断结尾，p - str 算出偏移了多少个 char（char 是 1 字节，所以偏移量就是字符数）。这也是"指针相减得到元素个数"最经典的用法。

字符串与字符指针的深入内容见 08 章。

11. 指针数组

1. 指针数组的本质，是一个二级指针。2. 二维数组是指针数组，也就是二级指针。
int a = 10;
int b = 20;
int c = 30;

int *arr[] = {&a, &b, &c};          // int 型指针数组：保存地址的数组

printf("*arr[0] = %d\n", *arr[0]);      // arr[0] == *(arr+0)
printf("*arr[0] = %d\n", *(*(arr + 0)));
printf("*arr[0] = %d\n", **arr);        // * 结合性：自右向左
int a[] = {10};
int b[] = {20};
int c[] = {30};

int *arr[] = {a, b, c};             // 存地址

printf("arr[0][0] = %d\n", arr[0][0]);
printf("*(*(arr+0)) = %d\n", *(*(arr + 0)));
printf("**arr = %d\n", **arr);      // 二级指针的间接引用

辨析两个容易混的名字（读法相反）：

写法名字是什么
int *arr[3]指针数组一个数组，里面装 3 个 int *
int (*arr)[3]数组指针一个指针，指向"含 3 个 int 的数组"

记忆法：[] 优先级高于 *。int *arr[3] 里 arr 先和 [3] 结合，所以是数组；加了括号 (arr) 才让 先结合，变成指针（第 7 节那个 int (*)[10] 就是它）。

二级指针 int ** 的完整用法见 08 章。

12. typedef：给指针类型起个名字

typedef 是"附加关键字"里最实用的一个，尤其配合指针。

12.1 解决多变量声明的坑

typedef int *PINT;      // 给 int * 起个别名 PINT
PINT p1, p2;            // p1、p2 都是 int *，都是指针！

对比不用 typedef 的写法：

int *p1, p2;            // p1 是 int *，p2 是 int  ← 坑

实测 sizeof：

PINT:   sizeof(a1)=8  sizeof(a2)=8      ← 两个都是指针
#define: sizeof(b1)=8  sizeof(b2)=4      ← b2 不是指针

12.2 别用 #define 代替

#define PINT2 int *
PINT2 b1, b2;       // 展开成 int *b1, b2;  → b2 又变成 int 了

原因：#define 是纯文本替换，PINT2 被替换成 int 四个字符， 还是只管它后面那一个变量。typedef 定义的是一个类型名，PINT 作为整体使用时，所有变量都带上指针属性。

#define 换字，typedef 生类型。涉及类型别名，一律用 typedef（C++ 里还有 using）。

12.3 简化复杂的指针类型

typedef const int *PCINT;       // 指向 const int 的指针
PCINT p = &a;                   // 比写 const int *p 更清楚

当类型变复杂（数组指针、函数指针）时，typedef 几乎是唯一可读的写法：

typedef int (*PARR3)[3];        // PARR3 是"指向含 3 个 int 的数组"的指针
PARR3 q = &arr;                 // 等价于 int (*q)[3] = &arr;

13. 两个"附加"关键字：volatile 与 restrict

它们不改变指针的用法，只影响编译器通过指针访问内存的方式。

13.1 volatile：每次都必须真的去读内存

volatile int *reg = (volatile int *)0x40000000;   // 硬件寄存器
*reg = 1;
while (*reg == 0) { }      // 每次都真读，不会被优化成死循环

编译器看到 while (*reg == 0)，会认为 *reg 在循环里没被改过，读一次就够 —— 循环被优化成死循环。volatile 告诉它：这块内存可能被程序之外的东西改变（硬件、中断、别的线程），任何读都必须真的去内存取，任何写都必须真的写下去，不许缓存到寄存器里。

用在：硬件寄存器、中断服务程序与主程序共享的变量、setjmp 涉及的变量。

注意：volatile 不保证原子性，也不保证线程安全。多线程同步要用锁或原子操作，不是 volatile。

13.2 restrict：承诺"只有我这一个指针碰这块内存"

C99 引入，只用于指针参数，是程序员的承诺，编译器据此放手优化。

void copy(int *restrict dst, const int *restrict src, int n)
{
    for (int i = 0; i < n; i++)
        dst[i] = src[i];
}

有了 restrict，编译器知道 dst 和 src 指向的内存绝不重叠，可以放心批量搬运。若你违约（实际重叠了），程序行为未定义。

这也解释了标准库里 memcpy 与 memmove 为什么是两个函数 —— 一个敢加 restrict，一个不敢。二者的具体差别见 09 章。

日常写业务代码很少手动写 restrict，但读懂标准库原型需要它。
