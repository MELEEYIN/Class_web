1. 枚举

入门★暴力详解做例题 →

本质：把所有可能的答案候选一个个试过去。难点从来不是「枚举」，而是枚举什么与如何压缩枚举量。

复杂度：O(状态数 × 单次验证代价)。优化方向：换一个维度枚举（枚举答案而非枚举方案）、子集枚举、配合前缀和/哈希把验证降到 O(1)。

例题：洛谷 P1036 选数 —— 从 n 个数里选 k 个，问有多少种选法使和为质数。n ≤ 20，直接子集枚举 2²⁰ ≈ 10⁶ 种，再加个 O(√s) 的质数判定即可。看到 n ≤ 20 就该想到 2ⁿ 枚举。

三个层次：① 枚举所有元素（O(n)）；② 枚举所有二元组（O(n²)）；③ 枚举所有子集（O(2ⁿ)，n ≤ 20）。压缩方向：换一个维度枚举（枚举答案而非方案）、用前缀和/哈希把验证降到 O(1)、加剪枝。

深入讲解 · 枚举：从「一个一个试」到「少试一个数量级」假设你只会 C++ 的基础语法
一、先建立直觉：枚举就是「一个一个试」

我给你两个任务，感受一下差别：

任务 A：在 10 个数里找出最大值。
任务 B：从 10 个数里挑出若干个，使它们的和恰好等于 100，问有几种挑法。

任务 A 你扫一眼就会 —— 这就是枚举，看一眼就懂。
任务 B 你会卡住，因为你连「候选答案」有哪些都列不出来。

这就是枚举真正的难点。所谓「枚举」，本质上是两步：

  1. 确定候选集合 —— 把所有可能的解，用一个「可遍历」的形式表示出来；
  2. 逐个验证 —— 对每个候选，判断它合不合法，或者用它更新答案。

所以复杂度天然就是 O(候选个数 × 单次验证代价)。优化也只有两条路： 减少候选个数，或者加快单次验证。卡片上写的「枚举什么」对应第一条，「压缩枚举量」两条都算。

三、模板①：子集枚举 —— 用一个整数表示一个集合

这是四个模板里最需要你啃下来的。先说思想：

一个集合有 n 个元素，每个元素只有「选 / 不选」两种状态。那就用一个 n 位的二进制整数 s 来表示这个集合 —— 第 i 位是 1，就表示第 i 个元素被选中。

于是「所有子集」和「所有 n 位二进制数」就一一对应了，也就是 0 到 2ⁿ−1。三个关键点：

  • 1 << n 就是 2ⁿ（把 1 左移 n 位 = 乘 2 乘 n 次）；
  • for (s = 0; s < (1 << n); ++s) 就把 2ⁿ 个集合全遍历了一遍；
  • s >> i & 1 在问「第 i 位是不是 1」，也就是「第 i 个元素选没选」。

把 s >> i & 1 拆开看：s >> i 把第 i 位挪到最低位，& 1 再把最低位单独取出来。结果是 1，就说明第 i 个元素被选中了。

坑 3：为什么偏偏是 n ≤ 20？这是竞赛里最关键的一个「手感」：

  • n = 20 → 2²⁰ ≈ 10⁶。如果每次验证是 O(1)，总共 10⁶，稳过；
  • 如果每次验证要 O(√V) 的质数判定（约 10⁴ 次），那 10⁶ × 10⁴ = 10¹⁰，必炸。

所以「n ≤ 20 就能 2ⁿ 枚举」这句话有个隐含前提：单次验证足够便宜。 看到 n ≤ 20 要先想 2ⁿ，但接着必须问自己「验证一次要多久」。

四、模板②：只枚举 s 的子集 —— 把 4ⁿ 压成 3ⁿ

它在干嘛？面对「我在枚举一个集合 s，同时还要枚举 s 的所有子集 t」这类问题 （例如「把 n 个物品分成三组」、「先选一个集合再从中选子集」），你当然可以写两层 0 ~ 2ⁿ 的循环，但那样是 (2ⁿ)² = 4ⁿ，n = 15 就 10⁹ 了，不行。

这段代码做的事是：固定 s 之后，只在 s 的「内部」跳，跳过所有不是 s 子集的 t。

关键在于 t = (t - 1) & s 这一句。它的效果是： 按数值从大到小，依次生成 s 的下一个子集。原理是「t - 1 会把 t 最低位的那个 1 变成 0、把右边的 0 全变成 1」，再 & s 一下，就只保留了仍然属于 s 的那些 1。

拿 s = 5（101₂，也就是 {a₀, a₂}）走一遍：

  • t = 5 → 处理 → (5-1) & 5 = 4 & 5 = 4
  • t = 4 → 处理 → (4-1) & 5 = 3 & 5 = 1
  • t = 1 → 处理 → (1-1) & 5 = 0
  • t = 0 → 处理 → 然后 if (t == 0) break; 退出

正好是 {a₀, a₂} 的全部 4 个子集：{ }、{a₀}、{a₂}、{a₀,a₂}，一个不多一个不少。 注意 break 写在处理之后，所以 t = 0 这个空集也会被处理到 —— 这个位置千万别挪。

那为什么总复杂度是 3ⁿ 而不是 4ⁿ？看这张图就懂了 —— 关键在于对每个元素来说，它只有 3 种状态：

每个元素相对 s 与 t 只有三种归属，所以全部组合数是 3ⁿ。

正式一点的证明：固定一个 s，内层要跑 2|s| 次（|s| 是 s 里 1 的个数）。 那么总次数就是所有 s 的 2|s| 之和。按「1 的个数」归并同类项：

Σs 2|s| = Σk=0..n C(n,k)·2k = (1+2)n = 3n

最后一步是二项式定理：把 (1+2)ⁿ 展开，第 k 项正好是 C(n,k)·2ᵏ。 所以 3ⁿ 不是凑出来的，是严格推出来的。n = 20 时 3²⁰ ≈ 3.5×10⁹ —— 偏大，实际用的时候一般 n ≤ 15 左右。

五、模板③：二元组 + 前缀和 —— 把验证从 O(n) 压到 O(1)

这是「求最大子段和 / 最大区间和」的暴力版本。枚举的东西没变 —— 还是枚举所有区间 [i, j]，共 O(n²) 个。变的是验证代价：

  • 朴素做法：对每个区间再 for 一遍求和 → O(n²) × O(n) = O(n³)；
  • 前缀和做法：先预处理 pre[i] = a[1] + ... + a[i]，那么 sum(i..j) = pre[j] - pre[i-1]，O(1) 直接算出来 → 总共 O(n²)。

这就是卡片上那句「用前缀和 / 哈希把验证降到 O(1)」的意思。

三个新手细节：

  • pre[0] = 0，并且数组下标从 1 开始，这样 pre[i-1] 在 i = 1 时才不会越界；
  • 1LL * (...) 里的 LL 是 long long 的后缀。 写成 1LL * x 会先把 1 变成 long long 再做乘法，避免 int 溢出 —— 这是竞赛里最常见的 WA 原因之一；
  • -1e18 是个 double 字面量，赋给 long long 时自动转换。当初值够用，但更稳的写法是 LLONG_MIN / 2。原则是初值必须比所有可能的答案都小。

顺带说说「换一个维度枚举」到底是什么，这是最高级的一招。

题目：求有多少对 i < j 满足 ai + aj = S。

  • 笨办法：枚举所有二元组 O(n²)，每组检查一次 → O(n²)；
  • 换维度：枚举 j，然后问「前面有多少个等于 S − aj」—— 用一个哈希表记录前面出现过的数，O(1) 查询 → 总共 O(n)。

枚举量从 n² 掉到 n。核心动作是把「枚举方案（二元组）」换成「枚举答案的一个端点 + 快速查另一个」。 同一招，就是「两数之和」从暴力到最优的全部关键。

六、模板④：剪枝 —— 不枚举那些「注定不行」的

搜索（DFS）本质也是枚举，只不过是把候选集合组织成一棵树，一个一个分支往下试。 剪枝就是在树的中间砍掉一整棵子树：

  • 最优性剪枝：我手上已经有答案 ans 了。如果「沿着当前分支往下， 理论上能拿到的最好结果」（best + possible_max）都不如 ans， 那这条分支就是白跑，直接 return；
  • 可行性剪枝：目标是凑 target。剩下的数全都加上 （sum + suffix[i]，suffix[i] 是后缀和）都够不着 target， 那这分支也不可能成功，直接 return。

剪枝的灵魂是「估计」 —— 你必须能算出一个「乐观上界 / 乐观下界」， 才能判断值不值得继续。估计得越准，砍得越狠。

七、例题精讲：洛谷 P1036 选数
题意：给 n 个数，从中选 k 个，问有多少种选法使它们的和为质数。（n ≤ 20）
第一步 —— 想清楚候选集合是什么：这是「从 n 个位置里选 k 个位置」，是一个组合问题。
第二步 —— 用最粗暴的方式枚举：for (s = 0; s < (1<<n); ++s)， 只要 s 里恰好有 k 个 1 就检查。n ≤ 20 → 2²⁰ ≈ 10⁶ 种，符合「看到 n ≤ 20 就想 2ⁿ」。
第三步 —— 单次验证：把选中的数加起来，再判质数。

两个必须注意的点：

  • 判质数要写对。不要写 for (i = 2; i < s; ++i) 的 O(s) 循环， 要写 O(√s)：for (i = 2; 1LL*i*i <= s; ++i)。否则 10⁶ × 10⁶ 直接超时；
  • 更快的写法是 DFS 枚举组合，而不是枚举全部 2ⁿ 个子集。 因为 C(20,10) = 184,756，比 2²⁰ = 1,048,576 少了 5 倍多。枚举子集写起来短， 但会浪费大量时间在「1 的个数不等于 k」的集合上。

深入讲解 · 模拟：把题面一字不差地翻译成代码这一篇没有算法，只有「翻译」
一、模拟题为什么最容易写错

模拟题不考算法，它考的是一件事：把自然语言规则，无损地翻译成状态机。 所有「代码量失败」都出在这里 —— 你写出来的东西，和题面描述的不是同一件事。

举个最典型的例子。题面说「小明从 1 号开始，每次往后数 k 个人」。 你的代码写 pos += k;。看起来没问题，但：

  • 「从 1 号开始」——1 号本人算不算第一个人？
  • 「往后数 k 个人」——数到的是第 k 个，还是数 k 次之后的那个？
  • 数到末尾要不要绕回开头？

这三个问题，题面里一定都写了答案，但很可能写在三个不同的段落后半句。 模拟题丢分从来不是「不会」，而是漏读一句。

为什么往前的那个要写成 (pos - 1 + n) % n？ 因为在 C++ 里 -1 % 5 的结果是 -1 而不是 4 —— C++ 的取模结果符号跟被除数走。 先加一个 n 把它抬成非负数，再取模就对了。这一行不知道坑掉过多少人。

方向数组为什么要写成两个数组？因为把「右下左上」这四个方向编码成下标 0~3 之后， 遍历方向就变成了一句 for (int d = 0; d < 4; ++d)， 以后要加对角线方向（八联通）只需要把数组改成 8 个元素，循环条件改一个数字 —— 不用动任何别的代码。

五、时间推进：逐时刻，还是按事件跳

模拟题的第二个分水岭，是时间怎么推进。

比如一题说「第 0 秒开始，每 3 秒 A 变化一次，每 5 秒 B 变化一次，问第 10⁹ 秒的状态」。
如果你写 for (t = 0; t <= 1e9; ++t) —— 10⁹ 次循环，写法没错但一定会超时。

正确做法是事件驱动：只关心「状态发生变化」的时刻。

  • 把所有会变的时间点算出来（3 的倍数、5 的倍数），排序后逐个处理；
  • 两个事件之间的「这段时间状态不变」，可以整段跳过去；
  • 如果题面说「同一时刻多个事件，规则 X 优先」，那排序的比较函数里要带上优先级 —— 这是模拟题里最容易被忽略的一句话。
六、坑清单（写完对着扫一遍）
  • 循环边界：是闭区间还是半开区间？下标从 0 还是 1 开始？写之前先定死，别中途改；
  • 取模结果可能为负：统一写 (x % MOD + MOD) % MOD；
  • 多组数据要清空：全局数组、vector、map 在每组数据开始前都得重置 —— 这是「多测不清空，爆零两行泪」的来源；
  • 输入格式：可能有空行、多余空格、行尾的 \r。 用 cin >> 或 scanf("%d") 会自动跳过空白，比 getline 省心；
  • 输出格式：行末有没有多余空格？每组之间要不要空行？最后有没有漏换行？ 模拟题对输出格式的容忍度是 0。

3. 递归

入门★思维详解做例题 →

本质：把规模为 n 的问题化为规模更小的同类问题。三要素：参数含义（函数在语义上代表什么）、边界条件、递推关系。递归是 DP、分治、搜索、树形结构的共同语言。

复杂度：由递归树节点数决定；不加记忆化常常指数级，加记忆化后转化为 DP。递归深度过大需改写成显式栈或增加栈空间。

补充（来自「学习计划」里的同名卡片）：

💡 递归为什么必须配记忆化

fib(40) 朴素递归要调用约 3.3×10⁸ 次；加记忆化后每个 n 只算一次，只有 40 次。同一段递归，一个超时一个秒过，差别只在于「有没有把算过的答案存下来」。

🚫 递归的两个坑

① 忘记写边界。递归会一直往下钻到栈溢出（RE）。
② 递归太深。深度超过 10⁵ 层就会爆栈。解决办法：改写成迭代 / 显式栈，或者提高编译栈空间（-Wl,--stack=268435456）。

深入讲解 · 递归：把大问题交给「规模更小的自己」递归的三要素 + 为什么会指数爆炸
一、先想明白一件事：递归不是「函数调用自己」

「函数调用自己」是递归的语法，不是它的思想。真正的思想是一句话：

如果我知道了「规模更小的同一个问题」的答案，我能不能拼出当前这个问题的答案？

举个例子。我问你「n! 是多少」，你答不上来；但我换个问法：「如果你已经知道 (n−1)! 是多少， n! 怎么算？」你立刻就能答：乘以 n 就行。这就是递归。

所以写递归永远只做三件事，顺序也不能变：

  1. 语义 —— 我这个函数的参数和返回值，用一句话说清楚代表什么。 例如「fib(n) 返回第 n 项斐波那契数」。这一句不说清楚，边界一定会写错；
  2. 边界 —— 最小规模（不用再递归）的答案是多少。例如 fib(0) = 0, fib(1) = 1；
  3. 递推 —— 大问题怎么由小问题拼出来。例如 fib(n) = fib(n-1) + fib(n-2)。

绝大多数人的递归写错，不是第三点写错，而是第一点根本没想。

二、递归树：为什么朴素递归会「指数爆炸」

看最经典的例子 fib(5) 展开成什么样子：

朴素递归里 fib(3) 被重复计算，总调用量指数级；加记忆化后每个规模只算一次。

fib(3) 被算了 2 次，fib(2) 被算了 3 次，而它们每次的答案完全一样。这就是浪费的来源。

规模一大就非常恐怖：fib(40) 朴素递归要调用约 3.3×10⁸ 次；而加一行记忆化之后，每个 n 只算一次，总共 40 次。 同一段递归，一个超时一个秒过，差别只在于「有没有把算过的答案存下来」。

三、两套模板：朴素递归 与 记忆化搜索

记忆化的含义要想透：所谓「自顶向下的 DP」，就是「我要算 fib(40)」， 但我不去按 0、1、2…40 的顺序填表，而是从 40 出发，需要谁就算谁，算完记下来。 两者算的是同一张表，只是遍历顺序相反。

看到「重复子问题」这五个字，就该想到记忆化。判断方法：把递归树画两层， 如果出现两个长得一模一样的节点（参数相同），那么它就是重复子问题。

四、例题精讲：洛谷 P1255 数楼梯
题意：楼梯有 n 阶，每次可以跨 1 阶或 2 阶，问有多少种走法。
第一步 —— 定义语义：设 f(n) 表示「走到第 n 阶的走法数」。
第二步 —— 边界：f(1) = 1（只能跨 1 阶），f(2) = 2（1+1 或 2）。
第三步 —— 递推：最后一步只有两种可能 —— 从第 n−1 阶跨 1 阶上来，或从第 n−2 阶跨 2 阶上来。 所以 f(n) = f(n-1) + f(n-2)。

看出来了吗？这题的递推式和斐波那契一模一样，只是换了起始值。 竞赛里大量「数方案」的题，最后都会落到这种「最后一步分类讨论」的思路上 —— 这就是「线性 DP」的起点。

P1255 的额外坑：n 可以到 5000，答案是天文数字，long long 存不下。 要么写高精度（数组存每一位），要么用 Python 大整数。这是这道题真正的考点 —— 先想清楚「答案有多大」，再决定用什么类型存。

五、两个必须躲开的坑
  • ① 忘记写边界。递归会一直往下钻，直到栈空间被吃光 —— 结果是 RE（运行错误）， 而且报错位置往往指不到你真正出错的那一行；
  • ② 递归太深。深度超过 10⁵ 层左右就会爆栈。三条出路： 改成迭代 / 显式栈；把递归改写成从小到大的递推（DP）；或者提高编译栈空间 -Wl,--stack=268435456。

一个实用的检查顺序：写完递归先别跑，盯着代码问自己三句话 —— 「最小时会不会停？」「每一层的参数有没有变小？」「同一个参数会不会算两次？」。 前两问防 RE，第三问防超时。

4. 前缀和与差分

入门★★高频详解做例题 →

本质：前缀和把「区间求和」变成「两次单点查询」；差分把「区间修改」变成「两次单点修改」。二者互为逆运算，是离线区间操作的第一把钥匙。

复杂度：预处理 O(n)，单次询问/修改 O(1)。进阶延伸：二维差分、树上差分（点差分/边差分）、差分约束。

补充（来自「学习计划」里的同名卡片）：

🎯 判断「该用前缀和还是差分」

修改少、查询多 → 前缀和（一次预处理，之后查询 O(1)）
修改多、查询少（或只在最后查一次）→ 差分（修改 O(1)，最后统一还原）
看到「若干次区间加，最后输出每个位置的值」——这几乎是差分的标准信号。

例题：数组 [1,2,3,4,5]，依次执行「[1,3] 各 +2」「[2,5] 各 −1」，求最终数组与最小值。
差分写法：d[1]+=2, d[4]-=2; d[2]-=1, d[6]+=1，前缀还原后得到 [3, 3, 4, 3, 4]，最小值 3（已用独立实现跑过）。若用暴力循环修改，每次 O(n)，区间多时直接超时。

深入讲解 · 前缀和与差分：一对互为逆运算的「记账」技巧区间问题的第一把钥匙
一、先从「求区间和」说起

题目：给一个数组，之后有 10 万次询问，每次问「第 l 个到第 r 个的和」。

最直白的写法是每次询问都 for (i = l; i <= r; ++i) sum += a[i]。 单次 O(n)，10 万次就是 10¹⁰ —— 超时。问题出在每次都在重复算同一段前缀。

那就在最开始把「所有前缀的和」一次算完，存进另一个数组：

pre[i] = a[1] + a[2] + ... + a[i]，预处理 O(n)。
之后任何区间和 sum(l, r) = pre[r] − pre[l−1]，一次减法，O(1)。

这是「用一次预处理，换掉之后所有重复计算」的第一次出场 —— 后面你会反复见到这个套路（排序、离散化、ST 表、莫队……都是同一个想法）。

二、差分：把同一件事反过来想

现在把问题反过来：不是「问你区间和」，而是「给 10 万次区间加，最后问每个位置是多少」。

朴素做法：每次把区间里每个数都加上 v，单次 O(区间长) → 又是 10¹⁰。

差分的思想是：不要在区间里每个位置都改，只在「开始的地方」和「结束的下一格」记两笔账。 最后从头到尾累加一遍，账就自动"摊开"到每个位置了。

区间加只在两端记两笔账，最后累加一遍就自动摊到每个位置。

为什么会这样？把「累加」这一步单独看：a[i] = a[i-1] + d[i]， 也就是说 a 其实就是 d 的前缀和。

所以前缀和与差分的关系是：

d 的前缀和 = a，a 的差分 = d —— 两者互为逆运算。
差分"还原"的过程，本身就是在做一次前缀和。
三、二维：多出来的那一块要减回去

一维只有「左」和「右」，二维多了「上」和「下」，于是出现了重叠 —— 这就是容斥。

二维前缀和是容斥：左上角被算重复了，要减掉一次。

把公式和这张图对着看：S[i-1][j] 覆盖了左上 + 左下， S[i][j-1] 覆盖了左上 + 右上，左上那块被算了两次，所以要减掉一次 S[i-1][j-1]，再加上当前格 a[i][j]。

记忆口诀：「加两个、减一个、再加自己」。子矩阵和的公式同理， 只是把「两个」变成「四个角」，符号是 + − − +。

二维差分正好相反，也是四个角，符号同样是 + − − + —— 但它是作用在差分数组上的「打标记」，最后做一次二维前缀和还原。两套公式长得像，别记混方向。

四、到底该用哪个？一句话判断

修改少查询多用前缀和，修改多查询少用差分。

再补一个容易忽略的兄弟：前缀异或。因为异或的逆运算是它自己（x ^ x = 0）， 所以 xor(l, r) = px[r] ^ px[l-1]，一样是 O(1)。

但前缀 gcd 不行 —— 因为 gcd 不可逆，你没法从 gcd(1..r) 和 gcd(1..l-1) 反推出 gcd(l..r)。区间 gcd 要用 ST 表或者线段树。「能不能用前缀和」的判断标准是： 这个运算有没有逆运算。

五、例题精讲：洛谷 P2367 语文成绩
题意：n 个同学的分数，p 次操作，每次给区间 [l, r] 的每个人加 v。 最后输出最低分。
第一步判信号：「若干次区间加，最后输出每个位置的值」—— 这是 差分的标准信号，几乎不用想。
第二步写：d[l] += v; d[r+1] -= v; 全部操作做完， 一趟前缀累加还原出每个人最终的成绩，顺手取 min。
第三步看边界：d[r+1] 在 r = n 时会写到 n+1， 数组一定要开到 n+2，否则越界。

复杂度：O(n + p)。暴力是 O(np)。

六、坑清单
  • 下标要从 1 开始。前缀和公式里出现 pre[l-1]，l = 1 时会碰到 pre[0]。所以 pre[0] = 0 是必须的，数组也多开一格；
  • 差分数组要开 n+2。因为会写 d[r+1]；
  • 注意溢出。n 个 10⁹ 加起来会超过 int，前缀和要用 long long；
  • 别把「离线」忘了。差分只有在「所有修改做完之后再统一查询」时才 O(1) 生效。 如果题目要求「每次修改之后立刻回答一次查询」，那就要用树状数组 / 线段树，差分救不了。

这两种技巧值得你练到不用想：它们的代码都不到五行，但能不能想到用它们， 直接决定这道题是 O(n²) 还是 O(n)。做题时看到「区间」两个字，先问一句 「是问和，还是改值？」—— 问和想前缀和，改值想差分。

5. 尺取法（双指针 / 滑动窗口）

入门★★高频详解做例题 →

本质：当「区间的可行性关于包含关系单调」时，右端点右移只会让左端点单调右移，于是两个指针总共走 O(n) 步。经典形态：同向双指针（最长/最短满足条件的子段）、相向双指针（有序数组两数之和）、快慢指针（链表）。

复杂度：O(n)（每个元素最多进出窗口一次）。前提必须验证单调性，否则不成立 —— 这也是最常见的误用。

深入讲解 · 尺取法：一条只会往前爬的「蠕虫」核心不是模板，是「单调性」
一、先看它解决了什么问题

题目：给一个正整数数组，求和恰好等于 S 的连续子段有多少个。

暴力枚举所有子段是 O(n²)。尺取法的想法很朴素：把子段想象成一条蠕虫， 左端点是头，右端点是尾。尾巴先往前拱，拱到"太长"了，头再往前拱一点。

整个过程里，头只往右，尾只往右，谁也不回头。所以两个指针加起来一共只走约 2n 步， 总复杂度 O(n)。

二、凭什么可以「不回头」—— 单调性

这是整篇最重要的一段，模板反而次要。

为什么头可以放心地只往右走？因为我们用了一个性质：数组全是正数。

  • 尾巴往右挪一格 → 窗口的和只会变大；
  • 头往右挪一格 → 窗口的和只会变小。

所以当「窗口和 > S」时，把尾巴再往右挪不可能让和变小， 唯一能做的就是让头往右。这就是「不回头」的依据。

反过来说：如果数组里有负数，这招立刻就废了。 因为尾巴往右挪可能让和变小、头往右挪也可能让和变大，两个指针都失去了方向。 这是尺取法最常见的误用 —— 看到题先确认有没有单调性，再动手写模板。

更通用的说法是：「区间的可行性关于包含关系单调」。也就是 「如果 [l, r] 已经不合法了，那么任何包含它的更大区间 [l', r'] 也不合法」。满足这条，才能用双指针。

三、两个指针怎么动

两个指针都只朝一个方向走：尾巴每步 +1，头在窗口非法时才右移。

四、四套模板，覆盖九成的双指针题

四套模板的共同骨架其实只有一句： for (r ...) { 把 r 纳进来; while (不合法) 把 l 吐出去; 记录答案; }。 A 和 B 是同一套骨头，只是「不合法」的定义不同；C 是两个指针相向而行；D 是同一个方向、不同速度。

为什么 while 不是 if？ 因为把头只挪一格可能还不够 —— 比如窗口里塞进了两个"坏元素"，得挪两次才合法。 写成 while 才不会漏。这一段写成 if 是双指针最经典的 bug： 样例能过，大样例就错。

五、例题精讲：洛谷 P1147 连续自然数和
题意：给一个 M，找出所有「连续的自然数之和等于 M」的区间。
第一步判单调性：自然数全是正的，尾巴往右和变大、头往右和变小 —— 满足单调性，可以用双指针。
第二步套模板 B：sum > M 就收头，sum == M 就记录。
第三步想边界：题面要求「至少两个数」，所以 r > l 才记录； 区间上界不用穷举到 M，因为 1 + 2 + ... 到某个长度就超过 M 了， 上界取 M/2 + 1 足够。

另一道更典型的：P1638 逛画展 —— 求「包含所有画家的最短区间」。 这题用的是模板 A：用一个计数数组统计窗口里每个画家出现几次， 再维护一个「窗口里不同画家的个数」变量。当它等于总数时窗口合法，此时收头求最短。

「维护一个计数变量」是模板 A 的关键技巧。不要每次都重新数一遍窗口里有几种画 —— 那样单次就是 O(窗口长)。正确做法是：add 时若该画家计数从 0 变 1，种类数 +1； remove 时若计数变成 0，种类数 −1。这样每次移动都是 O(1)。

六、坑清单
  • 没验证单调性就写。数组里有负数时，同向双指针直接失效 —— 这时应该用前缀和 + 哈希表；
  • 把 while 写成 if。见上文；
  • 计数数组忘了清零 / 忘了边界。remove 之后要把计数减回去， 否则下一次 add 判断就错了；
  • 「最短」和「最长」的记录位置不同。 求最长：窗口合法时用当前 r − l + 1 更新； 求最短：在 while 循环内部每收一次头就更新一次， 因为收头的过程中每一个位置都可能是合法的最短窗口。

6. 排序算法的原理理解

入门★★必背详解做例题 →

本质：排序是「用比较换信息」。真正要掌握的不是会写快排，而是：稳定性、是否原地、比较次数下界 O(n log n)、以及非比较排序（计数/基数/桶）何时能突破下界。

补充（来自「学习计划」里的同名卡片）：

🚫 比较函数的死亡写法 
bool cmp(int x, int y){ return x >= y; }   // ❌ 相等时返回 true，违反严格弱序 → RE

规则：相等时必须返回 false。写成 x > y 而不是 x >= y；写结构体排序时，把「层层比较」写成 if 串，最后一行一定返回 false 的等价形式。

✅ 实测：稳定排序 vs 不稳定排序

对 [(1,5),(2,5),(3,4)] 按分数降序：stable_sort 一定输出 [(1,5),(2,5),(3,4)]；sort 在小数组上通常也一样，但不保证。凡是题目说「相同分数按输入顺序输出」——必须用 stable_sort 或者把原始下标写进比较函数。

🔎 排序家族：sort / stable_sort / nth_element
sort(first, last) ｜ sort(first, last, cmp)
作用：区间升序 / 按 cmp 排序。复杂度：O(n log n)（内省排序：快排 + 堆排 + 插入排序的混合）。不稳定。
cmp 的语义：cmp(a, b) 返回 true 表示 a 应该排在 b 前面。所以降序写 [](int a, int b){ return a > b; }。
硬性要求：cmp 必须满足严格弱序 —— 也就是 cmp(x, x) 必须返回 false。写成 >= 或 <= 会让排序内部越界，直接 RE。
greater<int>() / less<int>()
作用：标准库提供的比较器函数对象，在 <functional> 里。greater 表示「大的在前」（降序），less 表示「小的在前」（升序，也是默认）。
用法：sort(v.begin(), v.end(), greater<int>());，比手写 lambda 短。
stable_sort(first, last, cmp)
作用：稳定排序 —— 排序后值相等的元素保持原来的相对顺序。
什么时候必须用：题目说「分数相同时按输入顺序输出」。
替代方案：用 sort，但在比较函数里加上「以原始下标为第二关键字」，效果一样而且更可控。
复杂度：有额外空间时 O(n log n)，空间不够时退化为 O(n log²n)。
nth_element(first, nth, last)
作用：执行完保证 *nth 这个位置放的就是「排序后应该在这里的元素」，且它左边都不大于它、右边都不小于它。
返回值：无。复杂度：平均 O(n)。
典型场景：求第 k 小（或中位数）时，比完整排序快。注意它不保证两侧有序。
自定义比较的两种写法
① lambda：sort(v.begin(), v.end(), [](const T &a, const T &b){ ... }); —— 临时用一次时最方便。
② 结构体重载 operator<：bool operator<(const Node &o) const { ... } —— 排序逻辑固定时更清晰，而且 sort、set、priority_queue 都能直接用。
建议：多关键字排序写成一串 if，最后一定要能返回「相等时为 false」。

深入讲解 · 排序：真正要掌握的不是「会写快排」稳定性 / 严格弱序 / 离散化
一、为什么「比较排序」突破不了 O(n log n)

这不是背结论，是一个很漂亮的推理，值得你花三分钟想通。

任何基于「两两比较」的排序，整个过程可以画成一棵决策树： 每个内部节点是一次比较（a < b？），两条分支是两种结果，每个叶子是一种可能的输出顺序。

  • n 个数一共有 n! 种排列，每种都可能成为答案 → 决策树至少要有 n! 个叶子；
  • 一棵高度为 h 的二叉树最多有 2h 个叶子；
  • 所以 2h ≥ n!，取对数用斯特林公式就有 h ≥ n log n。

结论：只要你是靠比较来决定顺序的，就至少要比较 n log n 次。 这就是为什么 std::sort 的最坏复杂度停在 O(n log n) 上不去。

那怎么突破它？答案是不比较。计数排序、基数排序、桶排序都是 「不看两个数谁大谁小，而是直接利用数值本身的信息」—— 比如「这个数等于 5，那就放到第 5 个桶里」。 所以它们的复杂度写成 O(n + V) 或 O(k·n)， 里面对数的那一项消失了。代价是要求值域小或者位数少。

二、稳定性：相等元素的相对顺序会不会被打乱

这个概念一句话就能说清：排序前 a 在 b 前面，且 a 和 b 的"比较键"相等， 排序后 a 还在 b 前面 —— 这就是稳定的。

为什么它重要？因为现实里的排序键往往只是"一部分信息"。比如按分数降序排一张成绩表， 分数相同的人应该保持原来的（比如学号）顺序。这时如果用了不稳定的排序， 同分的人可能被打乱 —— 题目如果说「分数相同的按输入顺序输出」，你就直接 WA 了。

两个解法，选一个：
① 用 stable_sort；
② 更推荐：用普通 sort，但在比较函数里把原始下标作为第二关键字。 这样效果一样，而且「稳定性」成了你自己代码的一部分，不受标准库实现影响。

四、比较函数：竞赛里最容易 RE 的一行

比较函数有一个硬性要求：必须满足严格弱序。 用大白话说就是两条：

  1. 自己不能小于自己：cmp(x, x) 必须返回 false；
  2. 不能互相小于：cmp(a, b) 和 cmp(b, a) 不能同时为真。

违反它的后果不是"排出来顺序怪怪的"，而是 std::sort 内部越界访问，直接 RE （因为它的实现会在数组前面放一个哨兵元素，依赖这个性质）。

怎么保证自己没写错？一个机械的检查法：把最后一行的相等情况代进去试试。 上面那个结构体，如果 score 和 id 都相等， 第一行不成立，落到 return id < o.id —— 相等时返回 false ✓。

五、排序最实用的一次副产品：离散化

题目给的值范围是 1 ~ 10⁹，但你只关心它们之间的大小关系， 而且 n 只有 10⁵。这时把它们压成 1 ~ n 的排名，就能用数组做桶 / 树状数组了。 这个操作叫离散化，是排序的一次经典副产品。

这三行的顺序不能乱：先排序，才能用 unique；先 unique，二分查到的才是唯一的排名。 如果先去重再排序，去重是没用的（unique 只把相邻的重复元素移到末尾）。

记住 unique 的真实行为：它不删除元素，只是把不重复的元素挪到前面， 返回「新的逻辑结尾」的迭代器，剩下的元素内容是不确定的。 所以必须紧跟着 erase，否则容器长度没变。

六、例题精讲：洛谷 P1093 奖学金
题意：按总分降序排序，总分相同按语文降序，语文也相同按学号升序。
解法：这就是一个纯粹的多关键字排序 —— 把「层层比较」写成一串 if：
if (总 != o.总) return 总 > o.总;
if (语文 != o.语文) return 语文 > o.语文;
return 学号 < o.学号;
注意最后一行：学号是唯一的，所以这一行永远不会遇到"全相等"的情况 —— 但就算万一遇到了，< 也保证了相等时返回 false，依然安全。

这道题真正的训练价值：以后凡是遇到「优先级从高到低的一系列比较条件」， 都用这个「一串 if 收尾」的骨架，一次都不用去想排序的其余部分。

七、坑清单
  • 比较函数用了 >= 或 <= → RE。见上文；
  • 比较函数里改状态。比较函数会被调用 O(n log n) 次，任何带副作用的操作都会炸；
  • 浮点数比较。不要写 a.x < b.x，要用 a.x < b.x - eps 之类，否则同值的浮点会被判成不等，顺序随机；
  • sort 区间写成了闭区间。sort(a, a + n) 是左闭右开；如果是 1-based 数组，要写 sort(a + 1, a + 1 + n)；
  • 拿 sort 去求第 k 小。那样是 O(n log n)。只求一个第 k 小时用 nth_element，平均 O(n)；
  • 需要 Top-K 且数据流式到来。不要每次重排，维护一个大小为 k 的堆，O(n log k)。

这一节真正的产出是两个习惯：① 写比较函数时，习惯性检查「相等时返回什么」； ② 看到值域很大但只关心相对大小，立刻想到离散化。

7. 二分与三分

入门★★★必背详解做例题 →

本质：二分 = 在单调的判定函数上找分界点。写对二分的唯一诀窍是明确「check(mid) 为真时答案落在哪一半」，然后让循环不变式保持不变。三分 = 在单峰/单谷函数上比较两侧导数。

复杂度：O(log n)，实数二分按精度迭代约 60~100 次即可达到 1e-15。二分答案的总复杂度是 O(log V × check)。

补充（来自「学习计划」里的同名卡片）：

🚫 二分最容易死在哪

① 死循环。「最大化」的模板必须用 mid = l + (r-l+1)/2（上取整）；「最小化」用 mid = l + (r-l)/2。用错了当 r = l+1 时会永远 l = mid = l。
② 边界开错。lo 取「一定可行」的值，hi 取「一定不可行」的值，宁可放宽一点。
③ 忘记排序。二分的前提是有序或单调，没排序直接二分 = 随机结果。

🔎 lower_bound 与 upper_bound 到底差在哪
lower_bound(first, last, x)
含义：第一个 ≥ x 的位置（lower = 下界，包含等于）。
返回：迭代器 / 指针，找不到返回 last。复杂度：O(log n)（比较次数 ≤ log₂n + 1）。
前提：区间必须按 < 有序。
upper_bound(first, last, x)
含义：第一个 > x 的位置（upper = 上界，跳过所有等于 x 的）。
返回：同上。复杂度：O(log n)。
x 的出现次数 = upper_bound(...) - lower_bound(...)
这是两个函数最经典的组合用法：
long long cnt = upper_bound(a, a+n, x) - lower_bound(a, a+n, x);
两者之差正好是「等于 x 的元素个数」，因为 [lower, upper) 就是所有 x 排成的区间。
注意指针相减的结果类型是 ptrdiff_t（有符号），可以放心用；但迭代器相减得到的是「元素个数」，不是字节数。
在「下降序列」上怎么用
默认版本假设升序。如果数组是降序的，要么先反转、要么传自定义比较器 greater<int>()：
lower_bound(a, a+n, x, greater<int>());
更省事的做法：把 「找最后一个 ≥ x」这类需求统一转成「在反转后的数组上找第一个」，思路更清楚。
set / map 的 lower_bound 是「成员函数」
重要区别：set<int> s; 要用 s.lower_bound(x)（成员函数，O(log n)）。
如果写成 lower_bound(s.begin(), s.end(), x)（全局算法），因为 set 的迭代器不支持随机访问，每次都只能一步一步挪，复杂度退化成 O(n) —— 这是很隐蔽的性能陷阱。

深入讲解 · 二分：在一串 0 后面找第一个 1把「写不对」变成「一定写得对」
一、先扔掉「猜数字」那个比喻

所有人初学二分听的都是「猜 1~100 之间的数」。这个比喻让你懂了「每次砍一半」， 但它解释不了你为什么写不对二分。真正有用的模型是下面这个：

有一个关于 x 的判定函数 check(x)，它的取值只有 真 / 假 两种，而且满足 「前面全是假，后面全是真」（这叫单调）。
二分就是在这一串 假 后面，找到第一个 真。

为什么这个模型有用？因为一旦你把题目翻译成这个模型， 「数组下标」这件事就消失了 —— 剩下的只是「区间在缩小」，你不会再去纠结 mid + 1 还是 mid − 1。

二、二分在做什么

二分就是在一串 0 里找第一个 1：check(mid) 为真就往左收，为假就往右收。

看这张图，你只要记住一句话：每次拿到 mid，先问「mid 是 0 还是 1」， 然后想「答案在 mid 的左边还是右边」。

如果 check(mid) 是真，说明 mid 已经在"1 那一段"里了， 但答案可能是 mid 左边更靠前的那个 1，所以 hi = mid（注意不是 mid − 1，因为 mid 本身还有可能是答案）；
如果是假，说明 mid 还在"0 那一段"里，答案一定在它右边，所以 lo = mid + 1。循环结束时 lo == hi， 那就是分界点。

三、两套模板与它们的「配套口诀」

「lo + (hi - lo) / 2 而不是 (lo + hi) / 2」 不是洁癖 —— 当 lo、hi 都是接近 INT_MAX 的大数时， lo + hi 会溢出成负数，然后数组越界 / 死循环。 加法改成减法，就永远不会溢出。这是个真实存在过的 bug（JDK 的 Arrays.binarySearch 就踩过）。

两套模板的记忆口诀：

  • 谁可行就留住谁 —— 模板 1 里 mid 可行就 hi = mid（留住 mid）， 模板 2 里 mid 可行就 lo = mid（也是留住 mid）；
  • 只要写了 lo = mid，就必须向上取整 —— 反过来， 写了 hi = mid 就用向下取整。这是唯一需要死记的一条。
四、为什么会死循环 —— 一个必须看懂的例子

区间只剩两个数时，取整方向决定区间是否还在缩小；不缩小就是死循环。

把区间缩到只有两个数（lo = 5, hi = 6）看： 如果写成「向上取整 + hi = mid」，那么 mid = 6， 若 check(6) 为真就 hi = 6 —— 区间原封不动，循环永远出不去。

反过来也有对应的死法：「向下取整 + lo = mid」时， mid = 5，若 check(5) 为真就 lo = 5 —— 同样原地打转。
所以「lo = mid 配向上取整」这一条不是建议，是必须。

五、二分答案：把「求最值」变成「判定可行性」

二分真正值钱的地方在这里。很多题不是让你在一个数组里查东西， 而是让你求一个「最大的最小值」或者「最小的最大值」。这类题的标准流程是：

  1. 确定答案的范围 [lo, hi]。不要凭感觉 —— 要从题面推。比如「砍树的高度」范围就是 [0, max(树高)]；
  2. 写 check(mid)：假设「答案是 mid」，判断这件事可不可行。 这一步往往就是一遍简单的贪心或者模拟；
  3. 判断单调方向：是「越大越容易满足」还是「越小越容易满足」， 这决定你用哪套模板。

为什么这样是对的？因为「可行性」通常关于答案大小是单调的： 如果高度 x 能砍够木材，那么比 x 矮的任何高度也一定能砍够。 于是「可行」这件事就变成了「一串 假 后面跟着一串 真」—— 正好是二分要找的分界点。

总复杂度是 O(log V × check 的代价)。 看到 10⁹ 级别的答案范围 + 一个容易验证的可行性条件，就该想到二分答案。

六、例题精讲：洛谷 P1873 砍树
题意：n 棵树各有高度，选一个锯片高度 H，把所有比 H 高的树砍掉高出的部分， 问「砍下的木材总量 ≥ M」的前提下，H 最大是多少。
第一步 —— 范围：lo = 0, hi = max(树高)。
第二步 —— check(H)：遍历所有树，sum += max(0, h[i] - H)， 判断 sum >= M。
第三步 —— 单调方向：H 越小，砍下的木材越多 → 「H 越小越容易满足」， 而我们要的是最大的 H。用模板 2。
注意：木材总量可能超过 int，sum 要用 long long。

把它和「在数组里查找一个数」对比一下 —— 你会发现二分答案的 check 就是一次独立的小问题，而二分只是套在外面的一层壳。 想清楚 check 怎么写，题就做完了一半。

七、三分：单峰函数上的"找山顶"

二分要求单调；如果函数是先升后降（单峰）或者先降后升（单谷）， 就轮到三分出场了。做法是取两个三等分点 m1 < m2， 比较 f(m1) 和 f(m2)：

  • 求最大值时：若 f(m1) < f(m2)，说明山顶在 m1 右边， 舍去左边 → lo = m1；否则舍去右边 → hi = m2；
  • 求最小值时反过来。

整数三分要小心：当区间长度只剩 2 或 3 时，两个三等分点可能重合。 稳妥的写法是长度很小时直接暴力比较剩下的几个点，别硬套公式。

八、坑清单
  • 死循环 —— 唯一原因是取整方向与 lo = mid / hi = mid 不配套；
  • 边界开错：lo 取「一定可行 / 一定在答案左侧」的值， hi 取「一定不可行 / 一定在答案右侧」的值，宁可放宽一点；
  • 忘了先排序。在无序数组上二分 = 得到随机结果，而且不报错；
  • 实数二分用 while (r - l > eps) 可能迭代次数过多或过少。 固定循环 80~100 次更稳（80 次已经能到 10⁻²⁴ 的精度，远超 double 极限）；
  • set / map 用全局 lower_bound。 因为它们的迭代器不支持随机访问，全局算法会退化成 O(n)。 必须用成员函数 s.lower_bound(x) —— 这是个很隐蔽的性能陷阱；
  • 二分答案时 check 写成了 O(n²)。那总复杂度就变成 O(n² log V)，照样超时。

这一节要练成的反射：看到「最大化的最小值 / 最小化的最大值」→ 二分答案； 看到「有序数组上找第一个 ≥ x」→ lower_bound； 看到「先增后减」→ 三分。以及那句口诀要背下来：谁可行就留住谁，写 lo = mid 就向上取整。

8. 分治

入门★★思维详解做例题 →

本质：把问题切成互不相交的子问题分别求解再合并。复杂度由主定理给出：T(n) = aT(n/b) + f(n)。分治的难点在 merge，不在 divide。

复杂度：归并/快速排序 O(n log n)；快速幂 O(log n)；CDQ 分治 O(n log² n)。

题单 洛谷 P1908 逆序对 · P1010 幂次方 · P1228 地毯填补问题 · P1966 火柴排队（排序+逆序对）· P1429 平面最近点对（分治经典，也是计算几何入门）。

资料 OI-Wiki「递归 & 分治」「CDQ 分治」；《算法竞赛进阶指南》0x05 节。

深入讲解 · 分治：切、治、合，难点在「合」为什么归并能顺手数出逆序对
一、分治就是三步，但第三步最容易想不明白

分治（Divide and Conquer）听起来很抽象，其实就是三个动作：

  1. 切（divide）：把大问题拆成几个规模更小、结构相同的子问题；
  2. 治（conquer）：递归地把子问题解决掉（规模足够小时直接给答案）；
  3. 合（merge）：把子问题的答案拼成原问题的答案。

第 1、2 步是机械的 —— 几乎所有分治题的切法都是「从中间切一半」。 真正需要动脑、也真正决定这道题能不能做出来的是第三步。 很多人的分治学不会，就是因为只背了模板的骨架，没有想清楚「合什么、怎么合」。

归并排序的「合」是什么？「我有两个已经排好序的数组，怎么把它们并成一个有序数组？」 —— 双指针一次扫描就够。
逆序对的「合」是什么？「数出所有『左半边元素 > 右半边元素』的数对个数。」 —— 恰好可以在上面那次扫描里顺便数出来。

所以分治题的正确切入方式是：先想「如果我拿到了两个子问题的答案，我能不能拼出来」， 再去写代码。

二、分治树与「合」的时机

先递归排好左右两半，合并时顺便数出跨过中点的逆序对 —— 每次合并都是线性的。

看图注意一件事：逆序对的统计发生在"合"的那一步，不是"切"的那一步。 每一层的合并只负责数「跨过中点的逆序对」（左半边取一个、右半边取一个）， 而「两个都在左半边」或「两个都在右半边」的逆序对，由下一层的递归负责。 一层一层加起来，就一个不漏。

为什么可以一次数出 (mid − i + 1) 个？ 因为左半边是有序的。当 a[i] > a[j] 时， a[i], a[i+1], ..., a[mid] 全都大于 a[j] （它们都比 a[i] 还大）。所以不用一个个数，一次就知道有 mid − i + 1 个。

这一句话就是整道题的核心。如果一个元素比 a[j] 大，那么它后面所有元素也都比 a[j] 大吗？ —— 只有当这一段有序时才成立。所以「先递归排好序，再合并时统计」这个顺序不能反。

三、模板：归并排序 + 逆序对

三个容易写错的地方：

  • tmp 必须用全局数组（或提前分配好）。 在递归函数里 new 一个数组会慢到超时；
  • 判定写成 a[i] <= a[j] 而不是 <。 写成严格小于会让「相等的两个元素」也被算成逆序对 —— 题目问的通常是「严格大于」构成的逆序对；
  • 最后一定要把 tmp 写回 a。 忘了这一步，排序结果永远不生效，但递归还是会跑完（不报错，只是答案错）。
四、分治的复杂度怎么算 —— 主定理速查

分治的复杂度写成递推式 T(n) = a·T(n/b) + f(n)： 把问题切成 a 份，每份大小是 n/b，合并的代价是 f(n)。入门阶段你只需要记住下面几种形状：

递推式复杂度典型算法
T(n) = T(n/2) + O(1)O(log n)二分查找、快速幂
T(n) = 2T(n/2) + O(n)O(n log n)归并排序、快速排序
T(n) = T(n/2) + O(n)O(n)线性选择（nth_element）
T(n) = 2T(n/2) + O(n²)O(n²)朴素分治失效，合并太贵

怎么快速判断？看「切开之后的合并代价」和「叶子结点总数」谁大：

  • 合并是线性的、叶子有 n 个 → 一共 n log n（每一层都是 n，共 log n 层）；
  • 合并是线性的、但只往下走一条路（a = 1）→ 一共 n（只有一层有效代价）；
  • 合并比线性还贵（比如 O(n²)）→ 分治白做了，总复杂度被最贵的那一层压住。

用「每一层总共花了多少」横向相加，比死记主定理公式更好用。 归并排序每一层都是 n，一共 log n 层，所以是 n log n —— 就这么简单。

五、快速幂：最迷你的一个分治

「求 ab mod p」，b 可以到 10¹⁸。 朴素做法循环 b 次 —— 不可能。分治的想法是：

ab = (ab/2)² —— 只要算出「一半」的答案，平方一下就是整个答案。
所以问题规模每次减半，一共只需 log b 步。

写成迭代形式就是那五行经典代码。注意几个细节：初值要写 1 % p 而不是 1（因为 p 可能等于 1，答案是 0）； 每次乘法都要 % p，否则溢出。

六、例题精讲：洛谷 P1908 逆序对
题意：求数组里有多少对 (i, j) 满足 i < j 且 ai > aj。
朴素做法：枚举所有数对，O(n²)。n = 5×10⁵ 时是 2.5×10¹¹，必炸。
分治做法：直接用上面的归并排序，一次 O(n log n)。
另一种做法：树状数组 / 离散化 + 前缀和，也是 O(n log n)。两种都对， 归并的代码短但要理解「合」；树状数组的思路更通用（能扩展到多维偏序）。

答案要用 long long。n = 5×10⁵ 时逆序对最多有 n(n−1)/2 ≈ 1.25×10¹¹ 个，int 装不下 —— 这是这道题最经典的一个 WA 原因。

七、坑清单
  • 递归边界写成了 l > r 而不是 l >= r。 前者在只剩一个元素时还会继续递归，栈会无限加深；
  • 临时数组每次重新分配。放进递归里 vector<int> tmp(r - l + 1) 看着干净，但每次分配内存会把复杂度常数抬高好几倍，n 大时直接 TLE；
  • 合并代价估计错。如果你在合并时对每个元素又扫了一遍整个区间， 那合并就是 O(n²)，分治的收益全部归零 —— 一定要检查 merge 是不是 O(区间长)；
  • 「切」得不均匀。切法必须是「规模按比例缩小」。 如果每次都只把问题缩小 1（比如快速排序里基准永远取到最小值）， 递归深度会退化成 n —— 这就是快排最坏 O(n²) 的来源。

这一节要练成的反射：看到「统计某种数对的个数」「求最值的最值」， 先问一句「能不能切成两半，只在合并时数跨中点的那些？」。 能，就是分治。归并排序和逆序对是这一招的原型，把它吃透， 后面 CDQ 分治、点分治都是同一个骨架。

9. 贪心

入门★★★思维详解做例题 →

本质：每步取局部最优，且能证明它不劣于任何最优解。常用的三种证明武器：交换论证（任意最优解可交换为我们的选择）、归纳法、反证 + 界。贪心没有通用模板，只有可证明的贪心才是贪心。

复杂度：通常 O(n log n)（因为多数贪心要排序或用堆）。

补充（来自「学习计划」里的同名卡片）：

⚠️ 贪心不成立时怎么办

反例：货币找零 —— 面值 [1, 3, 4]，凑 6 元。贪心拿 4+1+1 = 3 枚，但最优是 3+3 = 2 枚。贪心失败 → 上 DP。做题时如果举不出反例又证不出正确性，先写贪心 + 对拍，1 分钟就能验证。

例题：洛谷 P1090 合并果子 —— n 堆果子，每次合并两堆，代价为两堆之和，求最小总代价。贪心策略：每次合并当前最小的两堆。用小根堆实现 O(n log n)。n = 10⁴ 时暴力找最小值 O(n²) 也能过，n = 10⁵ 就必须用堆。

两种证明套路：
① 交换论证：假设存在最优解和贪心解不同，找到第一个不同的位置，把它俩交换，证明结果不会变差 → 贪心解也是最优。
② 反悔贪心：先贪心拿，如果发现不划算，就用堆把之前的决定「撤销」掉。

题单 洛谷 P1090 合并果子 · P1223 排队接水 · P1803 线段覆盖 · P5019 铺设道路 · P1080 国王游戏 · P1631 序列合并 · P1094 纪念品分组 · P4447 分组 · P2949 [USACO09OPEN] Work Scheduling（反悔贪心）。

资料 OI-Wiki「贪心」；《算法竞赛进阶指南》0x07 节；《挑战程序设计竞赛》「贪心」一章。

深入讲解 · 贪心：敢贪的前提是「能证明」三种证明武器 + 什么时候该转 DP
一、先分清：什么时候能贪，什么时候必须 DP

贪心和动态规划长得很像 —— 都在「一步一步做决定」。区别只有一句话：

贪心：每一步只考虑当前最优，做完就不再回头。
DP：每一步都保留所有可能的状态，因为现在看着不好的选择，后面可能翻盘。

所以「贪心能不能用」等价于一个问题：当前的最优选择，会不会堵死后面的路？ 不会，才能贪。

举两个最经典的对照：

  • 合并果子（能贪）：每次合并最小的两堆。因为合并的代价只跟这两堆的大小有关， 先合小的，大的被"垫底"的次数更少 —— 前面怎么选，不影响后面能做哪些选择；
  • 0/1 背包（不能贪）：按「性价比（价值 / 重量）」从高到低拿。 反例：背包容量 10，物品 A 性价比最高但重 10、价值 11；B、C 各重 5、价值各 6。 贪心拿 A 得 11，最优是 B + C = 12。拿了 A 就把后面的路堵死了。

这句话要记住：0/1 背包是「贪心与 DP 的分界线」。 凡是「选了就没法反悔、且选择之间互相挤占资源」的问题，都要上 DP。

二、三种证明武器

竞赛里，没有证明的贪心等于猜。你至少要能说出一个理由。 下面三种是最常用的：

  1. 交换论证（最常用）：假设存在一个最优解，它和贪心解在第一个不同的位置上选的不一样。 把它的选择交换成贪心的选择，证明结果不会变差 —— 于是贪心解也是最优解；
  2. 归纳法：证明「做完第 i 步之后，仍然存在一个最优解包含我当前的选择」；
  3. 反证 + 界：证明「任何解都不优于我给出的上界 / 下界」，而我的解恰好达到这个界。 区间调度就是这么证的 ——「最多只能选 k 个」这个上界被贪心达到了。

交换论证的模板长这样，背下来能套很多题：

设贪心第一步选了 A，某个最优解第一步选了 B（A ≠ B）。
如果能证明「把那个最优解里的 B 换成 A，解仍然最优」，那么第一步选 A 不会更差 —— 递归地对剩下的部分用同样的论证，贪心就是最优的。
三、最典型的例子：区间调度为什么按右端点排

题目：给一堆区间，选出尽量多的互不重叠的区间。

两种看起来都合理的贪心：「按左端点从小到大」「按右端点从小到大」。 哪个对？看这张图：

按右端点排序能选出最多互不重叠的区间；按左端点排序会先选走太长的区间，挡住后面的选择。

为什么右端点是对的？因为选完一个区间之后， 你唯一在意的就是「下一个区间最早能从哪儿开始」—— 也就是上一个区间的右端点。 右端点越小，留给后面的空间越大，后面的选择只会更多、不会更少。

而按左端点排序时，你会先把「开始得早但特别长」的区间选进来， 它虽然开始得早，却把一大段位置占掉了 —— 这就是图里 A 挡住 B 的情况。

这个思路值得迁移：贪心的排序键往往就是「把最稀缺的资源优先留给后面」。 区间调度里稀缺的是「位置」，所以按右端点排；排队接水题里稀缺的是「总等待时间」， 所以按接水时间从短到长排。想清楚「什么资源最紧」，排序键就出来了。

四、四种常见贪心模式

模式 3 的「邻项交换」值得单独说说，因为它是交换论证的直接代码化。 做法是：假设只有两个相邻元素 i 和 j，分别算出「i 在前」和「j 在前」的代价， 让 i 排在 j 前面的条件就是「前者更小」。把这个不等式化简，得到的式子就是排序键。

模式 4 的「反悔贪心」是贪心的升级形态： 它承认「我可能选错了」，于是用一个堆保留所有已做的选择， 当条件被破坏时，把代价最大的那个撤掉。 对顶堆、带撤销的调度问题都是这个套路。

五、贪心到底会不会失效

成立与不成立的两个经典例子：合并果子可以用交换论证证明；货币找零是贪心的反例。

举不出反例，也证不出正确性，怎么办？—— 写对拍。 贪心的验证成本特别低：写一个 O(n²) 的暴力（或者直接枚举小规模的所有方案）， 随机生成几百组小数据，跑一遍比对。如果 300 组都过，那你至少可以放心交上去了。 这是投入产出比最高的一次验证（具体的对拍写法见「日常开发 · 对拍」那一章）。

六、例题精讲：洛谷 P1090 合并果子
题意：n 堆果子，每次可以合并两堆，代价是两堆之和。问合并成一堆的最小总代价。
贪心策略：每次合并当前最小的两堆。
为什么对（交换论证的直观版）：总代价 = 每堆果子被"合并"的次数 × 它的重量。 小的堆多被合几次不心疼，大的堆要尽量少被合 —— 所以让小的先合， 大堆就会晚一点参与、少参与几次。
实现：小根堆，每次弹出两个、压回一个，O(n log n)。

这题的复杂度很有意思：n = 10⁴ 时暴力找最小值（O(n²)）也能过； n = 10⁵ 就必须用堆。这就是「同一个贪心策略，换一种数据结构实现」的典型例子 —— 思路是对的，卡住你的经常只是实现效率。

顺带记一个等价表述：合并果子其实就是 Huffman 编码的构造过程。 如果你学过哈夫曼树，会发现两者一模一样 —— 竞赛里大量「合并 / 拆分求最小代价」 的题都是它换个皮。

七、坑清单
  • 拿贪心当 DP 用。最典型的就是 0/1 背包按性价比贪心 —— 记住它是错的；
  • 贪心的排序键算错。尤其是模式 3 的邻项交换，不等式化简一步错就全错。 建议：在小数据上手写两组对比验证一下排序键；
  • 没考虑「相等时」。排序键相等时，不同的处理可能导致不同答案。 如果题目会卡这一层，比较函数里要补齐第二关键字；
  • 溢出。贪心经常要求「代价之和」，n 大时一定要用 long long；
  • 没验证就交。贪心的错误往往只在小数据上暴露，大样例反而是对的。

这一节要练成的反射：拿到一道「求最大 / 最小」的题，先假设它是贪心，问自己 「当前这一步选最优，会不会让后面变差？」。如果这个问题的答案显然是否定的（而且你能说出为什么）， 就写贪心；如果发现某个量在互相挤占，那就是 DP。

10. 简单搜索（DFS / BFS）

入门★★★必背详解做例题 →

本质：搜索 = 枚举状态空间。DFS 用栈（递归）走到底再回头，适合求所有方案 / 判定存在性 / 需要维护路径；BFS 用队列逐层扩散，适合无权图最短路 / 最少步数 / 层序性质。核心是状态的表示 + 剪枝。

复杂度：O(状态数 × 转移代价)。剪枝（可行性剪枝、最优性剪枝、去重、启发式排序）是把指数级压到能过的唯一办法。

资料 OI-Wiki「DFS（搜索）」「BFS（搜索）」；《算法竞赛进阶指南》0x21~0x25 节。

深入讲解 · 搜索：把状态空间走一遍DFS 与 BFS 的分工，以及剪枝的四种武器
一、搜索 = 枚举状态空间

搜索听起来玄，其实就是「枚举」的升级版：把「一步」的定义放宽成「一次转移」， 然后沿着转移关系把所有能到达的状态走一遍。

于是所有搜索题都归结成两个问题：

  1. 状态怎么表示？（一个坐标？一个棋盘？一个整数编码的字符串？）
  2. 怎么从状态转移到下一个状态？（上下左右走？选 / 不选？交换两个位置？）

把这两个问题答清楚，剩下的就是 DFS 还是 BFS 的选择题。 复杂度也统一写成 O(状态数 × 每个状态的转移数)。

二、DFS 和 BFS 的分工：一句话记住
DFS（用栈 / 递归）—— 一条道走到黑，走不通就回退。
适合：求所有方案、判定存在性、需要维护一条完整路径。

BFS（用队列）—— 一层一层向外扩散。
适合：无权图 / 无权网格的最短路、最少步数、按层处理。

为什么 BFS 能求最短路？因为它按距离由近到远地访问节点： 第一次走到某个点时，走的步数一定是最少的。DFS 没有这个性质 —— 它可能先绕很远的路到达同一个点。

所以「最短 / 最少」三个字出现时，先想 BFS； 「所有方案 / 有没有解」出现时，先想 DFS。

三、同一张图，两种走法

同一张图：DFS 沿一条路走到底再回退；BFS 按距离一层层向外扩散。

图里 A 是起点。DFS 走 A→B→C→F，走到 F 没路了才回退到 C、再到 B， 然后去 E、最后才到 D。而 BFS 是 A → B、D → C、E → F， 距离起点 1 的一层先访问完，再去距离 2 的那一层。

注意 D 的位置：DFS 最后才访问它，但它的距离其实和 B 一样近。 这就是为什么「求最短路必须用 BFS」—— DFS 找到的第一条路不保证最短。

四、DFS：回溯三件套

DFS 写「枚举所有方案」时的骨架叫回溯，核心是三步：

① 做选择（把当前选择记下来）→ ② 递归下一层 → ③ 撤销选择（恢复现场）。

第 ③ 步是回溯的灵魂，也是新手最常忘的一步。 忘了撤销，前一条分支的痕迹会带到下一条分支里，答案会莫名其妙地少或者多。

八皇后那三行是「用空间换时间」的典型： 与其每放一个皇后就回头检查前面所有皇后，不如维护三个布尔数组， 放下去的时候顺手标记，拿走的时候顺手取消 —— 判定一次冲突就是 O(1)。

这个技巧在搜索题里反复出现：把「验证合法性」变成「维护合法性」。 如果每到一个状态都要扫描全部已有元素去检查冲突，剪枝的效率会被吃掉一大半。

五、BFS：网格最短路的标准写法

「入队之前就标记」是 BFS 唯一的硬性要求。如果把 dist[nx][ny] = ... 挪到出队时再做，同一个点会被重复入队， 队列规模可能指数级膨胀 —— 小数据照样过，大数据直接 MLE / TLE。

反过来，DFS 是「出栈时标记」还是「入栈时标记」要小心： 如果题目允许同一个点被不同路径经过（比如求所有路径），就不能简单地标记访问过。 先想清楚「同一个状态允不允许被访问两次」，再决定在哪一行打标记。

多源 BFS：如果起点有多个，只要在初始化时把所有源点都压进队列， 其余代码一个字都不用改 —— 这就是「多源最短路」的标准写法（比如「求每个格子到最近的火的距离」）。

六、剪枝：把指数级压到能过的唯一办法

搜索的搜索树往往是指数级的，能不能过全看剪枝。四种武器：

剪枝一句话典型场景
可行性剪枝当前状态已经不可能满足约束 → 直接 return「剩下的数不够选了」
最优性剪枝当前代价已经 ≥ 已知答案 → 直接 return求最小代价，配合贪心先求一个较优解
顺序剪枝优先搜索更可能出解的分支先选大的数、先试更优的方向
记忆化 / 去重同一个状态只搜一次状态可编码成整数时用哈希表

最优性剪枝有一条很实用的技巧：先用贪心求一个"还不错"的解作为初始答案。 初始答案越接近最优，被剪掉的分支就越多 —— 同样的代码可能从 TLE 变成 AC。

八、坑清单
  • BFS 忘记「入队即标记」 → 同一点重复入队，队列爆炸。见上文；
  • DFS 忘记「撤销选择」 → 前一条分支的痕迹污染后面的分支；
  • 越界判断放在了访问之后。数组越界读到的可能是别的变量，程序不崩但答案错。 越界判断永远放最前面；
  • 递归太深。DFS 深度可能上万，记得提高栈空间或者改成显式栈；
  • 状态没编码好。八数码这类题要把棋盘压成一个整数（比如康托展开 / 9 位十进制数）， 否则 map<string, int> 会慢到不可接受；
  • 双向 BFS 忘了判「起点终点重合」。这是双向 BFS 最常见的边界错误；
  • 该剪枝没剪。搜索题如果超时，先问自己「我有没有在进入下一层之前就把不可能的情况挡掉？」

这一节要练成的反射：看到「最少步数 / 最短距离」→ BFS； 看到「所有方案 / 方案数 / 有解吗」→ DFS + 回溯； 看到搜索超时 → 先问「状态能不能编码去重」，再问「有没有上界可以剪枝」。 把 P1219 和 P1443 独立写到不用看模板，搜索这一关就稳了。
