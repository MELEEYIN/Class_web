入门篇的十张卡不是十个算法，而是十种思维动作。它们会被后面每一个高级算法反复用到——贪心用在 Kruskal 里，二分用在「二分答案 + 最短路」里，递归是 DP、分治、搜索、树形结构的共同语言。

3.1 枚举：把所有候选答案试过去

基础★★★★必考P1036P1008P1157

本质：把所有可能的答案候选一个个试过去。 难点从来不是「枚举」，而是枚举什么与如何压缩枚举量。

🎨 生活类比

宿舍 6 个人找钥匙，最简单的方法是每人抽屉都翻一遍——这比「推理钥匙应该在谁的桌上」更快，而且不会错。枚举就是「把抽屉全翻一遍」，但它要求你知道抽屉总共有几个。

怎么判断该不该枚举

看数据范围。看到下面这些数字，就该条件反射式地想到枚举：

范围说明
n ≤ 1010! = 3.6×10^6，全排列能过
n ≤ 202^20 approx 10^6，子集枚举能过
n ≤ 8n^n 级别也能过
答案值域 ≤ 10^6可以枚举所有可能答案再验证

套路：三种枚举对象

  1. 枚举方案：把所有组合/排列列出来（O(2^n) 或 O(n!)）。
  2. 枚举答案：如果答案范围小，就枚举答案再验证（这就是「二分答案」的暴力版）。
  3. 枚举一个维度：把问题固定在一维上，另一维交给前缀和/哈希降到 O(1)。

示例：子集枚举（n ≤ 20）

例题思路：P1036 选数

从 n ≤ 20 个数里选 k 个，问有多少种选法使和为质数。2^20 approx 10^6 种选法，每种再花 O(√ s) 判质数——完全能过。看到 n ≤ 20 就该想到 2^n 枚举，这是入门阶段最可靠的信号。

⚠️ 易错

子集枚举时 1 << n 在 n ≥ 31 时溢出（见 1.3 节）；候选答案重复时要注意去重。

✅ 小结

枚举的敌人不是"想不到"，而是"枚举漏了"或"枚举太多"。 写之前先算清「总共有多少种候选」，这个数必须小于 10^7。

3.2 模拟：把题目描述直译成代码

基础★★★★必考P1563P1042P1067

本质：把题目描述无损地直译成代码。 它考察的是「把自然语言规则翻译成状态机」的能力，是「代码量失败」（写了一大堆但全错）的主要来源。

🎨 生活类比

模拟题就像照菜谱做菜：菜谱说「水开后转小火炖 20 分钟」，你就得真的开火、看水、计时、转小火。漏了任何一步，菜就不对。

三步做法

  1. 先用文字把规则列全（写在纸上，不要写在脑子里）。
  2. 明确状态变量的含义与初值（pos 表示什么？下标从 0 还是 1？初始在哪？）。
  3. 按「事件」推进时间，而不是逐时刻模拟——除非数据规模小到可以逐时刻。

示例：环形位置取模（P1563 玩具谜题）

一圈小人，朝内/朝外 + 向左/向右，走若干步问你最后站在谁面前。核心就是两行取模：

把四种组合列成一张表，代码就是抄表。 这是模拟题的标准做法——先用表格把 8 种/16 种情况穷举清楚，再逐行翻译。

模拟题的四个高频坑

  • 边界：走到第 0 个人还是第 n-1 个人？取模后是 [0, n) 还是 [1, n]？
  • 多测清空：全局数组在下一组数据里还是脏的。
  • 取模与整除的区别：向下取整、向上取整、四舍五入，题目怎么说就怎么写。
  • 代码量失控：如果代码超过 100 行还在纠结，说明你还没把规则想清楚，回去画表。
✅ 小结

模拟题不快，是你没想清。 先写表格，再写代码，代码量会缩短一半。

3.3 递归：把大问题变成同样形状的小问题

基础★★★★必考P1255P1036P1464

本质：把规模为 n 的问题化为规模更小的同类问题。三要素：参数含义、边界条件、递推关系。

🎨 生活类比

俄罗斯套娃：打开一个，里面是小一号的同一个娃娃。你只要会「打开并处理一个娃娃」，剩下的都交给「小一号的自己」。「小一号」小到最后（最小的娃娃打不开）就是边界。

三要素模板

写递归前先回答三个问题，缺一个都写不对：

问题例子（阶乘）
f(x) 在语义上代表什么？f(n) 表示 n!
最小情形是什么？n = 1 时是 1
f(n) 怎么用 f(n-1) 表示？f(n) = n * f(n-1)

递归的三个必知风险

  1. 爆栈：递归深度超过约 10^4 ~ 10^5 就会 RE（每次递归都占栈空间）。树有 10^5 层时必须改迭代或手动加栈。
  2. 重复计算：f(n) = f(n-1) + f(n-2) 直接递归是 O(2^n)，加个记忆化数组就变成 O(n)。
  3. 忘记还原状态：回溯类递归（八皇后、全排列）里，改了的标记必须改回来。

记忆化：递归到 DP 的桥梁

记忆化 = 给递归加一个「草稿本」。 算过的答案写在本子上，下次先翻本子。这就是 DP 的本质，第 5 章会正式展开。

✅ 小结

递归是最省代码的写法，也是最容易爆栈和重复计算的写法。 深度过万先想迭代，状态重叠先想记忆化。

3.5 双指针与滑动窗口：把 O(n^2) 的枚举砍成 O(n)

基础★★★★必考P1638P1147P1381

本质：当区间的可行性关于包含关系单调时（右端点右移，只会让左端点单调右移），两个指针总共只走 O(n) 步。

🎨 生活类比

在书架上找一段「恰好包含所有 5 类书」的最短连续区间。你不会对每个起点都往后数一遍；你会从左往右推：右边不够就继续往右拿，够了就把左边一本本丢，直到不够为止。书不会回头拿第二遍——这就是双指针。

前提：单调性（这是最常见误用）

必须验证：「右端点往右移之后，满足条件的最优左端点只会往右移，不会往左移」。如果这个性质不成立，双指针就是错的。

同向双指针模板（最长/最短满足条件的子段）

三行口诀：右端进、左端退、中间记答案。

相向双指针（有序数组两数之和）

前提：数组已排序。 没排序就先排，O(nlog n)。

⚠️ 易错

左指针退出时忘记同步更新 cnt（漏了减）；while 条件写成 if（一次可能退不完）。

✅ 小结

双指针不是技巧，是"单调性"的应用。 用之前先问一句：左端点会不会往回退？

3.6 排序与自定义比较

基础★★★★必考P1177P1059P1093

本质：排序是用比较换信息。真正要掌握的不是会写快排，而是：稳定性、是否原地、比较次数下界 O(nlog n)、以及非比较排序（计数/基数/桶）何时能突破下界。

什么时候排序

排序本身就是一种「预处理」——排完序后，很多问题（去重、贪心、双指针、二分）才能做。看到题目要求"最大/最小/第 k"且数据无序，先想排序。

必会的三件事

非比较排序：什么时候能突破 O(nlog n)

算法复杂度前提
计数排序O(n+V)值域 V 很小（如分数 0~750）
桶排序O(n) 期望数据均匀分布
基数排序O(nlog_10V)整数
归并排序O(nlog n)无视前提，还能顺便求逆序对
⚠️ 易错

比较函数必须满足严格弱序（不能有 <=）；sort 对相等元素不保序（不稳定），需要稳定时用 stable_sort；对 vector<Node> 排序时比较函数参数一定要传引用 const Node&，否则每次比较都复制，慢十倍。

3.7 二分与二分答案

基础★★★★必考P1873P2249P1102

本质：二分 = 在单调的判定函数上找分界点。 写对二分的唯一诀窍是明确「check(mid) 为真时答案落在哪一半」，然后让循环不变式保持不变。

🎨 生活类比

猜数字游戏：1 到 100，你说 50，我说「大了」，你就知道答案在 1~49。每猜一次砍掉一半，7 次必然猜中。二分的全部威力来自「每次砍一半」。

两种写法（选一种，别混）

💡 提示

两种写法选一种用到底。 混用是二分写错的头号原因。新手推荐写法 A，因为它直接对应「答案区间」这个直觉。

二分答案：三要素

当题目问「最小/最大的……」且判定某个答案是否可行很容易时，就二分答案：

  1. 答案的单调性：如果 x 可行，那么比 x 更宽松的所有值也可行（或都不可行）。
  2. check(x) 函数：O(n) 或 O(nlog n) 判定「答案取 x 是否可行」。
  3. 答案范围：从可能的上下界开始二分，通常要做 O(log V) 轮。

总复杂度 O(nlog(text{值域}))。值域 10^9 时只需 30 轮。

三分：在单峰函数上找极值

二分要求单调，三分要求单峰——这是两组完全不同的前提，别混。

⚠️ 易错

mid = (lo + hi) / 2 在 lo, hi 都接近 2×10^9 时溢出，写成 lo + (hi - lo) / 2；check 里的答案也要用 long long；实数二分固定跑 100 次而不是比 eps。

✅ 小结

二分不考脑子，考纪律。 写完后拿「答案在边界上」的用例手推一遍循环。

3.8 分治

基础★★★★必考P1908P1010P1228

本质：把问题切成互不相交的子问题分别求解再合并。复杂度由主定理给出：T(n) = aT(n/b) + f(n)。分治的难点在 merge，不在 divide。

🎨 生活类比

数一个体育场里的人数：你数左边看台，让朋友数右边看台，两人各数一半，最后相加。你不会一个人从头数到尾。

三个经典分治

问题怎么分怎么 merge复杂度
归并排序从中间切两半双指针合并两个有序数组O(nlog n)
快速幂指数折半偶数 a^n = a^n/2· a^n/2O(log n)
逆序对从中间切两半合并时统计「左边比右边大」的对数O(nlog n)

归并求逆序对（必会）

cnt += mid - i + 1 的含义：a[j] 比 a[i..mid] 都小，所以这一批全都构成逆序对。

💡 提示

分治和递归的区别：递归只是写法，分治是策略。分治要求子问题「不相交且同类」，并且「合并」的代价可控。

✅ 小结

先想清楚 merge 写什么，再动手。 merge 写不出来，说明这个分法不对。

3.9 贪心

基础★★★★必考P1090P1223P1803

本质：每步取局部最优，且能证明它不劣于任何最优解。常用的三种证明武器：交换论证、归纳法、反证 + 界。贪心没有通用模板，只有可证明的贪心才是贪心。

🎨 生活类比

找零钱时优先用大面额：凑 87 元先拿 50，再 20，再 10，再 5，再 2——因为人民币面额设计得「后一个都是前一个的因数或倍数」，贪心才对。如果换成 1、3、4 元面额，凑 6 元贪心会得 4+1+1 = 3 张，而最优是 3+3 = 2 张——贪心失效。

三种证明武器

武器怎么用典型题
交换论证设最优解与贪心解第一个不同处，交换后不会变差区间调度、排队接水
归纳法证明「前 i 步贪心不劣于任何最优解的前 i 步」合并果子
反证 + 界假设最优解更好，推出矛盾国王游戏

例题思路：P1090 合并果子

n 堆果子，每次合并两堆，代价为两堆之和，求最小总代价。每次合并当前最小的两堆——用小根堆实现 O(nlog n)。

为什么对？可以想成哈夫曼树：被合并得越早的果子，会被后面每一次合并重复计入代价，所以它应该尽量小。这就是「小者优先」。

贪心的两个陷阱

  1. 局部最优不等于全局最优。0-1 背包用「单位价值贪心」是错的（换成「分数背包」才对）。
  2. 贪心的正确性必须能证。证不出来时，先写对拍：造随机数据，和暴力比 1000 组。对拍过了再提交。
✅ 小结

先猜策略，再证正确，证不出就对拍。 三步走不掉任何一步。

3.10 搜索：DFS 与 BFS

基础★★★★必考P1219P1605P1443

本质：搜索 = 枚举状态空间。DFS 用栈（递归）走到底再回头，适合求所有方案 / 判定存在性 / 需要维护路径；BFS 用队列逐层扩散，适合无权图最短路 / 最少步数 / 层序性质。核心是状态的表示 + 剪枝。

类比

  • DFS：走迷宫时贴着右手边的墙一直走，走到死胡同就退回来换一条路。它的优点是「一条路走到黑」，缺点是可能绕很远。
  • BFS：往水里丢一颗石子，波纹一圈一圈扩散。第一次碰到的地方，一定是最短的路径。

DFS 模板（求所有方案）

BFS 模板（无权图最短路）

BFS 的访问标记必须在入队时打。如果等出队时才打，同一个点会被重复入队，队列爆炸（表现为 MLE 或 TLE）。

剪枝：把指数级压到能过的唯一办法

剪枝类型做法
可行性剪枝当前状态已经不可能满足条件，直接 return
最优性剪枝当前代价已经比已知最优解差，直接 return
排序 + 优先扩展把更可能出解的分支排在前面（启发式）
去重相同状态只搜一次（哈希/数组标记）
迭代加深限制深度，逐步加深，兼顾 DFS 的空间和 BFS 的最优
✅ 小结

搜索题的分数几乎全部来自剪枝。 先写出能跑的暴力，再一层层加剪枝，每加一层对拍一次。
