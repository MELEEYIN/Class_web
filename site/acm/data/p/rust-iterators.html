迭代器是 Rust 里替代手写循环的主力：map、filter、fold 这些适配器惰性求值，只有遇到消费型方法（collect/sum/for）才真正执行，而且编译后与手写循环几乎同速。

一、闭包

let add = |a, b| a + b;                 // 类型可推断
let n = 10;
let plus_n = |x: i32| x + n;            // 捕获外部变量（默认按引用借用）

fn apply(f: impl Fn(i32) -> i32, v: i32) -> i32 { f(v) }
apply(|x| x * 2, 5);                     // 10
trait捕获方式能调用几次
Fn按引用多次，只读
FnMut按可变引用多次，可改捕获值
FnOnce按值（移动）一次

二、迭代器适配器

let v = vec![1, 2, 3, 4, 5];

let doubled: Vec<i32> = v.iter().map(|x| x * 2).collect();
let evens: Vec<&i32> = v.iter().filter(|x| *x % 2 == 0).collect();
let sum: i32 = v.iter().sum();
let total = v.iter().fold(0, |acc, x| acc + x);

// 链式：前 3 个偶数的平方和
let r: i32 = v.iter().filter(|x| **x % 2 == 0).take(3).map(|x| x * x).sum();

注意 iter()（借 &T）、iter_mut()（&mut T）、into_iter()（消耗，拿 T）三者的区别——for x in v 等价于 into_iter()。

三、常见坑

  1. 适配器不消费就不执行：v.iter().map(...); 什么都不会发生（还有 unused_must_use 警告）。
  2. filter 里的 x 是 &&T，比较要 **x 或 *x。
  3. collect() 需要目标类型，写 let v: Vec<_> = ...collect(); 或标注返回类型。
  4. 闭包借用外部变量导致借用冲突：需要时用 move 把所有权搬进闭包。
  5. 在闭包里改外部变量必须 let mut f = || {...}，且闭包本身要可 FnMut。

四、小结
