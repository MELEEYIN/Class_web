前四件是「做事的习惯」，这第五件是一件具体的前置技能。它本身只有十几行代码，但没有它，树状数组、线段树、扫描线这些结构有一大半题目都用不了。

5.1　本质与三步值域 10⁹ → 下标 n

本质：当数值很大（比如到 10⁹）但个数很少（比如 10⁵）时，我们往往只关心它们的相对大小，而不关心具体是多少。把「排序去重后的排名」当作新下标，值域就从 10⁹ 缩到 n。

三步：① 拷一份存起来 ② sort + unique 去重 ③ lower_bound 查排名（排名就是新下标）

原始值 [100, 3, 3, 55, 100, 3] → 排名 [3, 1, 1, 2, 3, 1]，映射表 {3→1, 55→2, 100→3}。值之间的「大小关系」被完整保留，这就是它能用的原因。

为什么需要它？因为「桶」和「树」这两种结构都要求下标是紧凑的整数。10⁹ 个桶开不出来（4 GB）；但 10⁵ 个桶、10⁵ 个节点的树状数组毫无压力。离散化做的事，就是把「值」翻译成「位置」。

5.2　完整模板（含 unique 的机制）最容易误解的一步

unique 不删除元素、也不改变容器长度，只是把不重复的挪到前面，然后返回「新逻辑结尾」的位置。

为什么 unique 必须配 erase

unique 的返回值是「新逻辑结尾」的迭代器，容器本身的 size() 一点没变。只调 unique 不 erase，后面那几个「已失效但还占着位置」的元素还会被 lower_bound 搜到 —— 排名就全错了。

b.erase(unique(b.begin(), b.end()), b.end()); └─ 返回新结尾 ─┘ └─ 从新结尾删到真正的末尾 ─┘

还要记住 unique 的前提：区间必须已经有序。它只去掉相邻的重复项。[3, 55, 3] 不排序直接 unique，结果还是 [3, 55, 3] —— 一个都没去掉。顺序永远是：先 sort，再 unique。

5.3　用到的四个函数：参数、返回值、复杂度一次讲清，不用再查
函数作用返回 / 复杂度最容易错的地方
sort(f, l) 把 [f, l) 升序排序，在 <algorithm> 无返回值 · O(n log n)，不稳定 左闭右开：对数组要写 sort(a, a + n)，不是 a + n − 1
unique(f, l) 把相邻的重复元素挪到后面，在 <algorithm> 返回新逻辑结尾的迭代器 · O(n) 不删除元素、不改长度；要求区间已有序；必须配 erase
lower_bound(f, l, x) 在有序区间里找第一个 ≥ x 的位置，二分实现 返回迭代器（全都 < x 时返回 l）· O(log n) 区间必须有序，否则结果随机；改成下发问 - begin() 拿 0-based 下标
v.erase(f, l) 删除一段区间，后面的元素整体前移 返回被删区间之后的第一个位置 · O(n) 删除会让后面的迭代器全部失效，别在遍历里随手 erase

顺带把 upper_bound 一起记了：它返回第一个 > x 的位置。
lower_bound(b, x) - begin() + 1 = x 的排名（从 1 开始，也是「比 x 小的个数 + 1」）
upper_bound(b, x) - lower_bound(b, x) = x 重复出现的次数
lower_bound(b, x) - begin() = 比 x 小的元素个数

5.4　离散化会丢掉什么什么时候不能这么干

这是原文里那句「要注意」的完整版 —— 也是唯一一个会让你用错离散化的地方。

判断标准就一句话：你要的是「顺序」还是「距离」？

问题在问什么能离散化吗例子
谁大谁小 / 排第几能第 k 小、比 x 小的有几个、排名、逆序对（只要比出大小）、去重后的种类数
相差多少 / 加起来是多少不能直接用区间和、加权和、两点距离、面积、计数（个数也要小心）

补救办法（很常用）：离散化时同时保留原值，用原值参与数值计算，用排名参与下标寻址，两者配对使用。

另一条路：不压缩坐标轴，改成只保留「关键点」。比如扫描线求矩形面积并，只用到矩形的 2n 条竖直边，把它们的 x 坐标离散化，这样区间长度可以靠相邻两个坐标的差算回来，距离信息并没有丢。

5.5　离散化之后能干什么它为什么是「前置技能」

值域从 10⁹ 降到 10⁵ 之后，一大批「下标必须紧凑」的结构才能用上：

解锁的东西离散化在这里做什么
树状数组求逆序对把数值当索引。原值 10⁹ 开不了那么大的数组，离散化后 n 个格子正好
线段树 / 主席树「第 k 小」「区间内第 k 大」—— 树的下标就是离散化排名
权值线段树同上，用排名当权值下标，才能统计「某个区间的数有几个」
扫描线求矩形面积并把 2n 条竖边的 x 坐标离散化，区间长度用相邻坐标差算
桶计数本来开 10⁹ 个桶是 4 GB；离散化后 n 个桶就能数了

一道题里它往往只是一行工具。所以真正要记住的不是「离散化怎么写」（第 5.2 节那 5 行已经够了），而是「什么时候该想到它」 —— 当你发现「值域很大、但个数不多」，而且想用「按下标寻址」的结构时，就该想起它。

5.6　离散化部分的六条常见错误第一条最常见

1. 用了 unique 却没有 erase

最常见的一条。容器长度没变，后面那些失效元素还会被搜到，排名整体错位。写成一行 b.erase(unique(b.begin(), b.end()), b.end()); 就不会忘。

2. 先 unique 才 sort

unique 只处理相邻重复。顺序必须是 sort → unique。写反了一个都去不掉，而且不报错。

3. lower_bound 之前忘了保证有序

lower_bound 是二分，区间无序时结果是随机的（不是报错，是安静地给你错答案）。所有 lower_bound / upper_bound / 二分查找都要求有序。

4. 忘记 +1 或 -1，1-based 与 0-based 混用

- b.begin() 得到 0-based；+1 变成 1-based。选一种用到底。混用的典型症状是「答案差 1」或者「最后一个元素丢失」—— 树状数组通常要 1-based（因为 lowbit(0) = 0 会死循环）。

5. 覆盖了原数组

直接 sort(a) 再离散化，原顺序就没了 —— 而很多题需要「原来的第 i 个数」。

6. 把「距离信息」也一起离散掉了

见 5.4。需要求和、算距离、算面积的题，离散化只能压缩坐标轴，不能压缩权值。离散化之后直接对排名求和，答案一定是错的。

自检清单（写完离散化立刻核对）：
① sort 和 unique 的顺序对吗？ ② 有 erase 吗？
③ 排名是 0 还是 1 开始，全文一致吗？ ④ 原数组有没有被破坏？
⑤ 这道题要的是「顺序」还是「距离」？
