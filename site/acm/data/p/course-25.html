第 21~24 节只教了一件东西：把一个大问题拆成「第一步 + 剩下的同样问题」，拆到不能再拆（出口），再把答案一层层抛回来。四节课是同一副骨架换了四种状态：递归算数、递推打表、枚举组合排列、在网格上走路。这一节不讲新算法，只练四个动作——出口写对、状态写全、现场恢复、不该走的枝不走了。

DFS 的分数 90% 不在 for 循环里，而在三个地方：出口、标记数组的下标、回溯那一行。

例题 · Backward Digit Sums洛谷 P1118普及/提高-去洛谷做这题 ↗

把 1 到 N 的某个排列写成一行，然后把相邻两个数相加，得到少一个数的新一行；重复这个过程，直到只剩一个数。例如 N = 4 的排列 3 1 2 4：3 1 2 4 → 4 3 6 → 7 9 → 16，最后得到 16。

现在给定 N 与最终的和 sum，求满足条件的字典序最小的初始排列。

输入格式：一行两个正整数 n、sum（1 ≤ n ≤ 12，1 ≤ sum ≤ 12345）。

输出格式：一行 n 个整数，即字典序最小的答案；若无解，什么都不输出。

输入： 4 16 输出： 3 1 2 4

第 23 节讲排列枚举，第 24 节讲剪枝，这一题把两者接起来：枚举排列（每层选一个没用过的数），边枚举边剪枝（当前的和已经超标就回头）。中间还藏着一个 combinatorics 的小结论——最终结果其实是初始排列的一个加权和，权重正好是杨辉三角。

新函数拆解 · 递归函数（DFS 骨架）
void dfs(int 状态参数, ...)
组成含义 / 格式要求
返回类型只做枚举和计数时用 void，答案写进全局变量；只求「能不能到」时用 bool。
参数只放「随分支变化」的量：第几行、第几步、当前和。不随分支变的（n、棋盘大小）一律放全局。
出口函数体第一句永远是 if (到出口) { 记录/输出; return; }。没有出口就是无限递归，结果 RE（爆栈）。
分支for 枚举这一步的所有选择，每个选择先「改状态」，再递归，再「还原状态」。
回溯递归返回后把状态改回去。漏了这一步，后面的分支会看到被污染的状态，答案偏少且难查。
深度上限默认栈约 8MB，一帧 48~64 字节，递归到 10⁵ 层就可能爆栈。更深的搜索要改手写栈或 BFS。
最小可运行示例
示例
int n, ans = 0;

void dfs(int step) {
    if (step > n) { ++ans; return; }      // 出口：n 步都走完了，得到一种方案
    for (int i = 1; i <= n; ++i) {         // 枚举这一步的所有选择
        // 改状态（本题没有需要改的数组）
        dfs(step + 1);                     // 递归到下一步
        // 还原状态
    }
}
注意

出口里的 return 不能省，否则走完一步还会接着往下枚举，同一方案被重复计数。

递归函数的返回值只用来「传答案」或「报告成败」，不要既返回值又改全局量，那样必然乱。

新函数拆解 · 全局标记数组
bool vis[N]; // 写在 main 外面
组成含义 / 格式要求
为什么放全局全局变量在静态区：自动清零（false），而且不占栈空间。在 main 里开 10⁶ 个 int（4MB）就可能爆栈。
两种写法vis[x] = true 记录访问过；网格题里也可以直接把地图 g[x][y] 改成 '.'，省一个数组。
成套出现mark(x); dfs(...); unmark(x); 三句一定连在一起，中间不要插别的逻辑。
数组大小按最大可能下标开，不是按元素个数：列号最大 n，就开 n+2；对角线下标最大 2n，就开 2n+2。
下标要能当索引负数不能做下标。row - col 最小是 1-n，加 n 平移成 1 ~ 2n-1 就能用了。
最小可运行示例
示例
int n;
bool col[30], d1[30], d2[30];      // 列、↘ 方向、↙ 方向

// 试图把第 row 行的皇后放在第 c 列
if (col[c] || d1[row + c] || d2[row - c + n]) continue;   // 三条线有任一条被占，就不能放
col[c] = d1[row + c] = d2[row - c + n] = true;            // 占住三条线

注意

连续赋值 a = b = c = true 是右结合，三处都会被赋 true，可以放心连写。

还原时漏掉一条线，那个位置后面就永远被占着，解会少一大截——这是八皇后最典型的错法。

新函数拆解 · memset（批量初始化）
memset(数组名, 值, sizeof 数组名);
组成含义 / 格式要求
按字节填memset 把内存按字节填成同一个值：填 0 得到全 0，填 -1 得到全 -1（每字节 0xFF），填 1 得到 16843009。
只有 0 / -1 能用想把 int 数组全设成 5、把 double 设成 0.3，memset 都做不到，只能用 fill 或循环。

替代品fill(f, f + N, 值) 可以填任意值，速度略慢，但语义清楚。
什么时候需要记忆化搜索里「没算过」要用 -1 标记时；多组数据之间清空状态数组时。

新函数拆解 · 方向数组
const int dx[4] = {-1, 1, 0, 0}; const int dy[4] = {0, 0, -1, 1};
组成含义 / 格式要求
两个下标数组dx[k]、dy[k] 是第 k 个方向的横纵增量，配成一对才表示一个方向。
4 连通上下左右：(-1,0) (1,0) (0,-1) (0,1)。顺序只影响输出顺序，不影响答案。

例题怎么想：先把“最终和”写成初始排列的加权和

① 关键一步：算权重。把一次合并看成“每个位置向上贡献一次”。合并一行之后，位置 i 的数会同时进入它左边和右边两个和里（边界只有一个）。反复 n−1 轮，位置 i 对最终答案的贡献次数就是 C(n−1, i−1)——杨辉三角第 n 行的第 i 个数。

② 于是题目变成等式求根。求排列 a₁…aₙ 使 Σ C(n−1, i−1) · aᵢ = sum。N = 4 时系数是 1 3 3 1，验证 3 1 2 4：3×1 + 1×3 + 2×3 + 4×1 = 16，与题面一致。

③ 状态：dfs(step, s) 表示“前 step 个位置已经填好，加权和为 s”。全局的 used[v] 记哪些数字已经用过——这就是第 23 节的排列模板。

④ 出口：step == n 时判断 s == sum。因为每一层都往下传了确定的 s，出口处不用再算一遍。

⑤ 剪枝：系数全是正的，所以 s 只增不减；一旦 s > sum，这一整棵子树都不可能再回到 sum，立刻 return false。这一句把 n = 12 时的 4.8×10⁸ 条排列砍到可以接受。

⑥ 为什么第一次找到的就是字典序最小：每层都从 1 到 n 递增地试、用过就跳过，于是搜索树的叶子按字典序排列。函数一旦在某条分支上返回 true 就层层往上返回，所以拿到的一定是第一个（也就是字典序最小的）解。

为什么这题不能用记忆化：状态是 (step, s, 已用集合)，只靠 (step, s) 区分不了不同集合，存表会算错。这类“状态里含集合”的搜索只能老老实实枚举，靠剪枝降复杂度。

规模：N ≤ 12，全排列 4.8×10⁸ 看着吓人，但系数是 1, 11, 55, 165, … 增长很快，只要 sum 不是特别大，绝大多数分支在前几层就被剪掉了。实测 N = 12 的极端数据也在毫秒级。

完整代码 · 排列枚举 + 加权和剪枝
#include <bits/stdc++.h>
using namespace std;

int n, target, a[15], coef[15];     // coef[i] = C(n-1, i)
bool used[15];

// step：正在填第几个位置；s：已填部分的加权和
bool dfs(int step, int s) {
    if (s > target) return false;              // 剪枝：系数全正，s 只会越来越大
    if (step == n) return s == target;         // 出口：n 个位置都填好了
    for (int v = 1; v <= n; ++v) {
        if (used[v]) continue;                 // 排列：每个数只能用一次
        used[v] = true;
        a[step] = v;
        if (dfs(step + 1, s + v * coef[step])) return true;   // 找到就一路返回
        used[v] = false;                       // 回溯
    }
    return false;
}

int main() {
    cin >> n >> target;

    coef[0] = 1;                               // 杨辉三角第 n 行：C(n-1, i) = C(n-1, i-1) * (n-i) / i
    for (int i = 1; i < n; ++i) coef[i] = coef[i - 1] * (n - i) / i;

    if (dfs(0, 0)) {                           // 有解才输出
        for (int i = 0; i < n; ++i) cout << a[i] << (i == n - 1 ? '\n' : ' ');
    }
    return 0;
}
逐行拆解
代码片段含义与理由
int coef[15];存杨辉三角第 n 行（n−1 次），最大 C(11,5) = 462，int 足够。它是“每个位置贡献几次”的权重，是本题唯一的数学。
coef[i] = coef[i - 1] * (n - i) / i;组合数的递推：C(m,i) = C(m,i−1)·(m−i+1)/i，m = n−1。先乘后除，中间值仍在 int 范围内，且每步都能整除。
bool dfs(int step, int s)返回 bool 而不是 void：搜索到第一个解就要停下并层层上报，这是“求字典序最小”类题目的通用写法。
if (s > target) return false;剪枝。因为 coef[i] ≥ 1 且每个 a[i] ≥ 1，s 单调不减，超标之后永远回不来。这一行是全题的性能关键。
if (step == n) return s == target;出口直接返回真假，不写 if/else。注意这里是 ==n 而不是 >n：第 n 个位置填完就停，不会再进一层。
if (used[v]) continue;排列的判重，和第 23 节完全一样。注意本题没有 start 参数——排列允许任意顺序，不能像组合那样强制递增。
if (dfs(step + 1, s + v * coef[step])) return true;把“当前数 × 当前权重”累加进 s。返回 true 说明后面已经找到完整解，本层立即返回，不再试别的 v。
used[v] = false;回溯。漏了这一句，后面的分支会以为数字被占着，方案数骤减甚至无解。
if (dfs(0, 0)) { ... }无解时什么都不输出——题目要求“当无解的时候请什么也不输出”，连换行都不要多打。
这一章最容易踩的 6 个坑（每个都写清了症状）

把权重算成 2 的幂或 1,2,3,…：样例 3 1 2 4 就跑不出 16。权重是杨辉三角，先手算 n = 4 验证 1 3 3 1。

组合数递推写成 coef[i-1] * (n-i+1) / i：把 m = n−1 记成 n，权重整体错一位，样例能跑但后面全错。

剪枝条件写成 s >= target：把恰好等于 sum 的分支也砍掉，答案永远是“无解”。

出口写成 step > n 后才发现：n 个位置填完就该判，多进一层会访问越界的 coef[n]。

忘了回溯 used[v] = false：只能试出第一条路径，多数数据直接输出空。

无解时输出了换行或 0：题目要求什么也不输出，多一个字符就是 WA。

大题 挑战题 1 · 外星密码
洛谷 P1928普及/提高-去洛谷做这题 ↗

外星人把连续的若干个相同子串 X 压缩成 [DX] 的形式，其中 D 是 1 到 99 的整数。例如 CBCBCBCB 可以压成 [4CB]，也可以压成 [2[2CB]]；后者叫二重压缩，方括号还可以继续嵌套。

例如 AC[3FUN] 展开是 ACFUNFUNFUN，[2[2A]] 展开是 AAAA。

给定一个压缩串，输出解压后的字符串。

输入格式：一行一个字符串，只含数字、大写字母和方括号，保证格式合法；解压后的长度不超过 20000，压缩最多十重。

输出格式：一行，解压后的字符串。

样例
输入： AC[3FUN] 输出： ACFUNFUNFUN
引导性提示（先只看这里）

这个串的结构天生是递归的：一个方括号里可以再套方括号，结构完全一样。

把「从当前位置一直读到配对的方括号为止」写成一个函数，让它自己调用自己。

读到左括号时，先读出重复次数，再递归读出里面那一整段，最后把那段重复拼接上去。

想看思路了？点开完整思路

递归函数 readStr() 的语义是：从当前读位置开始，读一段内容，读到配对的 ] 或输入末尾为止，返回这段内容。

循环读字符，三种情况：普通字母 → 直接接在结果后面；[ → 读整数 D，递归读出子串 t，把 t 重复 D 次接上；] → 本层读完，return。

出口有两个：读到 ]（这一层结束）和读到输入末尾（最外层结束）。

为什么这样一定对：左括号和右括号严格配对，递归进入一层就消耗掉一个左括号，返回时刚好消耗掉配对的右括号，流的位置自然停在括号后面，外层接着往下读。

复杂度：每个字符只被读一次，拼接总量等于输出长度，总时间 O(输出长度)。

洛谷 P1123普及/提高-去洛谷做这题 ↗

给定一个 N × M 的由非负整数构成的矩阵，从中取出若干个数，要求取出的任意两个数不相邻（一个格子在另一个格子的 8 个相邻格中，就认为这两个数相邻），求取出的数之和的最大值。

输入格式：第一行一个正整数 T（T ≤ 20），表示数据组数。每组数据的第一行两个正整数 N、M（1 ≤ N, M ≤ 6）；接下来 N 行，每行 M 个不超过 10⁵ 的非负整数。

输出格式：共 T 行，每行一个非负整数，表示该组数据的最大和。

样例
输入： 1 4 4 67 75 63 10 29 29 92 14 21 68 71 56 8 67 91 25 输出： 271
引导性提示（先只看这里）

每个格子只有两种命运：取或不取。按行序一个个决定，就得到一棵二叉搜索树。

决定「取」之前要检查它和已经决定过的格子是否相邻。按行序处理时，只需要看左、左上、上、右上四个方向。

所有格子都决定完才能更新答案；走不下去时，用「剩下的格子全取也超不过当前最优」把这一支砍掉。

想看思路了？点开完整思路

状态：dfs(x, y, sum) 表示正在决定第 x 行第 y 列，已取数字之和是 sum。

分支：不取 → 直接走到下一个格子；取 → 先检查 4 个已处理方向的邻格，没冲突才标记并累加。

出口：走完最后一行时用 sum 更新 best。

剪枝：预处理 suf[x][y] = 从 (x,y) 按行序到末尾的所有数字之和。若 sum + suf[x][y] <= best，后面的格子全取也不可能更好，直接 return。

为什么只查 4 个方向：行序遍历时，右、左下、下、右下都还没决定，不可能与当前格冲突。

规模：6×6 网格的独立集约 5.6×10⁶ 个，比 2³⁶ = 6.9×10¹⁰ 小得多；再加后缀和剪枝，T ≤ 20 也很快。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int T, n, m;
int a[8][8];
bool used[8][8];
int suf[8][8];              // suf[x][y]：从 (x,y) 按行序到末尾的所有数字之和
int best;

// 按行序处理时，只需要检查已经决定过的 4 个方向
const int dx[4] = {0, -1, -1, -1};
const int dy[4] = {-1, -1, 0, 1};

bool canTake(int x, int y) {
    for (int k = 0; k < 4; ++k) {
        int nx = x + dx[k], ny = y + dy[k];
        if (nx < 1 || nx > n || ny < 1 || ny > m) continue;
        if (used[nx][ny]) return false;          // 和已选的格子相邻，不能取
    }
    return true;
}

void dfs(int x, int y, int sum) {
    if (x > n) {                                 // 出口：所有格子都决定完了
        best = max(best, sum);
        return;
    }
    if (sum + suf[x][y] <= best) return;         // 剪枝：后面全取也超不过当前最优

    int nx = x, ny = y + 1;                      // 下一个格子（到行末就换行）
    if (ny > m) { nx = x + 1; ny = 1; }

    dfs(nx, ny, sum);                            // 分支一：不取当前格
    if (canTake(x, y)) {                         // 分支二：取当前格
        used[x][y] = true;
        dfs(nx, ny, sum + a[x][y]);
        used[x][y] = false;                      // 回溯：还回去
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> T;
    while (T--) {
        cin >> n >> m;
        for (int i = 1; i <= n; ++i)
            for (int j = 1; j <= m; ++j) {
                cin >> a[i][j];
                used[i][j] = false;              // 多组数据：每组都要清空
            }
        memset(suf, 0, sizeof suf);              // 边界 suf[n+1][1] 必须是 0，多组数据要还原
        for (int i = n; i >= 1; --i)             // 从右下往左上递推后缀和
            for (int j = m; j >= 1; --j) {
                int nxt = (j == m) ? suf[i + 1][1] : suf[i][j + 1];
                suf[i][j] = a[i][j] + nxt;
            }
        best = 0;
        dfs(1, 1, 0);
        cout << best << "\n";
    }
    return 0;
}
关键片段拆解
片段作用
int suf[8][8];后缀和表：把「剩下所有格子的数字之和」预先算好，剪枝时 O(1) 查。
for (int i = n; i >= 1; --i)从右下往左上递推：每个位置 = 自己的值 + 下一个位置的后缀和。i = n、j = m 时会读到边界 suf[n+1][1]，所以上面先 memset 成 0。
if (sum + suf[x][y] <= best) return;所有数字非负，所以「后面全取」是这个分支能达到的上界；上界都不如已知最优就砍掉。
int nx = x, ny = y + 1; if (ny > m) { nx = x + 1; ny = 1; }把二维格子压成一条顺序，递归时只剩一个「下一个」。
dfs(nx, ny, sum);分支一：不取，什么都不改，直接往后走。
if (canTake(x, y))分支二：只有和已决定的 4 个邻格都不冲突才取。
used[x][y] = false;回溯：离开这一支前必须还回去，否则后面所有分支都以为这格被占了。
used[i][j] = false;多组数据：上一组的标记必须在这里清掉，否则第二组开始全错。
这题最容易错的地方
  • 邻域检查写错：只查上下左右 4 个方向（漏斜对角），或者「取」的分支干脆不检查 —— 两种都会取出相邻的数，答案偏大。
  • 回溯漏写 used[x][y] = false → 后面的分支全被挡住，答案偏小。
  • 多组数据忘了清空 used 或 best → 从第二组开始答案全错。
  • 剪枝里把 suf[x][y] 写成 suf[x][y + 1]，把当前格也算进「已取」→ 漏掉最优解。
大题 挑战题 3 · Walking Home B
洛谷 P7995普及/提高-去洛谷做这题 ↗

农场是一个 N × N 的方阵（2 ≤ N ≤ 50），草地在左上角 (1,1)，牛棚在右下角 (N,N)。

Bessie 只向下或向右走，有干草捆的格子（H）不能通过。她希望改变行走方向至多 K 次（1 ≤ K ≤ 3）。

求不同的路线数量。两条路线只要经过的格子集合不同就算不同。

输入格式：第一行一个整数 T（1 ≤ T ≤ 50），表示子测试用例数。每个用例的第一行是 N、K；接下来 N 行，每行 N 个字符，. 表示空格子，H 表示干草捆。保证起点和终点不是干草捆。

输出格式：共 T 行，第 i 行是第 i 个用例的路线数。

样例
输入： 2 3 1 ... .H. ... 3 2 ... ... ... 输出： 2 4
引导性提示（先只看这里）

只往右下走，所以一条路线最多 2N-2 步，可以完整枚举。

递归时多带两个信息：上一步的方向（下 / 右），以及已经转了几次方向。

换方向才 +1，沿原方向继续走不 +1；转向预算超了就不要走这一格。

想看思路了？点开完整思路

状态：dfs(x, y, turns, dir) 表示站在 (x,y)，已经转了 turns 次，最后一步的方向是 dir（0 下、1 右）。

分支：向下或向右，各判一次「这一格能不能走」和「换方向后 turns 是否超 K」。

出口：走到 (N,N) 就 ++ans，然后立刻 return。

起点的第一步不算转向，所以先单独迈出第一步（向下或向右），再进入递归。

为什么不会重复计数：只往右下走时，一条路线的方向序列唯一确定这条路线，反过来也唯一，所以枚举方向序列等于枚举路线。

复杂度：K = 3 时合法路线只有 O(N³) 级别，N ≤ 50 时不过十几万条，T ≤ 50 也跑得完。

#include <bits/stdc++.h>
using namespace std;

int T, n, K;
char g[55][55];
long long ans;

// x,y：当前位置；turns：已经转向几次；dir：0 表示上一步向下，1 表示向右
void dfs(int x, int y, int turns, int dir) {
    if (x == n && y == n) { ++ans; return; }      // 出口：到牛棚
    if (x + 1 <= n && g[x + 1][y] == '.') {       // 向下走一格
        int t = (dir == 1) ? 1 : 0;               // 原来向右，现在向下 = 转一次
        if (turns + t <= K) dfs(x + 1, y, turns + t, 0);
    }
    if (y + 1 <= n && g[x][y + 1] == '.') {       // 向右走一格
        int t = (dir == 0) ? 1 : 0;
        if (turns + t <= K) dfs(x, y + 1, turns + t, 1);
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> T;
    while (T--) {
        cin >> n >> K;
        for (int i = 1; i <= n; ++i)
            for (int j = 1; j <= n; ++j) cin >> g[i][j];

        ans = 0;
        if (g[2][1] == '.') dfs(2, 1, 0, 0);      // 第一步向下：前面没有方向，不算转向
        if (g[1][2] == '.') dfs(1, 2, 0, 1);      // 第一步向右：同样不算转向
        cout << ans << "\n";
    }
    return 0;
}

片段作用

if (x == n && y == n) { ++ans; return; }出口。走到牛棚就完成一条路线，必须立刻 return，否则还会继续往下试探。

  • 方向编码两处不一致（一处判断 dir == 0、另一处传了 2）→ 转向次数算错。

N 只小猫要坐索道下山（N ≤ 18）。第 i 只小猫重 Ci，每辆缆车的最大承重是 W，一辆车上小猫的重量之和不能超过 W。保证每只猫的重量都不超过 W。

每租一辆缆车要付 1 美元，求把所有小猫都运下山最少要付多少美元（也就是最少几辆车）。

输入格式：第一行两个用空格隔开的整数 N、W（1 ≤ Ci, W ≤ 10⁸）；接下来 N 行，每行一个整数 Ci。

输出格式：一个整数，表示最少缆车数。

样例
输入： 5 5 1 2 3 4 5 输出： 3
引导性提示（先只看这里）

把猫一只只往车上放：放进某一辆已经开过的车，或者新开一辆，这就是一棵搜索树。

直接枚举到 3¹⁸ 级别会超时，必须剪枝：当前车数已经不优于已知答案，就没必要再往下搜。

先放大猫。大猫可选的车少，越早把「车不够用」的分支砍掉，剪枝越有效。

想看思路了？点开完整思路

状态：dfs(i, cnt) 表示正在安排第 i 只猫，目前已经租了 cnt 辆车；car[j] 记第 j 辆车的当前载重。

分支：放进某辆还装得下的车；或者新开一辆车。

出口：i > N 时用 cnt 更新答案。

剪枝一（最优性）：cnt >= ans 时直接 return——已经租的车不比已知答案少，后面再完美也不可能更优。

剪枝二（对称性）：如果这只猫放进去之前那辆车是空的，说明前面几辆都装不下它；此时再试其它空车完全是重复枚举，直接 break。

排序：把 C 从大到小排。这是本题能过的关键，不是可有可无的优化。

复杂度：3^18 ≈ 3.9×10⁸ 太大，但排序 + 两条剪枝之后实际搜索量很小，N = 18 稳定通过。

#include <bits/stdc++.h>
using namespace std;

int n, W;
int c[25];
int car[25];              // car[j]：第 j 辆车当前的载重
int ans;

void dfs(int i, int cnt) {              // 安排第 i 只猫，已用 cnt 辆车
    if (cnt >= ans) return;             // 剪枝一：车数已不优于答案，放弃这一支
    if (i > n) {                        // 出口：全部安排完
        ans = cnt;                      // 能到这里的 cnt 一定比 ans 小
        return;
    }
    for (int j = 1; j <= cnt; ++j) {
        if (car[j] + c[i] <= W) {
            car[j] += c[i];
            dfs(i + 1, cnt);
            car[j] -= c[i];             // 回溯：把猫从车上拿下来
            if (car[j] == 0) break;     // 剪枝二：空车彼此等价，不再重复试
        }
    }
    car[cnt + 1] = c[i];                // 新开一辆车
    dfs(i + 1, cnt + 1);
    car[cnt + 1] = 0;                   // 回溯
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> W;
    for (int i = 1; i <= n; ++i) cin >> c[i];
    sort(c + 1, c + n + 1, greater<int>());   // 大猫先放，剪枝才狠
    ans = n;                                  // 上界：一只猫一辆车
    dfs(1, 0);
    cout << ans << "\n";
    return 0;
}

if (car[j] + c[i] <= W)塞得进第 j 辆车才塞；塞不下就换一辆，都不行就新开。

给定一组单词和一个开头字母，要求接出以该字母开头的最长的「龙」。每个单词最多在龙中出现两次。

两个单词相连时，重合部分合并成一部分（例如 beast 和 astonish 可以接成 beastonish）；相邻两部分不能存在包含关系，例如 at 与 atide 之间不能相连。

输入格式：第一行一个整数 n（n ≤ 20）表示单词数；接下来 n 行每行一个单词；最后一行为一个单字符，表示龙开头的字母。保证以该字母开头的龙一定存在。

输出格式：一行一个整数，表示以此字母开头的最长的龙的长度。

样例
输入： 5 at touch cheat choose tact a 输出： 23
引导性提示（先只看这里）

两个单词能不能接、接上以后长度增加多少，只跟这两个词有关，可以先把所有配对算好存起来。

「每个单词最多用两次」是全局状态，每用一个要记下来，退出这一支时要还回去。

想看思路了？点开完整思路

预处理：ov[i][j] = 单词 i 的后缀与单词 j 的前缀的最短非空重叠长度，0 表示接不上。对每对单词从小到大枚举 k（1 ≤ k < min(leni, lenj)），第一个满足「i 的最后 k 个字符 == j 的前 k 个字符」的 k 就是答案。

为什么要最小的 k：接上以后长度增加 len_j - k，k 越小增加越多。

状态：dfs(last, len) 表示当前龙以第 last 个单词结尾，总长度是 len。

每进入一个状态先 ans = max(ans, len)——龙可以随时停下，最长值不一定出现在最后一步。

分支：枚举下一个单词 j，跳过「已用两次」和「接不上」的。

回溯：used[j]++ 后递归，返回后 used[j]--。

起点：枚举所有首字母等于给定字母的单词，把它记为用了一次，从它开始搜。

本题是上古 NOIP 题，数据很弱，朴素回溯就能过；它的难度评级只对应「能通过原始数据」的做法。

参考代码
#include <bits/stdc++.h>
using namespace std;

int n, ans = 0;
string w[25];
int used[25];              // 每个单词已经用了几次
int ov[25][25];            // ov[i][j]：i 后面接 j 的最短重叠长度，0 表示接不上

// a 的后缀与 b 的前缀的最短非空重叠长度
int overlap(const string &a, const string &b) {
    int la = a.size(), lb = b.size();
    for (int k = 1; k < la && k < lb; ++k) {     // 重叠必须小于任一整词
        bool ok = true;
        for (int t = 0; t < k; ++t)
            if (a[la - k + t] != b[t]) { ok = false; break; }
        if (ok) return k;                        // 第一个合法的 k 就是最短的
    }
    return 0;
}

void dfs(int last, int len) {
    ans = max(ans, len);                         // 每一步都可能是最长
    for (int j = 0; j < n; ++j) {
        if (used[j] >= 2 || ov[last][j] == 0) continue;   // 用满两次 / 接不上
        used[j]++;
        dfs(j, len + (int)w[j].size() - ov[last][j]);     // 重叠部分只算一次
        used[j]--;                                        // 回溯：还回去
    }
}

int main() {
    cin >> n;
    for (int i = 0; i < n; ++i) cin >> w[i];
    char st;
    cin >> st;

    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            ov[i][j] = overlap(w[i], w[j]);

    for (int i = 0; i < n; ++i)
        if (w[i][0] == st) {                     // 只能从这个字母开头的词起头
            used[i]++;                           // 开头词本身也算用了一次
            dfs(i, (int)w[i].size());
            used[i]--;
        }
    cout << ans << "\n";
    return 0;
}
关键片段拆解
片段作用
int ov[25][25];预处理表：把「两词怎么接」从每次递归里挪到外面，只算一遍。
for (int k = 1; k < la && k < lb; ++k)重叠长度从 1 试到 min(la, lb)-1：等于整词长度是不允许的（那就是包含关系）。
if (a[la - k + t] != b[t])比较 a 的后 k 个字符与 b 的前 k 个字符。la - k 是这段后缀的起点。
if (ok) return k;k 从小到大枚举，第一个合法的就是最短重叠，也就是能加得最多的接法。
ans = max(ans, len);放在函数开头：这条链随时可以停，最长值可能出现在中间某一步。
if (used[j] >= 2 || ov[last][j] == 0) continue;两个跳过条件：次数用满，或者根本接不上。
dfs(j, len + (int)w[j].size() - ov[last][j]);增加的长度是新词长度减去重叠部分，重叠只算一次。
used[j]--;回溯。漏了这一句，每种词用满两次之后搜索树就断了，答案偏小。
if (w[i][0] == st)起点必须是给定字母开头的单词；这个字母本身不计入长度。
这题最容易错的地方
  • 重叠长度取错：取最大而不是最小 → 龙变短；允许重叠等于整词长度又违反了「不能包含」的规则。
  • used[j]-- 漏写 → 搜索提前被掐断，答案偏小。
  • 起点忘了给 used[i]++，第一个词被多用了第三次。
  • 只在「接不下新词」时才更新 ans：最长的链如果还能继续接，这个长度就取不到。

挑战 2 · 小木棍
洛谷 P1120提高+去洛谷做这题 ↗

有一些长度相同的小木棍，把它们随意砍成若干段，每段长度都不超过 50。现在给出砍完后每一段的长度，求原始木棍的最小可能长度。

输入格式：第一行一个整数 n（n ≤ 65）；第二行 n 个用空格隔开的整数，表示每一段的长度（每段 ≤ 50）。

输出格式：一行一个整数，表示原始木棍的最小可能长度。

样例：9 段分别是 5 2 1 5 2 1 5 2 1，总长 24。拼成 4 根长度 6 的木棍（5+1、5+1、5+1、2+2+2）是可行的，而长度小于 6 都拼不出来，所以答案是 6。

样例
输入： 9 5 2 1 5 2 1 5 2 1 输出： 6
引导性提示（先只看这里）

原始长度必须是总长的约数，而且不能小于最长的那一段——候选长度只有这么几个，从小到大试。

判定“能不能拼成若干根长度 L”要用搜索：一根一根地拼，每根木棍从剩下的段里挑。长度从大到小排序，先放长的，选择更少、失败更早。

光枚举会超时，必须加剪枝。想想这三种“注定失败”的情形：同一长度的段刚试过并失败了；一根木棍的第一段就找不到能配的；某一段正好把当前木棍填满、但后面却拼不通。

想看思路了？点开完整思路

第一步：把候选长度缩到几个。原始长度 L 必须满足 sum % L == 0，且 L ≥ 最长段（否则最长那段装不进去）。于是从最长段枚举到 sum，只试能整除的 L。

第二步：搜索的状态。dfs(group, cur, pos)：已经完整拼好了 group 根，当前这一根已经拼了 cur 长，接下来从下标 pos 往后挑段。目标是在 group 达到 sum / L 时成功。

第三步：排序。所有段从大到小排序。好处有二：分支更少（大的先放，剩下的空间小、选择少）；失败更早（大段放不下时立刻就能发现）。

剪枝一：同长度跳过。本层试过长度 x 且失败了，本层再遇到长度也是 x 的段就跳过——它们在“当前剩余空间”下的作用完全相同，试第二次必然同样失败。

剪枝二：第一段就失败，整支无解。若 cur == 0（这是新一根木棍的第一个选择）且放 a[i] 之后无法完成，那么直接返回 false。理由：若 a[i] 不能作为某根木棍的第一段，它就只能出现在别的木棍的中间；那根木棍的第一段与 a[i] 互换一下，仍然是一个合法方案，于是矛盾——所以这种情况一定无解。

剪枝三：正好填满却失败，整支无解。若 cur + a[i] == L（这根正好拼满）但后续失败，同样直接返回 false。理由与上一条同源：剩下的段在这个“刚好填满”的选择下都排不通，换成别的组合也只会更零碎。

出口。group == sum / L 时所有木棍都拼好了，返回 true；当前这一根拼满时递归到下一根：dfs(group + 1, 0, 0)。

复杂度。最坏是指数级，但三条剪枝叠加后，n ≤ 65 的标准数据在毫秒级出解。这题是“剪枝价值”的教科书案例：不加剪枝跑不完，加了剪枝连 1 秒都用不到。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int n, a[70], sumLen;
bool used[70];

// group：已拼好的整根数；cur：当前这根已拼长度；pos：从哪个下标往后挑
bool dfs(int group, int cur, int pos, int L, int need) {
    if (group == need) return true;                   // 全部拼好
    if (cur == L) return dfs(group + 1, 0, 0, L, need);   // 这一根拼满，开始下一根
    int fail = -1;                                    // 本层失败的段长度，同长度不再试
    for (int i = pos; i < n; ++i) {
        if (used[i] || a[i] == fail || cur + a[i] > L) continue;
        used[i] = true;
        if (dfs(group, cur + a[i], i + 1, L, need)) return true;
        used[i] = false;
        fail = a[i];                                  // 剪枝一：同长度跳过
        if (cur == 0) return false;                   // 剪枝二：新一根的第一段都失败了
        if (cur + a[i] == L) return false;            // 剪枝三：正好拼满却接不下去
    }
    return false;
}

int main() {
    cin >> n;
    for (int i = 0; i < n; ++i) { cin >> a[i]; sumLen += a[i]; }
    sort(a, a + n, greater<int>());                   // 从大到小：分支更少、失败更早

    for (int L = a[0]; L <= sumLen; ++L) {            // 候选长度：不小于最长段
        if (sumLen % L) continue;                     // 必须整除总长
        memset(used, 0, sizeof used);
        if (dfs(0, 0, 0, L, sumLen / L)) { cout << L << "\n"; return 0; }
    }
    cout << sumLen << "\n";                           // 兜底：全部拼成一根
    return 0;
}
关键片段拆解
片段作用
sort(a, a + n, greater<int>());从大到小排序。这是本题最便宜也最有效的一步：大段先放，剩余空间立刻变小，后续分支数跟着变少，失败也能更早暴露。
for (int L = a[0]; L <= sumLen; ++L)原始长度从“最长段”开始枚举，到总长结束。从大到小排序后 a[0] 就是最长段，它保证任何一根木棍都装得下最长的那一段。
if (sumLen % L) continue;整除是必要条件：所有木棍等长，总长必然是 L 的整数倍。这一句把候选从 3000 个缩到几十个。
dfs(group, cur, pos, L, need)五个参数各管一件事：拼到第几根、当前根已多长、从哪往后挑、目标长度、一共要拼几根。把 L 和 need 放进参数只是为了少用全局变量，逻辑上它们全程不变。
if (cur == L) return dfs(group + 1, 0, 0, L, need);当前这根拼满就开新的一根，注意 pos 要回到 0——剩下的段重新从头挑。
if (used[i] || a[i] == fail || cur + a[i] > L) continue;三个跳过条件写在一起：用过、与本层刚失败的同长、放进去会超出当前木棍。
fail = a[i];记录“本层刚刚失败的长度”。因为数组已排序，后面遇到同样长度的段连试都不用试。
if (cur == 0) return false;剪枝二。新一根木棍的第一段试 a[i] 失败，说明 a[i] 放不进任何一根木棍的开头，整支方案必失败——用交换论证可以严格证明。
if (cur + a[i] == L) return false;剪枝三。a[i] 正好把当前木棍填满却接不下去，说明这个“刚好”的组合把剩余部分切碎了，换成更小的段只会更碎。
memset(used, 0, sizeof used);每个候选长度 L 都要重新开一局，used 必须清零。漏了这一句，第二个候选会带着上一局的标记。
这题最容易错的地方
  • 不加“同长度跳过”：n = 65 且大量重复长度时直接退化成阶乘级，必 TLE。
  • 剪枝二、三写成 continue 而不是 return false：答案仍然对，但剪枝几乎失效。
  • 候选长度从 1 开始枚举或忘了判 sumLen % L：多跑几十倍无用搜索，还可能输出比最长段还小的 L。
  • 忘记 memset(used, 0, ...)：第 2 个候选长度带着第 1 个的残留标记，答案直接错。
