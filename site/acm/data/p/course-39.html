概率的第一性原理仍然是计数：把所有等可能的情况数清，分子是符合条件的那部分。期望在此之上多一步——把每个结果乘上它的概率，再全部相加。竞赛里这两件事都不用“模拟”，只用一个公式：期望的线性性。

别去算整体的分布，去算每一个最小单位的贡献。它通常只依赖常数个数据，于是 2ⁿ 种情况被压成 n 个乘法。

三个公式打底。P(Ā) = 1 − P(A)：补集，恒成立，是“至少一个”类问题的首选。P(A∪B) = P(A) + P(B) − P(A∩B)：一般并，恒成立。P(A∩B) = P(A)·P(B)：只在 A、B 独立时成立。

“独立”的意思是：一个发生与否，不改变另一个的概率。两道题的正确答案分别是什么，是独立的；同一道题的两个不同选项，不独立。判断独立性不能靠感觉，要看两个事件的信息是否互相影响。

运算公式前提典型场景
补集P(Ā) = 1 − P(A)永远成立至少中一次、全部装错
互斥相加P(A∪B) = P(A) + P(B)A、B 不能同时发生掷出 1 或 2
一般并P(A∪B) = P(A)+P(B)−P(A∩B)永远成立两张牌至少一张是红桃
独立相乘P(A∩B) = P(A)·P(B)A、B 独立两次射击都命中
条件概率P(A|B) = P(A∩B)/P(B)P(B) > 0已知第一次是正面

两个可以立刻心算的例子：掷两枚硬币至少一个正面，1 − (1/2)(1/2) = 3/4；掷两枚骰子和为 7，只有 (1,6)(2,5)(3,4)(4,3)(5,2)(6,1) 六种，6/36 = 1/6。所有“和为几”的问题都是数点对，不要背公式。

新函数拆解 · 期望的线性性
E[X + Y] = E[X] + E[Y] // 恒成立，不需要独立 E[a·X + b] = a·E[X] + b
组成含义 / 格式要求
X、Y 是什么同一个随机试验上的两个量。可以是任意两个量，甚至互相依赖。
为什么不需要独立证明只用到“联合概率求和”和分配律，独立二字根本没进推导（见本节数学补给）。
最强的用法把总分拆成一堆 0/1 指示变量之和：X = X₁ + X₂ + … + Xₙ，Xᵢ 只标记“第 i 件事发生了”。于是 E[X] = Σ P(第 i 件事发生)，整体期望变成 n 个局部概率相加。
不能乱用乘法没有线性性：一般 E[XY] ≠ E[X]·E[Y]（只有独立时才相等）；E[X²] ≠ (E[X])²。
常见误解“期望”不是“最可能的值”。一枚均匀骰子的期望是 3.5，而 3.5 永远不会掷出来。

局部概率通常只依赖常数个数据（例如相邻两道题的选项数），于是整题从 O(2ⁿ) 降到 O(n)。

新函数拆解 · 除法取模：逆元与费马小定理
long long inv(long long a) { return qpow(a, MOD - 2); } // MOD 是质数 ans = p % MOD * inv(q) % MOD; // p/q mod MOD
组成含义 / 格式要求
为什么不能直接除(a/b) mod MOD ≠ (a mod MOD) / (b mod MOD)。例如 1/2 mod 7：直接除得 0，正确答案是 4，因为 2×4 = 8 ≡ 1 (mod 7)。
逆元的定义a·a⁻¹ ≡ 1 (mod MOD)。把“除以 a”换成“乘以 a⁻¹”，除法就消失了。
费马小定理MOD 是质数且 a 不是 MOD 的倍数时，a^(MOD−1) ≡ 1，于是 a⁻¹ ≡ a^(MOD−2)。一次快速幂，O(log MOD)。
两个前提① MOD 必须是质数（10⁹+7、998244353 都行）；② 分母 q 不能是 MOD 的倍数，否则逆元不存在。
常用值mod 10⁹+7 下：1/2 = 500000004，1/3 = 333333336，1/6 = 166666668，1/7 = 142857144。
最小可运行示例
示例
const long long MOD = 1000000007;

long long qpow(long long a, long long b) {
    long long res = 1 % MOD; a %= MOD;
    while (b) { if (b & 1) res = res * a % MOD; a = a * a % MOD; b >>= 1; }
    return res;
}

// 掷一次骰子出现 6 的概率是 1/6，写成模意义下的数：
cout << 1 * qpow(6, MOD - 2) % MOD << "\n";       // 166666668
// 验算：6 × 166666668 = 1000000008 = MOD + 1 ≡ 1
注意

什么时候用哪套：要求输出实数 → double；要求输出“答案 mod 998244353” → 逆元。后者越来越常见，因为它彻底没有精度问题。

多个分数相加时，逐项换成逆元再加，不要先把分母乘起来——分母的乘积极容易变成 MOD 的倍数，那时逆元就不存在了。

例题 · 单选错位洛谷 P1297提高+/省选-去洛谷做这题 ↗

n 道单选题，第 i 道题有 aᵢ 个选项，每个选项成为正确答案的概率相等。gx 全部做对了，但把第 i 题的答案填到了第 i+1 题的位置上（第 n 题的答案填到第 1 题）。求他期望做对几道题。

输入：一行 5 个整数 n, A, B, C, a₁（2 ≤ n ≤ 10⁷，0 ≤ A, B, C ≤ 10⁸）。因为 n 很大，a 由规则生成：q₁ = a₁，qᵢ = (qᵢ₋₁·A + B) mod 100000001（i ≥ 2），最后 aᵢ = qᵢ mod C + 1。

输出：一个实数，期望做对的题数，保留三位小数。

样例说明（n = 3，a = {2, 3, 1}）： 6 种正确答案等概率，对应做对 3、1、1、1、1、0 题 期望 = 7/6 ≈ 1.167，输出 1.167
例题怎么想：把“做对几题”拆成 n 个 0/1

先处理输入。这不是“读 n 个数”，而是读 5 个参数再按规则生成 a。规则里有个陷阱：qᵢ 用的是还没 mod C 的 qᵢ₋₁ 迭代，两步必须分开——先把整串 q 生成完，再统一做 aᵢ = qᵢ mod C + 1。混在一起写，从第 2 项起就全错。

概率部分：设 Xᵢ = 1 表示“抄到第 i+1 题位置上的那个答案，恰好等于第 i+1 题的正确答案”。第 n 题的答案填在第 1 题的位置，所以 Xₙ 看的是第 1 题。做对的题数 X = X₁ + X₂ + … + Xₙ，每个 Xᵢ 只取 0 或 1。

由线性性，E[X] = Σ E[Xᵢ] = Σ P(Xᵢ = 1)。这一步把题目之间的所有关联切断了：不需要知道 2ⁿ 种全局情况，也不需要管 X₁ 与 X₂ 是不是独立，每题单独算概率就行。

算 P(Xᵢ = 1)。第 i+1 个位置上写的是“第 i 题的正确答案”，它在 1..aᵢ 上均匀，概率 1/aᵢ；第 i+1 题的正确答案在 1..a_{i+1} 上均匀，概率 1/a_{i+1}，而且两者独立。于是

P = Σ_{v=1}^{min(aᵢ,aᵢ₊₁)} (1/aᵢ)(1/aᵢ₊₁) = min/(aᵢ·aᵢ₊₁) = 1/max(aᵢ, aᵢ₊₁)。一个“最小值除以乘积”，化简后就是一个“最大值取倒数”。

所以答案 = Σ_{i=1}^{n} 1/max(aᵢ, aᵢ₊₁)，其中 a_{n+1} = a₁。用样例 a = {2,3,1} 验算：1/3 + 1/3 + 1/2 = 7/6 ≈ 1.167，与题面一致。

实现：n ≤ 10⁷，开数组要 40 MB；但每一项只依赖相邻两个 a，边生成边累加即可，额外空间 O(1)。注意第 n 题的答案要填到第 1 题，所以循环结束后还差一项，别漏。

精度：n 项相加，每项 ≤ 1，和 ≤ 10⁷。double 的相对误差 10⁻¹⁶，累加 n 项的绝对误差约 10⁻⁹ 量级，保留三位小数完全安全。

完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, A, B, C;
    long long a1;
    cin >> n >> A >> B >> C >> a1;

    // 生成规则分两步：先按递推算出未取模的 q，再统一做 q mod C + 1。
    // 这里用流式写法：raw 保存"未 mod C"的值，first / prev 保存真正用到的 a。
    long long raw = a1;
    int first = (int)(raw % C) + 1;       // 第 1 题的选项数
    int prev  = first;
    double ans = 0;

    for (int i = 2; i <= n; ++i) {
        raw = (raw * A + B) % 100000001;  // raw·A 最大约 10¹⁶，long long 才装得下
        int cur = (int)(raw % C) + 1;
        ans += 1.0 / max(prev, cur);      // E[X_{i-1}] = 1 / max(a_{i-1}, a_i)
        prev = cur;
    }
    ans += 1.0 / max(prev, first);        // 第 n 题的答案填在第 1 题，补上最后一项

    printf("%.3f\n", ans);
    return 0;
}

上面那题能拆，是因为每一小份的概率可以独立算出来。很多题拆不动：下一步去哪由当前状态决定，同一道题里的概率互相纠缠。这时改用 DP，设 dp[s] = 从状态 s 出发到结束的期望代价，终点 dp[终点] = 0。

关键在方向。dp[s] 的值依赖“从 s 一步能到达的那些状态”，所以必须先算离终点近的状态，也就是倒着推。这和上一节“只看 dp 依赖谁”是同一条规矩：依赖更大的下标，就从大到小扫。

为什么不能正推？正推时每个状态要乘上“到达它的概率”，而那个概率本身还得再递推一层；倒推时每个状态只算一次，而且 dp[终点] 是已知的 0，整条链从末端固定下来。

倒推模板 + 一个骰子问题

模板只有五行（示意，真实的边枚举那一行要换成你自己的循环）。看清楚那个“1”是什么：它是走一步本身的代价，不是概率。

倒推模板（示意）
dp[终点] = 0;                                  // 边界：到终点不用再走
for (状态 s，按"离终点从近到远"的顺序) {        // 倒序！通常就是逆拓扑序
    dp[s] = 0;
    for (每个一步可达的 t)                          // 换成你的边枚举
        dp[s] += p(s -> t) * (cost(s -> t) + dp[t]);   // 全期望公式
}
// 答案 = dp[起点]

例：一枚均匀骰子，每次掷出 1~6 中的一个。从位置 0 出发，走到 ≥ n 就停，求步数期望。

设 dp[i] = 从位置 i 出发到结束的期望步数。i ≥ n 时已经结束，dp[i] = 0。i < n 时掷出 k（概率 1/6），花费 1 步，到达 min(i+k, n)。于是

转移方程
dp[i] = 1 + (1/6) · Σ_{k=1..6} dp[ min(i + k, n) ]

这个方程“自己包含自己”，但 dp[i] 只依赖 i+1..i+6，全是更大的下标，所以从 n−1 倒着扫一遍就能一次算完，不需要解方程。

骰子的完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;

    vector<double> dp(n + 7, 0.0);        // dp[n..n+6] = 0：已经到达或越过终点
    for (int i = n - 1; i >= 0; --i) {    // 倒着扫：dp[i] 只依赖更大的下标
        double s = 0;
        for (int k = 1; k <= 6; ++k) s += dp[min(i + k, n)];
        dp[i] = 1 + s / 6;                // 那个 1 是"这一步"本身的代价
    }

    printf("%.6f\n", dp[0]);
    return 0;
}

数学补给 · 线性性为什么恒成立；几何分布；误差怎么算

先证线性性。设 X、Y 定义在同一试验上，联合分布为 P(X=x, Y=y)。期望的定义是“值 × 概率”求和，于是

线性性的证明
E[X+Y] = Σ_x Σ_y (x+y)·P(X=x, Y=y)
       = Σ_x x·Σ_y P(X=x, Y=y)  +  Σ_y y·Σ_x P(X=x, Y=y)
       = Σ_x x·P(X=x)  +  Σ_y y·P(Y=y)
       = E[X] + E[Y]

中间那步只用了“边缘概率 = 联合概率求和”和分配律，独立二字从未出现。这就是它可以无条件使用的原因。而 E[XY] = E[X]E[Y] 需要把 P(X=x,Y=y) 拆成 P(X=x)P(Y=y)，那一步只有独立时才成立。

再看几何分布：每次成功概率 p，独立重复，求首次成功所需次数的期望。设所求为 E。第一次就成功（概率 p）花 1 次；失败（概率 1−p）花 1 次，然后一切重来，还要 E 次。于是

几何分布的期望
E = 1 + (1 − p)·E      →      p·E = 1      →      E = 1/p

用级数验证：E = Σ_{k≥1} k(1−p)^(k−1)·p = p/(1−(1−p))² = 1/p。p = 1/6 时 E = 6：等一个 6 平均要掷 6 次。这个“E = 1 + (1−p)E”的自指写法，正是倒推 DP 的雏形。

方差的三条常用性质：Var(X) = E[X²] − (E[X])²，Var(aX+b) = a²·Var(X)，独立时 Var(X+Y) = Var(X) + Var(Y)。注意 E[X²] ≠ (E[X])²——这就是为什么 OSU! 那类题必须单独维护“平方的期望”和“立方的期望”。

最后算一笔精度的账。double 有 53 位尾数，机器精度 ε ≈ 2.2×10⁻¹⁶。累加 n 项的相对误差最坏约 n·ε：n = 10⁷ 时是 2.2×10⁻⁹，n = 10⁹ 时是 2.2×10⁻⁷。

n（累加项数）相对误差 ≈ n·ε和 ≈ n 时的绝对误差3 位小数安全吗
10³2.2×10⁻¹³2.2×10⁻¹⁰安全
10⁵2.2×10⁻¹¹2.2×10⁻⁶安全
10⁷2.2×10⁻⁹0.022和是 10⁷ 量级时危险
10⁹2.2×10⁻⁷220完全不能用 double 直接加

结论：误差要看绝对量级，不能只看项数。P1297 的和不超过 10⁷ 而每项 ≤ 1，实际误差远小于上界，所以 double 稳过。但如果你在累加 10⁹ 个 10⁹ 量级的数，就必须换 long double、Kahan 求和或干脆取模。

取模那一侧没有误差问题，只有“逆元存不存在”的问题：mod 10⁹+7 下 1/2 = 500000004、1/3 = 333333336、1/6 = 166666668、1/7 = 142857144。验算只有一个办法：把逆元乘回分母，结果必须是 1。

  1. 为什么“做对题数”能拆成 n 个概率相加，而“做对题数的平方”不能？把 (X₁+…+Xₙ)² 展开，看看多出了哪些交叉项，它们在什么条件下才能拆开。
    想好了？点开核对思路与解析
    线性性只对一次式成立。(X₁+…+Xₙ)² = ΣXᵢ² + 2Σi<jXᵢXⱼ，而 Xᵢ 是 0/1 变量，Xᵢ² = Xᵢ，所以平方的期望 = E[X] + 2Σi<jP(Xᵢ=1 且 Xⱼ=1)。交叉项要算的是联合概率，只有 Xᵢ 与 Xⱼ 独立时才等于 P(Xᵢ=1)·P(Xⱼ=1)。P1297 里 Xᵢ 和 Xᵢ₊₁ 都用到 aᵢ₊₁，本来就不独立，所以拆不开。常见错路：把 E[X²] 直接写成 (E[X])²——这只在 X 几乎必然是常数时才对。
  2. 如果 P1297 改成“第 i 题的答案抄到第 i+2 题的位置”，答案会变成什么？为什么公式里还是“取最大值再取倒数”？
    想好了？点开核对思路与解析
    答案变成 Σ 1/max(aᵢ, ai+2)（下标循环，an+1=a₁、an+2=a₂）。推导一模一样：第 i 题的答案在 1..aᵢ 上均匀，第 i+2 题的正确答案在 1..ai+2 上均匀，两者独立，重合部分 min 个，概率 = min/(aᵢ·ai+2) = 1/max(aᵢ, ai+2)——偏移量只改配对的下标，不改这个化简。常见错路：忘了 n 必须大于偏移量。偏移 2 时 n = 2 会把答案抄回原位，正确期望是 2，公式给的是 1/a₁+1/a₂。
  3. 掷骰子直到连续两次都是 6 才停，期望掷几次？状态只有“当前连续 6 的个数 0 / 1 / 2”三种，试着倒推列方程。
    想好了？点开核对思路与解析
    答案 42 次。设 E₀ = 当前没有连续 6、E₁ = 已连一个 6，E₀ = 1 + (1/6)E₁ + (5/6)E₀，E₁ = 1 + (1/6)·0 + (5/6)E₀。第一式化简得 E₀ = 6 + E₁，代进第二式的变形 E₁ = 1 + (5/6)E₀，解得 E₀ = 42、E₁ = 36。常见错路：套几何分布的 1/p = 6——那等的是“出现一次 6”，不是“连续两次”；或者把失败时回到的状态写成 E₁ 而不是 E₀（掷出非 6 就把连击清零了）。
  4. 图上有环时为什么不能倒推？举一个环上最简单的例子（两个点互相走），说明“列方程”和“不断代入”分别怎么做。
    想好了？点开核对思路与解析
    有环时 dp[s] 依赖 dp[t]、dp[t] 又依赖 dp[s]，状态依赖图没有拓扑序，“离终点从近到远”这个顺序不存在，倒推必然读到还没算的 0。例子：A 一定走到 B，B 以 1/2 走回 A、1/2 到终点。列方程：dp[A] = 1 + dp[B]、dp[B] = 1 + 0.5·dp[A]，解线性方程组得 dp[B] = 3、dp[A] = 4（状态数 n 时用高斯消元，O(n³)）。不断代入：随便取初值，反复执行 dp[s] ← 1 + Σ p·dp[t]，每轮误差按“留在环里的最大概率”缩小，收敛到同一组解；若环上没有出边（永远逃不出去），期望是无穷，迭代不收敛。常见错路：直接倒推，得到的其实是“最多走几步”，而不是期望。
  5. 什么情况下必须用逆元而不能用 double？如果分母恰好是 MOD 的倍数，逆元不存在，这时题目通常保证了什么？
    想好了？点开核对思路与解析
    题目要求输出“答案 mod 998244353 / 10⁹+7”时必须用逆元：double 给出的是小数，根本变不回模值；答案的有效数字超过 15~16 位时 double 也不够。分母是 MOD 的倍数时逆元不存在，题目通常用两种办法回避：MOD 取大质数（10⁹+7），而分母来自 n ≤ 10⁵ 或 n! 且保证 n < MOD，于是分母一定与 MOD 互质。常见错路：先把所有分母乘起来再一次求逆元——乘积很容易变成 MOD 的倍数，那时逆元真的不存在；正确做法是逐项求逆元再相加，或者最后一次性约分。
  6. n 个人随机坐 n 个座位，“恰好 k 个人坐对”的方案数是 C(n,k)·D(n−k)。这个式子里哪一部分是计数、哪一部分是概率？
    想好了？点开核对思路与解析
    C(n,k) 和 D(n−k) 都是计数：前者数“选哪 k 个人坐对”，后者数“剩下 n−k 个人全部坐错”的排法，乘起来是“恰好 k 个坐对”的方案数；概率要再除以总方案数 n!，即 P = C(n,k)·D(n−k)/n!。这里没有概率参与乘法，只有等可能模型的“数情况”。常见错路：把 C(n,k)·D(n−k) 当成概率直接输出（结果远大于 1）；或者忘了“恰好”而算成“至少 k 个坐对”。

挑战题 · OSU!
洛谷 P1654提高-去洛谷做这题 ↗

一共 n 次操作，每次成功记 1、失败记 0，得到一个 01 串。串中每一段极长的连续 1，若长度为 X，就贡献 X³ 分（不同段分别计分）。给出每次操作的成功率，求最终得分的期望。

输入：第一行一个整数 n（n ≤ 10⁵），接下来 n 行每行一个 [0,1] 之间的实数 pᵢ，表示第 i 次操作的成功率。

输出：一个实数，四舍五入保留 1 位小数。

引导性提示（先只看这里）

不要指望“得分的期望 = 长度的期望的立方”。E[X³] ≠ (E[X])³。

把总分拆成“每一步新增的分数”。如果第 i 步成功，且它左边已经连了 L 个 1，这一步让分数增加多少？

把 (L+1)³ 减 L³ 展开，你会发现只需要维护“L 的期望”和“L² 的期望”两个量。

想看思路了？点开完整思路

只看第 i 位。设它左边紧挨着的连续 1 的长度为 L（第 i 位是 0 时 L 取 0）。若第 i 位成功，这一段从长度 L 变成 L+1，分数增加 (L+1)³ − L³ = 3L² + 3L + 1；若失败，增加 0。把每一步的增量加起来，正好等于最终的 X³ 之和（每一段内部逐项累加，首尾相接）。

于是总分的期望 = Σ E[第 i 步的增量]，这一步用线性性，不需要任何独立性假设。

而 E[第 i 步的增量] = pᵢ · (3·E[L²] + 3·E[L] + 1)。这里又用了一次线性性：把 3L² + 3L + 1 的期望拆成三项期望。注意 (L+1)³ 展开里有 L·L 这种项，所以 E[L²] 必须单独维护——它就是“为什么不能只存 E[L]”的全部原因。

维护两个量：e1 = E[L]、e2 = E[L²]。第 i 位之后，若成功则 L 变成 L+1，否则 L 变成 0。于是 e1 = p(e1+1)，e2 = p(e2 + 2e1 + 1)。

★ 更新顺序：先用旧的 e1、e2 算出这一步的期望增量，再用旧的 e1 更新 e2，最后更新 e1。顺序错一步，e2 里就会混进新的 e1。

复杂度 O(n)，n = 10⁵。答案最大到 n³ = 10¹⁵，用 double（它对 10¹⁵ 的 ulp 约 0.125，本题数据允许）；保险起见也可以开 long double。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    scanf("%d", &n);

    double e1 = 0, e2 = 0;       // e1 = E[L]，e2 = E[L²]，L 是"以当前位置结尾的连续 1 长度"
    double ans = 0;

    for (int i = 1; i <= n; ++i) {
        double p;
        scanf("%lf", &p);

        ans += p * (3 * e2 + 3 * e1 + 1);   // 先用旧的 e1、e2 算这一步的期望增量
        e2 = p * (e2 + 2 * e1 + 1);         // 再用旧的 e1 更新 e2（顺序不能换）
        e1 = p * (e1 + 1);                  // 最后更新 e1
    }

    printf("%.1f\n", ans);
    return 0;
}
关键片段拆解
片段作用
double e1 = 0, e2 = 0;初始时左边没有 1，L = 0，所以 E[L] = E[L²] = 0。
ans += p * (3*e2 + 3*e1 + 1);★ 核心公式。(L+1)³ − L³ = 3L² + 3L + 1，再乘上“这一步成功”的概率 p。失败时增量为 0，所以只乘 p，不用乘 (1−p)。
e2 = p * (e2 + 2*e1 + 1);若成功，L 变成 L+1，于是 L² 变成 L²+2L+1，取期望得 e2+2e1+1；若失败 L 归零。所以在 p 概率下取这个值。
e1 = p * (e1 + 1);同样的道理，成功时长度加一，失败时归零。
更新顺序e2 的更新式里要用旧的 e1。先更新 e1 再更新 e2，就把新的 e1 混进去了，答案会偏大。习惯写法：算 ans → 更新 e2 → 更新 e1。
printf("%.1f\n", ans);题目要求保留 1 位小数。n = 3、三次都是 0.5 时，输出 6.0。
这题最容易错的地方
  • 把 E[X³] 当成 (E[X])³，或者以为“总分的期望 = 期望长度的立方”。三次方不满足线性性。
  • 只维护 e1 不维护 e2。展开 (L+1)³ 时会出现 3L²，缺了这一项答案会明显偏小。
  • 更新顺序反了：先更新 e1 再用它更新 e2，等于用了 L+1 去算 L²，答案偏大。
  • 把“每一段的 X³”理解成“整串 1 的个数的立方”。分段计分是题目的关键设定，样例里 101 得 2 分就是证据。

挑战 2 · 奖励关
洛谷 P2473提高+/省选-去洛谷做这题 ↗

奖励关会依次随机抛出 k 次宝物，每次从 n 种宝物中等概率独立地选一种（可以重复）。每次抛出后你都可以选择吃或不吃，不吃就永久失去它。

第 i 种宝物值 pᵢ 分（可以为负），但它有一个前提集合 sᵢ：只有当 sᵢ 中所有宝物都至少吃过一次，才能吃第 i 种。若抛出时前提不满足，这一轮机会白丢。

假设你采取最优策略，求平均情况下一共能得到的分数。

输入格式：第一行两个整数 k、n（1 ≤ k ≤ 100，1 ≤ n ≤ 15）。接下来 n 行，第 i 行先是一个整数 pᵢ，接着若干个互不相同的整数表示前提宝物编号，行末一个 0 表示该行结束。

输出格式：一行一个实数，保留六位小数。数据范围 −10⁶ ≤ pᵢ ≤ 10⁶。

样例
输入： 1 2 1 0 2 0 输出： 1.500000
引导性提示（先只看这里）

“已经吃过哪些宝物”最多 15 种，正好压成一个 0..2¹⁵−1 的整数——第 34 节的老办法。

期望题必须回答“当前处于什么局面”，于是状态是（进行到第几轮）×（已吃集合）。

同一局面之后会发生什么与“怎么走到这里”无关，所以可以从最后一轮倒着往前推，dp[结束] = 0。

想看思路了？点开完整思路

状态 dp[i][S]：已经抛了 i 次、当前吃过的集合是 S，从第 i+1 次到第 k 次还能拿到的期望分数。

边界 dp[k][S] = 0：没有轮次了，收益为 0。答案 dp[0][0]。

倒推：第 i+1 次抛出宝物 j 的概率是 1/n。若 S 已包含 j 的全部前提，最优选择是 max(不吃 dp[i+1][S], 吃 dp[i+1][S ∪ {j}] + pⱼ)；否则只能不吃，得 dp[i+1][S]。把这 n 种情况取平均就是 dp[i][S]。

为什么可以倒推：dp[i][S] 只引用 dp[i+1][·]，阶段单向递增，依赖图是 DAG（第 31 节讲的“阶段推进”），所以从 i = k−1 往前算，每一步用到的值都已算好。

为什么“吃”要额外 + pⱼ：这一轮的收益只由这一轮的决定产生，未来的收益已经含在 dp[i+1][·] 里了——期望的线性性加上最优子结构。

为什么能吃也可能不吃：pⱼ 允许为负，max 自动处理“为了拿到前提而先吃负分宝物”的情形——这正是本题不能贪心、必须 DP 的原因。

复杂度：k·2ⁿ·n = 100×32768×15 ≈ 5×10⁷ 次 double 运算；滚动数组后空间只有 2×2¹⁵×8 B = 512 KB。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int k, n;
int p[16];                     // 每种宝物的分数
int pre[16];                   // 每种宝物的前提宝物集合（位掩码）
double dp[2][1 << 15];         // dp[S]：当前已吃集合为 S，还能拿到的期望分数

int main() {
    scanf("%d %d", &k, &n);
    for (int i = 0; i < n; ++i) {
        scanf("%d", &p[i]);
        int t;
        while (scanf("%d", &t) == 1 && t != 0) pre[i] |= 1 << (t - 1);   // 读到 0 结束
    }

    for (int i = k - 1; i >= 0; --i) {          // 倒推：从最后一轮往前推
        int cur = i & 1, nxt = cur ^ 1;         // 滚动数组：只留相邻两层
        for (int S = 0; S < (1 << n); ++S) {
            double val = 0;
            for (int j = 0; j < n; ++j) {
                if ((S & pre[j]) == pre[j])     // 前提齐了：吃和不吃里挑大的
                    val += max(dp[nxt][S], dp[nxt][S | (1 << j)] + p[j]);
                else                            // 前提没齐：这一轮只能白丢
                    val += dp[nxt][S];
            }
            dp[cur][S] = val / n;               // n 种宝物等概率出现
        }
    }
    printf("%.6f\n", dp[0][0]);
    return 0;
}
关键片段拆解
片段作用
while (scanf("%d", &t) == 1 && t != 0) pre[i] |= 1 << (t - 1);行末的 0 是结束标记；宝物编号 t 对应第 t−1 位。
for (int i = k - 1; i >= 0; --i)倒推。写成从 0 往上推，用到的下一层全是 0。
int cur = i & 1, nxt = cur ^ 1;滚动数组：dp[i] 只依赖 dp[i+1]，留两层就够，27 MB 压到 512 KB。
if ((S & pre[j]) == pre[j])前提全部满足。只写 S & pre[j] 会把“满足一部分”也当成满足。
max(dp[nxt][S], dp[nxt][S | (1 << j)] + p[j])吃与不吃取优。pⱼ 为负时 max 自动选择不吃，不用特判。
dp[cur][S] = val / n;n 种宝物等概率出现，除以 n 才是期望。
这题最容易错的地方
  • 正推 i（i 从 0 到 k−1）：用到的 dp[i+1] 还是 0，答案恒为 0。
  • 前提判断写成 if (S & pre[j])：只要满足一个前提就算能吃，答案偏大。
  • 把 pⱼ 加到“不吃”那一支上：等价于吃了不给分，答案偏小。
  • 忘了除以 n：期望被放大 n 倍。
