DP 不是一种算法，是一种把“重复计算”换成“查表”的写法。数字三角形 n = 1000 层，从顶到底的路径有 2⁹⁹⁹ 条，暴搜到宇宙热寂也跑不完；但互不相同的子问题只有 n(n+1)/2 ≈ 5×10⁵ 个。同一个子问题被重复算了天文数字次，DP 的全部工作就是让每个子问题只算一次、把结果存进数组。

写 DP 之前先在草稿纸上回答四个问题：状态是什么、怎么转移、边界在哪、答案是哪个格子。四个问题答完，代码不到 10 行；答不出来，抄模板必错。
  • ① 状态：用 dp[...] 的下标把子问题编码出来，数组的值就是这个子问题的答案。判断状态定得好不好，只看一条——能不能用规模更小的状态把当前状态算出来。
  • ② 转移：dp[当前] = 若干 dp[更小规模] 的 max / min / 和。本质是分类讨论“最后一步从哪来”，把所有来源列全，一个不漏。
  • ③ 边界：最小的、不需要转移就能直接写出来的状态，通常是 dp[0] 或第一行。边界写错，整张表都是垃圾。
  • ④ 答案：最终输出哪个格子？dp[n]？dp[n][n]？还是 max(dp[n][1..n])？至少三分之一的 WA 出在这一步。

无后效性是 DP 能不能用的唯一门槛：一个状态一旦确定，之后怎么走与“怎么走到这里”无关。数字三角形里 dp[i][j] 只记“走到 (i,j) 的最大和”，不需要知道具体走了哪条路——满足。如果题目改成“路径上不许出现两个相邻的相同数字”，dp[i][j] 立刻不够用，因为还得记住上一格是谁。

判断方法是一句话：要算出下一个状态，我还需要知道历史里的什么？答案是“什么也不需要”，直接 DP；答案是“需要知道某段历史”，就在下标里加一维把那点历史记下来。下一节背包多出来的那一维（选没选过）、后面状压 DP 多出来的那一维（哪些点走过），都是这个思路。

新函数拆解 · dp 数组：状态定义模板
int dp[MAXN][MAXN]; // dp[阶段][位置] = 这个子问题的最优值
组成含义 / 格式要求
dp数组名。规模大（10⁶ 以上）或二维的，一律开在 main 外面，走静态区。
第一维：阶段处理到第几行、前几个元素、走了几步、容量用了多少。挑一个只会增大的量当阶段，遍历顺序就天然合法。
第二维：位置当前停在哪一列、下标多少、还剩多少容量。转移时在这一维上左右移动。
值该子问题的答案：最大和 / 最小代价 / 方案数。值的类型决定会不会溢出，最值题一般 int 够，求和与计数先估上界。
初值最省事的做法：整表填 0 或整表填 −INF，再单独写边界。绝不能让“没算过”的格子参与 max。
注释每写一个 dp 数组，先写一行注释把含义写全。注释写不出来，说明状态还没想好，这时候敲代码只是在延长错误。

新函数拆解 · fill / memset：把 dp 表刷成同一种初值

组成含义 / 格式要求
fill(begin, end, v)把左闭右开区间 [begin, end) 逐元素赋成 v。能填任意 int / long long 值，最通用。

例题 · 数字三角形洛谷 P1216普及-去洛谷做这题 ↗

给出一个 n 层的数字三角形，第 i 层有 i 个整数。从顶层唯一的那个数出发，每一步可以走到下一层的正下方或右下方（第 i 层第 j 列可以走到第 i+1 层第 j 列或第 j+1 列）。求一条从顶到底的路径，使路径上所有数字之和最大，输出这个最大和。

输入：第一行一个整数 n（1 ≤ n ≤ 1000）；接下来 n 行，第 i 行 i 个非负整数（每个不超过 100）。

输出：一行一个整数，即最大路径和。

输入： 5 7 3 8 8 1 0 2 7 4 4 4 5 2 6 5 输出： 30
例题怎么想：先在草稿纸上把四步填完

暴力：从顶走到底，每层 2 个选择，总共 2ⁿ⁻¹ 条路径。n = 1000 时是 2⁹⁹⁹，死了。

① 状态：dp[i][j] = 从顶走到第 i 层第 j 列的所有路径中，能取得的最大路径和。

② 转移：走到 (i,j) 的最后一步只可能来自正上方 (i−1,j) 或左上方 (i−1,j−1)，两步各自取最优再比一次：dp[i][j] = a[i][j] + max(dp[i-1][j-1], dp[i-1][j])。

③ 边界：dp[1][1] = a[1][1]。另外第 i 层只有 1..i 列存在：j = 1 时没有左上格子，j = i 时没有正上格子。这两类情况必须单独写，否则会读到根本不存在的格子。

④ 答案：底行的最大值 max(dp[n][1..n])。不是 dp[n][n]——走到最右下角不一定是最大和。

无后效性：dp[i][j] 只引用第 i−1 行。第 i 行以后怎么走完全不影响它，所以按行推进一定正确。

复杂度：状态数 n(n+1)/2 ≈ 5×10⁵，每个状态两次比较，O(n²)。n = 1000 时约 10⁶ 次基本操作，1 毫秒量级。

完整代码
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1005;         // n ≤ 1000，开 1005 让下标 1000 安全
int a[MAXN][MAXN];             // 原始数字三角形
int dp[MAXN][MAXN];            // dp[i][j]：从顶走到 (i,j) 的最大路径和

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= i; ++j)
            cin >> a[i][j];

    // ③ 边界：起点没有“上面”，它的路径和就是它自己
    dp[1][1] = a[1][1];

    // ② 转移：按行推进。第 i 行只依赖第 i-1 行，所以“按行的顺序”天然就是合法的计算顺序
    for (int i = 2; i <= n; ++i)
        for (int j = 1; j <= i; ++j) {
            if (j == 1)                       // 左边缘：没有左上格子，只能从正上方来
                dp[i][j] = a[i][j] + dp[i - 1][j];
            else if (j == i)                  // 右边缘：没有正上格子，只能从左上方来
                dp[i][j] = a[i][j] + dp[i - 1][j - 1];
            else                              // 中间：两个前驱取优
                dp[i][j] = a[i][j] + max(dp[i - 1][j - 1], dp[i - 1][j]);
        }

    // ④ 答案：底行最大值，不是 dp[n][n]
    int ans = dp[n][1];
    for (int j = 2; j <= n; ++j) ans = max(ans, dp[n][j]);

    cout << ans << "\n";
    return 0;
}

代码片段含义与理由
const int MAXN = 1005;n 最大 1000，数组要开到 1000 以上。开成 1000 时 a[1000] 越界，本地可能不报错、评测机 RE。
int a[MAXN][MAXN]; int dp[MAXN][MAXN];两个 1005×1005 的 int 约 8 MB，必须放全局。写进 main 里是栈内存，通常只有 1~8 MB，直接段错误。
dp[1][1] = a[1][1];边界，整题的地基。不写这行，dp[1][1] 是 0，后面全部错，而且答案看起来还挺“合理”，最难查。
for (int i = 2; i <= n; ++i)阶段推进。i 从 2 开始，因为第 1 行已被边界处理完。
j == 1 → dp[i-1][j]分类讨论第一支：最左列不存在左上格子 a[i-1][0]。如果统一写 max(dp[i-1][j-1], dp[i-1][j])，就会用到 dp[*][0] 这个不存在的格子。
j == i → dp[i-1][j-1]分类讨论第二支：最右列不存在正上格子 a[i-1][i]。dp[i-1][i] 是 0（没赋过值），一旦把它放进 max，答案会被悄悄改小。
max(dp[i-1][j-1], dp[i-1][j])这就是“决策”：两条来路，选收益大的那条。所有 DP 的转移式都是这个形状——把可达的来源列全，取最优。
int ans = dp[n][1];答案从底行第一个格子起步，再往右扫。用 0 起步在本题能过（数字非负），但换一题允许负数时就是错的，养成用合法格子起步的习惯。
cout << ans << "\n";只输出一个整数加换行。

新函数拆解 · 滚动数组：把二维 dp 压成一维
dp[j] = a[j] + max(dp[j-1], dp[j]); // j 从 i 递减到 1
组成含义 / 格式要求
为什么要压第 i 行只用到第 i−1 行，再往前的行永远不再被访问。二维表里 dp[0..i-2][*] 全是死数据。
压成什么dp[j] 只保留“上一行第 j 列”的结果。算第 i 行时，它表示第 i−1 行；算完后它变成第 i 行。
j 的顺序必须倒序（j 从 i 递减到 1）。倒序时 dp[j-1] 还没被这一轮改写，读到的是上一行的值，正确。
正序会怎样正序时 dp[j-1] 已经是本行的新值，相当于“从同一行左边走过来”，路径非法，答案偏大。
内存变化8 MB → 4 KB。空间换时间不一定赚，但时间换空间在这里是白赚。
最小可运行示例
示例
int a[1005], dp[1005];        // dp 只需要 1005 个 int

for (int i = 1; i <= n; ++i) {
    for (int j = 1; j <= i; ++j) cin >> a[j];   // 先把这一行读进来
    for (int j = i; j >= 1; --j)                // 再倒序更新
        dp[j] = a[j] + max(dp[j - 1], dp[j]);
}
int ans = dp[1];
for (int j = 2; j <= n; ++j) ans = max(ans, dp[j]);
注意

倒序的理由和下一节 0/1 背包完全一样：一维数组里“上一层”和“本层”共用同一块空间，只有让被依赖的格子还没被写，读到的才是旧值。

这一节先用例题体会一次，下一节会把它变成背包题的生死线。

第二个模型：以 i 结尾。问题：给定 a[1..n]（n ≤ 1000），求最长严格上升子序列的长度。子序列可以不连续，但要保持原顺序。

LIS：以 i 结尾
int a[MAXN], f[MAXN];          // f[i]：以 a[i] 结尾的最长严格上升子序列长度

int ans = 1;
for (int i = 1; i <= n; ++i) {
    f[i] = 1;                                       // 边界：只有 a[i] 自己，长度 1
    for (int j = 1; j < i; ++j)                     // 枚举“紧挨在 i 前面的那个是谁”
        if (a[j] < a[i]) f[i] = max(f[i], f[j] + 1);
    ans = max(ans, f[i]);
}

为什么状态必须写成“以 i 结尾”？因为转移时需要知道“新元素能接在谁后面”，这一点只有 i 能提供。如果把状态定义成“前 i 个数的 LIS 长度”，dp[i] 和 dp[i−1] 之间就没有可用的转移式——a[i] 可能根本不在最优解里，dp[i] 甚至可能等于 dp[i−1]，推不下去。

代码片段含义与理由
f[i] = 1;边界。任何单个元素自成一串，长度 1。不写这句 f 全是 0，答案会变成 1。
for (int j = 1; j < i; ++j)枚举前驱。每个状态扫一遍历史，这是 O(n²) 的全部来源。

ans = max(ans, f[i]);答案不是 f[n]。n 号元素可能很小，最优串也许在第 3 个位置就结束了。

线性 DP 的 6 种典型死法（含症状）

WA：LIS 把答案写成 f[n]。测试点里只要有一个“最后一个元素很小”的数据就挂。

WA：边界没写。dp 初值全 0，LIS 输出 1 或 0，数字三角形输出 0。症状是“样例都对、提交全 WA”。

WA：数字三角形只从 (i−1,j−1) 转移，漏掉正上方；或者忘了处理 j = 1、j = i 两个边缘，把 0 当成了合法前驱。

RE：MAXN 写成 1000 而 n = 1000，访问 a[1000] 越界；二维数组写在 main 里，1005×1005×4 B ≈ 4 MB 直接爆栈。

RE：一维滚动写成正序，虽然多数情况只错答案不崩，但只要 n 稍大、数组只开到 n，就会读到 dp[-1]。

数学补给 · DP 为什么一定对，复杂度怎么估

正确性：对“状态规模”做数学归纳。① 基例：边界状态直接赋值，显然正确。② 归纳假设：所有规模小于当前的状态都已算对。③ 归纳步：当前状态引用的来源全都规模更小（数字三角形第 i 行只引用第 i−1 行），由假设它们都对，而转移式把所有可能的来源分类列尽、并在每一类里取了最优，所以当前状态也一定对。

无后效性 = 状态图是一个 DAG。把每个状态画成一个点，每条转移画成一条有向边。上面第 ③ 步要求“边只从规模小的点指向规模大的点”，这保证了图上无环。有向无环图必有拓扑序，按拓扑序递推就是合法的计算顺序——这就是“循环怎么写”的全部依据。

反过来：如果状态之间出现环（dp[i] 依赖 dp[i+1]，而 dp[i+1] 又依赖 dp[i]），就没有天然的递推序，只能改用记忆化搜索，或者把环上的方程解出来。所以“能不能按某个顺序把表填完”是 DP 可解性的判据。

题目状态数单次转移总复杂度暴搜复杂度
数字三角形 n = 1000n(n+1)/2 ≈ 5×10⁵O(1)O(n²)2ⁿ⁻¹
LIS n = 1000nO(n)O(n²)2ⁿ
0/1 背包（下一节）M×T = 10⁵O(1)O(MT)2^M

记住这个乘法：总复杂度 = 状态数 × 单次转移代价。设计状态时先把两个因子估出来。n = 1000 的 O(n²) 是 10⁶，随便过；n = 10⁵ 的 O(n²) 是 10¹⁰，必挂——这时要么压状态数，要么把转移降到 O(1) 或 O(log n)。

还有一条不写在书上的经验：状态数通常控制在 10⁷ 以内。因为每个状态至少要读写一次，10⁸ 次内存访问已经是 1 秒的极限，而 DP 的循环体往往不止一次访问。

  2. 最大子段和（P1115）：状态怎么设？为什么 dp[i] = max(a[i], dp[i-1] + a[i]) 就够了，答案为什么是 max(dp[i])？
    想好了？点开核对思路与解析
    状态必须带“以 a[i] 结尾”：f[i] = max(a[i], f[i-1] + a[i]) 就是二选一——要么从 a[i] 重新开一段，要么把 a[i] 接在前一段后面；f[i−1] 保证以 a[i−1] 结尾，所以右边一定接得上。答案取 max(f[i])，因为最优子段一定以某个位置结尾，而 f 只保证“以 i 结尾”，不知道哪个 i 最好。常见错路：状态写成“前 i 个数的最大子段和”，a[i] 选不选在转移式里说不清；或者答案写成 f[n]，全负数时必错。
  3. 把 LIS 条件里的 < 换成 <=、>、>=，分别求的是什么？如果要求“最长上升子序列的个数”，状态要加什么？
    想好了？点开核对思路与解析
    < 是严格上升，<= 是最长不下降，> 是最长严格下降，>= 是最长不上升——改的只是“a[j] 能不能接在 a[i] 前面”这一个判定里的等号。求“最长上升子序列的个数”时状态照旧，另开一个与 f 平行的 cnt[i]：f[j]+1 > f[i] 时 cnt[i] = cnt[j]，相等时 cnt[i] += cnt[j]。常见错路：只看 cnt 不看长度，把所有更短的前驱也算进方案数，答案偏大；数值有重复时还得去重，同一个串会被不同下标记多次。
  4. 如果题目要求输出这条最大和路径本身而不只是和，需要多存什么？为什么存“从哪来”比存“整条路径”省空间？
    想好了？点开核对思路与解析
    多存一个 pre[i][j]，只记下 (i,j) 的最优值来自 (i−1,j−1) 还是 (i−1,j)，一个字节就够。因为“到前驱的那条路径”再加一步就是到当前格的最优路径，从底行最优格沿 pre 倒推 n 步即可还原整条。常见错路：在 dp 里存 vector 存整条路径，每次转移复制 O(n)，总复杂度从 O(n²) 涨到 O(n³)，n = 1000 时是 10⁹，既超时又爆内存。
  5. 数字三角形的滚动数组为什么必须倒序 j？这个倒序和下一节 0/1 背包的倒序，是同一个原因吗？
    想好了？点开核对思路与解析
    因为一维数组里 dp[j] 同时承担“上一行第 j 列”和“本行第 j 列”两个身份。倒序时 dp[j−1] 还没被本轮改写，读到的是上一行的旧值；正序时它已经是本行的新值，等于允许从同一行左边横着走过来，路径非法，答案偏大。这和 0/1 背包的倒序是同一个原因：被依赖的格子必须还没被写。常见错路：试几次发现“结果恰好没变”就断定正序也行——样例小，非法路径不一定更大。
  6. 如果题目改成“可以从底边任意位置出发、走到顶”，状态定义和答案位置要怎么改？代码要改几行？
    想好了？点开核对思路与解析
    把状态掉个头：dp[i][j] = 从 (i,j) 出发走到顶的最大和，边界仍是 dp[1][1] = a[1][1]，只是计算顺序改成 i 从 n−1 递减到 1；答案还是底行的 max(dp[n][1..n])，因为起点可以是底边任意一格。转移式一个字都不用改，向上走的两条来路仍然是 (i−1,j) 和 (i−1,j−1)。常见错路：以为要重推转移式或改答案位置；以及忘了必须先把整个三角形读进 a[][] 再倒着算，不能边读边推。

挑战题 · 合唱队形
洛谷 P1091普及/提高-去洛谷做这题 ↗

n 位同学站成一排，音乐老师要请其中若干位出列，使剩下的同学排成“合唱队形”。

合唱队形指：剩下的 k 位同学从左到右编号 1..k，身高为 T₁…T_k，存在一个位置 i 使得 T₁ < T₂ < … < T_i 且 T_i > T_{i+1} > … > T_k。也就是先严格上升、再严格下降。

输入：第一行一个整数 n（2 ≤ n ≤ 100）；第二行 n 个整数，表示从左到右每位同学的身高（130 ≤ T ≤ 230）。输出：一行一个整数，表示最少需要几位同学出列。

引导性提示（先只看这里）

不要枚举“谁出列”，那是指数级；反过来想“最多能留下几位”。

留下的队形有一个最高点，一旦这个最高点定下来，左边只能一路升，右边只能一路降，两半互相独立。

左边那段“以最高点结尾、严格上升”，右边那段“以最高点开头、严格下降”，各算一次 LIS 就行。

想看思路了？点开完整思路

枚举最高点 i（1 ≤ i ≤ n）。

左半边：以 i 结尾的最长严格上升子序列长度 f[i]，用标准 LIS 正着算一遍。

右半边：以 i 开头的最长严格下降子序列长度 g[i]。做法是把 i 从 n 往 1 倒着扫，对 j > i 且 T[j] < T[i] 的做 g[i] = max(g[i], g[j] + 1)——本质就是在反方向上求一次 LIS。

以 i 为峰能留下的最多人数是 f[i] + g[i] − 1（i 被两段各数了一次，减掉重复）。

答案 = n − max(f[i] + g[i] − 1)。复杂度 O(n²)，n ≤ 100 时约 10⁴ 次，瞬间出解。

为什么对：任何一个合法队形都有唯一的最高点 i，它左半边是 i 的上升前缀、右半边是 i 的下降后缀，长度不会超过 f[i] 与 g[i]；反过来取到 f[i]、g[i] 的两段拼起来一定合法。所以枚举 i 不重不漏。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 105;
int t[MAXN];        // 身高
int f[MAXN];        // f[i]：以 i 结尾的最长严格上升子序列长度
int g[MAXN];        // g[i]：以 i 开头的最长严格下降子序列长度

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> t[i];

    // 正着推：f[i] = 1 + max{ f[j] : j < i 且 t[j] < t[i] }
    for (int i = 1; i <= n; ++i) {
        f[i] = 1;                                  // 边界：自成一串
        for (int j = 1; j < i; ++j)
            if (t[j] < t[i]) f[i] = max(f[i], f[j] + 1);
    }

    // 倒着推：g[i] = 1 + max{ g[j] : j > i 且 t[j] < t[i] }
    // 必须 i 从 n 递减，才能保证用到 g[j] 时它已经算好
    for (int i = n; i >= 1; --i) {
        g[i] = 1;
        for (int j = n; j > i; --j)
            if (t[j] < t[i]) g[i] = max(g[i], g[j] + 1);
    }

    int keep = 0;
    for (int i = 1; i <= n; ++i)
        keep = max(keep, f[i] + g[i] - 1);         // i 被两段都数了一次，减 1

    cout << n - keep << "\n";
    return 0;
}
关键片段拆解
片段作用
for (int i = 1; i <= n; ++i)正推阶段。i 从小到大，f[j] (j < i) 一定已经算好——遍历顺序就是拓扑序。
f[i] = 1;边界：任何一个人自己都能当一段上升序列，长度 1。漏写这句 f 全 0。
for (int i = n; i >= 1; --i)倒推阶段。g 的定义是“以 i 开头往下走”，依赖 j > i，所以 i 必须从 n 往 1。写成从 1 到 n，g[j] 还没值，全错。
if (t[j] < t[i])严格下降：站在 i 看后面，只有比 i 矮的人才能接在 i 后面。等号不能加，题目要求严格。
f[i] + g[i] - 1减 1 是因为最高点 i 在 f 和 g 里各出现一次。忘了减，留下的人数虚高 1，输出答案偏小 1。
n - keep题目问“最少出列几位”，等于总人数减最多留下的人数。别直接输出 keep。
这题最容易错的地方
  • g 数组用 i 从 1 到 n 推：用到的 g[j] 还没算出来，全是 1，下降段全被算成 1。样例恰好还能输出 4（因为 max f[i] 就是 4），但输入 5 / 1 2 3 2 1 时正确输出 0，它输出 2。
  • 忘记 f[i] + g[i] − 1 里的 −1，输出比正确答案小 1；有的数据能过，纯属运气。
  • 把 f 和 g 都算成“整个序列的 LIS 长度”，两段长度对不上同一个峰，拼出来的队形不合法。
  • 最高点写成 for (int i = 2; i < n; ++i)、跳过端点：输入 5 / 5 4 3 2 1 正确输出 0，跳端点后输出 1。标准解法是 1..n 全枚举。
  • 输出 keep 而不是 n − keep。读题时把最后一句话圈出来再写输出。

挑战 2 · 乌龟棋
洛谷 P1541提高+/省选-去洛谷做这题 ↗

棋盘是一行 N 个格子，第 i 格有一个分数 aᵢ（非负整数）。棋子从第 1 格出发，终点是第 N 格。

有 M 张爬行卡片，每张卡片上写着 1、2、3、4 之一，表示用掉这张卡后棋子向前走几格。每次从还没用过的卡片里挑一张，每张只能用一次；用完所有卡片后棋子恰好停在第 N 格。棋子自动获得起点格的分数，之后每到达一格就得到那一格的分数，求最大总得分。

输入格式：第一行两个整数 N、M（1 ≤ N ≤ 350，1 ≤ M ≤ 120）。第二行 N 个非负整数 a₁…a_N（0 ≤ aᵢ ≤ 100）。第三行 M 个整数，每个在 1..4 之间，是卡片上的数字。

输出格式：一行一个整数，最大总得分。四种卡片每种不超过 40 张。

样例
输入： 9 5 6 10 14 2 8 8 18 5 17 1 3 1 2 1 输出： 73
引导性提示（先只看这里）

四种卡片彼此等价：同一类卡片谁先谁后没有区别。真正影响后面的只有一件事——四种卡片各用掉了几张。

四种卡片的已用张数一旦确定，棋子停在哪一格就确定了：1 + 1×i + 2×j + 3×k + 4×l。所以位置根本不用单独进状态。

先把每种卡片有几张数出来，数组的四个上界就定下来了；状态总数是这四个数各加 1 的乘积。

想看思路了？点开完整思路

先统计 cnt[1..4]。状态 dp[i][j][k][l] = 四种卡片分别用掉 i、j、k、l 张时能拿到的最大得分。

位置被四个下标完全决定：pos = 1 + i + 2j + 3k + 4l，这正是四步法里“把多余信息从状态里消掉”的做法。要是把 pos 也写进下标，状态数直接乘 350，内存爆掉。

转移：最后一次用的只可能是四种卡片之一，四类互斥且完备：dp[i][j][k][l] = a[pos] + max(dp[i−1][j][k][l], dp[i][j−1][k][l], dp[i][j][k−1][l], dp[i][j][k][l−1])，对应卡片张数为 0 的那一支跳过。

边界：dp[0][0][0][0] = a[1]。起点格自动得分，这一步漏了整题少 a[1]。

答案：dp[cnt1][cnt2][cnt3][cnt4]——所有卡片都用完，题目保证那时正好停在 N。不要取全表最大值。

顺序：i、j、k、l 全部从小到大。转移只引用下标更小的格子，四重循环的自然顺序就是拓扑序。

正确性：任意一个卡片使用顺序，都唯一对应一条从 (0,0,0,0) 走到 (cnt1,cnt2,cnt3,cnt4) 的路径（前缀里各类卡片的数量）；反过来，每个状态也唯一对应该前缀用掉了哪些卡片。所以状态不重不漏，而转移把“最后一张是哪类”四类情形列尽了，取 max 即得最优。

复杂度：状态数 ≤ 41⁴ ≈ 2.8×10⁶，每个状态 4 次比较，约 10⁷ 次运算；空间 41⁴×4 B ≈ 11 MB，必须开在全局。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int a[355];                    // 棋盘第 i 格的分数
int cnt[5];                    // cnt[k]：数字 k 的卡片有几张
int dp[41][41][41][41];        // dp[i][j][k][l]：四种卡片各用了 i/j/k/l 张时的最大得分

int main() {
    int n, m;
    scanf("%d %d", &n, &m);
    for (int i = 1; i <= n; ++i) scanf("%d", &a[i]);
    for (int i = 0; i < m; ++i) { int b; scanf("%d", &b); ++cnt[b]; }

    dp[0][0][0][0] = a[1];     // 起点第 1 格自动得分：这是唯一的边界
    for (int i = 0; i <= cnt[1]; ++i)
        for (int j = 0; j <= cnt[2]; ++j)
            for (int k = 0; k <= cnt[3]; ++k)
                for (int l = 0; l <= cnt[4]; ++l) {
                    if (i == 0 && j == 0 && k == 0 && l == 0) continue;
                    int pos = 1 + i + 2 * j + 3 * k + 4 * l;   // 用了这些卡片后停在哪一格
                    int best = 0;
                    if (i) best = max(best, dp[i - 1][j][k][l]);
                    if (j) best = max(best, dp[i][j - 1][k][l]);
                    if (k) best = max(best, dp[i][j][k - 1][l]);
                    if (l) best = max(best, dp[i][j][k][l - 1]);
                    dp[i][j][k][l] = best + a[pos];            // 最后一步用的那张卡片决定这一格
                }
    printf("%d\n", dp[cnt[1]][cnt[2]][cnt[3]][cnt[4]]);
    return 0;
}
关键片段拆解
片段作用
int dp[41][41][41][41];41⁴×4 B ≈ 11 MB，只能放全局静态区。
dp[0][0][0][0] = a[1];边界：起点格的分数先拿到手，这是整张表的种子。
int pos = 1 + i + 2 * j + 3 * k + 4 * l;位置由四类卡片的张数唯一确定，所以少了一维状态。
if (i) best = max(best, dp[i - 1][j][k][l]);分类讨论“最后一张是 1”。四行各管一类，一类都不许漏。
dp[i][j][k][l] = best + a[pos];最后一步落到的格子必须加上，它是这一步的收益。
for (int i = 0; i <= cnt[1]; ++i)上界用实际张数，不要一律写 40：多出来的格子会把 pos 推到 N 之外。
printf(... dp[cnt[1]][cnt[2]][cnt[3]][cnt[4]]);答案格是“四类卡片全部用完”，不是 max。
这题最容易错的地方
  • 把位置也写进状态（dp[位置][i][j][k][l]）：状态数乘 350，直接 MLE；位置本来就是四个下标算出来的。
  • 漏掉边界 dp[0][0][0][0] = a[1]：样例从 73 变成 67，而且不报错。
  • 四维数组写在 main 里：约 11 MB 栈内存，编译能过，运行直接爆栈。
  • 答案写成全表最大值：本题分数非负时两者恰好相等，换一道允许负分的题立刻错。
