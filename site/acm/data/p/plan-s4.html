这一章开始，你手上的工具从「思维动作」升级为「武器」。每个数据结构都只解决一类问题，所以学的时候一定要先问：它到底替我做了什么我做不到的事？

4.1 栈与单调栈

基础★★★★★必考P1449P1739P5788

栈：后进先出

本质：最后放进去的东西最先拿出来。就像叠盘子——你只能从最上面拿。

竞赛里栈的三大用途：括号匹配、表达式求值、DFS 的手写版。

单调栈：一次扫描求出「最近的大于它的元素」

为什么需要它：求「每个元素左边/右边第一个比它大（或小）的元素」，暴力是 O(n^2)，但用单调栈只要 O(n)。

🎨 生活类比

一排人从左到右站着，你要给每个人找「右边第一个比他高的人」。如果后面来了个很高的人，那么所有比他矮的人就都有答案了——矮个子的信息一次性全部结算，不用再留着。

核心思想一句话：被弹出者的答案在弹出瞬间确定。 这就是单调栈的全部。

⚠️ 易错

while 里的比较符号决定是「第一个大于」还是「第一个大于等于」；相等元素要不要弹，取决于题目要「严格大」还是「大于等于」。

✅ 小结

单调栈不是"栈的一种用法"，而是"用栈做延迟结算"。

4.2 队列与单调队列

基础★★★★★必考P1996P1886P1440

队列：先进先出

本质：先进先出，保证处理的层次性——这正是 BFS 能得到最短路的原因。

单调队列：滑动窗口的最值

为什么需要它：求「每个长度为 k 的窗口的最大/最小值」，暴力 O(nk)，单调队列 O(n)。

🎨 生活类比

排队买票，队伍里前面的人如果比后面的人矮，那他就永远不可能当「最高的人」——直接踢掉。于是队伍始终保持从高到低，队首永远是当前窗口的最高者。

三行口诀：队首过期弹、队尾不如弹、队首是答案。

⚠️ 易错

三步顺序不能乱（先弹过期，再弹队尾，最后入队）；求最大值时比较符号反过来；队列里存的是下标不是值（否则无法判断过期）。

单调队列优化 DP

这是它真正值钱的地方。当转移形如 f(i) = max{f(j)} + a_i，其中 j ∈ [i-k, i-1]，就可以用单调队列把内层的 O(k) 枚举降到 O(1) 均摊，整体 O(n)。

✅ 小结

单调队列 = 一个会自动淘汰"没前途"元素的窗口。 判据是「决策区间随 i 单调移动」。

基础★★★★★必考P1160P1996P1540

本质：用指针/下标把不连续的内存串起来，支持 O(1) 插入删除。竞赛里几乎不用 new，一律用数组模拟（静态链表）。

为什么不用 vector

4.4 堆与优先队列

基础★★★★★必考P3378P1090P1631

本质：一棵满足「父 ≤ 子」的完全二叉树，用数组存储，支持 O(log n) 插入/删除、O(1) 取最值。竞赛中的堆多半是用来做「动态取最值 + 反悔」。

🎨 生活类比

一堆任务按紧急程度排队，你永远只处理最紧急的那个；新任务随时插进来，但不需要全体排序，只要保证「最紧急的在最上面」。

STL 用法

两个经典应用

① 合并果子（Huffman）：每次取最小的两堆合并。O(nlog n)。

② 对顶堆求中位数：用一个大根堆存较小的一半，一个小根堆存较大的一半，保持两者大小差不超过 1。中位数就是某个堆的堆顶。

⚠️ 易错

pq.pop() 没有返回值，要取值必须先 top()；对自定义结构体用 priority_queue 必须重载 operator<（注意方向是反的——大根堆用 <）。

4.5 哈希与字符串哈希

基础★★★★★必考P3370P1102P2580

本质：用函数把「大值域」压到「小值域」，用 O(1) 期望时间做判重/查找。关键永远是冲突处理：开放寻址、拉链法，或者对字符串用「多项式哈希 + 双模数」把冲突概率压到可忽略。

🎨 生活类比

图书馆按书名的首字母分区放书——你想找《算法导论》，直接去 A 区，不用翻遍全馆。代价是同一个区里可能有很多本，需要再逐个找。

字符串哈希：把子串变成整数

为什么有效：把字符串看成一个 B 进制的大整数再取模。判断两个子串是否相等，就变成比较两个整数——O(1) 完成，比 KMP 简单太多。

三个必须知道的坑

  1. 单模数会被构造数据卡掉。重要比赛用双哈希：取两个不同的模数（如 10^9+7 和 10^9+9），两个都相等才算相等。
  2. 字符必须映射成非零正整数。直接用 'a' = 97 就行，但 'A' = 65 这种小数字容易造成前导零混淆——统一加一个偏移量更安全。
  3. 不要用 unordered_map 当万能容器。它能被 O(n) 的构造数据卡成 O(n^2)，10^5 规模就可能 TLE。要么手写哈希表，要么加随机扰动。
✅ 小结

哈希是用错误率换速度。 单哈希在平时练习够用，正式比赛一律双哈希。

4.6 二叉树与遍历

基础★★★★★必考P1305P1030P1827

本质：二叉树是「分治的结构化表达」。要掌握的核心是三种遍历的关系：前序定根、中序分左右、后序定根；以及完全二叉树的数组编号（i 的孩子是 2i、2i+1）。

三种遍历

唯一要背的结论

已知能否唯一确定一棵二叉树
前序 + 中序✓ 能
后序 + 中序✓ 能
前序 + 后序✗ 不能（无法区分只有一个孩子时是左还是右）
层序 + 中序✓ 能

做法：前序的第一个元素是根 → 在中序里找到它，左边是左子树、右边是右子树 → 递归处理两段。

⚠️ 易错

递归时要传「子树在数组中的区间」，不要传下标本身；空树要单独判断。

4.7 Trie（字典树）与 01-Trie

基础★★★★★必考P8306P2580P4551

本质：把字符串按字符逐层挂在树上，用「公共前缀」共享存储。它把「前缀匹配」从多次哈希比较变成一次树上走步，天然支持前缀查询、前缀计数。

🎨 生活类比

查字典时，所有以 "abc" 开头的词都排在一起。Trie 就是把这个「排在一起」做成了树结构——共同前缀只存一份。

模板

01-Trie：把整数按二进制挂上去

处理「异或」问题的神器。把每个数按 31 位二进制从高到低插入，查询「与 x 异或最大的数」时就沿着与当前位相反的分支走。

⚠️ 易错

节点数组要开 总长度 × 字符集大小（10^5 个长度 26 的字符串就要 2.6×10^6 个节点），开小了直接 RE。

4.8 set / map：有序集合

基础★★★★★必考P1097P3879P2234

本质：set/map 底层是红黑树（一种平衡二叉搜索树），所以查找、插入、删除都是 O(log n)，并且天然有序。它解决的是「需要动态维护有序集合 + 查前驱后继/排名」这类问题。

什么时候用（对比 vector + sort）

需求用什么
一次性排序后静态查询vector + sort + lower_bound（更快）
边插入边查询、还要查前驱后继set / map
只要判重、不关心顺序unordered_set（注意 4.5 节的坑）

常用操作

mp["不存在的键"] 会自动插入一个默认值，既改变容器大小又可能让后面的逻辑出错。判断存在用 count 或 find，不要用 []。

✅ 小结

set/map 的常数很大（比手写平衡树慢 3~5 倍），2×10^5 规模的题要留意会不会 TLE。

4.9 并查集

基础★★★★★必考P1196P2024P1525

本质：维护「等价关系」的划分。两个优化缺一不可：路径压缩 + 按秩/按大小合并，合起来使单次操作近似 O(α(n))，比 log 还小。

🎨 生活类比

一群同学互相认识，问 A 和 B 是否属于同一个圈子。你只要维护「每个圈子的代表是谁」，问的时候看两人能不能走到同一个代表即可。

4.10 KMP：线性字符串匹配

基础★★★★★必考P3375P4391P4824

本质：当匹配失败时，不要回到开头重来，而是利用「已匹配部分的最长公共前后缀」跳到一个更靠后的位置继续。这个信息就是 next 数组（也叫前缀函数 π）。

🎨 生活类比

你在读 "abababc"，已经匹配了 "ababab"，下一个字符对不上。聪明做法不是从头再试，而是发现 "ababab" 的后缀 "abab" 等于它的前缀——于是直接把模式串挪到 "ab" 对齐的位置继续。

模板

复杂度 O(n + m)，因为 j 只会增加 n 次、减少 n 次，总共 O(n) 步。

前缀函数还能干什么

用途怎么做
最小循环节若 n % (n - pi[n-1]) == 0，循环节长度是 n - pi[n-1]
判断周期性同上，否则整串就是一个周期
求所有 border（既是前缀又是后缀）从 pi[n-1] 开始不断 j = pi[j-1]
⚠️ 易错

pi 数组用 0-based 时下标要减 1；手写时最常错的是 while 里少写 j > 0。

4.11 树状数组

基础★★★★★必考P1908P3374P3368

本质：用 i += lowbit(i) 的倍增结构把「前缀」切成 log n 段，实现单点修改 + 前缀查询 O(log n)，常数远小于线段树。

🎨 生活类比

你有 10 个存钱罐排成一排。树状数组的做法是——第 1 个罐记「前 1 个的总和」，第 2 个记「前 2 个」，第 4 个记「前 4 个」，第 8 个记「前 8 个」。要查前 7 个的和，就取 4 号罐 + 6 号罐 + 7 号罐，三段搞定。改一个数，只要顺着往上更新那几个「管辖它」的罐子。

模板（必背）

三个必须掌握的变体

需求做法
单点修改 + 区间查询上面这个模板
区间修改 + 单点查询用差分建树状数组：add(l, v), add(r+1, -v)，查 sum(i)
区间修改 + 区间查询维护两个树状数组（公式：Σ (r-i+1)d_i 展开）

它不能做什么

树状数组只能维护可减的运算：和、异或、计数。最值（max/min）不能直接维护（没有逆运算），除非只做「单点修改 + 前缀最值」。需要区间最值就上线段树。

💡 提示

树状数组求逆序对：离散化后从右往左扫，每次查「比当前小的数有几个」（sum(a[i]-1)），再 add(a[i], 1)。这是 P1908 的标准解法。

4.12 线段树

基础★★★★★必考P3373P4145P3372

本质：把区间二分成树，每个节点维护一段区间的合并信息。区间修改靠懒标记（lazy tag）延迟下发，保证 O(log n)。它是「区间信息维护」的通用武器，进阶篇的主席树、树链剖分、李超树全是它的变形。

🎨 生活类比

一个公司有 10 万员工，你想知道某个部门的绩效总和。你不需要把每个人加起来——每个小组存好小计，每个部门存好小计。要改一个人的绩效，只需沿途更新他所在的每一层小计（log 层）。懒标记则是：「这个部门整体加薪 100，先记在部门账上，等有人来查再往下摊」。

模板：区间加 + 区间求和（必会）

六个必知要点

  1. 数组开 4n。编号法最坏情况下节点数接近 4n，开小了必 RE。
  2. pushdown 的位置：递归到子区间之前必须下发，否则孩子的值还是旧的。
  3. apply 里要更新两个东西：区间和 t[p] 和懒标记 tag[p]。
  4. 乘法标记（P3373）要规定「先乘后加」，否则无法合并。
  5. 复杂度：建树 O(n)，单次修改/查询 O(log n)，空间 4n。
  6. 能不用就不用。树状数组能做的一律用树状数组（常数小 3 倍），线段树只在需要「区间最值」「区间合并」时才上。

线段树的四类扩展

扩展解决什么
区间赋值（势能线段树）区间取 max/min、区间开方（P4145 花神游历各国）
权值线段树维护值域，求第 k 小 / 排名
动态开点值域 10^9 但实际用到的节点少
可持久化保留历史版本（第 9 章主席树）
✅ 小结

线段树是"区间问题的万能解"，但绝不是"首选解"。 先想树状数组、前缀和、差分能不能做。
