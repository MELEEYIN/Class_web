猜数字是 Rust 官方的第一个实战：它把「读输入 → 解析类型 → 循环 → 比较 → 提前退出」串成一条完整链路，也第一次逼你面对 Result 和 match。

一、完整代码

use rand::Rng;
use std::cmp::Ordering;
use std::io;

fn main() {
    println!("猜一个 1 到 100 之间的数字");

    let secret = rand::thread_rng().gen_range(1..=100);

    loop {
        println!("请输入你的猜测：");

        let mut guess = String::new();
        io::stdin()
            .read_line(&mut guess)
            .expect("读取输入失败");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => {
                println!("请输入一个数字");
                continue;
            }
        };

        match guess.cmp(&secret) {
            Ordering::Less => println!("太小了"),
            Ordering::Greater => println!("太大了"),
            Ordering::Equal => {
                println!("猜对了！");
                break;
            }
        }
    }
}

Cargo.toml 里需要加一行依赖：

[dependencies]
rand = "0.8"

二、几个必须看懂的点

片段为什么这么写
let mut guessRust 变量默认不可变，要改就得 mut；read_line 要在原字符串后追加，所以必须可变
&mut guess传的是可变引用，函数才能写回原变量（第 4 章讲借用）
.expect(...)read_line 返回 Result，expect 在出错时 panic 并打印这条消息
guess.trim()输入带换行符 \n，先去掉首尾空白再解析
let guess: u32 = ...变量遮蔽（shadowing）：新变量复用旧名字但换了类型，从 String 变成 u32
match ... { Ok / Err }parse() 返回 Result<u32, ParseIntError>，必须处理两个分支，不能忽略
continue解析失败时直接进入下一轮循环，而不是让程序崩掉

三、和 C/C++ 的直觉差异

  • 没有隐式类型转换。"42".parse() 必须靠目标类型标注（: u32）来决定解析成什么，编译器不会猜。
  • 返回值必须处理。Result 标了 #[must_use]，你写 io::stdin().read_line(&mut s); 会收到警告——错误不能静默丢弃。
  • 比较是 cmp + match，而不是 if/else 三连；Ordering 是枚举，三个分支必须写全（穷尽性检查）。

四、常见坑

  1. 忘记 use rand::Rng;：gen_range 是 trait 方法，不导入 trait 就调不到。
  2. read_line 传 &guess：类型不匹配，需要 &mut。
  3. 没有 trim()："42\n" 解析失败，程序走进 Err 分支。
  4. guess.cmp(&secret) 少写 &：cmp 要的是引用，否则会移动所有权。
  5. 把 gen_range(1..=100) 写成 1...100：后者是已废弃语法，新版编译不过。

五、小结

这一章已经把 Rust 的几个“味道”尝到了：不可变优先、错误必须处理、类型必须明确、分支必须穷尽。下一章系统讲变量、可变性和数据类型，把这些直觉补成规则。
