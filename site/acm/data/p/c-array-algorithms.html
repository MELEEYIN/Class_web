1. 查找算法概述

什么是查找

查找（Searching）：在数据集合中，找出满足给定条件的元素（或确定它不存在）的过程。

  • 关键字（key）：用来标识一个数据元素的某个数据项的值，查找就是拿 key 去比较。
  • 查找表：由同一类型的数据元素构成的集合。 静态查找表：只做查找，不做插入/删除（如顺序查找、二分查找）。 动态查找表：查找过程中还会插入/删除（如哈希表、二叉排序树）。

衡量指标：平均查找长度 ASL

ASL（Average Search Length） = 查找过程中关键字比较次数的期望值：

ASL = Σ (Pi × Ci)

Pi —— 查找第 i 个元素的概率（通常认为各元素等概率，Pi = 1/n）
Ci —— 找到第 i 个元素所需的比较次数

ASL 越小，算法效率越高。分析查找算法时，"成功的 ASL"和"失败的 ASL"通常要分开算。

本章要讲的算法

分类算法前提
线性（顺序）结构查找基本查找（顺序查找）无
线性（顺序）结构查找二分查找（折半查找）数据必须有序
线性（顺序）结构查找插值查找有序 + 分布均匀

2. 基本查找（顺序查找 / 线性查找）

思路

从表的一端开始，逐个把元素的关键字与目标值 key 比较：

  • 相等 ——> 查找成功，返回下标；
  • 扫描到表尾仍不相等 ——> 查找失败。

对数据是否有序没有要求，这是它最大的优点。

代码实现

版本一：从前往后

// 基本查找：在 arr 中找 key，找到返回下标，找不到返回 -1
int seq_search(int arr[], int n, int key)
{
    for (int i = 0; i < n; i++)
    {
        if (arr[i] == key)
        {
            return i;           // 找到，返回下标
        }
    }
    return -1;                  // 遍历完没找到
}

版本二：带"哨兵"

把 key 放到下标 0 的位置（下标 0 不存有效数据），从后往前扫描，不必每次判断 i 是否越界，减少一次比较：

// 哨兵版：arr[0] 作为哨兵，有效数据从 arr[1] 开始
// 注意：这里 n 表示"最后一个元素的下标"（即数据占 arr[1] ~ arr[n]）
int seq_search_sentinel(int arr[], int n, int key)
{
    arr[0] = key;               // 设置哨兵
    int i = n;
    while (arr[i] != key)       // 不用判断 i > 0，因为 arr[0] == key 一定会停
    {
        i--;
    }
    return (i == 0) ? -1 : i;   // i == 0 说明是哨兵"撞"到的，即没找到
}

效率分析

  • 查找第 i 个元素需要比较 i 次（从前往后）。
  • 等概率下：
ASL成功 = (1 + 2 + 3 + ... + n) / n = (n + 1) / 2
ASL失败 = n + 1        （要比较完整个表）
  • 时间复杂度 O(n)，空间复杂度 O(1)。

优缺点

优点缺点
对数据无任何要求（无序也行）数据量大时效率很低
算法简单、易实现不适合频繁查找的大数据量场景
适合数据量较小、查找不频繁的场合

3. 二分查找（折半查找）

前提

数据必须是有序的（升序或降序，且支持随机访问 —— 顺序表/数组）。如果数据无序，必须先排序。

思路

设数组升序，用 left、right 标记查找区间，每轮取中间位置 mid：

  • arr[mid] == key ——> 找到了；
  • arr[mid] > key ——> 目标只可能在左半区，right = mid - 1；
  • arr[mid] < key ——> 目标只可能在右半区，left = mid + 1。

每比较一次，区间缩小一半，直到 left > right（区间为空）说明不存在。

代码实现

循环版（闭区间写法 [left, right]）

// 二分查找（升序数组），找到返回下标，找不到返回 -1
int binary_search(int arr[], int n, int key)
{
    int left = 0;
    int right = n - 1;          // 闭区间 [left, right]

    while (left <= right)       // 注意是 <=
    {
        int mid = left + (right - left) / 2;    // 防溢出写法
        if (arr[mid] == key)
        {
            return mid;         // 找到了
        }
        else if (arr[mid] > key)
        {
            right = mid - 1;    // 目标在左半区
        }
        else
        {
            left = mid + 1;     // 目标在右半区
        }
    }
    return -1;                  // 区间为空，没找到
}

递归版

int binary_search_rec(int arr[], int left, int right, int key)
{
    if (left > right)
    {
        return -1;              // 递归出口：区间为空
    }

    int mid = left + (right - left) / 2;
    if (arr[mid] == key)
    {
        return mid;
    }
    else if (arr[mid] > key)
    {
        return binary_search_rec(arr, left, mid - 1, key);   // 左半区
    }
    else
    {
        return binary_search_rec(arr, mid + 1, right, key);  // 右半区
    }
}

完整示例

int main(void)
{
    int arr[] = {7, 23, 79, 81, 103, 127, 131, 147};
    int n = sizeof(arr) / sizeof(arr[0]);

    int key = 103;
    int index = binary_search(arr, n, key);
    if (index == -1)
    {
        printf("%d 不存在\n", key);
    }
    else
    {
        printf("%d 的下标为：%d\n", key, index);
    }

    system("pause");
    return EXIT_SUCCESS;
}

关键点与易错点

  1. 必须先排序。 对无序数据做二分，结果是错的（不是"找不到"，而是"找错"）。
  2. 区间开闭要自洽，两种写法不能混用：
写法初值循环条件收缩方式
闭区间 [left, right]right = n - 1left <= rightright = mid - 1 / left = mid + 1
左闭右开 [left, right)right = nleft < rightright = mid / left = mid + 1
最常见的 bug：right = n - 1 却写 left < right，会漏掉最后一个元素；或写成 right = mid，导致 left == right 时死循环。
  1. mid 的溢出问题： ``c int mid = (left + right) / 2; // 当 left、right 都很大时 left+right 会溢出 int mid = left + (right - left) / 2; // 推荐写法，不会溢出 ``
  2. 只能用于顺序存储（数组）。链表不能随机访问，无法 O(1) 定位 mid。
  3. 重复元素的返回值不确定：数组里有多个相同值时，二分返回的是"某一个"，不保证是第一个或最后一个。

查找"边界"的变体（重要）

实际做题时经常需要的不只是"存在"，而是第一个/最后一个满足条件的位置：

// 查找第一个 >= key 的下标（lower_bound）
int lower_bound(int arr[], int n, int key)
{
    int left = 0, right = n;            // 左闭右开
    while (left < right)
    {
        int mid = left + (right - left) / 2;
        if (arr[mid] >= key)
            right = mid;                // mid 可能就是答案，保留
        else
            left = mid + 1;
    }
    return left;                        // 可能等于 n（表示都比 key 小）
}

// 查找第一个 > key 的下标（upper_bound）
int upper_bound(int arr[], int n, int key)
{
    int left = 0, right = n;
    while (left < right)
    {
        int mid = left + (right - left) / 2;
        if (arr[mid] > key)
            right = mid;
        else
            left = mid + 1;
    }
    return left;
}
结论：key 出现的次数 = upper_bound - lower_bound。

效率分析

  • 每次区间减半，最多比较 ⌈log₂(n+1)⌉ 次。
  • 时间复杂度 O(log n)，空间复杂度 O(1)（递归版为 O(log n) 栈空间）。
  • 等概率下 ASL ≈ log₂(n+1) - 1。

4. 插值查找

思路

二分查找每次都取"正中间"，但如果我们已经知道 key 可能靠前或靠后，取中间就不是最优的。插值查找按比例估算 key 应该在的位置：

mid = left + (key - arr[left]) / (arr[right] - arr[left]) × (right - left)

对比一下：

算法mid 公式
二分查找left + (right - left) × 1/2
插值查找left + (right - left) × (key - arr[left]) / (arr[right] - arr[left])

直观理解：把"1/2"换成了"目标值在当前区间中的比例"。

例子：在 1 ~ 10000 均匀分布的有序数组中查 15。二分第一次取 5000；插值查找会算出 15 大约在 15% 的位置，直接跳到 1500 附近，一下就缩掉绝大部分区间。

前提

  1. 数据必须有序；
  2. 数据分布比较均匀（近似等差数列效果最好）。

代码实现

// 插值查找（升序、分布较均匀的数组）
int interpolation_search(int arr[], int n, int key)
{
    int left = 0, right = n - 1;

    while (left <= right && key >= arr[left] && key <= arr[right])
    {
        // 防止分母为 0：区间内所有元素相同时，直接比较
        if (arr[right] == arr[left])
        {
            return (arr[left] == key) ? left : -1;
        }

        // 按比例估算位置
        int mid = left + (key - arr[left]) * (right - left) / (arr[right] - arr[left]);

        if (arr[mid] == key)
        {
            return mid;
        }
        else if (arr[mid] > key)
        {
            right = mid - 1;
        }
        else
        {
            left = mid + 1;
        }
    }
    return -1;
}

必须注意的三个点

  1. 分母为 0：当 arr[right] == arr[left]（区间内元素全相同）时，除法会崩，必须特判。
  2. mid 越界：如果 key 超出区间范围（比如比 arr[left] 还小）， 公式算出的 mid 可能小于 left 甚至为负数。 所以循环条件里要加 key >= arr[left] && key <= arr[right]， 或对算出的 mid 做夹紧（clamp）： ``c if (mid < left) mid = left; if (mid > right) mid = right; ``
  3. 数据不均匀时反而更慢：比如 {1, 2, 3, 4, 5, 100000} 里查 5， 插值公式会把它估到很靠后的位置，可能一次只缩掉一个元素，退化成 O(n)。

效率分析

情况时间复杂度
数据均匀分布O(log log n)，比二分更快
数据分布极不均匀最坏 O(n)，比二分差
结论：能用二分就用二分；只有在确认数据"均匀有序"且数据量很大时，插值查找才有优势。

5. 分块查找（索引顺序查找）

思路

分块查找是顺序查找与二分查找的折中，做法是把数据分成若干块：

  1. 块间有序：第 1 块的最大值 < 第 2 块的所有值 < 第 3 块 ……（块与块之间有序）；
  2. 块内可以无序（块内随便放）。

再建立一个索引表，每一项记录：

索引项内容
maxKey该块中的最大关键字
start该块在数组中的起始下标
length该块的元素个数

因为索引表按 maxKey 有序，所以可以先查索引表定位到块，再在块内顺序查找。

示例

数据：{16, 5, 9, 25, 12, 30, 38, 45, 60, 58, 71, 80}，每块 4 个元素：

块1: 16,  5,  9, 25   —— 最大 25
块2: 12, 30, 38, 45   —— 最大 45
块3: 60, 58, 71, 80   —— 最大 80

索引表：
  maxKey: 25  45  80
  start :  0   4   8

查找 38：

  1. 在索引表中比较：38 > 25，38 <= 45 ——> 锁定块2（start = 4）；
  2. 在块2（下标 4~7）中顺序查找 ——> 第 3 个元素命中。

代码实现

#define BLOCK_SIZE 4

// 索引项
typedef struct {
    int maxKey;     // 该块的最大关键字
    int start;      // 该块起始下标
    int length;     // 该块元素个数
} index_t;

// 建立索引表，返回块数
int build_index(int arr[], int n, index_t idx[])
{
    int blocks = (n + BLOCK_SIZE - 1) / BLOCK_SIZE;   // 向上取整
    for (int i = 0; i < blocks; i++)
    {
        int start = i * BLOCK_SIZE;
        int len = (start + BLOCK_SIZE <= n) ? BLOCK_SIZE : (n - start);
        int max = arr[start];

        for (int j = start; j < start + len; j++)
        {
            if (arr[j] > max) max = arr[j];
        }
        idx[i].maxKey = max;
        idx[i].start  = start;
        idx[i].length = len;
    }
    return blocks;
}

// 分块查找：先顺序查索引表确定块，再块内顺序查找
int block_search(int arr[], int n, index_t idx[], int blocks, int key)
{
    int b = -1;
    // ① 在索引表中顺序查找，找到第一个 maxKey >= key 的块
    for (int i = 0; i < blocks; i++)
    {
        if (key <= idx[i].maxKey)
        {
            b = i;
            break;
        }
    }
    if (b == -1)
    {
        return -1;      // 比所有块的最大值都大，一定不存在
    }

    // ② 在块内顺序查找
    for (int i = idx[b].start; i < idx[b].start + idx[b].length; i++)
    {
        if (arr[i] == key)
        {
            return i;
        }
    }
    return -1;
}
索引表本身是有序的，所以"①"这一步也可以改成二分查找索引表，当块数很多时能进一步提速。

效率分析

设 n 个元素分成 b 块、每块 s 个元素（b × s = n），若索引表和块内都用顺序查找：

ASL = ASL索引 + ASL块内 ≈ (b + 1)/2 + (s + 1)/2 = (b + s)/2 + 1

由均值不等式，b = s = √n 时 ASL 最小：

ASL最小 ≈ √n + 1
  • 时间复杂度 O(√n)，介于顺序查找 O(n) 与二分查找 O(log n) 之间。
  • 空间上需要额外的索引表。

优缺点

优点缺点
插入/删除比二分查找方便（块内无序，只要不破坏块间有序就行）需要额外维护索引表
适合数据量大、又要频繁动态增删的场景效率不如二分查找

6. 哈希查找（散列查找）

基本概念

前面几种查找都要"比较"，哈希查找的核心思想是：通过哈希函数直接算出元素的存储位置，理想情况下一次就能定位，O(1)。

  • 哈希表（散列表）：用哈希函数建立"关键字 → 存储位置"映射的存储结构。
  • 哈希函数 H(key)：把关键字映射成哈希表中下标的函数。
  • 哈希地址：H(key) 算出的下标。
  • 冲突（碰撞）：两个不同的 key 算出同一个哈希地址（H(k1) == H(k2) 但 k1 != k2）。
  • 同义词：产生冲突的那些关键字互称同义词。
冲突是不可避免的（因为关键字空间通常远大于哈希表空间），所以哈希查找的两个核心问题是：① 设计好的哈希函数；② 设计好的冲突解决办法。

常用哈希函数

方法做法适用
直接定址法H(key) = key 或 a × key + b关键字连续、范围小
除留余数法（最常用）H(key) = key % p，p 一般取小于表长的最大质数通用
数字分析法取关键字中分布较均匀的几位关键字位数多、分布有规律
平方取中法平方后取中间几位关键字位数少
折叠法把关键字分成几段相加位数很多
// 除留余数法示例：表长 13，取 p = 13（质数）
#define TABLE_SIZE 13
int hash_func(int key)
{
    return key % TABLE_SIZE;
}

冲突解决办法

方法一：开放定址法

当 H(key) 已被占用时，按某种规则向后探测空位置。

// 线性探测：依次看 H+1, H+2, H+3 ... （循环）
int next = (H(key) + i) % TABLE_SIZE;    // i = 1, 2, 3 ...
探测方式公式特点
线性探测(H + i) % m简单，但会产生聚集（连续占满一片）
二次探测(H ± i²) % m减少聚集
双重散列(H1 + i × H2) % m效果更好
重要坑：开放定址法删除元素不能直接置空，否则会截断后续元素的探测链，导致本来存在的元素查不到。要用"墓碑标记"（如 -1 表示已删除、INT_MIN 表示空）。

方法二：链地址法（拉链法，最常用）

哈希表的每个位置存一个链表头，所有哈希地址相同的元素挂到同一个链表上。

typedef struct node {
    int key;
    struct node *next;
} node_t;

node_t *table[TABLE_SIZE];      // 数组 + 链表
  • 优点：没有聚集问题；删除方便（直接摘链）；装载因子可以 > 1。
  • 缺点：需要额外的指针空间；链表长了退化成 O(n)。

其他方法

  • 再哈希法：冲突时换第二个哈希函数再算。
  • 公共溢出区：冲突的元素统一放到另一个溢出表里。

装载因子

α = 表中已存元素个数 n / 哈希表长度 m
  • α 越大 ——> 冲突越多、查找越慢；
  • 开放定址法一般控制 α < 0.75，超过就要扩容（rehash：新建更大的表，把所有元素重新插入）。

代码实现：除留余数 + 开放定址（线性探测）

#include <stdio.h>
#include <limits.h>

#define M 13                        // 表长，取质数
#define EMPTY  INT_MIN              // 空标记
#define DELETED (INT_MIN + 1)       // 墓碑标记（表示被删除过）

int table[M];

// 初始化
void ht_init(void)
{
    for (int i = 0; i < M; i++)
    {
        table[i] = EMPTY;
    }
}

// 哈希函数
int hash(int key)
{
    return key % M;
}

// 插入：成功返回下标，表满返回 -1
int ht_insert(int key)
{
    int h = hash(key);
    for (int i = 0; i < M; i++)             // 最多探测 M 次
    {
        int pos = (h + i) % M;
        if (table[pos] == EMPTY || table[pos] == DELETED)
        {
            table[pos] = key;
            return pos;
        }
    }
    return -1;                              // 表已满
}

// 查找：成功返回下标，失败返回 -1
int ht_search(int key)
{
    int h = hash(key);
    for (int i = 0; i < M; i++)
    {
        int pos = (h + i) % M;
        if (table[pos] == EMPTY)            // 遇到空位，说明探测链断了 ——> 不存在
        {
            return -1;
        }
        if (table[pos] == key)
        {
            return pos;
        }
        // 若是 DELETED，继续往后探测
    }
    return -1;
}

// 删除：把位置标记为"墓碑"，不能直接置空！
int ht_delete(int key)
{
    int pos = ht_search(key);
    if (pos == -1)
    {
        return -1;
    }
    table[pos] = DELETED;
    return 0;
}

int main(void)
{
    ht_init();

    int keys[] = {19, 14, 23, 1, 68, 20, 84, 27, 55, 11, 10, 79};
    int n = sizeof(keys) / sizeof(keys[0]);
    for (int i = 0; i < n; i++)
    {
        printf("插入 %2d -> 位置 %d\n", keys[i], ht_insert(keys[i]));
    }

    printf("\n查找 27 -> %d\n", ht_search(27));
    printf("查找 99 -> %d\n", ht_search(99));

    system("pause");
    return EXIT_SUCCESS;
}

代码实现：链地址法（拉链法）

#include <stdio.h>
#include <stdlib.h>

#define M 13

typedef struct node {
    int key;
    struct node *next;
} node_t;

node_t *table[M];

// 初始化
void ht_init(void)
{
    for (int i = 0; i < M; i++)
    {
        table[i] = NULL;
    }
}

// 哈希函数
int hash(int key)
{
    return key % M;
}

// 插入：头插法
void ht_insert(int key)
{
    int h = hash(key);
    node_t *p = malloc(sizeof(node_t));
    if (p == NULL)
    {
        return;
    }
    p->key = key;
    p->next = table[h];
    table[h] = p;
}

// 查找：在对应链表里顺序找
node_t *ht_search(int key)
{
    int h = hash(key);
    for (node_t *p = table[h]; p != NULL; p = p->next)
    {
        if (p->key == key)
        {
            return p;
        }
    }
    return NULL;
}

// 删除
int ht_delete(int key)
{
    int h = hash(key);
    node_t *prev = NULL;
    for (node_t *p = table[h]; p != NULL; prev = p, p = p->next)
    {
        if (p->key == key)
        {
            if (prev == NULL)
            {
                table[h] = p->next;
            }
            else
            {
                prev->next = p->next;
            }
            free(p);
            return 0;
        }
    }
    return -1;
}

效率分析

情况时间复杂度
平均（哈希函数设计良好、α 合理）O(1)
最坏（全部冲突，退化成一条链/连续探测）O(n)
  • 空间复杂度：O(n)（需要额外的指针或空位）。

哈希查找小结

  • 哈希查找不要求数据有序，这是它相对二分查找的最大优势；
  • 查找速度最快，但不适合范围查找（如"找 50~80 之间的所有数"）， 也不适合按顺序遍历输出；
  • 空间换时间的典型代表。

7. 冒泡排序（Bubble Sort）

思路

重复走访要排序的数列，每次比较相邻的两个元素，如果顺序不对就交换；每走一趟，最大的元素就会"冒泡"到未排序部分的最后面。

  • 有 n 个元素，最多需要 n - 1 趟；
  • 第 i 趟只需要比较 n - 1 - i 次（后面已经是排好的）。

逐步演示

对 {5, 2, 9, 1, 6} 升序排序：

初始：      5  2  9  1  6

第 1 趟：
  5>2 交换  2  5  9  1  6
  5<9 不动  2  5  9  1  6
  9>1 交换  2  5  1  9  6
  9>6 交换  2  5  1  6  9     ← 最大值 9 归位
                比较 4 次

第 2 趟：  2  5  1  6 | 9
  2<5 不动  2  5  1  6
  5>1 交换  2  1  5  6
  5<6 不动  2  1  5  6     ← 次大值 6 归位
                比较 3 次

第 3 趟：  2  1  5 | 6  9
  2>1 交换  1  2  5
  2<5 不动  1  2  5         ← 5 归位
                比较 2 次

第 4 趟：  1  2 | 5  6  9
  1<2 不动  1  2             ← 2 归位
                比较 1 次

结果：      1  2  5  6  9

总比较次数 = 4 + 3 + 2 + 1 = 10 = n(n-1)/2。

代码实现

基础版

void bubble_sort(int arr[], int n)
{
    for (int i = 0; i < n - 1; i++)             // 外层控制"趟数"
    {
        for (int j = 0; j < n - 1 - i; j++)     // 内层控制"每次比较"
        {
            if (arr[j] > arr[j + 1])            // 相邻两两比较（升序：前面大就换）
            {
                int tmp = arr[j];               // 三杯水交换
                arr[j] = arr[j + 1];
                arr[j + 1] = tmp;
            }
        }
    }
}

优化版：加"是否发生交换"标志

如果某一趟一次交换都没有，说明数组已经有序，可以直接结束：

void bubble_sort_opt(int arr[], int n)
{
    for (int i = 0; i < n - 1; i++)
    {
        int swapped = 0;                        // 本趟是否发生交换
        for (int j = 0; j < n - 1 - i; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                int tmp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = tmp;
                swapped = 1;
            }
        }
        if (swapped == 0)                       // 已经有序，提前结束
        {
            break;
        }
    }
}

进一步优化：记录最后一次交换的位置

某一趟中，最后一次交换位置之后的元素已经有序，下一趟不必再比较：

void bubble_sort_opt2(int arr[], int n)
{
    int border = n - 1;
    while (border > 0)
    {
        int lastSwap = 0;
        for (int j = 0; j < border; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                int tmp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = tmp;
                lastSwap = j;
            }
        }
        border = lastSwap;
    }
}

完整示例

int main(void)
{
    int arr[] = {5, 2, 9, 1, 6, 3};
    int n = sizeof(arr) / sizeof(arr[0]);

    bubble_sort(arr, n);

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }
    printf("\n");

    return EXIT_SUCCESS;
}

效率分析

指标值
最好时间复杂度O(n)（原数组已有序 且 用了标志位优化）
平均时间复杂度O(n²)
最坏时间复杂度O(n²)（完全逆序）
空间复杂度O(1)（原地排序）
稳定性稳定（相等元素不会交换，相对次序不变）

常见坑

  1. 内层边界写错：写成 j < n - 1 会做多余的比较（虽然结果对，但效率更差）； 写成 j <= n - 1 - i 会越界（arr[j+1] 越界）。
  2. 交换时忘了用临时变量：arr[j] = arr[j+1]; arr[j+1] = arr[j]; 是错的。
  3. 外层只需 n - 1 趟：n - 1 趟后前 n-1 个位置都有序，最后一个自然也就位了。

8. 选择排序（Selection Sort）

思路

把数组分成"已排序区"和"未排序区"：

  • 每一趟在未排序区里找到最小（或最大）的元素；
  • 把它和未排序区的第一个元素交换；
  • 未排序区缩小一个，重复直到只剩一个元素。
与冒泡的区别：冒泡是"边走边换"，选择排序是"先找最小、最后只换一次"，所以交换次数少得多。

逐步演示

对 {5, 2, 9, 1, 6} 升序排序：

初始：          5  2  9  1  6
                未排序区：[0..4]

第 1 趟：在 5 2 9 1 6 中找最小值 1（下标 3），与 arr[0] 交换
        1 | 2  9  5  6        已排序：[0]

第 2 趟：在 2 9 5 6 中找最小值 2（下标 1），与 arr[1] 交换（自己，不变）
        1  2 | 9  5  6        已排序：[0..1]

第 3 趟：在 9 5 6 中找最小值 5（下标 3），与 arr[2] 交换
        1  2  5 | 9  6        已排序：[0..2]

第 4 趟：在 9 6 中找最小值 6（下标 4），与 arr[3] 交换
        1  2  5  6 | 9        已排序：[0..3]

结果：  1  2  5  6  9

代码实现

void select_sort(int arr[], int n)
{
    for (int i = 0; i < n - 1; i++)             // i 是未排序区的第一个位置
    {
        int minIndex = i;                       // 先假设 arr[i] 最小
        for (int j = i + 1; j < n; j++)         // 在未排序区找真正的最小值
        {
            if (arr[j] < arr[minIndex])
            {
                minIndex = j;
            }
        }
        // 只交换一次：把最小值换到未排序区的最前面
        if (minIndex != i)
        {
            int tmp = arr[i];
            arr[i] = arr[minIndex];
            arr[minIndex] = tmp;
        }
    }
}

完整示例

int main(void)
{
    int arr[] = {5, 2, 9, 1, 6, 3};
    int n = sizeof(arr) / sizeof(arr[0]);

    select_sort(arr, n);

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }
    printf("\n");

    return EXIT_SUCCESS;
}

效率分析

指标值
时间复杂度O(n²)（最好/平均/最坏都是；因为不管数据怎样都要找最小值）
比较次数n(n-1)/2，固定不变
交换次数最多 n - 1 次（比冒泡少很多）
空间复杂度O(1)
稳定性不稳定

为什么选择排序不稳定？

稳定要求：相等的元素排序后相对次序不变。选择排序的交换会跨过中间元素，可能打乱顺序。

反例：{5a, 5b, 2}（5a 与 5b 值相等，5a 在前）

第 1 趟：找最小值 2（下标 2），与 arr[0] 交换
        2  5b  5a          ← 5a 和 5b 的相对次序被交换打乱了
结果：  2  5b  5a

5a 原本在 5b 前面，排序后跑到后面去了 —— 所以不稳定。

与冒泡排序对比

冒泡排序选择排序
比较次数≤ n(n-1)/2固定 n(n-1)/2
交换次数最多 n(n-1)/2最多 n - 1
最好情况O(n)（有序 + 优化）O(n²) 无法优化
稳定性稳定不稳定
适用数据基本有序时表现好交换成本高（如元素很大）时更合适

9. 综合对比

查找算法

算法前提时间复杂度空间能否动态增删特点
基本查找（顺序）无O(n)O(1)方便最简单，数据量小才用
二分查找必须有序O(log n)O(1)不方便最常用，效率高

怎么选？

  • 数据有序 ——> 优先考虑二分查找；
  • 数据有序且分布均匀、量很大 ——> 可以试插值查找；
  • 数据量大、频繁增删 ——> 哈希表 或 分块查找；
  • 数据无序、量小 ——> 顺序查找最省事；
  • 排序：数据规模小、要求稳定 ——> 冒泡；交换元素的代价很大 ——> 选择排序。 （数据量大时两者都不适用，应使用快速排序 / 归并排序 / 堆排序。）

10. 标准库里的查找函数（C 没有 find）

前面讲的查找算法都是"自己写循环"。那 C 标准库有没有现成的查找函数？没有叫 find 的。 C 的做法是"按数据形态分头提供专用函数"，再加一个通用的 bsearch()。

10.1 查找函数全家谱

想找什么函数头文件返回前置要求
字符串里的字符（首次）strchrstring.h指针 / NULL—
字符串里的字符（最后一次）strrchrstring.h指针—
字符串里的子串strstrstring.h指针—
字符串里任一个字符strpbrkstring.h指针—
内存块里的字节memchrstring.h指针—
任意类型的有序数组bsearchstdlib.h指针必须先排序
任意类型但无序的数组lfind / lsearchsearch.h指针非 ISO C（POSIX）
补充几个"查跨度"的：strspn（开头连续属于某集合的字符个数）、strcspn（开头连续不属于某集合的个数）。

10.2 C 查找函数的两个约定

  1. 一律返回指针（找不到返回 NULL），不返回下标。 要下标就自己做指针相减：(int *)p - arr。
  2. 通用型函数（bsearch、lfind）必须由你提供比较函数 —— 因为 C 没有泛型， 库函数不知道你的元素怎么比大小。

10.3 bsearch：C 里最接近"通用 find"的东西

#include <stdlib.h>
void *bsearch(const void *key,      // 【要找的值】的地址
              const void *base,     // 数组首地址
              size_t nmemb,         // 元素个数
              size_t size,          // 单个元素的字节数
              int (*compar)(const void *, const void *));   // 比较函数
参数说明
key指向"要找的值"的指针（传变量的地址，不是值本身）
base数组首地址
nmemb元素个数
size单个元素占多少字节（通常写 sizeof(arr[0])）
compar比较函数，返回 <0 / 0 / >0
返回值指向匹配元素的指针；找不到返回 NULL
#include <stdio.h>
#include <stdlib.h>

// 比较函数：返回 1 / 0 / -1
int cmp_int(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

int main(void)
{
    int arr[] = {103, 7, 147, 81, 23, 131, 127, 79};
    int n = sizeof(arr) / sizeof(arr[0]);
    int key = 103;

    // ① 必须先排序（同样的比较规则！）
    qsort(arr, n, sizeof(arr[0]), cmp_int);

    // ② 再二分查找
    int *p = bsearch(&key, arr, n, sizeof(arr[0]), cmp_int);

    if (p == NULL)
    {
        printf("%d 不存在\n", key);
    }
    else
    {
        printf("找到 %d，下标 %d\n", *p, (int)(p - arr));   // 指针相减得下标
    }

    return EXIT_SUCCESS;
}

五个必须注意的点

  1. 必须已排序，而且要用同一个比较规则。 对无序数组调用 bsearch，结果是未定义的 —— 不是"找不到"，而是"可能找错"。
  2. 有重复元素时返回哪一个不确定，不保证是第一个。
  3. 做不到 lower_bound / upper_bound（"第一个 ≥ key 的位置"）。 这是 bsearch 最大的功能缺口 —— 有这种需求只能手写二分（见第 3 章变体部分）。
  4. 比较函数不要写成相减： ``c return (int )a - (int )b; // ✗ 可能溢出（INT_MIN 和 INT_MAX 相减） return (x > y) - (x < y); // ✓ 安全，且天然返回 1 / 0 / -1 ``
  5. key 必须是"和数组元素同类型"的对象。bsearch 是按你给的内存当元素去比的， 传 int 就要传 &int_var，传结构体就要传结构体变量的地址。

结构体数组的例子

typedef struct {
    int  id;
    char name[32];
} stu_t;

// 按 id 排序 / 比较
int cmp_stu(const void *a, const void *b)
{
    int x = ((const stu_t *)a)->id;
    int y = ((const stu_t *)b)->id;
    return (x > y) - (x < y);
}

int main(void)
{
    stu_t arr[] = {{103, "Tom"}, {7, "Jerry"}, {81, "Andy"}};
    int n = sizeof(arr) / sizeof(arr[0]);

    qsort(arr, n, sizeof(arr[0]), cmp_stu);

    stu_t key;
    key.id = 81;                                    // 只看 id 作为关键字
    stu_t *p = bsearch(&key, arr, n, sizeof(arr[0]), cmp_stu);

    if (p != NULL)
    {
        printf("查到：%d %s\n", p->id, p->name);
    }

    return EXIT_SUCCESS;
}

10.4 其它专用查找函数速查

#include <string.h>

char buf[] = "hello world";

char *p1 = strchr(buf, 'w');            // 找字符：返回 "world" 的地址

char *p3 = strstr(buf, "wor");          // 找子串：返回 "world" 的地址

10.5 POSIX 的 lfind / lsearch（无序数组的通用查找）

bsearch 要求有序，那无序数组想用通用的查找怎么办？POSIX 提供了这两个线性查找函数：

#include <search.h>

// lfind：只查找，找不到返回 NULL
void *lfind(const void *key, const void *base, size_t *nmemb, size_t size,
            int (*compar)(const void *, const void *));

// lsearch：找不到就【追加】到数组末尾，并更新 nmemb
void *lsearch(const void *key, void *base, size_t *nmemb, size_t size,
              int (*compar)(const void *, const void *));
  • 两者都是 O(n)（线性查找）；
  • 注意 nmemb 是指针 —— 因为 lsearch 会修改元素个数；
  • lsearch 的"找不到就插入"特性，正好用来实现动态查找表；
  • 它们不是 ISO C 标准（属 POSIX）。在 MSVC 里名字是 _lfind / _lsearch； 在 Linux/glibc 下需要 #include <search.h>。 跨平台代码里不要用它们，自己写循环更稳。

10.6 自己写一个通用 find

C 里最实用的做法还是自己封装一个：

// 通用线性查找：返回匹配元素的指针，找不到返回 NULL
void *my_find(const void *base, size_t n, size_t size, const void *key,
              int (*cmp)(const void *, const void *))
{
    const char *p = (const char *)base;         // 按字节推进，兼容任意类型
    for (size_t i = 0; i < n; i++)
    {
        if (cmp(p + i * size, key) == 0)
        {
            return (void *)(p + i * size);
        }
    }
    return NULL;
}

如果元素是"纯数据"（没有指针成员、没有结构体填充字节），也可以直接用 memcmp：

void *my_find_mem(const void *base, size_t n, size_t size, const void *key)
{
    const unsigned char *p = (const unsigned char *)base;
    for (size_t i = 0; i < n; i++)
    {
        if (memcmp(p + i * size, key, size) == 0)
        {
            return (void *)(p + i * size);
        }
    }
    return NULL;
}
坑：结构体可能有填充字节（sizeof 里那些"看不见"的字节），其内容不确定，用 memcmp 比结构体可能误判 —— 所以结构体要用比较函数，不要用 memcmp。

10.7 和 C++ 对照：别被名字骗了

语言函数复杂度说明
CbsearchO(log n)通用，但要求有序
Clfind / 手写循环O(n)无序数组
C++std::findO(n)它是线性遍历，不是二分！
C++std::binary_searchO(log n)要求有序
C++std::lower_bound / upper_boundO(log n)有序数组的边界查找
常见误解："C 没有 find、C++ 有 find，所以 C++ 查找更快。"错 —— std::find 和你的手写循环一样是 O(n)。真正二分的是 binary_search / lower_bound / upper_bound（在 <algorithm> 里），而 C 里对应的就是 bsearch。

11. 练习

查找

  1. 二分查找基础：在 {7, 23, 79, 81, 103, 127, 131, 147} 中查找 103，写出每轮的 left / mid / right。
  2. 手写二分：分别用"闭区间"和"左闭右开"两种写法实现二分查找，并互相验证结果一致。
  3. 边界变体：在有序数组 {1, 2, 2, 2, 3, 4} 中，求 2 出现的第一个位置、最后一个位置和出现次数。
  4. 插值查找：在 1 ~ 10000 的等差数组中查找 15，统计二分查找与插值查找各自需要比较几次。
  5. 分块查找：把 {16, 5, 9, 25, 12, 30, 38, 45, 60, 58, 71, 80} 分成每块 4 个元素，建立索引表，实现查找 38、71、50。
  6. 哈希表：对 {19, 14, 23, 1, 68, 20, 84, 27, 55, 11, 10, 79} 用表长 13 的除留余数法建表，分别用线性探测和链地址法实现，并统计各自的平均查找长度。

排序

  1. 冒泡排序：对 {5, 2, 9, 1, 6, 3} 写出每一趟排序后的结果。
  2. 冒泡优化：给冒泡排序加上"标志位"和"最后一次交换位置"两种优化，用已经有序的数组测试优化效果。
  3. 选择排序：对 {5, 2, 9, 1, 6, 3} 写出每一趟排序后的结果，并统计交换次数。
  4. 比较：构造一组数据，让冒泡排序的交换次数远多于选择排序，并说明原因。
  5. 综合：把本章所有查找、排序算法写成一个程序，用同一组随机数据测试，打印各自的耗时和比较/交换次数。

标准库函数

  1. bsearch 实战：给一个 stu_t 结构体数组（含 id、name），先用 qsort 按 id 排序， 再用 bsearch 按 id 查找指定学生；然后故意不排序直接 bsearch，观察结果是否正确。
  2. 比较函数的坑：分别用 return (int )a - (int )b; 和 return (x > y) - (x < y); 作为 qsort 的比较函数，构造一组包含 INT_MIN、INT_MAX 的数据，比较两者结果差异。
  3. 字符串查找：给定一句话，用 strchr 找出第一个空格的位置、用 strrchr 找出最后一个空格的位置， 用 strstr 判断某个单词是否出现，并输出它在句中的下标。
  4. 通用 find：实现 10.6 节的两个版本（比较函数版 / memcmp 版）， 再构造一个含指针成员或存在填充字节的结构体，验证 memcmp 版为什么会误判。
