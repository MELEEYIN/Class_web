泛型解决“同一套逻辑适配多种类型”，trait 解决“多种类型共享同一种行为”，生命周期解决“引用能活多久”。这三件事构成了 Rust 的抽象体系，也是它零成本抽象的来源。

一、泛型函数与结构体

fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in &list[1..] {
        if item > max { max = item; }
    }
    max
}

struct Point<T> { x: T, y: T }

impl<T> Point<T> {
    fn x(&self) -> &T { &self.x }
}

<T: PartialOrd> 是“约束”：不是所有类型都能比大小，所以必须声明 T 至少实现了 PartialOrd。泛型在编译期单态化（每个具体类型生成一份代码），运行时没有额外开销。

二、trait：行为的契约

trait Summary {
    fn summarize(&self) -> String;

    fn preview(&self) -> String {          // 默认实现
        format!("{}...", &self.summarize()[..10.min(self.summarize().len())])
    }
}

impl Summary for Point<i32> {
    fn summarize(&self) -> String { format!("({}, {})", self.x, self.y) }
}

// 参数用 impl Trait 或泛型都行
fn show(s: &impl Summary) { println!("{}", s.summarize()); }
写法含义
impl Trait（参数位）静态分发，编译期确定具体类型
dyn Trait（&dyn Trait）动态分发，运行时查虚表，可装不同类型
where T: A + B约束太多时移到 where 子句，提升可读性

三、生命周期：引用能活多久

// 返回值的引用来自 a 还是 b？编译器需要你说明
fn longer<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}

'a 不是“让变量活更久”，而是声明两个入参和返回值至少活一样长。多数情况下编译器能自动推断（生命周期省略规则），只有“返回引用且来源不唯一”时才要手写。

结构体里存引用必须标生命周期：struct Parser<'a> { input: &'a str }，因为它不能比被借用的数据活得更久。

四、常见坑

  1. 泛型没加约束就调用 >、+：编译器不知道 T 支持什么操作。
  2. trait 方法忘了 pub？trait 本身要可见，方法默认随 trait 可见。
  3. &dyn Trait 忘了 &：dyn Trait 是 unsized，不能按值传。
  4. 生命周期标注写在返回值上却漏了入参，报“missing lifetime specifier”。
  5. 以为 'static 是“全局变量”：它表示“活得和程序一样久”，字面量字符串就是 &'static str。

五、小结

泛型写一次适配多种类型，trait 描述共享行为，生命周期保证引用安全。下一章讲测试，把前面写的东西都验证一遍。
