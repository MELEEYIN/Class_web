所有权是 Rust 最独特、也最容易卡住新人的地方。它要解决的问题很朴素：一块堆内存由谁负责释放，什么时候释放，会不会有人还在用它。C 靠人记，GC 语言靠回收器，Rust 靠编译器在编译期算清楚。

一、三条规则

  1. 每个值都有且只有一个所有者（owner）。
  2. 同一时刻只能有一个所有者。
  3. 所有者离开作用域时，值被自动丢弃（drop）。
{
    let s = String::from("hello");   // s 进入作用域，堆上分配
    // 使用 s
}                                    // 作用域结束，s 被 drop，内存释放

二、移动而不是拷贝

let s1 = String::from("hello");
let s2 = s1;                 // 所有权从 s1 移动（move）到 s2
// println!("{}", s1);       // 编译错误：value borrowed here after move
println!("{}", s2);          // OK
类型赋值时发生什么例子
实现了 Copy（全在栈上）按位复制，原变量仍可用i32、bool、char、[i32; 3]、&T
未实现 Copy（含堆数据）移动，原变量失效String、Vec<T>、自定义结构体

想保留原变量就显式克隆：let s2 = s1.clone();——clone 是深拷贝，有成本，别在热循环里随手写。

三、函数调用同样会移动

fn takes(s: String) { /* s 在这里被 drop */ }

let s = String::from("hi");
takes(s);
// println!("{}", s);        // 错误：s 已经被移进函数

不想交出所有权，就传引用（借用）：

fn measure(s: &String) -> usize { s.len() }

let s = String::from("hi");
let n = measure(&s);         // 只借不拿
println!("{} {}", s, n);     // s 还能用

四、借用规则

在任意时刻，对同一个值，要么有任意多个不可变引用 &T，要么只有一个可变引用 &mut T，二者不能同时存在；引用必须始终有效（不能悬垂）。
let mut v = vec![1, 2, 3];

let a = &v;        // 不可变借用
let b = &v;        // 再来一个，OK（多个只读没问题）
println!("{:?} {:?}", a, b);

let c = &mut v;    // 可变借用：此时 a、b 必须已经不再使用
c.push(4);

这条规则的好处是不需要锁就能防数据竞争：编译器在编译期就保证“读的时候没人写，写的时候没人读”。

五、切片：不拿走所有权的“视图”

let s = String::from("hello world");
let hello = &s[0..5];        // &str，指向原字符串的一段
let world = &s[6..];         // 到末尾
println!("{} {}", hello, world);

let a = [1, 2, 3, 4, 5];
let part = &a[1..3];         // &[i32]

切片本身就是引用，所以同样受借用规则约束：拿着 &s[..] 的时候不能 s.push_str(..)，否则会因为“可变借用与不可变借用共存”被拒。

六、常见坑

  1. for x in v 会把 v 移进循环（若元素不是 Copy）；想保留就写 for x in &v。
  2. 函数返回引用，但被引用的值在函数内创建 → 悬垂引用，编译直接拒绝。
  3. 同一作用域里先 &mut 再 &：报 cannot borrow as immutable because it is also borrowed as mutable，调整顺序或缩小作用域即可。
  4. 结构体方法里 self.field 与 &self 混用导致借用冲突，常见于“边遍历边修改”，需要 split_at_mut 或索引。
  5. 以为 clone 是免费的：String/Vec 的 clone 会重新分配内存。

七、小结

移动保证唯一所有权，借用保证访问安全，切片提供零拷贝视图。这三件事撑起了 Rust 的“无 GC 内存安全”。下一章讲结构体与方法，然后进入枚举与模式匹配。
