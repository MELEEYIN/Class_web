判复杂度时会遇到的词12 条

术语大白话在哪节
复杂度一句话：n 变大时，程序要跑的步数涨得多快。O(n) 约等于「和 n 成正比」，O(n²) 约等于「和 n 的平方成正比」。1.1
常数因子复杂度里的「系数」。2n 和 100n 都写成 O(n) —— 只看涨得快不快，不看具体是几倍。1.6
渐进（渐进行为）只看 n 非常大时的趋势，不管 n 小的时候谁更快。所以复杂度不预测具体秒数。1.2
上界「最多跑到这么多」。说某个算法的复杂度是 O(n)，意思是「不会比正比增长更快」。1.1
均摊某一次操作可能很慢，但把它摊到很多次操作上，平均下来很快。1.4
对数 / log反着问「2 的多少次方等于 n」。n = 100 万时，log₂n 只有 20。1.4
底数log₂ 和 log₁₀ 里那个 2 和 10。换底只差一个固定倍数，所以复杂度里不写底数。1.5
调和级数1 + 1/2 + 1/3 + … + 1/n 这种和。看起来会很大，其实只涨到 ln n 那么大。1.5
调和数 H(n)上面那个和的数学名字。不用手算，只要知道它约等于 ln n。1.5
欧拉常数 γ≈ 0.5772 的一个固定数，出现在调和数的精确公式里。记不住完全没关系。1.5
级数一串数相加。1.5
值域这些数可能取到的范围。比如「值域到 10⁹」= 数最大能到十亿。5.1

C++ 语言15 条

术语大白话在哪节
头文件C++ 把功能分成一包包，用 #include 拿进来。要什么拿什么，别一次全拿。2.2
万能头#include <bits/stdc++.h>，一行几乎把所有功能都拿进来。方便，但不是标准，换编译器可能就编译不过。2.2
预处理编译之前先做的一遍文本加工，#include 和 #define 都在这一步完成。2.6
宏（#define）编译前的「查找替换」。写 #define N 100，之后代码里所有的 N 都会被换成 100。2.6
文本替换宏的本质：它不懂语法，只是把字换掉 —— 所以经常出你没想到的意外。2.6
函数式宏#define sqr(x) ((x)*(x)) 这种「带参数的宏」。参数会被替换两次，容易出错。2.6
类型一个变量能装什么、能装多大。int 装约 ±21 亿，long long 装约 ±9.2×10¹⁸。4.7
溢出装不下了，数字绕回去变成离谱的值。int 相加超过约 21 亿就会发生。4.7
未定义行为标准没规定该发生什么，所以「本机跑对了、评测机跑错了」都可能。溢出、越界都属于这一类。4.7
引用给变量起的第二个名字，改它就等于改原来的变量。2.6
内联（inline）告诉编译器「这个小函数直接展开到调用处」，省一次函数调用的开销。2.6
模板（template）写一份代码适配多种类型，比如同一个 sqr 既能算 int 也能算 double。2.6
容器能装一堆东西的「盒子」，比如 vector（变长数组）、map（有序键值表）。2.8
迭代器指向容器里某个位置的「游标」，类似数组下标，但更通用。5.3
迭代器失效容器被改动（比如删了元素）之后，之前拿到的迭代器可能指向无效位置，再用就会出错。5.3

内存与初始化12 条

术语大白话在哪节
栈（stack 内存）程序运行时自动分配的一小块内存，默认只有 1～8 MB。函数里的局部变量住这里，放太多会爆。4.4
堆（heap）手动申请的大块内存（new、vector 用的是这里），空间大，但不会自动释放。4.4
静态区全局变量和 static 变量住的地方。程序启动就分配好，空间比栈大得多。4.4
全局变量写在所有函数外面的变量。默认全是 0，能开很大。4.4
局部变量写在函数里面的变量。默认是随机值，住在栈上。4.4
爆栈栈用完了，程序直接崩，而且不给有用的报错。4.4
越界用了数组范围之外的下标，比如只开了 5 个却访问第 6 个。最常见的 RE 原因。4.4
字节 / bit内存的基本单位。一个 int 占 4 个字节，一个字节是 8 个 bit。1.3
位宽一个类型用多少个 bit 存。int 是 32 位，long long 是 64 位。2.2
零初始化把变量的值设成 0。全局变量自动做，局部变量不会。4.7
memset按「字节」批量填内存的函数。只能填 0、-1、0x3f 这种每个字节都一样的值。4.7
sizeof求「占多少个字节」。数组传进函数后会变成指针，这时 sizeof 就不再是数组大小了。4.7
