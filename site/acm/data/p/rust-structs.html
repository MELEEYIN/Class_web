结构体是把几个值打包成一个有名字的整体。Rust 的结构体没有类继承，方法靠 impl 块挂上去——这决定了它后面“用组合代替继承”的设计取向。

一、定义与实例化

struct User {
    name: String,
    age: u32,
    active: bool,
}

let u = User {
    name: String::from("小明"),
    age: 18,
    active: true,
};

println!("{}", u.name);      // 字段访问
let u2 = User { age: 20, ..u };   // 更新语法：其余字段从 u 复制/移动过来

..u 不是“复制整个 u”：实现了 Copy 的字段按值复制，String 这类会被移动，之后 u.name 就不能用了。

二、方法：impl 块

impl User {
    fn new(name: &str, age: u32) -> Self {      // 关联函数，没有 self
        Self { name: name.to_string(), age, active: true }
    }

    fn birthday(&mut self) {                     // &mut self：要改字段
        self.age += 1;
    }

    fn is_adult(&self) -> bool {                 // &self：只读
        self.age >= 18
    }
}

let mut u = User::new("小明", 17);
u.birthday();
println!("{}", u.is_adult());
接收者能不能改字段调用后原变量
self能，但会消耗所有权不能再用
&mut self能可以继续用
&self不能可以继续用

三、派生常用 trait

#[derive(Debug, Clone, PartialEq)]
struct Point { x: i32, y: i32 }

let p = Point { x: 1, y: 2 };
println!("{:?}", p);          // 需要 Debug
let q = p.clone();            // 需要 Clone
println!("{}", p == q);       // 需要 PartialEq

#[derive(...)] 让编译器自动生成这些 trait 的实现，是 Rust 最常用的“零成本样板消除”。

四、常见坑

  1. 方法里忘写 &：fn f(self) 会消耗对象，调用一次后原变量失效。
  2. 只读方法写成了 &mut self，导致同一作用域内无法与其它借用共存。
  3. ..u 之后又用 u.name：String 已被移动。
  4. 结构体字段全是私有（默认），跨模块访问要么 pub，要么用方法。
  5. 忘了 #[derive(Debug)] 就 println!("{:?}", x)，编译直接报错。

五、小结

结构体管数据，impl 管行为，derive 管样板。下一章讲枚举——Rust 的枚举比 C 的 enum 强大得多，每个变体可以带不同的数据。
