Rust 的并发口号是“无畏并发”：数据竞争在编译期就被所有权与 Send/Sync 挡住，而不是靠运行时调试。

一、线程

use std::thread;
use std::time::Duration;

let h = thread::spawn(|| {
    for i in 0..3 { println!("子线程 {}", i); thread::sleep(Duration::from_millis(10)); }
});
h.join().unwrap();            // 等它结束

// 需要把数据搬进线程就用 move
let v = vec![1, 2, 3];
let h2 = thread::spawn(move || println!("{:?}", v));

二、channel：线程间通信

use std::sync::mpsc;

let (tx, rx) = mpsc::channel();
thread::spawn(move || { tx.send("hi").unwrap(); });
println!("{}", rx.recv().unwrap());     // 阻塞直到收到或通道关闭

“不要通过共享内存来通信，要通过通信来共享内存”——channel 把所有权传过去，天然避免了竞争。

三、共享状态：Arc + Mutex

use std::sync::{Arc, Mutex};

let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..10 {
    let c = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        let mut n = c.lock().unwrap();
        *n += 1;
    }));
}
for h in handles { h.join().unwrap(); }
println!("{}", *counter.lock().unwrap());   // 10
trait含义谁需要实现
Send值可以移动到另一个线程Rc 不实现，Arc 实现
Sync&T 可以安全地被多个线程共享RefCell 不实现，Mutex 实现

四、常见坑

  1. 忘了 move：闭包借用栈上变量，编译器会报“可能比函数活得更久”。
  2. 死锁：两个 Mutex 加锁顺序不一致，固定顺序即可。
  3. lock() 返回 Result：持锁线程 panic 会导致中毒，需要处理 PoisonError。
  4. 用 Rc 跨线程：Rc 没有 Send，必须 Arc。
  5. 以为加锁就万事大吉：锁保护的是“数据访问”，不是“业务逻辑顺序”。

五、小结

spawn 起线程、channel 传数据、Arc+Mutex 共享状态。最后一章把它们拼成一个能跑的小服务器。
