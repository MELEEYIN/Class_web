Rust 把错误分成两类：不可恢复的 panic 和可恢复的 Result。原则很简单：程序 bug 用 panic，外部输入/IO 用 Result。

一、panic! 与栈展开

fn main() {
    let v = vec![1, 2, 3];
    println!("{}", v[9]);      // panic: index out of bounds
}

panic 默认展开栈（跑 drop 释放内存）；在 Cargo.toml 里设 panic = "abort" 可以直接终止，二进制更小，但没法被 catch_unwind 捕获。

二、Result 与 ? 运算符

use std::fs::File;
use std::io::{self, Read};

fn read_file(path: &str) -> Result<String, io::Error> {
    let mut f = File::open(path)?;    // 失败就 return Err(...)
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}

fn main() {
    match read_file("a.txt") {
        Ok(s) => println!("{}", s),
        Err(e) => eprintln!("读取失败: {}", e),
    }
}
写法行为
expr?Ok(v) 取出 v；Err(e) 立即返回（会做 From 类型转换）
unwrap()失败就 panic，仅适合原型/测试
expect("msg")同上，但 panic 信息更清楚
unwrap_or(default)失败给默认值，不 panic
map_err(|e| ...)转换错误类型
? 只能用在返回 Result（或 Option）的函数里。在 main 里用也行——把 fn main() 写成 fn main() -> Result<(), Box<dyn Error>>。

三、自定义错误类型

#[derive(Debug)]
enum AppError {
    Io(io::Error),
    Parse(std::num::ParseIntError),
}

impl From<io::Error> for AppError {
    fn from(e: io::Error) -> Self { AppError::Io(e) }
}
impl From<std::num::ParseIntError> for AppError {
    fn from(e: std::num::ParseIntError) -> Self { AppError::Parse(e) }
}

有了 From 实现，? 就能自动把底层错误“装箱”成你的错误类型，函数签名统一成 Result<T, AppError>。实际项目里通常直接用 thiserror / anyhow 两个 crate 省掉样板。

四、什么时候不该 panic

  • 库代码：不要替调用者决定“这算致命”，返回 Result 让他选。
  • 用户输入：解析失败是常态，用 match/? 而不是 unwrap。
  • 能证明不可能失败时（如刚检查过长度），unwrap 可以接受，但更推荐 expect("不变量说明")。

五、常见坑

  1. ? 用在返回 () 的函数里，报 the `?` operator can only be used in a function that returns Result。
  2. unwrap 遍地：正式代码里每多一个 unwrap 就多一个潜在崩溃点。
  3. 错误类型不匹配：? 需要 From 转换，没实现就要 map_err。
  4. 把 Err 吞掉：let _ = f(); 会静默丢弃错误。
  5. 在 eprintln! 与 println! 之间纠结：错误信息走 stderr，别污染正常输出。

六、小结

panic 表示“程序错了”，Result 表示“这次操作失败了”。下一章讲泛型与 trait，这是 Rust 抽象能力的核心。
