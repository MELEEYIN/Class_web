Rust 把测试做进了语言和 cargo：#[test] 标注函数，cargo test 编译并运行。测试代码和生产代码可以写在一起（#[cfg(test)]），也可以放 tests/ 做集成测试。

一、单元测试

fn add(a: i32, b: i32) -> i32 { a + b }

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_two_numbers() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn negative_works() {
        assert_eq!(add(-2, -3), -5);
    }
}
断言用途
assert!(cond)条件不成立则失败
assert_eq!(a, b)相等，失败时打印两个值（需要 Debug）
assert_ne!(a, b)不相等
#[should_panic]断言“这段代码应当 panic”
Result<(), E> 作为返回用 ? 在测试里传播错误

二、集成测试

// tests/integration.rs —— 只能访问 crate 的 pub 接口
use my_crate::add;

#[test]
fn works_via_public_api() {
    assert_eq!(add(1, 1), 2);
}

cargo test 还会跑文档注释里的示例（cargo test --doc），所以例子写错也会被发现。

三、常见坑

  1. 忘了 #[cfg(test)]：测试模块会被编进 release 二进制。
  2. assert_eq! 比较自定义类型却忘了 #[derive(Debug, PartialEq)]。
  3. 集成测试放在 src/ 里：应在 tests/，且只测 pub 接口。
  4. 测试之间共享全局状态：测试默认多线程并行，互相污染就随机失败。
  5. 只测 happy path：边界（空、0、负数、极大值）才是 bug 高发区。

四、小结

单元测试验证内部逻辑，集成测试验证对外契约。下一章讲迭代器与闭包，把循环写得更“函数式”。
