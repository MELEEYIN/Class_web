例题 · 均分纸牌洛谷 P1031普及-去洛谷做这题 ↗

有 N 堆纸牌排成一行，编号 1..N，第 i 堆有 Aᵢ 张，纸牌总数一定是 N 的倍数。

每次操作可以「从某一堆取若干张牌，放到与它相邻的堆上」，取几张都一样，只记 1 次操作。其中 1 号堆只能往 2 号堆放，N 号堆只能往 N−1 号堆放，中间各堆可以往左邻或右邻放。

求最少的操作次数，使每堆纸牌数都相等。

输入格式：第一行一个整数 N（1 ≤ N ≤ 100）；第二行 N 个整数 A₁..A_N（1 ≤ Aᵢ ≤ 10000）。

输出格式：一行一个整数，表示最少操作次数。

输入： 4 9 8 17 6 输出： 3 样例解释：4 堆最终都是 10 张。先从第 3 堆给第 4 堆 4 张，再从第 3 堆给第 2 堆 3 张，最后从第 2 堆给第 1 堆 1 张，共 3 次。
热身题的 5 分钟怎么想

最终每堆都是 avg = 总数 / N 张。总数是 N 的倍数，所以一定整除，不用考虑除不尽。

盯住第 1 堆：它只和第 2 堆相邻，能打交道的只有第 2 堆。它比 avg 少 1 张，那就只能从第 2 堆拿 1 张过来；比 avg 多，就把多的部分整个推给第 2 堆。无论哪种，一次操作就能把第 1 堆永久修好，之后再也不用管它。

  1. 算出 avg。
  2. 从左往右看第 i 堆：只要 a[i] ≠ avg，就把差额 a[i] − avg 加到 a[i+1] 上，答案 +1。
  3. 处理完第 i 堆，它一定等于 avg，从此不再参与。
  4. 扫到第 N−1 堆就停：前面的差额全推到最后一堆，它必然已经等于 avg。

复杂度 O(N)，N ≤ 100 时只有 100 次加法。这题的真正成本在读题那 5 分钟：想清楚「为什么从左往右一次扫描就一定最优」，比写出这 8 行更重要。

热身题完整代码
#include <bits/stdc++.h>
using namespace std;

int n, a[10005];

int main() {
    scanf("%d", &n);
    long long sum = 0;
    for (int i = 1; i <= n; ++i) { scanf("%d", &a[i]); sum += a[i]; }
    int avg = (int)(sum / n);

    int ans = 0;
    for (int i = 1; i <= n - 1; ++i) {
        if (a[i] != avg) {
            a[i + 1] += a[i] - avg;     // 多退少补，全甩给右边那一堆
            ++ans;
        }
    }
    printf("%d\n", ans);
    return 0;
}
逐行拆解
代码片段含义与理由
int avg = (int)(sum / n);目标值。总数一定是 N 的倍数，整除没有余数，不需要处理除不尽的情况。
for (int i = 1; i <= n - 1; ++i)只扫到 N−1。最后一堆不用处理：前面的差额全推到它这里，它必然已经等于 avg。写成 i <= n 会去访问 a[N+1]，越界。
if (a[i] != avg)已经相等就一次都不动，这是「最少次数」的来源——能不搬就不搬。
a[i + 1] += a[i] - avg;第 i 堆多了正数、少了负数，差额整个甩给第 i+1 堆。一次操作可以搬任意多张，所以只花 1 次。
++ans;每修好一堆记一次。题目数的是操作次数，不是搬了多少张牌。
printf("%d\n", ans);只输出一个整数加换行，不要任何提示语。

新函数拆解 · 单调队列：队尾弹逆序、队头出窗口
int h = 1, t = 0; // 手写双端队列，h > t 表示空 for (int i = 1; i <= n; ++i) { while (h <= t && a[q[t]] >= a[i]) --t; // ① 队尾活不下来 q[++t] = i; // ② 新下标入队 if (q[h] < i - k + 1) ++h; // ③ 队头滑出窗口 [i-k+1, i] if (i >= k) ans = a[q[h]]; // ④ 此时队头就是答案 }
组成含义 / 格式要求
q[++t] = i队列里存下标，不存值。存下标才能判断“是否滑出窗口”，也能反查 a[q[h]]。
while (h <= t && a[q[t]] >= a[i]) --t求最小值用 >=；求最大值把 >= 换成 <=，其余不动。方向写反，队头就不是最值。
h <= t空队列判据：h = t + 1 即空。写成 h < t 会把“只剩一个元素”误判成空队列。
if (q[h] < i - k + 1) ++h窗口左端点是 i − k + 1。每步最多过期一个下标，所以用 if 就够，不必 while。
if (i >= k)前 k − 1 步窗口还没填满，不能输出。
总复杂度 O(n)每个下标进队一次、出队一次，while 的总执行次数不超过 n。暴力是 O(nk)，最坏 10¹²。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int a[6] = {0, 5, 3, 8, 1, 9};   // 1 开始存，n = 5
int q[10];

int main() {
    int n = 5, k = 3, h = 1, t = 0;
    for (int i = 1; i <= n; ++i) {
        while (h <= t && a[q[t]] >= a[i]) --t;
        q[++t] = i;
        if (q[h] < i - k + 1) ++h;
        if (i >= k) cout << a[q[h]] << " ";   // 输出 3 1 1
    }
    return 0;
}
注意

队列里存下标、不存值——这是这一节唯一需要背死的一句话。

求最大值时，队尾弹出条件和答案取值都要反过来；只改一半是这类题最常见的错法。

新函数拆解 · 树状数组：单点加、前缀和查询
int lowbit(int x) { return x & -x; } void add(int i, int v) { for (; i <= sz; i += lowbit(i)) t[i] += v; } int sum(int i) { int s = 0; for (; i > 0; i -= lowbit(i)) s += t[i]; return s; }
组成含义 / 格式要求
lowbit(x) = x & -x取 x 最低位的 1 所代表的权值：lowbit(6) = 2，lowbit(8) = 8，lowbit(0) = 0。
add(i, v)把 i 这条链上的结点都加 v：i, i+lowbit(i), i+lowbit(i+lowbit(i)) …，直到超过 sz。O(log n)。
sum(i)前缀和：t[i] + t[i−lowbit(i)] + … 直到下标 0。O(log n)。区间和 = sum(r) − sum(l−1)。
下标必须 ≥ 1lowbit(0) = 0 会让 add 的循环变量原地不动，死循环 → TLE。
sz值的上界（本题是离散化后不同值的个数）。add 的终止条件是 i <= sz，不是 i <= n。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int t[20], sz = 8;
int lowbit(int x) { return x & -x; }
void add(int i, int v) { for (; i <= sz; i += lowbit(i)) t[i] += v; }
int sum(int i) { int s = 0; for (; i > 0; i -= lowbit(i)) s += t[i]; return s; }

int main() {
    add(3, 1); add(3, 1); add(6, 1);   // 排名 3 出现两次，排名 6 出现一次
    cout << sum(2) << "\n";            // 0：排名 ≤ 2 的没有
    cout << sum(3) - sum(2) << "\n";   // 2：排名恰为 3 的个数
    cout << sum(6) << "\n";            // 3：排名 ≤ 6 的总个数
    return 0;
}
注意

sum 与 add 的循环方向相反：一个 i -= lowbit(i)，一个 i += lowbit(i)。写反就是死循环或答案偏小。

求逆序对时查 sum(r−1) 而不是 sum(r)，否则相等元素会被算成逆序对。

本题每次只“加 1”，所以 D 题代码里把 add 简化成 void add(int i) { ++t[i]; }，省掉了加数参数。

新函数拆解 · 离散化：把 10⁹ 的值压成 5×10⁵ 的排名
sort(b + 1, b + n + 1); sz = unique(b + 1, b + n + 1) - (b + 1); int r = lower_bound(b + 1, b + sz + 1, a[i]) - b;
组成含义 / 格式要求
sort(b + 1, b + n + 1)先把原数组复制一份到 b，排序。a 本身不动，后面还要按下标扫。
unique(b+1, b+n+1)把相邻的重复元素搬到末尾，返回“去重后区间的尾后指针”。它不删除元素，只是搬家。
- (b + 1)去重后的元素个数 sz。写成 - b 会多 1，是所有离散化 bug 里最常见的一个。
lower_bound(b+1, b+sz+1, x) - b第一个 ≥ x 的位置，即 x 的排名（从 1 开始）。右端点是 sz+1，不是 n+1。
相等元素拿到同一个排名这正是需要的：逆序对要求严格大于，用 r−1 查询天然排除相等的情况。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int a[6] = {0, 1000000000, -5, 7, 7, 233};
int b[6];

int main() {
    int n = 5;
    for (int i = 1; i <= n; ++i) b[i] = a[i];
    sort(b + 1, b + n + 1);
    int sz = unique(b + 1, b + n + 1) - (b + 1);   // 4 个不同值
    for (int i = 1; i <= n; ++i)
        cout << lower_bound(b + 1, b + sz + 1, a[i]) - b << " ";
    // 输出 4 1 2 2 3
    return 0;
}
注意

if (x < 1 || x > sz) 说明离散化写错了：出现这种情况几乎都是 sz 的表达式少减了一次。

离散化不改变答案的正确性，它只是把“值域”换成“排名”，让桶和树状数组开得下。

新函数拆解 · 断环成链：把环拆成 2n 的链再区间 DP
for (int i = 1; i <= n; ++i) { cin >> a[i]; a[i + n] = a[i]; } for (int len = 2; len <= n; ++len) for (int i = 1; i + len - 1 <= 2 * n; ++i) { int j = i + len - 1; for (int k = i; k < j; ++k) f[i][j] = min(f[i][j], f[i][k] + f[k + 1][j] + pre[j] - pre[i - 1]); } // 答案 = 对 i ∈ [1, n] 取 f[i][i + n - 1] 的最优值
组成含义 / 格式要求
a[i + n] = a[i]把数组复制一份接在后面。环上任意一种“从哪断开”的走法，都对应 2n 链上一个长度为 n 的连续区间。
for (len = 2; len <= n; ++len)按区间长度从小到大算。区间 DP 的方向是“先短后长”，长度 1 的区间是初值。
i + len - 1 <= 2 * n右端点不能越过 2n。只写 i <= n 是不够的：短区间的右端点完全可以超过 n。
for (k = i; k < j; ++k)枚举最后一次合并的分界：左半 a[i..k]、右半 a[k+1..j]。k 不能取到 j，否则右半为空。
+ pre[j] - pre[i - 1]本次得分 = 这一段的总和，用前缀和一次算出。写两层求和会把 O(n³) 变成 O(n⁴)。
答案取 n 个区间环有 n 种断法，对应 n 个长度为 n 的区间，答案在这 n 个里取最优。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

long long pre[10], f[10][10];

int main() {
    int a[4] = {0, 4, 5, 9};                 // 三堆：4 5 9
    for (int i = 1; i <= 3; ++i) pre[i] = pre[i - 1] + a[i];
    for (int len = 2; len <= 3; ++len)
        for (int i = 1; i + len - 1 <= 3; ++i) {
            int j = i + len - 1;
            f[i][j] = LLONG_MAX;
            for (int k = i; k < j; ++k)
                f[i][j] = min(f[i][j], f[i][k] + f[k + 1][j] + pre[j] - pre[i - 1]);
        }
    cout << f[1][3] << "\n";                 // 27：先 4+5=9，再 9+9=18
    return 0;
}
注意

长度只枚举到 n，不要到 2n：长度大于 n 的区间在环上没有意义，还会把数组写越界。

求最小值的那张表初值要是 INF（memset 0x3f），求最大值的要是 0。两张表不能共用初值。

本场最容易丢的分，每条都写明症状

单调队列存值不存下标 → WA。A 题 q[] 里存 a[i] 的值，就没法判断队头是否滑出窗口，只能靠“值相等”猜，一遇到重复数字全错。

h <= t 写成 h < t → WA 或 RE。只剩一个元素时被判成空队列，q[h] 读到的是过期下标，输出一个根本不在窗口里的数。

窗口左端点写成 i−k → WA。窗口是 [i−k+1, i]，差这一格会让每个窗口多留一个过期元素，最小值普遍偏小、最大值普遍偏大。

LIS 的比较写成 ≤ → WA。B 题要求严格递增，写 a[j] <= a[i] 时，两个同身高的同学会被串进同一条上升链。样例前两个人身高都是 186，答案会小 1。

B 题把 n − best 写成 best → WA。题目问的是“出列几人”，best 却是“留下几人”。样例里 n = 8、best = 4，两种写法都能过样例——这就是为什么必须自己再造一组数据：n = 5、身高 1 2 1 2 1 时 best = 3 而答案是 2，一眼就露。

二分中点用了下取整 → TLE。C 题求“最大可行值”，mid 必须上取整；写成 (lo+hi)/2 配 lo = mid，当 hi = lo+1 时 mid 恒等于 lo，区间不再缩小，程序空转到超时。

check 漏了最后一跳 → WA。C 题只判石头与石头之间、忘了 L − last，样例能过，错在“最后一段太短”的数据上。

逆序对答案用 int → WA 成负数。D 题 n = 5×10⁵ 全逆序时答案 ≈ 1.25×10¹¹，int 上限才 2.1×10⁹，溢出后输出一个负数。

树状数组下标从 0 开始 → TLE。lowbit(0) = 0，add(0) 里 i += 0 原地踏步，死循环。

E 题 f 初值设成 0 → WA。求最小值的表如果不 memset 成 INF，min 永远取到 0，输出 0；而求最大值的表初值又必须是 0，两张表的初值不能共用。

E 题 i + len − 1 越界 → RE。数组只开到 205 而循环边界写错，越界写的可能是另一个数组，表现为“样例全过、一交就崩”。

有一个长为 n 的序列 a，以及一个大小为 k 的窗口。窗口从序列最左端开始，每次向右滑动一个单位，直到右端到达序列末尾。对每一个位置上的窗口，求出窗口内元素的最小值和最大值。

输入格式：第一行两个正整数 n、k（1 ≤ k ≤ n ≤ 10⁶）。第二行 n 个整数，表示序列 a（绝对值不超过 10⁹）。

输出格式：共两行。第一行为每个窗口的最小值，第二行为每个窗口的最大值，同一行的数字之间用一个空格隔开。

样例输入
8 3
1 3 -1 -3 5 3 6 7
样例输出
-1 -3 -3 -3 3 3
3 3 5 5 6 7

引导性提示（先只看这里）

先估一下暴力：n 和 k 都可能到 10⁶，每个窗口重扫一遍是 O(nk)，最坏 10¹²，稳 TLE。

换角度看：窗口右移一格，只进来一个新数、只出去一个旧数。哪些数从此再也不可能成为最小值？

如果新来的数比当前候选里最后一个还小，那个候选在过期之前都不可能成为答案——因为新数既更小、又活得更久。

想看思路了？点开完整思路

维护一个下标队列 q，保证 q 里的下标递增、对应的 a 值也递增。此时队头 a[q[h]] 就是当前窗口的最小值。

每步三件事：① 新元素入队前，把队尾所有“值 ≥ 新元素”的下标弹掉——它们既不如新元素小、又比新元素先过期，永远没机会了；② 把 i 放进队尾；③ 检查队头是否还在窗口 [i−k+1, i] 里，不在就弹掉。

正确性：队列里值单调递增，所以队头是整个队列的最小值；队头一定在窗口内（过期就弹了）。被弹掉的下标要么值更大且更靠左，要么已经过期，都不可能成为任何后续窗口的答案。

复杂度：每个下标最多进队一次、出队一次，while 的总执行次数不超过 n，整体 O(n)。

最大值完全同构：把队尾弹出条件从 a[q[t]] ≥ a[i] 改成 a[q[t]] ≤ a[i]，别的一个字都不改。

输出细节：前 k−1 步窗口没填满，不输出；行末只换行，不加多余空格。

using namespace std;

int n, k;
int a[1000005];
int q[1000005];                  // 手写双端队列，存的是下标

int main() {

    cin.tie(nullptr);

    cin >> n >> k;
    for (int i = 1; i <= n; ++i) cin >> a[i];

    // ---- 最小值：队列里的下标对应的 a 值严格递增，队头即窗口最小值 ----

n 位同学站成一排，音乐老师要请其中的 n−k 位同学出列，使剩下的 k 位同学排成“合唱队形”。合唱队形指存在一个“顶峰”位置 i，使身高满足 t₁ < t₂ < … < tᵢ > tᵢ₊₁ > … > t_k。求最少需要几位同学出列。

输入格式：第一行一个整数 n（2 ≤ n ≤ 100）。第二行 n 个整数，第 i 个表示第 i 位同学的身高 tᵢ（130 ≤ tᵢ ≤ 230）。

输出格式：一个整数，即最少需要出列的人数。

4

引导性提示（先只看这里）

“留下的人”必须是先升后降的。形状只由一件事决定：谁是那个最高的人。

枚举顶峰 i 之后，左右两段互相独立：左边是“以 i 结尾的最长上升子序列”，右边是“以 i 开头的最长下降子序列”。

想看思路了？点开完整思路

答案 = n − （能留下的最多人数）。所以问题变成“最多能留下几人”。

枚举顶峰 i。左边必须以 i 结尾且严格递增，长度就是 f[i] = 以 i 结尾的最长上升子序列；右边必须以 i 开头且严格递减，长度是 g[i] = 以 i 开头的最长下降子序列。

以 i 为顶峰时的最大保留人数 = f[i] + g[i] − 1，减 1 是因为顶峰自己被两段都算了一次。

f 从左往右推：f[i] = 1 + max{ f[j] : j < i 且 a[j] < a[i] }，没有合法的 j 时 f[i] = 1。

g 从右往左推，转移条件同样是 a[j] < a[i]：g[i] = 1 + max{ g[j] : j > i 且 a[j] < a[i] }。

两遍都是 O(n²)，总 O(n²) = 10⁴ 次操作。最后输出 n − max(f[i]+g[i]−1)。

int n, a[105];
int f[105], g[105];              // f：以 i 结尾的最长上升长度；g：以 i 开头的最长下降长度

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> a[i];

    // 左半边：以 i 结尾的最长上升子序列

        f[i] = 1;                            // 至少包含自己

            if (a[j] < a[i]) f[i] = max(f[i], f[j] + 1);   // 严格递增：不能取等
    }

    // 右半边：以 i 开头的最长下降子序列，从右往左推
    for (int i = n; i >= 1; --i) {
        g[i] = 1;
        for (int j = i + 1; j <= n; ++j)
            if (a[j] < a[i]) g[i] = max(g[i], g[j] + 1);
    }

    int best = 0;                            // 能留下的最多人数
    for (int i = 1; i <= n; ++i)

比赛在一条笔直的河道中进行，河道中有 N 块岩石（不含起点与终点）。选手从起点出发，每一步跳到相邻的岩石上，直到到达终点。组委会至多可以移走 M 块岩石（起点和终点不能移走），要求移走之后，选手所有跳跃距离中的最小值尽可能大。求这个最大可能的最短跳跃距离。

输入格式：第一行三个整数 L、N、M，分别表示起点到终点的距离、岩石数、至多移走的岩石数；接下来 N 行，每行一个整数 Dᵢ，表示第 i 块岩石到起点的距离，按从小到大给出。（0 ≤ M ≤ N ≤ 50000，0 < L ≤ 10⁹）

输出格式：一个整数，即最短跳跃距离的最大值。

样例输入
25 5 2
2
11
14
17
21
样例输出
4

引导性提示（先只看这里）

“最大值最小 / 最小值最大”这类字眼一出现，先想二分答案。这里问的是“最短跳跃距离的最大值”。

固定一个 d，问：能不能只移走不超过 M 块石头，让每一跳都 ≥ d？这个判断比原问题好想得多。

判断的时候从左往右贪心：能跳到就跳，跳不到就把中间那块石头搬走。搬走一块之后，跨度会变大还是变小？

想看思路了？点开完整思路

二分答案 d：判定“最短跳跃距离 ≥ d”是否可行。d 越大越难满足，单调性成立。

check(d)：last 记录上一块“保留下来的落脚点”坐标（起点是 0），从左往右扫岩石。若 a[i] − last < d，这跳太短，只能把第 i 块搬走（cnt++），last 不变；否则保留它，last = a[i]。

扫完还要检查最后一跳 L − last：若它 < d，就把最后保留的那块石头搬走（不是搬终点），这样“上一落脚点 → L”的距离只会更大，一定也 ≥ d。

为什么贪心最优：能保留就保留，保留只会让后续的距离更容易够（last 更靠右）。提前搬走一块只会让跨度更大、消耗更多次数，不可能更优。

判定条件是 cnt ≤ M：不超过 M 块就合法，题目说的是“至多移走 M 块”。

二分区间 [1, L]：答案至少 1，至多 L（一块石头都不留时就是 L）。求最大可行值，中点要上取整。

复杂度 O(N log L) ≈ 5×10⁴ × 30 = 1.5×10⁶，稳过。

#include <bits/stdc++.h>
using namespace std;

int L, n, m;
int a[50005];                    // a[1..n] 是岩石坐标；起点 0 由 last 的初值表示

// 判定：能不能只移走 ≤ m 块石头，使每一跳都 ≥ d
bool check(int d) {
    int cnt = 0, last = 0;               // last：上一个保留的落脚点
    for (int i = 1; i <= n; ++i) {
        if (a[i] - last < d) ++cnt;      // 这跳太短，只能搬走第 i 块
        else last = a[i];                // 跳得到，保留它
    }
    if (L - last < d) ++cnt;             // 最后一跳不够长：搬走 last 这块（不是终点）
    return cnt <= m;                     // “至多 m 块”，不是“恰好 m 块”
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> L >> n >> m;
    for (int i = 1; i <= n; ++i) cin >> a[i];

    int lo = 1, hi = L;                  // 答案至少 1，至多 L
    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;    // 上取整：求最大可行值必须这么写
        if (check(mid)) lo = mid;            // 可行，试着更大
        else hi = mid - 1;                   // 不可行，必须更小
    }
    cout << lo << "\n";
    return 0;
}

对于给定的一段正整数序列，逆序对就是序列中满足 aᵢ > aⱼ 且 i < j 的有序对 (i, j)。给定一个长度为 n 的序列，求它的逆序对数目。注意序列中可能有重复数字。

输入格式：第一行一个整数 n（n ≤ 5×10⁵）。第二行 n 个整数，表示给定的序列，每个数字不超过 10⁹。

输出格式：一个整数，即逆序对的数目。

样例输入
6
5 4 2 6 3 1
样例输出
11

引导性提示（先只看这里）

n = 5×10⁵，枚举 (i, j) 是 1.25×10¹¹ 对，稳 TLE。目标复杂度 O(n log n)。

换个计数角度：对每个 j，数一数它左边有多少个数比 aⱼ 大，全部加起来就是答案。

“左边有多少个数比它小”这种前缀计数，值域又只有 5×10⁵ 个不同值——把 10⁹ 压成排名，就能用树状数组一次 log 查出来。

想看思路了？点开完整思路

逆序对总数 = 对每个位置 i，统计“右边比 aᵢ 小的元素个数”，全部累加。

值域到 10⁹，桶开不下。先离散化：把 a 复制成 b，排序去重，用 lower_bound 把每个 aᵢ 换成排名，排名范围 1..sz，sz ≤ n ≤ 5×10⁵。

从右往左扫。树状数组 t 里记的是“某个排名已经出现过几次”。扫到 aᵢ 时，排名是 r，则 sum(r−1) 就是右边比它小的个数，直接加进答案；然后把 r 加进树状数组。

为什么用 r−1 而不是 r：逆序对要求严格大于，相等元素不能算。排名相同意味着值相等，必须排除。

正确性：每个逆序对 (i, j) 在扫描到 i 时被恰好数到一次——那时 j 已经进树状数组，且排名更小。

复杂度 O(n log n)：离散化 O(n log n)，每次查询和修改 O(log n)，总计约 5×10⁵ × 19 × 2 次操作。

答案上界：n(n−1)/2 ≈ 1.25×10¹¹，必须 long long。

int n;

void add(int i) {
    for (; i <= sz; i += lowbit(i)) ++t[i];
}

int sum(int i) {                 // 排名 ≤ i 的元素个数
    int s = 0;
    for (; i > 0; i -= lowbit(i)) s += t[i];
    return s;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    }

在一个圆形操场的四周摆放 N 堆石子，现要将石子有次序地合并成一堆。规定每次只能选相邻的 2 堆合并成新的一堆，并把新堆的石子数记为本次合并的得分。求把 N 堆合并成一堆的最小总得分和最大总得分。

输入格式：第一行一个整数 N（N ≤ 100）；第二行 N 个整数，依次表示每堆石子的个数（正整数）。

输出格式：共两行，第一行为最小得分，第二行为最大得分。

样例输入
4
4 5 9 4
样例输出
43
54
样例解释：最小方案先合并 4+4=8（得 8 分），再 8+5=13（13 分），再 13+9=22（22 分），共 43。

引导性提示（先只看这里）

先做一条链上的版本：n 堆排成一行，每次合并相邻两堆。把“最后一步”想清楚——它一定是把某个前缀段和某个后缀段合并。

于是需要知道“把 a[i..j] 合并成一堆”的最优得分。这就是区间 DP：先算小区间，再用小区间拼出大区间。

环怎么处理？一种断法对应一种走法，有 n 种断法。有没有办法不写 n 遍，一遍扫完？

想看思路了？点开完整思路

断环成链：把数组复制一份接在后面，得到 a[1..2n]。环上任意一种“从哪断开”的合并方案，都对应 2n 链上一个长度为 n 的连续区间。答案在这 n 个区间里取最优。

状态：f[i][j] = 把 a[i..j] 合并成一堆的最小得分；g[i][j] 同理求最大。

转移：最后一次合并必然把 a[i..k] 与 a[k+1..j] 两堆合成一堆，本次得分 = 这一段总和。f[i][j] = min over k∈[i, j−1] of f[i][k] + f[k+1][j] + (pre[j] − pre[i−1])。

顺序：按区间长度 len 从小到大枚举。长度 1 的区间不需要合并，得分 0。不能用“从 i 推到 j”的方式，因为 f[i][j] 依赖的所有子区间长度都比它短。

边界：f[i][i] = 0，其余 f 初值设成 INF；g 全部初值 0（最大值的下界就是 0）。

答案：对 i = 1..n 取 f[i][i+n−1] 的最小值、g[i][i+n−1] 的最大值。

复杂度 O(n³)：区间 O(n²) 个（实际是 2n 个起点 × n 种长度），每个枚举 O(n) 个分界点，n = 100 时约 2×10⁶ 次。

using namespace std;

int n;
long long a[205], pre[205];
long long f[205][205], g[205][205];      // f：最小得分，g：最大得分

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) { cin >> a[i]; a[i + n] = a[i]; }   // 断环成链
    for (int i = 1; i <= 2 * n; ++i) pre[i] = pre[i - 1] + a[i];     // 前缀和，O(1) 取段和

    memset(f, 0x3f, sizeof(f));              // 求最小值：初值设成极大
    for (int i = 1; i <= 2 * n; ++i) f[i][i] = 0;   // 一堆不用合并，得分 0

    for (int len = 2; len <= n; ++len)                    // 区间长度，先短后长
        for (int i = 1; i + len - 1 <= 2 * n; ++i) {      // 左端点
            int j = i + len - 1;
            long long s = pre[j] - pre[i - 1];            // 本次合并的得分
            for (int k = i; k < j; ++k) {                 // 最后一次合并的分界

                g[i][j] = max(g[i][j], g[i][k] + g[k + 1][j] + s);
            }
        }

    long long mn = LLONG_MAX, mx = 0;
    for (int i = 1; i <= n; ++i) {                        // n 种断法
        mn = min(mn, f[i][i + n - 1]);
        mx = max(mx, g[i][i + n - 1]);
    }
    cout << mn << "\n" << mx << "\n";
    return 0;
}

洛谷 P2627提高-/提高去洛谷做这题 ↗

Farmer John 有 N 只排成一排的奶牛，编号 1..N，第 i 只奶牛的效率是 Eᵢ（0 ≤ Eᵢ ≤ 10⁹）。他要选一些奶牛来剪草坪，把这些奶牛的效率加起来就是总效率。

麻烦在于：如果 FJ 安排了超过 K 只连续的奶牛，它们就会罢工。也就是说，选中的奶牛里不能出现长度超过 K 的连续段。

求能获得的最大总效率。

输入格式：第一行两个整数 N、K（1 ≤ N ≤ 10⁵，1 ≤ K ≤ N）；第 2 到 N+1 行，每行一个整数 Eᵢ。

输出格式：一行一个整数，表示最大效率值。

样例输入
5 2
1
2
3
4
5
样例输出
12
样例解释：选 1、2、4、5 号奶牛，总效率 1+2+4+5 = 12，两段连续长度都是 2，不超过 K = 2；换成别的选法都不会更大。

样例
输入： 5 2 1 2 3 4 5 输出： 12
引导性提示（先只看这里）

直接写「前 i 只奶牛的最大效率」很难转移——你不知道当前已经连续选了几只。换一个角度：把没选的位置当成隔板，两片隔板之间夹着的就是一段被选中的连续奶牛。

设 h[i] 表示「第 i 个位置不选」时前 i 只奶牛的最大效率。若上一个不选的位置是 p，那么 p+1..i−1 全是选中的，长度 i−1−p 不能超过 K，也就是 p ≥ i−1−K。把转移写出来，你会发现它是一个滑动窗口最大值。

窗口里的量是 h[p] − s[p]（s 是效率的前缀和）。用单调队列在 O(1) 内取窗口最大，和本节 P1886 求窗口最大值完全同构，只是把「数组值」换成了「h[p] − s[p]」。

想看思路了？点开完整思路

① 状态怎么定。令 s[i] = E₁ + … + E_i，h[i] = 第 i 个位置不选时前 i 只奶牛的最大效率。把「不选」当成隔板：两片隔板 p 与 i 之间（p < i）的 p+1..i−1 全是选中的连续段，它的长度 i−1−p 必须 ≤ K。

② 转移。h[i] = s[i−1] + max{ h[p] − s[p] : i−1−K ≤ p ≤ i−1 }。含义：p+1..i−1 这一整段全选（贡献 s[i−1] − s[p]），前面到 p 为止的最优值是 h[p]，两部分相加。

③ 答案在哪。在末尾补一个虚拟位置 n+1（不选），答案就是 h[n+1]——这样最后一段连续奶牛也被「隔板」截住了，长度同样受限。

④ 为什么能用单调队列。窗口的左右端点都随 i 单调右移，窗口里要的是最大值，这正是本节滑动窗口的标准场景：队尾弹掉「更小且更早过期」的，队头弹掉「已经滑出窗口」的。每个下标进出队各一次，均摊 O(1)。

⑤ 初值。h[0] = 0、s[0] = 0，把 p = 0 当成第 0 个隔板先放进队列；转移时 q[head] 对应的 h[q[head]] − s[q[head]] 就是窗口最大。

⑥ 数值与复杂度。Eᵢ ≤ 10⁹、N ≤ 10⁵，总和能到 10¹⁴，h、s、差值全部用 long long。总复杂度 O(N)，N = 10⁵ 时不到 3×10⁵ 次操作。
