A · 失落的画卷

P1659时间 1 秒 / 内存 128 兆去 OJ 做题 ↗

把一张 n×m 的字符画用 RLE 压缩，或把 RLE 串还原成字符画；op=1 压缩、op=2 解压。

题意

题目描述

在某些古老的编程大赛档案馆里，保存着许多巨大的
字符画。这些字符画是用 ASCII 字符排成的 n × m 的矩形，每个位置都有一个字符。
然而，字符画常常很大，直接存储会占用很多空间。于是，管理员决定使用
RLE（Run-Length Encoding，游程编码）
压缩技术来存档。

RLE 的规则非常简单：

- 将相同的连续字符合并为“出现次数 + 字符”的形式。 例如：

AAAABBCCCC

会被压缩成

4A2B4C

管理员希望你来实现一个程序，能够：

- 压缩 一个 n × m 的字符画。

- 解压 一个 RLE 压缩后的字符串，还原为 n × m 的字符画。

输入格式

- 第一行输入三个整数 n (0 ≤ n ≤ 100), m (0 ≤ m ≤ 100), op (op ∈ [1, 2])。

- n, m
表示字符画的行数和列数。

- op = 1 表示执行
压缩操作。

- op = 2 表示执行
解压操作。

- 若 op = 1： 接下来输入 n 行，每行 m 个字符，表示字符画。

- 若 op = 2：
接下来输入一个压缩字符串。保证该压缩字符串正确无误，解压后正好可以得到
n × m 个字符。

输出格式

- 若 op = 1：输出压缩后的字符串（不包含换行符）。

- 若 op = 2：输出解压后的 n × m 字符画，每行 m 个字符。

提示

- 当 n=0 或 m=0
时，字符画为空，不需要输出任何内容。

- 压缩与解压后的结果均唯一。

样例输入
2 5 1
AAAAB
BBCCC
样例输出
4A3B3C

先想一想

  • “行”是干扰项：把 n 行首尾相接成一条长串，跨行的相同字符也要合并。
  • 解压时先连续读数字（次数可能超过一位），再读一个字符，把这个字符重复 count 次。
  • n 或 m 为 0 时字符画是空的，压缩结果为空串。
完整思路（点开看推导）

压缩就是最朴素的游程编码：把所有行拼成一个长串 s，用双指针扫一遍，i 指向一段的起点，j 一直往右走到字符变化为止，这一段就是 j−i 个 s[i]，输出「次数 + 字符」后令 i=j。因为拼接时行与行之间不插入任何分隔，跨行的同字符自然会被并到一起，正好符合样例 AAAAB + BBCCC = 4A3B3C。

解压是逆过程：从左到右扫字符串，遇到数字就累加计数（cnt = cnt*10 + c−数字0），遇到非数字就把当前字符重复 cnt 次追加到答案里，然后清零计数。最后按每行 m 个字符切出来输出即可，不必真的维护二维数组。

参考代码

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m, op;
    if (!(cin >> n >> m >> op)) return 0;
    if (op == 1) {
        string s;
        string line;
        getline(cin, line);                 // 吃掉行尾
        for (int i = 0; i < n; ++i) {
            getline(cin, line);
            s += line;
        }
        string out;
        for (size_t i = 0; i < s.size(); ) {
            size_t j = i;
            while (j < s.size() && s[j] == s[i]) ++j;
            out += to_string(j - i);
            out += s[i];
            i = j;
        }
        cout << out << '\n';
    } else {
        string s;
        cin >> s;
        string out;
        int cnt = 0;
        for (char c : s) {
            if (isdigit((unsigned char)c)) cnt = cnt * 10 + (c - '0');
            else { out.append(cnt, c); cnt = 0; }
        }
        for (int i = 0; i < n; ++i) {
            cout << out.substr(1LL * i * m, m) << '\n';
        }
    }
    return 0;
}

代码逐段看

  • 读入用 getline：字符画里可能有空格之类的符号，用 cin >> char 会把空白吃掉。
  • 压缩用双指针 i / j，每段只扫一遍，整体 O(nm)。
  • 解压时 out.append(cnt, c) 一次展开一段，最后 substr(i*m, m) 切行。

复杂度：O(nm)
坑点：别把行尾换行读进字符画；次数可能是两位数（如 10A），必须累加而不是只取一位。

B · 坏掉的时针

P1660时间 2 秒 / 内存 32 兆去 OJ 做题 ↗

定义 f(x) 为「十进制各位数字 +1 之后的乘积」，对 n 连续做 x 次，输出结果（n ≤ 1e18，x ≤ 1e9）。

题意

题目描述

大一开学不久，小 a 迎来了自己的 18 岁生日。朋友们送了他一份特别的礼物 ——
一只“坏掉的时钟”。

这只时钟看起来和普通时钟一样，有一个时针。但它的走法却十分古怪：

普通时钟的时针会依次从 1 走到
12，然后再回到 1；

而这只“坏掉的时钟”，每次走动时，都会把当前时针所指的数字拆开成十进制的各个位数，把每一位都加上
1，再将它们全部相乘，得到的新数，才是时针下一步所指向的位置。

小 a
越看越离谱，于是决定研究一下这只奇怪时钟的规律。他可以随意设定时针的起始位置，然后想知道：在经过
x
次走动之后，时针会停在什么数字上？

定义操作： 对于一个非负整数 a，操作前其十进制表示为 a_0a_1a_2·s a_n-1，操作后的值表示为∏_i=0^n-1(a_i + 1)。

给定初始整数 n 和 x，要求对 n 连续进行上述操作 x 次，输出最终结果。

输入格式

第一行包含 T (1 ≤ T ≤ 2× 10^6) —
测试用例的数量。

每个测试用例一行包含两个非负整数 n (0 ≤ n ≤ 10^18)和 x (0 ≤ x ≤ 10^9)。

输出格式

对于每个测试样例，输出一行一个整数，表示答案。

提示

以下是对第二组样例的解释：

输入: n = 20250927, x = 2

解释:

- 第 1 次操作 (对 20250927):

- 各位数字为 2, 0, 2, 5, 0, 9, 2, 7。

- 计算 (2+1) × (0+1) × (2+1) × (5+1) × (0+1) × (9+1) × (2+1) × (7+1) = 12960。

- 第 2 次操作 (对 12960):

- 各位数字为 1, 2, 9, 6, 0。

- 计算 (1+1) × (2+1) × (9+1) × (6+1) × (0+1) = 420。

- 最终结果: 420

本题输入数据较大，请使用较快的读入方式。

样例输入
2
999999 1
20250927 2
样例输出
1000000
420

先想一想

  • 先手算几个数：f(999999)=10⁶，f(12960)=420，多做几次会发现数值掉得飞快。
  • 想想 f(x) 能取到哪些值：它是若干个 1..10 的乘积，质因子只可能是 2、3、5、7。
  • 把轨迹画出来，会看到一个很短的循环。
完整思路（点开看推导）

先看 f 的量级：一次操作把 x 变成各位 (digit+1) 的乘积，结果最大是 9^19 ≈ 1.35e18，但只有「几乎全是 9」的数才可能这么大，而这种数的下一轮 f 会瞬间掉到很小（如 10^18 变 2）。所以轨迹很快就会落到 2~10 这一段，而这一段正好是一个 9 长环：2→3→4→5→6→7→8→9→10→2。

因此答案只由「进环前走了几步」和「从环上哪个位置进」决定。预处理 10^6 以内每个数：dep[v] = 走多少步进环，ent[v] = 进环时踩到的值；用记忆化沿路径回溯填表，总代价 O(10^6 × 位数)。

单次询问：x=0 直接输出 n；否则先做一次 f（输入可能到 1e18），若结果仍大于 10^6 就继续手算（最多两三次）；剩下 x 步时，若 x < dep[v] 就直接走，否则跳到环上算：答案 = 2 + ((ent[v]-2) + (x-dep[v])) mod 9。

参考代码

#include <bits/stdc++.h>
using namespace std;

static const int LIM = 1000000;
static unsigned char dep[LIM + 1];
static unsigned char ent[LIM + 1];
static int F[LIM + 1];

static inline long long f(long long v) {
    long long r = 1;
    if (v == 0) return 1;
    while (v > 0) { r *= (v % 10) + 1; v /= 10; }
    return r;
}

int main() {
    for (int v = 0; v <= LIM; ++v) F[v] = (int)f(v);

    memset(dep, 0xFF, sizeof(dep));          // 0xFF = 未知
    memset(ent, 0xFF, sizeof(ent));
    for (int v = 2; v <= 10; ++v) { dep[v] = 0; ent[v] = (unsigned char)v; }

    static int path[64];
    for (int v = 0; v <= LIM; ++v) {
        if (dep[v] != 0xFF) continue;
        int len = 0, cur = v;
        while (dep[cur] == 0xFF && len < 60) { path[len++] = cur; cur = F[cur]; }
        unsigned char d = dep[cur], e = ent[cur];
        for (int i = len - 1; i >= 0; --i) {
            if (++d > 250) d = 250;
            dep[path[i]] = d;
            ent[path[i]] = e;
        }
    }

    static char buf[1 << 25];
    size_t len = fread(buf, 1, sizeof(buf), stdin);
    size_t p = 0;
    auto readLL = [&]() -> long long {
        while (p < len && (buf[p] < '0' || buf[p] > '9')) ++p;
        long long x = 0;
        while (p < len && buf[p] >= '0' && buf[p] <= '9') x = x * 10 + (buf[p++] - '0');
        return x;
    };

    long long T = readLL();
    string out;
    out.reserve(T * 8);
    while (T--) {
        long long n = readLL(), x = readLL();
        if (x == 0) { out += to_string(n); out += '\n'; continue; }
        long long v = f(n);
        --x;
        while (x > 0 && v > LIM) { v = f(v); --x; }
        if (x == 0) { out += to_string(v); out += '\n'; continue; }
        if (x < dep[v]) {                     // 还没进环，直接走
            while (x-- > 0) v = f(v);
            out += to_string(v); out += '\n';
            continue;
        }
        long long t = x - dep[v];             // 进环后再走 t 步
        int e = ent[v];
        int idx = (e - 2 + t % 9) % 9;        // 环：2,3,...,10
        out += to_string(2 + idx); out += '\n';
    }
    fwrite(out.data(), 1, out.size(), stdout);
    return 0;
}

代码逐段看

  • 预处理 F[v] 存 f(v)；dep/ent 用 unsigned char 省内存。
  • 记忆化：沿路把点压进 path[]，撞到已知点后倒着填 dep/ent。
  • 读入必须自己写缓冲区：T 最大 2×10^6，cin 偏慢。
  • 输出用 string 攒起来一次 fwrite，避免两百万次 printf。

复杂度：预处理 O(10^6·7)，单次 O(1)
坑点：x=0 要原样输出 n（不是 f(n)）；环是 2..10 共 9 个元素。

C · CS2: 图神的伤害计算器

题意

题目描述

图神 是 ACM_CS2
界的传奇选手，以其惊人的反应速度和精准的枪法而闻名。为了在比赛中做出最快、最正确的决策，他需要一个能快速计算不同战斗场景下伤害值的程序。现在，他把这个任务交给了你，你需要编写一个程序，模拟三种核心的战斗伤害计算场景。

程序将接收一个操作类型 option 和两个数值 a
和 b。你需要根据 option
的值执行相应的计算：

- 当 option 为 1 时，代表
【火力叠加】。

- 情况说明：图神 和队友同时向一个敌人开火，图神 造成了 a
点伤害，队友造成了 b 点伤害。

- 计算任务：请求出敌人受到的总伤害。

- 当 option 为 2 时，代表
【护甲减伤】。

- 情况说明：图神 的一发子弹理论上能造成 a
点巨额伤害，但敌人装备了精良的护甲，抵消了 b 点伤害。

- 计算任务：请求出敌人实际受到的伤害。

发。

第一行包含一个整数 t (1 ≤ t ≤ 100) —— 测试用例的数量。

对于每个测试用例，只有一行输入，包含三个整数：option,
a, b。

- 1 ≤ a, b ≤ 2 × 10^9

- 数据保证在 option 为 2 时，a ≥ b。

对于每个测试用例，输出一行，包含一个整数 ——
对应场景下的计算结果。

样例输入
3
1 100 800
2 2000 500
3 150 4

900
1500
600

先想一想

  • 就是三个分支，读完直接算。
  • a、b 最大 2×10^9，乘法会溢出 int。
完整思路（点开看推导）

签到题。option=1 输出 a+b，option=2 输出 a−b（题目保证 a ≥ b），option=3 输出 a×b。唯一要注意的是第三种乘积上界 4×10^18，必须用 64 位整数；前两种其实 int 够，但统一 long long 更省心。

#include <bits/stdc++.h>
using namespace std;
int main() {

D · 奶龙数日子

P1662时间 1 秒 / 内存 256 兆去 OJ 做题 ↗

给两个合法日期，求相差多少天（含起始日、不含结束日）。

题意

题目描述

在一个阳光明媚的下午，健忘的奶龙在后山发现了一根极其稀有的“七彩流光笋”！这根竹笋看起来美味极了，但他的好朋友小七告诉他，这种笋必须埋在地下，耐心等待一段时间，风味才会达到顶峰。

奶龙听话地把笋埋了起来，并在他的小本本上记下了两个重要的日期：

- 埋藏日: Y_1 年
M_1 月 D_1 日

- 开挖日: Y_2 年
M_2 月 D_2 日

可是，奶龙的脑容量和他的肚子一样，装满了就容易忘事。他现在已经不记得自己需要等待多少天了。他只知道，“等待的天数”就是从埋藏日的那天开始，一直数到开挖日那天，总共有多少天。

作为小七和奶龙最好的伙伴，你能帮帮这只犯迷糊的胖胖龙，算出他总共需要“睡几觉”才能吃到美味的竹笋吗？

给定两个日期（保证第二个日期不早于第一个日期），请计算这两个日期之间相差了多少天。

例如，从 2025年9月18日 到 2025年9月20日，奶龙需要等待 2 天（即
9月18日 和 9月19日 这两天）。

输入格式

第一行包含一个整数 t (1 ≤ t ≤ 100) —— 测试用例的数量。

对于每个测试例，只有一行输入，包含六个整数：Y_1, M_1, D_1, Y_2, M_2, D_2，分别代表第一个日期的年、月、日和第二个日期的年、月、日。

- 1800 ≤ Y_1, Y_2 ≤ 3000

- 1 ≤ M_1, M_2 ≤ 12

- 1 ≤ D_1, D_2 ≤ 31

- 输入保证所有日期均为有效日期，且第二个日期大于或等于第一个日期。

输出格式

对于每个测试用例，输出一个整数，代表两个日期之间相隔的天数。

提示

样例解释：

- 样例 1：从 9月18日 到 9月20日，相差 2 天。

- 样例 2：2024年是闰年，2月有29天。从 2月25日 到
3月5日，需要经过 2月的(29-25)=4天，以及3月的5天，共 4 + 5 = 9 天。

- 样例 3：从 2023年12月30日 到 2024年1月2日，需要经过
12月的(31-30)=1天，以及1月的2天，共 1 + 2 = 3 天。

- 样例 4：从 2023年1月1日 到
2025年1月1日，经历了完整的 2023年（平年, 365天）和 2024年（闰年,
366天），共 365 + 366 = 731 天。

在公历中，闰年遵循以下规则：

- 年份能被 4 整除，但不能被 100 整除。

- 或者，年份能被 400 整除。

样例输入
4
2025 9 18 2025 9 20
2024 2 25 2024 3 5
2023 12 30 2024 1 2
2023 1 1 2025 1 1
样例输出
2
9
3
731

先想一想

  • 不同月份天数不同，闰年二月还要 +1。
  • 与其一个月一个月加，不如把日期换算成「从固定起点过了多少天」，再相减。
  • 闰年规则：4 的倍数且不是 100 的倍数，或 400 的倍数。
完整思路（点开看推导）

定义 idx(y,m,d) = 从 1800-01-01 到 (y,m,d) 经过的天数。先累加整年（1800..y−1，闰年 366、平年 365），再累加整月（1..m−1，二月遇闰年补 1），最后加 d−1。两个日期都换算成 idx 后相减，跨月、跨年、跨闰年全部自动处理。

用样例检验：2023-12-30 到 2024-01-02 差 3 天；2023-01-01 到 2025-01-01 跨一个平年一个闰年，365+366=731，与样例一致。

参考代码

#include <bits/stdc++.h>
using namespace std;
static bool leap(int y) { return (y % 4 == 0 && y % 100 != 0) || y % 400 == 0; }
static long long idx(int y, int m, int d) {
    static const int md[] = {0,31,28,31,30,31,30,31,31,30,31,30,31};
    long long r = d - 1;

完整思路（点开看推导）

单价排序是大包 < 中包 < 单买，所以最优解里大包尽量多，唯一不确定的是「余数怎么处理」。于是枚举大包个数 a（0..n/50），剩余 r = n − 50a < 50；再枚举中包个数 b（0..r/10），余下 r − 10b 枚单买，花费 a·130 + b·28 + (r−10b)·3，取最小。


因为 r < 50，b 最多 5 个取值，总枚举量约 (n/50)×5，n=1e5 时只有一万次。这个「枚举一维、其余直接算」的套路在小范围贪心里很常用：把不确定的部分摊开枚举，就不必证明贪心。

G · 共鸣圣歌

题意


题目描述
纺都的歌声正在哀鸣，这个被丝线与信仰统治的王国，正等待着一位真正的英雄。为了打破施加于此地的诅咒，解放整个纺都，我们勇敢的大黄蜂姐姐必须完成一项艰巨的使命：从雄伟的圣堡出发，一路向上攀登，最终抵达那云端的摇篮圣所。

个叫做“共鸣点”的东西。 每个共鸣点 i
都有一个坐标 p_i
和一份基础的灵丝 s_i。
大黄蜂姐姐需要选择 一个 共鸣点 j 站着不动，然后她会同时从
所有 的 N
个点（包括她脚下的点）吸取灵丝。
从一个点 i
能吸取到的灵丝，会因为距离而减少，公式是：
汲取灵丝 = max(0, s_i - |p_i - p_j|)
也就是说，如果点 i 离她站的点
j 太远，远到距离 |p_i - p_j| 超过了点 i 本身的基础灵丝 s_i，那就一点灵丝都吸不到啦。
我们在点 j
停留，能收集到的总灵丝就是把从所有 N

提示
这个区域有3个共鸣点。让我们逐一计算将每个点作为停留点时的情况：
- 停留在点 1 (坐标 10, 灵丝量 20):
- 从点 1 汲取: (0, 20 - |10 - 10|) = 20
- 从点 2 汲取: (0, 5 - |20 - 10|) = max(0, 5 - 10) = 0
- 从点 3 汲取: (0, 12 - |22 - 10|) = max(0, 12 - 12) = 0

- 停留在点 2 (坐标

- 从点 1 汲取: (0, 20 - |10 - 20|) = max(0, 20 - 10) = 10
- 从点 2 汲取: (0, 5 - |20 - 20|) = 5
- 从点 3 汲取: (0, 12 - |22 - 20|) = max(0, 12 - 2) = 10

- 停留在点 3 (坐标

- 从点 1 汲取: (0, 20 - |10 - 22|) = max(0, 20 - 12) = 8

先想一想
  • 固定 j 之后，每个点 i 的贡献只和自己有关，互不影响。
  • 所以把 j 从 1 枚举到 N，每次算一遍总和即可。
  • 贡献可能为 0，不能算成负数。


完整思路（点开看推导）

这题没有隐藏结构：N ≤ 1000，直接 O(N²) 枚举答案点。对每个 j，内层遍历所有 i，算 d = |pᵢ − pⱼ|；若 d ≥ sᵢ 则贡献为 0（对应 max(0, …)），否则贡献 sᵢ − d，累加后与当前最优比较。


为什么不用更聪明的办法：坐标和 s 都到 1e5，理论上能用前缀和做 O(N log N)，但 N 只有 1000，O(N²)=1e6 完全够，没必要给自己加戏。




参考代码
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n; scanf("%d", &n);
    vector<int> p(n), s(n);
    for (int i = 0; i < n; ++i) scanf("%d %d", &p[i], &s[i]);
    long long best = 0;
    for (int j = 0; j < n; ++j) {
        long long sum = 0;
        for (int i = 0; i < n; ++i) {
            int d = abs(p[i] - p[j]);
            if (d < s[i]) sum += s[i] - d;
        }
        best = max(best, sum);
    }
    printf("%lld\n", best);
    return 0;
}


代码逐段看
  • 外层枚举停留点 j，内层累加所有 i。
  • 距离用 abs(p[i]-p[j])。
  • 先判 d < s[i] 再加，天然实现截断为 0。


复杂度：O(N²)
坑点：s 可能小于距离，必须截断到 0；答案用 long long 更稳。

完整思路（点开看推导）

先抽象：一个串 = 首字母 A + 中间 C + 末尾（A/B/C 之一）。把三个位置看成三个角色，每种实体字母能担任的角色是固定的：A→{首,末}，B→{末}，C→{中,末}，X→{首,末}，Y→{首,中,末}，Z→{中,末}。


给定 k，判断能否拼出 k 个串 = 能否把字母分给三个角色、每个角色恰好 k 个（同一字母不能身兼两职）。这是标准二分图匹配：左边 6 种字母（容量 = 个数），右边 3 个角色（容量 = k），按「能否担任」连边，源点连字母、角色连汇点，跑最大流看是否达到 3k。


可行性关于 k 单调（k 可行则 k−1 一定可行：拆掉任意一个串即可），所以二分 k ∈ [0, (a+b+c+x+y+z)/3]，每次跑一个只有 11 个点的小网络。




参考代码
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

struct Dinic {
    struct E { int to, rev; ll cap; };
    vector<vector<E>> g;
    vector<int> lv, it;
    Dinic(int n) : g(n), lv(n), it(n) {}
    void add(int u, int v, ll c) {
        g[u].push_back({v, (int)g[v].size(), c});
        g[v].push_back({u, (int)g[u].size() - 1, 0});
    }
    bool bfs(int s, int t) {
        fill(lv.begin(), lv.end(), -1);
        queue<int> q; lv[s] = 0; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (auto &e : g[u]) if (e.cap > 0 && lv[e.to] < 0) { lv[e.to] = lv[u] + 1; q.push(e.to); }
        }
        return lv[t] >= 0;
    }
    ll dfs(int u, int t, ll f) {
        if (u == t) return f;
        for (int &i = it[u]; i < (int)g[u].size(); ++i) {
            E &e = g[u][i];
            if (e.cap > 0 && lv[e.to] == lv[u] + 1) {
                ll d = dfs(e.to, t, min(f, e.cap));
                if (d > 0) { e.cap -= d; g[e.to][e.rev].cap += d; return d; }
            }
        }
        return 0;
    }
    ll maxflow(int s, int t) {
        ll f = 0;
        while (bfs(s, t)) { fill(it.begin(), it.end(), 0); while (ll d = dfs(s, t, LLONG_MAX)) f += d; }
        return f;
    }
};

int main() {
    int t; scanf("%d", &t);
    while (t--) {
        ll a, b, c, x, y, z;
        scanf("%lld %lld %lld %lld %lld %lld", &a, &b, &c, &x, &y, &z);
        // 角色：0 = 首字母 A；1 = 中间 C；2 = 末尾任意
        // 字母：A B C X Y Z
        ll cnt[6] = {a, b, c, x, y, z};
        bool ok[6][3] = {
            {1, 0, 1},  // A: A 首 / 任意
            {0, 0, 1},  // B: 任意
            {0, 1, 1},  // C: C 中 / 任意
            {1, 0, 1},  // X: A 首 / 任意
            {1, 1, 1},  // Y: A 首 / C 中 / 任意
            {0, 1, 1}   // Z: C 中 / 任意
        };
        auto feasible = [&](ll k) -> bool {
            if (k == 0) return true;
            int S = 9, T = 10;
            Dinic din(11);
            for (int i = 0; i < 6; ++i) din.add(S, i, cnt[i]);
            for (int i = 0; i < 6; ++i)
                for (int r = 0; r < 3; ++r)
                    if (ok[i][r]) din.add(i, 6 + r, LLONG_MAX / 4);
            for (int r = 0; r < 3; ++r) din.add(6 + r, T, k);
            return din.maxflow(S, T) == 3 * k;
        };
        ll lo = 0, hi = (a + b + c + x + y + z) / 3, ans = 0;
        while (lo <= hi) {
            ll mid = (lo + hi) / 2;
            if (feasible(mid)) { ans = mid; lo = mid + 1; } else hi = mid - 1;
        }
        printf("%lld\n", ans);
    }
    return 0;
}


代码逐段看
  • 角色编号 0=首(A)、1=中(C)、2=末(任意)，ok[6][3] 表写死谁能当什么。
  • 建图：S→字母容量 cnt，字母→角色容量 INF，角色→T 容量 k。
  • 判据 maxflow == 3*k。
  • 容量用 long long：字母数到 1e9，3k 也到 3e9。


复杂度：O(log(Σ/3) · 最大流)，图仅 11 点

题目描述

- 首先，计算指定分段内所有分数的精确乘积。这个结果会是一个最终的总分数，记为
P/Q。
- 然后，将这个总分数 P/Q

1 ≤ p_i, q_i ≤ 10^10（所有的 q_i 均不为

先想一想
  • 模意义下「除以 q」等于「乘以 q 的逆元」。
  • 区间乘积可以前缀积相除：ans = pre[r] × pre[l−1]⁻¹。
  • M 是质数，逆元用费马小定理 a^(M−2) 快速幂。


完整思路（点开看推导）

把每个分数先化成模意义下的整数：vᵢ = pᵢ · qᵢ^(M−2) mod M；再做前缀积 pre[i] = pre[i−1]·vᵢ。区间 [l,r] 的乘积 = pre[r]·pre[l−1]⁻¹。


为什么能这样「除」：模数为质数时非零元素构成乘法群，每个元素有唯一逆元，所以分数运算在模意义下完全合法（题目保证 qᵢ 不是 M 的倍数）。


每次询问做一次快速幂，约 30 次乘法；n、m 在 2×10^5 量级也只有几百万次运算旋。




参考代码
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const ll MOD = 998244353;
ll qpow(ll a, ll b) { ll r = 1; a %= MOD; while (b) { if (b & 1) r = r * a % MOD; a = a * a % MOD; b >>= 1; } return r; }
int main() {
    int n; scanf("%d", &n);
    vector<ll> pre(n + 1, 1);
    for (int i = 1; i <= n; ++i) {
        ll p, q; scanf("%lld %lld", &p, &q);
        pre[i] = pre[i - 1] * (p % MOD) % MOD * qpow(q % MOD, MOD - 2) % MOD;
    }
    int m; scanf("%d", &m);
    while (m--) {
        int l, r; scanf("%d %d", &l, &r);
        ll ans = pre[r] * qpow(pre[l - 1], MOD - 2) % MOD;
        printf("%lld\n", ans);
    }
    return 0;
}


代码逐段看
  • 边读边算前缀积，省一个数组。
  • qpow(q, MOD-2) 求逆元，先对 q 取模。
  • 询问 pre[r] * qpow(pre[l-1], MOD-2) % MOD。


复杂度：O((n+m) log M)
坑点：q 先 %MOD 再求逆；l=1 时 pre[0]=1，不用特判。

- 咒语会将魔导书魔法般地分成均等的两半：包含第 1 到 N/2

芙莉莲认为这是一个教导的好机会，便将这个挑战交给了费伦。你能帮助费伦找到答案吗？
输入格式
输入文件中有三个用空格间隔的整数，分别表示 N,M,L。
（其中 1≤ N≤ 10^10,0 ≤ M≤ 10^10，且 N
为偶数）。
输出格式
输出一个整数，代表经过 M 次织法后，位于第 L

样例输入

样例输出

先想一想
  • 先看 N=6 时一次洗牌：4 1 5 2 6 3，把「新位置→原页码」列成表。
  • 盯 1→4、2→1、3→5、4→2、5→6、6→3，像不像「乘某个数再取模」？
  • 试模数 N+1=7：1×4=4、2×4=8≡1、3×4=12≡5 …… 全对上。
  • 4 正是 2 在模 7 下的逆元，所以 M 次就是乘 (2⁻¹)^M。


完整思路（点开看推导）

把一次洗牌看成置换 s：s(x) = x/2（x 偶），s(x) = N/2 + (x+1)/2（x 奇）。N=6 时算出 s = [4,1,5,2,6,3]，恰好等于 x×4 mod 7；而 4 是 2 关于模 7 的逆元。这个结论对任意偶数 N 成立：s(x) ≡ x·2⁻¹ (mod N+1)。


于是 M 次洗牌后第 L 个位置的原页码 = L·(2⁻¹)^M mod (N+1)。2⁻¹ = (N+2)/2（因为 2·(N+2)/2 = N+2 ≡ 1），用快速幂求它的 M 次方再乘 L。


为什么是 N+1 而不是 N：洗牌把「前半的第 k 个」和「后半的第 k 个」交错，位置与页码之间的对应天然带一个「第 0 位 = 第 N 位」的环绕，模 N+1 正好把这个环绕表达出来。




参考代码
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
typedef __int128 lll;

int main() {
    ll N, M, L;
    scanf("%lld %lld %lld", &N, &M, &L);
    ll mod = N + 1;                    // s(x) = x * inv2 (mod N+1)
    ll inv2 = (N + 2) / 2;             // 2 * inv2 ≡ 1 (mod N+1)
    auto mul = [&](ll a, ll b) { return (ll)((lll)a * b % mod); };
    ll pw = 1, base = inv2 % mod, e = M;
    while (e) { if (e & 1) pw = mul(pw, base); base = mul(base, base); e >>= 1; }
    ll ans = mul(L % mod, pw);
    if (ans == 0) ans = mod;
    printf("%lld\n", ans);
    return 0;
}


代码逐段看
  • 模数取 N+1，底数 inv2 = (N+2)/2。
  • N 到 1e10，模乘用 __int128 防溢出。
  • 对 M 做二进制拆分，O(log M)。


复杂度：O(log M)
坑点：模乘必须防溢出；M=0 时答案是 L；L 也要先对 N+1 取模。

题意


题目描述

- 当你从一个点连到另一个点时，如果这两个点的连线段上经过了其他点，那么这些点必须已经在之前的路径中被选中过，否则这条连线是不合法的。
（例如，在 3 \times 3
九宫格中，如果要从左上角 (1,1)
连到右上角 (1,3)，必须先经过中间点
(1,2)；若 (1,2) 尚未选过，则不能直接连 (1,1) → (1,3)。）
现在，小 a 把这个问题推广到 n × m
的点阵，并想知道：一共有多少种不同的密码？
定义：
一个密码就是点阵上的一条合法路径。
与正常手机系统不同，本题路径长度至少为 1 而不是至少为 4（即单个点也算密码）。
两个密码不同，当且仅当：它们的长度不同，或它们在某个位置所选择的点不同。
输入格式
一行包含两个正整数表示点阵大小。
输出格式
输出一个整数，表示不同密码的总数。
提示
样例说明：
当点阵是 1 \times 3（点依次为 A, B, C）时，所有合法的密码路径如下：
- 长度为 1 的路径（任选一个点）：
A, \; B, \; C —— 共 3 种。
- 长度为 2 的路径：
- 相邻点之间：
A \to B, \; B \to A, \; B \to C, \; C \to
B —— 共 4 种。
- 注意 A \to C
直接相连是不允许的，因为中间的点 B
没有被经过。
- 长度为 3 的路径：
- A \to B \to C, \; C \to B \to A ——
从一端到另一端依次经过。
- B \to A \to C, \; B \to C \to A ——
先访问中间点 B，此时再连 A \to C 或 C \to
A 就合法了（因为中点 B
已经访问过）。 —— 共 4 种。
因此总数为 3 + 4 + 4 = 11

对于所有数据，保证：n, m \ge 1， n \le 3, m
\le 3


样例输入

样例输出

先想一想
  • 点数最多 9，总路径数百万级，可以直接搜索。
  • 判断「A 到 B 中间有没有格点」：取 Δx、Δy 的 gcd，g=1 说明相邻无阻挡，否则中间有 g−1 个点。
  • 那些中间点必须都已在当前路径里，才允许跨过去。


完整思路（点开看推导）

这就是手机九宫格解锁的计数问题，规模只有 3×3，标准做法是 DFS 枚举所有简单路径。状态用 vis[9] 记录踩过的点，每进入一个点就把答案 +1（长度 1 的路径也算）；扩展时枚举未访问的 nx，检查从 cur 到 nx 是否合法：令 g = gcd(|Δx|,|Δy|)，g=1 直接可连；g>1 说明中间有 g−1 个等分格点，必须全部已访问。


注意判定只看中间点「是否已访问」，不看它是怎么被访问的 ——所以 1×3 里 A→B→C 与 B→A→C 都合法，总数是 11 而不是 9。


复杂度是「走法数 × 9」，3×3 也就百万级，跑得飞快。




参考代码
#include <bits/stdc++.h>
using namespace std;
int n, m, N;
long long ans = 0;
int vis[9];

int g(int x) { return x < 0 ? -x : x; }

bool between_ok(int a, int b) {              // a→b 中间的点是否都已访问
    int ax = a / m, ay = a % m, bx = b / m, by = b % m;
    int dx = bx - ax, dy = by - ay;
    int gg = __gcd(g(dx), g(dy));
    if (gg <= 1) return true;                // 相邻，中间无点
    int sx = dx / gg, sy = dy / gg;
    for (int k = 1; k < gg; ++k) {
        int x = ax + sx * k, y = ay + sy * k;
        if (!vis[x * m + y]) return false;
    }
    return true;
}

void dfs(int cur, int cnt) {
    ans += 1;                                 // 当前路径本身算一条
    if (cnt == N) return;
    for (int nx = 0; nx < N; ++nx) {
        if (vis[nx]) continue;
        if (!between_ok(cur, nx)) continue;
        vis[nx] = 1;
        dfs(nx, cnt + 1);
        vis[nx] = 0;
    }
}

int main() {
    scanf("%d %d", &n, &m);
    N = n * m;
    for (int s = 0; s < N; ++s) {
        vis[s] = 1;
        dfs(s, 1);
        vis[s] = 0;
    }
    printf("%lld\n", ans);
    return 0;
}


代码逐段看
  • 点编号成 x*m+y，用一维 vis。
  • between_ok(a,b) 里用 gcd 求步数，逐个检查中间点。
  • dfs 一进来先 ans++，因为当前前缀本身就是一条密码。
  • 回溯记得把 vis[nx] 清 0。


复杂度：O(路径数 × 点数)，3×3 约 1e6 内
坑点：单点也算密码；跨点判定是「中间点已访问」；答案用 long long。
