🚫 三个必须戒掉的坏习惯
  • 看题解 = 抄代码。看懂和写出来之间隔着一道鸿沟。正确做法：看懂 → 关掉题解 → 自己写 → 写不出来再看 → 立刻关掉再写第二遍。
  • 只做会做的题。一直做会做的题 = 一直不进步。健康的比例是：70% 需要想 10~30 分钟的题 + 20% 需要看题解的题 + 10% 巩固题。
  • 不写对拍。「样例过了」不等于「对了」。第 1 章会专门讲怎么用随机数据 + 暴力程序验证自己的解法。

做题前先做这件事：估复杂度

🎯 经验法则

C++ 在 1 秒内大约能做 10⁸ 次简单运算。所以「n ≤ 10⁶ 的两重循环」= 10¹² 次 = 必然超时，看到就要立刻放弃这个方向。

1基本功：先把「工具」磨利▾

这一章不教算法，教的是做算法题的肌肉记忆。很多人卡在入门，不是因为算法难，而是因为：不会估复杂度、不会调试、不知道自己在写什么。先把这五件事做完。

1. 复杂度分析：一分钟算出「能不能过」

入门★必会补充

本质：不数具体指令，只数「循环嵌套了几层、每层跟谁有关」。外层和与 n 有关的量相乘，就是把复杂度写在纸上。

计数规则：循环 for(i=0;i<n;i++) 是 O(n)；两重独立循环相加仍是 O(n)，两重嵌套相乘变 O(n²)；循环每轮把区间减半就是 O(log n)；外层 n 层、内层 log n 就是 O(n log n)。常量全部丢掉，只留最高阶。

代码形状复杂度典型代表
for(...) {...}O(n)前缀和、线性筛、双指针
for(...) for(...) {...}O(n²)朴素 DP、Floyd、冒泡排序
while(n > 1) n /= 2;O(log n)二分、快速幂、倍增
sort(a, a+n);O(n log n)排序、线段树、Dijkstra
for(...) while(...) p /= 2;O(n log n)KMP、树状数组
3 层 for(...)O(n³)区间 DP、高斯消元、矩阵乘法
例题：洛谷 P1045 麦森数要求算 2ᵖ−1 的位数，p ≤ 3.1×10⁶。位数 = ⌊p·log₁₀2⌋ + 1，一行公式 O(1) 解决；但要求输出「最后 500 位」，就得老老实实高精度做 O(p) 次乘法。这题的价值在于：同一道题里，「要位数」和「要末 500 位」的复杂度可以完全不同。

常见错误：把 O(log n) 写成 O(√n)（试除法求单个数质因数是 O(√n)，反复二分才是 O(log n)）；忘记 sort 也占时间。

题单洛谷 P1045 麦森数 · P3383「模板」线性筛素数（体会 O(√n) 与 O(n) 的差别）· P1226「模板」快速幂。

2. 竞赛代码脚手架：快读、快写与常用宏

入门★效率补充

本质：把「每次都写一遍」的东西固化成自己的模板，比赛时直接在编辑器里 Tab 出来。省下的不是几秒钟，而是打断思路的次数。模板的第一行就是 #include，所以「引哪些头文件」是你每天都要做的一个决定。

🚫 第一件事：不要用 <bits/stdc++.h>（万能头）

很多竞赛模板第一行是 #include <bits/stdc++.h>，看起来「一行顶所有」，但它有三个实打实的问题：

  • 它不是 C++ 标准的一部分。这是 GCC 私有的实现细节。换到 MSVC、部分 clang 严格模式、某些评测机或真实工程里，直接编译不过——你的代码就废了。
  • 把整个标准库展开，编译变慢。小代码里差几百毫秒无所谓，但递归式地写下去，你会习惯「反正都能用」，永远不知道自己用了什么。
  • 你学不到「哪个功能在哪个头文件里」。而面试、笔试、看别人代码、改工程时，这个知识是硬需求。早期养成按需 include 的习惯，成本最低。

💡 记不住怎么办

不用背。写代码时把用到的函数列出来，再去 cppreference 或编辑器补全里确认它在哪个头文件，写两三次自然就记住了。
本文所有代码块都在首行标出了「依赖头文件」，可以直接照抄。

⚠️ 什么时候才需要快读

cin 在默认状态下会和 stdio 同步，读 10⁶ 个数大约要 0.5~1 秒。解决办法有两个：
① 加一行 ios::sync_with_stdio(false); cin.tie(0);（放在 main 开头，注意之后不能混用 printf）
② 手写快读（上面那段），比 cin 快 3~5 倍。
除此之外的场景，老老实实用 cin 更不容易写错。

💡 变量命名与边界预防

mx/mn 之类宏名容易和变量撞车，建议用 mxv；数组一律多开 5 个；用 ll 而不是 long long；看到「求和」「乘积」先想会不会爆 int（2×10⁹ 就爆了）。

🔎 第一次见到这些输入输出函数
cin >> x ｜ cout << x
作用：从标准输入读一个值 / 往标准输出写一个值。
返回值：返回流对象本身（cin / cout 的引用），所以可以连着写 cin >> a >> b >> c;。
关键性质：读取失败时流会进入 fail 状态，此时把 cin 当条件用会得到 false —— 多组数据输入就是靠这个：while(cin >> n){ ... }，读到文件末尾自动停下。
复杂度：单个值的读写都可以当作 O(1)。
ios::sync_with_stdio(false);
作用：关闭 C 标准流（printf/scanf）与 C++ 流（cin/cout）之间的同步。默认是开的，所以 cin 每次都要先和 stdio 对齐，慢。
效果：cin 提速约 2~5 倍。
放在哪：main 函数的第一行。
代价：调用之后不能再混用 printf/scanf，否则输出顺序会乱。
cin.tie(0);
作用：解除 cin 与 cout 的绑定。默认情况下每次 cin 之前都会自动把 cout 刷新一次（为了让「先输出的提示语」能及时出现），这个自动刷新很费时间。
参数：0 就是空指针，等价于 cin.tie(nullptr);。
注意：交互题不要关——关了之后你写到 cout 的内容可能不立刻发出去，导致对方一直在等。
endl　vs　"\n"
endl = 换行 + 强制刷新缓冲区（flush）。
"\n" = 只换行。
结论：只要换行就用 "\n"。输出 10⁶ 行时，endl 的强制刷新会让程序慢好几倍，是 TLE 的常见原因之一。
小技巧：cout << a[i] << " \n"[i == n]; 可以在行末自动换成换行符，避免多输出一个空格。
printf / scanf
作用：C 风格的格式化输入输出，在 <cstdio> 里。
为什么还要学：格式化输出（保留几位小数、按宽度对齐）比 cout 简洁。
格式符：%d int、%lld long long、%u unsigned、%c 字符、%s 字符串、%.2f 两位小数、%5d 宽度 5 右对齐。
经典坑：用 %d 输出 long long 是未定义行为，结果会莫名其妙。
getchar() / putchar(c)
作用：读 / 写一个字符，速度极快，是手写快读快写的基石。
返回值：getchar 返回 int（不是 char！）——因为要在 0~255 之外再表示一个 EOF（通常是 −1）。用 char 接会导致 EOF 判断失效。
putchar 返回写入的字符（int）。
复杂度：O(1)。

3. 对拍：用随机数据证明自己是对的

入门★★调试神器补充

本质：写一个「肯定对但很慢」的暴力程序，再写一个随机数据生成器，让两者在同一份数据上跑，输出不一致就说明正解错了。这是竞赛里唯一可靠的调试手段。

对拍三件套：① gen 数据生成器；② brute 暴力（枚举/搜索，慢但一定对）；③ std 你的正解。循环比较两者输出，不同就停下并把数据存下来。

🎯 生成器的三个关键技巧

① 先小后大：从 n ≤ 8 开始，边界错误（空、n=1、全负数、全相等）几乎一定在小数据里出现。
② 构造特殊数据：全相同、严格递增、严格递减、只有 0、最大值贴着数据范围上限。
③ 数据范围卡边：如果题目说 a ≤ 10⁹，随机数就要包含 10⁹ 和 −10⁹。

⚠️ 对拍的三个前提

① 暴力必须真的对（可以先用题目样例验证暴力）；
② 两边读入格式必须完全一致（多一个空格都会导致假报错）；
③ 时间限制内跑不动就不叫对拍——暴力请写 O(n²) 甚至 O(n³)，别去优化它。

🔎 第一次见到这些随机数 / 计时函数
srand(unsigned seed)
作用：给 rand() 设置随机种子。
为什么必须有：rand() 是伪随机——不设种子时，程序每次运行产生的序列完全一样。对拍时如果数据每次相同，就永远试不出新情况。
参数：无返回值。
time(0)
作用：返回当前 Unix 时间戳（从 1970-01-01 起的秒数），类型 time_t，在 <ctime> 里。
参数：传 0 表示「只要返回值，不要写回指针」。
注意：粒度是秒，同一秒内启动两次种子相同 —— 所以常见写法是 srand(time(0) ^ clock()) 把毫秒级的时间差也揉进去。
clock()
作用：返回程序启动至今消耗的 CPU 时间（单位 CLOCKS_PER_SEC，Windows 上一般是 1000，即毫秒）。
典型用法：测一段代码的耗时 —— double t = (double)clock() / CLOCKS_PER_SEC;。
和 time(0) 的区别：clock() 只算 CPU 占用的时间，time(0) 是墙上时钟。
rand()
作用：返回一个 [0, RAND_MAX] 之间的伪随机整数。
关键坑：RAND_MAX 在 Windows 上只有 32767（Linux 上是 2³¹−1）。所以在 Windows 本地测试时 rand() 根本出不了大数 —— 想生成 10⁶ 级的数必须手动拼：rand() * rand() 或 (rand() << 15) ^ rand()。
第二个坑：rand() % n 分布不均匀（除非 n 整除 RAND_MAX+1）。正式场合用 <random> 的 mt19937。
sleep / 等待技巧
注意：C++ 标准里没有可移植的 sleep。竞赛里需要等待时，一般用一个空循环或 <thread> 的 this_thread::sleep_for（C++11，需要 <thread> 和 <chrono>）。对拍脚本里不需要它。

题单找任意一道你有把握的题，把「暴力 + 正解 + 生成器」三份代码都写一遍，跑 1 分钟对拍。

4. 常见错误字典：看到结果就知道错在哪

入门★★排查补充

本质：把「玄学错误」变成「查表」。评测机给的结果只有几种，每一种背后的原因都非常固定。

结果含义最先检查这四件事
CE编译错误① 头文件漏了；② 分号 / 括号不配对；③ 变量名拼错；④ 用了本地能过但 OJ 版本不支持的东西
RE运行时错误① 数组越界（最常见）；② 除数为 0；③ 递归太深爆栈；④ 空 vector 取下标
WA答案错误① 边界没特判（n=1、n=0）；② 爆 int；③ 多组数据没清空；④ 输出格式（空格 / 换行 / 大小写）
TLE超时① 复杂度算错；② 死循环；③ cin/cout 太慢；④ 用了 O(n²) 但 n=10⁵
MLE内存超限① 数组开太大（局部变量在栈上更容易爆）；② 递归栈太深；③ 没释放的容器
OLE / PE输出超限 / 格式错① 死循环在不停输出；② 行末多空格；③ 少输出 / 多输出一组
🚫 三个最贵的坑

① 爆 int。两个 10⁹ 相乘 = 10¹⁸，早就爆了。看到乘法、求和、阶乘，先问一句「会不会超 2×10⁹」。int × int 不会自动变成 long long，必须写 1LL * a * b。
② 数组开小了 1。下标从 1 开始却只开了 n 个。规则：从 1 开始 → 开 n+5。
③ 多组数据忘清空。第二组数据读到上一组的残留，答案莫名其妙。

🔎 第一次见到 memset 与「初始化」的坑
memset(指针, 值, 字节数)
作用：把一块内存的每一个字节都设成指定的值，在 <cstring> 里。返回第一个参数的指针。
核心理解：它按字节操作，不是按元素！所以
  • memset(dist, 0x3f, sizeof dist) —— 每个字节都设成 0x3f，一个 int 有 4 个字节，拼出来就是 0x3f3f3f3f = 1061109567（不是 63！）。
  • 它只能用来设 0、-1、0x3f 这类「每个字节都相同」的值。想全设成 1 是做不到的 —— 那样会得到 0x01010101。
  • 为什么不直接用 0x7fffffff 当 INF？因为它 + 任何正数都会溢出成负数。而 0x3f3f3f3f ≈ 1.06×10⁹，两个相加还不到 2.1×10⁹（int 上限），可以放心相加不会溢出。
sizeof dist
作用：求变量 / 类型占用的字节数。
关键点：sizeof(数组名) 得到的是整个数组的字节数，所以 memset(a, 0, sizeof a) 正好覆盖整块。
大坑：传入函数后数组会退化成指针，此时 sizeof 只剩 4 或 8 —— 所以 memset 只写在数组所在的作用域里，不要写进辅助函数。
fill(first, last, v)
作用：把区间 [first, last) 的每个元素都赋成 v，在 <algorithm> 里，O(n)。
比 memset 好在哪：按元素赋值，想初始化成 1、100、1e18 都可以，不会出现「按字节」的怪结果。
典型用法：fill(dp, dp + n + 1, -1e18);
全局变量自动清零
事实：开在函数外面的全局 / 静态数组，默认全部初始化为 0，不需要手动清。
开在 main 里的局部数组是随机值 —— 这既是 WA 的来源（忘记初始化），也是 RE 的来源（局部大数组会爆栈）。
结构体成员：struct Node { int a, b; }; 直接定义时也是随机值，写 Node x{}; 才会零初始化。

5. 离散化：把「很大的数」压成「很小的下标」

基础★★前置技能补充

本质：当数值很大（比如 10⁹）但个数很少（比如 10⁵）时，我们只关心它们的相对大小。把「排序去重后的排名」当作新下标，值域就从 10⁹ 变成 n。

三步：① 把所有值拷一份存起来；② sort + unique 去重；③ lower_bound 查排名，排名就是新下标。

✅ 实测

输入 [100, 3, 3, 55, 100, 3] → 排名 [3, 1, 1, 2, 3, 1]，映射表 {3→1, 55→2, 100→3}。原始值之间的「大小关系」被完整保留，这就是离散化能用的原因。

💡 离散化之后能干什么

值域从 10⁹ 降到 10⁵ 之后：树状数组 / 线段树就能用来统计「第 k 大」「比 x 小的有几个」；桶计数也能用了；二维坐标压缩后还能做扫描线求矩形面积并。

要注意：离散化会丢掉「值之间的距离」。如果题目关心「相差多少」（比如计数、求和），不能直接离散化，只能压缩下标。

🔎 第一次见到离散化用到的三个函数
sort(first, last)
作用：把区间 [first, last) 按 < 升序排序，在 <algorithm> 里。
参数：两个迭代器 / 指针，左闭右开 —— 对 vector<int> b 写 sort(b.begin(), b.end())，对数组 int a[n] 写 sort(a, a + n)（注意是 a+n 不是 a+n-1）。
返回值：无。复杂度：O(n log n)，不稳定（相等元素顺序不保证）。
unique(first, last)
作用：把区间里相邻的重复元素挪到后面去，返回「去重后新结尾」的迭代器，在 <algorithm> 里，O(n)。
最容易误解的一点：它不删除元素，也不改变容器长度，只是把不重复的挪到前面。所以必须配合 erase 才能真正缩短：
v.erase(unique(v.begin(), v.end()), v.end());
前提：区间必须已经有序，否则只能去掉「挨在一起的」重复项。返回值的含义：新逻辑结尾的迭代器。
lower_bound(first, last, x)
作用：在有序区间里找第一个 ≥ x 的元素位置，在 <algorithm> 里，二分实现，O(log n)。
返回：指向该元素的迭代器 / 指针；如果全区间都小于 x，返回 last。
怎么拿下标（0 开始）：int pos = lower_bound(b.begin(), b.end(), x) - b.begin();
怎么拿排名（1 开始）：后面 + 1。
前提：区间必须有序，否则结果是随机的 —— 忘了排序直接二分是最常见的错误之一。
v.erase(iterator) / v.erase(first, last)
作用：删除一个元素或一段区间，让后面的元素整体前移，返回被删区间之后的第一个位置。
复杂度：O(n)（因为要搬移元素）。
注意：删除元素会让后面的迭代器全部失效，不要在遍历中随手 erase。

这一章的共同点：它们不是「算法」，而是思维动作。后面所有复杂算法的代码，都是这些小动作的组合。这一章要练到看到题目就知道该用哪一个。

1. 枚举

入门★暴力

本质：把所有候选答案一个个试过去。难点从来不是「枚举」，而是枚举什么与如何压缩枚举量。

三个层次：① 枚举所有元素（O(n)）；② 枚举所有二元组（O(n²)）；③ 枚举所有子集（O(2ⁿ)，n ≤ 20）。压缩方向：换一个维度枚举（枚举答案而非方案）、用前缀和/哈希把验证降到 O(1)、加剪枝。

例题：洛谷 P1036 选数 —— 从 n 个数里选 k 个，问有多少种选法使和为质数。n ≤ 20，直接子集枚举 2²⁰ ≈ 10⁶ 种，再加个 O(√s) 的质数判定即可。看到 n ≤ 20 就该想到 2ⁿ 枚举。

2. 模拟

入门★实现

本质：把题目描述无损地直译成代码。它考察的是「把自然语言规则翻译成状态机」的能力，是「代码量失败」的主要来源。

3. 递归与记忆化

入门★★思维

本质：把规模为 n 的问题化为规模更小的同类问题。三要素：参数含义（函数在语义上代表什么）、边界条件、递推关系。递归是 DP、分治、搜索、树形结构的共同语言。

💡 递归为什么必须配记忆化

fib(40) 朴素递归要调用约 3.3×10⁸ 次；加记忆化后每个 n 只算一次，只有 40 次。同一段递归，一个超时一个秒过，差别只在于「有没有把算过的答案存下来」。

🚫 递归的两个坑

① 忘记写边界。递归会一直往下钻到栈溢出（RE）。
② 递归太深。深度超过 10⁵ 层就会爆栈。解决办法：改写成迭代 / 显式栈，或者提高编译栈空间（-Wl,--stack=268435456）。

4. 前缀和与差分

基础★★★高频必考

本质：前缀和把「区间求和」变成「两次单点查询」；差分把「区间修改」变成「两次单点修改」。二者互为逆运算，是离线区间操作的第一把钥匙。

🎯 判断「该用前缀和还是差分」

修改少、查询多 → 前缀和（一次预处理，之后查询 O(1)）
修改多、查询少（或只在最后查一次）→ 差分（修改 O(1)，最后统一还原）
看到「若干次区间加，最后输出每个位置的值」——这几乎是差分的标准信号。

例题：数组 [1,2,3,4,5]，依次执行「[1,3] 各 +2」「[2,5] 各 −1」，求最终数组与最小值。
差分写法：d[1]+=2, d[4]-=2; d[2]-=1, d[6]+=1，前缀还原后得到 [3, 3, 4, 3, 4]，最小值 3（已用独立实现跑过）。若用暴力循环修改，每次 O(n)，区间多时直接超时。

5. 双指针 / 尺取法

基础★★★高频必考

本质：当「区间的可行性关于包含关系单调」时（右端点右移只会让左端点单调右移），两个指针总共只走 O(n) 步，把暴力的 O(n²) 降到 O(n)。

⚠️ 最大的误用：没验证单调性

双指针成立的前提是「区间变大后不会又变合法」。
反例：数组含负数时求「和为 S 的区间」——窗口和变大了还能靠右移左端点减回来吗？不能，因为左边可能是负数。此时必须换成前缀和 + 哈希表。
写双指针前，先在心里证一遍单调性。

例题：洛谷 P1147 连续自然数和 —— 求把 M 拆成连续正整数之和的所有方案。M ≤ 2×10⁶，直接枚举起点 O(M²) 超时；用双指针，左右端点都只单调右移，O(M) 通过。

6. 排序与自定义比较

入门★工具

本质：sort 本身没什么好讲的，真正要掌握的是「比较函数的语义要严格」——不满足严格弱序的比较函数会让 sort 直接崩溃（RE）。

🚫 比较函数的死亡写法 
bool cmp(int x, int y){ return x >= y; }   // ❌ 相等时返回 true，违反严格弱序 → RE

规则：相等时必须返回 false。写成 x > y 而不是 x >= y；写结构体排序时，把「层层比较」写成 if 串，最后一行一定返回 false 的等价形式。

✅ 实测：稳定排序 vs 不稳定排序

对 [(1,5),(2,5),(3,4)] 按分数降序：stable_sort 一定输出 [(1,5),(2,5),(3,4)]；sort 在小数组上通常也一样，但不保证。凡是题目说「相同分数按输入顺序输出」——必须用 stable_sort 或者把原始下标写进比较函数。

🔎 排序家族：sort / stable_sort / nth_element
sort(first, last) ｜ sort(first, last, cmp)
作用：区间升序 / 按 cmp 排序。复杂度：O(n log n)（内省排序：快排 + 堆排 + 插入排序的混合）。不稳定。
cmp 的语义：cmp(a, b) 返回 true 表示 a 应该排在 b 前面。所以降序写 [](int a, int b){ return a > b; }。
硬性要求：cmp 必须满足严格弱序 —— 也就是 cmp(x, x) 必须返回 false。写成 >= 或 <= 会让排序内部越界，直接 RE。
greater<int>() / less<int>()
作用：标准库提供的比较器函数对象，在 <functional> 里。greater 表示「大的在前」（降序），less 表示「小的在前」（升序，也是默认）。
用法：sort(v.begin(), v.end(), greater<int>());，比手写 lambda 短。
stable_sort(first, last, cmp)
作用：稳定排序 —— 排序后值相等的元素保持原来的相对顺序。
什么时候必须用：题目说「分数相同时按输入顺序输出」。
替代方案：用 sort，但在比较函数里加上「以原始下标为第二关键字」，效果一样而且更可控。
复杂度：有额外空间时 O(n log n)，空间不够时退化为 O(n log²n)。
nth_element(first, nth, last)
作用：执行完保证 *nth 这个位置放的就是「排序后应该在这里的元素」，且它左边都不大于它、右边都不小于它。
返回值：无。复杂度：平均 O(n)。
典型场景：求第 k 小（或中位数）时，比完整排序快。注意它不保证两侧有序。
自定义比较的两种写法
① lambda：sort(v.begin(), v.end(), [](const T &a, const T &b){ ... }); —— 临时用一次时最方便。
② 结构体重载 operator<：bool operator<(const Node &o) const { ... } —— 排序逻辑固定时更清晰，而且 sort、set、priority_queue 都能直接用。
建议：多关键字排序写成一串 if，最后一定要能返回「相等时为 false」。

7. 二分查找与二分答案

基础★★★必考

本质：把答案空间每次砍一半。二分查找要求在有序数组里找元素；二分答案要求「答案的判定函数具有单调性」（答案成立 → 更大的也成立）。二分答案才是竞赛的主战场。

🚫 二分最容易死在哪

① 死循环。「最大化」的模板必须用 mid = l + (r-l+1)/2（上取整）；「最小化」用 mid = l + (r-l)/2。用错了当 r = l+1 时会永远 l = mid = l。
② 边界开错。lo 取「一定可行」的值，hi 取「一定不可行」的值，宁可放宽一点。
③ 忘记排序。二分的前提是有序或单调，没排序直接二分 = 随机结果。

🔎 lower_bound 与 upper_bound 到底差在哪
lower_bound(first, last, x)
含义：第一个 ≥ x 的位置（lower = 下界，包含等于）。
返回：迭代器 / 指针，找不到返回 last。复杂度：O(log n)（比较次数 ≤ log₂n + 1）。
前提：区间必须按 < 有序。
upper_bound(first, last, x)
含义：第一个 > x 的位置（upper = 上界，跳过所有等于 x 的）。
返回：同上。复杂度：O(log n)。
x 的出现次数 = upper_bound(...) - lower_bound(...)
这是两个函数最经典的组合用法：
long long cnt = upper_bound(a, a+n, x) - lower_bound(a, a+n, x);
两者之差正好是「等于 x 的元素个数」，因为 [lower, upper) 就是所有 x 排成的区间。
注意指针相减的结果类型是 ptrdiff_t（有符号），可以放心用；但迭代器相减得到的是「元素个数」，不是字节数。
在「下降序列」上怎么用
默认版本假设升序。如果数组是降序的，要么先反转、要么传自定义比较器 greater<int>()：
lower_bound(a, a+n, x, greater<int>());
更省事的做法：把 「找最后一个 ≥ x」这类需求统一转成「在反转后的数组上找第一个」，思路更清楚。
set / map 的 lower_bound 是「成员函数」
重要区别：set<int> s; 要用 s.lower_bound(x)（成员函数，O(log n)）。
如果写成 lower_bound(s.begin(), s.end(), x)（全局算法），因为 set 的迭代器不支持随机访问，每次都只能一步一步挪，复杂度退化成 O(n) —— 这是很隐蔽的性能陷阱。

8. 三分法：在单峰函数上找极值

基础★★补充补充

本质：二分要求「单调」，三分要求「单峰」——函数先升后降（或先降后升）。取两个三等分点 m₁ < m₂，比较 f(m₁) 与 f(m₂) 就能砍掉三分之一区间。

✅ 实测

对 f(x) = −(x−3)² + 7 用三分法迭代 200 次，得到极值点 x ≈ 3.000000（解析解就是 3），与理论吻合。

⚠️ 三分的两个前提

① 函数在区间上有且只有一个峰（多峰会失败）；② 函数必须可微或至少是离散单峰。竞赛里三分常用于「距离平方和函数」「凸多边形内某点」「二分的对偶问题」。

9. 贪心

基础★★★思想

本质：每一步都取当前看起来最优的选择，并保证不后悔。难点不是写代码，而是证明这个贪心是对的。竞赛里最常用的证明工具是「交换论证」和「反悔贪心」。

两种证明套路：
① 交换论证：假设存在最优解和贪心解不同，找到第一个不同的位置，把它俩交换，证明结果不会变差 → 贪心解也是最优。
② 反悔贪心：先贪心拿，如果发现不划算，就用堆把之前的决定「撤销」掉。

例题：洛谷 P1090 合并果子 —— n 堆果子，每次合并两堆，代价为两堆之和，求最小总代价。贪心策略：每次合并当前最小的两堆。用小根堆实现 O(n log n)。n = 10⁴ 时暴力找最小值 O(n²) 也能过，n = 10⁵ 就必须用堆。
⚠️ 贪心不成立时怎么办

反例：货币找零 —— 面值 [1, 3, 4]，凑 6 元。贪心拿 4+1+1 = 3 枚，但最优是 3+3 = 2 枚。贪心失败 → 上 DP。做题时如果举不出反例又证不出正确性，先写贪心 + 对拍，1 分钟就能验证。

10. 简单搜索：DFS 与 BFS

基础★★★★必考

本质：穷举所有状态，区别只在探索顺序。DFS 用递归一路走到底再回头，能天然地做「枚举 + 回溯」；BFS 用队列一层层扩展，在边权都为 1 时第一次到达就是最短路。

DFS（深度优先）BFS（广度优先）
实现递归 / 显式栈队列
擅长枚举方案、回溯、连通块、树形遍历最短路（边权 1）、层序、拓扑
空间O(深度)O(最宽一层的宽度)
是否最优不保证保证（边权相同时）
💡 什么时候用 BFS 而不是 DFS

问题里出现「最少步数」「最短路径」「最少操作次数」——只要每一步的代价相同，就是 BFS 的信号。
反过来，出现「有多少种方案」「输出所有方案」「能不能凑出来」——考虑 DFS + 回溯。

🚫 搜索题的三个大坑

① BFS 入队时就标记，不要出队再标记，否则同一节点会被重复入队导致超时或死循环。
② DFS 的回溯要么都写、要么都别写。标记了忘记撤销 → 后续搜索被堵死。
③ 没有剪枝的 DFS = 指数级爆炸。n = 20 的暴力搜索通常需要剪枝才能过。

1. 栈与单调栈

入门★★必会

本质：栈是「后进先出」的容器。而单调栈是栈的一个用法——维护一个「从栈底到栈顶单调」的栈，用来求每个元素左边/右边第一个比它大（或小）的元素，一次 O(n) 扫完。

例题：洛谷 P5788「模板」单调栈 —— n ≤ 3×10⁶，输出每个数后面第一个大于它的数的下标。暴力 O(n²) 必超时；单调栈 O(n)，实测 3×10⁶ 规模在 1 秒内轻松通过。
💡 记住了这个「思维动作」你就赚了

单调栈之所以 O(n)，是因为用「永久排除法」：如果 a[j] ≤ a[i] 且 j < i，那么对 i 右边的元素来说，j 永远不可能成为答案（因为 i 更近且更大），所以可以放心弹掉。以后看到「找最近的大于/小于」就往这个方向想。

2. 队列、循环队列与双端队列

入门★工具补充

本质：队列是「先进先出」。deque（双端队列）两端都能进出，是「0-1 BFS」「单调队列」「滑动窗口」的基础容器。

✅ 0-1 BFS 为什么比 Dijkstra 好

Dijkstra 要堆，复杂度 O(m log n)；0-1 BFS 只要 deque，复杂度 O(n + m)。代价是它要求边权只能是 0 或 1。看到「边权非 0 即 1」立刻想到它。

🔎 queue 与 deque 的成员函数
queue<T>（<queue>）
push(x) / emplace(x)：把元素放到队尾，O(1)。
front()：取队首元素（不删除），O(1)。
pop()：删除队首元素，O(1)。注意它不返回值 —— 想「取出并删掉」要写 T x = q.front(); q.pop();，这是初学者最常踩的一个坑。
empty() / size()：判空 / 求元素个数。
越界行为：对空队列取 front 或 pop 是未定义行为，可能直接崩 —— 先判 empty 再取。
deque<T>（<deque>，double-ended queue）
push_back(x) / pop_back()：尾部进出，均摊 O(1)。
push_front(x) / pop_front()：头部进出，均摊 O(1)。
front() / back()：看两端元素（不删除）。
clear()：清空。
operator[]：支持随机访问（dq[2]），这是 queue 没有的。
复杂度：两端增删都是均摊 O(1)；中间插入删除是 O(n)。
什么时候用哪个
queue：只需要「队尾进、队首出」—— BFS、拓扑排序。
deque：两端都要操作 —— 单调队列、0-1 BFS。
vector：只在尾部操作、且需要频繁随机访问 —— 邻接表、普通数组。
竞赛里如果想省事，用 deque 或 vector 手动模拟 queue 也很常见（比 STL 快一些，而且能取任意位置）。
手写队列
写法：int que[N], head = 0, tail = 0; 区间约定为 [head, tail)。
que[tail++] = x; 入队，int u = que[head++]; 出队，head < tail 表示非空。
好处：比 STL 快；而且队里可以同时存多个数组（比如同时存点编号和距离）；BFS 里还能直接按层遍历（记录当前层的 tail）。

3. 单调队列：滑动窗口最值

基础★★★高频补充

本质：用一个双端队列维护「当前窗口内单调的候选集合」。队首是窗口最值；队尾插入新元素时把「比它没用的」弹掉；队首过期了就弹掉。每个元素最多进出各一次 → O(n)。

样例输入（洛谷 P1886）
8 3
1 3 -1 -3 5 3 6 7
样例输出（已独立跑过）
最小值：-1 -3 -3 -3 3 3
最大值： 3  3  5  5 6 7
🎯 从「滑动窗口最值」到「单调队列优化 DP」

单调队列真正的价值在于优化 DP 的转移。只要转移式长这样：
dp[i] = max{ dp[j] + w(i) } ，其中 j ∈ [i-k, i-1]
内层的「在长度为 k 的窗口里找最大值」就可以用单调队列压成 O(1)，整体从 O(nk) 降到 O(n)。这是提高组的高频考点。

4. 堆与优先队列（含对顶堆）

基础★★★必会补充

本质：堆能 O(1) 取最值、O(log n) 插入和删除。它解决的是「在动态变化的数据里反复取最大/最小」这类问题。

例题：洛谷 P1090 合并果子（Huffman）—— 每次取最小的两堆，小根堆 O(n log n)。洛谷 P1168 中位数 —— 用对顶堆，每次插入后 O(log n) 就能读出中位数。洛谷 P3378「模板」堆——入门第一道。
⚠️ priority_queue 的运算符方向最容易记反

priority_queue<T> 默认是大根堆，因为它内部用 less<T> 比较，「较小的」被判定为「优先级低」。所以自定义结构体时，想在堆顶放「值最大的」，就写 return x.val < y.val;。记忆口诀：堆顶永远是「不小于号指向的那一方」。

🔎 priority_queue 的模板参数与成员函数
priority_queue<T>
默认是什么：大根堆，也就是 top() 给出最大的元素。
三个模板参数（需要小根堆时必须写全）：
priority_queue<T, Container, Compare>
① T：元素类型，如 int、pair<int,int>。
② Container：底层容器，必须支持随机访问，默认 vector<T>，通常照抄 vector<T> 就行。
③ Compare：比较器，默认 less<T>。规则是「比较器认为较小的元素优先级低、沉在下面」，所以想小根堆就传 greater<T>（在 <functional> 里）。
top() / push() / pop() / empty() / size()
top()：看堆顶（最值），O(1)。
push(x)：插入并调整，O(log n)。
pop()：删除堆顶，O(log n)。和 queue 一样，它不返回值。
empty() / size()：判空 / 元素个数。
emplace(...)：用参数原地构造元素，比 push 少一次拷贝（C++11 起）。
没有的功能：不能遍历、不能删除任意元素、不能改堆里的值。需要这些就得换 set（O(log n) 但支持删除）或「懒删除」技巧。
pair 的比较规则
pair<A,B> 的 < 定义是：先比 first，first 相等再比 second。
所以 priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> 会按 first 从小到大出队 —— 这正是 Dijkstra 里「按距离出队」想要的效果，不用自己写比较函数。
greater<> 里的空尖括号是 C++14 起的「透明比较器」，编译器能自动推导类型，等价于 greater<pair<int,int>>。
重载 operator< 给自定义结构体
写法：在结构体外面（或里面）写全局的 bool operator<(const Node &a, const Node &b)。
方向提醒：priority_queue 用的是 less 语义，即「a < b 为真」表示 a 的优先级更低、要沉下去。所以想让「val 大的在堆顶」，就写 return a.val < b.val;。
口诀：堆顶永远是「小于号指向的那一方」。

6. 树状数组（BIT）

基础★★★★必背

本质：用一个数组维护前缀信息的可减组合（和、异或、最值不可减）。核心是那个 lowbit——它决定了「谁管谁」。单点修改 O(log n)，前缀查询 O(log n)，代码只有十几行。

✅ 实测

数组 [3,5,1,4,2,6,7,8]：sum(1..4) = 13、sum(3..7) = 20；把 a[4] 加 10 后 sum(4..4) = 14。三组结果与暴力累加完全一致。

⚠️ 树状数组支持不了什么

它只能维护可减的信息：和、异或、乘积（模质数时有逆元才能除）。
最值不可减（你没法用 [1,r] 的最大值减去 [1,l−1] 的最大值得到区间最大值）→ 区间最值要用 ST 表（无修改）或线段树（有修改）。

7. 线段树（含懒标记）

基础★★★★必背

本质：把区间建成一棵二叉树，每个节点维护一段区间的信息。修改和查询都递归到「被完整覆盖」的节点就停。懒标记让区间修改也是 O(log n)——把「要加的值」挂在节点上，等到需要往下走时再下发。

✅ 实测

数组 [1,5,4,2,3]：初始 sum(2..4) = 11；执行「区间 [2,3] 各加 2」后，sum(1..5) = 19，a[3] = 6。全部与暴力算法一致。

💡 线段树 vs 树状数组：怎么选

能用树状数组就用树状数组——代码短一半，常数小十倍，不容易写错。
必须用线段树的情形：① 要维护区间最值 + 区间修改；② 要维护的信息不可减（区间 gcd、区间最大子段和）；③ 要合并两个子区间的信息；④ 需要「线段树二分」（找第一个满足条件的位置）。

8. ST 表：O(1) 的静态区间最值

基础★★★必会补充

本质：倍增思想。预处理 st[j][i] = 从 i 开始、长度为 2ʲ 的区间的最值。回答 [l, r] 时，用两个长度为 2ᵏ 的区间拼起来覆盖它（允许重叠），因为最值「重复算不改变结果」，于是 O(1) 出答案。

✅ 实测

数组 [7,2,3,0,5,10,3]（下标 1~7）：min(1,5) = 0、min(2,7) = 0、min(4,4) = 0，与暴力逐个比较一致。

💡 为什么能重叠？

因为 min/max/gcd 这些运算满足幂等性（f(x,x) = x）。而区间求和不可幂等，重叠会重复计数，所以 ST 表不能求区间和。求区间和要用前缀和或树状数组。

10. 字符串哈希：把字符串变成一个数

基础★★★高频实用补充

本质：把字符串看成一个 B 进制的大整数，对模数取模。这样「判断两个子串是否相等」就变成「比较两个整数」，O(1) 完成——比 KMP 简单太多，能解决 KMP 解决不了的一大批问题。

✅ 实测

字符串 "abcabcabc"：hash[1,3] == hash[4,6] == hash[7,9] 全部相等（都对应 "abc"），而 hash[1,3] != hash[2,4]。哈希比较与直接做子串比较的结果完全一致。

⚠️ 哈希的两个坑

① 被卡。如果出题人知道你的底数 B 和模数，可以构造出「哈希相等但字符串不等」的碰撞数据。对策：用随机底数（B = rand()）或双哈希。
② 减法要处理负数。用有符号整数取模时，h[r] - h[l-1]*pw[...] 可能为负，要 (x % M + M) % M。用 unsigned long long 就不会有这个问题。

11. KMP 算法

基础★★★★必背

本质：当匹配失败时，不要回到开头重来，而是利用「已匹配部分的最长公共前后缀」跳到一个更靠后的位置继续。这个信息就是 next 数组（也叫前缀函数 π）。总复杂度 O(n + m)。

🎯 理解 next 数组的两个视角

视角一（匹配）：失配时该跳到哪里继续比。
视角二（结构）：nxt[i] 就是「前缀 p[1..i] 的最长公共前后缀长度」，所以 i − nxt[i] 就是这段前缀的最小循环节。
很多 KMP 题的答案就藏在视角二里——看到「循环」「周期」「重复」这些词，先算一遍 next。

🚫 KMP 的两个经典错误

① 失配时写成 k = 0。那就退化成暴力 O(nm)。必须是 k = nxt[k]，而且外面还要包一层 while（可能连跳多次）。
② 求 next 时忘记 nxt[1] = 0。下标要统一：本文用 1-indexed 的 next，代码里访问字符串用 p[i-1]，很容易少减一个 1。

12. set / map 与平衡树思想

入门★★★实用

本质：set/map 底层是红黑树（一种平衡二叉搜索树），所以查找、插入、删除都是 O(log n)，并且天然有序。它解决的是「需要动态维护有序集合 + 查前驱后继 / 排名」这类问题。

💡 set / map 的三个必用场景

① 维护「当前有哪些元素」并反复查前后关系（例如：找「比 x 大的最小元素」）。
② 需要去重后按大小顺序输出。
③ 动态维护「区间合并」：用一个 set<pair<int,int>> 存区间，插入新区间时找前驱后继进行合并——这是「区间覆盖」类题的标准做法。

⚠️ multiset 的 erase 陷阱

ms.erase(3) 会删掉所有值为 3 的元素并返回删除个数，而不是只删一个。只想删一个必须写 ms.erase(ms.find(3))。这个坑在竞赛里坑过无数人。

🔎 set / map 的成员函数
s.insert(x)
作用：插入元素（set 会自动去重、自动保持有序），O(log n)。
返回值：pair<iterator, bool> —— 第二项表示是否真的插入了（false 说明本来就有）。判断「有没有重复插入」就靠它。
对 map 是 insert({key, value})，语义相同。
s.erase(...)　★ 两个版本完全不同
按值删：s.erase(x) —— 删掉所有值为 x 的元素，返回删除的个数。对 multiset 来说这就是「一次删光」。
按迭代器删：s.erase(it) —— 只删这一个，返回下一个元素的迭代器。
只想删一个怎么办：ms.erase(ms.find(x)); —— 先找到再按迭代器删。这是 multiset 的头号坑。
s.count(x) / s.find(x)
count(x)：值为 x 的元素个数。对 set 只有 0 或 1，对 multiset 是实际个数。注意它的复杂度是 O(log n + 出现次数)。
find(x)：返回指向 x 的迭代器，找不到返回 s.end()。判断「在不在」时 find 和 count 都行，O(log n)。
s.lower_bound(x) / s.upper_bound(x)
含义和全局的 std::lower_bound 一样（第一个 ≥ x / 第一个 > x），但必须用成员函数：s.lower_bound(x)，O(log n)。
为什么：全局版需要随机访问迭代器，而 set 的迭代器是双向的，调用全局版会退化成 O(n)。
经典用法：求前驱和后继 —— auto it = s.lower_bound(x); 是后继；if(it != s.begin()) --it; 得到前驱。
prev(it) / next(it)（<iterator>）
作用：返回迭代器向前 / 向后移动一步的副本，不会改变原迭代器。
prev(s.end()) 就是「最后一个元素」（end() 指向最后一个元素的后面）。
陷阱：对 begin() 求 prev、对 end() 求 next 都是越界，必须先判边界。
map 的 operator[]　★ 会「凭空创建」
作用：mp[key] 返回 value 的引用。
关键坑：如果 key 不存在，operator[] 会插入一个默认值（数值 0、字符串空）。所以「只想查、不想改」时应该用 mp.count(k) 或 mp.find(k)。
后果：在多测 / 统计类题目里，无意中的 mp[x] 会把 size 撑大，导致答案错。
安全版：mp.at(k) 在 key 不存在时抛异常（比赛里一般不推荐抛异常）；C++17 起可以用 mp.contains(k) 判断。
um.reserve(n)
作用：给 unordered_map / unordered_set 预留足够的桶数，避免反复 rehash。
为什么需要：不定量插入 10⁶ 个元素时，容器会多次重新分配哈希表，既慢又可能在中途爆内存；预估好容量能显著提速。
顺带提醒：unordered_* 平均 O(1)，但出题人如果知道默认哈希函数，可以构造出让所有元素落进同一个桶的数据，把它卡成 O(n) —— 需要防卡时改用 map（稳定 O(log n)）或自定义哈希函数。

4动态规划：把「重复计算」变成「查表」▾

DP 是分水岭。它没有固定套路，但有一套固定的思考流程。先把第 1 张卡的方法论吃透，后面每张卡都只是换了一种「状态定义」。

1. DP 方法论：五步法

基础★★★★核心补充

本质：DP = 递推 + 记录。把一个大问题拆成若干子问题，子问题之间有重叠，于是把子问题的答案存起来复用。它成立的前提是「无后效性」——后面的决策只依赖于当前状态，与怎么走到这里无关。

🎯 五步法：写 DP 时按顺序问自己这五个问题

① 状态是什么？用一句话描述 dp[...] 的含义，必须能读成一句完整的话（如「前 i 个物品、背包容量 j 时的最大价值」）。
② 转移是什么？当前状态由哪些「更小的状态」推出来。要能列出等式。
③ 边界是什么？最小规模时的答案（dp[0] = 0 之类）。
④ 填表顺序是什么？保证「用到的状态已经算好」。
⑤ 答案在哪个状态里？（dp[n][m]？还是所有状态取最值？）

⚠️ 无后效性不成立时就不是 DP

反例：如果状态是「走到 (i, j) 且路径上经过的最小值」——那「怎么走过来的」会影响后续决策吗？只要状态里把「最小值」记进去，就仍满足无后效性。无后效性的本质是：把你需要的历史信息全部编码进状态里。状态维度不够，就会出现「转移需要知道更多信息」的情况。

4. 区间 DP

基础★★★★必会

本质：状态是一个区间 dp[l][r]，转移是「枚举分割点 k，把区间拆成两半」。所以必须先枚举区间长度，再枚举起点——保证小区间先算好。

⚠️ 区间 DP 最容易死在哪

循环顺序写反。如果你按「起点 l 从 1 到 n、终点 r 从 l 到 n」来写，会发现计算 dp[l][r] 时 dp[l+1][r] 还没算——必须先枚举长度。记住模板的第一行永远是 for(len = 2; ...)。

6. 状态压缩 DP

基础★★★★必考

本质：当状态是「一个集合」（谁被选了、哪些位置放了棋子）且元素个数 n ≤ 20 时，用一个整数的二进制位表示这个集合，整数就是状态。

💡 什么时候该想到状压

题目里的关键量满足两个条件：① 是个「集合 / 选取状态」；② 元素个数不超过 20。典型信号：「n ≤ 20 的选或选不选」「棋盘上放棋子且不能相邻」「图的顶点访问情况」。
n ≤ 20 时 2ⁿ ≈ 10⁶，乘上 n 就是 2×10⁷，正好卡在 1 秒的边界上——这就是状压 DP 的适用范围。

7. 数位 DP：统计「区间内有多少个满足条件的数」

进阶★★★★模板题高频补充

本质：按位从高位到低位填数字，用一个「是否贴住上界」的标志 limit 控制取值范围。答案用 solve(R) − solve(L−1) 得到区间计数。

⚠️ 数位 DP 的三个易错点

① 记忆化只能在「不贴界」时进行。贴界状态下答案依赖于具体上界，缓存会出错。
② 前导零。如果题目关心「数码 0 的个数」或「有几位」，前导零会被误算。要额外增加一维 lead（是否还在前导零阶段）。
③ 用 -1 当「未计算」标记，别用 0——因为真实答案可能就是 0。

8. DP 优化入门：滚动数组 / 前缀和 / 单调队列

进阶★★★★提分点补充

本质：先把 DP 写对（哪怕超时），再观察转移式里「重复计算的部分」，用数据结构把它压成 O(1)。写对 → 优化，顺序不能反。

例题：洛谷 P1725 琪露诺 —— dp[i] = max(dp[j]) + a[i]，其中 j ∈ [i−R, i−L]。这是一个定长滑动窗口求最大值，直接套单调队列即可从 O(nR) 降到 O(n)。

3. 最短路之一：Floyd（全源最短路）

基础★★模板

本质：动态规划。f[k][i][j] = 只允许经过前 k 个点中转时，i 到 j 的最短路。压掉第一维后就是那个三重循环。O(n³)，但代码只有五行，n ≤ 500 时首选。

🚫 两个必踩的坑

① k 循环写到内层。那就退化成「只允许经过一个中转点」，答案是错的。k 必须在最外层。
② INF 设置得太小。用 0x3f3f3f3f（约 10⁹），不要用 INT_MAX——两个 INF 相加会溢出成负数，导致错误地「松弛」出一个很短的路径。

4. 最短路之二：Dijkstra（单源、非负权）

基础★★★★必背

本质：贪心。每次取出「当前距离最小的未确定节点」，它的距离就确定下来了（因为边权非负，绕路不可能更短），然后拿它去松弛邻居。用堆优化后是 O(m log n)。

🚫 Dijkstra 的三个坑

① 用在有负权的图上。贪心前提被破坏，结果可能错。反例：1→2 (5)、1→3 (2)、3→2 (−10)，Dijkstra 会先确定 dist[2] = 5，但实际是 −8。
② vis 判断与堆的懒删除。不加 if(vis[u]) continue; 也能对，但会重复处理同一个点导致变慢。
③ dist 数组清零。多组数据或多次调用时忘记重置，第二组全错。

5. 最短路之三：Bellman-Ford 与 SPFA

基础★★★负权 / 判环

本质：所有点一起松弛，重复 n−1 轮。SPFA 是它的队列优化版：只有「距离被更新过」的点才需要继续松弛别人。SPFA 能处理负权、能判负环，但最坏复杂度 O(nm)，会被特殊数据卡掉。

⚠️ SPFA 已经「死了」吗？

对于非负权的最短路，永远优先用 Dijkstra——SPFA 可能被网格图卡到 O(nm)。
SPFA 仍然不可替代的场合：① 有负权边；② 要判负环；③ 差分约束系统；④ 边权是随机数据时的快速实现。

6. 最小生成树：Kruskal 与 Prim

基础★★★必会

Kruskal（边驱动）：把所有边按权从小到大排序，依次尝试加入，用并查集判断会不会成环。Prim（点驱动）：从一个点出发，每次把「距离已选集合最近的点」拉进来（用堆维护）。

💡 Kruskal 为什么是正确的

因为它每一步都在执行「割性质」：把所有点分成已连和未连两部分，跨越这条割的最小边一定属于某棵最小生成树。按边权从小到大贪心，实际上是在不断找「当前最小的合法割边」。

9. 割点与桥

进阶★★★★补充补充

本质：割点是删掉后图不再连通的点；桥是删掉后图不再连通的边。用 Tarjan 的 dfn/low 就能 O(n+m) 全部找出来。

💡 割点和桥的判定式，只差一个符号

割点：low[v] >= dfn[u]　桥：low[v] > dfn[u]
直观理解：low[v] > dfn[u] 说明边 (u,v) 是 v 那一侧的「唯一出口」，所以它是桥；而 low[v] == dfn[u] 时边不是桥（还能绕回 u），但 u 仍然可能是割点。

1. 位运算技巧

入门★★★工具
例题：__builtin_popcount(x) 返回 x 的二进制中 1 的个数（GCC 内置，O(1)）；__builtin_ctz(x) 返回末尾 0 的个数。洛谷 P1469 找筷子 —— 2n−1 根筷子，异或一遍就能找出唯一落单的那根。
🔎 三个编译器内建函数（不需要头文件）
__builtin_popcount(unsigned x)
作用：返回 x 的二进制里 1 的个数（也叫 popcount、汉明重量）。
复杂度：O(1) —— 编译成一条 CPU 指令（POPCNT），比循环数位快几十倍。
参数类型：unsigned int。要数 64 位就加后缀：__builtin_popcountll(x)。
说明：这是 GCC / Clang 的扩展，不是 C++ 标准库的一部分。换了编译器（比如 MSVC）要用 __popcnt 或 <bit>（C++20）。
__builtin_ctz(x)
作用：count trailing zeros —— 返回二进制里末尾连续的 0 的个数。
等价关系：1 << __builtin_ctz(x) 就是 x & (-x)，也就是 lowbit（树状数组用的那个）。
大坑：__builtin_ctz(0) 是未定义行为（没有末尾 0 可数），会返回随机值。用之前必须先判 x != 0。
兄弟函数：__builtin_clz(x) = 开头连续 0 的个数（同样，clz(0) 未定义）。
怎么自己算（不依赖内建函数）
数 1 的个数：while(x){ cnt += x & 1; x >>= 1; }，O(位数)。
更快的手写版：while(x){ x &= x - 1; ++cnt; } —— 每次 x & (x-1) 都会消掉最低位的 1，循环次数等于 1 的个数。
取 lowbit：x & (-x)。这个写法依赖补码表示法，而所有现代平台都用补码，可以放心用。

2. 快速幂与矩阵快速幂

基础★★★★必背补充

3. GCD 与扩展欧几里得

基础★★★必背补充

本质：gcd(a, b) = gcd(b, a mod b)，三行代码。EXGCD 在求 gcd 的同时，顺便求出满足 a·x + b·y = gcd(a, b) 的一组整数解——它是求逆元、解同余方程、解不定方程的基础。

🔎 gcd / lcm / __gcd 的区别
__gcd(a, b)
作用：求最大公约数，GCC / Clang 的扩展函数（不在 <algorithm> 的正式文档里，但 <bits/stdc++.h> 或 <algorithm> 能带出来）。
参数：两个整数，返回它们的最大公约数；__gcd(a, 0) = a。
缺点：换到 MSVC 就没有这个函数了。
std::gcd(a, b) / std::lcm(a, b)（C++17，<numeric>）
作用：标准库版本，语义和上面一样，但可移植。
注意：需要 C++17（洛谷默认是 C++14，提交时要在「语言」下拉框里选 C++17，否则会编译错误）。
负数：标准规定结果非负，gcd(-4, 6) = 2。
lcm 为什么总是「先除后乘」
公式：lcm(a, b) = a / gcd(a, b) * b。
不能写成 a * b / gcd(a, b) —— a、b 都是 10⁹ 时，a * b 先算出来就溢出 int 了，结果是垃圾值。
口诀：先除后乘，能除就除。这个习惯在组合数、概率 DP 里同样重要。
手写辗转相除（必须会默写）
递归版：int gcd(int a, int b){ return b ? gcd(b, a % b) : a; }
迭代版：while(b){ int t = a % b; a = b; b = t; } return a;
复杂度：O(log min(a, b))（拉梅定理）。
为什么能这么写：gcd(a, b) == gcd(b, a % b)，因为任何同时整除 a、b 的数也整除 a - kb，反之亦然。

5. 欧拉函数与乘法逆元

基础★★★必背补充

欧拉函数 φ(n) = 1~n 中与 n 互质的数的个数。它的价值在于欧拉定理：a^φ(m) ≡ 1 (mod m)（a、m 互质），于是 a 的逆元就是 a^(φ(m)−1)。逆元的意义：模意义下不能直接做除法，要把「除以 a」换成「乘以 a 的逆元」。

💡 三种求逆元的方法，怎么选

模数是质数 → 费马小定理（qpow(a, m-2, m)），一行。
模数是质数且要批量求 → 线性递推，O(n)。
模数不是质数 → 必须用 EXGCD 或欧拉定理，且要保证 gcd(a, m) = 1（否则逆元不存在）。

🔎 fabs 与 abs：浮点题的头号陷阱
fabs(x)（<cmath>）
作用：求浮点数的绝对值，返回 double。参数可以是 int / double / long double。
在几何和高斯消元里的用法：判断「是否为 0」不能写 x == 0（浮点有误差），要写 fabs(x) < 1e-9，这个 1e-9 叫 epsilon（eps）。
eps 怎么取：和数据的量级有关。一般 1e-9 够用；如果坐标是 10⁹ 级别的整数，除法后误差会放大，改用 1e-6 更稳；判断「两数相等」时用 fabs(a-b) < 1e-9 而不是 a == b。
abs(x)（<cstdlib> 整数版 / <cmath> 浮点版）
致命坑：只 #include <cstdlib> 时，abs 只有整数重载。写 abs(3.14) 会被隐式截断成 3，再返回 int 3 —— 看起来没错，但结果完全不对，而且不报错。
正确做法：浮点一律用 fabs；或者同时 #include <cmath> 用 std::abs 的重载版本。
整数用 abs 也要小心：abs(INT_MIN) 是未定义行为（−(−2³¹) 溢出）。
sqrt / pow / exp / log（<cmath>）
sqrt(x)：平方根，返回 double，O(1)（硬件指令级）。输入负数返回 NaN，不会报错，会静默错下去。
pow(a, b)：幂，返回 double。★ 整数幂不要用它 —— 它是浮点运算，算 10¹⁸ 这类大数会丢精度，而且慢。整数幂用快速幂，或直接乘。
exp(x) / log(x)：e 的幂 / 自然对数。求 log₂ 用 log(x)/log(2) 或 log2(x)；取位数用 log10(x)。
floor / ceil / round：下取整 / 上取整 / 四舍五入，返回仍是 double，要转 int 记得 (int)floor(x)。
浮点比较的正确姿势
错误：if(a == b)、if(a > b) —— 0.1+0.2 != 0.3 就是这个原因。
正确：if(fabs(a - b) < 1e-9) 判相等；比较大小用 if(a - b > 1e-9) 表示「严格大于」。
更好的做法：能不进浮点就别进 —— 判两向量方向用叉积的符号（整数坐标时叉积是整数，可以精确比较），这比算角度可靠得多。

3. AC 自动机：多模式串匹配

进阶★★★★必会补充

本质：Trie 树 + KMP 的失配指针。把一堆模式串建 Trie，然后给每个节点求出 fail 指针（「失配时该跳到哪个节点」），最后拿文本串在图上跑一遍，就能同时找出所有模式串的出现位置。O(总模式串长度 + 文本串长度 + 命中次数)。

✅ 实测

⚠️ AC 自动机的两个易错点

① 节点数开小了。节点总数 = 所有模式串的长度之和 + 1，不是模式串个数。开小了直接 RE。
② 统计时忘记沿 fail 链往上走。在节点 u 匹配成功，只说明有模式串以 u 结尾；fail 链上的所有节点也都是匹配（比如匹配到 abc 同时说明 bc 也匹配了）。

本质：在一个有容量的有向图上，从源点往汇点「输水」，求最大流量。Dinic 的做法是反复 BFS 分层 + DFS 多路增广，复杂度 O(n²m)。难点从来不是写模板，而是把实际问题建网络。

💡 最大流的三件套结论

① 最大流 = 最小割（最大流最小割定理）——「去掉最少多少代价能断开源汇」等价于最大流。
② 二分图最大匹配 = 最大流（源→左部容量 1，左→右容量 1，右→汇容量 1）。
③ 常见建模套路：点拆边（限制点容量）、上下界、费用流（加一个「费用」维度）、最小路径覆盖、最大权闭合子图。

7. 随机化：模拟退火与随机哈希

进阶★★★骗分利器补充

本质：当问题「难以精确求解」或者「不确定自己的做法对不对」时，用随机化。模拟退火在解空间里随机游走，以一定概率接受变差的解从而跳出局部最优；随机哈希用随机参数抵抗构造数据。

⚠️ 随机化算法要「多跑几次」

模拟退火的单次结果是不确定的，正确用法是：循环 5~20 次取最优值，并且把初始解设为「贪心/暴力得到的较优解」而不是纯随机。另外注意 OJ 上通常没有真正的随机（固定种子），要用 chrono 或 time(0) 播种。

🔎 想要真正好的随机数：mt19937
mt19937 是什么
全名：Mersenne Twister（梅森旋转）32 位版本，在 <random> 里（C++11）。
为什么比 rand() 好：周期长达 2¹⁹⁹³⁷−1、分布均匀、速度快，而且范围是整个 32 位无符号整数（不是 rand() 在 Windows 上的可怜 32767）。
用法：mt19937 rng(seed); 然后用 rng() 取值。
怎么播种才不会「每次都一样」
常见写法：mt19937 rng(chrono::steady_clock::now().time_since_epoch().count());
拆解：steady_clock::now() 取当前时刻（纳秒级），.time_since_epoch() 变成时段，.count() 转成整数当作种子。因为纳秒级、几乎不可能重复，所以每次运行都不一样。
为什么要用 steady_clock 而不是 system_clock：steady 是单调时钟，不受系统时间被改动的影响。
uniform_int_distribution<int>(l, r)
作用：把 rng 产出的均匀 32 位整数，映射成 [l, r] 上的真正均匀分布。
用法：uniform_int_distribution<int> dist(1, 100); int x = dist(rng);
为什么不能直接 rng() % 100：取模会引入偏差（模不整除 2³² 时，小的余数出现概率略高）。要均匀分布就得用 distribution。
实数版：uniform_real_distribution<double>(0.0, 1.0)。
shuffle(first, last, rng)
作用：把区间随机打乱（需要 <algorithm> 和 <random>）。
参数：区间的两个迭代器 + 一个随机数引擎。返回值：无。复杂度：O(n)。
典型用途：随机化贪心（打乱后贪一遍，多跑几次取最优）、造随机排列的测试数据。
别再用 random_shuffle —— 它在 C++17 里已经被移除了。

关键观察：H 越小，锯下来的木头越多。这是一条单调性：

总木材多多←少少
是否 ≥ M✅✅/❌❌

5 20
4 42 40 26 46
样例输出
36

H = 36 时：(42−36) + (40−36) + (46−36) = 6 + 4 + 10 = 20 ≥ 20 ✅
H = 37 时：5 + 3 + 9 = 17 < 20 ❌ → 所以答案是 36。

P1886　滑动窗口 /【模板】单调队列 单调队列 · 定长窗口最值

题意：给一个长度为 n 的数组和一个窗口长度 k。窗口从左滑到右，每滑一步就输出窗口内的最小值（第一行）与最大值（第二行）。

⚠️ 数据范围决定做法

n ≤ 10⁶。暴力做法是每个窗口扫一遍 k 个数 → O(nk) = 10¹²，必然超时。
目标是 O(n)——于是想到「每个元素只进出容器一次」的结构：单调队列。

思路：让队列「永远单调」

维护一个双端队列，里面存下标（不是值），并且队列里的值保持单调递增。三条规则：

  1. 入队时：把队尾所有「值 ≥ 新元素」的都弹掉。因为它们比新元素先过期、又比新元素大，永远不可能再成为答案。
  2. 过期检查：如果队首下标 < i−k+1，说明它已经滑出窗口，弹掉。
  3. 取答案：窗口形成后（i ≥ k），队首就是当前窗口的最小值。
🎯 复杂度为什么是 O(n)

每个下标最多被压入队列一次、弹出一次，所以内层两个 while 加起来总共执行 O(n) 次。这就是「均摊分析」——单次最坏 O(k)，但总代价 O(n)。

样例输入
8 3
1 3 -1 -3 5 3 6 7
样例输出
-1 -3 -3 -3 3 3
 3  3  5  5 6 7

第一行最小值：窗口 [1,3,−1]→−1；[3,−1,−3]→−3；[−1,−3,5]→−3；[−3,5,3]→−3；[5,3,6]→3；[3,6,7]→3。
第二行最大值同理。两组结果均已用独立实现跑过，与官方样例一致。

完整代码（一次循环求最小值，第二次求最大值）

✅ 实测结果

官方样例 → 最小值 -1 -3 -3 -3 3 3、最大值 3 3 5 5 6 7，完全一致。

易错点

  • 比较符号写错。求最小值用 >= 弹队尾（求最大值用 <=）。写成 > 会把相等的留下，虽然结果对，但队列变长、性能下降；更麻烦的是容易和「过期判断」搞混。
  • 先入队还是先检查过期？先弹队尾、再入队、再检查队首过期。顺序换掉可能在 k=1 时出错，建议照抄模板。
  • 队列里存值而不是下标。那样无法判断「过期」，必须存下标。
  • 输出格式。用 " \n"[i == n] 这个小技巧，可以保证每行末尾不多空格。

P1048　[NOIP2005 普及组] 采药 01 背包 · 滚动数组

题意：有 T 个单位的采药时间，有 M 株药，第 i 株需要时间 tᵢ、价值 vᵢ。每株只能采一次，问在时间内能采到的最大总价值。

⚠️ 数据范围

T ≤ 1000，M ≤ 100。也就是说朴素的二维 DP f[M][T]（10⁵ 个状态）完全可以。但这一题最好的写法是滚动成一维——这是背包的标准写法，必须养成习惯。

思路

状态：f[j] = 「用 j 的时间最多能采到多少价值」。
转移：对每株药，要么采、要么不采——f[j] = max(f[j], f[j − tᵢ] + vᵢ)。
关键在循环方向：容量 j 必须从大到小遍历。因为 f[j] 用到的是 f[j−tᵢ]，如果从小到大，f[j−tᵢ] 可能已经被「这一株药」更新过，等于同一株药采了多次（那就变成完全背包了）。

样例输入
70 3
71 100
69 1
1 2
样例输出
3

第一株要 71 分钟 > 70，采不了。第二株（69, 1）+ 第三株（1, 2）= 70 分钟、价值 3，正好装满。所以答案是 3。

完整代码（一维滚动写法）

✅ 实测结果

官方样例 → 输出 3　与标准答案一致。
同一组数据换成完全背包（每株可无限采）→ 输出 140（只采第三株，采 70 次，每次 2 点价值）。循环方向只差一个符号，答案差了 47 倍——这就是背包最核心的细节。

易错点

  • 循环方向写反。01 背包必须 for(j = T; j >= t; j--)。
  • 内层循环下界写成 0 或 1。应该是 j >= t，因为 f[j−t] 的下标不能为负。
  • 边读边算。本题可以边读边算（因为每株药独立），但如果题目需要「恰好装满」的初始化，就要先把所有物品读进来。
  • 「恰好装满」与「至多装」的初始化不同。本题是「至多」，所以 f[] 全为 0 即可；若是「恰好装满 T」，要把 f[0]=0、其余设为 −INF。

题意：给一张 n 个点、m 条有向边的图（边权非负），给定起点 s，输出 s 到每个点的最短距离，到不了输出 2³¹−1。

⚠️ 数据范围

2 3 2
2 4 1
1 3 5
3 4 3
1 4 4

0 2 4 3

1→1 距离 0；1→2 直连 2；1→3 走 1→2→3 = 4（比直连 5 短）；1→4 走 1→2→4 = 3（比直连 4 短）。

P2602　[ZJOI2010] 数字计数 数位统计 · 贡献法

题意：给定 a、b（a ≤ b），求在 [a, b] 的所有整数中，数码 0~9 各出现了多少次。

⚠️ 数据范围

a, b ≤ 10¹²。这意味着不能枚举每一个数（10¹² 个数）。必须按位统计：只看「某一位上出现某个数码」的所有数有多少个，复杂度 O(位数 × 10) = 常数级。

思路：逐位贡献（贡献法）

把 n 写成数字串，对每一个位置 i 单独统计「数码 d 在这一位上出现了几次」：

设 left = 该位左边的数、cur = 该位的数码、right = 右边的数、pw = 10^(右边位数)。

  • cur > d：左边可以取 0~left 全部 → (left+1) × pw
  • cur == d：左边取 0~left−1 时右边任意（left×pw），左边取 left 时右边只能 0~right（right+1）→ 合计 left×pw + right + 1
  • cur < d：左边只能取 0~left−1 → left × pw
🎯 数码 0 的特殊处理

算 0 的时候必须排除前导零：最高位不能是 0。所以 i == 0 时直接跳过；其余位置把 left 换成 left − 1（因为「左边全是 0」这种取法会让这个 0 变成前导零，不算数）。这一步是本题最容易写错的地方。

0 出现 9 次（10,20,…,90 的个位）；1~9 各出现 20 次（例如 1：个位上 1,11,…,91 共 10 次，十位上 10~19 共 10 次）。总和 189。

第 1 题：复杂度（对应 1.1）

下面这段代码的复杂度是多少？

for(int i = 1; i <= n; i++)
    for(int j = i; j <= n; j += i)
        work();

答：O(n log n)。内层循环执行约 n/i 次，总数 = n(1/1 + 1/2 + … + 1/n) = n·H(n) ≈ n ln n。这是「调和级数」的经典形态，埃氏筛、倍数枚举都是这个结构。

第 2 题：数据范围倒推（对应 0 章）

某题 n ≤ 10⁶，你写了一个 O(n²) 的做法。能不能过？如果不行，还有什么方向？

答：不能。10¹² 次操作，1 秒只能做约 10⁸ 次。可选方向：排序后双指针、前缀和/差分、二分、单调栈/单调队列、树状数组/线段树、离散化——这些都能把 O(n²) 压到 O(n log n) 或 O(n)。

第 3 题：前缀和 vs 差分（对应 2.4）

题目：「有 q 次操作，每次把数组的 [l, r] 区间全部加 v；最后输出整个数组。」应该用前缀和还是差分？为什么？

答：用差分。因为「修改多、查询少（只在最后查一次）」。差分的每次修改是 O(1)（只改两个位置），最后 O(n) 还原。
反过来如果是「一次修改、多次查询」，就用前缀和。

第 4 题：二分模板选择（对应 2.7）

题目要「最大化 H，使得 H 可行」。应该用哪套二分模板？mid 怎么算？

答：用「最大化答案」模板，mid = l + (r - l + 1) / 2（上取整），if(check(mid)) l = mid; else r = mid - 1;。答案是 l。
关键：必须上取整，否则当 r = l+1 时 mid = l，l = mid 不变化 → 死循环。

第 5 题：单调队列（对应 3.3）

求滑动窗口最小值时，队尾弹出的条件是 a[dq.back()] >= a[i] 还是 >？两者结果一样吗？

答：结果一样（都保留最小值），但推荐用 >=。原因是队列里保留「相等但更靠后」的元素毫无价值——它先过期，值也不更优。用 >= 可以让队列更短、更快。
但要注意：过期判断必须用下标，不能用值。

第 6 题：堆的运算符方向（对应 3.4）

想让 priority_queue 的堆顶是「值最小的元素」，结构体要怎么重载 <？

答：return x.val > y.val;。
原因：priority_queue 把「< 判定为较小」的元素放到堆底，所以「更大的」才会浮到堆顶。想让小的浮上去，就要让「比较时 x 大于 y」返回 true。
记忆口诀：堆顶是「不小于号指向的那一方」。或者直接用 greater<>。

第 7 题：并查集合并（对应 3.5）

合并两个集合时写 fa[x] = y; 有什么问题？正确写法是什么？

答：x 可能不是根节点，直接挂过去会让树的结构被破坏、路径压缩失效。正确写法：fa[find(x)] = find(y);——永远只操作根节点。

第 8 题：背包循环方向（对应 4.3）

01 背包的内层循环为什么要倒序？如果正序会发生什么？

答：倒序保证「f[j - w] 还没被本轮（这一件物品）更新过」，从而每件物品只用一次。
正序时会用到「本轮已更新过」的 f[j-w]，等价于同一件物品被反复放入 → 退化成完全背包，答案偏大。
实测：P1048 那组数据，01 背包答案 3，完全背包答案 140。

第 9 题：DP 状态定义（对应 4.2）

LIS 的 dp[i] 定义是「前 i 个元素的最长上升子序列长度」还是「以 i 结尾的最长上升子序列长度」？答案取哪个？

答：必须是「以 i 结尾」。因为只有「以 i 结尾」才满足转移 dp[i] = max(dp[j]) + 1 (a[j] < a[i])。
所以答案是 max(dp[1..n])，不是 dp[n]。这是最高频的 DP 错误之一。

第 10 题：Dijkstra 的适用范围（对应 5.4）

图里有一条权值为 −10 的边，能用 Dijkstra 吗？为什么？该用什么？

答：不能。Dijkstra 的正确性依赖「边权非负」——它假设「当前距离最小的点，其距离已经确定」。有负边时，绕一刀可能更短。
反例：1→2 (5)、1→3 (2)、3→2 (−10)，Dijkstra 会先锁定 dist[2] = 5，但正确答案是 −8。
应该用 SPFA / Bellman-Ford；如果是 DAG 还可以按拓扑序 DP。

第 11 题：矩阵快速幂（对应 6.2）

题目给递推 f(n) = f(n−1) + f(n−2) + 1，n ≤ 10¹⁸。该怎么求？

答：用矩阵快速幂。把常数项 1 也放进状态向量，转移矩阵是 3×3：

[f(n)  ]   [1 1 1]   [f(n-1)]
[f(n-1)] = [1 0 0] · [f(n-2)]
[  1   ]   [0 0 1]   [  1   ]

用快速幂算矩阵的 n 次方，复杂度 O(3³ log n) = O(log n)。

第 12 题：综合判断（对应 5 章 + 7 章）

题目：给一个长度为 10⁵ 的字符串，100 次询问「子串 s[l..r] 是不是回文」。用什么方法？

答：字符串哈希。预处理正串哈希和反串哈希，每次询问 O(1) 比较 hash(l, r) 与反串对应区间。总复杂度 O(n + q)。
备选：Manacher 预处理出每个中心的最长回文半径，询问时 O(1) 判断「以 (l+r)/2 为中心能否覆盖到 r」。
不适合的做法：每次询问暴力比较——100 × 10⁵ = 10⁷ 也能过，但如果询问变成 10⁵ 次就超时。

v.push_back(x) / v.pop_back()<vector>尾部追加 / 删除一个元素。均摊 O(1)push_back 触发扩容会让已有迭代器 / 指针失效。
v.size()<vector>返回元素个数，类型是 无符号 size_t。O(1)v.size()-1 在 v 为空时是个巨大的正数！建议写 (int)v.size()。
q.push(x) / q.front() / q.pop()<queue>入队尾 / 看队首 / 删队首。均摊 O(1)pop 不返回值：要 T x=q.front(); q.pop();；空队列取 front 是未定义行为。
dq.push_front / push_back / pop_front / pop_back<deque>双端队列，两端都能进出；还支持 dq[i] 随机访问。均摊 O(1)中间插入删除是 O(n)；单调队列 / 0-1 BFS 用它。
pq.top() / pq.push(x) / pq.pop()<queue>优先队列（堆）取堆顶 / 插入 / 删堆顶。top O(1)，push/pop O(log n)不能遍历、不能删任意元素；小根堆要写全三个模板参数。
priority_queue<T, vector<T>, greater<T>><queue>+<functional>构造小根堆。三个参数：元素类型 / 底层容器 / 比较器。—greater 让「小的」优先级高、浮到堆顶。
st.push / st.top() / st.pop()<stack>栈的入栈 / 看栈顶 / 出栈。均摊 O(1)top 不删除，和 queue 的命名习惯不同，别记混。
s.insert(x)<set><map>插入（自动去重、自动有序），返回 pair<iterator,bool>，bool 表示是否真的插入。O(log n)可以用返回值判断「是不是重复了」。
ms.erase(x) vs ms.erase(it)<set>按值删 -> 删掉全部等于 x 的元素；按迭代器删 -> 只删这一个。O(log n + 个数) / O(log n)multiset 想只删一个必须写 ms.erase(ms.find(x))。
s.count(x) / s.find(x)<set>统计个数 / 返回迭代器（找不到是 s.end()）。O(log n)count 对 multiset 是 O(log n + 个数)，只判存在用 find 更好。
s.lower_bound(x) / s.upper_bound(x)<set>第一个 ≥ x / 第一个 > x 的位置，必须用成员函数。O(log n)写成全局 std::lower_bound(s.begin(), s.end(), x) 会退化成 O(n)。
prev(it) / next(it)<iterator>返回迭代器前 / 后移一步的副本。O(1)prev(s.begin())、next(s.end()) 都是越界。
mp[k] / mp.at(k) / mp.count(k)<map>下标访问 / 带检查的访问 / 存在性判断。O(log n)mp[k] 会在 k 不存在时凭空插入默认值，只查不改请用 count / find。
um.reserve(n)<unordered_map>预留桶数，避免反复 rehash。O(n)平均 O(1)，但可被构造数据卡到 O(n)；防卡改用 map。
bitset<N> b<bitset>定长位集，支持 & | ^ ~ << >> 与 count()，常数是 1/64。O(N/64)N 必须是编译期常量；常用于传递闭包加速和状压。

C · 算法函数

函数 / 用法头文件作用 · 参数 · 返回值复杂度常见坑
sort(first, last)<algorithm>区间 [first, last) 升序排序，不稳定。O(n log n)闭区间要写 a + n，写成 a + n - 1 会漏掉最后一个元素。
sort(first, last, cmp)<algorithm>按 cmp 排序，cmp 返回 true 表示 a 应排在 b 前面。O(n log n)cmp 必须满足严格弱序：相等时要返回 false，写成 >= 会 RE。
stable_sort(first, last)<algorithm>稳定排序，相等元素保持原相对顺序。O(n log n)题目要求「同分按输入顺序」时用它，或在 cmp 里加原始下标。
nth_element(first, nth, last)<algorithm>让第 nth 小的元素就位，左边都不大于它、右边都不小于它。平均 O(n)不保证两侧有序；求第 k 小 / 中位数时比完整排序快。
lower_bound(first, last, x)<algorithm>有序区间里第一个 ≥ x 的位置。O(log n)区间必须已排序；减首迭代器得到下标。
upper_bound(first, last, x)<algorithm>有序区间里第一个 > x 的位置。O(log n)upper - lower 就是 x 的出现次数。
unique(first, last)<algorithm>把相邻重复元素挪到后面，返回新的逻辑结尾；不删除元素。O(n)必须配合 v.erase(unique(...), v.end()) 才真正缩短；前提是已排序。
reverse(first, last)<algorithm>原地反转区间。O(n)常用来「翻转后再跑一遍」处理对称问题。
max(a,b) / min(a,b) / swap(a,b)<algorithm>取较大 / 较小 / 交换。O(1)两个参数类型必须一致，混用 int 和 long long 会报错。
fill(first, last, v)<algorithm>把区间每个元素赋成 v。O(n)比 memset 安全（memset 是按字节的）。
next_permutation(first, last)<algorithm>把区间变成下一个字典序排列，返回是否还有下一个。O(n)用之前必须先把序列排成升序，否则枚举不全。
accumulate(first, last, init)<numeric>求和（默认加法，也可传自定义运算）。O(n)返回值类型由 init 决定：写 0 会按 int 累加而溢出，写 0LL。
gcd(a,b) / lcm(a,b)<numeric>（C++17）最大公约数 / 最小公倍数。O(log n)C++14 及以下用 GCC 扩展 __gcd；lcm 要「先除后乘」防溢出。
__builtin_popcount(x)编译器内建（无头文件）x 的二进制里 1 的个数。O(1)GCC/Clang 扩展非标准；64 位用 __builtin_popcountll。
__builtin_ctz(x) / clz(x)编译器内建（无头文件）末尾连续 0 的个数 / 开头连续 0 的个数。O(1)ctz(0)、clz(0) 都是未定义行为，先判非 0。

函数 / 用法头文件作用 · 参数 · 返回值复杂度常见坑
sqrt(x) / fabs(x)<cmath>平方根 / 浮点绝对值。O(1)浮点绝对值必须用 fabs；abs 在只引 <cstdlib> 时是整数版，会把小数截断。

memset(p, byte, n)<cstring>把 n 个字节都设成 byte。O(n)只能设 0 / −1 / 0x3f；memset(a,0x3f,sizeof a) 得到 0x3f3f3f3f = 1061109567。

to_string(x) / stoi(s)<string>数值转字符串 / 字符串转整数。O(位数)stoi 遇到非法字符抛 invalid_argument 异常，比赛里可以先判一遍格式。

s[i] / s.c_str() / s.empty()<string>取字符（可修改）/ 转 C 风格字符串 / 判空。O(1)s[i] 不做越界检查，s.at(i) 会抛异常。

mt19937 rng(seed)<random>梅森旋转随机数引擎，32 位全范围、分布均匀。O(1)要播种：chrono::steady_clock::now().time_since_epoch().count()。
uniform_int_distribution<int>(l,r)<random>把引擎输出映射成 [l,r] 上真正均匀的整数分布。O(1)不要用 rng() % n 取范围，会引入偏差。
shuffle(first, last, rng)<algorithm>+<random>用指定引擎随机打乱区间。O(n)random_shuffle 在 C++17 已移除，别再用。

特别容易记错的四组：

  • pop() 系列（queue / stack / priority_queue）都不返回值，必须先 front/top 再 pop。
