# 《Python 语法教程》写作规范 v1（内部约定，不面向学生）

这份文件定义 `site/acm/python/` 下所有章节的**结构、语气、代码块规则和验收标准**。写新章、改旧章都照这份来，别自己发明格式。

**范本**：`03-variables-and-types.md` 是唯一的标准样板。动笔前先把它从头读一遍，尤其是 pycon 块、脚本块、表格、练习的写法。

## 1. 读者与目标

- 读者：会一点 C/C++（知道变量、循环、函数、数组），但**没系统学过 Python** 的竞赛/本科低年级学生，以及想从 C++ 转 Python 刷题的人。
- 目标：读完整章能**独立写出可运行代码**，遇到报错能自己定位，知道 Python 与 C++ 的语义差异在哪。
- 因此每一处讲"是什么"之后，必须讲到"**为什么**"和"**什么时候会翻车**"。

## 4. 代码块三件套（最容易出错的地方）

### 4.1 `pycon` 块：交互式验证，主力形式

````markdown
```pycon
>>> a = [1, 2]
>>> b = a
>>> b.append(3)
>>> a
[1, 2, 3]
```
````

- 必须有 `>>> ` / `... ` 前缀，输出按 `repr` 原样写。
- **异常不要用 `Traceback` 块**，用 try/except 打印，理由是这样跨版本稳定：

```pycon
>>> try:
...     int("3.5")
... except ValueError as e:
...     print(type(e).__name__, e)
ValueError invalid literal for int() with base 10: '3.5'
```

- 一个块内 1～6 条交互最佳；太长就拆块，块与块之间用一句正文过渡。
- 这些块会被 `verify.py` 当 doctest **真跑**，写错一个字符就 FAIL。

### 4.2 `python` 块 + `text` 块：完整可运行脚本

````markdown
```python
# 示例：examples/ch05_02_format.py
<文件原文，一字不改>
```

```text
<该文件真实 stdout，原样粘贴，末尾不留空行>
```
````

- 首行**必须**是 `# 示例：examples/xxx.py`，路径精确到文件。
- 块内容必须与示例文件**逐字节相同**（除了这行标记），`verify.py` 会比对。
- 紧跟的 `text` 块必须是**实跑得到的 stdout**，不是手写的。
- 顺序不能变：`python` 块 → `text` 块；中间不许插正文。

### 4.3 `片段` 块：练习里的小代码

````markdown
```python
# 片段
g = [[0] * 3] * 3
```
````

首行 `# 片段` 表示"这不是完整文件，不参与自动校验"。仅在练习、反例展示里使用，正文知识讲解必须用 4.1 或 4.2。

### 4.4 输出确定性红线（违反即返工）

| 禁止 | 原因 | 替代 |
| --- | --- | --- |
| 直接 `print` 一个 `set` / `frozenset` | 字符串哈希随机化，每次顺序不同 | `print(sorted(s))` |
| `print(id(x))`、`print(hex(id(x)))` | 地址随机 | 用 `a is b` 比较 |
| 打印对象默认 `repr`（`<__main__.A object at 0x…>`） | 带地址 | 自定义 `__repr__` 后再打印 |
| 线程/进程交错的输出顺序 | 调度不确定 | 加 `Lock`，或用 `Queue` 收集后统一打印 |
| 打印耗时、时间戳、`datetime.now()` | 每次不同 | 只打印"是否小于阈值"这类布尔结果 |
| 字典键的遍历顺序依赖插入顺序以外的东西 | 索引用 | 显式 `sorted(d)` |
| 浮点全精度输出未固定 | 平台差异 | `f"{x:.6f}"` |
| 文件绝对路径 | 各机器不同 | 用 `Path(__file__).parent` 或只打印文件名 |

## 5. 语气与信息密度

**要**：

- 第二人称"你"，断言句，一句话给一个事实。
- 给因果、给数字、给代价：不要写"性能不好"，写"`list` 的 `in` 是 O(n)，10^5 次查询在 10^5 规模上就是 10^10 次比较，必然 TLE"。
- 给 C++ 的对照锚点：C++ 学生理解新概念最靠"这相当于 …"。
- 用表格压缩并列信息（方法清单、复杂度、易错点）。
- 用 `> **💡 提示**`、`> **⚠️ 易错**`、`> **✅ 小结**` 三种提示框（对应站点的 `box tip` / `box warn` / `box ok`），每章 2～4 个，别滥用。
- 术语用行内代码包裹：`list`、`__init__`、`TypeError`、`sys.path`。

**不要**（出现就是噪声）：

- 空话：'Python 是一门强大的语言'、'非常方便'、'简单易学'、'总之'、'众所周知'。
- 无信息量的过渡：'接下来我们来看一下'。
- 不解释就抛术语：'鸭子类型'必须先一句说清"只要会叫会走就当鸭子"。
- 炫耀式冷知识：与本章主线无关的 CPython 实现细节一律删。
- 用 `!` 结尾的口号句。

**密度指标（每章）**：中文正文 2500～4500 字；pycon 块 8～15 个；脚本块 2～4 个；表格 2～4 张；不要出现连续 3 段没有代码或表格的纯文字。

## 6. C++ 对照的写法

每个核心概念都要有一句"相当于 C++ 的什么 / 与 C++ 不同在哪"，集中汇总到 `## 与 C++ 的差别` 表里。表至少 6 行，覆盖：内存/类型模型、语法便利、性能语义、错误处理、工程习惯。

示例（照这个颗粒度写）：

| 维度 | C++ | Python |
| --- | --- | --- |
| 变量 | 有类型的内存块 | 名字 → 对象的绑定 |
| `4 / 2` | `2`（整型除法） | `2.0`（`/` 永远 float） |
| 异常 | 可选，常用错误码 | 一切错误都是异常，无法忽略 |

## 7. 易错点清单的写法

三列固定：`现象`（学生看到的报错或错误结果，带原文片段）、`原因`（一句话机制）、`一行修复`（可直接抄的代码）。每章 8～12 行。报错原文要精确，例如 `TypeError: 'int' object is not iterable`。

## 8. 练习的写法

- 5 题固定配比：**3 道基础**（改写/预测输出/补全）、**1 道变式**（换场景）、**1 道挑战**（综合，需要组合本章 2 个以上知识点）。
- 每题必须有 `验收：` 一行，写**可判定的标准**（输出应该是什么、函数签名、必须处理哪种输入）。
- 不给完整答案（这是教程不是题解），但给足够的提示（提示放在"验收"前一句）。

## 9. 术语与风格统一表

| 统一用法 | 不要用 |
| --- | --- |
| 名字 / 绑定 / 指向（讲变量） | 变量盒子、内存单元 |
| 可变 / 不可变 | 可修改/可改变 |
| 可迭代对象 / 迭代器 | 可遍历/游标 |
| 内置函数 / 内置类型 | 系统函数 |
| 解释器 / CPython | 编译器（Python 语境下错） |
| 返回 / 抛出（异常） | 报出/弹出 |
| 下标从 0 开始 | 索引从 1 开始 |
| `None`（代码格式） | null、nil、空 |

标点用中文全角（`，。：；`），代码与英文两侧留半角空格（`用 `list` 存`），不用「」以外的花哨括号。

## 10. 版本边界

- 目标版本 **Python 3.10+**，示例在 **CPython 3.14.7** 上实测。
- 用到 3.10 以下没有的特性（`match`、`X | None`、`except*`、`itertools.batched`、`TaskGroup`）时，**必须一句话标注版本**，例如"（3.10+）"。
- 不提 Python 2 的 `print` 语句、`unicode` 类型，除非在"新手坑"里一句话点明"你抄到了 Python 2 的代码"。

## 11. 验收流程（每章提交前必须走完）

写一章的完整流程（四个脚本都在 `_build/` 里，幂等，可反复跑）：

```powershell
# 在仓库根目录
$env:PYTHONIOENCODING = 'utf-8'
[Console]::OutputEncoding = [Text.Encoding]::UTF8

python site/acm/python/_build/sync.py 05          # python 块只写标记行，sync 用文件全文覆盖
python site/acm/python/_build/fill.py 05          # 空 text 块 → 真实 stdout
python site/acm/python/_build/verify.py 05        # 只查第 5 章；不传参数 = 全量
python site/acm/python/_build/gen_index.py        # 章节稳定后刷新 index.json
```

必须看到 `[OK  ]` 且退出码 0。FAIL 的处理方式：

1. `doctest 失败` → 文档里的输出与实跑不符，**改文档**（或改示例，两边必须一致）。
2. `输出不一致` → 跑一次 `fill.py`，别手改数字。
3. `代码块与示例文件内容不一致` → 跑一次 `sync.py`。
4. `缺少 # 示例：…` → 补标记行，或者这段本该是 `片段`。

> **⚠️ 易错**：`python` 块后面**必须**紧跟一个 ` ```text ` 块，否则 `fill.py` 会跳过它、`verify.py` 也不校验输出（只打印一条 `!` 警告）。看到 `!` 就去补。
