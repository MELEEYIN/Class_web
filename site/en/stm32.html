01

认识 STM32 与最小系统板第一篇 · 起步

P1 – P2 · 课程简介 / STM32 简介　·　5 节　·　4 题

入门

STM32 不是一块「神秘的黑片」，而是「一个内核 + 几条总线 + 一堆挂在总线上的外设」。学它，本质上就是学会三件事：外设的时钟挂在哪条总线上、要配哪几个寄存器、出错时先查哪一处。

读完这一课你能做到

  • 能把 STM32F103C8T6 的资源、引脚命名和存储器映射说清楚
  • 能画出 72MHz 是怎么从 8MHz 晶振一路倍频、分频出来的
  • 能解释 BOOT0 / BOOT1 的三种组合分别从哪块存储启动
  • 知道「最小系统」到底少了哪四样就跑不起来
一、芯片型号就是一张配置单

STM32F103C8T6 这串字符不是随手编的，每一位都在说参数。会读型号，选型时就不用翻半天数据手册。

字段取值含义
STM32系列ST 的 32 位 MCU，ARM Cortex-M 内核
F产品类型F = 通用型（L 低功耗、H 高性能、G 主流）
103子系列主流型，Cortex-M3，72MHz
C引脚数C = 48 脚（T=36、C=48、R=64、V=100、Z=144）
8Flash 容量8 = 64KB（6=32K、8=64K、B=128K、C=256K）
T封装T = LQFP，B = QFPN，U = UFQFPN
6温度等级6 = −40～85℃，7 = −40～105℃

所以 C8T6 = 48 脚、64KB Flash、LQFP 封装、工业温度。它属于 ST 的「中容量（Medium-density）」产品，这个档次直接决定了后面建工程时 STM32F10X_MD 这个宏不能写错。

这颗芯片的实际家底：

资源F103C8T6 的实际值对写代码的影响
内核 / 主频Cortex-M3，最高 72MHz一条指令约 13.9ns，for 空转的延时可以粗算
Flash / SRAM64KB / 20KB存字模、缓存一帧 OLED 显存（1KB）都够，别塞大数组
通用 IO37 个（可用 35 个：PA0–15、PB0–15、PC13–15）每个 GPIO 端口 16 位，正好对应寄存器低 16 位
定时器TIM1（高级）+ TIM2/3/4（通用）+ SysTick + IWDG/WWDG + RTCPWM、输入捕获、编码器都靠这几个通用定时器
通信3×USART、2×I2C、2×SPI、1×CAN、1×USB 2.0 全速一门课能把 USART/I2C/SPI 全练一遍

一个容易踩的命名坑

STM32F103C8T6 和 STM32F103CBT6 引脚完全兼容，只差 Flash（64KB vs 128KB）。所以网上卖「C8T6 升级版 CBT6」的板子是同一块 PCB；但如果你在工程里锁死了 STM32F10X_MD，换芯片时启动文件要跟着换（_md / _hd 的向量表长度不同）。

二、引脚：三组端口 + 两条「特殊线」

48 个脚里，能当普通 IO 用的是 PA0–PA15、PB0–PB15、PC13–PC15。命名规则很机械：端口字母 + 位号，PA0 就是 GPIOA 的第 0 位，对应 GPIOA->ODR 的第 0 位——寄存器的一位 = 一个引脚，这句话后面每一课都会用到。

除了通用 IO，还有几类脚必须单独记住：

引脚固定功能为什么必须记住
PA13 / PA14SWDIO / SWCLK下载调试就靠这两根，复用成普通 IO 后 ST-Link 连不上（要按住复位再下载）
PA9 / PA10USART1_TX / RX串口实验默认走这里，也是 FlyMcu 串口下载的通道
PA11 / PA12USB DM / DP板子上的 USB 口直连，别乱配
PD0 / PD1OSC_IN / OSC_OUT8MHz 晶振，配了外部晶振就不能再当 IO
PC14 / PC15OSC32_IN / OUT32.768kHz，RTC 用的
NRST复位低电平复位，板上已有 10k 上拉 + 100nF
BOOT0启动选择决定上电从 Flash 还是系统存储器启动
VBAT备份电池接纽扣电池，掉电后 RTC + BKP 才能继续走

还有一个只写在数据手册里的细节：引脚能不能接 5V。数据手册的引脚定义表里带 FT（Five-volt Tolerant）标记的脚可以输入 5V 并识别为高电平，不带 FT 的只能接 3.3V。输出永远只有 3.3V——因为整块板就供 3.3V。要驱动 5V 器件（比如某些继电器模块），中间得加三极管或电平转换。

三、最小系统：少一样都不启动

「最小系统板」之所以叫最小，是因为它只保证「芯片能跑起来」，一个外设都没多给。它必须包含四样东西：

组成板上长什么样缺了会怎样
电源3.3V LDO（常见 AMS1117-3.3）+ 若干 100nF 去耦电容芯片不工作，或跑起来随机复位
晶振8MHz 石英晶振 + 两个 20pF 负载电容只能用内部 RC（HSI，精度差、温漂大），串口波特率会偏
复位NRST 脚 10kΩ 上拉到 3.3V + 100nF 到地 + 复位按键上电复位不可靠，偶发不启动
启动配置BOOT0 经 10kΩ 下拉到地BOOT0 悬空时启动方式随机，可能进了系统存储器不跑你的程序

再加一个 SWD 排针（3.3V / GND / SWDIO / SWCLK）就能下载调试了。买板子时重点看两处：BOOT0 有没有下拉电阻（很多便宜板子只留跳线帽，拔了帽就悬空）、晶振是不是 8MHz（极少数板子用 12MHz，那样 SystemInit 里默认的 PLL 参数会算出 108MHz，超频跑飞）。

四、时钟：72MHz 是算出来的

STM32 的时钟不是「插上就是 72M」，而是一棵树：源头 → 锁相环 → 分频器 → 各条总线。搞不清这棵树，后面所有「定时器算不准、串口乱码、ADC 采样率不对」的问题都无从下手。

环节F103 的默认配置结果
时钟源HSE = 外部 8MHz 晶振（HSI = 内部 8MHz RC）8MHz
PLLHSE × 972MHz → SYSCLK
AHB 预分频÷1HCLK = 72MHz（内核、DMA、SRAM、Flash）
APB2 预分频÷1PCLK2 = 72MHz（GPIO、AFIO、USART1、ADC1/2、TIM1、SPI1）
APB1 预分频÷2PCLK1 = 36MHz（USART2/3、I2C1/2、SPI2、TIM2/3/4、PWR、BKP、WDG）

最容易记错的一条

APB1 上限是 36MHz，所以 TIM2/3/4 挂在 APB1 上——但定时器的时钟是 PCLK1 的两倍，等于 72MHz。规则是：APB 预分频 ≠ 1 时，定时器时钟 = PCLK × 2。

所以「TIM2 用 72MHz 算 PSC」是对的，而「I2C1 用 72MHz 算分频」就错了（I2C 只吃 36MHz）。这两个数在第 07 课和第 14 课会分别用到。

时钟树还解释了另一件事：为什么刚上电、SystemInit() 还没跑完的时候，芯片其实是 8MHz 的 HSI 在跑。所有「上电先延时一下」的习惯，源头都在这儿。

五、上电之后发生了什么

按下复位键到 main() 的第一行，中间隔着一段你从没写过、但每次都在跑的代码。顺序是这样的：

  1. 取栈顶与复位向量：内核从 0x08000000 读出主栈指针（MSP）初值，从 0x08000004 读出 Reset_Handler 的地址并跳过去。这也是为什么中断向量表必须放在 Flash 起始处。
  2. **Reset_Handler**（在 startup_stm32f10x_md.s 里）：调 SystemInit()，再调 __main。
  3. **SystemInit()**（system_stm32f10x.c）：开 HSE、配 PLL ×9、切 SYSCLK 到 PLL、设 AHB/APB 分频，最后把 72MHz 写进 SystemCoreClock。
  4. **__main**（编译器提供的库函数，不是你的 main）：把 .data 段从 Flash 拷到 SRAM、把 .bss 段清零、初始化堆栈，然后才跳到 main()。
  5. **main()**：你的代码从这里开始。此时全局变量已经是初值，SystemCoreClock == 72000000。

这张「启动链」还能解释两个常见现象：全局数组不初始化就是 0（.bss 被清零），而没有初始化的局部数组是随机值（在栈上，没人清）。以及为什么在 main 里改主频后，SystemCoreClock 这个变量必须同步改——所有用 SystemCoreClock 算波特率、算定时的库函数都读它。

练习做完再看答案
本课练习 · 4 题自编 · 按课程考点

  1. 一块板子上写着 STM32F103RCT6，它的 Flash 有多大、有多少个引脚、封装是什么？

    逐位拆：R = 64 脚；C = 256KB Flash；T = LQFP 封装；6 = −40～85℃。
    顺带一个结论：它是「大容量（High-density）」产品，建工程时宏要写 STM32F10X_HD，启动文件用 startup_stm32f10x_hd.s，写成 _md 会因为向量表不够长而在中断里跑飞。

  2. 为什么说「TIM2 的时钟是 72MHz，而 I2C1 的时钟是 36MHz」？两者不都在 APB1 上吗？

    都在 APB1 上，但规则不同：APB1 预分频为 2 时，PCLK1 = 36MHz。
    定时器有一条例外规则——APB 预分频 ≠ 1 时定时器时钟自动 ×2，所以 TIM2/3/4 拿到 72MHz；I2C、USART、SPI 这些外设不加倍，仍是 36MHz。
    记忆口诀：定时器翻倍，其他照旧。第 07 课算 PSC 用 72M，第 14 课算 I2C 分频用 36M。

  3. BOOT0 = 1、BOOT1 = 0 时芯片从哪启动？这个模式有什么实用价值？

    从「系统存储器」启动，也就是 ST 出厂固化的一段 Bootloader，它支持通过 USART1（PA9/PA10）接收程序。
    实用价值：没有 ST-Link 时可以用 FlyMcu 之类工具经串口下载程序（第 13 课会用到）；也能在程序把 SWD 脚复用掉、导致连不上调试器时救砖。

  4. 你写的 main() 里第一行就点亮 LED，但从复位到这一行之间，SystemInit() 已经做了哪些事？

    打开外部 8MHz 晶振并等待稳定；配置 PLL 为 HSE×9；把 SYSCLK 切到 PLL 输出 72MHz；设置 AHB ÷1、APB2 ÷1、APB1 ÷2；更新 SystemCoreClock = 72000000。
    在此之前芯片一直跑内部 HSI 8MHz，所以任何「上电立刻要求精准时序」的操作（比如马上发串口）都要考虑这段切换时间。

三、第一个 main：先把骨架立住

先不管外设，把 main.c 写成这个结构，后面所有课都在这个骨架上加东西：

#include "stm32f10x.h"                  // 器件寄存器定义（必须第一行）
#include "Delay.h"

int main(void)
{
    /* 1. 初始化：时钟由 SystemInit 配好，外设在这里逐个开 */
    LED_Init();

    /* 2. 主循环：单片机程序永远不返回 */
    while(1){
        GPIO_ResetBits(GPIOA, GPIO_Pin_0);
        Delay_ms(500);
        GPIO_SetBits(GPIOA, GPIO_Pin_0);
        Delay_ms(500);
    }
}

while(1) 不是可选项。Cortex-M3 的 main 一旦 return，会跳到启动文件里的死循环（B .），表现出来就是「程序跑了但外设全停」——新手常把它当成死机。

配套的 Delay.c 用 SysTick 做一个毫秒级延时，比 for 空转准得多，也不受编译器优化影响：

#include "stm32f10x.h"

/* 72MHz 下 SysTick 计 72000 次 = 1ms */
void Delay_us(uint32_t us)
{
    SysTick->LOAD = 72 * us;            // 重装值 = 72 × us
    SysTick->VAL  = 0x00;               // 清当前计数
    SysTick->CTRL = 0x01;               // 使能，时钟源 = HCLK（不分频）
    while(!(SysTick->CTRL & 0x00010000));  // 等 COUNTFLAG 置位
    SysTick->CTRL = 0x00;               // 关掉，避免影响别处
}

void Delay_ms(uint32_t ms)
{
    while(ms--){
        Delay_us(1000);
    }
}

  1. 建工程时忘了在 C/C++ 里加 USE_STDPERIPH_DRIVER，会出现什么现象？为什么？

    现象：GPIO_Init、RCC_APB2PeriphClockCmd 等全部报「undefined symbol」，但 #include "stm32f10x.h" 本身不报错。
    原因：stm32f10x.h 里 #include "stm32f10x_conf.h" 这段被 #ifdef USE_STDPERIPH_DRIVER 包着。宏没定义 → 配置头文件不参与编译 → 各外设的函数声明与寄存器宏都没有 → 链接找不到符号。只有寄存器级代码（直接写 GPIOA->ODR）还能过。

  2. 为什么建议把中断服务函数写在 stm32f10x_it.c 或模块自己的 .c 里，而不是 main.c？

    两个理由：① 启动文件 startup_stm32f10x_md.s 里的向量表用的是弱符号（WEAK），你在任何一个 .c 里定义同名函数都会覆盖它，所以位置随意——但集中放便于查找；② 第 06 课起中断会越来越多（EXTI、TIM、USART、ADC），全堆在 main.c 会让主逻辑被淹没，按模块分文件才管得住。

  3. Delay_us 里最后为什么要关掉 SysTick（SysTick->CTRL = 0x00）？

    不关的话，CTRL 的 ENABLE 位一直是 1，SysTick 会持续重装、持续产生 COUNTFLAG；如果别处（比如 RTOS 或后面的定时器实验）也要用 SysTick，就会互相打架。
    另一个更隐蔽的后果：LOAD/VAL 被这次延时改过，别人再读到的就不是自己设的值了。用完即关、下次重设，是「借用」外设的基本礼貌。

  4. 用 for(i=0;i<1000000;i++); 做延时，为什么在 Debug 版能闪、Release 版不闪了？

    因为空循环没有任何副作用，编译器开优化（-O2 以上）会直接把它删掉，等于没有延时，LED 闪烁快到看不见（看起来像常亮）。
    正确做法：延时用 SysTick 或定时器（有硬件副作用，删不掉）；确实要用空循环时，循环变量加 volatile 并确认编译器不会优化掉。这也是第 07 课要学硬件定时器的原因之一。

P5 – P6 · GPIO 输出 / LED 流水灯与蜂鸣器　·　5 节　·　4 题

基础

输出就是把寄存器某一位写成 0 或 1；但写之前必须先做两件事——给这个端口开时钟、把引脚配成「输出」。忘了第一步，写进去的值永远不会出现在脚上。

读完这一课你能做到

  • 能背出 GPIO 的八种工作模式，说清推挽和开漏的区别
  • 能独立写出「开时钟 → 配结构体 → 初始化 → 读写」四步
  • 能做出 LED 闪烁、八灯流水、蜂鸣器三种现象
  • 能解释为什么套件上的 LED 是低电平点亮
一、八种模式：四进四出

每个 GPIO 引脚背后是一小片电路，通过两个配置寄存器（CRL 管 0–7 位，CRH 管 8–15 位）里的 4 个比特选择模式。八种模式可以分成两半：

模式库里的宏电路状态什么时候用
浮空输入GPIO_Mode_IN_FLOATING上下拉都断开外部已有确定电平（如串口 RX、编码器）
上拉输入GPIO_Mode_IPU内部 40kΩ 接到 VDD按键一端接地，没按下时读 1
下拉输入GPIO_Mode_IPD内部 40kΩ 接到 VSS按键一端接 VDD，没按下时读 0
模拟输入GPIO_Mode_AIN上下拉断开，数字部分关闭ADC 采集电压（第 11 课）
推挽输出GPIO_Mode_Out_PPP-MOS + N-MOS 都能导通驱动 LED、蜂鸣器、普通数字信号
开漏输出GPIO_Mode_Out_OD只有 N-MOS，只能拉低I2C 的 SDA/SCL（第 14 课）、电平转换
复用推挽GPIO_Mode_AF_PP引脚交给片上外设控制PWM 输出、SPI 的 SCK/MOSI、USART 的 TX
复用开漏GPIO_Mode_AF_OD同上，但只能拉低硬件 I2C 的 SCL/SDA

推挽 vs 开漏是这一课唯一需要动脑的地方：

  • 推挽：想输出高就打开上面的 P-MOS（接到 3.3V），想输出低就打开下面的 N-MOS（接到 GND）。两种状态都是「主动驱动」，所以带负载能力强、边沿陡。
  • 开漏：上面那只管子根本不存在，只能主动拉低；要输出高，只能靠外部上拉电阻把线「拉」上去。好处是可以做线与——I2C 总线上任何一个从机拉低，整条线就是低，主机就知道有人在应答。这就是 I2C 必须用开漏的原因。

复用模式最容易犯的错

配了 GPIO_Mode_AF_PP 却忘了开外设时钟（比如 TIM2），引脚就变成「悬空的高阻态」：示波器上没有波形，程序却一切正常。凡是「代码看起来对、脚上没信号」，先查外设时钟。

二、四步配置法

标准库把所有外设的初始化都统一成了这个套路，后面每一课都是它的变体：

  1. 开时钟：GPIOA 挂在 APB2 上 → RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
  2. 填结构体：GPIO_InitTypeDef 有三个成员——GPIO_Pin（哪几位）、GPIO_Mode（哪种模式）、GPIO_Speed（输出速度 2/10/50MHz）
  3. 调初始化：GPIO_Init(GPIOA, &GPIO_InitTypeDef 变量);
  4. 读写：输出用 GPIO_SetBits / GPIO_ResetBits / GPIO_WriteBit；输入用 GPIO_ReadInputDataBit

第 2 步里的 GPIO_Speed 只对输出模式有意义，它决定输出驱动器的翻转速率。驱动 LED、蜂鸣器这种慢速负载，GPIO_Speed_2MHz 就够；跑 SPI、PWM 高速信号才需要 50MHz。选太快会增加电磁干扰和功耗，选太慢波形会变钝。

三、点亮八个 LED：流水灯

套件上的八位 LED 模块是这样接的：八个 LED 的阳极一起接 3.3V，阴极各经限流电阻接到 PA0–PA7。所以 IO 输出低电平（0）灯亮，输出高电平（1）灯灭。这一点如果搞反了，现象就是「写 1 反而亮」，程序看起来完全没毛病。

#include "stm32f10x.h"
#include "Delay.h"

void LED_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   // ① 开 GPIOA 时钟

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;       // 推挽输出
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_All;           // PA0~PA7 一次配完
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);                  // ② 写进寄存器

    GPIO_SetBits(GPIOA, GPIO_Pin_All);                      // 全部熄灭（高电平）
}

/* 八灯流水：每次只让低 8 位里的一位为 0，高 8 位原样保留 */
void LED_Flow(void)
{
    uint8_t i;
    for(i = 0; i < 8; i++){
        uint16_t keep = GPIO_ReadOutputData(GPIOA) & 0xFF00;   // 保住 PA8~PA15
        GPIO_Write(GPIOA, keep | (~(0x0001 << i) & 0x00FF));
        Delay_ms(120);
    }
}

GPIO_Pin_All 是 0xFFFF，会把 PA0–PA15 全部配成推挽输出。这里 PA8–PA15 没用上，配了也无害（不接线就是悬空输出）；但要养成习惯：只配自己用的位，否则以后接别的东西会冲突（比如 PA13/PA14 是 SWD，配成普通输出就把调试口占了）。

GPIO_Write 是整端口写 16 位，比逐个 SetBits/ResetBits 快，适合流水灯这种整体刷新。但它写的是 ODR 的整个低 16 位，所以必须先把高 8 位的原值取出来拼回去，否则 PA8–PA15 会被顺手改掉。

GPIO_Write 的陷阱

GPIO_Write(GPIOA, ~(0x0001 << i)) 传入的是 0xFFFE 这类值，高 8 位被写成 1（对 PA8–15 是「输出高」）。如果 PA8–15 上还接了别的东西，会被误动作。

更稳的写法是只改低 8 位：GPIO_Write(GPIOA, (GPIO_ReadOutputData(GPIOA) & 0xFF00) | (~(0x0001 << i) & 0x00FF));

或者干脆用 GPIO_ResetBits(GPIOA, 0x0001 << i); GPIO_SetBits(GPIOA, ~(0x0001 << i) & 0x00FF);。流水灯看不出差别，但接上别的东西就会出问题。

四、蜂鸣器：先分清有源还是无源
类型内部结构给什么信号怎么判断
有源蜂鸣器内部自带振荡电路给高/低电平就响，频率固定直接接 3.3V 和 GND 就「滴」一声
无源蜂鸣器只有电磁线圈，靠外部方波驱动必须给 2–5kHz 方波，频率决定音调接直流不响，接方波才响

套件里通常是有源蜂鸣器，接 PB12，配置和 LED 一模一样：

#define BEEP_PORT  GPIOB
#define BEEP_PIN   GPIO_Pin_12

void BEEP_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Pin   = BEEP_PIN;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(BEEP_PORT, &GPIO_InitStructure);

    GPIO_ResetBits(BEEP_PORT, BEEP_PIN);    // 关掉（低电平不响）
}

有源蜂鸣器的工作电流常在 20–30mA，而 STM32 单个 IO 的绝对最大输出是 25mA（推荐 8mA 以内）。直接接能用，但声音偏小、长期跑会发热。规范做法是 IO 驱动一个 NPN 三极管（如 S8050）或 MOS 管，蜂鸣器接在集电极回路上，基极串 1kΩ 电阻。

  1. 套件上的 LED 阳极接 3.3V，阴极接 PA0。要让 LED 亮，应该给 PA0 写 0 还是 1？为什么？

    写 0（低电平）。LED 导通条件是阳极电位高于阴极电位并超过正向压降（红色约 1.8V）。阳极固定 3.3V，只有阴极被拉到 0V 时才有压差，电流才会流过。
    如果写 1（3.3V），两端等电位，没有电流，灯不亮。所以这类接法叫「低电平驱动」，初始化时要把引脚先置高（熄灭），避免上电瞬间闪一下。

  2. 想把 PA8 配成推挽输出，但只写了 GPIO_Init(GPIOA, ...) 却把 GPIO_Pin 设成 GPIO_Pin_0，PA8 会有输出吗？

    不会。GPIO_Pin 决定「配哪几位」，GPIO_Pin_0 只把第 0 位的配置写进 CRL，PA8 对应的 CRH 位没动，仍是复位后的默认值——浮空输入。
    这时对 PA8 调 GPIO_SetBits 只会改 ODR 的第 8 位，但引脚处于输入模式，输出驱动器没打开，脚上测不到电平。这是「写代码没错、示波器没波形」的经典原因。

  3. 为什么 I2C 的 SDA/SCL 一定要配成开漏（或复用开漏），而不能用推挽？

    因为 I2C 是多主多从的总线，一条线上挂着多个器件。推挽输出高电平时会主动把线拉到 3.3V，若另一个器件此时输出低电平（拉地），两只管子直接对通，形成大电流，可能烧引脚。
    开漏只能主动拉低、靠外部上拉电阻恢复高电平，天然实现「线与」：任何一方拉低，线就是低。这也是 I2C 必须外接 4.7kΩ 上拉电阻的原因——没有上拉，开漏永远输出不了高电平。

  4. 有源蜂鸣器接在 PB12 上，程序里一直给它 1kHz 方波，声音会变吗？

    不会变调。有源蜂鸣器内部自带振荡电路，外部给的方波只是「开关」，音调由它自己的振荡频率决定；给 1kHz 或 10kHz 方波，听到的都是同一个音，只是可能因为占空比变化而音量略有不同。
    想要不同音调（比如播放简单旋律），必须换无源蜂鸣器，用 PWM 给不同频率的方波——这正是第 08 课 PWM 输出比较的用途。

基础

输入不是「读一下就完事」。一个引脚如果什么都不接，读回来的值是随机的——所以输入的第一件事是给它一个确定的默认电平；第二件事是处理机械按键的抖动。

读完这一课你能做到

  • 能根据按键的接法选对上拉/下拉/浮空输入，而不是背模式表
  • 能写出带 20ms 消抖、支持「按下/松开」两种触发的按键函数
  • 能说清为什么按键要消抖，以及抖动在示波器上是什么样
  • 能用光敏模块的数字输出控制蜂鸣器
一、为什么输入必须先「定一个默认值」

数字输入只有两种解读：高或低。但引脚如果悬空（什么都没接），它既不是高也不是低——它是一根天线，会捡周围的电磁噪声。这时读 IDR 得到的是随机 0/1，程序就会「自己乱跳」。

解决办法是给引脚接一个电阻，把它「默认」拉到某一侧：

接法内部配置空闲时读到按键接法按下时读到
上拉输入GPIO_Mode_IPU（内部 40kΩ 接 VDD）1按键另一端接 GND0
下拉输入GPIO_Mode_IPD（内部 40kΩ 接 VSS）0按键另一端接 VDD1
浮空输入GPIO_Mode_IN_FLOATING不确定外部已有上/下拉电阻取决于外部

嵌入式里九成的按键都是「一端接 IO、一端接 GND」+ 上拉输入，因为这样按键不按下时 IO 是确定的高电平，而且 GND 到处都有，接线最省事。代价是逻辑反了：读到 0 才表示按下。这个「反逻辑」是按键代码里最常见的 bug 来源。

用内部上拉还是外部上拉

内部上拉约 40kΩ，够用但偏弱：杜邦线拉长到 20cm 以上、或者旁边有电机干扰时，可能被耦合噪声拉低。工业上一般用外部 10kΩ 上拉 + 100nF 电容滤波。学习阶段用内部上拉完全够，遇到「没按也乱触发」再补外部电阻。

二、机械按键的抖动：为什么必须消抖

轻触按键内部是金属弹片。按下和松开的瞬间，弹片会在接触点之间弹跳 5–20ms，电压在 0 和 1 之间来回跳好几次。如果主循环跑得足够快（72MHz 下几微秒一轮），一次按键会被读成「按下 → 松开 → 按下 → 松开」好几次。

三种消抖方式：

方式做法优点缺点
延时消抖读到变化后 Delay_ms(20) 再读一次代码最短，易懂阻塞 20ms，期间别的事都干不了
定时扫描每 10ms 由定时中断采样，连续两次相同才认不阻塞，可同时处理多个键需要定时器（第 07 课）
状态机记录「稳定态 + 计时」，松手才算一次最严谨，能区分长按短按代码稍长

本课先用延时消抖把现象做出来；第 07 课有了定时中断，再改成非阻塞版本——这是从「能跑」到「能用在产品里」的一步。

三、按键代码：读、消抖、返回键值
#include "stm32f10x.h"
#include "Delay.h"

void Key_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;      // 上拉输入
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_1 | GPIO_Pin_11;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);
}

/* 返回：0 = 没按，1 = KEY1 按下，2 = KEY2 按下；松手才返回一次 */
uint8_t Key_GetNum(void)
{
    static uint8_t last = 0;                            // 上一次的稳定状态
    uint8_t now = 0;

    if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1)  == 0) now = 1;
    if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11) == 0) now = 2;

    if(now != 0 && last == 0){                          // 出现「按下」的跳变
        Delay_ms(20);                                   // 等抖动过去
        if(GPIO_ReadInputDataBit(GPIOB, now == 1 ? GPIO_Pin_1 : GPIO_Pin_11) == 0){
            last = now;
            while(GPIO_ReadInputDataBit(GPIOB, now == 1 ? GPIO_Pin_1 : GPIO_Pin_11) == 0);
            last = 0;                                   // 等松手，避免连发
            return now;
        }
    }
    return 0;
}

三个细节值得说：

  • **GPIO_ReadInputDataBit 读的是 IDR（输入数据寄存器）**，不是 ODR。用错函数（比如写成 GPIO_ReadOutputDataBit）读到的是「你让它输出什么」，不是「脚上实际是什么」，按键永远读不到。
  • **while(引脚 == 0); 等松手**，让一次按压只返回一次。不然按住不放，主循环每轮都返回一次，LED 会闪成一片。
  • **static 变量记住上一次状态**，才能区分「一直按着」和「刚按下」。去掉 static 就是每轮都当成新按下。
四、光敏传感器：读别人算好的结果

光敏模块（套件里常见的那种三针/四针小板）内部是「光敏电阻 + 比较器（LM393）」：光敏电阻分压后与电位器设定的阈值比较，结果直接以数字高低电平从 DO 脚输出。所以对 STM32 来说，它和按键没有区别——一个会自己变的数字输入。

引脚作用接法
VCC / GND供电3.3V / GND
DO数字输出（阈值比较结果）接 PB13，配浮空或上拉输入
AO模拟输出（光敏电阻分压原值）接 PA0，第 11 课用 ADC 读
/* 光越暗 → DO 输出高（具体极性看模块电位器，先实测一次） */
void Light_Beep(void)
{
    if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13) == 1){
        GPIO_ResetBits(GPIOB, GPIO_Pin_12);    // 有源蜂鸣器低电平响
    }else{
        GPIO_SetBits(GPIOB, GPIO_Pin_12);
    }
}

不要猜 DO 的极性

不同厂家的光敏模块，比较器同相/反相端接法不同，遮光时 DO 可能是高也可能是低。拿到模块先用万用表量一次：遮住 → 记下电平；照光 → 再记一次。猜错的结果是「逻辑全反」，代码看起来完全正确。

五、把输入接进主循环
int main(void)
{
    uint8_t key;

    LED_Init();
    BEEP_Init();
    Key_Init();

    while(1){
        key = Key_GetNum();
        if(key == 1){                          // KEY1：翻转 LED1
            static uint8_t s = 0;
            s = !s;
            if(s) GPIO_ResetBits(GPIOA, GPIO_Pin_0);
            else  GPIO_SetBits(GPIOA, GPIO_Pin_0);
        }
        if(key == 2){                          // KEY2：蜂鸣器响一下
            GPIO_ResetBits(GPIOB, GPIO_Pin_12);

            GPIO_SetBits(GPIOB, GPIO_Pin_12);

}

这个主循环有个隐患：Key_GetNum 里的 Delay_ms(20) 和 while(等松手) 会卡住整个循环。按键按住不放时，Light_Beep() 就不再执行了。学习阶段无所谓，但这也正是第 06 课要学外部中断、第 07 课要学定时扫描的动机——把「等事件」变成「事件来找我」。

  1. 按键一端接 PB1、另一端接 GND，程序里却把 PB1 配成了下拉输入（GPIO_Mode_IPD），会出现什么现象？

    下拉输入时空闲电平被内部 40kΩ 拉到 0，按下接 GND 也是 0，读到的永远是 0——现象是「一直显示按下」，或者按住和不按没区别。
    正确配置是上拉输入（GPIO_Mode_IPU）：空闲读到 1，按下被 GND 拉低读到 0。反过来，如果按键接的是 VDD，就要用下拉输入。

  2. 为什么 Key_GetNum 里要用 while(引脚 == 0); 等松手？去掉会怎样？

    去掉后，只要手按着，主循环每转一圈就检测到一次「按下」，1 秒能触发几万次。如果是「翻转 LED」，看起来是 LED 半亮；如果是「计数」，数字会疯长。
    加了这个循环，一次按压只产生一次返回值。代价是按住不放时程序卡在这里——这就是「阻塞式按键」的本质缺陷，后面用定时扫描替代。

  3. GPIO_ReadInputDataBit 和 GPIO_ReadOutputDataBit 在读按键时有什么区别？

    ReadInputDataBit 读 IDR，反映引脚上的实际电平（外部电路决定的），按键必须用这个。
    ReadOutputDataBit 读 ODR，反映你让它输出什么。在输入模式下 ODR 只用于存上拉/下拉的配置，和外部电平无关，所以读按键会永远得到同一个值。

  4. 光敏模块的 DO 接到 PB13，你希望「天黑时蜂鸣器响」，但实测是「天亮时响」。不改硬件，代码上怎么修最简单？

    把判断条件取反：if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13) == 0)。因为模块的比较器极性由厂家接法决定，软件取反等价于换极性。
    更彻底的做法是改硬件：调模块上的电位器（改变阈值）或交换比较器两个输入。软件取反最省事，但要在注释里写清「此模块遮光输出低」，否则下次换模块又要重新试。

OLED：用软件 I2C 驱动 SSD1306第二篇 · GPIO 与显示

基础

OLED 不是「一个能写字的东西」，而是一块 128×64 的显存加一个扫描控制器。你要做的只有一件：把字节写到显存里正确的位置上，屏幕自己去扫。所以这一课真正的难点不是「显示」，是「怎么把那 1024 个字节送过去」——也就是软件 I2C 的时序。

读完这一课你能做到

  • 能说清 SSD1306 的页结构，以及「一个字节管 8 个像素」是怎么回事
  • 能徒手写出软件 I2C 的起始、停止、写字节、读应答四个函数
  • 能初始化一块 0.96 寸 OLED，并显示字符、汉字、数字
  • 遇到「花屏 / 全黑 / 乱码」时，知道分别先查哪里
一、显存：1024 个字节管 8192 个像素

0.96 寸 OLED 的控制器是 SSD1306，分辨率 128×64。它的显存（GDDRAM）按「页（page）」组织：每页 8 行像素，共 8 页，每页 128 列，每列 1 个字节。

概念数值关系
屏幕像素128 × 64横向 128 列，纵向 64 行
页（page）8 页每页 8 行 → 8 × 8 = 64 行
显存总量128 × 8 = 1024 字节每字节管一列上的 8 个像素
坐标写法(x, page)x = 0–127，page = 0–7

一个字节的 8 个位，垂直排列：最低位在最上面。所以往 (x=0, page=0) 写 0x01，屏幕左上角第 1 个像素亮；写 0xFF，那一列的前 8 个像素全亮。字号必须是 8 的倍数（8×16、16×16 等），根源就在这里——一页正好 8 行，跨页就要拼两次。

为什么 OLED 特别适合调试

单片机没有屏幕，printf 又要占串口。一块 OLED 只要两根 IO，能实时显示变量名和值，比反复烧程序看 LED 高效得多。课程里从第 05 课开始，几乎所有实验都用它显示状态。

二、软件 I2C：四根线里的两根，靠 IO 模拟

硬件 I2C 外设（第 14 课）还没学，先用手动翻转 IO 的方式模拟 I2C 时序，好处是「时序全在你手里」，看得见、好调试。

接线（软件 I2C，套件默认）：

OLED 引脚接 STM32配置
VCC3.3V—
GNDGND—
SCLPB8开漏输出（GPIO_Mode_Out_OD）
SDAPB9开漏输出（读应答时临时切输入）

I2C 的四个基本动作，本质都是「拉低 / 释放」：

  1. 起始（Start）：SCL 高电平时，SDA 由高变低。
  2. 停止（Stop）：SCL 高电平时，SDA 由低变高。
  3. 写一位：SCL 低时改 SDA，然后 SCL 拉高让从机采样。
  4. 应答（ACK）：主机释放 SDA（切输入），发第 9 个时钟，读到 0 表示从机应答。
#include "stm32f10x.h"
#include "Delay.h"

#define SCL_H  GPIO_SetBits(GPIOB, GPIO_Pin_8)
#define SCL_L  GPIO_ResetBits(GPIOB, GPIO_Pin_8)
#define SDA_H  GPIO_SetBits(GPIOB, GPIO_Pin_9)
#define SDA_L  GPIO_ResetBits(GPIOB, GPIO_Pin_9)
#define SDA_R  GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_9)

void MyI2C_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_OD;   // 开漏：只能拉低
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_8 | GPIO_Pin_9;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    SCL_H; SDA_H;                                       // 空闲时都为高
}

void MyI2C_Start(void)
{
    SDA_H; SCL_H; Delay_us(2);
    SDA_L; Delay_us(2);                                 // SCL 高时 SDA 下降 = 起始
    SCL_L; Delay_us(2);
}

void MyI2C_Stop(void)
{
    SDA_L; SCL_H; Delay_us(2);
    SDA_H; Delay_us(2);                                 // SCL 高时 SDA 上升 = 停止
}

void MyI2C_SendByte(uint8_t byte)
{
    uint8_t i;
    for(i = 0; i < 8; i++){
        if(byte & 0x80) SDA_H; else SDA_L;              // 先发最高位
        byte <<= 1;
        Delay_us(2);
        SCL_H; Delay_us(2);
        SCL_L; Delay_us(2);
    }
}

uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t ack;
    SDA_H; Delay_us(2);                                 // 释放 SDA，交给从机
    SCL_H; Delay_us(2);
    ack = SDA_R;                                        // 0 = 应答
    SCL_L; Delay_us(2);
    return ack;
}

开漏配置 + 没有外部上拉电阻时，SDA_H 只是「松手」，电平靠 OLED 模块板上的上拉电阻恢复——这也是为什么开漏必须配上拉。

三、命令和数据：同一个地址，两种字节

SSD1306 的从机地址是 7 位 0x3C，写成 8 位就是写 0x78、读 0x79。每次传输第一个字节是地址，第二个字节是控制字节，决定后面跟的是命令还是数据：

控制字节含义典型内容
0x00后面全是命令初始化、设置坐标、开关显示
0x40后面全是数据（写进显存）字模点阵
void OLED_WriteCommand(uint8_t cmd)
{
    MyI2C_Start();
    MyI2C_SendByte(0x78);        // 从机地址 + 写
    MyI2C_ReceiveAck();
    MyI2C_SendByte(0x00);        // 控制字节：命令
    MyI2C_ReceiveAck();
    MyI2C_SendByte(cmd);
    MyI2C_ReceiveAck();
    MyI2C_Stop();
}

void OLED_WriteData(uint8_t *data, uint8_t count)
{
    uint8_t i;
    MyI2C_Start();
    MyI2C_SendByte(0x78);
    MyI2C_ReceiveAck();
    MyI2C_SendByte(0x40);        // 控制字节：数据
    MyI2C_ReceiveAck();
    for(i = 0; i < count; i++){
        MyI2C_SendByte(data[i]);
        MyI2C_ReceiveAck();
    }
    MyI2C_Stop();
}

一次 Start…Stop 里可以连续写多个字节，SSD1306 会自动把地址往后加。所以写一个 16×16 汉字（32 字节）只需要一次 Start，比「每字节一次 Start」快得多，也更稳。

四、初始化：一串固定命令

初始化不需要理解每一条，但要知道哪几条最关键：

void OLED_Init(void)
{
    Delay_ms(100);                       // 上电后等电源稳定，否则可能白屏

    OLED_WriteCommand(0xAE);             // 关显示
    OLED_WriteCommand(0xD5); OLED_WriteCommand(0x80);   // 时钟分频
    OLED_WriteCommand(0xA8); OLED_WriteCommand(0x3F);   // 复用率 64 行
    OLED_WriteCommand(0xD3); OLED_WriteCommand(0x00);   // 显示偏移 0
    OLED_WriteCommand(0x40);             // 起始行 = 0
    OLED_WriteCommand(0xA1);             // 左右方向：正常（0xA0 为镜像）
    OLED_WriteCommand(0xC8);             // 上下方向：正常（0xC0 为翻转）
    OLED_WriteCommand(0xDA); OLED_WriteCommand(0x12);   // COM 引脚配置
    OLED_WriteCommand(0x81); OLED_WriteCommand(0xCF);   // 对比度
    OLED_WriteCommand(0xD9); OLED_WriteCommand(0xF1);   // 预充电周期
    OLED_WriteCommand(0xDB); OLED_WriteCommand(0x30);   // VCOMH
    OLED_WriteCommand(0xA4);             // 显示跟随显存
    OLED_WriteCommand(0xA6);             // 正常显示（0xA7 为反色）
    OLED_WriteCommand(0x8D); OLED_WriteCommand(0x14);   // 开电荷泵（不开不亮）
    OLED_WriteCommand(0xAF);             // 开显示

}

0x8D 0x14 这一条最容易被漏：不开电荷泵，屏幕有显存但一点都不亮，现象是「代码全对、屏幕全黑」。

五、写字：把字模铺到正确的位置

显示一个 8×16 的字符，要写 16 个字节：上半页 8 个（page p），下半页 8 个（page p+1）。先把光标定到 (x, page)：

void OLED_SetCursor(uint8_t page, uint8_t x)
{
    OLED_WriteCommand(0xB0 | page);                 // 页地址 0~7
    OLED_WriteCommand(0x10 | (x & 0xF0) >> 4);      // 列地址高 4 位
    OLED_WriteCommand(0x00 | (x & 0x0F));           // 列地址低 4 位
}

/* 显示一个 8x16 的 ASCII 字符，x 为 0~127，page 为 0~6 */
void OLED_ShowChar(uint8_t page, uint8_t x, char ch)
{
    uint8_t i, buf[16];

    ch = ch - ' ';                                  // 字库从空格开始
    for(i = 0; i < 8; i++)  buf[i]     = OLED_F8x16[ch][i];       // 上半部分
    for(i = 0; i < 8; i++)  buf[i + 8] = OLED_F8x16[ch][i + 8];   // 下半部分

    OLED_SetCursor(page, x);
    OLED_WriteData(buf, 8);                         // 写上半页
    OLED_SetCursor(page + 1, x);
    OLED_WriteData(buf + 8, 8);                     // 写下半页
}

字模从哪来？用取模软件（PCtoLCD2002）按固定参数生成，课程配套的 OLED_Font.h 已经取好。参数必须和代码里的读取方式一致，否则字是「花」的：

取模参数课程采用选错的表现
字模选项阴码选阳码 → 字变成黑底白字（反色）
取模走向列行式（逐列）选逐行 → 字被旋转 90° 或错位
字节内位序逆向（低位在前）选顺向 → 每个字节上下翻转，字是碎的
输出格式C51 格式十六进制格式要自己加 0x

90% 的「花屏」都是这三件事

① 字模参数不对（字是碎的、反的）；② 坐标算错（写到屏幕外，SSD1306 会绕回来覆盖别处）；③ page 传了 7 还写两页（page+1 = 8 越界，屏幕行为不可预测）。

先测一行纯 ASCII，通了再上汉字——汉字 32 字节跨两页，出错时更难判断是哪一步错。

  1. SSD1306 的显存是 1024 字节，可屏幕有 8192 个像素，为什么够用？

    因为它是单色屏：一个像素只要 1 位（亮/灭）。1024 字节 = 8192 位，正好对应 8192 个像素。
    组织方式是「一列 8 个像素打包成一个字节」，所以 8 页 × 128 列 × 8 位 = 8192。这也是字号必须是 8 的倍数的原因。

  2. 代码编译下载都正常，OLED 一点反应都没有（全黑）。最可能漏了哪条命令？

    漏了开电荷泵：OLED_WriteCommand(0x8D); OLED_WriteCommand(0x14);。SSD1306 的 OLED 面板需要 7–9V 驱动电压，靠内部电荷泵升压，不开就完全不亮。
    其次是 0xAF（开显示）和上电延时 Delay_ms(100)。排查顺序：先量 VCC 有没有 3.3V → 再看 I2C 有没有应答（ReceiveAck 返回 0 才正常）→ 最后查初始化序列。

  3. 显示出来的汉字是「碎块」或上下颠倒，问题出在哪？

    字模的取模参数和代码的读取方式不匹配。课程字库按「阴码 + 列行式 + 逆向（低位在前）」生成，若软件里选了「逐行」或「顺向」，每个字节的 8 个位顺序就不对，字就碎了。
    修法不是改代码，而是重新取模：在 PCtoLCD2002 里把「取模走向」设为列行式、「字节内位序」设为逆向，重新生成数组替换 OLED_Font.h。

  4. 为什么写一个 32 字节的汉字，最好放在一次 Start…Stop 里连续发，而不是每字节都 Start 一次？

    I2C 每次 Start/Stop 都有额外时序开销，且 SSD1306 内部地址指针在 Stop 后不会自动归位到「接着写」，多次 Start 容易出现地址错位。
    连续写时控制器会自动递增列地址，一次传完 32 字节最稳也最快。同理 OLED_Clear 应该一次写 128 字节的空白缓冲，而不是逐字节调用。

EXTI 外部中断：红外计次与旋转编码器第三篇 · 中断与定时器

P11 – P12 · EXTI 外部中断 / 对射式红外计次、旋转编码器计次　·　6 节　·　4 题

进阶

轮询是「我一遍遍问你有没有事」，中断是「有事你直接来找我」。前者把 CPU 浪费在等待上，后者把响应时间从「一圈循环」压到「几个时钟」。代价是：中断里发生的每一件事，都要有人负责收尾。

读完这一课你能做到

  • 能画出「引脚 → AFIO → EXTI → NVIC → CPU」这条链路，并说清每一级要配什么
  • 能独立配置一路下降沿中断，并在中断函数里完成计数
  • 能解释抢占优先级与响应优先级的区别，知道什么时候会嵌套
  • 能用 EXTI 做红外计次和旋转编码器判向
一、中断链路：信号从引脚到 CPU 要走四步

一个外部电平变化要变成「CPU 跳去执行你的函数」，中间经过四道关：

环节作用要配的东西
GPIO引脚的电平输入模式（上拉/下拉/浮空）
AFIO把哪个端口接到 EXTI 线上GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource14)
EXTI选触发边沿、开中断屏蔽EXTI_InitTypeDef：EXTI_Line、EXTI_Mode、EXTI_Trigger、EXTI_LineCmd
NVIC给这条中断线排优先级、使能NVIC_InitTypeDef：NVIC_IRQChannel、抢占/响应优先级、NVIC_IRQChannelCmd

第一道关最容易忽略的细节：EXTI 只有 16 条线（EXTI0–EXTI15），每条线对应「所有端口的同号引脚」。也就是说 PA0、PB0、PC0 共用 EXTI0，同一时刻只能选一个端口接上去。这个「多选一」的开关就在 AFIO 的 EXTICR 寄存器里，所以用 EXTI 必须先开 AFIO 时钟：

RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);
GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource14);   // 把 PB14 接到 EXTI14
二、触发方式：三种边沿
触发什么时候触发典型场景
上升沿低 → 高按键「松开」、编码器某一相
下降沿高 → 低按键「按下」、红外遮挡
双边沿任何变化旋转编码器 A/B 相（两次变化都要数）

对于「一端接 GND 的按键」，按下瞬间是下降沿。所以按键中断用下降沿，红外对射管被遮挡的瞬间也是下降沿（输出从高变低）。

为什么中断里不能写 Delay_ms(20) 消抖

中断服务函数执行期间，同优先级及更低优先级的中断都进不来。在里面 Delay_ms(20)，等于把系统冻结 20ms——如果有串口数据在这时到达，就会丢字节（USART 只有 1 字节缓冲）。

正确做法：中断里只做「计数 / 置标志」，消抖放到主循环或定时扫描里做。第 07 课的定时中断就是干这个的。

三、优先级：两个数字，两件事

Cortex-M3 的 NVIC 给每个中断两个优先级：抢占优先级（preemption）和响应优先级（subpriority）。规则只有两条：

  • 抢占优先级高的可以打断低的（发生嵌套）。
  • 抢占优先级相同时，响应优先级高的先执行，但不能打断（谁已经在跑就让它跑完）。

F103 的优先级是 4 位，可以自由切分成「几位给抢占、几位给响应」。常用分组是 NVIC_PriorityGroup_2：2 位抢占（0–3）+ 2 位响应（0–3）。

设置抢占响应结果
A: 1, 010能被抢占 0 的中断打断
B: 2, 020优先级低于 A，不能打断 A
C: 1, 111与 A 抢占相同 → 不能打断 A，A 结束后按响应优先级排队

数字越小优先级越高。这条「越小越高」和直觉相反，配反了会出现「串口中断把定时器中断饿死」这类怪现象。

四、五步配置 + 中断函数
#include "stm32f10x.h"

uint16_t IR_Count = 0;          // 遮挡次数（中断里改，主循环里读）

void IR_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    EXTI_InitTypeDef EXTI_InitStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    /* ① 时钟：GPIOB + AFIO（用 EXTI 必须开 AFIO） */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);

    /* ② 引脚：上拉输入，遮挡时被拉低 */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_14;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    /* ③ 把 PB14 接到 EXTI14，并选下降沿触发 */
    GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource14);
    EXTI_InitStructure.EXTI_Line    = EXTI_Line14;
    EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);

    /* ④ NVIC：给 EXTI15_10 这条通道开中断 */
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitStructure.NVIC_IRQChannel = EXTI15_10_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}

/* ⑤ 中断服务函数：名字必须和启动文件里的一致 */
void EXTI15_10_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line14) == SET){
        IR_Count++;                                  // 只做计数
        EXTI_ClearITPendingBit(EXTI_Line14);         // 必须清标志
    }
}

注意 NVIC 里的 NVIC_IRQChannel 填的是中断通道，不是 EXTI 线号。STM32 把 16 条 EXTI 线打包成了 3 个通道：EXTI0_IRQn、EXTI1_IRQn、EXTI2_IRQn、EXTI3_IRQn、EXTI4_IRQn、EXTI9_5_IRQn（5–9 共用）、EXTI15_10_IRQn（10–15 共用）。所以 PB14 走的是 EXTI15_10_IRQHandler，函数里还要再用 EXTI_GetITStatus 判断是哪条线——因为 10–15 共用一个入口。

五、旋转编码器：两次边沿判方向

旋转编码器内部是两片相位差 90° 的触点（A 相、B 相）。正转时 A 超前 B，反转时 B 超前 A。每个「咔哒」位置，两相各变化一次，所以一个机械位置会产生两次边沿。

最简单的判向方法：A 相双边沿中断，读 B 相电平。

int16_t Encoder_Count = 0;

void Encoder_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    EXTI_InitTypeDef EXTI_InitStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;       // 编码器是开集输出，必须上拉
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0 | GPIO_Pin_1;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    /* A 相 PB0：双边沿 */
    GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0);
    EXTI_InitStructure.EXTI_Line    = EXTI_Line0;
    EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Rising_Falling;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}

void EXTI0_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line0) == SET){
        if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_0) == 0){   // A 相下降沿
            if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 1) Encoder_Count--;  // 反转
            else                                             Encoder_Count++;  // 正转
        }else{                                                // A 相上升沿
            if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 1) Encoder_Count++;
            else                                             Encoder_Count--;
        }
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
}

方向的正负取决于 A/B 谁接哪个脚、以及编码器型号。第一次用一定要手动转一圈确认符号，别指望「正转就是加」。

中断里该做什么，不该做什么

该做：读数据寄存器、置标志、计数、清中断标志。

不该做：Delay、printf、浮点运算（M3 无 FPU，软件模拟很慢）、动态内存分配、长循环。

判断标准：中断函数应该在几微秒内返回。超过 10μs 就要考虑「只置标志，主循环处理」。

  1. 为什么用 EXTI 之前必须开 AFIO 时钟？不开会怎样？

    因为「把哪个端口接到哪条 EXTI 线」这件事由 AFIO 的 EXTICR 寄存器控制。不开 AFIO 时钟，GPIO_EXTILineConfig 写进去的值不生效，引脚和 EXTI 线之间没有连接。
    现象是：GPIO 输入读得到变化（主循环轮询能看到），但中断永远不进。这类「引脚有信号、中断不响应」的问题，先查 AFIO 时钟。

  2. PA0 和 PB0 都想做外部中断，能同时用吗？为什么？

    不能。EXTI 只有 16 条线，EXTI0 只能连一个端口（PA0 或 PB0 或 PC0），由 AFIO->EXTICR[0] 的 4 个位选择。
    两个都要用，只能把其中一个改成「轮询 + 定时扫描」，或换到不同号的引脚（比如 PA0 + PB1，走 EXTI0 和 EXTI1）。

  3. 抢占优先级 1、响应优先级 0 的中断 A，正在执行时来了一个抢占 0、响应 3 的中断 B，会发生什么？

    B 会立即打断 A（0 < 1，抢占更高），A 的现场被压栈，B 执行完再恢复 A。
    如果来的是一个抢占 1、响应 0 的中断 C，则不会打断 A：抢占相同不能嵌套，C 只能等 A 结束后按响应优先级排队（C 的响应 0 比 A 的 1 更优先，所以 C 排在 A 后面第一个执行）。

  4. 编码器正转时数字在减小，反转时在增大。除了交换 A/B 两根线，代码上怎么改最稳？

    把 Encoder_Count++ 和 -- 两处对调（等价于把「判向逻辑」取反），或者最终显示时取负号。
    推荐前者并把注释写清楚「本套件正转 = A 下降沿时 B 为低」。硬件交换线更彻底，但拆线容易接错；代码取反最安全，也不会影响后续第 10 课的硬件编码器接口（那里靠 TIM_EncoderInterfaceConfig 的极性参数改）。

TIM 定时中断：给系统装一个心跳第三篇 · 中断与定时器

P13 – P14 · TIM 定时中断 / 定时器定时中断、定时器外部时钟　·　6 节　·　4 题

进阶

定时器是一个「会自己数数的硬件」：时钟每来一个脉冲，计数寄存器加一；加到你设定的数，就归零、并且举手告诉你「时间到了」。从此你的程序有了不依赖 Delay 的时间基准。

读完这一课你能做到

  • 能用 PSC / ARR / 时钟频率三个数算出任意定时时间，反过来也能由时间和频率定 PSC 与 ARR
  • 能配出一路 1ms 中断，并在中断里做 1 秒闪灯、计时器
  • 能说清「内部时钟」与「外部时钟模式」的区别，会用 ETR 引脚数外部脉冲
  • 知道定时器中断里该做什么、不该做什么
一、时基单元：三个寄存器说清一切
寄存器作用范围类比
PSC 预分频器把输入时钟「减速」0–65535（实际分频 = PSC+1）秒针走一圈，分针才走一格
CNT 计数器当前数到几0–65535（向上/向下/中央对齐）数数的人
ARR 自动重装数到这个值就归零并产生事件0–65535「数到 1000 就重新开始」

整条链路是：定时器时钟（fCK）→ ÷(PSC+1) → CNT 每来一个脉冲加一 → CNT 追上 ARR → 归零 + 产生更新事件（UEV）→ 若开了中断，就进中断函数。

定时频率和定时时间的公式只有一条，务必背下来：

f_update = fCK / ((PSC + 1) × (ARR + 1))　　　T = 1 / f_update

TIM2/3/4 挂在 APB1 上，APB1 = 36MHz，但定时器时钟自动 ×2，所以 fCK = 72MHz（第 01 课讲过这条例外规则）。

二、算例：从「我要 1ms」到两个数字
目标取 PSC得 CNT 计数频率取 ARR实际周期误差
1ms71（÷72）1MHz（1μs 一次）9991000 × 1μs = 1ms0
1ms（错误算例）7199（÷7200）10kHz（100μs 一次）99100 × 100μs = 10ms ❌大了 10 倍
10ms719910kHz99100 × 100μs = 10ms0
1s719910kHz999910000 × 100μs = 1s ✓0（ARR 已接近上限）

第三行是故意写错的：PSC 和 ARR 要一起算，只盯着一个数必然算错。养成习惯：先在纸上写 72,000,000 / (PSC+1) / (ARR+1) = 目标频率，代进去验算一遍再写代码。

为什么常用「PSC=71, ARR=999」

因为它把计数器变成「1μs 一跳」，ARR=999 就是 1ms，改 ARR 就能直接读成「多少毫秒」。调试时把 ARR 当参数改，比每次重算 PSC 方便得多。

代价是 PSC 分频比小（÷72），计数器跑得快，长时间定时（比如 1 小时）需要软件累加。

三、1ms 心跳：代码
#include "stm32f10x.h"

uint16_t ms_Tick = 0;        // 软件毫秒计数
uint8_t  sec = 0, min = 0;

void Timer_Init(void)
{
    TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);   // TIM2 在 APB1 上

    /* ① 时基：72MHz / 72 = 1MHz，数 1000 次 = 1ms */
    TIM_TimeBaseStructure.TIM_Prescaler         = 72 - 1;      // PSC = 71
    TIM_TimeBaseStructure.TIM_Period            = 1000 - 1;    // ARR = 999
    TIM_TimeBaseStructure.TIM_ClockDivision     = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_CounterMode       = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;           // 高级定时器才用
    TIM_TimeBaseInit(TIM2, &TIM_TimeBaseStructure);

    /* ② 清一下更新标志，避免一开中断就立刻进一次 */
    TIM_ClearFlag(TIM2, TIM_FLAG_Update);

    /* ③ 开 TIM2 的更新中断 */
    TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE);

    /* ④ NVIC */
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitStructure.NVIC_IRQChannel = TIM2_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    /* ⑤ 启动定时器 */
    TIM_Cmd(TIM2, ENABLE);
}

void TIM2_IRQHandler(void)
{
    if(TIM_GetITStatus(TIM2, TIM_IT_Update) == SET){
        ms_Tick++;
        if(ms_Tick >= 1000){              // 1 秒
            ms_Tick = 0;
            sec++;
            if(sec >= 60){ sec = 0; min++; }
        }
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
    }
}

第 ② 步的 TIM_ClearFlag 不是可选的。初始化时写 ARR 会立刻产生一次「更新事件」，标志位被置起；这时如果先开了中断使能再启动，程序会一上电就多进一次中断。表现为：秒表刚上电就显示 1 秒，或者计数器初始值总是多 1。

有了这个 1ms 心跳，前面第 04 课的按键消抖就可以改成非阻塞的：

/* 每 1ms 调一次，连续 20 次读到相同状态才认 */
void Key_Scan_1ms(void)
{
    static uint8_t cnt = 0, stable = 1;
    uint8_t raw = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1);

    if(raw != stable){
        if(++cnt >= 20){ stable = raw; cnt = 0; /* 这里产生一次按键事件 */ }
    }else{
        cnt = 0;
    }
}
四、外部时钟模式：数外面的脉冲

内部时钟是「数自己心跳」，外部时钟是「数别人给的脉冲」。三种常见来源：

模式时钟从哪来配置要点用途
内部时钟RCC 给的 72MHz默认定时、PWM
外部时钟模式 1引脚 ETR（TIM2_ETR = PA0）TIM_ETRClockMode2Config数外部脉冲个数

  1. 要求每 500ms 进一次中断，TIM3 的 fCK = 72MHz。给出两组 (PSC, ARR) 并验算。

    取 PSC = 7199（÷7200 → 10kHz，每跳 100μs），ARR = 4999：周期 = 5000 × 100μs = 500ms ✓
    另一组：PSC = 71（÷72 → 1MHz，每跳 1μs），ARR = 499999 —— 超过 65535，不合法。所以必须用大分频，「小 PSC + 大 ARR」在小定时时间才可行。

  2. 初始化里漏了 TIM_ClearFlag(TIM2, TIM_FLAG_Update)，程序会有什么现象？

    上电后第一次进中断的时间不确定：因为写 ARR 时已经产生过一次更新事件、标志已置位，中断使能一开就立刻进一次，相当于「多计了一个周期」。
    表现是秒表起跑就慢 1ms、或者计数器初始值比预期大 1。修法是在 TIM_ITConfig 之前先 TIM_ClearFlag，把这笔「历史账」清掉。

  3. 想统计一个外部方波的频率，用「定时器外部时钟模式 + 每 1 秒读一次 CNT」的做法，在 1kHz 信号下分辨率是多少？有什么局限？

    分辨率 1Hz（1 秒窗口内计到的脉冲数就是频率），对 1kHz 信号误差约 0.1%。
    局限：① 低频信号（比如 10Hz）在 1 秒窗口里只有 10 个脉冲，量化误差 10%；② 要等满 1 秒才出结果，响应慢。改进就是第 09 课的输入捕获——直接测一个周期的时长，低频时反而更准。

  4. 为什么定时器中断里不能调用 Delay_ms() 或 printf()？

    Delay_ms 依赖 SysTick 或循环，会阻塞几毫秒；printf 要等串口发完（9600 波特率下发 10 个字符约 10ms）。两者都会让 1ms 的中断严重超时，导致后续中断被推迟或丢失。
    正确做法：中断里只置标志或累加计数，把显示、打印放到主循环。这也是「1ms 心跳 + 主循环处理」这个模式能撑住整个项目的原因。

进阶

PWM 的本质是「用一个不断计数的计数器，把占空比这个数字变成一段时间的平均值」。硬件替你在后台翻转引脚，CPU 只管改一个寄存器——这就是为什么呼吸灯可以不占用主循环，电机可以一边转一边通信。

读完这一课你能做到

  • 能画出「CNT 与 CCR 比较 → 输出参考信号 → 引脚」这条通路

  • 能做出呼吸灯、舵机转角、直流电机调速三个现象
  • 知道为什么 PWM 引脚必须配成复用推挽，以及电源为什么必须共地
一、输出比较：比较一次，翻转一次

定时器里有个一直在跑的 CNT，还有一个你设定的 CCR（捕获/比较寄存器）。硬件不停地做一件事：比较 CNT 和 CCR。比较结果决定输出引脚的高低。

模式规则结果
冻结不比较引脚保持
匹配时置有效CNT == CCR 时输出高单脉冲
匹配时翻转CNT == CCR 时翻转输出方波，占空比 50%
PWM 模式 1CNT < CCR 输出有效电平，否则无效最常用：CCR 越大，高电平越宽
PWM 模式 2与模式 1 相反CCR 越大，低电平越宽

「有效电平」是高还是低，由 TIM_OCPolarity_High/Low 决定。默认高有效，于是：

占空比 = CCR / (ARR + 1)　　PWM 频率 = fCK / ((PSC + 1) × (ARR + 1))

两个公式一起用：先定频率（PSC、ARR），再用 CCR 调占空比。ARR 决定分辨率——ARR = 99 时占空比只能取 0%–100% 之间的 100 档（1% 一步），ARR = 999 就有 1000 档。

三、呼吸灯：TIM2_CH1 → PA0
#include "stm32f10x.h"

void PWM_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
    TIM_OCInitTypeDef TIM_OCInitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);

    /* ① 引脚：必须是复用推挽，交给定时器控制 */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_CounterMode   = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM2, &TIM_TimeBaseStructure);

    /* ③ 输出比较：PWM 模式 1，高电平有效 */
    TIM_OCInitStructure.TIM_OCMode      = TIM_OCMode_PWM1;
    TIM_OCInitStructure.TIM_OutputState = TIM_OutputState_Enable;
    TIM_OCInitStructure.TIM_Pulse       = 0;               // 初始 CCR = 0（全灭）
    TIM_OCInitStructure.TIM_OCPolarity  = TIM_OCPolarity_High;
    TIM_OC1Init(TIM2, &TIM_OCInitStructure);               // 通道 1

    TIM_Cmd(TIM2, ENABLE);
}

/* 0~100 的占空比 */
void PWM_SetCompare1(uint8_t duty)
{
    TIM_SetCompare1(TIM2, duty);       // 直接写 CCR1 = duty
}

呼吸灯的主循环：

int main(void)
{
    uint8_t duty = 0;
    int8_t  step = 1;

    PWM_Init();
    while(1){
        PWM_SetCompare1(duty);
        Delay_ms(10);
        duty += step;
        if(duty == 0 || duty == 100) step = -step;   // 到顶或到底就反向
    }
}

duty 必须是 uint8_t（0–255），如果写成 int8_t，加到 100 没问题但减法到 0 再减就变 −1，TIM_SetCompare1 会收到 255，灯突然全亮——这是「呼吸灯跳到最亮再熄」的经典原因。

四、舵机：50Hz 里的 0.5–2.5ms

SG90 这类舵机认的是脉宽：每 20ms 来一个脉冲，脉宽 0.5ms 对应 0°，1.5ms 对应 90°，2.5ms 对应 180°。

参数计算取值
频率50Hz → 周期 20ms—
PSC72MHz / 7200 = 10kHz（每跳 0.1ms）7199
ARR20ms / 0.1ms = 200 → 计 200 次199
CCR @ 0°0.5ms / 0.1ms = 55
CCR @ 90°1.5ms / 0.1ms = 1515
CCR @ 180°2.5ms / 0.1ms = 2525

所以 ARR 固定 199，CCR 在 5–25 之间就是 0–180°。写成一个角度函数：

/* 角度 0~180 → CCR 5~25。TIM2_CH2 需要单独初始化 OC2Init */
void Servo_SetAngle(uint8_t angle)
{
    if(angle > 180) angle = 180;
    TIM_SetCompare2(TIM2, 5 + (uint16_t)angle * 20 / 180);   // 5 + angle/9
}

angle * 20 / 180 先乘后除，避免整数除法把小数全丢成 0。如果角度范围要求更细，可以放大 ARR（比如 ARR = 1999、每跳 10μs），代价是 CCR 数值更大、分辨率更高。

{

        GPIO_SetBits(GPIOA, GPIO_Pin_4);
        GPIO_ResetBits(GPIOA, GPIO_Pin_5);
    }else{
        GPIO_ResetBits(GPIOA, GPIO_Pin_4);
        GPIO_SetBits(GPIOA, GPIO_Pin_5);
        speed = -speed;

}

电机实验最容易烧的三处

① 电源不共地：TB6612 的 GND 没接到 STM32 的 GND，控制信号没有参考点，电机乱转或不动。

② 用 USB 供电：USB 口最多 500mA，电机启动瞬间的浪涌能到 1A，会把电压拉到 3V 以下，STM32 直接复位。电机必须用独立电池，只共地。

③ 方向脚同时为高：AIN1 = AIN2 = 1 时 TB6612 是「短路刹车」，电流很大且发热，长时间会烧驱动。代码里必须保证两者互斥。

  1. 要输出 1kHz 的 PWM，且占空比能精确到 1%，请给出 (PSC, ARR) 并验算。

    1kHz → 周期 1ms。取 PSC = 71（÷72 → 1MHz，每跳 1μs），ARR = 999（1000 × 1μs = 1ms ✓）。
    分辨率 = 1/1000 ≈ 0.1%，满足 1% 要求。若取 ARR = 99 则需要 PSC = 719，分辨率 1%，刚好够但不留余量。

  2. 呼吸灯程序里 duty 用了 int8_t，为什么灯会「跳到最亮再熄」？

    int8_t 范围是 −128～127。当 duty 从 0 减 1 变成 −1 时，传给 TIM_SetCompare1（参数是 uint16_t）会发生隐式转换，−1 变成 65535。
    而 CCR 大于 ARR+1 时，PWM 模式 1 的输出一直是有效电平（全亮）。所以现象是「暗到 0 突然全亮，再掉回来」。改用 uint8_t 或 int16_t 并做范围保护即可。

  3. 舵机接在 PA1（TIM2_CH2），代码写好了但舵机纹丝不动，示波器也没有波形。先查什么？

    先查引脚模式：必须是 GPIO_Mode_AF_PP（复用推挽）。配成普通推挽时，定时器根本没接管引脚，示波器上什么都没有。
    其次查通道：PWM_Init 里只调了 TIM_OC1Init，通道 2 需要单独 TIM_OC2Init，且 TIM_OutputState_Enable。最后确认 TIM_Cmd(TIM2, ENABLE) 有没有执行。

  4. 为什么电机必须用独立电源，只把 GND 和 STM32 连在一起？

    电机启动和堵转时电流可达 1A 以上，远超 USB 口和板载 LDO 的供给能力，会把 3.3V 拉低，导致 STM32 欠压复位（现象是「电机一转，程序就重启」）。
    独立供电后，两边必须有共同的地参考，否则 TB6612 收到的 PWM 高低电平没有基准，可能误判。所以「电源分开、地必须相连」是电机驱动的标准做法。

输入捕获：测频率与占空比第三篇 · 中断与定时器

P17 – P18 · TIM 输入捕获 / 输入捕获测频率、PWMI 测频率占空比　·　6 节　·　4 题

难点

输入捕获就是「在边沿到来的那一刻，把 CNT 的值拍下来」。一张快照是时刻，两张快照之差就是一个周期。有了周期，频率和占空比都只是除法。

读完这一课你能做到

  • 能说清「测频法」与「测周法」各自适合什么频率段
  • 能配出一路上升沿捕获，用两次 CCR 之差算出频率
  • 能用 PWMI 模式一次拿到周期与高电平时间，算出占空比
  • 知道捕获溢出、滤波器、通道绑定这三个坑怎么排
一、捕获通道：四个通道，各有一个 CCR

输入捕获和输出比较共用同一套 CCR 寄存器，只是方向相反：输出比较是「我写 CCR，硬件去比」，输入捕获是「边沿来了，硬件把 CNT 抄进 CCR」。

概念含义配置项
捕获边沿上升沿 / 下降沿 / 双边沿TIM_ICPolarity_Rising 等
输入分频每 N 个边沿才捕获一次TIM_ICPSC_DIV1 最常用
滤波器忽略短于 N 个采样周期的毛刺TIM_ICFilter = 0x0F 为最强
直接/间接映射通道 1 可以映射到 TI1 或 TI2TIM_ICSelection_DirectTI

滤波器这一项值得单独说：ICFilter 不是「软件消抖」，而是硬件数字滤波——它按 fCK_INT 的节奏对输入采样，连续 N 次一致才认。所以它能滤掉微秒级毛刺，但滤不掉机械抖动（那是毫秒级）。

二、两种测法：测频 vs 测周
方法做法误差来源适合
测频法固定窗口（如 1s）数脉冲个数量化误差 ±1 个脉冲高频（>10kHz）
测周法测一个周期的时长，取倒数计时分辨率（1μs 或更细）低频（<10kHz）
等精度用两个计数器同时数「被测脉冲」与「标准时钟」几乎无量化误差全频段，实现复杂

第 07 课的外部时钟模式就是测频法。这一课做测周法——它响应更快，低频时更准。

公式（捕获两次上升沿，CCR1 分别是 t1、t2）：

周期 T = (t2 − t1) × (PSC + 1) / fCK　　f = fCK / ((PSC + 1) × (t2 − t1))

若 PSC = 71（CNT 每跳 1μs），则周期 = (t2 − t1) 微秒，频率 = 1,000,000 / (t2 − t1)。

    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICFilter    = 0x0F;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    /* ④ 开捕获中断 + NVIC */
    TIM_ITConfig(TIM3, TIM_IT_CC1, ENABLE);
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitStructure.NVIC_IRQChannel = TIM3_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    TIM_Cmd(TIM3, ENABLE);
}

void TIM3_IRQHandler(void)
{
    if(TIM_GetITStatus(TIM3, TIM_IT_CC1) == SET){
        if(Is_First_Captured == 0){
            IC_Val1 = TIM_GetCapture1(TIM3);           // 第一次：记下 t1
            Is_First_Captured = 1;
        }else{
            IC_Val2 = TIM_GetCapture1(TIM3);           // 第二次：记下 t2
            if(IC_Val2 > IC_Val1){
                Frequency = 1000000.0f / (IC_Val2 - IC_Val1);
            }
            Is_First_Captured = 0;                     // 重新开始下一轮
        }
        TIM_ClearITPendingBit(TIM3, TIM_IT_CC1);
    }
}

if(IC_Val2 > IC_Val1) 这个判断是必需的：如果两个边沿之间 CNT 溢出过一次（超过 65535μs ≈ 65ms，对应 <15Hz），IC_Val2 会小于 IC_Val1，减法变成负数。正确做法是在中断里也数「溢出次数」，把周期算成 overflow × 65536 + (t2 − t1)。

四、PWMI 模式：一次拿到周期和占空比

PWM 输入模式（PWMI）把同一个信号同时接到两个通道：CH1 抓上升沿（周期起点），CH2 抓下降沿（高电平结束）。于是：

  • CCR1 = 一个完整周期的长度
  • CCR2 = 高电平的长度

占空比 = CCR2 / CCR1　　（单位：同一个 CNT 计数）

void PWMI_Init(void)
{
    /* 前半段与 IC_Init 相同：GPIO / 时基 / TIM_Cmd 略 */
    TIM_ICInitTypeDef s;

    /* CH1：上升沿，直接映射 TI1 */
    s.TIM_Channel     = TIM_Channel_1;
    s.TIM_ICPolarity  = TIM_ICPolarity_Rising;
    s.TIM_ICSelection = TIM_ICSelection_DirectTI;
    s.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    s.TIM_ICFilter    = 0x0F;
    TIM_ICInit(TIM3, &s);

    /* CH2：下降沿，交叉映射 TI1（同一个输入脚，不同边沿） */
    s.TIM_Channel     = TIM_Channel_2;
    s.TIM_ICPolarity  = TIM_ICPolarity_Falling;
    s.TIM_ICSelection = TIM_ICSelection_IndirectTI;    // 注意是 Indirect
    TIM_ICInit(TIM3, &s);

    /* 让 CH1 触发时自动复位 CNT，这样每次都能直接读周期 */
    TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1);
    TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset);

    TIM_Cmd(TIM3, ENABLE);
}

/* 主循环里直接读，不用中断 */
void Get_PWM(void)
{
    uint16_t period = TIM_GetCapture1(TIM3);   // 一整个周期
    uint16_t high   = TIM_GetCapture2(TIM3);   // 高电平时间
    if(period){
        Frequency = 1000000.0f / period;                 // PSC=71 → 1μs 一跳
        Duty      = (float)high / period * 100.0f;
    }
}

「从模式复位（Slave Reset）」这一步是 PWMI 的精髓：每次上升沿到来，硬件自动把 CNT 清零。于是 CCR1 直接就是周期长度，CCR2 直接就是高电平长度，不用做减法，也不用担心溢出。

五、坑：捕获读不到、读数乱跳、频率差一倍
现象原因修法
中断完全不进引脚配成了推挽输出，或忘了 TIM_ITConfig输入信号引脚必须是浮空/上拉输入
读数为 0 或巨大值第一次捕获没区分，把 t1 当成了 t2用 Is_First_Captured 标志分两次
低频时读数乱跳CNT 溢出没计入中断里累加溢出次数，周期 = 溢出×65536 + 差值

为什么测频率要用「两个上升沿」而不是「上升沿到下降沿」

上升沿到下降沿的高电平时间只反映占空比，不反映周期。占空比 10% 的 1kHz 方波，高电平只有 100μs，算出来会变成 10kHz。

测周期必须用「同类边沿」：上升→上升，或下降→下降。这是测周法唯一必须记牢的规则。

六、测周法的边界
待测频率周期（CNT 计数，1μs/跳）是否可行
1MHz1分辨率不够（±1 计数 = ±100% 误差）
100kHz10误差约 10%，勉强
10kHz100误差 1%，可用
1kHz1000很好
10Hz100000超过 65535，必须处理溢出
1Hz1000000溢出 15 次，必须累加

所以工程上的常规做法是：高频用测频法（外部时钟计数），低频用测周法（输入捕获），中间用等精度。三种都学过的标志，是能看着一个信号说出「该用哪种」。

  1. 用 PSC = 71 的输入捕获测得两个上升沿的 CCR 差为 2000，信号频率是多少？占空比能算吗？

    频率 = 1,000,000 / 2000 = 500Hz。
    单通道上升沿捕获只测了周期，拿不到高电平长度，所以算不出占空比。要算占空比必须再加一个下降沿通道（PWMI 模式），或改用「双边沿捕获 + 四次时间戳」。

  2. 为什么测周期必须用两个同类边沿（上升→上升），而不能用上升→下降？

    上升→下降的间隔是高电平时间，等于「周期 × 占空比」。占空比一变，读数就跟着变，测出来的不是频率。
    只有同类边沿之间的间隔才等于一个完整周期。这也是 PWMI 模式要两个通道的原因：CH1 抓上升沿定周期，CH2 抓下降沿定高电平，两者之比才是占空比。

  3. 输入捕获测 5Hz 的信号时读数乱跳，可能是什么原因？怎么改？

    5Hz 的周期是 200ms，而 PSC=71 时 CNT 每 1μs 一跳，200ms 需要 200000 个计数，超过 16 位上限 65535，会溢出 3 次。
    两个改法：① 加大 PSC（比如 PSC = 7199，CNT 每 100μs 一跳，200ms 只要 2000 个计数，不溢出，但高频时分辨率变差）；② 保留 PSC 但在中断里累加溢出次数，周期 = 溢出次数 × 65536 + 差值。工程上常用 ②，兼顾量程与精度。

  4. PWMI 初始化里不加 TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset) 会怎样？

    也能工作，但每次都要自己做减法（CCR2 − CCR1），而且一旦周期超过 65535 就得处理溢出。
    加了复位从模式后，每个上升沿自动清 CNT，CCR1 直接等于周期、CCR2 直接等于高电平宽度，代码更短也更抗溢出。代价是 CNT 不能用来做别的事（比如同时当定时器用）。

一、正交编码：相位差 90° 的两路方波

编码器内部是一个带缝隙的码盘加两对光电管，输出 A、B 两路方波，相位差 90°。转向决定谁超前：

转向相位关系观察点
正转A 超前 B 90°A 上升沿时，B 还是低
反转B 超前 A 90°A 上升沿时，B 已是高

「四倍频」来自计数方式：如果只在 A 的上升沿计数，一圈 N 个脉冲；如果 A、B 两个通道都数上升沿和下降沿，一圈就是 4N 个计数。分辨率提高 4 倍，代价是同样转速下 CNT 增长快 4 倍。

计数模式每个周期计几次分辨率对应库宏
只数 TI1 边沿2（上升+下降）2×TIM_EncoderMode_TI1
只数 TI2 边沿22×TIM_EncoderMode_TI2
两通道都数44×（最常用）TIM_EncoderMode_TI12
二、三步配好编码器接口

编码器接口用的是定时器的通道 1 和通道 2，所以引脚必须选「CH1/CH2」那一对。以 TIM3 为例：CH1 = PA6、CH2 = PA7（也可以重映射到 PB4/PB5，或直接用 TIM2 的 PA0/PA1）。

#include "stm32f10x.h"

void Encoder_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
    TIM_ICInitTypeDef TIM_ICInitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);

    /* ① 两个引脚：上拉输入（编码器多为开集输出，必须上拉） */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_6 | GPIO_Pin_7;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* ② 时基：编码器模式下 PSC 固定为 0，ARR 设满量程 */
    TIM_TimeBaseStructure.TIM_Prescaler     = 0;
    TIM_TimeBaseStructure.TIM_Period        = 65536 - 1;
    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_CounterMode   = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure);

    /* ③ 通道配置（编码器模式下这两句是固定写法） */
    TIM_ICInitStructure.TIM_Channel     = TIM_Channel_1;
    TIM_ICInitStructure.TIM_ICPolarity  = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICFilter    = 0x0F;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    TIM_ICInitStructure.TIM_Channel     = TIM_Channel_2;
    TIM_ICInitStructure.TIM_ICPolarity  = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    /* ④ 打开编码器接口：两通道都计数 → 四倍频 */
    TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12,
                               TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);

    TIM_SetCounter(TIM3, 0);
    TIM_Cmd(TIM3, ENABLE);
}

配好之后，CNT 会随转动自动增减：正转加，反转减。你不需要任何中断，读一次 TIM_GetCounter(TIM3) 就是当前位置。

三、读位置与算转速：差值法

CNT 是 16 位的，转到 65535 会回绕到 0，直接读数值会看到「65530 → 3」这种跳变。所以工程上一律用两次读数之差：

/* 返回自上次调用以来转过的计数（正=正转，负=反转） */
int16_t Encoder_GetDelta(void)
{
    static uint16_t last = 0;
    uint16_t now = TIM_GetCounter(TIM3);
    int16_t delta = (int16_t)(now - last);   // 关键：转成有符号再减
    last = now;
    return delta;
}

(int16_t)(now - last) 这一句是整个测速的关键：无符号数相减再强转有符号，天然处理了回绕。比如 now = 3、last = 65530，3 - 65530 = 9（mod 65536），正好是实际前进的 9 个计数。

转速计算：

/* 每 100ms 调用一次；每圈 4×N 个计数（N 为编码器线数，常见 11 或 20） */
float Motor_RPM(void)
{
    int16_t d = Encoder_GetDelta();
    float rev = (float)d / (4.0f * 11.0f);    // 转过的圈数
    return rev * 600.0f;                      // 每 100ms → 每分钟 ×600
}
量公式说明
每圈计数4 × 线数四倍频；11 线 → 44 计数/圈
角速度Δ计数 / 每圈计数 × 2π / Δt弧度每秒
转速 RPMΔ计数 / 每圈计数 / Δt × 60Δt 单位秒
线速度RPM × π × 轮径 / 60小车里换算成 m/s
四、坑：数字不动、只增不减、跳变
现象原因修法
转起来数字完全不动引脚不是 CH1/CH2 对应的脚，或忘了 TIM_EncoderInterfaceConfig查引脚表；确认调了编码器配置而不是普通输入捕获
正反转都在加CNT 方向被固定（TIM_CounterMode_Up + 极性配成同一相）用 TIM_EncoderMode_TI12，两个极性都设 Rising
数值偶尔跳一大截直接读 CNT 且发生回绕用 (int16_t)(now - last) 差值法
静止时数字缓慢乱走引脚没上拉，输入悬空捡噪声加外部 10kΩ 上拉，或确认配了 GPIO_Mode_IPU
转速比实际大一倍每圈计数按「线数」算，没乘 4四倍频要乘 4

编码器模式会「占用」整个定时器

一旦配成编码器接口，这个定时器的 CNT 由外部脉冲驱动，不能再拿它做定时中断或 PWM（时钟源已经换成了 TI1/TI2）。

小车项目里通常这样分配：TIM2 做 PWM 驱动电机、TIM3/TIM4 做左右轮编码器、SysTick 或 TIM1 做控制周期。定时器不够用时才考虑软件解码。

  1. 一个 11 线（每圈 11 个脉冲）的编码器，用四倍频模式，轮子转一圈 CNT 变化多少？转 20 圈呢？

    四倍频 = 每圈 4 × 11 = 44 个计数。转 20 圈 = 880 个计数。
    注意 880 没有超过 65535，所以不用处理溢出；但如果连续正转 1489 圈（65535/44）以上就会回绕，所以位置上要一直用差值法累计，不要只读瞬时值。

  2. int16_t delta = (int16_t)(now - last); 这一句为什么能自动处理 16 位回绕？

    C 语言的整型提升规则：now - last 是两个 uint16_t，先提升为 int 做减法，结果为负时也是正确的数学差（如 3 − 65530 = −65527）。
    再强转成 int16_t 会按 16 位截断，−65527 mod 65536 = 9，正好等于「前进 9 个计数」。也就是说：只要两次读数之间的真实变化量小于 32768，这个写法永远正确。

  3. 编码器接在 PA6/PA7 上，代码也调了 TIM_EncoderInterfaceConfig，但转起来 CNT 一直是 0。最可能的原因是什么？

    PA6/PA7 是 TIM3 的 CH1/CH2，但如果不做重映射，引脚功能默认就是 TIM3 通道——一般是能用的。真正常见的原因是：引脚没上拉（编码器是开集输出，悬空读不到有效电平），或编码器没供电（VCC/GND 漏接）。
    其次是 TIM_Cmd(TIM3, ENABLE) 没调，或只配了 TIM_ICInit 却漏了 TIM_EncoderInterfaceConfig（此时定时器还在用内部时钟数数，CNT 会自己涨，看起来「不转也在增加」）。

  4. 小车左轮编码器读数一直在增加，右轮一直在减少，但两个轮子明明都往前转。怎么统一？

    两个编码器装的方向相反（一个 A 相接 PA6，另一个 A 相接 PA7），导致硬件判向相反。
    代码上统一：右轮取负号 delta = -delta;，或在初始化时把 TIM_EncoderInterfaceConfig 的两个极性参数对调（Rising/Falling）。推荐在驱动层做一次符号统一，上层控制代码就不用关心左右差异。

    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* ② ADC 基本参数 */
    ADC_InitStructure.ADC_Mode               = ADC_Mode_Independent;
    ADC_InitStructure.ADC_ScanConvMode       = DISABLE;     // 单通道
    ADC_InitStructure.ADC_ContinuousConvMode = DISABLE;     // 单次
    ADC_InitStructure.ADC_ExternalTrigConv   = ADC_ExternalTrigConv_None;
    ADC_InitStructure.ADC_DataAlign          = ADC_DataAlign_Right;
    ADC_InitStructure.ADC_NbrOfChannel       = 1;
    ADC_Init(ADC1, &ADC_InitStructure);

    /* ③ 规则组通道 + 采样时间 */
    ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5);

    /* ④ 校准：上电必须做一次，否则偏差几十个 LSB */
    ADC_Cmd(ADC1, ENABLE);
    ADC_ResetCalibration(ADC1);
    while(ADC_GetResetCalibrationStatus(ADC1));
    ADC_StartCalibration(ADC1);
    while(ADC_GetCalibrationStatus(ADC1));
}

/* 读一次电压（mV） */
uint16_t AD_GetValue(void)
{
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);                 // 软件触发一次
    while(!ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC));          // 等转换完成
    return ADC_GetConversionValue(ADC1);                    // 0~4095
}

/* 换算成毫伏：value * 3300 / 4096 */
uint16_t AD_To_mV(uint16_t value)
{
    return (uint16_t)((uint32_t)value * 3300 / 4096);
}

(uint32_t)value * 3300 这一步必须强制转 32 位：4095 × 3300 = 13,513,500，超过 16 位上限 65535，不转会溢出成一个乱数。这是 ADC 代码里最常见的 bug，而且在低压时看起来是对的（数值小不溢出），电压一高就跳变。

四、多通道：扫描 + 轮流读

多通道有两条路：

方案做法优点缺点
轮流切换 + 单次转换每次 ADC_RegularChannelConfig 换通道再启动代码直观、想读哪路读哪路每次都要重配，速度慢
扫描 + DMA规则组排好 4 个通道，DMA 自动搬到数组快、不占 CPU需要 DMA（第 12 课）

先看不用 DMA 的版本：

uint16_t AD_Read(uint8_t ch)
{
    ADC_RegularChannelConfig(ADC1, ch, 1, ADC_SampleTime_55Cycles5);
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);
    while(!ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC));
    return ADC_GetConversionValue(ADC1);
}

/* 依次读 4 路 */
void AD_Read4(uint16_t *out)
{
    out[0] = AD_Read(ADC_Channel_0);   // PA0
    out[1] = AD_Read(ADC_Channel_1);   // PA1
    out[2] = AD_Read(ADC_Channel_2);   // PA2
    out[3] = AD_Read(ADC_Channel_3);   // PA3
}

切换通道后第一次转换的读数往往偏高或偏低，因为采样保持电容还残留着上一路的电压。做法是丢弃切换后的第一次读数，或者把采样时间加长（55.5 或 239.5 周期），给电容足够的充电时间。

五、坑：读数总是 0、总是 4095、跳来跳去
现象原因修法
读数恒为 0引脚配成了 GPIO_Mode_IPU/IPD（数字输入），模拟通路没打开必须是 GPIO_Mode_AIN
读数恒为 4095输入电压超过 3.3V（比如误接 5V 传感器）加分压电阻；ADC 引脚绝对不能超过 VDDA
读数跳 ±20 LSB没做校准，或参考电压不稳上电做一次校准；VDDA 加 100nF + 10μF
多通道串扰切换太急，采样电容没充够加长采样时间，或丢弃第一次读数
电压高时数值乱跳value * 3300 用 16 位算了，溢出强制转 uint32_t 再乘

ADC 引脚不要接 5V

ADC 输入范围是 0 到 VDDA（3.3V）。接 5V 会通过内部保护二极管灌电流，轻则读数失真，重则永久损坏这个通道。

读 5V 信号要么用电阻分压（两个 10kΩ 各一半），要么用外部运放做衰减。传感器模块标「5V 供电」不代表输出是 5V——先量一次再接线。

六、采样时间怎么选

采样时间决定「采样保持电容充电多久」，选得越长越准，但转换越慢：

采样时间总转换时间（12.5 周期固定开销）适合的信号源
1.5 周期约 1.17μs低阻抗（运放输出）
7.5 周期约 1.67μs一般传感器
55.5 周期约 5.67μs高阻抗（电位器、光敏电阻，常见）
239.5 周期约 21μs极高阻抗、需要极稳

电位器动辄 10kΩ 以上，属于高阻抗源，直接用 1.5 周期会读到偏低的电压。课程里的电位器、光敏电阻统一用 55.5 周期，这是「读数莫名其妙偏低」的常见解法。

  1. 12 位 ADC、3.3V 参考，读数为 2048 时输入电压是多少？如果读数只有 1，代表多少毫伏？

    2048 × 3.3 / 4096 = 1.65V（正好是量程中点）。
    读数 1 → 1 × 3.3 / 4096 ≈ 0.806mV。注意 0.806mV 是「1 个 LSB 的理论值」，实际能分辨的最小变化还要考虑噪声，通常有效位数（ENOB）只有 10 位左右。

  2. 电位器接 PA0，程序里把 PA0 配成了 GPIO_Mode_IPU，读数会怎样？

    读数基本恒为 4095（或接近满量程）。上拉输入把引脚通过 40kΩ 接到 3.3V，同时数字输入通路打开、模拟通路没开，ADC 采到的是被上拉钳住的电平。
    正确配置是 GPIO_Mode_AIN：关闭数字部分（省电、避免干扰），把引脚直接连到采样开关。凡是 ADC 读数「不随输入变化」，先查这一行。

  3. 用 uint16_t mv = value * 3300 / 4096; 计算毫伏，为什么电压一高就得到乱数？

    value 是 uint16_t，value * 3300 仍在 16 位里算（整型提升到 int 时其实是 32 位，但如果写的是 uint16_t mv = value * 3300 / 4096，中间结果 13,513,500 超出 16 位，赋值时被截断）。
    稳妥写法：uint16_t mv = (uint16_t)((uint32_t)value * 3300 / 4096);——先转 32 位再乘，最后截回 16 位（结果最大 3300，不会溢出）。

  4. 依次读 PA0–PA3 四路电压，发现每一路都比实际值偏高一点，且通道之间互相影响。怎么改？

    典型的采样电容残留：切换通道后第一次转换，采样保持电容里还有上一路的电荷。
    两个改法：① 把采样时间从 1.5 周期加到 55.5 周期，让电容充分充放电；② 每次切换通道后先转换一次并丢弃结果，再取第二次的值。前者简单，后者更准。

DMA：让数据自己搬家第四篇 · 模拟与数据通路

P23 – P24 · DMA 直接存储器存取 / DMA 数据转运、DMA + AD 多通道　·　6 节　·　4 题

难点

逐字节搬运数据是 CPU 最不值得干的活。DMA 是总线上的一个「搬运工」：你告诉它从哪搬到哪、搬多少，它就在后台自己搬，搬完给你一个标志。CPU 从「搬箱子的人」变成「下指令的人」。

读完这一课你能做到

  • 能说清「外设地址 / 内存地址 / 传输方向 / 数据宽度 / 地址自增 / 传输数量」六个参数的含义
  • 能用 DMA 做一次内存到内存的转运，并验证结果
  • 能配出「ADC 扫描 + DMA 循环」，让 4 路电压自动刷新到数组里
  • 记住 DMA 通道与请求的固定对应关系，知道为什么通道不能乱选

参数库里对应的成员含义常见取值
外设地址DMA_PeripheralBaseAddr搬的一端（外设寄存器）(uint32_t)&ADC1->DR
内存地址DMA_MemoryBaseAddr另一端（SRAM 数组）(uint32_t)buffer

「外设地址不自增、内存地址自增」是最常用的组合：外设这边永远是同一个数据寄存器（ADC1->DR），内存那边从 buf[0] 一路写到 buf[3]。

数据宽度必须两边一致。ADC 是 12 位、寄存器 16 位，所以两边都设 HalfWord；设成 Byte 会把 16 位拆成两次，读出来的值全是错的。

二、通道是固定的：查表，别猜

DMA1 有 7 个通道，每个通道能响应哪些请求是硬件焊死的，不能自由分配：

通道可响应的请求（部分）常用场景
DMA1_Channel1ADC1、TIM2_CH3、TIM4_CH1ADC 采集（本课主角）
DMA1_Channel2SPI1_RX、USART3_TX、TIM1_CH1、TIM2_UP串口/SPI 接收
DMA1_Channel3SPI1_TX、USART3_RX、TIM1_CH2SPI 发送
DMA1_Channel4SPI2_RX、USART1_TX、I2C2_TX串口 1 发送（printf 加速）

所以「ADC1 用 DMA」只能是 DMA1_Channel1。选错通道程序不会报错，就是永远不搬——这类 bug 最难查，因为所有配置看起来都「对」。

三、内存到内存：先验证搬运本身

学习 DMA 建议先做一次「SRAM → SRAM」的转运，不牵扯外设，最容易验证：

#include "stm32f10x.h"

uint8_t  SrcBuf[4] = {0x01, 0x02, 0x03, 0x04};
uint8_t  DstBuf[4] = {0};

void MyDMA_Init(uint32_t src, uint32_t dst, uint16_t size)
{
    DMA_InitTypeDef DMA_InitStructure;

    RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1, ENABLE);   // DMA 挂在 AHB 上

    DMA_InitStructure.DMA_PeripheralBaseAddr = src;
    DMA_InitStructure.DMA_MemoryBaseAddr     = dst;
    DMA_InitStructure.DMA_DIR                = DMA_DIR_PeripheralSRC;
    DMA_InitStructure.DMA_BufferSize         = size;
    DMA_InitStructure.DMA_PeripheralInc      = DMA_PeripheralInc_Enable;  // 内存→内存：两端都自增
    DMA_InitStructure.DMA_MemoryInc          = DMA_MemoryInc_Enable;
    DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;
    DMA_InitStructure.DMA_MemoryDataSize     = DMA_MemoryDataSize_Byte;
    DMA_InitStructure.DMA_Mode               = DMA_Mode_Normal;           // 只搬一次
    DMA_InitStructure.DMA_Priority           = DMA_Priority_Medium;
    DMA_InitStructure.DMA_M2M                = DMA_M2M_Enable;            // 软件触发
    DMA_Init(DMA1_Channel1, &DMA_InitStructure);

    DMA_Cmd(DMA1_Channel1, ENABLE);
}

/* 启动一次转运并等它完成 */
void MyDMA_Transfer(uint16_t size)
{
    DMA_Cmd(DMA1_Channel1, DISABLE);          // ① 改数量前必须先关
    DMA_SetCurrDataCounter(DMA1_Channel1, size);
    DMA_Cmd(DMA1_Channel1, ENABLE);           // ② 重新使能即开始

    while(DMA_GetFlagStatus(DMA1_FLAG_TC1) == RESET);   // ③ 等传输完成
    DMA_ClearFlag(DMA1_FLAG_TC1);                       // ④ 清标志
}

四个动作的顺序不能乱：关 → 改数量 → 开 → 等标志 → 清标志。改 BufferSize 时通道必须是关闭的，否则新值不生效。

四、ADC + DMA：四路电压自动刷新

这是 DMA 在单片机里最典型、也最有用的用法：ADC 按规则组顺序扫 4 个通道，每转换完一个，DMA 就把它搬进数组。CPU 完全不参与。

uint16_t AD_Value[4];        // 必须放全局！放局部会被栈回收

void AD_DMA_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    ADC_InitTypeDef ADC_InitStructure;
    DMA_InitTypeDef DMA_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_ADC1, ENABLE);
    RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1, ENABLE);
    RCC_ADCCLKConfig(RCC_PCLK2_Div6);                 // 12MHz

    /* ① 4 个引脚全部模拟输入 */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_AIN;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 | GPIO_Pin_3;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* ② DMA：外设 ADC1->DR → 内存数组，循环模式 */
    DMA_InitStructure.DMA_PeripheralBaseAddr = (uint32_t)&ADC1->DR;
    DMA_InitStructure.DMA_MemoryBaseAddr     = (uint32_t)AD_Value;
    DMA_InitStructure.DMA_DIR                = DMA_DIR_PeripheralSRC;
    DMA_InitStructure.DMA_BufferSize         = 4;
    DMA_InitStructure.DMA_PeripheralInc      = DMA_PeripheralInc_Disable;
    DMA_InitStructure.DMA_MemoryInc          = DMA_MemoryInc_Enable;
    DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_HalfWord;
    DMA_InitStructure.DMA_MemoryDataSize     = DMA_MemoryDataSize_HalfWord;
    DMA_InitStructure.DMA_Mode               = DMA_Mode_Circular;   // 循环，永不停
    DMA_InitStructure.DMA_Priority           = DMA_Priority_High;
    DMA_InitStructure.DMA_M2M                = DMA_M2M_Disable;
    DMA_Init(DMA1_Channel1, &DMA_InitStructure);
    DMA_Cmd(DMA1_Channel1, ENABLE);

    /* ③ ADC：扫描 + 连续 + 4 个通道 */
    ADC_InitStructure.ADC_Mode               = ADC_Mode_Independent;
    ADC_InitStructure.ADC_ScanConvMode       = ENABLE;      // 扫描
    ADC_InitStructure.ADC_ContinuousConvMode = ENABLE;      // 连续
    ADC_InitStructure.ADC_ExternalTrigConv   = ADC_ExternalTrigConv_None;
    ADC_InitStructure.ADC_DataAlign          = ADC_DataAlign_Right;
    ADC_InitStructure.ADC_NbrOfChannel       = 4;
    ADC_Init(ADC1, &ADC_InitStructure);

    ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5);
    ADC_RegularChannelConfig(ADC1, ADC_Channel_1, 2, ADC_SampleTime_55Cycles5);
    ADC_RegularChannelConfig(ADC1, ADC_Channel_2, 3, ADC_SampleTime_55Cycles5);
    ADC_RegularChannelConfig(ADC1, ADC_Channel_3, 4, ADC_SampleTime_55Cycles5);

    ADC_DMACmd(ADC1, ENABLE);          // ④ 让 ADC 转换完发 DMA 请求
    ADC_Cmd(ADC1, ENABLE);
    ADC_ResetCalibration(ADC1);
    while(ADC_GetResetCalibrationStatus(ADC1));
    ADC_StartCalibration(ADC1);
    while(ADC_GetCalibrationStatus(ADC1));

    ADC_SoftwareStartConvCmd(ADC1, ENABLE);   // ⑤ 启动一次，之后就自动循环
}

之后主循环里什么都不用做，AD_Value[0..3] 会一直是最新的四路电压。

五、坑：不搬、搬一半、值不对
现象原因修法
数组一直是 0通道选错（比如 ADC 用了 Channel2）ADC1 只能用 DMA1_Channel1
只搬了一次就停用了 DMA_Mode_Normal连续采集要 DMA_Mode_Circular
数组前几个对、后面乱BufferSize 和实际通道数不一致4 个通道就填 4
数据跳动很大数据宽度设成 Byte，16 位值被拆开两边都用 HalfWord
程序偶尔跑飞数组定义在函数内（栈上），函数返回后被复用改成全局变量或 static
改了电压值不更新忘了 ADC_DMACmd(ADC1, ENABLE)ADC 不产生 DMA 请求，DMA 就空等

全局数组不是「好习惯」，是硬要求

DMA 在后台按地址搬运，它不知道「这个数组是谁的」。如果数组是某个函数的局部变量，函数返回后这块栈空间会被别的变量覆盖，DMA 就把数据写进了别人的地盘——表现是「数值随机、程序偶发跑飞」。

凡是给 DMA 用的缓冲区，一律定义为全局或 static，并加注释说明「DMA 目标，勿移出全局」。

六、DMA 还能省下哪些 CPU
场景不用 DMA用 DMA收益

代价是「调试变难」：数据是后台写的，你打断点看不到搬运过程。所以每次用 DMA，先做一次内存到内存的验证，确认配置无误再接外设。

本课练习 · 4 题自编 · 按课程考点

  1. ADC 采集 4 路电压用 DMA，为什么必须配成 DMA_Mode_Circular 而不是 Normal？

    Normal 模式搬完 BufferSize 个数据就停止，需要软件重新使能才会再搬。ADC 连续转换时，第二次转换的数据就没人搬了，数组会停在第一批值上。
    Circular 模式搬完自动重置计数器，永远循环，正好匹配「ADC 一直转、DMA 一直搬」的连续采集场景。单次采集（比如按一下键读一次）才用 Normal。

  2. DMA_InitStructure.DMA_PeripheralInc 为什么设成 Disable，而 DMA_MemoryInc 设成 Enable？

    因为外设端永远是同一个寄存器 ADC1->DR：4 个通道的数据都从这一个地址读出，地址不能变。设成 Enable 会让它去读 DR+2、DR+4，那些地址不是 ADC 数据寄存器，读回来是垃圾。
    内存端要依次写 AD_Value[0]、[1]、[2]、[3]，所以必须自增。这个「外设不动、内存动」的组合是外设→内存传输的标准配置。

  3. 把 AD_Value[4] 定义在 AD_DMA_Init() 函数内部，会发生什么？

    函数返回后，这块栈空间被释放，可能被其他函数的局部变量覆盖。DMA 仍在往里写，就写到了别人的数据上。
    现象：读数偶尔正确、偶尔是奇怪的数；严重时覆盖返回地址导致程序跑飞（HardFault）。修法是把缓冲区定义为全局数组或 static，并在注释里标明用途。

  4. 用 DMA 搬 1000 字节，BufferSize 填 1000，但发现只搬了 500 个就停了。可能是什么原因？

    最常见的是数据宽度设成了 HalfWord（16 位）：BufferSize 的单位是「数据单元」而不是字节。1000 个 HalfWord 需要 2000 字节的缓冲区，如果实际缓冲区只有 1000 字节，后半段就写越界了。
    另一种可能：BufferSize 是 16 位寄存器，最大 65535，超过要分批。先确认「单元数 × 单元字节数 = 实际缓冲区大小」，再查方向与自增配置。

USART 串口：收发、数据包与串口下载第五篇 · 通信总线

P25 – P30 · 串口协议 / 串口外设 / 发送与接收 / 数据包 / 串口下载　·　7 节　·　4 题

进阶

串口是「没有时钟线的通信」：双方事先约好速度（波特率），然后一位一位地发。没有时钟线省了两根线，代价是双方的计时必须足够准，差一点点就会把 0 读成 1。

读完这一课你能做到

  • 能画出串口一帧的位序，说清起始位、校验位、停止位各自防的是什么错
  • 能手算 BRR 寄存器值，解释为什么 9600 波特率在 72MHz 下是 0x1D4C
  • 能用中断接收 + 状态机解析一个「包头 + 数据 + 校验」的数据包
  • 知道没有 ST-Link 时怎么用 FlyMcu 经串口下载程序
一、一帧数据长什么样

串口（UART）在没有数据时线保持高电平（空闲态）。发一个字节的过程是：

顺序内容说明
1起始位（0）从高变低，告诉对方「要开始了」
2–98 个数据位低位在前（LSB first），先发 bit0
10校验位（可选）奇校验/偶校验/无
11停止位（1）拉高，长度可 1 / 1.5 / 2 位

「低位在前」这一点最容易记错：发 0x01 时，线上是先 1 后 7 个 0。用逻辑分析仪看波形时如果读出来是 0x80，就是这个位序搞反了。

起始位的作用是帧同步：接收方在空闲时一直等一个下降沿，一旦看到就启动自己的采样时钟。所以只要每帧都能重新对齐，双方波特率的微小误差就不会累积——这也是异步串口能工作的根本原因。

二、波特率：一个除法和一个小数

波特率 = 每秒传多少位。STM32 的波特率由 USART_BRR 决定：

USARTDIV = fCK / (16 × 波特率)

fCK 对 USART1 是 PCLK2 = 72MHz，对 USART2/3 是 PCLK1 = 36MHz。以 72MHz、9600 为例：

步骤计算结果
除法72,000,000 / (16 × 9600)468.75
整数部分（mantissa）4680x1D4
小数部分 × 160.75 × 16 = 120xC
BRR0x1D4C468.75

所以 9600 在 72MHz 下的 BRR 是 0x1D4C。实际误差约 0.02%，可以忽略。作为对照，115200 时 USARTDIV = 39.0625，小数部分只能取 1/16 的倍数（0.0625 正好等于 1/16），误差也几乎为零——这两个波特率是「天生准」的，所以最常用。

波特率对不上，第一个字节一定是乱码

接收方按自己的时钟采样，两边差 3% 以上就会在某一位采错。典型现象是：发 "Hello" 收到 "H€llo" 或一堆 ?。

排查顺序：① 两边波特率是不是一样（注意有些模块默认 115200）；② USART2/3 用的是 PCLK1 = 36MHz，别按 72MHz 算；③ 有没有奇偶校验不一致（8N1 是最常见的组合）。

四、中断接收：不要在主循环里死等

轮询接收（while(RXNE == RESET)）会把主循环卡住。正确做法是中断接收，把收到的字节放进缓冲区：

uint8_t RxData;                  // 最近收到的字节
uint8_t RxFlag = 0;

void Serial_RxIRQ_Init(void)
{
    NVIC_InitTypeDef NVIC_InitStructure;

    USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);   // 接收寄存器非空中断

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

void USART1_IRQHandler(void)
{
    if(USART_GetITStatus(USART1, USART_IT_RXNE) == SET){
        RxData = USART_ReceiveData(USART1);          // 读 DR 会自动清标志

}

读 DR 会自动清除 RXNE 标志，所以这个中断里不需要手动清。但如果开了溢出错误中断（ORE），就必须手动清，否则会卡在中断里反复进。

五、数据包：从「收字节」到「收一条消息」

单字节只能传命令，传不了「一组数据」。要传结构化的信息，得自己定一个包格式：

方案格式优点缺点
定长包0xFF + 4 字节数据 + 校验和解析简单数据长度固定
变长包（HEX）0xFF + len + data[len] + sum灵活要做状态机
文本包@data# 或 data\r\n人可读，串口助手能直接看效率低、要处理转义

变长 HEX 包的状态机是这类代码的标准答案：

/* 收到的字节喂进来，凑齐一包返回 1 */
uint8_t Packet_Parse(uint8_t byte, uint8_t *out, uint8_t *len)
{
    static uint8_t state = 0, idx = 0, sum = 0, n = 0;

    switch(state){
    case 0:                                  /* 等包头 */
        if(byte == 0xFF){ state = 1; }
        break;
    case 1:                                  /* 收长度 */
        n = byte;
        if(n == 0 || n > 32){ state = 0; break; }
        idx = 0; sum = 0; state = 2;
        break;
    case 2:                                  /* 收数据 */
        out[idx++] = byte;
        sum += byte;
        if(idx >= n){ state = 3; }
        break;
    case 3:                                  /* 校验 */
        state = 0;
        if(byte == sum){ *len = n; return 1; }
        break;
    }
    return 0;
}

这个状态机的价值不在代码本身，而在思路：每个字节都可能让状态前进或回到起点，任何时候都不会「卡住等」。串口数据随时可能丢字节、被干扰，一个会死等的解析函数（比如「等到收满 5 个字节」）会让整个接收通路永久瘫痪。

为什么中断里不能 printf

printf 最终会调到 fputc → Serial_SendByte → while(TXE == RESET)。9600 波特率发 1 个字节要 1.04ms，发 20 个字符就是 20ms。

USART 只有一个字节的接收缓冲，这 20ms 里来的数据全部丢失——而且是在「你正在调试的接收中断里」丢的，最容易误导排查方向。

  1. 72MHz 下要配 115200 波特率，USARTDIV 是多少？BRR 怎么填？

    USARTDIV = 72,000,000 / (16 × 115200) = 39.0625。整数部分 39 = 0x27，小数部分 0.0625 × 16 = 1，所以 BRR = 0x271。
    误差为 0（0.0625 正好是 1/16 的整数倍）。这就是 115200 在 72MHz 下特别准的原因；换成 100000 就有约 0.16% 误差，长帧可能出错。

  2. 串口收到的数据偶尔整段丢失，而且都是在「程序刚打印完调试信息」之后。最可能的原因？

    在接收中断里调用了 printf（或主循环长时间阻塞），导致 RXNE 溢出。USART 只有一个字节的接收缓冲，下一个字节到来时上一个还没读走，就会置 ORE 溢出标志、丢掉新数据。
    修法：中断里只把字节存进环形缓冲区并置标志，解析和打印都放到主循环。规范做法是「中断搬数据，主循环做业务」。

  3. 自定义的 HEX 包用「包头 0xFF + 长度 + 数据 + 校验和」，为什么必须校验和？

    串口在电气干扰、长线、共地不良时会翻转个别位。没有校验，一个 0x01 被干扰成 0x02，接收方会当成合法数据执行。
    校验和只能发现错误、不能纠正。工程上更稳的做法是 CRC16 + 超时重发；学习阶段用「累加和」足够，但一定要有——它是「数据可信」和「数据不可信」的分界线。

  4. 用 FlyMcu 下载程序，一直提示连接不上芯片，可能漏了哪一步？

    最常见的是 BOOT0 没接 1（此时芯片跑的是用户程序，不是 Bootloader），或者 TX/RX 没交叉接（TX 接 TX 是接不通的）。
    其次检查共地和波特率：波特率先降到 9600 试；有些 USB-TTL 模块的 3.3V 输出带不动板子，要单独给板子供电（只接 TX/RX/GND 三根线）。

难点

I2C 只用两根线就能挂一总线器件，靠的是「地址」和「应答」。它的时序不复杂，难的是节奏：什么时候该谁拉低、什么时候必须释放、释放多久才能被从机认出来。软件 I2C 写一遍，这套节奏就长在手上了。

一、两根线怎么区分「谁在说话」
线全称方向特点
SCLSerial Clock主机 → 从机时钟由主机产生
SDASerial Data双向半双工，同一时刻只能一个方向

起止条件（这两条是「帧边界」）：

  • 起始（S）：SCL 高电平时，SDA 由高变低。
  • 停止（P）：SCL 高电平时，SDA 由低变高。

数据有效性：SCL 高电平期间 SDA 必须稳定（接收方在这时采样），SDA 只允许在 SCL 低电平时变化。这条规则是「为什么起始/停止要用 SCL 高时的跳变」的原因——正常数据不允许这么跳，所以这种组合能被唯一识别为边界。

二、地址：7 位与 8 位的换算

每个从机有一个 7 位地址。传输时把它左移一位，最低位放读写标志：

8 位写地址 = 7 位地址 << 1 　 8 位读地址 = (7 位地址 << 1) | 1

器件7 位地址写（8 位）读（8 位）
MPU6050（AD0 = 0）0x680xD00xD1
MPU6050（AD0 = 1）0x690xD20xD3
SSD1306 OLED0x3C0x780x79
AT24C02 EEPROM0x500xA00xA1

代码里常见的「地址差 1」的 bug，几乎都是把 7 位当成了 8 位（或反过来）。判据：发送时用的是 8 位形式；算偏移、查手册时用 7 位形式。

三、读一个寄存器：写地址 → 写寄存器号 → 重启 → 读

I2C 读操作比写多一个「重复起始（Sr）」：

步骤主机动作从机回应
1S（起始）—
2发 0xD0（写）ACK
3发寄存器地址（如 0x75）ACK
4Sr（重复起始）—
5发 0xD1（读）ACK
6收 1 字节，回 NACK送出数据
7P（停止）—

第 6 步的 NACK 是「我只要一个字节，别再发了」的暗号。要读多个字节，前几个回 ACK，最后一个回 NACK。

/* 软件 I2C 读寄存器：先写寄存器地址，再读数据 */
uint8_t MPU6050_ReadReg(uint8_t reg)
{
    uint8_t data;

    MyI2C_Start();
    MyI2C_SendByte(0xD0);        MyI2C_ReceiveAck();   // 写地址
    MyI2C_SendByte(reg);         MyI2C_ReceiveAck();   // 寄存器号
    MyI2C_Start();                                     // 重复起始
    MyI2C_SendByte(0xD1);        MyI2C_ReceiveAck();   // 读地址
    data = MyI2C_ReceiveByte();  MyI2C_SendAck(1);     // 读 1 字节 + NACK
    MyI2C_Stop();
    return data;
}

void MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    MyI2C_Start();
    MyI2C_SendByte(0xD0);        MyI2C_ReceiveAck();
    MyI2C_SendByte(reg);         MyI2C_ReceiveAck();
    MyI2C_SendByte(value);       MyI2C_ReceiveAck();
    MyI2C_Stop();
}

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t i, byte = 0;
    MyI2C_SDA_H();                                  // 释放 SDA，交给从机
    for(i = 0; i < 8; i++){
        MyI2C_SCL_L(); Delay_us(2);
        MyI2C_SCL_H(); Delay_us(2);
        byte <<= 1;
        if(MyI2C_SDA_R()) byte |= 0x01;              // 高位先到
    }
    return byte;
}

void MyI2C_SendAck(uint8_t ack)                     // ack=0 应答，1 非应答
{
    MyI2C_SCL_L();
    if(ack) MyI2C_SDA_H(); else MyI2C_SDA_L();
    Delay_us(2);
    MyI2C_SCL_H(); Delay_us(2);
    MyI2C_SCL_L(); Delay_us(2);
}

    MPU6050_WriteReg(0x1A, 0x06);    // ③ 低通滤波 5Hz
    MPU6050_WriteReg(0x1B, 0x00);    // ④ 陀螺 ±250°/s

void MPU6050_GetData(int16_t *ax, int16_t *ay, int16_t *az,
                     int16_t *gx, int16_t *gy, int16_t *gz)
{
    uint8_t buf[14];
    uint8_t i;

    MyI2C_Start();
    MyI2C_SendByte(0xD0);  MyI2C_ReceiveAck();
    MyI2C_SendByte(0x3B);  MyI2C_ReceiveAck();       // 从数据首地址开始
    MyI2C_Start();
    MyI2C_SendByte(0xD1);  MyI2C_ReceiveAck();

    for(i = 0; i < 14; i++){
        buf[i] = MyI2C_ReceiveByte();
        MyI2C_SendAck(i == 13);                      // 最后一个 NACK
    }
    MyI2C_Stop();

    *ax = (int16_t)((buf[0]  << 8) | buf[1]);        // 高字节在前
    *ay = (int16_t)((buf[2]  << 8) | buf[3]);
    *az = (int16_t)((buf[4]  << 8) | buf[5]);
    *gx = (int16_t)((buf[8]  << 8) | buf[9]);        // buf[6..7] 是温度
    *gy = (int16_t)((buf[10] << 8) | buf[11]);
    *gz = (int16_t)((buf[12] << 8) | buf[13]);
}

换算成物理量：角度 = 原始值 / 16384（单位 g），角速度 = 原始值 / 131（单位 °/s），温度 = 36.53 + 原始值 / 340。静止平放时，az 应该接近 16384（1g），ax、ay 接近 0——这是最快的自检方法。

五、硬件 I2C：把时序交给外设

软件 I2C 占两个普通 IO，每个字节都要 CPU 逐位翻转。硬件 I2C 把它交给外设，CPU 只发命令：

对比软件 I2C硬件 I2C
占用引脚任意两个 IO固定的 I2C 引脚（I2C1: PB6/PB7 或重映射 PB8/PB9）
CPU 占用高（每位都要执行指令）低（写数据寄存器即可）
速度通常 50–100kHz可达 400kHz（快速模式）
灵活性时序可调，任何脚都行受外设限制，遇从机时钟拉伸可能卡死
调试难度直观，示波器一看就懂卡在 while 等标志时很难判断

硬件 I2C 的关键调用顺序（F103 的标准库，缺一步就会卡住）：

硬件 I2C 卡死的经典场景

现象：程序停在某个 while(!I2C_CheckEvent(...)) 里出不来。

原因：从机在做时钟拉伸（SCL 拉低不放），或总线上有器件把 SDA 一直拉低（上一次通信被打断）。

救法：① 加超时计数，超时就 I2C_GenerateSTOP + 软复位 I2C（I2C_DeInit）；② 上电初始化时先发 9 个 SCL 脉冲，把卡住的从机「敲」出来。这也是很多工程宁可用软件 I2C 的原因——出问题时你看得见。

  1. MPU6050 的 7 位地址是 0x68，代码里为什么写 0xD0 和 0xD1？

    因为 I2C 传输时第一个字节是「7 位地址 + 1 位读写标志」。0x68 << 1 = 0xD0（写），0xD0 | 1 = 0xD1（读）。
    0x68 是手册里的 7 位地址，0xD0/0xD1 是总线上的 8 位形式。两者不是两个器件，写错会得到 NACK（从机不应答），表现为读回 0xFF。

  2. 用软件 I2C 读 MPU6050，WHO_AM_I（0x75）能读回 0x68，但加速度三个值一直是 0。最可能的原因？

    芯片还在睡眠模式。MPU6050 上电默认 PWR_MGMT_1 = 0x40（SLEEP = 1），此时内部振荡器关闭、传感器不采样，数据寄存器保持 0。
    解决：初始化时先写 PWR_MGMT_1 = 0x01（解除睡眠并选陀螺 X 轴 PLL 作时钟），延时 50ms 再读。这个顺序不能颠倒——先读后唤醒，第一次读到的还是 0。

  3. 为什么 I2C 的 SDA 和 SCL 必须用开漏输出，而且必须外接上拉电阻？

    总线上挂着多个器件，任何一个都可能拉低。如果用推挽，一个器件输出高（主动接 3.3V）、另一个输出低（接 GND），两只管子直接对通，会烧引脚。
    开漏只能「拉低或松手」，高电平靠上拉电阻恢复，天然实现「线与」：谁拉低，线就是低。没有上拉电阻，开漏永远输出不了高电平，总线会一直保持低、通信完全不通。

  4. 硬件 I2C 程序卡在 while(!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED)); 里不动，怎么排查和救活？

    先判断是「从机没应答」还是「总线被占住」：用示波器看 SCL 是否还在跳。SCL 不动 = 从机在拉伸时钟，或外设状态机卡住。
    救活三板斧：① 加超时计数，超时后 I2C_GenerateSTOP 并 I2C_DeInit 重初始化；② 初始化前手动发 9 个 SCL 脉冲，把拉低 SDA 的从机「敲」松；③ 换回软件 I2C——时序全在手里，出问题能立刻定位。产品里更稳的做法是软件 I2C + 超时保护。

SPI 与 W25Q64：外部 Flash第五篇 · 通信总线

难点

SPI 是「用线换速度」的总线：四根线，全双工，没有地址、没有应答，靠一根片选线决定跟谁说话。因为没有任何协议开销，它能跑到几十 MHz——代价是接错一根线就完全不通，而且从机不会告诉你它没听懂。

一、四根线，各管一件事

和 I2C 最大的区别：SPI 没有地址，也没有应答。选哪个器件全靠 CS 拉低；从机收没收到，主机不知道。所以 SPI 器件通常需要「读回 ID」或「读状态寄存器」来确认通信正常。

另一个区别是全双工：发一个字节的同时就收到一个字节。所以 SPI 的读写是同一个动作——SwapByte(0xFF) 既能发数据，也能收数据。

标准库里的对应关系：SPI_CPOL_Low + SPI_CPHA_1Edge 就是模式 0。

Flash 只能「1 变 0」

NOR Flash 的物理特性决定了：写入只能把 1 变成 0，想把 0 变回 1 必须擦除（擦除会把整片区域变成 0xFF）。

所以每次写之前都要先擦。忘了擦的典型现象是：第一次写成功，第二次写同一个地址读出来还是旧数据（因为旧数据里的 0 无法变回 1）。

    GPIO_ResetBits(GPIOA, GPIO_Pin_5);     // 模式 0：SCK 空闲为低
}

void MySPI_Start(void)  { GPIO_ResetBits(GPIOA, GPIO_Pin_4); }
void MySPI_Stop(void)   { GPIO_SetBits(GPIOA, GPIO_Pin_4); }

/* 全双工交换一个字节：模式 0（SCK 低空闲，上升沿采样，高位先出） */
uint8_t MySPI_SwapByte(uint8_t byte)
{
    uint8_t i, recv = 0;

    for(i = 0; i < 8; i++){
        if(byte & 0x80) GPIO_SetBits(GPIOA, GPIO_Pin_7);
        else            GPIO_ResetBits(GPIOA, GPIO_Pin_7);
        byte <<= 1;

        GPIO_SetBits(GPIOA, GPIO_Pin_5);          // 上升沿：从机采样 MOSI
        Delay_us(1);
        recv <<= 1;
        if(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_6)) recv |= 0x01;   // 同时采 MISO
        GPIO_ResetBits(GPIOA, GPIO_Pin_5);        // 下降沿：数据可以变化
        Delay_us(1);
    }
    return recv;
}

/* 读 JEDEC ID，应得 EF 40 17 */
void W25Q64_ReadID(uint8_t *mid, uint16_t *did)
{
    MySPI_Start();
    MySPI_SwapByte(0x9F);
    *mid = MySPI_SwapByte(0xFF);
    *did = (MySPI_SwapByte(0xFF) << 8) | MySPI_SwapByte(0xFF);
    MySPI_Stop();
}

读 ID 是验证 SPI 通路的最快方法：EF 40 17 说明线接对了、模式对了、供电正常。先过这一关，再写 Flash——否则后面出错时分不清是时序问题还是芯片问题。

void W25Q64_WriteEnable(void)
{
    MySPI_Start();
    MySPI_SwapByte(0x06);          // 写使能
    MySPI_Stop();
}

void W25Q64_WaitBusy(void)
{
    uint8_t status;
    MySPI_Start();
    MySPI_SwapByte(0x05);          // 读状态寄存器
    do{
        status = MySPI_SwapByte(0xFF);
    }while(status & 0x01);         // bit0 = BUSY
    MySPI_Stop();
}

void W25Q64_SectorErase(uint32_t addr)
{
    W25Q64_WriteEnable();
    MySPI_Start();
    MySPI_SwapByte(0x20);                            // 扇区擦除
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    MySPI_Stop();
    W25Q64_WaitBusy();                               // 擦除要等，别紧接着写
}

/* 写一页（≤256 字节，且不能跨页） */
void W25Q64_PageProgram(uint32_t addr, uint8_t *buf, uint16_t len)
{
    uint16_t i;
    if(len > 256) len = 256;

    W25Q64_WriteEnable();
    MySPI_Start();
    MySPI_SwapByte(0x02);                            // 页编程
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    for(i = 0; i < len; i++){
        MySPI_SwapByte(buf[i]);
    }
    MySPI_Stop();
    W25Q64_WaitBusy();
}

void W25Q64_ReadData(uint32_t addr, uint8_t *buf, uint32_t len)
{
    uint32_t i;
    MySPI_Start();
    MySPI_SwapByte(0x03);                            // 读数据
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    for(i = 0; i < len; i++){
        buf[i] = MySPI_SwapByte(0xFF);               // 读的时候发什么无所谓
    }
    MySPI_Stop();
}

三个必须遵守的顺序：

  1. 擦 → 写 → 读，不能跳过擦除。
  2. 写之前发 Write Enable（0x06），否则写入被忽略，读回来还是旧数据。
  3. 每次写/擦之后等 BUSY 清零，芯片在忙时只认读状态指令，其他指令一概不理。

页内回卷是什么

页大小为 256 字节，页内地址是 8 位。写第 257 个字节时，低 8 位地址回绕到 0，于是又写回页首，把刚写的第一批数据覆盖了。

现象：写 300 字节，最后读出来「后 44 字节覆盖了前 44 字节」。跨页写必须拆成两次 PageProgram。

  1. 读 W25Q64 的 JEDEC ID 读到 EF 40 17，这三位分别代表什么？读到 FF FF FF 说明什么？

    EF = 厂商 ID（Winbond），4017 = 器件型号，对应 W25Q64（64Mbit）。读对说明 SPI 四根线、模式、供电都正常。
    FF FF FF 说明 MISO 一直是高（或 CS 没拉低）：可能是 MISO 没接、从机未被选中、或者从机根本没供电。这是「通信完全没建立」的典型值，而不是「读错了数据」。

  2. 为什么 Flash 写之前必须先擦除？不擦会怎样？

    NOR Flash 的写入只能把位从 1 变成 0（电子注入），无法从 0 变回 1。擦除会把整片区域恢复成全 1（0xFF）。
    不擦直接写：如果目标位已经是 0，新数据要写 1 就写不进去，读出来仍是 0。现象是「第一次写成功，改值后再写无效」——因为旧数据的 0 位卡住了。擦除的最小单位是 4KB 扇区，不能只擦一个字节。

  3. 用软件 SPI 写 300 字节的数据，写完读回来发现第 0–43 字节和第 256–299 字节内容一样。为什么？

    发生了页内回卷。页大小 256 字节，页内地址只有 8 位，写到第 257 个字节时地址回绕到页首，把开头的数据覆盖了。
    修法：按 256 字节对齐拆包，每次 PageProgram 只写一页内的数据。写之前还要确认这笔地址已经擦除过，否则旧数据的 0 位仍然卡住。

  4. 硬件 SPI 用 SPI_NSS_Soft（软件片选），为什么 CS 引脚要配成普通推挽输出而不是复用推挽？

    因为 SPI_NSS_Soft 的意思是「NSS 由软件管理」，硬件不接管这个引脚。配成复用推挽的话，引脚由 SPI 外设控制，你在代码里拉低/拉高 CS 不会生效。
    配成普通推挽，代码里手动 GPIO_ResetBits(CS) 拉低选中、SetBits 拉高释放，事务边界完全由你控制。这也是为什么「软件片选 + 硬件 SPI」既快又灵活。

一、时间戳：用一个整数表示一个时刻

Unix 时间戳 = 从 1970-01-01 00:00:00 UTC 起，经过的秒数。

时刻时间戳说明

2000-01-01 00:00:00 UTC946684800约 30 年
2026-11-16 00:00:00 UTC1794700800约 56.8 年

用一个整数表示时刻，好处是：比较大小、算间隔、存进 Flash，全都是一句减法。代价是显示时要自己换算成年月日。

时区差 8 小时

时间戳永远是 UTC。北京时间 = UTC + 8 小时 = 时间戳 + 28800 秒。

如果显示的时间总是差 8 小时，不是 RTC 不准，是换算时忘了加 28800。反过来，如果「设置时间」时加了 28800、读的时候又加一次，就会差 16 小时。

二、时间戳 ↔ 日期：闰年是唯一的坑

从时间戳算日期，就是把秒数一年一年、一月一月地减下去：

步骤做法
年从 1970 开始，每年减 365 或 366 秒数，减不动为止
月用 12 个月的天数表，逐月减
日时分秒剩下的秒数整除 86400 得日，余数再拆时、分、秒
闰年规则能被 4 整除且不能被 100 整除，或能被 400 整除

月天数表：{31, 28/29, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31}。二月在闰年是 29 天——这是唯一需要特殊处理的地方，其他地方都是固定值。

typedef struct {
    uint16_t year;
    uint8_t  month, day, hour, minute, second;
} MyTime;

uint8_t Is_Leap(uint16_t y)
{
    return (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
}

/* 时间戳 → 日期（不考虑时区，需要北京时间就先用 ts + 28800 再调） */
void Timestamp_To_Time(uint32_t ts, MyTime *t)
{
    static const uint8_t mdays[12] = {31,28,31,30,31,30,31,31,30,31,30,31};
    uint32_t days = ts / 86400;
    uint32_t secs = ts % 86400;
    uint16_t y = 1970;
    uint8_t  m = 0;

    t->hour   = secs / 3600;
    t->minute = secs % 3600 / 60;
    t->second = secs % 60;

    while(1){
        uint16_t yd = Is_Leap(y) ? 366 : 365;
        if(days < yd) break;
        days -= yd;
        y++;
    }
    t->year = y;

    for(m = 0; m < 12; m++){
        uint8_t md = mdays[m] + ((m == 1 && Is_Leap(y)) ? 1 : 0);
        if(days < md) break;
        days -= md;
    }
    t->month = m + 1;
    t->day   = days + 1;        // days 是从 0 开始的
}

反过来（日期 → 时间戳）就是把同样的事做加法。这一段建议自己写一遍——写完就再也不会记错闰年规则。

三、RTC：一个 32 位秒计数器

STM32 的 RTC 不是「年月日时分秒寄存器」，而是一个 32 位的秒计数器（RTC_CNT），每来一个 1Hz 时钟加一。它有三种时钟源：

时钟源频率精度说明
LSE（外部 32.768kHz 晶振）32.768kHz高（取决于晶振）首选，配 6pF 负载电容
LSI（内部 RC）约 40kHz差（±50% 起振误差，温漂大）省晶振，但一天能差几分钟
HSE/1288MHz/128 = 62.5kHz高（主晶振）主电源断电就停，不适合做 RTC

选 LSE 后，预分频设成 32767（即 ÷32768），得到精确的 1Hz：

1Hz = 32768Hz / (PRL + 1)　→　PRL = 32767

void MyRTC_Init(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR | RCC_APB1Periph_BKP, ENABLE);
    PWR_BackupAccessCmd(ENABLE);          // ① 打开备份域写权限（必须！）

    if(BKP_ReadBackupRegister(BKP_DR1) != 0xA5A5){
        /* ② 第一次上电（或备份域被清）：重新配置 */
        RCC_LSEConfig(RCC_LSE_ON);
        while(RCC_GetFlagStatus(RCC_FLAG_LSERDY) == RESET);   // 等 LSE 起振

        RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE);
        RCC_RTCCLKCmd(ENABLE);

        RTC_WaitForSynchro();             // 等 RTC 寄存器与 APB1 同步
        RTC_WaitForLastTask();

        RTC_SetPrescaler(32767);          // 32768 / 32768 = 1Hz
        RTC_WaitForLastTask();

        MyRTC_SetTime(2026, 11, 16, 12, 0, 0);
        BKP_WriteBackupRegister(BKP_DR1, 0xA5A5);   // ③ 打个标记，下次不再重配
    }else{
        /* 备份域还在，RTC 一直在走，什么都不用做 */
    }
}

uint32_t MyRTC_GetCounter(void)
{
    return RTC_GetCounter();
}

void MyRTC_SetCounter(uint32_t ts)
{
    RTC_SetCounter(ts);
    RTC_WaitForLastTask();
}

BKP_DR1 里那个 0xA5A5 是整个流程的关键：它记录「RTC 已经配过了」。没有它，每次上电都会把时间重置成 2026-11-16，断电就白搭。

四、BKP：备份域里那 20 个字节
项目规格说明
备份寄存器16 位 × 10 个（BKP_DR1–DR10），部分型号 42 个每个 16 位，共 20 字节
供电VBAT（纽扣电池）或 VDD主电源断了自动切到 VBAT
访问前提开 PWR 时钟 + PWR_BackupAccessCmd(ENABLE)少一步，写不进去也不报错
会被清空的情况备份域复位（BKP_DeInit）、VBAT 断电、下载时勾了「全片擦除」所以标记要能容错

BKP 的用途不止存标记，还能存「校准值」「开机次数」「上次的配置参数」——任何「掉电不能丢、但又不是每秒都变」的小数据都适合。

五、每秒中断：让时间「动」起来

有了秒计数，可以开 RTC 秒中断，每秒刷新一次显示：

void MyRTC_IRQ_Init(void)
{
    NVIC_InitTypeDef NVIC_InitStructure;

    RTC_ITConfig(RTC_IT_SEC, ENABLE);
    RTC_WaitForLastTask();

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitStructure.NVIC_IRQChannel = RTC_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}

void RTC_IRQHandler(void)
{
    if(RTC_GetITStatus(RTC_IT_SEC) != RESET){
        RTC_ClearITPendingBit(RTC_IT_SEC);       // 必须清
        RTC_WaitForLastTask();
        /* 这里只置标志，显示放主循环 */
    }
}

注意 RTC_WaitForLastTask() 这个调用：RTC 寄存器挂在 APB1 上，但 RTC 本体跑在 LSE 域，写操作是异步的。不等同步就连续写，后一次可能被丢弃——这是「设置了时间但没生效」的常见原因。

  1. 2026-11-16 12:00:00（北京时间）对应的时间戳大概是多少？为什么不用精确值也能判断对错？

    北京时间要先减 8 小时换成 UTC：2026-11-16 04:00:00 UTC。从 1970 到 2026 是 56 年，其中闰年 14 个（1972…2024），天数 = 56×365 + 14 = 20454 天，秒数 ≈ 20454 × 86400 ≈ 1,767,225,600，再加 4 小时 14400 ≈ 1,767,240,000。
    手算允许有几百秒误差（闰年数、跨年边界），量级对上就说明方法对了。要精确值就用代码算，或用 date -d 之类工具核对。

  2. 为什么 RTC 要配 32767 而不是 32768 作为预分频值？

    因为 RTC 的预分频寄存器 PRL 是「分频值 − 1」。写 32767 表示 ÷(32767+1) = ÷32768，得到 1Hz。
    写 32768 会变成 ÷32769，时钟慢约 30ppm，一天差约 2.6 秒。这类「差一点点」的错误很难在短时间内发现，但对时钟产品是致命的。

  3. 断电后时间归零，但换了新电池就好了。怎么判断到底是电池没电还是配置没保存？

    先量 VBAT 电压：正常纽扣电池应 ≥2.5V（CR1220 新电池约 3V），低于 2V 就会丢备份域。
    电池正常但仍归零，说明 BKP 标记没写成功：检查是否漏了 PWR_BackupAccessCmd(ENABLE)（不打开写权限，写 BKP 静默失败）。也可以读一次 BKP_DR1 确认标记是否真的存进去了。

  4. 用 RTC 秒中断每秒刷新 OLED，发现屏幕偶尔闪一下或显示错位。为什么不能直接在中断里刷屏？

    刷一整屏 OLED 要走 I2C 写 1024 字节，软件 I2C 下要几十毫秒。这远超 1 秒的中断间隔不说，期间所有其他中断都被阻塞，显示会撕裂。
    正确做法：中断里只置 sec_flag = 1，主循环检测到标志再刷新显示。这就是「中断搬数据、主循环做业务」的又一次应用。

难点

低功耗不是「关机」，而是「把不要的部分一个个关掉，只留下能把自己叫醒的最小电路」。三种模式的区别只有一个问题：断电断到什么程度，以及醒来之后还记不记得自己是谁。

三个关键结论：

  1. 睡眠最省事：外设都在跑，醒来接着干，适合「等一个中断但不想空转」。
  2. 停止最常用：电流从 mA 级降到 μA 级，SRAM 还在（变量不丢），代价是醒来要重配时钟。
  3. 待机最省电：变量全丢、程序从头跑，只适合「按一下键开机」这类场景。
二、进停止模式：四行代码，两个坑
#include "stm32f10x.h"

void Enter_Stop_Mode(void)
{
    /* ① 开 PWR 时钟（必须，否则下面两句静默失败） */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

    /* ② 允许在停止模式下使用低功耗稳压器 */
    PWR_EnterSTOPMode(PWR_Regulator_LowPower, PWR_STOPEntry_WFI);
    /* —— 程序在这里停住，直到有 EXTI 中断把它叫醒 —— */

    /* ③ 唤醒后时钟自动切回 HSI 8MHz，必须重新配成 72MHz */
    SystemInit();

    /* ④ 如果开了串口，波特率要按新时钟重算 */
    Serial_Init();
}

两个坑：

  • 唤醒后时钟是 HSI 8MHz。如果不调 SystemInit()，所有依赖 72MHz 的东西全部变慢 9 倍：串口波特率变成 1/9（全是乱码）、定时器周期变成 9 倍、I2C 时序全乱。现象是「唤醒后串口突然全是乱码」，很多人误以为是串口坏了。
  • 调试时进停止模式会断开 SWD。芯片一停，调试器就失去连接，看起来像「程序卡死」。做法是调试阶段先不调 PWR_EnterSTOPMode，或者用 DBGMCU_Config(DBGMCU_STOP, ENABLE) 让调试器暂停时保持时钟。
三、进待机模式：醒来就是一次重启
void Enter_Standby_Mode(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

    /* ① 使能 WKUP 引脚（PA0）作为唤醒源 */
    PWR_WakeUpPinCmd(ENABLE);

    /* ② 清唤醒标志，否则可能立刻被上一次的标志唤醒 */
    PWR_ClearFlag(PWR_FLAG_WU);

    /* ③ 进待机 */
    PWR_EnterSTANDBYMode();
}

待机唤醒后等同复位：main 从头执行，全局变量重新初始化，SRAM 内容全没了。所以「待机前保存的状态」必须写进 BKP 或 Flash，醒来再读回来。

唤醒源配置方式说明
WKUP 引脚（PA0）PWR_WakeUpPinCmd(ENABLE)上升沿有效，板上通常接按键
RTC 闹钟RTC_ITConfig(RTC_IT_ALR, ENABLE) + RTC_SetAlarm可以定时唤醒，做「每小时采一次」
IWDG 复位使能独立看门狗看门狗超时把芯片复位唤醒

四、改主频：72 / 36 / 24 怎么切

SystemInit() 里默认把 PLL 配成 HSE×9 = 72MHz。想在运行时改，本质是改 PLL 倍频系数并重新切换时钟源：

目标PLL 倍频分频说明
72MHz×9AHB ÷1、APB1 ÷2、APB2 ÷1默认，性能最高
36MHz×9 后 AHB ÷2APB1 ÷2 → 18MHz常用低功耗档
24MHz×6全 ÷1低速、低功耗
8MHz（HSI）不用 PLL—最省电，但外设时序全变

改主频的标准步骤：**切回 HSI → 关 PLL → 改 PLL 参数 → 开 PLL → 等锁定 → 切到 PLL → 更新 SystemCoreClock**。中间任何一步顺序错了，芯片会短暂失去时钟（表现为程序跑飞）。

改完主频必须同步 SystemCoreClock

所有库函数（串口波特率、定时器、SysTick、I2C 分频）都读 SystemCoreClock 这个变量。你改了实际主频却没改这个变量，库函数会按旧的 72MHz 算分频，结果全部偏差。

标准做法：把 system_stm32f10x.c 里的 SystemCoreClockUpdate() 调一次，它会重新读寄存器算出真实频率。

五、功耗优化的实际顺序
优先级措施能省多少代价
1关掉不用的外设时钟（RCC_APB2PeriphClockCmd(..., DISABLE)）几 mA无
2没用到的 GPIO 配成模拟输入几百 μA无
3降低主频（72 → 8MHz）约 10 倍性能下降
4空闲时进睡眠一半以上唤醒有延迟
5空闲时进停止降 1000 倍要重配时钟
6空闲时进待机降到 2μA状态全丢

「GPIO 配成模拟输入」这一条最反直觉，但很有效：浮空输入的引脚会被外部噪声不断充放电，产生额外功耗；模拟输入把数字通路完全关闭，最省电。

六、这一课和前面几课的关系

低功耗不是孤立的一课，它把前面所有外设串了起来：

  • EXTI（第 06 课）：停止模式的唤醒源，没有它就叫不醒。
  • RTC（第 16 课）：待机模式下唯一还能「看时间」的东西，也是定时唤醒的闹钟。
  • USART（第 13 课）：唤醒后要重配波特率，否则乱码。
  • IWDG（第 18 课）：待机时也能复位唤醒，是「兜底」手段。

一个真实的低功耗采集节点大概长这样：平时待机（2μA）→ RTC 每小时闹钟唤醒 → 醒来配时钟、读传感器、发串口 → 再进待机。整机平均电流可以做到几十 μA，一节纽扣电池撑一年。

  1. 停止模式唤醒后，为什么串口会输出乱码？

    唤醒后时钟自动切回 HSI 8MHz，而 USART_BRR 还是按 72MHz 算出来的值。实际波特率变成设定值的 1/9（比如设 9600，实际约 1067），对方按 9600 采样，收到的全是乱码。
    修法：唤醒后先 SystemInit() 把时钟恢复到 72MHz 再 Serial_Init() 重算 BRR；或者接受 8MHz 运行，用 8MHz 重算一次波特率。

  2. 睡眠、停止、待机三种模式，分别丢失了什么？

    睡眠：什么都不丢，只是内核停了。
    停止：丢时钟（HSI/HSE 停），但 SRAM 和寄存器内容保持，变量还在。
    待机：丢 SRAM 和寄存器内容，等于复位，只有 BKP 和 RTC（有 VBAT 时）还在。

  3. 想让设备「按一下 PA0 上的按键才开机」，应该用哪种低功耗模式？为什么不能用停止模式？

    用待机模式。WKUP 引脚（PA0）的上升沿是待机模式的专用唤醒源，醒来等同复位，正好符合「开机」的语义。
    停止模式也能被 EXTI 唤醒，但它是「从暂停处继续」：醒来变量还在、程序接着跑，适合「休眠—继续」；而「开机」要求程序从头初始化，用待机更干净。

  4. 把主频从 72MHz 改成 36MHz 后，串口能通、但定时器慢了正好一倍。为什么？

    因为外设的时钟是从主频分频来的。主频减半、分频系数不变，定时器时钟也减半，同样的 PSC/ARR 算出来的周期就翻倍。
    这其实是「正确」的行为，不是 bug。要恢复原来的定时，需要把 PSC 或 ARR 减半；同时别忘了更新 SystemCoreClock，否则库函数还会按旧值算。

看门狗是一个「你不按时喂我，我就复位你」的倒计时器。它不管你的代码写得对不对，只保证一件事：程序卡死以后，设备能自己爬起来。

  • 能正确选择喂狗位置（主循环，不是中断）
  • 知道调试时怎么防止「被狗咬」
一、两种狗，两种脾气
项目独立看门狗 IWDG窗口看门狗 WWDG

一句话选择：只想防卡死，用 IWDG；要检测「任务执行时间异常」，用 WWDG。绝大多数项目只用 IWDG。

二、IWDG：算清溢出时间

公式：

T = (4 × 2^prer) × (RLR + 1) / 40000

其中 prer 是预分频档位（0–6，对应分频 4、8、16、32、64、128、256），RLR 是 12 位重装值（0–4095），40kHz 是 LSI 的标称频率。

预分频分频值RLR溢出时间说明
4（prer=0）44095约 410ms太短，容易误复位
16（prer=2）164095约 1.6s—
64（prer=4）64625约 1.0s1 秒档最常用
64（prer=4）644095约 6.55s慢任务
256（prer=6）2564095约 26.2s上限
#include "stm32f10x.h"

/* prer: IWDG_Prescaler_4/8/16/32/64/128/256；rlr: 0~4095 */
void IWDG_Init(uint8_t prer, uint16_t rlr)
{
    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);   // ① 解锁（写保护）
    IWDG_SetPrescaler(prer);                        // ② 预分频
    IWDG_SetReload(rlr);                            // ③ 重装值
    IWDG_ReloadCounter();                           // ④ 先喂一次，避免立刻溢出
    IWDG_Enable();                                  // ⑤ 启动（启动后不能关）
}

/* 喂狗：把计数器重新装成 RLR */
void IWDG_Feed(void)
{
    IWDG_ReloadCounter();
}

注意 LSI 不准：40kHz 只是标称值，实际可能在 30–60kHz 之间（温漂大）。所以溢出时间有 ±50% 的误差。设计时按「最坏情况」留余量：想让狗 1 秒咬人，就按 0.5 秒来算喂狗周期。

三、WWDG：喂早了也咬人

WWDG 的计数器是 7 位的，从 0x7F 递减。它有两个界限：

界限含义
窗口值 W[6:0]计数器高于这个值时喂狗 → 复位（喂太早）
0x3F计数器低于这个值就复位（喂太晚）

所以合法喂狗区间是 0x3F < CNT ≤ W。窗口值由 WWDG_SetWindowValue() 设定，越低窗口越窄。

void WWDG_Init(uint8_t tr, uint8_t wr, uint32_t fprer)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);

    WWDG_SetPrescaler(fprer);        // WWDG_Prescaler_1/2/4/8
    WWDG_SetWindowValue(wr);         // 窗口上限（一般 0x5F 左右）
    WWDG_Enable(tr);                 // tr: 初始计数值（0x40~0x7F）
}

void WWDG_Feed(void)
{
    WWDG_SetCounter(0x7F);           // 重新装满
}

WWDG 的真实价值不在「防卡死」，而在「检测执行时间异常」：如果一个周期性任务本应 10ms 完成，你可以在任务开始时喂狗、任务结束时检查，一旦某次跑了 100ms，狗已经咬过了——这比 IWDG 的「卡死才复位」更敏感。

四、喂狗位置：这一条决定狗有没有用
喂狗位置效果评价
主循环开头主循环任何一步卡住 → 复位正确
定时器中断里主循环死了，中断还在喂 → 永远不复位错误，最常见
每个任务结束时任务没跑完就不喂好（多任务系统）
只在初始化后喂一次等于没开狗无效

在中断里喂狗 = 白开看门狗

定时器中断是硬件触发的，只要时钟在、中断没被关，它就会一直进。主循环里 while(1) 卡死、I2C 死等、指针跑飞——这些都不会阻止定时中断继续喂狗。

所以狗永远不咬，问题永远暴露不出来。喂狗必须放在「主循环走完一圈」这个位置，让「主循环还活着」成为喂狗的前提。

正确的用法是这样：

int main(void)
{
    IWDG_Init(IWDG_Prescaler_64, 625);   // 约 1 秒

    LED_Init();
    OLED_Init();
    Key_Init();

    while(1){
        /* 业务：读按键、刷显示、算数据 */
        Key_Process();
        OLED_Refresh();

        /* 一圈都走完了，才喂狗 */
        IWDG_Feed();
    }
}

如果某次 OLED_Refresh() 因为 I2C 总线被拉死而卡住，主循环回不来，1 秒后狗就复位——设备自己恢复。这就是看门狗的全部价值。

五、调试时别被狗咬

现象原因修法

设太长（比如 30 秒），设备卡死后要等半分钟才恢复，用户体验很差；设太短，正常的长任务会被误杀。

  1. LSI 按 40kHz 算，预分频 64、重装值 625，看门狗的溢出时间是多少？

    分频后计数频率 = 40000 / 64 = 625Hz，即每 1.6ms 减一。计数 626 次（RLR+1）→ 626 × 1.6ms ≈ 1.0 秒。
    由于 LSI 实际可能在 30–60kHz，真实溢出时间在 0.67–1.33 秒之间。所以喂狗周期要按 0.5 秒左右设计，留足余量。

  2. 为什么「在定时器中断里喂狗」等于没开看门狗？

    定时器中断由硬件触发，只要时钟在跑、中断没被屏蔽，它就会一直进——不管主循环是不是已经卡死。
    于是主循环死在某个 while 里，中断仍在喂狗，狗永远不咬，故障就永远暴露不出来。喂狗必须放在「主循环走完一圈」的位置，让它成为「主循环还活着」的证据。

  3. 独立看门狗一旦启动就不能关闭，这句话有什么实际后果？

    启动之后，只要程序没有按期喂狗，芯片就一定会复位，IWDG_Disable 之类的函数并不存在。所以「调试时先关掉狗」这条路走不通，只能用 DBGMCU_Config 在调试暂停时冻结计数。
    另一个后果：如果代码里有超过溢出时间的阻塞操作（大块 Flash 擦除、长时间延时），必须在中间插喂狗，否则功能永远做不完就被复位。

  4. 什么情况下该用窗口看门狗而不是独立看门狗？举一个具体例子。

    当「程序跑得太快」也是异常时。比如一个控制循环要求每 10ms 执行一次，如果某次因为逻辑错误 1ms 就转完了，说明某段代码被跳过——IWDG 检测不到（它只看你有没有卡住），WWDG 能：喂太早直接复位。
    典型场景：电机闭环控制、安全联锁、通信协议的超时检测。普通业务代码用 IWDG 就够了，WWDG 属于「对时序有硬性要求」的场合。

内部 FLASH 与芯片 ID：把参数存进芯片里第六篇 · 系统与可靠性

P48 – P49 · FLASH 闪存 / 读写内部 FLASH、读取芯片 ID　·　6 节　·　4 题

进阶

内部 Flash 是一块「掉电不丢、可以按页擦、按半字写」的存储器。它让单片机有了「记忆」：校准值、开机次数、设备编号，都可以写进去，下次上电还在。代价是操作有严格顺序，顺序错了就写不进去——而且不会报错。

  • 能按「解锁 → 擦除 → 写半字 → 上锁」四步完成一次写入
  • 能读出芯片的 96 位唯一 ID 和 Flash 容量，用来做设备标识
  • 知道为什么不能擦第 0 页、为什么只能写半字
一、Flash 的组织：64KB，64 页，每页 1KB

「页 0 不能擦」是硬规矩：中断向量表和启动代码就在里面，擦了芯片就再也启动不了——只能靠 SWD 重新烧程序救回来。存参数一律用最后的几页（比如页 62、页 63，地址 0x0800_F800 起）。

怎么算地址

地址 = 0x08000000 + 页号 × 1024。

页 62 → 0x08000000 + 62 × 1024 = 0x0800F800；页 63 → 0x0800FC00。

反推：页号 = (地址 - 0x08000000) / 1024。

二、四步写入法

Flash 有写保护，必须先「解锁」才能擦写。标准库把两次写入密钥的动作封装成了 FLASH_Unlock()：

#include "stm32f10x.h"

/* 擦除一页（1KB） */
void MyFLASH_ErasePage(uint32_t addr)
{
    FLASH_Unlock();                         // ① 解锁
    FLASH_ClearFlag(FLASH_FLAG_EOP | FLASH_FLAG_PGERR | FLASH_FLAG_WRPRTERR);
    FLASH_ErasePage(addr);                  // ② 擦除（整页变 0xFF）
    FLASH_Lock();                           // ③ 上锁
}

/* 写一个半字（16 位）；addr 必须是偶数 */
void MyFLASH_WriteHalfWord(uint32_t addr, uint16_t data)
{
    FLASH_Unlock();
    FLASH_ProgramHalfWord(addr, data);
    FLASH_Lock();
}

/* 读：直接当指针访问，不需要解锁 */
uint16_t MyFLASH_ReadHalfWord(uint32_t addr)
{
    return *(volatile uint16_t *)addr;
}

/* 读 32 位 / 字节同理 */
uint32_t MyFLASH_ReadWord(uint32_t addr)
{
    return *(volatile uint32_t *)addr;
}

读操作不需要解锁、不需要库函数——Flash 在地址空间里就是普通内存，指针直接读。这一点和第 12 课的 DMA 一样：地址即数据。

三、写一个结构体：先凑成半字再写

实际项目里要存的通常是一组参数，不是一个半字。做法是把它当字节数组，两个字节拼成一个半字写入：

typedef struct {
    uint16_t magic;        // 0x5AA5 表示「已初始化」
    uint16_t boot_count;   // 开机次数
    int16_t  offset;       // 校准偏移
    uint16_t crc;          // 简单校验
} Param_t;

#define PARAM_ADDR  0x0800F800     // 页 62
#define PARAM_MAGIC 0x5AA5

void Param_Save(Param_t *p)
{
    uint8_t *raw = (uint8_t *)p;
    uint16_t i, sum = 0;

    p->magic = PARAM_MAGIC;
    p->crc   = 0;
    for(i = 0; i < sizeof(Param_t); i++) sum += raw[i];   // 先把 crc 当 0 累加
    p->crc = sum;                                          // 再把结果写进 crc 字段

    MyFLASH_ErasePage(PARAM_ADDR);
    for(i = 0; i < sizeof(Param_t); i += 2){
        uint16_t hw = raw[i] | (raw[i + 1] << 8);          // 小端拼半字
        MyFLASH_WriteHalfWord(PARAM_ADDR + i, hw);
    }
}

uint8_t Param_Load(Param_t *p)
{
    uint8_t *raw = (uint8_t *)p;
    uint16_t i, sum = 0, crc;

    for(i = 0; i < sizeof(Param_t); i += 2){
        uint16_t hw = MyFLASH_ReadHalfWord(PARAM_ADDR + i);
        raw[i]     = hw & 0xFF;
        raw[i + 1] = hw >> 8;
    }
    if(p->magic != PARAM_MAGIC) return 0;                    // 从没写过

    crc = p->crc;
    for(i = 0; i < sizeof(Param_t); i++) sum += raw[i];
    return ((uint16_t)(sum - crc) == crc);                   // 去掉 crc 自身后应等于它
}

sizeof(Param_t) 是偶数（4 个 uint16_t 成员），所以按半字循环正好对齐。如果结构体里有 uint8_t 成员，总长度可能是奇数，最后一次写入要补一个 0xFF——半字对齐是 Flash 写入最硬的要求。

五、坑：写不进、读回 0xFF、程序跑不起来
现象原因修法
写进去读回还是旧值没擦除（0 位无法变 1）写前必须 FLASH_ErasePage

擦写期间 CPU 会停

Flash 擦除一页需要 20–40ms，这段时间内 CPU 从 Flash 取指令会被硬件挂起（总线等待）。表现是「按一下保存，程序像卡了一下」。

如果这时有串口数据在收，会丢字节；如果有看门狗（第 18 课），可能被咬。所以擦写要放在主循环里做，且中间不要指望中断能及时响应。

本课练习 · 4 题自编 · 按课程考点

  1. F103C8 的页大小是 1KB，要存 100 字节的参数，会浪费多少空间？为什么不能只擦 100 字节？

    擦除单位是整页 1KB，所以会浪费约 924 字节。
    因为 Flash 的擦除是「按页施加高压、整页置 1」的物理过程，硬件不支持按字节擦除。这也是为什么小数据量参数适合存在 BKP（20 字节）或外部 EEPROM 里，而不是内部 Flash。

  2. 想把参数存在 0x0800F800，这是第几页？如果误擦了 0x08000000 会怎样？

    (0x0800F800 − 0x08000000) / 1024 = 62，所以是第 62 页（倒数第二页）。
    0x08000000 是第 0 页，里面是中断向量表和启动代码。擦掉后芯片上电找不到复位向量，直接不启动；SWD 通常还能连上（SWD 不依赖 Flash 内容），可以重新烧程序救回来——但如果没有调试器，芯片就「砖」了。

  3. 写入一个 5 字节的结构体，按半字写会出什么问题？怎么处理？

    5 字节不是偶数，最后一次只凑得出 1 个字节，无法组成一个完整半字。若强行写 2 个字节，会多写一个字节到不该写的地址。
    处理办法：把结构体补齐到偶数长度（加一个 padding 字节），或把最后 1 字节与 0xFF 拼成半字写入，读回时忽略那个 0xFF。__attribute__((packed)) 能让结构体紧凑，但会破坏对齐，反而更容易出错——宁可浪费 1 字节。

  4. 为什么读 Flash 不需要 FLASH_Unlock()，写却需要？

    读只是总线访问，和读 SRAM 一样，没有任何副作用。写/擦会改变存储内容，为了防止程序跑飞时误改代码区，硬件加了「密钥序列」保护：连续写入 0x45670123 和 0xCDEF89AB（FLASH_Unlock 内部完成）才打开写权限。
    上锁之后 FPEC 寄存器只读，任何写操作都被忽略。这也是为什么忘了 Unlock 时「程序不报错、就是写不进去」——硬件直接丢弃了操作。
