2 第 2 章 · CT117E-M4 硬件解剖

2.1 这台板子不是一个「大号开发板」，是被设计过的考试工具

本章目标：认清板子上每个器件的型号、连接方式、控制逻辑。这一章的每一个数字，后面都会用到。
和网课的区别：网课教你「LED 接在 PC13 上，拉低就亮」。但没人告诉你 —— 为什么这块板的 LED 非要过一颗 74HC573 锁存器。不懂这个，你的灯和屏会互相打架。

2.3 核心问题：为什么 LED 要过一颗 74HC573

看引脚表你会发现一件事：PC8~PC15 既接 LED，又接 LCD。 也就是说这两组外设共用同一批引脚。

如果 LED 直接挂在 PC8~PC15 上，那么 LCD 刷新时数据在 PC 口上飞速变化，LED 就会跟着乱闪。反之点灯也会破坏 LCD 数据。

74HC573 就是来解决「抢引脚」的。它顺序逻辑很简单：
LE 引脚电平Q 输出端含义
高跟着 D 输入端实时变「透明」—— 像根导线
低保持住上一个值「锁存」—— 拍照定格

所以点灯的标准动作是：先摆数据 → LE 高 → LE 低。一高一下，就是一个「拍照脉冲」，PC 口是什么样，LED 就定格成什么样。之后 LCD 再怎么折腾 PC 口，LED 都不动。

这一步是必背的：没有第三行（LE 拉低），灯根本不亮 —— 因为它从没被「拍照」过。

2.4 按键为什么是「按下为低」

按键一端接 MCU 引脚，另一端接 GND。板上另有 10kΩ 上拉电阻把引脚拉到 3.3V。

状态引脚电平HAL_GPIO_ReadPin 返回
松开被上拉到 3.3VGPIO_PIN_SET
按下被 GND 拉到 0VGPIO_PIN_RESET
为什么必须有上拉：松开时引脚是「悬空」的，CMOS 输入脚阻抗极高（MΩ 级），悬空电压由干扰决定，读数会乱跳。上拉电阻给它一个确定的「默认答案」。
按下时电流 = 3.3V ÷ 10kΩ ≈ 0.33mA，几乎不耗电，但电压被强行拉到 0V。

2.5 同一根 I2C 总线挂两个器件

AT24C02 和 MCP4017 都挂在 PB6/PB7 上，靠 器件地址区分：

器件功能怎么区分
AT24C02存参数（256 字节）固定器件地址 0xA0
MCP4017可编程电阻（0~100kΩ）自己的地址（查数据手册）
为什么用「软件模拟 I2C」而不是硬件 I2C 外设：两个器件共用总线，软件模拟时序完全可控；而且官方 BSP 就是这么写的，考场上直接调官方函数，别自己造。

2.6 板子上必须先检查的三处

位置要求不对会怎样
USB 线插 CN2（左上角，靠近 F103 那颗芯片）必须插右下「USB从设备」口 → 板子能亮但电脑永远认不到调试器

2.7 本章自测

📖 参考答案（点击展开）
  1. 问：只写 HAL_GPIO_WritePin(GPIOC, GPIO_PIN_8, RESET)，灯会亮吗？
    答：不会。PC8 的电平只是「摆在了 D 端」，没给 LE 脉冲，锁存器输出端还是旧值。
  2. 问：按住 LED 锁存好了以后，去刷新 LCD，灯会变吗？
    答：不会。LE 已经拉低，锁存器处于「保持」状态，PC 口怎么变都不影响 Q 端。
  3. 问：按键为什么要上拉，而不是下拉？
    答：由接线决定。按键另一端接 GND，所以空闲时必须靠上拉保持高电平，按下才被拉低。
  4. 问：板上两个 I2C 器件会打架吗？
    答：不会。I2C 是总线协议，每个器件有独立地址，主机寻址到谁，谁才应答。

4 第 4 章 · 时钟树：整块板子的心跳

4.1 为什么时钟是「第一章之外最重要的东西」

本章目标：搞清 80MHz 是怎么来的，以及它为什么决定了定时器、串口、ADC 的每一个时间参数。
和网课的区别：网课会说「配好时钟就行」。但它不解释：为什么你的定时器差了 2 倍、串口乱码 —— 根因往往不是代码写错，是时钟配错。

4.2 这块板子是 80MHz，而且用的是内部振荡器

看官方例程的 SystemClock_Config()，它是这么配的：

HSI 16MHz  ÷ PLLM(2) = 8MHz
           × PLLN(20) = 160MHz  (VCO)
           ÷ PLLR(2)  = 80MHz   → SYSCLK
FLASH_LATENCY_3
APB1 / APB2 都不分频 → 定时器时钟 = 80MHz
两个容易被忽略的事实：
① 用的是 HSI（内部 16MHz），不是外部晶振。板上确实焊了一颗 24MHz 晶振 X1（接 PF0/PF1），但官方例程一次都没用它 —— 所以你也不要去配 HSE，配了就和所有例程、教材对不上。
② APB 不分频，所以定时器时钟就是 80MHz。如果分频了，定时器时钟会是 APB×2，很多人在这里算错。

4.3 时钟错了，会连锁错在哪

外设依赖时钟的方式时钟错的症状
定时器周期 = (PSC+1)×(ARR+1) ÷ 定时器时钟延时／频率整体偏大偏小固定倍数
串口波特率由 PCLK 分频得到乱码（收发双方分频比不一致）
ADC采样时间以 ADC 时钟周期计转换时间不符、读数不稳
SysTick1ms 中断基于 HCLKHAL_Delay 不准
排查技巧：如果现象是「一切都按固定比例错」，几乎一定是时钟问题，而不是逻辑问题。

4.4 算一遍：1ms 定时中断怎么配

目标：每 1ms 进一次中断。定时器时钟 80MHz。

步骤计算
① 先决定计数频率想让 1 个计数 = 1µs，则 80MHz ÷ 80 = 1MHz → PSC = 80 - 1 = 79
② 再决定数多少个1µs × 1000 = 1ms → ARR = 1000 - 1 = 999
③ 验证(79+1)×(999+1) ÷ 80MHz = 80000 ÷ 80M = 1ms ✅
/* 通用公式 */
中断周期 = (PSC + 1) × (ARR + 1) / 定时器时钟

/* 反推：给定周期 T(秒)，先固定 PSC，再算 ARR */
ARR + 1 = T × 定时器时钟 / (PSC + 1)

4.5 为什么 PSC 和 ARR 都要减 1

5.1 一个引脚里面到底有什么

本章目标：弄清 GPIO 的位结构，从而明白「推挽 / 开漏 / 上拉 / 下拉」到底在选什么，而不是死记八个模式。
和网课的区别：网课给你「八种模式」的表格让你背。本章告诉你这八种模式其实是两个开关的组合，理解了就不用背。

5.2 GPIO 位结构的三个关键部件

部件作用对应用途
输出驱动器（上管 + 下管）决定输出是「推」还是「拉」推挽 / 开漏
上拉 / 下拉电阻给空闲引脚一个默认电平输入时防悬空

5.3 推挽 vs 开漏：一个开关的差别

模式结构能输出高吗典型用途
推挽（PP）上管 + 下管都有✅ 能主动输出高、低点灯、驱动、普通输出
开漏（OD）只有下管，上管拿掉❌ 只能拉低，高电平靠外部上拉I2C 总线、多器件共享信号线
为什么 I2C 必须用开漏：I2C 上可能挂多个器件，任何一个都能把线拉低。如果用推挽，A 器件输出高、B 器件输出低，两个管子直接对烧 —— 这就是「短路」。开漏保证只有「拉低」这一个动作，谁拉低都安全。

5.4 点灯三行代码，逐行拆

HAL_GPIO_WritePin(GPIOC, GPIO_PIN_8, GPIO_PIN_RESET);  /* ① */
HAL_GPIO_WritePin(GPIOD, GPIO_PIN_2, GPIO_PIN_SET);    /* ② */
HAL_GPIO_WritePin(GPIOD, GPIO_PIN_2, GPIO_PIN_RESET);  /* ③ */
行做了什么物理含义
①PC8 输出低把「亮」这个数据摆到 74HC573 的 D 端
②PD2（LE）拉高锁存器变「透明」，Q 端跟随 D 端
③PD2（LE）拉低锁存器「拍照」定格，Q 端保持
为什么灯是「低电平亮」：LED 阳极接 3.3V（或经限流电阻），阴极接 74HC573 的输出端。输出低 = 有压差 = 有电流 = 亮。这叫「灌电流驱动」，比「拉电流驱动」能力更强，是数字电路里的常见设计。

5.5 一次写多个灯：先全灭，再点亮

/* mask 的 bit0~bit7 对应 LED1~LED8 */
void LED_Write(uint8_t mask)
{
    uint16_t pins = 0;
    if (mask & 0x01) pins |= GPIO_PIN_8;
    if (mask & 0x02) pins |= GPIO_PIN_9;
    if (mask & 0x04) pins |= GPIO_PIN_10;
    if (mask & 0x08) pins |= GPIO_PIN_11;
    if (mask & 0x10) pins |= GPIO_PIN_12;
    if (mask & 0x20) pins |= GPIO_PIN_13;
    if (mask & 0x40) pins |= GPIO_PIN_14;
    if (mask & 0x80) pins |= GPIO_PIN_15;

    /* 先全部置高（灭），再把要亮的拉低 */
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_8 | GPIO_PIN_9 | GPIO_PIN_10 | GPIO_PIN_11 |
                                  GPIO_PIN_12 | GPIO_PIN_13 | GPIO_PIN_14 | GPIO_PIN_15,
                       GPIO_PIN_SET);
    HAL_GPIO_WritePin(GPIOC, pins, GPIO_PIN_RESET);

    /* 锁存脉冲 */
    HAL_GPIO_WritePin(GPIOD, GPIO_PIN_2, GPIO_PIN_SET);
    HAL_GPIO_WritePin(GPIOD, GPIO_PIN_2, GPIO_PIN_RESET);
}
为什么不能只写「要亮的」：HAL_GPIO_WritePin 只改你指定的位，其他位保持原状。如果上一帧亮了 LED3，这一帧只写 LED5，那 LED3 还亮着 —— 灯灭不掉。所以必须先整体置高。

6.1 按键不是「一个开关」这么简单

本章目标：理解机械抖动的物理本质，写出考场级的非阻塞按键扫描；彻底搞明白为什么不能用 HAL_Delay 消抖。
和网课的区别：网课给你一个「检测到按下就 delay 20ms 再读」的代码，说它能用。本章告诉你为什么这段代码在真题里会让你丢分。

6.2 抖动的物理本质：金属弹跳

轻触按键内部是金属簧片。按下瞬间，簧片并不是「啪」一下贴住，而是在接触点上来回弹跳几次才稳定，就像硬币掉桌上弹几下才停。

参数典型值
抖动持续时间5 ~ 20ms
抖动次数几次到几十次
常见消抖阈值20ms（覆盖绝大多数按键）
为什么这会造成灾难：主循环一秒钟能跑几十万次。如果不消抖，一次物理按下会被读成「按下-松开-按下-松开…」—— LED 翻了偶数次看起来没反应，翻了奇数次看起来闪了一下。人按一次，机器认为你按了 8 次。

6.3 为什么 HAL_Delay(20) 是错的

延时消抖的写法：

/* ❌ 反面教材 */
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
    HAL_Delay(20);                          /* 这里 CPU 完全被卡住 */
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
        /* 确认按下 */
    }
}
问题后果
20ms 内 CPU 什么都不干LCD 停止刷新 → 肉眼可见的卡顿
其他按键在这 20ms 内不响应快速连按会丢键
定时器计数/串口接收被拖延时序整体漂移
本质区别：HAL_Delay 是「查着秒表干等着」；正确做法是「记下时间戳，先走，下次回来再比」。同样是等 20ms，一个把 CPU 锁死，一个不锁。

6.4 四状态机：考场级标准写法

把按键看成一个有四个「房间」的状态机，每次扫描看一眼当前电平，决定留在原地还是换房间：

状态含义下一步条件
KEY_IDLE空闲，手没按读到低 → 进「按下消抖」，记时间戳
KEY_PRESS_DEBOUNCE看到低电平，但可能是抖动20ms 后仍是低 → 确认按下，报告一次事件；中途变高 → 回空闲
KEY_PRESSED已确认按住读到高 → 进「松开消抖」
KEY_RELEASE_DEBOUNCE看到高电平，也怕抖动20ms 后仍是高 → 回空闲，可以接受下一次按键
typedef enum { KEY_IDLE = 0, KEY_PRESS_DEBOUNCE, KEY_PRESSED, KEY_RELEASE_DEBOUNCE } KeyState_t;
static KeyState_t s_state = KEY_IDLE;
static uint32_t   s_tick  = 0;

/* 返回 1 = 检测到"消抖后刚按下"的那一下 */
uint8_t Key_Scan(void)
{
    uint8_t  down = (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) ? 1 : 0;
    uint8_t  fired = 0;
    uint32_t now = HAL_GetTick();

    switch (s_state) {
    case KEY_IDLE:
        if (down) { s_state = KEY_PRESS_DEBOUNCE; s_tick = now; }
        break;
    case KEY_PRESS_DEBOUNCE:
        if (!down)                       s_state = KEY_IDLE;
        else if (now - s_tick >= 20)     { s_state = KEY_PRESSED; fired = 1; }
        break;
    case KEY_PRESSED:
        if (!down) { s_state = KEY_RELEASE_DEBOUNCE; s_tick = now; }
        break;
    case KEY_RELEASE_DEBOUNCE:
        if (down)                        s_state = KEY_PRESSED;
        else if (now - s_tick >= 20)     s_state = KEY_IDLE;
        break;
    default: s_state = KEY_IDLE; break;
    }
    return fired;
}
关键点：返回值是「事件」不是「状态」。它只在消抖后按下的那一瞬间返回 1，按住不放也只返回一次。这是做长按、双击、多按键的基础。

7.1 ADC 不是「直接读出电压」的

本章目标：搞懂逐次逼近型 ADC 的工作过程，从而明白「采样时间」为什么要那么长、读数为什么会抖、为什么要除以 4096。
和网课的区别：网课给你 HAL_ADC_Start() 和 HAL_ADC_GetValue() 两行代码。它不告诉你：为什么电位器转到底也只有 3.29V，为什么读数末位总在跳，为什么除 4096 不是 4095。

7.2 深挖：逐次逼近是做「二分查找」

ADC 内部有一个 DAC 和一个比较器。转换过程是这样的：

步骤动作举例（输入 2.0V，满量程 3.3V）
1DAC 试一半量程 1.65V2.0 > 1.65 → 最高位记 1
2试 3/4 量程 2.475V2.0 < 2.475 → 次位记 0
3试 5/8 量程 2.0625V2.0 < 2.0625 → 记 0
…继续二分，共 12 次得到 12 位结果
所以 12 位 ADC 需要 12 个比较周期。这就是为什么转换时间和分辨率成正比 —— 位数越多越慢。

7.3 为什么「采样时间」要设很长

ADC 前端有个采样保持电容 C，转换前要先把它充电到被测电压。充电需要时间，而充电速度取决于信号源内阻。

概念说明
采样时间开关接通、电容充电的那段时间
源阻抗信号源本身的电阻。电位器分压时内阻可能高达几十 kΩ
规律源阻抗越大 → 采样时间必须越长，否则电容充不满，读数偏小且不稳
这条直接解释了一个实战现象：为什么同一次采样里，前面通道读得准、切到另一个通道就读不准 —— 因为切换瞬间电容还带着上一个通道的电压，采样时间不够就没充到新值。

7.4 换算：为什么除以 4096

项值
位数12 位
刻度总数212 = 4096
可表示的码值0 ~ 4095（共 4096 个）
换算公式电压 = 码值 × 3.3V / 4096

严格来说满量程码值 4095 对应「略小于 3.3V」，所以用 4096 是一种把量程均分成 4096 份的做法，物理意义更顺，误差不到 1 LSB。

8 第 8 章 · I2C 与 EEPROM：开漏线与和 5ms 忙等

8.1 为什么 EEPROM 要用「开漏 + 上拉」

本章目标：理解 I2C 的物理层为什么必须是开漏，掌握 AT24C02 读写的完整时序，并知道为什么要等 5ms。
和网课的区别：网课给你两行 x24c02_write() / x24c02_read() 就结束了。它不说：连续写为什么会丢数据、为什么两个器件能挂在同一根线上、上拉电阻的作用到底是什么。

8.2 深挖：开漏「线与」是 I2C 的灵魂

I2C 只有两根线：SCL（时钟）、SDA（数据）。两根都是开漏输出 + 上拉电阻。

谁在驱动能做什么结果
任何一个器件拉低把线拉低线上是 0
所有器件都松手释放总线上拉电阻把线拉高 → 1
这叫「线与」：线的电平 = 所有器件输出值的逻辑与。只要有一个拉低，整条线就是低。
这带来两个好处：① 不会出现两个器件一个拉高一个拉低造成的短路；② 天然实现「多主机仲裁」—— 谁拉低谁赢。
如果上拉电阻丢了会怎样：线永远不会变高，I2C 完全通信不了，所有读写超时。而它又是「软件问题」看不出来的 —— 属于硬件坑里最阴的一类。

8.3 一次完整写操作：起始 → 地址 → 应答 → 数据 → 停止

阶段内容由谁发
① 起始 StartSCL 高时 SDA 由高变低主机
② 器件地址AT24C02 固定地址 0xA0（写）主机
③ 应答 ACK从机把 SDA 拉低表示「收到」从机
④ 字节地址要写哪个存储单元（0~255）主机
⑤ 应答ACK从机
⑥ 数据一个字节内容主机
⑦ 应答ACK从机
⑧ 停止 StopSCL 高时 SDA 由低变高主机
「应答」是关键：没有 ACK 说明芯片没收到（地址错、没上拉、器件坏）。调试 I2C 时先看有没有 ACK，能省一半时间。

8.4 深挖：为什么写完要等 5ms

EEPROM 不是 RAM。写入时，芯片内部要做真正的电荷注入（把电子打进浮栅），这个物理过程需要时间。

阶段总线状态能不能马上写下一条
数据传输结束（Stop 之后）空闲❌ 不能
内部擦写周期（约 5ms）芯片「忙」，不响应任何地址❌ 会丢
擦写完成恢复响应✅ 可以
/* 连续写多个字节，每次之间必须等 */
for (i = 0; i < len; i++) {
    x24c02_write(addr + i, data[i]);
    HAL_Delay(5);                 /* 等内部擦写完成 */
}
这是真题里最隐蔽的丢分点：单次读写测试完全正常，一旦「保存 3 个参数」就连环失败 —— 因为没等 5ms。

  1. 问：同一条 I2C 上挂两个器件，会互相干扰吗？
    答：不会。主机先发器件地址，只有地址匹配的器件才应答，其他器件保持沉默。
  2. 问：把上拉电阻从 4.7k 改成 100k 会怎样？
    答：上升沿变缓（RC 时间常数变大），高速时数据出错。上拉太小又增加功耗和灌电流。4.7k 是常见平衡值。

9 第 9 章 · 定时器：时基单元、影子寄存器与输入捕获

9.1 定时器是整块芯片最值得搞懂的模块

本章目标：搞清 PSC / CNT / ARR 三个寄存器和「影子寄存器」机制，理解输入捕获测频的完整过程与误差来源。
和网课的区别：网课给你公式 T = (PSC+1)(ARR+1)/f。它不讲：为什么改了 ARR 要等下一个周期才生效、为什么测高频时读数会跳、为什么捕获要用「从模式复位」。

9.2 三个寄存器，一条流水线

寄存器作用类比
PSC（预分频）把定时器时钟先降频秒表的「最小刻度」
CNT（计数器）实际在数的值秒表读数
ARR（自动重装）数到多少归零「一圈多少秒」
计数频率 = 定时器时钟 / (PSC + 1)
溢出周期 = (ARR + 1) / 计数频率
         = (PSC + 1) × (ARR + 1) / 定时器时钟

本板定时器时钟 = 80MHz（APB 不分频）。

9.3 深挖：影子寄存器 —— 为什么改 ARR 不会立刻生效

CNT 正在数的时候，如果 CPU 突然把 ARR 从 999 改成 1999，会怎样？如果立即生效，这个周期就会变成「一半按旧值、一半按新值」—— 出现一个宽度错误的周期。

机制说明
影子寄存器（预装载）你写的值先进「预装载寄存器」，等当前周期结束（更新事件）才搬到「影子寄存器」
效果每个周期都是完整的，不会出现被切断的畸形周期
开关ARR 有 ARPE 位，CCR 有 OCxPE 位
类比：换秒表的量程，要等它跑完这一圈再换，不能跑一半就换 —— 否则这一圈的数据是废的。

9.4 深挖：输入捕获测频，误差从哪来

原理很简单：测两个上升沿之间的计数值，乘以计数周期，就是信号周期，取倒数就是频率。

环节误差来源
计数分辨率计数频率 1MHz → 分辨率 1µs。测 1kHz（周期 1ms）误差 0.1%；测 100kHz（周期 10µs）误差 10%
捕获边沿抖动信号本身抖动、噪声导致边沿位置不定
计数器溢出周期超过 ARR 范围 → 读数错乱，必须处理溢出
所以低频用「测周期法」准，高频要改用「测频率法」（固定闸门时间内数脉冲个数）。这是仪器设计的经典权衡，不是 bug。

9.5 本板接法

项值
定时器 / 通道TIM2 / CH1，输入捕获
引脚PA15（跳线 J10 把 555 脉冲接过来）
信号源XL555，频率由电位器 R40 调节（约 700Hz ~ 14kHz）
PSC官方例程设 80 → 计数频率 1MHz

9.6 基本定时器中断：考试里最常用的写法

volatile uint32_t g_tick = 0;

/* 回调函数名是固定的，不能自己起 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3) {     /* 实例名必须和配置一致 */
        g_tick++;
    }
}

/* 启动（光初始化不会跑，必须 Start_IT） */
HAL_TIM_Base_Start_IT(&htim3);
两个高频错误：① 忘了 HAL_TIM_Base_Start_IT → 中断永远不进；② 回调里判断的实例名写错（写成别的定时器）→ 中断进了但你的变量不涨。

9.7 本章自测

📖 参考答案（点击展开）
  1. 问：80MHz，PSC=79，ARR=1999，中断周期多少？
    答：(80)×(2000)/80M = 2ms。
  2. 问：为什么中断里不要写 HAL_Delay？
    答：中断服务程序里死等会阻塞所有同级和低级中断，还可能和主循环的延时互相干扰（SysTick 计数被拖住）。
  3. 问：捕获值乘以 1µs 得到的是周期还是频率？
    答：周期。频率 = 1 / 周期。

10 第 10 章 · LCD：并口时序与消影

10.1 屏幕是考场上的「得分窗口」

本章目标：掌握 LCD 的五个 API，理解为什么动态刷新必须补空格，写出一个不闪、不残留的显示层。
和网课的区别：网课教你 LCD_DisplayStringLine()。它不讲：为什么数字从 100 变成 99 后，屏幕上是 990；为什么频繁 Clear 会让屏幕狂闪 —— 这两条直接决定你的观感分。

10.2 就五个函数，全部要会

LCD_Init();                                    /* 初始化，必须最先 */
LCD_Clear(Black);                              /* 清屏 + 填背景色 */
LCD_SetBackColor(Black);                       /* 文字底色 */
LCD_SetTextColor(White);                       /* 文字颜色 */
LCD_DisplayStringLine(Line2, (uint8_t *)"HELLO");  /* 第 2 行写字 */
常量取值
行号Line0 ~ Line9（共 10 行）
颜色Black White Red Green Blue Yellow Magenta Cyan …
每行字符最多 20 个

10.3 深挖：为什么动态数字必须补空格

屏幕是「逐字符覆盖」的，不是「整行重画」。你写 "VAL:100" 占了 7 个字符位；下一帧写 "VAL:99" 只占 6 位 —— 第 7 位没人去覆盖它，于是上一帧的 0 留了下来，屏幕显示 VAL:990。

错误做法后果
直接写短字符串尾部残留旧字符
每帧 LCD_Clear()全屏闪烁，观感极差，且耗时
补齐到 20 位空格✅ 既消影又不闪
char buf[40], line[40];
sprintf(buf, "VAL:%.2fV", v);
sprintf(line, "%-20s", buf);                    /* 左对齐，补空格到 20 位 */
LCD_DisplayStringLine(Line4, (uint8_t *)line);
%-20s 的含义：- 表示左对齐，20 表示最小宽度 20 —— 不足就自动补空格。这一行就是「消影」的全部秘密。

10.4 多页面框架（真题几乎必考）

static uint8_t page = 1;

void UI_Refresh(void)
{
    switch (page) {
    case 1:  /* 数据页 */
        LCD_DisplayStringLine(Line2, (uint8_t *)"  DATA PAGE      ");
        break;
    case 2:  /* 设置页 */
        LCD_DisplayStringLine(Line2, (uint8_t *)" SETTING PAGE    ");
        break;
    default: page = 1; break;
    }
}
切换页面时要重画整页：不同页面的行内容不一样，切页时不重画会留下上一页的残留。可以在切页时对整页写 20 个空格。

10.5 类型警告怎么消

官方 lcd.h 的函数原型是 u8 *（即 uint8_t *），直接传字符串常量会报：
expected 'u8 *' but argument is of type 'char *'
解决：强制转换 (uint8_t *)"..."。养成习惯，全场统一这么写。

10.6 本章自测

📖 参考答案（点击展开）
  1. 问：只写 "%-20s" 不写颜色设置，颜色会变吗？
    答：不会。颜色是「保持上一次设置」的状态，只有调用 Set 才变。
  2. 问：为什么 LCD_Init() 要放在 USER CODE 2（外设初始化之后）？
    答：LCD 依赖 GPIO 和延时，必须在 HAL 与 GPIO 初始化完成后才调用，否则白屏或花屏。
  3. 问：10 行 × 20 字符，够显示几个参数？
    答：足够 7~8 行有效内容（标题占 1~2 行）。规划好排版再动手，别写到第 8 行才发现放不下。

11.1 为什么「会点灯」和「能交卷」之间差一大截

本章目标：把六个外设组织成清晰的分层工程，让你在考场上改代码不互相牵连。
和网课的区别：网课每个例程都是一个 main.c 塞满。真题要同时跑 LCD + 按键 + ADC + EEPROM + 定时器，全塞在 main.c 里会让你在第 3 小时崩溃。

11.2 推荐目录结构

工程根/
├─ Core/Src/main.c         主循环、状态机、业务逻辑
├─ Core/Inc/main.h
├─ BSP/
│  ├─ led.c / led.h        LED_Write(mask)
│  ├─ key.c / key.h        Key_ScanOne()
│  ├─ lcd.c / lcd.h        官方提供，直接拷
│  └─ i2c.c / i2c.h        官方提供，直接拷
层次职责可以调用谁
BSP 层把寄存器操作封装成语义函数（点亮/读键）HAL 库
应用层（main.c）状态机、页面逻辑、参数计算BSP 层
HAL 层芯片驱动寄存器
分层的真正目的不是「好看」，是「改坏一处不牵连其他」。真题改需求时（比如把 B3 从「加」改成「减」），你只需要动应用层一行。

11.3 主循环的正确形态

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    /* USER CODE BEGIN 2 */
    LCD_Init();
    LCD_Clear(Black);
    LCD_SetBackColor(Black);
    LCD_SetTextColor(White);
    HAL_TIM_Base_Start_IT(&htim3);    /* 1ms 节拍 */
    /* USER CODE END 2 */

    while (1)
    {
        /* ① 采集 —— 只读，不做判断 */
        g_adc = getADC_Avg(8);
        g_vol = g_adc * 3.3f / 4096.0f;

        /* ② 输入事件 —— 只产生事件，不直接改业务 */
        for (i = 0; i < 4; i++) {
            if (Key_ScanOne(&keys[i], KEY_PORT[i], KEY_PIN[i]))
                g_key_event = i + 1;
        }

        /* ③ 业务处理 —— 集中在这里 */
        switch (g_key_event) {
        case 1: page = (page == 1) ? 2 : 1; g_key_event = 0; break;
        case 2: if (page == 2) threshold += 0.1f; g_key_event = 0; break;
        default: break;
        }

        /* ④ 输出 —— 统一刷新 */
        UI_Refresh();
        Alarm_Check();

        HAL_Delay(20);    /* 20ms 一帧，足够刷屏，又不会卡输入 */
    }
}
这个「采集 → 事件 → 业务 → 输出」四段式是真题最佳形态。它保证：按键不会在 LCD 刷新途中改变状态，ADC 值一帧内不会变两次，逻辑全部可控。

11.4 参数与单位的规范

量内部用显示用
电压float，单位 V%.2f
频率uint32_t，单位 Hz%d Hz
阈值float，单位 V%.1f V
时间uint32_t，单位 ms换算后显示
统一单位能避免一大类 bug：如果一处用 mV 一处用 V，就会出现「设了 2.5 却触发在 2500」这种离谱错误，而且很难看出来。

11.5 本章自测

📖 参考答案（点击展开）
  1. 问：为什么按键事件要「先存起来，再集中处理」？
    答：如果在扫描里直接改业务（比如直接改 page），而 LCD 正在刷新的中途，就会出现「这一帧上半屏是旧页、下半屏是新页」的撕裂。
  2. 问：HAL_Delay(20) 在主循环里合适吗？
    答：这里可以，因为它限定了整帧节拍，且 20ms 内没有必须响应的事。但不能用它做按键消抖 —— 那个必须在 Key_Scan 内部用时间戳。
  3. 问：BSP 层要不要用全局变量传数据？
    答：尽量用函数返回值和参数。全局变量只在「中断给主循环传标志」时用，且必须加 volatile。
