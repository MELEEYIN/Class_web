1 第 1 章 · HAL 到底是什么，为什么每个外设都要一个「句柄」

1.1 从「操作寄存器」到「调用函数」

本章目标：搞懂 HAL 的三层结构和「句柄」这个核心概念。不懂句柄，后面每个外设都会糊里糊涂。
和网课的区别：网课会让你「照抄 HAL_GPIO_Init 就行」。它不讲：为什么每个外设都有个 hadc1 / htim2 / huart1，这些名字是谁起的、里面装了什么。

HAL = Hardware Abstraction Layer（硬件抽象层）。它的作用就一句话：把「往寄存器某一位写值」包装成「调用一个有名字的函数」。

做法点一个 LED 要写什么特点
直接操作寄存器GPIOC->BSRR = 0x00002000;快、但看不懂、换芯片要全改
HAL 库HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);看得懂、跨型号通用、略慢一点

1.2 三层结构：你的代码 / HAL / 寄存器

层谁写的职责
应用层你业务逻辑、状态机、页面显示
HAL 库STHAL_xxx_Init() / HAL_xxx_Start() 等函数
寄存器芯片GPIOA->CRL、TIM2->PSC 这些
为什么要分层：你写业务时不关心寄存器；ST 改芯片时只改 HAL，你的代码不用动。这叫「解耦」。

1.3 核心概念：句柄（Handle）

HAL 给每个外设维护一个结构体，里面装着这个外设的全部状态：用哪个硬件、当前配置、缓冲区指针、状态标记……

UART_HandleTypeDef huart1;    /* 串口 1 的句柄 */
ADC_HandleTypeDef  hadc1;     /* ADC 1 的句柄 */
TIM_HandleTypeDef  htim2;     /* 定时器 2 的句柄 */
I2C_HandleTypeDef  hi2c1;     /* I2C 1 的句柄 */

这个名字谁起的？CubeMX 起的。你在 CubeMX 里启用 USART1，它就生成一个叫 huart1 的全局句柄。

句柄里有什么（以 UART 为例）作用
Instance指向哪个硬件：USART1
Init波特率、数据位、停止位等参数
pRxBuffPtr / RxXferSize中断/DMA 接收时，数据往哪放、收多少
State / gState当前是忙还是闲 —— HAL 靠它防重入
ErrorCode出错时记录错误码

1.4 为什么函数都要传「&huart1」

HAL_UART_Transmit(&huart1, buf, len, 100);   /* 注意 & */
HAL_ADC_Start(&hadc1);
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);
为什么是 &huart1 而不是 huart1：HAL 需要指针才能修改句柄内部的状态（比如把 State 改成 BUSY_TX）。传值的话 HAL 改的是副本，你的句柄永远不知道发送已开始。
忘了写 & → 编译直接报错（类型不匹配），这是新手第一个必踩的坑。

1.5 一个外设的完整生命周期（记住这四步，全篇通用）

步函数干什么谁生成
①HAL_xxx_Init(&hxxx)配置寄存器，让外设「准备好」CubeMX 生成
②HAL_xxx_Start() 系列真正启动（Init 只是配置，不启动！）你自己写
③收发 / 读写 / 等待业务操作你写
④HAL_xxx_Callback()中断/完成后自动调用的回调你重写
90% 的「外设没反应」死在第 ② 步：只调了 Init 忘了 Start。
典型：HAL_TIM_Base_Start_IT() / HAL_ADC_Start() / HAL_DAC_Start() / HAL_IWDG_Init()（这个是例外，Init 就生效）

1.6 本章自测

📖 参考答案（点击展开）
  1. 问：huart1 这个名字能改吗？
    答：能改，但要全局改（CubeMX 里也能设）。改名后所有引用它的地方都要跟着改，不推荐。
  2. 问：Init 和 Start 有什么区别？
    答：Init 是「填好配置、让外设待命」；Start 是「按下启动键」。比如定时器：Init 配好 PSC/ARR，Start_IT 才真正开始计数。
  3. 问：为什么 HAL_GPIO_Init 没有对应的 Start？
    答：GPIO 是「被动」外设，配好就直接生效，不需要启动。

2.1 你需要认识的文件其实只有 5 个

本章目标：认出 CubeMX 生成的一堆文件里，哪 5 个和你有关，其余全部不用碰。

2.3 五个文件的分工

文件要动吗作用
main.c✅ 天天动主循环、业务逻辑。只改 USER CODE 区
main.h🟡 少动引脚号宏（LED_Pin、LED_GPIO_Port）。要在 CubeMX 里给引脚起名字才会生成
stm32f1xx_it.c🟡 看情况中断服务函数。CubeMX 已经帮你调好 HAL_xxx_IRQHandler，一般不用动
stm32f1xx_hal_msp.c🟡 少动MSP = MCU Support Package。放「引脚复用、外设时钟使能」这类底层配置
stm32f1xx_hal_conf.h🔴 别动控制哪些 HAL 模块参与编译。改错会链接失败

2.4 为什么「外设初始化」会分成两个文件

这是 HAL 设计里最容易困惑的地方。以串口为例：

在哪配什么
MX_USART1_UART_Init()（main.c）逻辑参数：波特率、数据位、停止位、校验
HAL_UART_MspInit()（hal_msp.c）物理参数：开 USART1 时钟、把 PA9/PA10 配成复用推挽
为什么要拆：因为「用哪个引脚」是板级信息，「波特率多少」是应用信息。拆开后 ST 的 HAL 代码不用关心你的板子接线 —— 换块板只要改 MSP。

2.5 main.c 里 20 个 USER CODE 区（必须记住）

标记写什么常用度
USER CODE Includes额外 #include⭐⭐
USER CODE PD#define 宏⭐⭐
USER CODE PV全局变量⭐⭐
USER CODE 0自己写的函数⭐⭐⭐
USER CODE 2外设初始化之后的准备（Start、LCD_Init）⭐⭐⭐
USER CODE 3主循环体（最常改）⭐⭐⭐⭐
USER CODE 4回调函数实现（如 HAL_TIM_PeriodElapsedCallback）⭐⭐⭐
铁律：只改 BEGIN 和 END 之间。外面的内容 CubeMX 一重新生成就覆盖。
验证方法：改完保存 → 回 CubeMX 点 GENERATE CODE → 再看你的代码还在不在。

案例目标：不再把 CubeMX 生成的文件当黑盒。我们往 4 个文件里各改一处，用现象证明它们各自负责什么。

① 四处改动

文件改什么证明它负责
main.c · USER CODE PV加 volatile uint32_t g_tick_cnt = 0;业务变量放这里
stm32f1xx_it.c · SysTick_Handler加 g_tick_cnt++;（在 HAL_IncTick() 后）中断入口文件真的在编译

② 完整代码

/* ---- main.c · USER CODE BEGIN PV ---- */
volatile uint32_t g_tick_cnt = 0;     /* 中断里加，主循环里读 → volatile */

/* ---- main.c · USER CODE BEGIN Includes ---- */
#include <stdio.h>
#include <string.h>

/* ---- main.c · USER CODE BEGIN 2 ---- */
/* 需要先按第 7 章配好 USART1；这里只演示结构 */
char msg[48];

/* ---- main.c · USER CODE BEGIN 3 ---- */
static uint32_t last = 0;
if (HAL_GetTick() - last >= 1000)          /* 每 1 秒打印一次 */
{
    last = HAL_GetTick();
    sprintf(msg, "tick=%lu, systick_cnt=%lu\r\n",
            (unsigned long)HAL_GetTick(), (unsigned long)g_tick_cnt);
    HAL_UART_Transmit(&huart1, (uint8_t *)msg, strlen(msg), 100);
}

/* ---- stm32f1xx_it.c · SysTick_Handler 里加一行 ---- */
void SysTick_Handler(void)
{
  HAL_IncTick();
  g_tick_cnt++;                 /* ← 我们加的，证明 it.c 参与编译 */
}

现象结论

3.1 学会这一章，后面所有外设都是同一套

本章目标：掌握 HAL 的「返回值判错」「状态机防重入」「阻塞/中断/DMA 三模式」三件事。这是全篇方法论。
和网课的区别：网课写 HAL_UART_Transmit(...); 就完事，不判断返回值。本章告诉你 为什么不判返回值是坏习惯，以及 三种模式的本质区别。

3.2 返回值：HAL_StatusTypeDef

typedef enum
{
  HAL_OK      = 0x00U,   /* 成功 */
  HAL_ERROR   = 0x01U,   /* 错误（参数错、外设故障）*/
  HAL_BUSY    = 0x02U,   /* 忙：上一次操作还没完成 */
  HAL_TIMEOUT = 0x03U    /* 超时：等了 Timeout 还没结果 */
} HAL_StatusTypeDef;
返回值含义常见原因
HAL_OK成功—
HAL_ERROR失败参数非法、外设没初始化、硬件没响应
HAL_BUSY上一个操作还没完连续调用太快；中断/DMA 还没结束
HAL_TIMEOUT等超时了从设备没应答（I2C 没接、上拉丢失）
新手该养成的习惯：
if (HAL_UART_Transmit(&huart1, buf, len, 100) != HAL_OK)
{
    /* 这里至少给个 LED 闪烁或变量 +1，方便调试 */
    g_err_count++;
}
在学习阶段这样写，比事后猜「为什么没输出」快 10 倍。

3.3 状态机：为什么会有 HAL_BUSY

每个句柄里都有一个 State 字段。HAL 用它保证同一个外设不会同时干两件事。

/* 串口发送时 State 的变化 */
HAL_UART_Transmit()  → State = HAL_UART_STATE_BUSY_TX
     ...发完...      → State = HAL_UART_STATE_READY
典型 BUSY 场景表现
连续两次 HAL_UART_Transmit_IT第二次返回 HAL_BUSY，数据没发出去
DMA 传输中又调一次启动HAL_BUSY
I2C 还在等 ACK 时发下一条HAL_BUSY
怎么避免：① 中断/DMA 模式要等回调里再发起下一次；② 阻塞模式不要在多处同时调用同一个外设。

3.4 三种工作模式：这是 HAL 的核心分野

模式函数后缀CPU 占用何时返回适合
阻塞（Polling）无后缀🔴 全程占着传输完成或超时简单场景、调试
中断（IT）_IT🟡 中断里占用立刻返回不定时收数据
DMA_DMA🟢 几乎不占立刻返回大批量、高速
/* 同一个功能，三种写法 */
HAL_UART_Transmit(&huart1, buf, len, 100);       /* 阻塞：发完才走 */
HAL_UART_Transmit_IT(&huart1, buf, len);         /* 中断：立刻返回 */
HAL_UART_Transmit_DMA(&huart1, buf, len);        /* DMA：立刻返回，CPU 不参与 */

3.5 中断模式的关键：回调函数

用 _IT 后缀后，HAL 什么时候算「完成」？它会调用一个回调函数：

/* 你只需要重写这个函数（放 USER CODE 4 区） */
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1)
    {
        g_tx_done = 1;      /* 发送完成标志 */
    }
}
行为谁负责
中断向量入口 USART1_IRQHandlerCubeMX 生成，调 HAL_UART_IRQHandler
HAL 内部判断是发送完成还是接收完成HAL 库
调用对应的 CallbackHAL 库
Callback 里干什么你写
重要：HAL 库里的回调函数是弱定义（__weak）空函数。你不重写它，就等于什么都不做 —— 这就是「用了 _IT 但没有任何反应」的原因。

① 三种实现

方式核心代码闪烁是否受影响
轮询HAL_GPIO_ReadPin 在主循环里不断读不受影响（读很快）

/* USER CODE BEGIN PV */
static uint8_t  s_led_on    = 0;
static uint8_t  s_last_key  = 1;      /* 上电时按键未按下 = 高 */
static uint32_t s_blink_t   = 0;
/* USER CODE END PV */

/* USER CODE BEGIN 3 */
/* ① 按键边沿检测（比"按住就翻转"更可靠）*/
uint8_t now_key = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0);
if (s_last_key == 1 && now_key == 0)    /* 1→0 下降沿 */
{
    s_led_on = !s_led_on;
}
s_last_key = now_key;

/* ② 非阻塞闪烁：LED 灭时每 500ms 闪一下表示"我活着" */
if (!s_led_on)
{
    if (HAL_GetTick() - s_blink_t >= 500)
    {
        s_blink_t = HAL_GetTick();
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    }
}
else
{
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);   /* 常亮 */
}
/* USER CODE END 3 */

③ 把闪烁改成阻塞版做对比

/* ❌ 反例：这样写，按键响应会被拖慢 500ms */
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
HAL_Delay(500);          /* 这 500ms 内按按键，完全没反应 */

/* ✅ 正确：用 HAL_GetTick 差值，不阻塞 */
if (HAL_GetTick() - s_blink_t >= 500) { s_blink_t = HAL_GetTick(); HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13); }

4.1 GPIO 常用函数就 5 个

本章目标：掌握 GPIO 的 5 个函数 + 4 个配置字段，能写出点灯、按键、蜂鸣器这类基础代码。
和网课的区别：网课让你点灯就完了。它不讲 Pull 在 F1 上和 F4/G4 的实现差异，也不讲「为什么写多个引脚要用位或」。
函数作用返回
HAL_GPIO_Init(GPIOx, &init)初始化引脚void
HAL_GPIO_WritePin(GPIOx, pin, state)输出高/低void
HAL_GPIO_ReadPin(GPIOx, pin)读引脚电平GPIO_PinState
HAL_GPIO_TogglePin(GPIOx, pin)翻转电平void

4.2 初始化：4 个字段（CubeMX 已生成，你只需看懂）

GPIO_InitTypeDef GPIO_InitStruct = {0};

GPIO_InitStruct.Pin   = GPIO_PIN_13;              /* 哪个/哪些脚 */
GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;      /* 模式 */
GPIO_InitStruct.Pull  = GPIO_NOPULL;              /* 上下拉 */
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;      /* 速度 */
HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);

/* 别忘了先开时钟！*/
__HAL_RCC_GPIOC_CLK_ENABLE();
最常见的坑：忘了开 GPIO 时钟。F1 的 GPIO 挂在 APB2 上，不开时钟，后面所有配置都像「写进空气」。
CubeMX 生成的 MX_GPIO_Init() 第一行就是 __HAL_RCC_GPIOC_CLK_ENABLE()，别删。
📌 重要：上面这段代码 CubeMX 已经替你写好了，不需要自己敲。

它就躺在 main.c 的 MX_GPIO_Init() 里。这里列出来是为了让你：
① 读懂那几十行生成代码到底在配什么（否则只能当黑盒）；
② 出问题时能判断「是 CubeMX 配错了，还是我代码写错了」；
③ 明白 GPIO_MODE_OUTPUT_PP、GPIO_NOPULL 这些宏到底在选什么。

那什么时候才需要自己调用 HAL_GPIO_Init()？只有这三种情况：
· 运行中动态改引脚功能（比如同一个脚先做输出点亮，之后切成输入读传感器）；
· 想要 CubeMX 界面上没有的组合（如运行时切换上拉/下拉）；
· 在中断/回调里临时切换引脚模式（软件模拟 I2C 时 SDA 要反复切输入/输出）。

普通点灯、按键、串口、PWM —— 一律交给 CubeMX，不要手写初始化。

4.4 位掩码：一次操作多个引脚

/* GPIO_PIN_x 每一位独立：PIN_0=0x0001, PIN_1=0x0002, PIN_8=0x0100 ... */
GPIO_InitStruct.Pin = GPIO_PIN_0 | GPIO_PIN_1 | GPIO_PIN_2;   /* 三个脚一起配 */
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0 | GPIO_PIN_1, GPIO_PIN_SET);/* 两个脚一起拉高 */
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5 | GPIO_PIN_6);            /* 两个脚一起翻 */
为什么能这样：HAL_GPIO_WritePin 内部用 BSRR/BRR 寄存器，一次写多位。比「逐个写」快，而且是原子的（不会被中断打断成两半）。

4.5 输入：上拉/下拉怎么选

外部电路Pull 选理由
按键另一端接 GNDGPIO_PULLUP松开时靠上拉保持高，按下被拉低
按键另一端接 3.3VGPIO_PULLDOWN松开时靠下拉保持低，按下被拉高
外部已有上拉电阻GPIO_NOPULL不要重复
模拟输入（ADC）（Pull 无效）Mode 一定是 ANALOG
F1 的实现差异：F1 没有独立的 PUPDR 寄存器，输入模式下的上拉/下拉是靠 ODR 位的值决定的。HAL 已经帮你处理了，代码写法和其他系列一样，但读 gpio.c 源码时会发现它多做了一步 —— 不是 bug。

5 第 5 章 · 中断与 EXTI：HAL 在这块最反直觉

5.1 为什么中断比「主循环轮询」强

本章目标：搞清 HAL 的中断调用链 —— 为什么你写 HAL_GPIO_EXTI_Callback 就能收到中断，以及 NVIC 优先级怎么配。
和网课的区别：网课会说「写这个函数就行」。它不讲 中断向量表 → HAL_GPIO_EXTI_IRQHandler → Callback 这条链是谁串起来的，所以出问题时根本无从下手。
对比轮询（主循环读）中断
响应延迟取决于循环周期微秒级
CPU 占用一直占着查空闲时不占
会丢事件吗脉冲太短会漏不会（有挂起位）

5.2 中断调用链（这是本章的核心）

硬件中断触发
   ↓
stm32f1xx_it.c:  EXTI0_IRQHandler()
   ↓                    （CubeMX 生成，只有一行）
   HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)
   ↓                    （HAL 库：清标志位、判断是哪个脚）
   HAL_GPIO_EXTI_Callback(GPIO_PIN_0)
   ↓                    （⭐ 这个你重写，放 USER CODE 4）
   你的代码
所以你要做的只有两件事：① CubeMX 里把引脚配成 EXTI 模式；② 在 main.c 里重写 HAL_GPIO_EXTI_Callback。中间两步 HAL 和 CubeMX 自动接好了。

5.3 外部中断的写法

/* USER CODE BEGIN 4 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)          /* 判断是哪个引脚触发 */
    {
        /* ⚠ 这里在中断里，尽量短：置标志位，回主循环处理 */
        g_key_pressed = 1;
    }
}
/* USER CODE END 4 */
中断里绝对不要做这些：
① HAL_Delay（死等会卡住所有同级/低级中断）
② 大量计算、浮点运算
③ printf（串口发送本身就慢，还可能导致阻塞）
正确做法：中断里只置标志位，主循环里处理。

5.4 NVIC 优先级：抢占优先级 vs 子优先级

概念作用
抢占优先级（Preempt）数值小的能打断数值大的 —— 决定嵌套
子优先级（Sub）同时挂起时的排队顺序，不能嵌套
优先级分组决定这 4 个优先级位怎么分给抢占/子。HAL 默认 NVIC_PRIORITYGROUP_4（全给抢占）
HAL_NVIC_SetPriority(EXTI0_IRQn, 2, 0);   /* 抢占 2，子 0 */
HAL_NVIC_EnableIRQ(EXTI0_IRQn);           /* 打开该中断通道 */
数值越小优先级越高（0 最高）。新手常见错误：以为 0 是最低。

5.5 中断里为什么要 volatile

volatile uint8_t g_key_pressed = 0;   /* ⚠ 必须 volatile */
不加会发生什么：编译器优化时认为「主循环里没改过这个变量」，把它缓存进寄存器，导致中断改了、主循环看不到。而且代码看着完全正确，极难查。
规则：中断和主循环都会访问的变量，一律加 volatile。

5.6 中断函数名不能自己起

外设中断入口函数名（必须在 it.c 里，CubeMX 生成）
EXTI0EXTI0_IRQHandler
TIM2TIM2_IRQHandler
USART1USART1_IRQHandler
ADC1_2ADC1_2_IRQHandler
这些名字来自启动文件 startup_stm32f103xb.s 的向量表，写错一个字就进不去中断，而且编译不报错（相当于新定义了一个普通函数）。这是嵌入式最经典的「幽灵 bug」。

📖 参考答案（点击展开）
  1. 问：HAL_GPIO_EXTI_Callback 是谁调用的？

6.1 时钟是一切的时间基准

本章目标：搞懂 F103 的时钟树怎么到 72MHz，以及 HAL_Delay / HAL_GetTick 的底层依赖。

6.2 F103C8T6 的典型时钟链

外部晶振 8MHz (HSE)
   ↓ ÷1
  8MHz
   ↓ ×9 (PLL)
 72MHz  = SYSCLK（系统时钟）
   ├─ AHB  ÷1 → HCLK  = 72MHz   （内核、内存、DMA）
   └─ APB1 ÷2 → PCLK1 = 36MHz   （定时器 ×2 = 72MHz）
      APB2 ÷1 → PCLK2 = 72MHz   （GPIO、USART1、ADC）
总线挂什么F103C8 典型频率
AHB (HCLK)内核、SRAM、DMA72 MHz
APB1 (PCLK1)TIM2~4、USART2/3、I2C、SPI236 MHz（定时器实际 72MHz）
APB2 (PCLK2)GPIO、USART1、ADC1/2、SPI172 MHz
重点：APB1 = 36MHz，但挂在上面的定时器时钟是 ×2 = 72MHz。算 PSC/ARR 时用 72MHz，不是 36MHz —— 这是最常算错的地方。

6.3 RCC 相关的 HAL 函数

函数作用要不要自己写

6.4 SysTick 与延时

函数作用实现
HAL_Init()初始化 HAL + 配好 SysTick 为 1ms 中断CubeMX 生成的第一句
HAL_Delay(ms)阻塞延时 N 毫秒查 SysTick 计数死等
HAL_GetTick()返回开机以来的毫秒数读一个全局计数
/* 非阻塞延时：记时间戳，先干别的 */
uint32_t t_last = 0;

while (1)
{
    if (HAL_GetTick() - t_last >= 500)     /* 每 500ms 干一次 */
    {
        t_last = HAL_GetTick();
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    }
    /* 这 500ms 里可以干别的事，不像 HAL_Delay 卡死 */
}
HAL_Delay 的三个坑：
① 中断里不能用（会卡住其他中断）
② 时钟配置错时它会跟着错（SysTick 按 SysClock 算）
③ 只能延时不能提前退出，需要灵活性就用 HAL_GetTick 自己比

📖 参考答案（点击展开）
  1. 问：72MHz 下要 1ms 定时中断，PSC 和 ARR 怎么配？
    答：先分频到 1MHz：PSC = 72-1 = 71；再数 1000 个：ARR = 1000-1 = 999。
  2. 问：APB1 是 36MHz，那 TIM2 的时钟是多少？

8 第 8 章 · TIM 定时器：时基 / PWM / 输入捕获三件套

8.1 定时器的三种典型用法

本章目标：一次搞清定时器的三大用途 —— 定时中断、输出 PWM、输入捕获，以及它们的函数差异。
和网课的区别：网课分开讲「定时器中断」「PWM」「输入捕获」三节，你看完还是不知道为什么用 HAL_TIM_Base_Start_IT 和 HAL_TIM_PWM_Start。本章一次讲清楚「启动函数为什么不同」。

8.2 三个寄存器决定一切

寄存器含义类比
PSC 预分频把定时器时钟降频秒表最小刻度
CNT 计数器当前计数值秒表读数
ARR 自动重装数到多少归零一圈多少秒
计数频率 = 定时器时钟 / (PSC + 1)
溢出周期 = (PSC + 1) × (ARR + 1) / 定时器时钟
F103 的定时器时钟：TIM2~TIM4 挂在 APB1（36MHz），但定时器时钟是 72MHz（APB1 分频后 ×2）。算的时候用 72MHz。

8.3 用法一：定时中断（最常用）

函数作用
HAL_TIM_Base_Init(&htim)配置 PSC/ARR（CubeMX 生成）
HAL_TIM_Base_Start_IT(&htim)启动 + 开中断（必须调！）
HAL_TIM_Base_Stop_IT(&htim)停止
HAL_TIM_PeriodElapsedCallback(&htim)你重写：溢出回调
/* USER CODE BEGIN 0 */
volatile uint32_t g_ms = 0;
/* USER CODE END 0 */

/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)     /* ⚠ 实例名必须和配置一致 */
    {
        g_ms++;
    }
}
/* USER CODE END 4 */

/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim2);    /* ⚠ 忘了这句 = 中断永远不进 */
/* USER CODE END 2 */
两个高频错误：① 忘了 Start_IT；② 回调里判断的 Instance 写错（写成别的定时器），中断进了但变量不涨。

8.4 用法二：输出 PWM

函数作用
HAL_TIM_PWM_Init(&htim)配置（CubeMX 生成）
HAL_TIM_PWM_ConfigChannel(&htim, &sConfig, TIM_CHANNEL_x)配通道
HAL_TIM_PWM_Start(&htim, TIM_CHANNEL_x)启动 PWM 输出
__HAL_TIM_SET_COMPARE(&htim, ch, value)改占空比（运行中也能改）
__HAL_TIM_SET_AUTORELOAD(&htim, value)改周期（ARR）
/* 启动 PWM（在 USER CODE 2） */
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);

/* 运行中改占空比（在 USER CODE 3 主循环） */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 500);   /* CCR = 500 */
占空比公式：
占空比 = CCR / (ARR + 1)
比如 ARR=999，CCR=500 → 占空比 ≈ 50%
PWM 没输出的三个原因：① 忘了 HAL_TIM_PWM_Start；② 引脚没配成 AF_PP 复用；③ 该定时器通道的引脚被别的功能占了。

8.5 用法三：输入捕获（测频率 / 测脉宽）

函数作用
HAL_TIM_IC_Init(&htim)配置（CubeMX 生成）
HAL_TIM_IC_ConfigChannel(&htim, &sConfig, ch)配触发边沿
HAL_TIM_IC_Start_IT(&htim, ch)启动捕获
HAL_TIM_ReadCapturedValue(&htim, ch)读捕获到的计数值
HAL_TIM_IC_CaptureCallback(&htim)你重写：捕获到边沿时回调
volatile uint32_t t_start = 0, t_end = 0;
volatile uint8_t  done = 0;

void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3 && htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1)
    {
        if (!done) { t_start = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1); }
        else       { t_end   = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1); }
        done = !done;
    }
}

/* 周期 = (t_end - t_start) × 计数周期；频率 = 1 / 周期 */

8.6 为什么启动函数各不相同

用途启动函数为什么
定时中断HAL_TIM_Base_Start_IT只要「计数溢出」这个事件
PWMHAL_TIM_PWM_Start要「输出比较」通道工作
输入捕获HAL_TIM_IC_Start_IT要「捕获通道」工作 + 中断
本质：同一个定时器内部有很多「子功能」，你启用的子功能不同，启动函数就不同。不是记不住，是没理解这个结构。

📖 参考答案（点击展开）

    答：PSC=71（→1MHz）、ARR=10000-1=9999。
  2. 问：PWM 改占空比要不要停掉重启？

9.1 ADC 的三种读取方式

本章目标：掌握 ADC 三种读取方式，理解「为什么要校准」「多通道为什么会串」。
和网课的区别：网课给 HAL_ADC_Start + GetValue 两行。它不讲 PollForConversion 是干什么的、为什么多通道读数会乱。
函数模式典型用法
HAL_ADC_Start(&hadc)启动一次转换所有模式都要
HAL_ADC_PollForConversion(&hadc, timeout)阻塞等转换完成轮询模式必用
HAL_ADC_GetValue(&hadc)取结果0 ~ 4095
HAL_ADC_Start_IT(&hadc)中断模式启动转换完成时回调
HAL_ADC_Start_DMA(&hadc, buf, n)DMA 模式多通道连续采样
HAL_ADC_ConvCpltCallback(&hadc)回调（你重写）IT/DMA 完成时
HAL_ADCEx_Calibration_Start(&hadc)校准Init 之后、Start 之前调一次

9.2 轮询模式：最基础的读法

uint32_t adc;
float vol;

HAL_ADC_Start(&hadc1);                                  /* ① 启动 */
if (HAL_ADC_PollForConversion(&hadc1, 10) == HAL_OK)    /* ② 等转换完 */
{
    adc = HAL_ADC_GetValue(&hadc1);                     /* ③ 取值 */
    vol = adc * 3.3f / 4096.0f;                         /* ④ 换算电压 */
}
步为什么必须有
① Start不启动就一直读到上次的旧值
② PollForConversion转换需要时间（微秒级），不等直接读会读到未完成的值
③ GetValue取 12 位结果
最常见的错：只写了 Start 就 GetValue，跳过了 PollForConversion —— 读数会是小一个转换周期的旧值，而且看起来「能读、就是不准」，极难发现。

9.3 校准：为什么必须做

HAL_ADCEx_Calibration_Start(&hadc1);   /* F1 只有一个参数 */
校准做什么：ADC 内部有电容和比较器，存在制造偏差。校准让芯片自己测量这个偏差并补偿，能显著改善零点误差。
位置：MX_ADC1_Init() 之后、第一次 Start 之前，调一次就够。
版本差异：F1 是 HAL_ADCEx_Calibration_Start(&hadc) 一个参数；G4/F4 是 (&hadc, ADC_SINGLE_ENDED) 两个参数。跨系列迁移时必改。

9.4 中断模式

9.5 多通道：为什么会串

问题原因
所有通道读出来一样通道号写死（sConfig.Channel = ADC_CHANNEL_1 从不改）
切换通道后第一个值不准采样保持电容还残留上一个通道的电压
通道顺序乱没配 Rank（规则组转换顺序）
/* 单次切换通道的正确写法 */
ADC_ChannelConfTypeDef sConfig = {0};
sConfig.Channel = ADC_CHANNEL_4;          /* 每次改这里 */
sConfig.Rank = ADC_REGULAR_RANK_1;
sConfig.SamplingTime = ADC_SAMPLETIME_55CYCLES_5;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);

HAL_ADC_Start(&hadc1);
HAL_ADC_PollForConversion(&hadc1, 10);
value = HAL_ADC_GetValue(&hadc1);
多通道批量采样：配成 ScanConvMode = ENABLE + 多个 Rank，然后 用 DMA 一次性收完（见第 12 章）。这是最规范的做法。

9.6 换算与滤波

/* 12 位 ADC：0~4095 对应 0~3.3V */

/* 8 次平均滤波 */
uint32_t sum = 0;
for (uint8_t i = 0; i < 8; i++) sum += get_adc();
uint32_t avg = sum / 8;
平均滤波只能压随机噪声，压不掉系统偏差（比如采样时间不足导致的整体偏小）。先解决采样时间，再谈滤波。

10.1 先说结论：初学用软件模拟更稳

本章目标：掌握 I2C 的常用函数（硬件）和软件模拟的写法，知道什么场景用哪个。
和网课的区别：网课直接教硬件 I2C。它不讲 F103 的硬件 I2C 有已知问题，也不讲为什么很多项目宁愿用软件模拟。

10.3 读 EEPROM（AT24C02）标准写法

#define EE_ADDR   (0xA0)              /* AT24C02 的 8 位地址 */

uint8_t buf[1];

/* 写一个字节到地址 0x10 */
buf[0] = 0x5A;
HAL_I2C_Mem_Write(&hi2c1, EE_ADDR, 0x10, I2C_MEMADD_SIZE_8BIT, buf, 1, 100);
HAL_Delay(5);                          /* ⚠ EEPROM 内部擦写约 5ms */

/* 读回来 */
HAL_I2C_Mem_Read(&hi2c1, EE_ADDR, 0x10, I2C_MEMADD_SIZE_8BIT, buf, 1, 100);
为什么写完要等 5ms：EEPROM 写入是物理电荷注入过程，期间芯片不响应任何地址。不等就写下一字节 → 丢数据。单次测试正常、连写就崩是这个坑的典型症状。

10.4 软件模拟 I2C：核心就 6 个动作

/* 引脚：SCL = PB6，SDA = PB7（开漏 + 上拉） */
#define SCL_H()  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET)
#define SCL_L()  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET)
#define SDA_H()  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_SET)
#define SDA_L()  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_RESET)
#define SDA_R()  HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_7)

void I2C_Start(void)   { SDA_H(); SCL_H(); delay_us(2); SDA_L(); delay_us(2); SCL_L(); }
void I2C_Stop(void)    { SDA_L(); SCL_H(); delay_us(2); SDA_H(); delay_us(2); }
/* 后面依次实现：发送字节 / 等待 ACK / 接收字节 / 发 ACK */
关键细节：① SDA 要能在「输出」和「输入」之间切换（收数据时改输入模式）；② 每次拉低/拉高之间要加微秒级延时；③ 上拉电阻必须有（外部 4.7k 或内部上拉，内部较弱）。

12.1 为什么需要 DMA

本章目标：理解 DMA 的适用场景，掌握三个最常用外设的 DMA 启动方式。
和网课的区别：网课说「DMA 就是不占 CPU」。它不讲 DMA 什么时候真的比中断快，也不讲忘了「先配 DMA 再配外设」会怎样。
方式传 1000 字节 @9600 串口CPU 占用
阻塞约 1 秒🔴 100%
中断约 1 秒🟡 每字节一次中断
DMA约 1 秒🟢 只有结束时一次中断
DMA 的本质：一个「专职搬运工」硬件。CPU 只下命令「把这 1000 字节搬到串口数据寄存器」，然后该干嘛干嘛。适合大批量、连续的数据流。

12.2 DMA 相关函数

函数作用
HAL_DMA_Init(&hdma)配置通道（CubeMX 生成，一般不用手动调）
HAL_DMA_Start(&hdma, src, dst, len)启动一次搬运
HAL_DMA_Start_IT(...)带完成中断
__HAL_LINKDMA(&huart1, hdmatx, hdma_usart1_tx)把 DMA 和外设句柄绑起来（CubeMX 生成）
HAL_DMA_Abort(&hdma)中止

12.3 串口 DMA 发送

/* USER CODE BEGIN 2 */
/* 启动一次 DMA 发送 */
HAL_UART_Transmit_DMA(&huart1, tx_buf, sizeof(tx_buf));

/* USER CODE BEGIN 4 */

{
    if (huart->Instance == USART1)
    {
        g_tx_done = 1;      /* 真正发完了 */
    }
}
坑：HAL_UART_Transmit_DMA 返回 HAL_OK 只代表「启动成功」，不代表发完。而且 DMA 传输期间你不能改 tx_buf 的内容（DMA 还在读它）。

12.4 ADC 多通道 DMA（最经典的组合）

uint16_t adc_dma_buf[4];       /* 4 个通道的结果 */

/* 启动：一次触发，DMA 自动填满 4 个元素 */
HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_dma_buf, 4);

/* 之后 adc_dma_buf[0..3] 就自动更新了，不需要再调用任何函数 */
为什么这是最规范的多通道做法：ADC 扫描模式依次转换 4 个通道，每转换完一个就触发一次 DMA 搬运，CPU 全程不用管。比「切通道 + 等转换 + 读值」循环干净得多。

12.5 配置顺序（容易配反）

顺序做什么配反的后果
①CubeMX 里给外设加 DMA 通道—
②生成代码（会自动 __HAL_LINKDMA）没有链接 → DMA 不工作
③调用外设的 _DMA 版启动函数调普通版 → DMA 根本不参与
「配了 DMA 但没效果」的头号原因：调用了 HAL_UART_Transmit 而不是 HAL_UART_Transmit_DMA —— 名字只差 4 个字母，行为天差地别。

12.6 本章自测

📖 参考答案（点击展开）
  1. 问：DMA 传 1000 字节和阻塞传 1000 字节，速度一样吗？
    答：一样。DMA 快在「不占 CPU」，不是快在传输速度（速度由外设决定）。
  2. 问：DMA 传输中能改源缓冲区吗？
    答：不能。DMA 还在读它，改了会发出错乱数据。
  3. 问：为什么 ADC 多通道推荐 DMA？
    答：扫描模式下每个通道转换完都会触发 DMA，一次性收完，CPU 完全不用参与。

Flash 的三个铁律：
① 写之前必须先擦（擦成 0xFF 才能写）
② 只能 1→0：擦完是 0xFF，写 0x0F 可以，再想写回 0xFF 必须重新擦
③ 擦除单位是「页」（F103 是 1KB），写单位是半字（16 位）

14.9 本章自测

📖 参考答案（点击展开）
  1. 问：为什么 s_mode 不加 volatile，而 g_key_event 要加？
    答：s_mode 只在主循环里读写；g_key_event 是中断写、主循环读，不加 volatile 编译器可能把它优化进寄存器，导致主循环看不到变化。
  2. 问：如果把闪烁改成 HAL_Delay(500) 会怎样？

  3. 问：为什么回调里只置标志位，不直接切模式？
    答：中断里做耗时操作（比如串口打印）会阻塞其他中断，还可能和主循环抢同一个外设（返回 HAL_BUSY）。
  4. 问：想再加一个 LED 该怎么改？
    答：CubeMX 里加一个输出引脚 → 生成 → 在 USER CODE 3 的 switch 里加一行 HAL_GPIO_WritePin(...)。这就是分层的好处。

📖 参考答案
  1. 存这个外设的全部运行状态和外设寄存器基地址（Init 参数、State、缓冲区指针、错误码）。一个外设一个句柄，因为每个实例（USART1/USART2）状态独立。
  2. Init 只配置（写寄存器参数），Start 才让外设真正工作。必须 Start 的：TIM（PWM/中断/编码器）、ADC、USART 接收、DAC、DMA。
  3. 时钟不开，外设寄存器写的值会丢（时钟停止时不响应写操作）。表现是"配置全对但一点反应没有"。
  4. 变量被中断改、主循环读（或反之）时必须加。不加编译器可能把它常驻寄存器，主循环永远看不到变化。
  5. 中断要尽快返回。printf 可能耗时几毫秒并依赖串口状态，Delay 直接空等几百毫秒 —— 期间其他中断全被拖住，严重时会死锁。
  6. 因为 Receive_IT 是一次性的：收满 Size 个字节就结束并关闭接收中断。想连续收必须在回调里重新调用。
  7. Delay 是阻塞：CPU 原地等，什么都不能干；GetTick 差值是非阻塞：记个时间戳就往下走，主循环继续转。
  8. 填 0x78（0x3C << 1）。因为 HAL 的 DevAddress 参数要求8 位地址（最后一位是读写位）。
  9. 没有上拉，SDA/SCL 无法回到高电平（开漏结构），通信必然失败。SPI 是推挽输出 + 单向片选，不需要共用总线仲裁，所以不用上拉。
  10. PSC 决定计数频率（分频），ARR 决定周期长度（计到多少溢出）→ 两者共同决定频率。改亮度改 CCR（SET_COMPARE）。
  11. 2048/4095×3.3 ≈ 1.65V。除 4095 是因为 12 位 ADC 的满量程对应 4095（0~4095 共 4096 个档位，最大值是 4095）。
  12. SPI 没有应答机制，发出去就认为成功，错了也不知道；I2C 每个字节都有 ACK，没应答立刻能发现。
  13. Normal：搬完 N 个就停；Circular：搬完自动从头再来。ADC 连续采集用 Circular（否则只能采一轮）。
  14. 中断里喂狗，等于"只要中断还在跑就认为系统正常"。但主循环卡死时中断往往还在跑 → 看门狗失效。喂狗要放在主循环，代表整个系统健康。
