# 08 · NVIC 中断优先级与中断机制

## 一、中断体系：内核异常 + 外设中断

Cortex-M3 的「异常」分两类：

| 类型 | 编号 | 例子 | 谁管理 |
|---|---|---|---|
| 内核异常 | 负编号 | Reset、NMI、HardFault、SVCall、PendSV、SysTick | 内核（SCB/NVIC） |
| 外设中断 | 0–67 | EXTI0、USART1、TIM2、ADC1_2 | NVIC + 外设 |

外设产生中断请求后，信号进入 NVIC；NVIC 根据「使能位 + 优先级」决定是否打断当前执行，然后 CPU 跳到向量表里对应的地址。F1 的向量表在启动文件 `startup_stm32f103xb.s` 里，名字必须与 `stm32f103xb.h` 的 `xxx_IRQn` 对应。

```
外设事件 → 外设中断标志 → NVIC 使能位 → 优先级仲裁 → CPU 响应
                                                        ├─ 压栈（R0-R3, R12, LR, PC, xPSR）
                                                        ├─ 取向量表地址
                                                        └─ 执行 xxx_IRQHandler()
```

## 二、优先级：4 位，分成「抢占」和「子优先级」

F1 的 NVIC 给每个中断 4 位优先级（0–15，**数值越小越高**）。这 4 位可以按不同比例分给两组：

| 分组 | 抢占位数 | 子优先级位数 | 抢占级数 | 子优先级级数 |
|---|---|---|---|---|
| Group 0 | 0 | 4 | 1 | 16 |
| Group 1 | 1 | 3 | 2 | 8 |
| Group 2 | 2 | 2 | 4 | 4 |
| Group 3 | 3 | 1 | 8 | 2 |
| Group 4 | 4 | 0 | 16 | 1 |

规则只有两条：

1. **抢占优先级不同**：高抢占可以打断低抢占（嵌套）；
2. **抢占优先级相同**：谁先到谁先执行，后到的等高抢占的那一个执行完再进；**子优先级只在同时挂起时决定顺序，不能嵌套**。

> 一个工程里**只设置一次分组**。HAL 的 `HAL_Init()` 默认用 `NVIC_PRIORITYGROUP_4`（4 位全给抢占）。如果你在别处又调了 `HAL_NVIC_SetPriorityGrouping()`，之前配好的优先级含义会整体变化。

## 三、HAL 的三个函数

```c
/* 1. 设分组（整个工程一次，放在 main 开头或 HAL_Init 后） */
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);

/* 2. 设某个中断的抢占/子优先级 */
HAL_NVIC_SetPriority(USART1_IRQn, 1, 0);   /* 抢占 1，子优先级 0 */

/* 3. 使能该中断 */
HAL_NVIC_EnableIRQ(USART1_IRQn);
```

关闭/清除挂起：

```c
HAL_NVIC_DisableIRQ(USART1_IRQn);
HAL_NVIC_ClearPendingIRQ(USART1_IRQn);
```

CubeMX 的 **NVIC Settings** 勾选就是把这三步生成到 `HAL_xxx_MspInit()` 里；勾 `Enable` 后不要又在代码里改优先级，否则两边打架。

### 中断服务函数怎么写

外设中断的标准结构是「HAL 公共处理 + 用户回调」：

```c
/* stm32f1xx_it.c（CubeMX 生成） */
void USART1_IRQHandler(void)
{
  HAL_UART_IRQHandler(&huart1);   /* 清标志、判类型、调回调 */
}

/* 你自己的文件 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1) {
    /* 业务：只做轻量操作 */
  }
}
```

**不要直接改 `USART1_IRQHandler` 里的生成区**；要加逻辑就重写回调。

## 四、优先级怎么排：一个可用的模板

| 中断 | 建议抢占优先级 | 理由 |
|---|---|---|
| SysTick / HAL 时基 | 0（最高） | `HAL_Delay` 与超时依赖它 |
| 看门狗 / 故障保护 | 0 | 要最先响应 |
| 串口 / SPI / I2C | 2–4 | 要快，但不能压过时基 |
| 定时器 PWM/捕获 | 3–5 | 周期性，允许少量抖动 |
| 按键 EXTI | 6–10 | 人手速度，慢一点没关系 |
| 低速 ADC | 6–10 | 按采样率定 |

### 中断里不要做的事

- `HAL_Delay()`：等 SysTick，优先级不高于 SysTick 时会死等；
- `printf()`：阻塞发送，几十微秒到几毫秒，期间其他中断被拖；
- 大数组拷贝/浮点运算：拉长中断时间，影响实时性；
- 调用不可重入函数：可能破坏主循环的状态。

正确做法：中断里只置标志/存数据，主循环处理；必须快发的用 DMA。

## 五、临界区与关中断

```c
__disable_irq();          /* 关全局中断（PRIMASK） */
/* 临界区：极短，不要放函数调用 */
__enable_irq();           /* 开全局中断 */

/* 或者只关某个中断 */
HAL_NVIC_DisableIRQ(TIM2_IRQn);
```

HAL 提供 `__disable_irq/__enable_irq` 与 `__get_PRIMASK/__set_PRIMASK`。临界区越短越好；在临界区里调用 `HAL_Delay` 会导致永久卡死。

## 六、坑：优先级配反的典型症状

| 现象 | 原因 | 修法 |
|---|---|---|
| 串口偶尔丢字节 | 串口中断被更高优先级长时间占用 | 降低高优先级中断的处理时间，或串口用 DMA |
| 程序卡在 `HAL_Delay` | 在中断里调用，SysTick 被屏蔽 | 中断里改用状态机 |
| 两个中断互相等 | 高优先级等低优先级的资源 | 不要跨优先级等锁；用无锁队列/标志 |
| 改了分组后全乱 | 工程里设置了两次分组 | 只设置一次，放在 `HAL_Init` 后 |
| 中断只进一次 | 忘了清外设标志 / 没重新挂接收 | 回调里清标志或重启接收 |
| HardFault 在中断里 | 栈溢出 / 访问空指针 / 未使能外设时钟 | 查 MSP、查指针、查 MSP 初始化 |

## 练习

Q| 抢占优先级和子优先级的本质区别是什么？两个中断抢占优先级相同、子优先级不同，能互相打断吗？
A| 抢占优先级决定「能不能打断正在执行的中断」；子优先级只在多个中断同时挂起时决定「谁先排队」，不能打断。两个中断抢占级相同，无论子优先级如何都不能互相嵌套；先到的执行完，后到的才进。只有抢占级不同才有嵌套。

Q| `HAL_NVIC_SetPriorityGrouping()` 为什么建议整个工程只调用一次？如果在两个文件里分别设了 Group 2 和 Group 4 会怎样？
A| 分组决定 4 位优先级里「几位是抢占、几位是子优先级」，是全局解释规则。如果两处设置不同，后设置的会改变所有已配置中断的语义：原本按 Group 2 配的「抢占 1、子 2」在 Group 4 下会变成「抢占 1、无子优先级」，嵌套关系完全变化。表现是「以前能嵌套的现在不能、以前不嵌套的现在抢了」。应统一在 `main` 开头设一次。

Q| 为什么在优先级低于 SysTick 的中断里调用 `HAL_Delay()` 会卡死？如果必须延时，应该怎么做？
A| `HAL_Delay` 靠 `uwTick` 递增，`uwTick` 由 SysTick 中断维护。如果当前中断的抢占优先级低于 SysTick，SysTick 可以打断它，`uwTick` 会继续走——这种情况其实不会卡死。真正卡死的是：当前中断优先级**不低于** SysTick（数值 ≤ SysTick），SysTick 无法抢占，`uwTick` 停止增长，while 永远不满足。正确做法：中断里不要阻塞延时；用硬件定时器、状态机、或把工作放到主循环。

Q| 串口接收中断里把收到的字节追加到一个 256 字节环形缓冲区，主循环读取。需要保护哪些共享变量？怎么保护最省事？
A| 共享的是「写指针、读指针、缓冲区内容」。最省事的单生产者/单消费者做法：中断只写 `head` 和缓冲区，主循环只写 `tail`；两边各自只改自己的指针，用 `volatile` 防止优化，判断空/满用下标差值，避免同时改一个变量。若必须改同一变量，用极短的 `__disable_irq()/__enable_irq()` 临界区，不要在临界区里做拷贝。
