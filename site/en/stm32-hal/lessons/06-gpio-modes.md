# 06 · GPIO 结构与八种工作模式

part: 第二篇 · GPIO 与中断
video: P45 – P48
level: 基础
lead: GPIO 看着最简单，其实是「数字电路 + 模拟开关 + 复用矩阵」的组合。八种工作模式不是背出来的，而是从输入/输出两条通路推出来的：信号从哪进、经过什么、最后由哪个寄存器控制。把这一课弄透，后面按键、OLED、SPI、PWM 的引脚配置都不会再配错。

goals:
- 能画出 GPIO 的输入通路与输出通路，指出上下拉、施密特触发器、输出 MOS 的位置
- 能根据场景选择推挽/开漏、上拉/下拉/浮空/模拟，并解释理由
- 能读懂 CRL/CRH/ODR/IDR/BSRR 的位定义，知道 BSRR 为什么比 ODR 好
- 能区分普通 GPIO 与复用功能（AF），知道什么时候必须配复用

stats: 8 种模式 · 7 个寄存器 · 1 张选择表

## 一、一条引脚里有什么

F1 的每个 GPIO 位都有一整套电路：

```
                 VDD
                  │
              ┌───┴───┐ 上拉
              │       │
  引脚 ──┬────┤       ├────┬──► 输入数据寄存器 IDR
         │    └───┬───┘    │
         │        │ 下拉    │
         │        ▼        │
         │       VSS       │
         │                 │
         │    ┌─────────┐  │
         └────┤ 施密特  ├──┘   （数字输入时整形）
              │ 触发器  │
              └─────────┘
         │
         │    ┌──────────┐
         └────┤ 输出控制 ├────┬──► 推挽/开漏输出
              │  (P-MOS  │    │
              │   N-MOS) │    │
              └──────────┘    │
                              ▼
                          引脚
```

关键点：

- **上拉/下拉**是可编程的弱电阻（约 30–50kΩ），只在输入/开漏输出时起作用；
- **施密特触发器**把模拟电平整形成 0/1，输入模式下一定经过它；
- **输出 MOS** 决定推挽还是开漏：推挽是上下两个 MOS 轮流导通，开漏只有下管，输出高时是高阻；
- **复用功能**把引脚的「输出控制」从 ODR 切到某个外设（USART/TIM/SPI），此时 GPIO 只负责电气属性（推挽/开漏、速度），信号由外设产生。

## 二、八种工作模式：其实只有四条路

CubeMX 的 GPIO 模式下拉框有八项，本质是「输入/输出/复用/模拟」四类，每类再分推挽/开漏或上拉/下拉：

| 模式 | 方向 | 谁在驱动 | 典型用途 |
|---|---|---|---|
| 输入浮空（Input floating） | 输入 | 外部电路 | 外部已有上下拉的信号、USART_RX |
| 输入上拉（Input pull-up） | 输入 | 内部弱上拉 | 按键一端接地、悬空时为高 |
| 输入下拉（Input pull-down） | 输入 | 内部弱下拉 | 按键一端接 VCC、悬空时为低 |
| 模拟（Analog） | 模拟 | — | ADC 采样、低功耗 |
| 输出推挽（Output push-pull） | 输出 | 内部上下 MOS | LED、蜂鸣器、普通数字输出 |
| 输出开漏（Output open-drain） | 输出 | 只有下 MOS | I2C SDA/SCL、电平转换、线与 |
| 复用推挽（AF push-pull） | 输出 | 外设 | USART_TX、SPI_MOSI、TIM_PWM |
| 复用开漏（AF open-drain） | 输出 | 外设 | 硬件 I2C 的 SCL/SDA |

### 怎么选：三句口诀

1. **要读电平** → 输入；外部有明确电平就浮空，没有就上拉/下拉。
2. **要驱动负载** → 推挽；要「线与」或接 5V 器件 → 开漏（外加上拉）。
3. **信号由外设产生** → 复用；ADC 采样 → 模拟。

### 输出速度与驱动能力

CubeMX 里的 `Maximum output speed` 有 Low/Medium/High。速度越高，边沿越陡、EMI 越大；普通 LED、按键扫描用 Low 就够，SPI 高速时钟才用 High。F1 单脚最大灌/拉电流约 20mA（绝对最大 25mA），**不能直接驱动电机、继电器**，中间要加三极管或驱动芯片。

## 三、寄存器：配置在 CRL/CRH，数据在 IDR/ODR

F1 的 GPIO 寄存器不多，CubeMX 和 HAL 最终都落到这几个：

| 寄存器 | 作用 | 位宽 |
|---|---|---|
| `CRL` | 配置 Px0–Px7 的模式与速度 | 每脚 4 位：MODE[1:0] + CNF[1:0] |
| `CRH` | 配置 Px8–Px15 | 同上 |
| `IDR` | 读输入电平（只读） | 每脚 1 位 |
| `ODR` | 写输出电平 | 每脚 1 位 |
| `BSRR` | 原子置位/复位 | 低 16 位置 1，高 16 位清 0 |
| `BRR` | 原子复位（F1 独有） | 低 16 位清 0 |
| `LCKR` | 锁定配置 | 需按序列写 |

### 为什么推荐 BSRR 而不是 ODR

```c
GPIOA->ODR |= (1 << 8);      /* 读-改-写：可能被中断打断，误改其他位 */
GPIOA->BSRR = (1 << 8);      /* 原子置位，一条指令，不会被中断拆开 */
GPIOA->BRR  = (1 << 8);      /* 原子复位 */
```

HAL 的 `HAL_GPIO_WritePin()` 内部就是写 BSRR/BRR；`HAL_GPIO_TogglePin()` 则是读 ODR 再写，**不是原子操作**，在多任务/中断里同时翻转同一引脚要加保护。

### 复用功能与重映射

F1 的复用功能有两层：

- **AFIO 时钟**：用 EXTI、重映射、调试口复用时要先 `__HAL_RCC_AFIO_CLK_ENABLE()`；
- **重映射**：比如 USART1 默认 PA9/PA10，可重映射到 PB6/PB7，需要写 AFIO_MAPR。CubeMX 里点引脚时如果出现黄色/绿色提示，说明该功能可重映射；不点重映射就直接用默认脚。

## 四、CubeMX 里的 GPIO 配置项

点一个引脚，选择信号后，左侧 **System Core → GPIO** 会出现该脚的具体选项：

| 选项 | 含义 | 建议 |
|---|---|---|
| GPIO output level | 初始化后的默认电平 | LED 低电平点亮 → High（灭） |
| GPIO mode | 输入/输出/复用/模拟 | 按上一节选择 |
| GPIO Pull-up/Pull-down | 内部上下拉 | 按键接地 → Pull-up |
| Maximum output speed | 输出速度 | 普通 IO 选 Low |
| User Label | 给引脚起名 | `LED`、`KEY`，生成宏 `LED_Pin` |

**User Label 很有用**：CubeMX 会在 `main.h` 里生成 `#define LED_Pin GPIO_PIN_8`、`#define LED_GPIO_Port GPIOA`，代码里写 `HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, ...)`，比记 PA8 清楚。

## 五、坑：GPIO 配错的典型现象

| 现象 | 原因 | 修法 |
|---|---|---|
| LED 很暗/不亮 | 推挽驱动能力不够 / 限流电阻过大 | 算电流，加三极管/驱动 |
| 按键读数一直为 0 | 配了输入下拉，按键又接 VCC | 改上拉或改接线 |
| 按键读数随机跳 | 浮空输入，手一碰就变 | 加上拉/下拉，或外部电阻 |
| I2C 拉不高 | 配成推挽，两个器件打架 | 改开漏 + 外部上拉 |
| PWM 没波形 | 配成普通输出而不是复用推挽 | 改 `GPIO_MODE_AF_PP` |
| ADC 读数固定 4095 | 配成输入/输出，不是模拟 | 改 `GPIO_MODE_ANALOG` |
| 下载后再也连不上 | PA13/PA14 被配成普通 IO | 保持 SWD，Connect under Reset |
| 改引脚后功能没变 | 只改了 User Label，没改实际 Pin | 在 CubeMX 里看引脚图，重新生成 |

## 练习

Q| 为什么 I2C 的 SDA/SCL 必须配成开漏输出，而不能用推挽？上拉电阻起什么作用？
A| I2C 是多主多从的「线与」总线：任何器件都可以把线拉低，但不能主动输出高（否则两个器件一个推高一个拉低会短路大电流）。开漏输出只能拉低、释放时高阻，高电平由外部上拉电阻提供，这样多个器件「线与」才安全。上拉电阻同时决定上升沿时间，阻值太大边沿慢、通信失败，太小功耗大，常用 4.7kΩ。

Q| `HAL_GPIO_TogglePin()` 和 `HAL_GPIO_WritePin()` 在实现上有什么区别？为什么说前者不是原子的？
A| `WritePin` 根据电平写 `BSRR`（置位）或 `BRR`（复位），是单次寄存器写，原子。`TogglePin` 先读 `ODR` 的当前位，取反后再写回 `ODR`，是「读-改-写」三步；如果在这之间发生中断且中断也改了同一引脚，就会丢一次翻转。多上下文共用引脚时要用 `BSRR` 直接写目标电平，或加临界区。

Q| 一个按键一端接 GND，另一端接 PA0。要读到「按下为 0、松开为 1」，GPIO 应该配成什么模式？如果按键一端接 3.3V，又该怎么配？
A| 接 GND：配「输入上拉」，松开时内部上拉到 1，按下被拉到 0。接 3.3V：配「输入下拉」，松开时内部下拉到 0，按下为 1。两种都不应配浮空，否则松开时电平不确定。若外部已有 10k 上/下拉，也可以配浮空，避免内外电阻并联改变电平。

Q| 同一引脚先被配置成 TIM2_CH1 的复用推挽，后来又被配置成普通推挽输出，会发生什么？为什么？
A| 后配置的会覆盖前一个：引脚输出控制从 TIM2 切回 GPIO 的 ODR，PWM 波形消失，引脚电平由 `HAL_GPIO_WritePin` 决定。因为复用功能本质是把输出选择器从 GPIO 切到外设，同一时刻只能有一个源驱动引脚；CubeMX 里一个引脚也只能分配一个信号，冲突时会标红。写代码时不要在两个初始化里重复配置同一脚。
