## 一、一帧数据长什么样

UART 异步通信没有时钟线，双方靠「起始位」对齐，然后按波特率逐位采样。8 位数据、无校验、1 停止位（8-N-1）的一帧是 10 位：

```
空闲(高)  起始  D0  D1  D2  D3  D4  D5  D6  D7  停止  空闲
────────┐    ┌──┬──┬──┬──┬──┬──┬──┬──┐    ┌────────
        └────┘  │  │  │  │  │  │  │  └────┘
         0     1  0  1  0  0  1  1  1
```

- **空闲为高**，起始位是 1 位低电平；
- **数据低位在前**（LSB first）；
- **校验位**可选（奇/偶）；
- **停止位** 1/1.5/2 位高电平；
- 波特率 = 每秒传输的位数。115200 时一位约 8.68µs，一帧 10 位约 86.8µs。

接收方在起始位下降沿后，按 16 倍频采样，在第 8、9、10 个采样点做多数表决，所以能容忍一定的波特率误差（通常 < 3%）。

## 二、F1 的 USART 框图

```
                 ┌──────────────── USART1 ────────────────┐
APB2 72MHz ─────►│ BRR（波特率）                          │
                 │  ├─ 发送：DR → 发送移位寄存器 → TX      │
                 │  └─ 接收：RX → 接收移位寄存器 → DR      │
                 │ CR1/CR2/CR3：使能、字长、校验、中断      │
                 │ SR：TXE/RXNE/TC/ORE/FE/NE/PE            │
                 └─────────────────────────────────────────┘
```

| 寄存器 | 作用 | HAL 里的对应 |
|---|---|---|
| `CR1` | UE、TE、RE、M、PCE、中断使能 | `HAL_UART_Init()` |
| `CR2` | 停止位 | `Init.StopBits` |
| `CR3` | DMA、流控 | `Init.HwFlowCtl` |
| `BRR` | 波特率分频 | `Init.BaudRate` |
| `SR` | 状态标志 | `HAL_UART_GetState()` / 回调 |
| `DR` | 数据寄存器（收发共用） | `HAL_UART_Transmit/Receive` |

发送过程：写 `DR` → 硬件把数据移到移位寄存器 → 逐位输出 → `TXE` 置位表示可以写下一位 → 最后一个停止位发完 `TC` 置位（传输完成）。

接收过程：检测起始位 → 16 倍频采样 → 组成字节 → 放入 `DR` → `RXNE` 置位 → 读 `DR` 清标志。**读太慢会溢出（ORE）**，这是串口丢数据的根因。

## 三、波特率：从公式到 BRR

F1 的 USART 波特率公式（过采样 16）：

```
USARTDIV = fCK / (16 × BaudRate)
BRR = (整数部分 << 4) | (小数部分 × 16 四舍五入)
```

以 72MHz、115200 为例：

```
USARTDIV = 72,000,000 / (16 × 115200) = 39.0625
整数 39 = 0x27，小数 0.0625 × 16 = 1
BRR = 0x271
```

9600：

```
USARTDIV = 72,000,000 / (16 × 9600) = 468.75
整数 468 = 0x1D4，小数 0.75 × 16 = 12 = 0xC
BRR = 0x1D4C
```

HAL 不需要你算：`huart1.Init.BaudRate = 115200;` 后 `HAL_UART_Init()` 会按 `HAL_RCC_GetPCLK2Freq()` 自动写 BRR。但**你要知道它依赖 PCLK2**：USART1 挂 APB2（72MHz），USART2/3 挂 APB1（36MHz）。时钟改错，BRR 就错，输出全是乱码。

| 实际/目标 | 误差 | 结果 |
|---|---|---|
| 2% 以内 | 可接受 | 通常能通信 |
| 3% 左右 | 临界 | 偶发误码，长帧更明显 |
| > 5% | 不可用 | 全是乱码 |

## 四、引脚与电平

| 信号 | F1 默认引脚 | 方向 | CubeMX 模式 |
|---|---|---|---|
| USART1_TX | PA9 | 输出 | AF Push-Pull |
| USART1_RX | PA10 | 输入 | Input floating / Pull-up |
| USART2_TX/RX | PA2/PA3 | — | 复用 |
| USART3_TX/RX | PB10/PB11 | — | 复用 |

- **TTL 串口**：0–3.3V，单片机能直接接；与电脑通信要 USB 转 TTL（CH340）。
- **RS-232**：逻辑反相、±3～15V，必须经 MAX3232 电平转换，不能直接接单片机。
- **交叉接**：设备 A 的 TX 接设备 B 的 RX，双方共地；TX 对 TX 是常见接线错误。

## 五、CubeMX 配置串口

1. **Connectivity → USART1 → Mode: Asynchronous**；
2. Parameter Settings：115200、8 Bits、None、1、无流控；
3. **NVIC Settings**：勾 `USART1 global interrupt`（要用中断/DMA 时）；
4. 引脚图确认 PA9/PA10 变绿；
5. 生成后 `usart.c` 里有 `MX_USART1_UART_Init()` 与 `HAL_UART_MspInit()`。

## 六、坑：串口不通先查这五处

| 现象 | 先查 | 说明 |
|---|---|---|
| 完全没波形 | TX 引脚是否复用、时钟是否使能 | 量 PA9 空闲应为高 |
| 全是乱码 | 波特率、PCLK2 频率、晶振 | 两边都 115200；确认 HSE 8MHz |
| 收到但偶尔错字节 | 采样误差、线太长、干扰 | 降波特率、加共地、缩短线 |
| 只能收不能发 | TX/RX 接反 | 交叉接 |
| 接收溢出 | 主循环读太慢 / 中断优先级低 | 用中断/DMA，加环形缓冲 |

## 练习

Q| 8-N-1、115200 波特率下，传输 100 字节需要多长时间？如果把停止位改成 2 位，时间变成多少？
A| 8-N-1 一帧 10 位（1 起始 + 8 数据 + 1 停止），100 字节 = 1000 位，115200 bps 下约 1000/115200 ≈ 8.68ms。2 停止位时一帧 11 位，100 字节 = 1100 位 ≈ 9.55ms。实际还要加上软件处理与帧间空隙。

Q| 72MHz、USART1、目标波特率 115200，BRR 应该是多少？如果误把 USART1 的时钟按 36MHz 算，会怎样？
A| USARTDIV = 72e6/(16×115200) = 39.0625，BRR = 0x271。如果按 36MHz 算，USARTDIV ≈ 19.53，BRR 约 0x139，实际波特率只有目标的一半（约 57600），与电脑的 115200 不匹配，收到的是乱码。USART1 挂 APB2，不能用 PCLK1 算。

Q| 为什么 UART 不需要时钟线也能正确采样？它对双方时钟误差的容忍度为什么大约是 3%？
A| 接收方用起始位的下降沿重置内部采样计数器，然后按约定的 16 倍波特率计数，在每位中间采样；每帧起始都会重新对齐，所以不需要共享时钟。误差容忍度来自「一帧 10 位、采样点在第 8–10 个 16 分频点」：若双方累计偏差在一帧内超过约半个位，采样就会落到相邻位，通常允许 2–3%（10 位帧，最后一位的累计误差最大）。

Q| 串口接收中断里只读了一个字节，但主循环处理很慢，会发生什么？如何用最简单的方式避免？
A| USART 的 `DR` 只有一级缓冲，下一字节到来前没读走就置 `ORE`（溢出），新数据覆盖旧数据，表现为丢字节。最简单：接收中断里立刻把字节存入环形缓冲区（只做搬运，几十个周期），主循环慢慢处理；或者用 DMA 把数据直接搬到内存，CPU 只在空闲中断时批量处理。不要在高优先级中断里做耗时解析。
