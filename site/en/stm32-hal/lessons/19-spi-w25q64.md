# 19 · SPI 与 W25Q64

part: 第五篇 · 总线与数据通路
video: P152 – P153 · P169 – P170
level: 进阶
lead: SPI 比 I2C 快得多：四根线、全双工、没有地址和 ACK，时钟由主机说了算。代价是每多一个从机就多一根片选。这一课把 SPI 的四种模式讲清，再用 W25Q64 走一遍「读 ID → 写使能 → 擦除 → 页写 → 读回」的完整流程；会了这套，SD 卡、LCD、无线模块都是同一个套路。

goals:
- 能解释 CPOL/CPHA 四种模式，知道 W25Q64 用模式 0/3
- 能用 `HAL_SPI_Transmit/Receive/TransmitReceive` 完成全双工读写
- 能按指令序列操作 W25Q64：读 ID、写使能、擦扇区、页写、读数据
- 能处理「写不进、读回 0xFF、BUSY 卡住」这三类故障

stats: 4 根线 · 4 种模式 · 6 条常用指令

## 一、SPI 的线与模式

```
主机                         从机
SCK  ──────────────────────► SCK
MOSI ──────────────────────► MOSI（主机出）
MISO ◄────────────────────── MISO（从机出）
CS   ──────────────────────► CS（低有效）
```

- **全双工**：发一个字节的同时收一个字节；
- **无地址**：靠 CS 片选选器件；
- **时钟由主机产生**，速率可达 18MHz（F1 SPI1 挂 APB2）。

CPOL/CPHA 决定采样边沿：

| 模式 | CPOL | CPHA | 空闲电平 | 采样边沿 |
|---|---|---|---|---|
| 0 | 0 | 0 | 低 | 第一个边沿（上升） |
| 1 | 0 | 1 | 低 | 第二个边沿（下降） |
| 2 | 1 | 0 | 高 | 第一个边沿（下降） |
| 3 | 1 | 1 | 高 | 第二个边沿（上升） |

W25Q64 支持模式 0 和 3，CubeMX 默认模式 0 即可。模式选错，读出来全是 0xFF 或移位错位。

## 二、CubeMX 配置 SPI1

1. **Connectivity → SPI1 → Full-Duplex Master**；
2. Parameter Settings：
   - Frame Format = Motorola
   - Data Size = 8 Bits
   - First Bit = MSB First
   - Prescaler = 4（72/4 = 18MHz）
   - CPOL = Low，CPHA = 1 Edge（模式 0）
   - NSS = Software（用普通 GPIO 控制 CS）
3. 引脚：PA4=CS（GPIO_Output）、PA5=SCK、PA6=MISO、PA7=MOSI；
4. 生成后 `spi.c` 有 `MX_SPI1_Init()`。

> CS 用软件控制更灵活：一个 SPI 总线挂多个从机时，每个从机一根 CS。片选拉低→传输→拉高，三步不能少。

## 三、HAL 的 SPI API

```c
/* 只发 */
HAL_SPI_Transmit(&hspi1, buf, len, timeout);

/* 只收（主机要发 dummy 时钟） */
HAL_SPI_Receive(&hspi1, buf, len, timeout);

/* 全双工：发 len 字节同时收 len 字节 */
HAL_SPI_TransmitReceive(&hspi1, txbuf, rxbuf, len, timeout);
```

W25Q64 的读操作是「先发指令，再收数据」，用两次调用：

```c
uint8_t cmd = 0x03;
uint8_t buf[16];

CS_LOW();
HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
HAL_SPI_Receive(&hspi1, buf, 16, 100);
CS_HIGH();
```

## 四、W25Q64 指令与流程

| 指令 | 代码 | 作用 |
|---|---|---|
| JEDEC ID | `0x9F` | 读厂商/容量，正常返回 `EF 40 17` |
| 读状态 | `0x05` | bit0=BUSY，bit1=WEL |
| 写使能 | `0x06` | 写/擦前必须发 |
| 扇区擦除 | `0x20` | 擦 4KB，参数 24 位地址 |
| 页编程 | `0x02` | 写最多 256 字节 |
| 读数据 | `0x03` | 读任意长度 |

### 读 ID

```c
uint8_t id[3];
CS_LOW();
uint8_t cmd = 0x9F;
HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
HAL_SPI_Receive(&hspi1, id, 3, 100);
CS_HIGH();
/* id[0]=0xEF, id[1]=0x40, id[2]=0x17 表示 W25Q64 */
```

### 写一个扇区（4KB）

```c
#define W25Q_SECTOR 0x000000

static void W25Q_WriteEnable(void)
{
    uint8_t cmd = 0x06;
    CS_LOW();
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    CS_HIGH();
}

static void W25Q_WaitBusy(void)
{
    uint8_t cmd = 0x05, sr;
    do {
        CS_LOW();
        HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
        HAL_SPI_Receive(&hspi1, &sr, 1, 100);
        CS_HIGH();
    } while (sr & 0x01);
}

static void W25Q_EraseSector(uint32_t addr)
{
    uint8_t buf[4] = {0x20, (addr >> 16) & 0xFF, (addr >> 8) & 0xFF, addr & 0xFF};
    W25Q_WriteEnable();
    CS_LOW();
    HAL_SPI_Transmit(&hspi1, buf, 4, 100);
    CS_HIGH();
    W25Q_WaitBusy();
}

static void W25Q_PageWrite(uint32_t addr, const uint8_t *data, uint16_t len)
{
    uint8_t head[4] = {0x02, (addr >> 16) & 0xFF, (addr >> 8) & 0xFF, addr & 0xFF};
    W25Q_WriteEnable();
    CS_LOW();
    HAL_SPI_Transmit(&hspi1, head, 4, 100);
    HAL_SPI_Transmit(&hspi1, (uint8_t *)data, len, 1000);
    CS_HIGH();
    W25Q_WaitBusy();
}
```

**三条硬规则**：

1. 每次写/擦前必须发 `0x06`（写使能），否则被忽略；
2. 擦除单位是扇区（4KB），写入前必须擦成 0xFF；
3. 页编程不能跨 256 字节页边界，跨页要分段写。

## 五、把 W25Q64 当参数存储器

「擦扇区 → 读旧参数 → 合并新值 → 页写」是最小可用方案：

```c
typedef struct __attribute__((packed)) {
    uint32_t magic;
    uint16_t brightness;
    uint16_t volume;
    uint8_t  reserved[8];
} Param_t;

void Param_Save(const Param_t *p)
{
    W25Q_EraseSector(W25Q_SECTOR);
    W25Q_PageWrite(W25Q_SECTOR, (const uint8_t *)p, sizeof(Param_t));
}
```

`__attribute__((packed))` 让结构体紧凑，但会破坏对齐；写/读用 `memcpy` 到字节数组更稳。结构体里加 `magic` 和 CRC 可以判断「是不是第一次上电/数据是否损坏」。

## 六、坑：SPI 读不到 ID

| 现象 | 原因 | 修法 |
|---|---|---|
| 读 ID 全 0xFF | CS 没拉低 / MISO 没接 / 模式错 | 量 CS、MISO；确认模式 0 |
| 写入后读回 0xFF | 没擦除 / 没写使能 | 先擦扇区，再 `0x06` |
| 写一半失败 | 跨页 / BUSY 没等 | 按 256 字节分段，写后等 BUSY |
| 偶尔出错 | 速率太高/线太长 | 降 SPI 时钟，缩短线 |
| 多个从机互相干扰 | 共用一个 CS | 每个从机独立 CS，未选中的保持高 |
| 读回错位一字节 | 多发了 dummy / 指令长度错 | 检查指令与地址字节数 |

## 练习

Q| SPI 模式 0 和模式 3 的差别是什么？为什么 W25Q64 两种都能用？
A| 模式 0：CPOL=0、CPHA=0，空闲低电平、第一个（上升）沿采样；模式 3：CPOL=1、CPHA=1，空闲高电平、第二个（上升）沿采样。两者的采样沿都在上升沿，数据在下降沿变化，只是空闲电平不同。W25Q64 的时序允许这两种，所以 CubeMX 默认模式 0 即可；模式 1/2 则采样沿不同，会读错。

Q| W25Q64 页编程为什么不能跨 256 字节页边界？如果要写 500 字节，应该怎么写？
A| 页编程指令只更新页内地址的低 8 位，写到页尾会回卷到页首覆盖开头，所以跨页会破坏数据。写 500 字节要按页拆分：第一段写到本页剩余空间，第二段从下一页地址继续，最多 256 字节一段；每段写前发写使能、写后等 BUSY。擦除仍按 4KB 扇区做。

Q| 读 W25Q64 时，`HAL_SPI_Transmit(&cmd)` 之后为什么要再 `HAL_SPI_Receive(buf)`，而不是直接 Receive？接收时主机发的是什么？
A| SPI 是全双工、主机产生时钟：从机只有在 SCK 跳动时才输出数据。`Transmit` 负责把指令字节发出去并产生 8 个时钟；随后 `Receive` 继续产生时钟，同时把从机输出的数据读进来。`Receive` 期间 MOSI 上发的是 dummy（通常是 0xFF），对从机无意义。若直接用 `Receive`，指令没发出去，从机不知道要干什么。

Q| 一个 SPI 总线上挂 W25Q64 和一块 SPI LCD，片选分别接 PA4、PB0。软件上要注意什么？
A| ① 任一时刻只能拉低一个 CS，操作前拉低目标、操作完立刻拉高，未选中的保持高；② 两个器件的 SPI 模式/时钟可能不同，切换前用 `HAL_SPI_DeInit/Init` 或分别初始化不同 SPI 外设；③ 共用 SCK/MOSI/MISO 时，未选中器件的 MISO 应高阻，否则会打架；④ 不要在中断和主循环里同时操作同一 SPI 总线，加互斥或统一在主循环调度。
