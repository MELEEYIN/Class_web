# STM32 课讲义写作规范（内部约定，不面向学生）

这份文件定义 `site/en/stm32/lessons/` 下所有 `.md` 的结构与写法。
写新课、改旧课都照这份来，别自己发明格式——渲染器只认下面这些记号。

**范本**：`09-input-capture.md`（原理 + 代码 + 坑 + 练习都齐全，篇幅适中）。
动笔前先从头读一遍，尤其是代码块、表格、练习三处的写法。

---

## 1. 读者与目标

- 读者：会 C 语言（知道指针、结构体、位运算），摸过 Arduino 或完全没碰过单片机的大一/大二学生。
- 目标：读完能**照着接线把现象做出来**，并且能回答「这个外设的时钟挂在哪、要配哪几个寄存器、出错先查哪里」。
- 所以每一处「怎么做」后面必须跟一句「**为什么这样做**」，以及「**做错了会看到什么现象**」。

## 2. 文件与命名

| 东西 | 路径 | 规则 |
| --- | --- | --- |
| 讲义正文 | `site/en/stm32/lessons/NN-english-slug.md` | `NN` 两位数字（01–19），附录固定 `99-apx.md` |

## 3. 文件骨架（强制，顺序不可变）

```
# 05 · OLED：用软件 I2C 驱动 SSD1306
part: 第二篇 · GPIO 与显示
video: P9 – P10 · OLED 调试工具 / OLED 显示屏
level: 基础
lead: 一句话把这一课的内核说透（不是复述标题）。
goals:
- 能……（4 条，动词开头，可检验）
- 能……
- 能……
- 知道……
stats: 6 个小节 · 4 张表 · 4 道练习

## 一、第一个小节

正文……

## 二、……

……

## 练习
Q| 题干（一行）
A| 答案第一段
A| 答案第二段（会渲染成 <br> 换行）
```

- `part` 必须与 `STM32_PARTS` 里的篇名完全一致（`第二篇 · GPIO 与显示`）。
- `level` 只取 `入门` / `基础` / `进阶` / `难点` 四档，决定右上角徽标颜色。
- `lead` 一句话，30–80 字，必须是「本质」而不是「概述」。
- `goals` 恰好 4 条：3 条技能 + 1 条认知。别写成「了解 xxx」。
- 小节 5–7 个，编号用 `一、二、三`（渲染器不解析数字，只取整行文字）。

## 4. 可用记号（硬约束）

| 记号 | 渲染成 | 说明 |
| --- | --- | --- |
| `## 一、标题` | 节标题（页内目录第二层） | 每节至少 2 段正文 |
| `### 标题` | 小标题 `h4` | 慎用，超过 3 个就显得碎 |
| ```` ```c ```` | 代码块（带复制按钮） | 只写能编译的代码 |
| `| a | b |` + `| --- | --- |` | 表格 | 必须有分隔行 |
| `:::tip 标题` … `:::` | 绿框提示 | `tip` / `warn` / `note` 三种 |
| `**粗体**` | `<b>` | 一段里最多 3 处，多了等于没有重点 |
| `` `代码` `` | `<code>` | 函数名、寄存器名、引脚名一律用它 |
| `- 条目` | 无序列表 | |
| `1. 条目` | 有序列表 | 步骤类内容用它 |
| `> 引用` | blockquote | 少用，提示块更合适 |
| `Q|` / `A|` | 练习组 | 必须写在 `## 练习` 之后 |

**不要在代码段之外裸写 `*`**。行内解析会把它当斜体标记，`value * 3300` 这种写法
必须放进反引号里写成 `` `value * 3300` ``——渲染器先按反引号切段，代码段内不再解析强调。

## 5. 代码块规则（最容易出错的地方）

1. **能编译**：库函数签名、结构体成员名、外设时钟都对照标准库 3.5.0 头文件写，
   不确定就查 `stm32f10x_xxx.h`，不要凭记忆编。
2. **一个代码块只讲一件事**：初始化一段、使用一段，别把 200 行塞进一个块。
3. **关键行加注释**：注释写在行尾或上一行，讲「为什么」而不是「做了什么」。
4. **引脚用课程套件的接法**：PA0–PA7 八灯、PB12 蜂鸣器、PB1/PB11 按键、PB8/PB9 软件 I2C、
   PB14 红外、PB0/PB1 编码器、PA9/PA10 串口、PA4–PA7 SPI。换引脚要在文里说明。
5. **数值要能验算**：定时器 PSC/ARR、波特率 BRR、ADC 换算、IWDG 溢出时间，
   文中必须给出算式，不能只给结论。

## 6. 每课的固定节奏

一篇合格的一课，读起来应该是这个顺序：

1. **本质一句话**（`lead`）
2. **读完能做到什么**（`goals`）
3. **原理**：先讲清「这个外设在芯片里长什么样」，一张表或一段框图式描述
4. **配置步骤**：编号列表，3–6 步，每步一句「不这么做会怎样」
5. **代码**：完整可编译，带注释
6. **坑**：一张表（现象 / 原因 / 修法），至少 4 行
7. **练习**：4 题（2 基础 + 1 变式 + 1 挑战），每题答案带「为什么」
