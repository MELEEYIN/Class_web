## 一、芯片型号就是一张配置单

`STM32F103C8T6` 这串字符不是随手编的，每一位都在说参数。会读型号，选型时就不用翻半天数据手册。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| STM32 | 系列 | ST 的 32 位 MCU，ARM Cortex-M 内核 |
| F | 产品类型 | F = 通用型（L 低功耗、H 高性能、G 主流） |
| 103 | 子系列 | 主流型，Cortex-M3，72MHz |
| C | 引脚数 | C = 48 脚（T=36、C=48、R=64、V=100、Z=144） |
| 8 | Flash 容量 | 8 = 64KB（6=32K、8=64K、B=128K、C=256K） |
| T | 封装 | T = LQFP，B = QFPN，U = UFQFPN |
| 6 | 温度等级 | 6 = −40～85℃，7 = −40～105℃ |

所以 C8T6 = 48 脚、64KB Flash、LQFP 封装、工业温度。它属于 ST 的「中容量（Medium-density）」产品，这个档次直接决定了后面建工程时 `STM32F10X_MD` 这个宏不能写错。

这颗芯片的实际家底：

| 资源 | F103C8T6 的实际值 | 对写代码的影响 |
| --- | --- | --- |
| 内核 / 主频 | Cortex-M3，最高 72MHz | 一条指令约 13.9ns，`for` 空转的延时可以粗算 |
| Flash / SRAM | 64KB / 20KB | 存字模、缓存一帧 OLED 显存（1KB）都够，别塞大数组 |
| 通用 IO | 37 个（可用 35 个：PA0–15、PB0–15、PC13–15） | 每个 GPIO 端口 16 位，正好对应寄存器低 16 位 |
| 定时器 | TIM1（高级）+ TIM2/3/4（通用）+ SysTick + IWDG/WWDG + RTC | PWM、输入捕获、编码器都靠这几个通用定时器 |
| 通信 | 3×USART、2×I2C、2×SPI、1×CAN、1×USB 2.0 全速 | 一门课能把 USART/I2C/SPI 全练一遍 |
| 模拟 | 2×ADC，12 位，最快 1μs 一次转换 | 0–3.3V 映射到 0–4095，分辨率约 0.8mV |
| 没有的 | DAC、SDIO、FSMC、以太网 | 要 DAC 得换 F103RC 以上，或用 PWM + RC 滤波凑 |

:::note 一个容易踩的命名坑
`STM32F103C8T6` 和 `STM32F103CBT6` 引脚完全兼容，只差 Flash（64KB vs 128KB）。所以网上卖「C8T6 升级版 CBT6」的板子是同一块 PCB；但如果你在工程里锁死了 `STM32F10X_MD`，换芯片时启动文件要跟着换（`_md` / `_hd` 的向量表长度不同）。
:::

## 二、引脚：三组端口 + 两条「特殊线」

48 个脚里，能当普通 IO 用的是 PA0–PA15、PB0–PB15、PC13–PC15。命名规则很机械：端口字母 + 位号，`PA0` 就是 GPIOA 的第 0 位，对应 `GPIOA->ODR` 的第 0 位——**寄存器的一位 = 一个引脚**，这句话后面每一课都会用到。

除了通用 IO，还有几类脚必须单独记住：

| 引脚 | 固定功能 | 为什么必须记住 |
| --- | --- | --- |
| PA13 / PA14 | SWDIO / SWCLK | 下载调试就靠这两根，复用成普通 IO 后 ST-Link 连不上（要按住复位再下载） |
| PA9 / PA10 | USART1_TX / RX | 串口实验默认走这里，也是 FlyMcu 串口下载的通道 |
| PA11 / PA12 | USB DM / DP | 板子上的 USB 口直连，别乱配 |
| PD0 / PD1 | OSC_IN / OSC_OUT | 8MHz 晶振，配了外部晶振就不能再当 IO |
| PC14 / PC15 | OSC32_IN / OUT | 32.768kHz，RTC 用的 |
| NRST | 复位 | 低电平复位，板上已有 10k 上拉 + 100nF |
| BOOT0 | 启动选择 | 决定上电从 Flash 还是系统存储器启动 |
| VBAT | 备份电池 | 接纽扣电池，掉电后 RTC + BKP 才能继续走 |

还有一个只写在数据手册里的细节：**引脚能不能接 5V**。数据手册的引脚定义表里带 `FT`（Five-volt Tolerant）标记的脚可以输入 5V 并识别为高电平，不带 FT 的只能接 3.3V。输出永远只有 3.3V——因为整块板就供 3.3V。要驱动 5V 器件（比如某些继电器模块），中间得加三极管或电平转换。

## 三、最小系统：少一样都不启动

「最小系统板」之所以叫最小，是因为它只保证「芯片能跑起来」，一个外设都没多给。它必须包含四样东西：

| 组成 | 板上长什么样 | 缺了会怎样 |
| --- | --- | --- |
| 电源 | 3.3V LDO（常见 AMS1117-3.3）+ 若干 100nF 去耦电容 | 芯片不工作，或跑起来随机复位 |
| 晶振 | 8MHz 石英晶振 + 两个 20pF 负载电容 | 只能用内部 RC（HSI，精度差、温漂大），串口波特率会偏 |
| 复位 | NRST 脚 10kΩ 上拉到 3.3V + 100nF 到地 + 复位按键 | 上电复位不可靠，偶发不启动 |
| 启动配置 | BOOT0 经 10kΩ 下拉到地 | BOOT0 悬空时启动方式随机，可能进了系统存储器不跑你的程序 |

再加一个 SWD 排针（3.3V / GND / SWDIO / SWCLK）就能下载调试了。买板子时重点看两处：**BOOT0 有没有下拉电阻**（很多便宜板子只留跳线帽，拔了帽就悬空）、**晶振是不是 8MHz**（极少数板子用 12MHz，那样 `SystemInit` 里默认的 PLL 参数会算出 108MHz，超频跑飞）。

## 四、时钟：72MHz 是算出来的

STM32 的时钟不是「插上就是 72M」，而是一棵树：源头 → 锁相环 → 分频器 → 各条总线。搞不清这棵树，后面所有「定时器算不准、串口乱码、ADC 采样率不对」的问题都无从下手。

| 环节 | F103 的默认配置 | 结果 |
| --- | --- | --- |
| 时钟源 | HSE = 外部 8MHz 晶振（HSI = 内部 8MHz RC） | 8MHz |
| PLL | HSE × 9 | 72MHz → SYSCLK |
| AHB 预分频 | ÷1 | HCLK = 72MHz（内核、DMA、SRAM、Flash） |
| APB2 预分频 | ÷1 | PCLK2 = 72MHz（GPIO、AFIO、USART1、ADC1/2、TIM1、SPI1） |
| APB1 预分频 | ÷2 | PCLK1 = 36MHz（USART2/3、I2C1/2、SPI2、TIM2/3/4、PWR、BKP、WDG） |

:::warn 最容易记错的一条
APB1 上限是 36MHz，所以 TIM2/3/4 挂在 APB1 上——**但定时器的时钟是 PCLK1 的两倍，等于 72MHz**。规则是：APB 预分频 ≠ 1 时，定时器时钟 = PCLK × 2。
所以「TIM2 用 72MHz 算 PSC」是对的，而「I2C1 用 72MHz 算分频」就错了（I2C 只吃 36MHz）。这两个数在第 07 课和第 14 课会分别用到。
:::

时钟树还解释了另一件事：为什么刚上电、`SystemInit()` 还没跑完的时候，芯片其实是 8MHz 的 HSI 在跑。所有「上电先延时一下」的习惯，源头都在这儿。

## 五、上电之后发生了什么

按下复位键到 `main()` 的第一行，中间隔着一段你从没写过、但每次都在跑的代码。顺序是这样的：

1. **取栈顶与复位向量**：内核从 `0x08000000` 读出主栈指针（MSP）初值，从 `0x08000004` 读出 `Reset_Handler` 的地址并跳过去。这也是为什么中断向量表必须放在 Flash 起始处。
2. **`Reset_Handler`**（在 `startup_stm32f10x_md.s` 里）：调 `SystemInit()`，再调 `__main`。
3. **`SystemInit()`**（`system_stm32f10x.c`）：开 HSE、配 PLL ×9、切 SYSCLK 到 PLL、设 AHB/APB 分频，最后把 72MHz 写进 `SystemCoreClock`。
4. **`__main`**（编译器提供的库函数，不是你的 `main`）：把 `.data` 段从 Flash 拷到 SRAM、把 `.bss` 段清零、初始化堆栈，然后才跳到 `main()`。
5. **`main()`**：你的代码从这里开始。此时全局变量已经是初值，`SystemCoreClock == 72000000`。

这张「启动链」还能解释两个常见现象：全局数组不初始化就是 0（`.bss` 被清零），而**没有初始化的局部数组是随机值**（在栈上，没人清）。以及为什么在 `main` 里改主频后，`SystemCoreClock` 这个变量必须同步改——所有用 `SystemCoreClock` 算波特率、算定时的库函数都读它。

## 练习
Q| 一块板子上写着 `STM32F103RCT6`，它的 Flash 有多大、有多少个引脚、封装是什么？
A| 逐位拆：R = 64 脚；C = 256KB Flash；T = LQFP 封装；6 = −40～85℃。
A| 顺带一个结论：它是「大容量（High-density）」产品，建工程时宏要写 `STM32F10X_HD`，启动文件用 `startup_stm32f10x_hd.s`，写成 `_md` 会因为向量表不够长而在中断里跑飞。
Q| 为什么说「TIM2 的时钟是 72MHz，而 I2C1 的时钟是 36MHz」？两者不都在 APB1 上吗？
A| 都在 APB1 上，但规则不同：APB1 预分频为 2 时，PCLK1 = 36MHz。
A| 定时器有一条例外规则——APB 预分频 ≠ 1 时定时器时钟自动 ×2，所以 TIM2/3/4 拿到 72MHz；I2C、USART、SPI 这些外设不加倍，仍是 36MHz。
A| 记忆口诀：**定时器翻倍，其他照旧**。第 07 课算 PSC 用 72M，第 14 课算 I2C 分频用 36M。
Q| BOOT0 = 1、BOOT1 = 0 时芯片从哪启动？这个模式有什么实用价值？
A| 从「系统存储器」启动，也就是 ST 出厂固化的一段 Bootloader，它支持通过 USART1（PA9/PA10）接收程序。
A| 实用价值：没有 ST-Link 时可以用 FlyMcu 之类工具经串口下载程序（第 13 课会用到）；也能在程序把 SWD 脚复用掉、导致连不上调试器时救砖。
Q| 你写的 `main()` 里第一行就点亮 LED，但从复位到这一行之间，`SystemInit()` 已经做了哪些事？
A| 打开外部 8MHz 晶振并等待稳定；配置 PLL 为 HSE×9；把 SYSCLK 切到 PLL 输出 72MHz；设置 AHB ÷1、APB2 ÷1、APB1 ÷2；更新 `SystemCoreClock = 72000000`。
A| 在此之前芯片一直跑内部 HSI 8MHz，所以任何「上电立刻要求精准时序」的操作（比如马上发串口）都要考虑这段切换时间。
