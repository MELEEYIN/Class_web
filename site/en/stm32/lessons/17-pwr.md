## 一、三种模式：断到哪里，记得多少

| 项目 | 睡眠（Sleep） | 停止（Stop） | 待机（Standby） |
| --- | --- | --- | --- |
| 内核 | 停（SLEEPDEEP = 0） | 停 | 停 |
| 1.8V 域（数字部分） | 供电 | **断电** | **断电** |
| HSI / HSE | 继续跑 | 停 | 停 |
| SRAM 与寄存器 | 保持 | **保持** | **丢失** |
| RTC / BKP | 保持 | 保持 | 保持（有 VBAT 时） |
| 典型电流 | 十几 mA | 十几 μA | 约 2μA |
| 唤醒源 | 任意中断 | EXTI 线（外部中断） | WKUP 引脚上升沿 / RTC 闹钟 / IWDG 复位 |
| 唤醒后 | 从 WFI 下一句继续 | 从下一句继续，但时钟变回 HSI 8MHz | **相当于复位**，从头执行 |

三个关键结论：

1. **睡眠最省事**：外设都在跑，醒来接着干，适合「等一个中断但不想空转」。
2. **停止最常用**：电流从 mA 级降到 μA 级，SRAM 还在（变量不丢），代价是醒来要重配时钟。
3. **待机最省电**：变量全丢、程序从头跑，只适合「按一下键开机」这类场景。

## 二、进停止模式：四行代码，两个坑

```c
#include "stm32f10x.h"

void Enter_Stop_Mode(void)
{
    /* ① 开 PWR 时钟（必须，否则下面两句静默失败） */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

    /* ② 允许在停止模式下使用低功耗稳压器 */
    PWR_EnterSTOPMode(PWR_Regulator_LowPower, PWR_STOPEntry_WFI);
    /* —— 程序在这里停住，直到有 EXTI 中断把它叫醒 —— */

    /* ③ 唤醒后时钟自动切回 HSI 8MHz，必须重新配成 72MHz */
    SystemInit();

    /* ④ 如果开了串口，波特率要按新时钟重算 */
    Serial_Init();
}
```

两个坑：

- **唤醒后时钟是 HSI 8MHz**。如果不调 `SystemInit()`，所有依赖 72MHz 的东西全部变慢 9 倍：串口波特率变成 1/9（全是乱码）、定时器周期变成 9 倍、I2C 时序全乱。现象是「唤醒后串口突然全是乱码」，很多人误以为是串口坏了。
- **调试时进停止模式会断开 SWD**。芯片一停，调试器就失去连接，看起来像「程序卡死」。做法是调试阶段先不调 `PWR_EnterSTOPMode`，或者用 `DBGMCU_Config(DBGMCU_STOP, ENABLE)` 让调试器暂停时保持时钟。

## 三、进待机模式：醒来就是一次重启

```c
void Enter_Standby_Mode(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

    /* ① 使能 WKUP 引脚（PA0）作为唤醒源 */
    PWR_WakeUpPinCmd(ENABLE);

    /* ② 清唤醒标志，否则可能立刻被上一次的标志唤醒 */
    PWR_ClearFlag(PWR_FLAG_WU);

    /* ③ 进待机 */
    PWR_EnterSTANDBYMode();
}
```

待机唤醒后**等同复位**：`main` 从头执行，全局变量重新初始化，SRAM 内容全没了。所以「待机前保存的状态」必须写进 BKP 或 Flash，醒来再读回来。

| 唤醒源 | 配置方式 | 说明 |
| --- | --- | --- |
| WKUP 引脚（PA0） | `PWR_WakeUpPinCmd(ENABLE)` | 上升沿有效，板上通常接按键 |
| RTC 闹钟 | `RTC_ITConfig(RTC_IT_ALR, ENABLE)` + `RTC_SetAlarm` | 可以定时唤醒，做「每小时采一次」 |
| IWDG 复位 | 使能独立看门狗 | 看门狗超时把芯片复位唤醒 |
| NRST 引脚 | 硬件复位 | 按复位键 |

## 四、改主频：72 / 36 / 24 怎么切

`SystemInit()` 里默认把 PLL 配成 HSE×9 = 72MHz。想在运行时改，本质是改 PLL 倍频系数并重新切换时钟源：

| 目标 | PLL 倍频 | 分频 | 说明 |
| --- | --- | --- | --- |
| 72MHz | ×9 | AHB ÷1、APB1 ÷2、APB2 ÷1 | 默认，性能最高 |
| 36MHz | ×9 后 AHB ÷2 | APB1 ÷2 → 18MHz | 常用低功耗档 |
| 24MHz | ×6 | 全 ÷1 | 低速、低功耗 |
| 8MHz（HSI） | 不用 PLL | — | 最省电，但外设时序全变 |

改主频的标准步骤：**切回 HSI → 关 PLL → 改 PLL 参数 → 开 PLL → 等锁定 → 切到 PLL → 更新 `SystemCoreClock`**。中间任何一步顺序错了，芯片会短暂失去时钟（表现为程序跑飞）。

:::warn 改完主频必须同步 SystemCoreClock
所有库函数（串口波特率、定时器、SysTick、I2C 分频）都读 `SystemCoreClock` 这个变量。你改了实际主频却没改这个变量，库函数会按旧的 72MHz 算分频，结果全部偏差。
标准做法：把 `system_stm32f10x.c` 里的 `SystemCoreClockUpdate()` 调一次，它会重新读寄存器算出真实频率。
:::

## 五、功耗优化的实际顺序

| 优先级 | 措施 | 能省多少 | 代价 |
| --- | --- | --- | --- |
| 1 | 关掉不用的外设时钟（`RCC_APB2PeriphClockCmd(..., DISABLE)`） | 几 mA | 无 |
| 2 | 没用到的 GPIO 配成模拟输入 | 几百 μA | 无 |
| 3 | 降低主频（72 → 8MHz） | 约 10 倍 | 性能下降 |
| 4 | 空闲时进睡眠 | 一半以上 | 唤醒有延迟 |
| 5 | 空闲时进停止 | 降 1000 倍 | 要重配时钟 |
| 6 | 空闲时进待机 | 降到 2μA | 状态全丢 |

「GPIO 配成模拟输入」这一条最反直觉，但很有效：浮空输入的引脚会被外部噪声不断充放电，产生额外功耗；模拟输入把数字通路完全关闭，最省电。

## 六、这一课和前面几课的关系

低功耗不是孤立的一课，它把前面所有外设串了起来：

- **EXTI**（第 06 课）：停止模式的唤醒源，没有它就叫不醒。
- **RTC**（第 16 课）：待机模式下唯一还能「看时间」的东西，也是定时唤醒的闹钟。
- **USART**（第 13 课）：唤醒后要重配波特率，否则乱码。
- **IWDG**（第 18 课）：待机时也能复位唤醒，是「兜底」手段。

一个真实的低功耗采集节点大概长这样：平时待机（2μA）→ RTC 每小时闹钟唤醒 → 醒来配时钟、读传感器、发串口 → 再进待机。整机平均电流可以做到几十 μA，一节纽扣电池撑一年。

## 练习
Q| 停止模式唤醒后，为什么串口会输出乱码？
A| 唤醒后时钟自动切回 HSI 8MHz，而 `USART_BRR` 还是按 72MHz 算出来的值。实际波特率变成设定值的 1/9（比如设 9600，实际约 1067），对方按 9600 采样，收到的全是乱码。
A| 修法：唤醒后先 `SystemInit()` 把时钟恢复到 72MHz 再 `Serial_Init()` 重算 BRR；或者接受 8MHz 运行，用 8MHz 重算一次波特率。
Q| 睡眠、停止、待机三种模式，分别丢失了什么？
A| 睡眠：什么都不丢，只是内核停了。
A| 停止：丢时钟（HSI/HSE 停），但 SRAM 和寄存器内容保持，变量还在。
A| 待机：丢 SRAM 和寄存器内容，等于复位，只有 BKP 和 RTC（有 VBAT 时）还在。
Q| 想让设备「按一下 PA0 上的按键才开机」，应该用哪种低功耗模式？为什么不能用停止模式？
A| 用待机模式。WKUP 引脚（PA0）的上升沿是待机模式的专用唤醒源，醒来等同复位，正好符合「开机」的语义。
A| 停止模式也能被 EXTI 唤醒，但它是「从暂停处继续」：醒来变量还在、程序接着跑，适合「休眠—继续」；而「开机」要求程序从头初始化，用待机更干净。
Q| 把主频从 72MHz 改成 36MHz 后，串口能通、但定时器慢了正好一倍。为什么？
A| 因为外设的时钟是从主频分频来的。主频减半、分频系数不变，定时器时钟也减半，同样的 PSC/ARR 算出来的周期就翻倍。
A| 这其实是「正确」的行为，不是 bug。要恢复原来的定时，需要把 PSC 或 ARR 减半；同时别忘了更新 `SystemCoreClock`，否则库函数还会按旧值算。
