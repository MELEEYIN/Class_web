## 一、两根线怎么区分「谁在说话」

| 线 | 全称 | 方向 | 特点 |
| --- | --- | --- | --- |
| SCL | Serial Clock | 主机 → 从机 | 时钟由主机产生 |
| SDA | Serial Data | 双向 | 半双工，同一时刻只能一个方向 |

起止条件（这两条是「帧边界」）：

- **起始（S）**：SCL 高电平时，SDA 由高变低。
- **停止（P）**：SCL 高电平时，SDA 由低变高。

数据有效性：**SCL 高电平期间 SDA 必须稳定**（接收方在这时采样），SDA 只允许在 SCL 低电平时变化。这条规则是「为什么起始/停止要用 SCL 高时的跳变」的原因——正常数据不允许这么跳，所以这种组合能被唯一识别为边界。

## 二、地址：7 位与 8 位的换算

每个从机有一个 7 位地址。传输时把它左移一位，最低位放读写标志：

**8 位写地址 = 7 位地址 << 1 　 8 位读地址 = (7 位地址 << 1) | 1**

| 器件 | 7 位地址 | 写（8 位） | 读（8 位） |
| --- | --- | --- | --- |
| MPU6050（AD0 = 0） | 0x68 | 0xD0 | 0xD1 |
| MPU6050（AD0 = 1） | 0x69 | 0xD2 | 0xD3 |
| SSD1306 OLED | 0x3C | 0x78 | 0x79 |
| AT24C02 EEPROM | 0x50 | 0xA0 | 0xA1 |

代码里常见的「地址差 1」的 bug，几乎都是把 7 位当成了 8 位（或反过来）。判据：**发送时用的是 8 位形式**；算偏移、查手册时用 7 位形式。

## 三、读一个寄存器：写地址 → 写寄存器号 → 重启 → 读

I2C 读操作比写多一个「重复起始（Sr）」：

| 步骤 | 主机动作 | 从机回应 |
| --- | --- | --- |
| 1 | S（起始） | — |
| 2 | 发 0xD0（写） | ACK |
| 3 | 发寄存器地址（如 0x75） | ACK |
| 4 | **Sr（重复起始）** | — |
| 5 | 发 0xD1（读） | ACK |
| 6 | 收 1 字节，回 **NACK** | 送出数据 |
| 7 | P（停止） | — |

第 6 步的 NACK 是「我只要一个字节，别再发了」的暗号。要读多个字节，前几个回 ACK，最后一个回 NACK。

```c
/* 软件 I2C 读寄存器：先写寄存器地址，再读数据 */
uint8_t MPU6050_ReadReg(uint8_t reg)
{
    uint8_t data;

    MyI2C_Start();
    MyI2C_SendByte(0xD0);        MyI2C_ReceiveAck();   // 写地址
    MyI2C_SendByte(reg);         MyI2C_ReceiveAck();   // 寄存器号
    MyI2C_Start();                                     // 重复起始
    MyI2C_SendByte(0xD1);        MyI2C_ReceiveAck();   // 读地址
    data = MyI2C_ReceiveByte();  MyI2C_SendAck(1);     // 读 1 字节 + NACK
    MyI2C_Stop();
    return data;
}

void MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    MyI2C_Start();
    MyI2C_SendByte(0xD0);        MyI2C_ReceiveAck();
    MyI2C_SendByte(reg);         MyI2C_ReceiveAck();
    MyI2C_SendByte(value);       MyI2C_ReceiveAck();
    MyI2C_Stop();
}

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t i, byte = 0;
    MyI2C_SDA_H();                                  // 释放 SDA，交给从机
    for(i = 0; i < 8; i++){
        MyI2C_SCL_L(); Delay_us(2);
        MyI2C_SCL_H(); Delay_us(2);
        byte <<= 1;
        if(MyI2C_SDA_R()) byte |= 0x01;              // 高位先到
    }
    return byte;
}

void MyI2C_SendAck(uint8_t ack)                     // ack=0 应答，1 非应答
{
    MyI2C_SCL_L();
    if(ack) MyI2C_SDA_H(); else MyI2C_SDA_L();
    Delay_us(2);
    MyI2C_SCL_H(); Delay_us(2);
    MyI2C_SCL_L(); Delay_us(2);
}
```

## 四、MPU6050：先唤醒，再读 14 个字节

MPU6050 上电后默认处于**睡眠模式**，此时所有数据寄存器都是 0。不唤醒就读，得到的永远是 0——这是「I2C 通信正常但数据全 0」的头号原因。

| 寄存器 | 地址 | 作用 | 常用值 |
| --- | --- | --- | --- |
| `WHO_AM_I` | 0x75 | 器件 ID，只读 | 应返回 0x68 |
| `PWR_MGMT_1` | 0x6B | 电源管理 | 写 0x01 唤醒并选陀螺 X 轴作时钟源 |
| `SMPLRT_DIV` | 0x19 | 采样分频 | 0x09（1kHz / 10 = 100Hz 输出） |
| `CONFIG` | 0x1A | 数字低通滤波 | 0x06（5Hz，足够稳） |
| `GYRO_CONFIG` | 0x1B | 陀螺量程 | 0x00 = ±250°/s（灵敏度 131 LSB/(°/s)） |
| `ACCEL_CONFIG` | 0x1C | 加速度量程 | 0x00 = ±2g（灵敏度 16384 LSB/g） |
| `ACCEL_XOUT_H` | 0x3B | 数据起点 | 连续 14 字节：加速度 6 + 温度 2 + 陀螺 6 |

量程与灵敏度的关系（这也是换量程时必须改的换算系数）：

| 量程 | 灵敏度 | 含义 |
| --- | --- | --- |
| ±2g | 16384 LSB/g | 1g 的重力对应读数 16384 |
| ±4g | 8192 LSB/g | 量程大一倍，精度降一半 |
| ±8g | 4096 LSB/g | — |
| ±16g | 2048 LSB/g | 适合冲击、跌落检测 |
| ±250°/s | 131 LSB/(°/s) | 慢速姿态 |
| ±500°/s | 65.5 LSB/(°/s) | — |
| ±2000°/s | 16.4 LSB/(°/s) | 快速旋转 |

```c
void MPU6050_Init(void)
{
    MyI2C_Init();
    MPU6050_WriteReg(0x6B, 0x01);    // ① 解除睡眠（必须）
    MPU6050_WriteReg(0x19, 0x09);    // ② 采样率 100Hz
    MPU6050_WriteReg(0x1A, 0x06);    // ③ 低通滤波 5Hz
    MPU6050_WriteReg(0x1B, 0x00);    // ④ 陀螺 ±250°/s
    MPU6050_WriteReg(0x1C, 0x00);    // ⑤ 加速度 ±2g
}

void MPU6050_GetData(int16_t *ax, int16_t *ay, int16_t *az,
                     int16_t *gx, int16_t *gy, int16_t *gz)
{
    uint8_t buf[14];
    uint8_t i;

    MyI2C_Start();
    MyI2C_SendByte(0xD0);  MyI2C_ReceiveAck();
    MyI2C_SendByte(0x3B);  MyI2C_ReceiveAck();       // 从数据首地址开始
    MyI2C_Start();
    MyI2C_SendByte(0xD1);  MyI2C_ReceiveAck();

    for(i = 0; i < 14; i++){
        buf[i] = MyI2C_ReceiveByte();
        MyI2C_SendAck(i == 13);                      // 最后一个 NACK
    }
    MyI2C_Stop();

    *ax = (int16_t)((buf[0]  << 8) | buf[1]);        // 高字节在前
    *ay = (int16_t)((buf[2]  << 8) | buf[3]);
    *az = (int16_t)((buf[4]  << 8) | buf[5]);
    *gx = (int16_t)((buf[8]  << 8) | buf[9]);        // buf[6..7] 是温度
    *gy = (int16_t)((buf[10] << 8) | buf[11]);
    *gz = (int16_t)((buf[12] << 8) | buf[13]);
}
```

换算成物理量：**角度 = 原始值 / 16384（单位 g）**，**角速度 = 原始值 / 131（单位 °/s）**，**温度 = 36.53 + 原始值 / 340**。静止平放时，`az` 应该接近 16384（1g），`ax`、`ay` 接近 0——这是最快的自检方法。

## 五、硬件 I2C：把时序交给外设

软件 I2C 占两个普通 IO，每个字节都要 CPU 逐位翻转。硬件 I2C 把它交给外设，CPU 只发命令：

| 对比 | 软件 I2C | 硬件 I2C |
| --- | --- | --- |
| 占用引脚 | 任意两个 IO | 固定的 I2C 引脚（I2C1: PB6/PB7 或重映射 PB8/PB9） |
| CPU 占用 | 高（每位都要执行指令） | 低（写数据寄存器即可） |
| 速度 | 通常 50–100kHz | 可达 400kHz（快速模式） |
| 灵活性 | 时序可调，任何脚都行 | 受外设限制，遇从机时钟拉伸可能卡死 |
| 调试难度 | 直观，示波器一看就懂 | 卡在 `while` 等标志时很难判断 |

硬件 I2C 的关键调用顺序（F103 的标准库，缺一步就会卡住）：

1. `I2C_GenerateSTART(I2C1, ENABLE)` → 等 `I2C_EVENT_MASTER_MODE_SELECT`
2. `I2C_Send7bitAddress(I2C1, 0xD0, I2C_Direction_Transmitter)` → 等 `I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED`
3. `I2C_SendData(I2C1, reg)` → 等 `I2C_EVENT_MASTER_BYTE_TRANSMITTED`
4. 重复起始 + 读地址 → 等 `I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED`
5. 收数据前 `I2C_AcknowledgeConfig(I2C1, DISABLE)`（最后一个字节）
6. `I2C_GenerateSTOP`

:::warn 硬件 I2C 卡死的经典场景
现象：程序停在某个 `while(!I2C_CheckEvent(...))` 里出不来。
原因：从机在做时钟拉伸（SCL 拉低不放），或总线上有器件把 SDA 一直拉低（上一次通信被打断）。
救法：① 加超时计数，超时就 `I2C_GenerateSTOP` + 软复位 I2C（`I2C_DeInit`）；② 上电初始化时先发 9 个 SCL 脉冲，把卡住的从机「敲」出来。这也是很多工程宁可用软件 I2C 的原因——出问题时你看得见。
:::

## 六、坑：全 0、地址错、线太长

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 读 `WHO_AM_I` 返回 0x00 或 0xFF | 没应答：接线错、地址错、没供电 | 先读 0x75，应得 0x68；0xFF 说明 SDA 被拉高（从机没应答） |
| 通信正常但数据全 0 | MPU6050 还在睡眠模式 | 写 `PWR_MGMT_1 = 0x01` |
| 偶尔读出错值 | 杜邦线太长、没有上拉 | 线缩短到 10cm 内；SDA/SCL 各加 4.7kΩ 上拉到 3.3V |
| 加速度静止时 `az` 只有 1000 多 | 量程配成了 ±16g，却按 ±2g 换算 | 换算系数必须与 `ACCEL_CONFIG` 一致 |
| 读多字节时数据错位 | 最后一个字节没发 NACK，从机继续输出 | 最后一字节回 NACK，再 Stop |

## 七、从原始值到姿态：下一步是什么

拿到加速度和角速度只是起点。真正要「知道板子倾斜多少度」，还需要：

| 方法 | 做法 | 特点 |
| --- | --- | --- |
| 加速度算倾角 | `atan2(ay, az)` | 静止准、运动时被线性加速度干扰 |
| 角速度积分 | 对角速度累加 | 短期准、长期漂移 |
| 互补滤波 | 两者加权融合（如 0.98 / 0.02） | 工程最常用，几行代码就够 |
| 卡尔曼滤波 | 状态估计 | 更准，但要调参、算矩阵 |

课程只到「读出可靠数据」为止。要往姿态解算走，建议先把互补滤波写出来：它只有一行公式，效果却比单独用任何一种都好。

## 练习
Q| MPU6050 的 7 位地址是 0x68，代码里为什么写 0xD0 和 0xD1？
A| 因为 I2C 传输时第一个字节是「7 位地址 + 1 位读写标志」。0x68 << 1 = 0xD0（写），0xD0 | 1 = 0xD1（读）。
A| 0x68 是手册里的 7 位地址，0xD0/0xD1 是总线上的 8 位形式。两者不是两个器件，写错会得到 NACK（从机不应答），表现为读回 0xFF。
Q| 用软件 I2C 读 MPU6050，`WHO_AM_I`（0x75）能读回 0x68，但加速度三个值一直是 0。最可能的原因？
A| 芯片还在睡眠模式。MPU6050 上电默认 `PWR_MGMT_1 = 0x40`（SLEEP = 1），此时内部振荡器关闭、传感器不采样，数据寄存器保持 0。
A| 解决：初始化时先写 `PWR_MGMT_1 = 0x01`（解除睡眠并选陀螺 X 轴 PLL 作时钟），延时 50ms 再读。这个顺序不能颠倒——先读后唤醒，第一次读到的还是 0。
Q| 为什么 I2C 的 SDA 和 SCL 必须用开漏输出，而且必须外接上拉电阻？
A| 总线上挂着多个器件，任何一个都可能拉低。如果用推挽，一个器件输出高（主动接 3.3V）、另一个输出低（接 GND），两只管子直接对通，会烧引脚。
A| 开漏只能「拉低或松手」，高电平靠上拉电阻恢复，天然实现「线与」：谁拉低，线就是低。没有上拉电阻，开漏永远输出不了高电平，总线会一直保持低、通信完全不通。
Q| 硬件 I2C 程序卡在 `while(!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED));` 里不动，怎么排查和救活？
A| 先判断是「从机没应答」还是「总线被占住」：用示波器看 SCL 是否还在跳。SCL 不动 = 从机在拉伸时钟，或外设状态机卡住。
A| 救活三板斧：① 加超时计数，超时后 `I2C_GenerateSTOP` 并 `I2C_DeInit` 重初始化；② 初始化前手动发 9 个 SCL 脉冲，把拉低 SDA 的从机「敲」松；③ 换回软件 I2C——时序全在手里，出问题能立刻定位。产品里更稳的做法是软件 I2C + 超时保护。
