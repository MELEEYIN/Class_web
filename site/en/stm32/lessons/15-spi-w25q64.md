## 一、四根线，各管一件事

| 线 | 全称 | 方向 | 说明 |
| --- | --- | --- | --- |
| SCK | Serial Clock | 主机 → 从机 | 时钟，由主机产生 |
| MOSI | Master Out Slave In | 主机 → 从机 | 主机发、从机收 |
| MISO | Master In Slave Out | 从机 → 主机 | 从机发、主机收 |
| CS / NSS | Chip Select | 主机 → 从机 | **低电平有效**，拉低才通信 |

和 I2C 最大的区别：**SPI 没有地址，也没有应答**。选哪个器件全靠 CS 拉低；从机收没收到，主机不知道。所以 SPI 器件通常需要「读回 ID」或「读状态寄存器」来确认通信正常。

另一个区别是**全双工**：发一个字节的同时就收到一个字节。所以 SPI 的读写是同一个动作——`SwapByte(0xFF)` 既能发数据，也能收数据。

## 二、四种模式：CPOL 与 CPHA

| 模式 | CPOL（空闲电平） | CPHA（采样边沿） | 常见器件 |
| --- | --- | --- | --- |
| 0 | 0（低） | 第 1 个边沿（上升） | W25Q64、多数 Flash/传感器 |
| 1 | 0 | 第 2 个边沿（下降） | 部分 ADC |
| 2 | 1（高） | 第 1 个边沿（下降） | 少见 |
| 3 | 1 | 第 2 个边沿（上升） | 部分显示屏 |

模式不匹配的现象很典型：**读回来全是 0x00 或 0xFF，偶尔能读对几个字节**。因为采样点落在了数据变化的瞬间，采到的是「正在跳变」的模糊值。

标准库里的对应关系：`SPI_CPOL_Low` + `SPI_CPHA_1Edge` 就是模式 0。

## 三、W25Q64：8MB 的规矩

| 参数 | 数值 | 说明 |
| --- | --- | --- |
| 容量 | 64Mbit = 8MB | 型号里的 64 指 64Mbit |
| 页（page） | 256 字节 | **一次最多写 256 字节**，跨页会回卷 |
| 扇区（sector） | 4KB（16 页） | 擦除的最小单位 |
| 块（block） | 64KB | 也可按块擦 |
| 地址宽度 | 24 位（3 字节） | 0x000000 – 0x7FFFFF |
| 寿命 | 约 10 万次擦写 | 别在循环里反复擦同一扇区 |

W25Q64 只有几条指令，但每条都必须记住：

| 指令 | 码 | 作用 |
| --- | --- | --- |
| JEDEC ID | 0x9F | 读厂商 + 器件 ID，应返回 `EF 40 17` |
| Read Status | 0x05 | 读状态寄存器，bit0 = BUSY |
| Write Enable | 0x06 | **写/擦之前必须先发** |
| Read Data | 0x03 | 读任意长度 |
| Page Program | 0x02 | 写一页（≤256 字节） |
| Sector Erase | 0x20 | 擦 4KB |
| Block Erase | 0xD8 | 擦 64KB |
| Chip Erase | 0xC7 | 全片擦除（很慢，几秒） |

:::warn Flash 只能「1 变 0」
NOR Flash 的物理特性决定了：写入只能把 1 变成 0，想把 0 变回 1 必须擦除（擦除会把整片区域变成 0xFF）。
所以**每次写之前都要先擦**。忘了擦的典型现象是：第一次写成功，第二次写同一个地址读出来还是旧数据（因为旧数据里的 0 无法变回 1）。
:::

## 四、软件 SPI：先手动跑通时序

接线（W25Q64 模块，SPI1 默认脚）：

| W25Q64 | STM32 | 配置 |
| --- | --- | --- |
| CS | PA4 | **普通推挽输出**（软件控制） |
| SCK | PA5 | 推挽输出 |
| MISO | PA6 | 上拉输入 |
| MOSI | PA7 | 推挽输出 |
| VCC / GND | 3.3V / GND | — |

```c
#include "stm32f10x.h"
#include "Delay.h"

void MySPI_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* CS / SCK / MOSI：推挽输出 */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_4 | GPIO_Pin_5 | GPIO_Pin_7;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* MISO：上拉输入 */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_6;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_SetBits(GPIOA, GPIO_Pin_4);       // CS 默认拉高（不选中）
    GPIO_ResetBits(GPIOA, GPIO_Pin_5);     // 模式 0：SCK 空闲为低
}

void MySPI_Start(void)  { GPIO_ResetBits(GPIOA, GPIO_Pin_4); }
void MySPI_Stop(void)   { GPIO_SetBits(GPIOA, GPIO_Pin_4); }

/* 全双工交换一个字节：模式 0（SCK 低空闲，上升沿采样，高位先出） */
uint8_t MySPI_SwapByte(uint8_t byte)
{
    uint8_t i, recv = 0;

    for(i = 0; i < 8; i++){
        if(byte & 0x80) GPIO_SetBits(GPIOA, GPIO_Pin_7);
        else            GPIO_ResetBits(GPIOA, GPIO_Pin_7);
        byte <<= 1;

        GPIO_SetBits(GPIOA, GPIO_Pin_5);          // 上升沿：从机采样 MOSI
        Delay_us(1);
        recv <<= 1;
        if(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_6)) recv |= 0x01;   // 同时采 MISO
        GPIO_ResetBits(GPIOA, GPIO_Pin_5);        // 下降沿：数据可以变化
        Delay_us(1);
    }
    return recv;
}

/* 读 JEDEC ID，应得 EF 40 17 */
void W25Q64_ReadID(uint8_t *mid, uint16_t *did)
{
    MySPI_Start();
    MySPI_SwapByte(0x9F);
    *mid = MySPI_SwapByte(0xFF);
    *did = (MySPI_SwapByte(0xFF) << 8) | MySPI_SwapByte(0xFF);
    MySPI_Stop();
}
```

读 ID 是验证 SPI 通路的最快方法：`EF 40 17` 说明线接对了、模式对了、供电正常。**先过这一关，再写 Flash**——否则后面出错时分不清是时序问题还是芯片问题。

## 五、擦除、写入、读取：三步走

```c
void W25Q64_WriteEnable(void)
{
    MySPI_Start();
    MySPI_SwapByte(0x06);          // 写使能
    MySPI_Stop();
}

void W25Q64_WaitBusy(void)
{
    uint8_t status;
    MySPI_Start();
    MySPI_SwapByte(0x05);          // 读状态寄存器
    do{
        status = MySPI_SwapByte(0xFF);
    }while(status & 0x01);         // bit0 = BUSY
    MySPI_Stop();
}

void W25Q64_SectorErase(uint32_t addr)
{
    W25Q64_WriteEnable();
    MySPI_Start();
    MySPI_SwapByte(0x20);                            // 扇区擦除
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    MySPI_Stop();
    W25Q64_WaitBusy();                               // 擦除要等，别紧接着写
}

/* 写一页（≤256 字节，且不能跨页） */
void W25Q64_PageProgram(uint32_t addr, uint8_t *buf, uint16_t len)
{
    uint16_t i;
    if(len > 256) len = 256;

    W25Q64_WriteEnable();
    MySPI_Start();
    MySPI_SwapByte(0x02);                            // 页编程
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    for(i = 0; i < len; i++){
        MySPI_SwapByte(buf[i]);
    }
    MySPI_Stop();
    W25Q64_WaitBusy();
}

void W25Q64_ReadData(uint32_t addr, uint8_t *buf, uint32_t len)
{
    uint32_t i;
    MySPI_Start();
    MySPI_SwapByte(0x03);                            // 读数据
    MySPI_SwapByte(addr >> 16);
    MySPI_SwapByte(addr >> 8);
    MySPI_SwapByte(addr);
    for(i = 0; i < len; i++){
        buf[i] = MySPI_SwapByte(0xFF);               // 读的时候发什么无所谓
    }
    MySPI_Stop();
}
```

三个必须遵守的顺序：

1. **擦 → 写 → 读**，不能跳过擦除。
2. **写之前发 Write Enable（0x06）**，否则写入被忽略，读回来还是旧数据。
3. **每次写/擦之后等 BUSY 清零**，芯片在忙时只认读状态指令，其他指令一概不理。

## 六、硬件 SPI：把时序交给外设

软件 SPI 一字节要几十条指令，最高也就几百 kHz。硬件 SPI1 能跑到 36MHz（PCLK2/2）。配置要点：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `SPI_Direction` | `SPI_Direction_2Lines_FullDuplex` | 全双工 |
| `SPI_Mode` | `SPI_Mode_Master` | 主机 |
| `SPI_DataSize` | `SPI_DataSize_8b` | 8 位 |
| `SPI_CPOL` / `SPI_CPHA` | `Low` / `1Edge` | 模式 0 |
| `SPI_NSS` | `SPI_NSS_Soft` | **软件片选**（CS 用普通 IO） |
| `SPI_BaudRatePrescaler` | `SPI_BaudRatePrescaler_8` | 72/8 = 9MHz，先用慢的 |
| `SPI_FirstBit` | `SPI_FirstBit_MSB` | 高位先出 |

```c
void MySPI_HW_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    SPI_InitTypeDef SPI_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_SPI1, ENABLE);

    /* SCK / MOSI：复用推挽；MISO：上拉输入；CS：普通推挽（软件控制） */
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_5 | GPIO_Pin_7;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_6;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_4;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
    GPIO_SetBits(GPIOA, GPIO_Pin_4);

    SPI_InitStructure.SPI_Direction         = SPI_Direction_2Lines_FullDuplex;
    SPI_InitStructure.SPI_Mode              = SPI_Mode_Master;
    SPI_InitStructure.SPI_DataSize          = SPI_DataSize_8b;
    SPI_InitStructure.SPI_CPOL              = SPI_CPOL_Low;
    SPI_InitStructure.SPI_CPHA              = SPI_CPHA_1Edge;
    SPI_InitStructure.SPI_NSS               = SPI_NSS_Soft;
    SPI_InitStructure.SPI_BaudRatePrescaler = SPI_BaudRatePrescaler_8;
    SPI_InitStructure.SPI_FirstBit          = SPI_FirstBit_MSB;
    SPI_InitStructure.SPI_CRCPolynomial     = 7;
    SPI_Init(SPI1, &SPI_InitStructure);

    SPI_Cmd(SPI1, ENABLE);
}

uint8_t MySPI_HW_SwapByte(uint8_t byte)
{
    while(SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_TXE) == RESET);
    SPI_I2S_SendData(SPI1, byte);
    while(SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_RXNE) == RESET);
    return SPI_I2S_ReceiveData(SPI1);
}
```

**「软件片选 + 硬件 SPI」是最常用的组合**：因为 CS 的时序（拉低、发指令、拉高）和事务边界强相关，交给软件控制最灵活；而时钟和数据移位交给硬件，速度又快又准。

## 七、坑：读全 FF、写不进、跨页回卷

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 读 ID 全是 0xFF | MISO 没接、CS 没拉低、模式不对 | 先查线，再看 CPOL/CPHA |
| 读 ID 全是 0x00 | 供电不足或芯片没焊好 | 量 VCC 是否有 3.3V |
| 写入后读出还是旧数据 | 没发 Write Enable（0x06），或没先擦除 | 「写使能 + 擦除 + 等待」三步别省 |
| 写 300 字节只成功前 256 字节 | 超过一页，发生页内回卷（又从页首覆盖） | 按 256 字节分页写 |
| 擦除后立刻写失败 | 擦除是异步的，没等 BUSY 清零 | 每次擦/写后 `WaitBusy()` |
| 偶尔读到错数据 | 速度太快、线太长 | 分频改小（如 /16），线缩到 10cm 内 |

:::tip 页内回卷是什么
页大小为 256 字节，页内地址是 8 位。写第 257 个字节时，低 8 位地址回绕到 0，于是又写回页首，**把刚写的第一批数据覆盖了**。
现象：写 300 字节，最后读出来「后 44 字节覆盖了前 44 字节」。跨页写必须拆成两次 `PageProgram`。
:::

## 练习
Q| 读 W25Q64 的 JEDEC ID 读到 `EF 40 17`，这三位分别代表什么？读到 `FF FF FF` 说明什么？
A| `EF` = 厂商 ID（Winbond），`4017` = 器件型号，对应 W25Q64（64Mbit）。读对说明 SPI 四根线、模式、供电都正常。
A| `FF FF FF` 说明 MISO 一直是高（或 CS 没拉低）：可能是 MISO 没接、从机未被选中、或者从机根本没供电。这是「通信完全没建立」的典型值，而不是「读错了数据」。
Q| 为什么 Flash 写之前必须先擦除？不擦会怎样？
A| NOR Flash 的写入只能把位从 1 变成 0（电子注入），无法从 0 变回 1。擦除会把整片区域恢复成全 1（0xFF）。
A| 不擦直接写：如果目标位已经是 0，新数据要写 1 就写不进去，读出来仍是 0。现象是「第一次写成功，改值后再写无效」——因为旧数据的 0 位卡住了。擦除的最小单位是 4KB 扇区，不能只擦一个字节。
Q| 用软件 SPI 写 300 字节的数据，写完读回来发现第 0–43 字节和第 256–299 字节内容一样。为什么？
A| 发生了页内回卷。页大小 256 字节，页内地址只有 8 位，写到第 257 个字节时地址回绕到页首，把开头的数据覆盖了。
A| 修法：按 256 字节对齐拆包，每次 `PageProgram` 只写一页内的数据。写之前还要确认这笔地址已经擦除过，否则旧数据的 0 位仍然卡住。
Q| 硬件 SPI 用 `SPI_NSS_Soft`（软件片选），为什么 CS 引脚要配成普通推挽输出而不是复用推挽？
A| 因为 `SPI_NSS_Soft` 的意思是「NSS 由软件管理」，硬件不接管这个引脚。配成复用推挽的话，引脚由 SPI 外设控制，你在代码里拉低/拉高 CS 不会生效。
A| 配成普通推挽，代码里手动 `GPIO_ResetBits(CS)` 拉低选中、`SetBits` 拉高释放，事务边界完全由你控制。这也是为什么「软件片选 + 硬件 SPI」既快又灵活。
