# 校园主页 · Campus Home

一个**零构建**的校园导航主页：常用网站入口、课表导入与日程管理、全班共享的公共事务、校园地图与 C5 楼层平面图，
外加一个由主机发布、全站同步的**通知栏**，以及一个内嵌的**看番记录**页。
前端是纯 HTML / CSS / JavaScript 手写，没有打包步骤；后端只有一个很小的 Cloudflare Worker，
只做两件事——把主机发的通知同步给所有访客、给看番页中转 Bangumi 数据。push 到 GitHub，Cloudflare 自动发布。

> `main` 必须指向 `worker/index.js`。

> 站点里**没有任何示例课表或个人信息**。课表完全由使用者自己导入，
> 数据只存在各自浏览器的 localStorage 里，互不可见。这个页面可以直接给全班用。

### 顶部信息条（问候 + 三张小卡）

左边是问候语、日期、当前教学周和几个状态标签。右边三张小卡，从左到右：

- **⏱ 实时时间卡**：时:分:秒 每秒跳一次，下面跟日期、星期、当前教学周和本机时区名。
  时间和页面上所有日期都来自设备的**系统时间**（`new Date()`，本地时区），没有另外的服务器时间源，
  所以你的电脑/手机是什么时间，页面就是什么时间（`时钟卡` 悬停会显示具体时区名）。
- **⛅ 天气卡**：深圳坪山实时天气。上面一行是图标 + 温度 + 天气状况，下面 2×2 四个小格：
  体感 / 湿度 / 今日温度区间 / 降水概率（没有降水数据时第三格换成风速），底部一行是地点与「缓存」标记。
- **🔔 通知栏**：内容由**服务端（主机）发布**，所有打开本站的人都能看到同一条。
  显示级别标签、标题、正文（最多 3 行）、发布者与时间；点「查看全部通知」打开完整列表。
  页面每 60 秒自动对一次、切回标签页时立刻对一次，主机发新通知后不用刷新就能看到。

### 手机版界面（自动切换）

**默认就是「自动」**：进入页面时按屏幕宽度 + 是否触摸屏判断，手机上一律启用手机版，
而且判断发生在**首次绘制之前**（`js/boot.js` 里同步执行），所以不会先闪一下桌面版。

手机版和「窄屏也能看」不是一回事，它换了一套更适合手指的布局：

| | 手机版做了什么 |
|---|---|
| 导航 | 顶部收成两行（品牌 + 图标一行、搜索框一行），搜索框在手机上直接可见 |
| 信息流 | **日程提到最前**，然后才是 8 个入口、待办、倒数日、工具 |
| 入口卡片 | 收成紧凑列表（图标 + 名称 + 域名），滚动距离少一半 |
| 底部导航栏 | 固定一条：**首页 / 日程 / 待办 / 地图 / 更多**；待办还有未完成数量的角标 |
| 弹窗 | 全部改成全屏，头部和底部按钮固定在两端，只有内容区滚动 |
| 点击区 | 按钮 42–44px、输入框 44px、周次方格 36px，都按手指尺寸放大 |
| 课表/月历 | 课表列宽收窄、靠横向滚动看全天；月历每天最多显示 2 条 |
| 其它 | 适配刘海屏安全区（`env(safe-area-inset-*)`）、去掉触屏上没意义的悬停抬升、横屏时底部栏自动变扁 |

**想手动控制**：`数据与设置` → **显示模式** → `自动 / 手机版 / 电脑版`。
抽屉里也有一键切换（「切换到电脑版 / 手机版」）。

- 选 **自动**：跟随屏幕，转屏或改窗口大小都会重新判断
- 强行选 **手机版**：在电脑上也能预览手机版；此时内容会收成 600px 居中显示，看起来像手机预览而不是被拉宽
- 强行选 **电脑版**：手机上也能用桌面布局（窄屏的兜底媒体查询仍然生效，不会撑破）

判断规则（`window.CW_RESOLVE_VIEW`，`js/boot.js` 里唯一定义）：

| 条件 | 结果 |
|---|---|
| 已手动锁定 | 用锁定的 |
| 宽度 ≤ 720px | 手机版 |
| 触摸屏 且 宽度 ≤ 900px | 手机版（手机横屏就是这种情况） |
| 其它 | 电脑版 |

### 装到桌面（PWA）

首页「常用入口」里的 **装到桌面** 卡片会把本站按 PWA 装到桌面 / 主屏幕：独立窗口打开、断网也能看课表（通知、投票仍需联网）。

| 环境 | 会看到什么 |
|---|---|
| 安卓 Chrome / Edge、电脑 Chrome / Edge | 卡片小字变成「点开可一键安装」，点开弹窗后按 **立即安装**，直接调起系统安装 |
| 微信 / QQ / 抖音等内置浏览器 | 装不了（这类浏览器不提供安装能力）。卡片提示「内置浏览器装不了」，按提示点右上角「…」→「在浏览器打开」，再用 Chrome 装 |
| iPhone / iPad | 没有安装事件，只能 Safari →「分享」→「添加到主屏幕」 |
| 已经装过 | 入口自动隐藏；删掉后 Chrome 可能要过一阵才重新给出安装入口，手动「添加到主屏幕」效果一样 |

几个要点：

- **安装只在 https 的正式域名下可用**（`https://leeyin.xyz`）。本地预览（`http://127.0.0.1:8931`、`file://`）浏览器不给安装入口，这是浏览器的安全要求，不是站点的问题；`localhost` / `127.0.0.1` 是例外，可以拿来试界面。
- 判断逻辑都在 `site/js/pwa.js`；`beforeinstallprompt` 可能早于 `DOMContentLoaded` 触发，所以 `site/js/boot.js` 会先接住一份（`window.CW_INSTALL_PROMPT`），两处兜底 —— 漏掉这个事件，入口就永远不会出现。
- 手机版会隐藏卡片底部的 `.lc-foot`，所以安装状态写在那行**小字**上（`#installCardHost`），点卡片打开的是 `#modal-install` 弹窗，真正的安装按钮在弹窗里。
- 改过 `css` / `js` 记得把 `site/sw.js` 里的 `VERSION` +1，否则已安装的用户会一直跑旧缓存。

## 二、全班共用的两块内容

这个网站有两种「一个人改了、全班都能看到」的内容，都跟个人的课表数据完全分开：

| | 通知栏 | 公共事务 |
|---|---|---|
| 长什么样 | 顶部右侧那张小卡 / 点开的通知弹窗 | 日程弹窗 → **公共事务** 标签页 |
| 内容是什么 | 主机发的通知（调课、提醒、临时安排） | 全班都要知道的事务（班会、考试、截止日） |
| 谁维护 | 你自己，在 `/admin.html` 里发布 | 你自己，编辑 `site/data/public-events.json` 后 push |
| 怎么到访客那里 | Worker 接口 `/api/notice`，每 60 秒自动同步，**不用刷新** | 页面打开时读 `data/public-events.json` |
| 访客能改吗 | 不能，只能看 | 能「复制到我的日程」，但不能改原始清单 |
| 存在哪里 | Cloudflare KV（没绑 KV 时退回 `site/data/hosts.json`） | 仓库里的那个 JSON 文件 |

**公共事务为什么不做成「大家都能在线发」？**
因为那意味着要账号、要登录、要防乱发，而且服务器上会开始堆大家的数据。
现在这样做的好处是：全班看到的一定是同一份、有人核对过的内容，谁也改不了别人的日程，
你自己的课表也永远不会离开你的浏览器。

### 公共事务的字段（`site/data/public-events.json`）

```jsonc
{
  "version": 1,
  "source": "public-events.json",
  "updatedAt": "2026-09-01T00:00:00.000Z",
  "items": [
    { "id": "p1", "title": "开学班会", "kind": "date", "date": "2026-09-14",
      "start": "15:00", "end": "16:00", "location": "C-5-101",
      "note": "带学生证", "owner": "班长" },

    { "id": "p2", "title": "英语四级报名截止", "kind": "date", "date": "2026-09-20",
      "location": "教务系统", "owner": "学委" },

    { "id": "p3", "title": "晚自习", "kind": "weekly", "day": 7,
      "start": "19:00", "end": "21:00", "weeksText": "1-16",
      "location": "C-5-303", "owner": "班长" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 随便取一个不重复的字符串。**它的作用是记住「这个人加过没有」**，改内容时别改 id |
| `title` | 标题，必填 |
| `kind` | `date` = 某一天的事；`weekly` = 每周固定的事 |
| `date` | `kind=date` 时必填，格式 `2026-09-14` |
| `day` | `kind=weekly` 时必填，`1`=周一 … `7`=周日 |
| `start` / `end` | 格式 `09:00`；留空表示全天 |
| `weeksText` | 只给 `weekly` 用，写法跟课表一个样：`1-16`、`1-16周(双)`、`单周`；留空 = 整学期 |
| `repeat` | 只有 `date` 用得上：`none` / `daily` / `weekly` / `monthly` |
| `location` / `note` / `owner` | 地点 / 备注 / 发布者署名 |

> 访客点「添加」时，会把这条复制成**他自己的一个普通事务**：周事务会自动变成「每周重复 + 到学期末结束」，
> 之后他可以随便改、随便删，都不影响清单里的原始内容。点「重新读取」可以立刻拉一次最新清单。

## 三、通知栏与主机后台（`/admin.html`）

### 主机怎么发通知

1. 打开 `你的网址/admin.html`（首页「实用工具」里也有「通知后台」入口）
2. **第一次**会让你设一个管理密码（至少 5 位，会提示你输两遍）
3. 之后每次输入这个密码即可进入
4. 填标题、正文，选重要程度（普通 / 好消息 / 要注意 / 很紧急），勾上「置顶显示在首页通知栏」，点 **发布到全站**
5. 访客页面最迟 1 分钟内自动出现这条通知；不用刷新，也不用重新部署

页面上还能：编辑已发布的、置顶/取消置顶（同一时间只有一条置顶）、删除某一条、清空全部。

### 管理密码是怎么保护的

| 问题 | 答案 |
|---|---|
| 服务器存明文密码吗 | **不存**。KV 里只有 SHA-256 哈希（`cw:auth`），比对用的是定长比较 |
| 密码会出现在网页里吗 | 不会。你输入后通过请求头 `x-cw-key` 传给 Worker，只用于当次校验 |
| 会被暴力破解吗 | 同一个 IP 连续错 8 次锁 15 分钟 |
| 管理页会被搜索引擎收录吗 | 不会，`/admin.html` 带了 `X-Robots-Tag: noindex, nofollow` |
| 能不能把密码固定死 | 能：`npx.cmd wrangler@latest secret put ADMIN_HASH`（填你自己的哈希），这样就没人能通过网页改它了 |

> 「在这台设备上记住密码」是把密码写进你浏览器的 localStorage，只为省一次输入。
> 公用电脑上**不要勾**，用完点右上角「退出」。

### 不绑 KV 会怎样

通知栏会退化成**只读**：内容来自 `site/data/hosts.json`。
这时候想改通知，就在管理页点 **导出 hosts.json**，把文件覆盖到 `site/data/hosts.json`，再 `git push`，
等 Cloudflare 部署完成后全站生效（大约 1 分钟）。功能一样，只是慢一点、要动一次仓库。

## 四、看番记录（`/anime.html`）

首页「实用工具」里的**看番记录**卡片（或键盘按 `A`）会打开一个弹窗，里面嵌的就是 `site/anime.html`。
它是一个独立的单页应用：搜索番剧、记录进度、打分、排序看榜，界面是自带的暗紫色主题。

| 项目 | 说明 |
|---|---|
| 打开方式 | 首页工具卡 / 抽屉里的「看番记录」/ 快捷键 `A` / 直接访问 `你的网址/anime.html` |
| 记录存在哪 | 那台设备浏览器的 localStorage（键名 `anime_tracker_*`，跟首页的 `cw.*` 互不干扰） |
| 内嵌方式 | 首页弹窗里放了一个 `iframe`，第一次点开才加载；关掉再打开时里面的状态还在 |
| 想整屏用 | 弹窗右上角有「新标签页」按钮 |

### 数据源：为什么 Bangumi 要中转一下

官方 `api.bgm.tv` 有两个坑，直连基本不可用：

1. 老的 `search/subject/` 接口已经废弃，经常直接不响应；
2. 它**不返回 CORS 头**，浏览器里的 `fetch` 一定会被同源策略拦下来，而且国内网络普遍连不上 `api.bgm.tv`。

所以这个页面按顺序试两个地址（`site/anime.html` 里的 `bangumiFetch()`）：

1. **本站 Worker 中转** `/api/bangumi/search/subject/...` —— 由 Cloudflare 的节点去取数据，
   绑了 KV 还会缓存 7 天，最稳也最快；
2. **`bgmapi.anibt.net`** —— 一个能直连、带 CORS 的公共中转站，作为兜底（Worker 挂了也能用）。

搜不到时另外两个源（AniList / Jikan）会顶上；三个都失败时，下拉框会**把每个源失败的原因写出来**，
方便区分是「没这部番」还是「网络连不上」。

> 封面图统一会被改写成 `https://bgmimg.anibt.net/...`：上游给的常是 http，
> 在 https 页面里会被浏览器当成混合内容拦掉，图片就全白了。

`/api/bangumi/*` 这个中转只允许 `/search/subject/`、`/subject/`、`/v0/subjects` 开头的路径，
单次响应超过 512KB 直接拒绝，免得被人拿去当通用代理刷流量。

## 六、怎么导入课表（四种方式）

### 方式 1：上传教务系统导出的文件（最稳，推荐）

1. 进教务系统 → **信息查询 → 学生个人课表**
2. 导出 / 打印成 `.xls`（教务系统的默认导出格式）
3. 回到本页，点左栏日程卡片上的 **`导入`** → **上传文件**，把文件拖进去
4. 核对预览表格，点 **确认导入**

支持 `.xls`、`.xlsx`、`.csv`、`.tsv`、`.ics`、`.json`。
**文件只在你的浏览器里解析，不会被上传到任何服务器**（课表数据没有任何后端接收）。

> `.xls` 解析器是手写的（`js/xls.js`），实现了 OLE2 复合文档 + BIFF8 记录 + SST/CONTINUE 跨块字符串，
> 专门针对国内教务系统的导出格式调过。不依赖 SheetJS 之类的第三方库，所以不用担心 CDN 被墙。
>
> **很多学校的「导出 / 打印」其实是把一个 HTML 表格直接存成 `.xls`**（Excel 打得开，学校就这么用了）。
> 这种文件不是真正的 xls，按二进制解析必然报「不是有效的 .xls 文件」。现在会自动认出这类文件、
> 转去走 HTML 解析，所以这两种 `.xls` 都能导进来。

#### 导入没反应？先看这几条

| 现象 | 原因 / 怎么办 |
|---|---|
| 提示「这次没有新增内容：文件里的排课和现有课表重复」 | **说明导入其实是成功的**，只是这些课之前已经导过一遍。看左栏「门课程 / 周均节次」就知道数据在不在 |
| 提示「不是有效的 .xls 文件」 | 文件可能没下完，或它根本不是表格。重新导出一次，或者在课表页面 `Ctrl+A`、`Ctrl+C` 直接粘贴到「复制粘贴」那一栏 |
| 提示「表格读出来了，但里面没有能认成课程或事务的行」 | 这份表格排版比较特殊。把课表页面整页复制粘贴过来（保留表格结构）识别率最高 |
| 什么都没弹出 | 按 F12 打开浏览器控制台，看有没有红色报错 |
| 导入成功但刷新后没了 | 检查是不是无痕窗口，或者换了浏览器 / 换了域名打开——数据是按「域名 + 浏览器」分开存的 |

> 失败提示现在会**留在导入弹窗里**（不再只是一闪而过的提示条），并且写清楚是哪个文件、
> 什么原因、下一步可以怎么做。

### 方式 2：复制粘贴

在课表页面按 `Ctrl+A`、`Ctrl+C`，回到本页点 **`导入` → `复制粘贴`**，按 `Ctrl+V`。
粘贴板里带表格结构时识别率最高；纯文本、JSON 也认。

### 方式 3：书签自动抓取（最省事）

教务系统不允许别的网站跨域读它的页面（浏览器安全策略），所以「自动抓取」用的是**书签小工具**：

1. 本页点 **`导入` → `自动抓取（书签）`**
2. 把那个蓝色的「抓取本校课表」按钮**拖到浏览器书签栏**
   （手机上不好拖的话，点「复制书签代码」，新建一个书签把网址整段替换掉）
3. 打开教务系统的课表页面，**等课表显示出来**
4. 点一下这个书签 —— 它会读到你自己登录后的课表，自动跳回本页并填好导入预览

书签只在你的浏览器里跑，不联网、不上传。抓到的内容通过网址片段传回来，随后会自动从地址栏清掉。
内容特别大时会自动改成「复制到剪贴板」，然后提示你改用粘贴方式。

### 方式 4：记住教务系统账号，一键自动登录 + 抓课表（最省事）

前三种都要你先登录、再手动点一次。这一种是**把「登录」也省掉**：

1. 本页点 **`导入` → `教务系统账号`**
2. 填上学号（想连密码一起记住就填密码，不想记就留空），点 **`保存到本机`**
3. 把那个蓝色的「**一键登录教务并抓课表**」按钮**拖到书签栏**
4. 以后想更新课表，随便在哪个页面点一下这个书签就行

点下去之后，那个书签会自己完成这一套：打开教务系统 → 填好账号密码 → 提交登录 →
找到「学生个人课表」→ 读走课表 → 跳回本页把导入预览填好。

**关于密码，先把话说清楚：**

| 问题 | 答案 |
|---|---|
| 密码存在哪 | 只在你**这台设备的浏览器**里，键名 `cw.jwAccount`（`localStorage`） |
| 会上传到服务器吗 | **不会**。本站后端只有通知接口，没有接收账号密码的接口 |
| 那它怎么登录的 | 书签脚本在**教务系统自己的页面**上运行，用你本机存的账号密码填那个登录表单；跨域限制让别的网站不能替你登录，但拦不住「在它自己页面上跑的脚本」 |
| 有风险吗 | 有。浏览器里的密码是**明文**的，同一台电脑上能打开这个浏览器的人、或者恶意扩展，都可能读到。**公用电脑、机房电脑上不要存** |
| 不想存密码怎么办 | 密码留空：书签会在教务系统页面上弹框让你当场输一次，不保存任何密码 |
| 教务系统有验证码怎么办 | 脚本会把账号密码填好然后停下来，你手动补验证码、点登录；**之后课表还是自动抓回来的** |
| 怎么撤销 | 回到那一页点 **`忘掉账号与密码`**，本机记录立刻清掉；顺手把书签也删掉 |

> 抓取逻辑只有一份，和「方式 3」共用：找到页面上「星期…」出现次数最多的那张表，
> 或者最大的那张表，序列化后经网址片段带回本页解析。学校改版后如果抓不到，
> 退回「方式 1 / 方式 2」即可，那两条路不依赖任何页面结构。

### 导入事务（不是课程）

- 在日程浮窗的月历上**双击某一天**，直接新建事务
- 或 **`修改` → `事务` → `新增事务`**
- 也支持粘贴 `.ics`，或者粘贴一段「标题/日期/时间/地点」的表格

### 「不是每周都上」的课怎么写

很多课只在单周、双周或某几周上，本页都认。**周次**这一栏支持：

| 写法 | 含义 |
|---|---|
| `1-16` | 第 1 到 16 周，每周都上 |
| `2-3,5-6,9-18` | 第 2、3、5、6、9…18 周（注意：CSV 里这种带逗号的要用双引号包起来） |
| `1-16周(单)`、`1-16单周`、`单周` | 第 1-16 周里的**奇数周** |
| `1-16周(双)`、`双周` | 第 1-16 周里的**偶数周** |
| `13` | 只有第 13 周 |
| 留空 | 整学期每周都上 |

**改周次最省事的办法**：打开 `修改 → 课程`，点某门课，周次那里有一排 **1…18 的方格**，
点一下就切换那一周。上面输入框会同步显示等价的文字写法。

> 导入预览里如果出现「**有 N 门课没读到上课周次，将按整学期每周都上处理**」的提醒，
> 就说明这几门课的周次没被识别出来。一般是因为学校那边的写法比较特殊，
> 按上面点方格手动改一下即可。

## 七、学期第几周是怎么算的 —— 第一次用记得核对

课表里的「1-16 周」是个**相对**概念，本页需要知道**第 1 周的周一**是哪天，才能把课程铺到具体日期上。

- 默认值是「今年 9 月 1 日所在周的周一」，**这个默认值不保证对**。
  （深圳技术大学 2026-2027 学年第一学期是 **8 月 31 日开始上课**，[校历通知](https://jw.sztu.edu.cn/info/1005/3336.htm)。）

**对不上就在两处改：**

1. **`修改` → `学期与节次` → 「第 1 周周一」** 直接选日期；
2. 或者用下面的**快捷校准**：看一眼教务系统上显示的当前周次（比如「第 3 周」），
   填进「按今天算，今天是第 N 周」，点 **`反推开学日期`**，本页会把第 1 周周一算好。

导入预览里也能直接改这个日期，导入时一起生效。

## 八、数据存在哪里（很重要）

**你的课表数据没有后端，全部在你自己浏览器里：**

| 内容 | 存放位置 |
|---|---|
| 课表、事务、待办、倒数日、设置 | `localStorage`，键名前缀 `cw.` |
| 公共事务清单 + 「我加过哪些」 | `/data/public-events.json`（清单本身在服务器上）+ `localStorage` 的 `cw.public`（只记标记） |
| 教务系统学号/密码（如果选择了保存） | `localStorage` 的 `cw.jwAccount`，**只在本机，明文，不上传** |
| 自定义背景图片 | `IndexedDB`，数据库 `cw-bg` |
| 主题选择 | `localStorage` 的 `cw.theme` |
| 看番记录（追番、进度、评分） | `localStorage`，键名前缀 `anime_tracker_`（看番页自己的命名空间） |
| 通知栏内容 | Cloudflare KV（服务端），或退回 `site/data/hosts.json`（静态文件） |
| 管理密码 | 只存 SHA-256 哈希，在 Cloudflare KV 或 Worker secret 里 |

**这意味着：**

- ✅ 换浏览器、换电脑、清理浏览器缓存中的「图片和文件」**不会**丢数据
- ❌ 但「清除 Cookie 及网站数据 / 清除站点数据」**会全部丢掉**（包括记住的教务账号）
- ❌ 手机浏览器、电脑浏览器、无痕窗口之间**不共享**数据
- ⚠️ 「导出全部数据」的备份里**故意不含教务系统密码**，只有课表和标记

**所以请定期备份**：`数据与设置`（导航栏那个数据库图标）→ **`导出全部数据`**，
拿到一个 JSON 文件。换设备时点 **`从备份恢复`** 选这个文件即可。

备份文件里包含课表、事务、待办、倒数日与全部设置，可以放心地当存档。

### 这个页面可以直接给全班人用

**每个人的课表互不可见：**

- 每个人打开同一个网址，看到的界面一样，但**各自的课表互相看不到**
- 谁导入了什么课、加了什么待办，只写在自己浏览器的 `localStorage` 里
- 服务器（Cloudflare）只发静态文件 + 一个通知接口，**从头到尾收不到任何人的课表数据**
- 所以不需要账号、你的课表也不会「一个人改了全班都变」

**全班共享的只有两块，而且是单向的：**

- **通知栏**：主机发布 → 所有人只读。访客这边没有任何写接口
- **公共事务**：一份仓库里的清单 → 访客只能「复制到我自己的日程」，改不了清单本身

代价就是上面说的：**数据不跟着人走**。换手机、换浏览器、清站点数据都要重新导入一次，
所以每个人自己用「导出全部数据」留一份备份比较稳。

> 站点本身**不含任何人的真实课表**。仓库里没有示例数据文件，
> 页面首次打开会提示「还没有课表，点导入」。

## 九、部署：GitHub + Cloudflare Workers

**先说结论：这个仓库走的是 Workers，不是 Pages。**
新版 Cloudflare 控制台把 Pages 并入了 Workers & Pages，你的 `Create application` 给出的是
`Create an app → Set up your application` 这个 **Workers** 流程。

这没关系——**Workers 静态资源托管一个纯静态网站，一样免费、一样有 HTTPS、一样 push 自动部署**，
而且是 Cloudflare 现在主推的方向。代价只有一个：**必须有 `wrangler.jsonc`**，这个文件已经建好了。

### 当前状态

| 项目 | 值 |
|---|---|
| 远程仓库 | <https://github.com/MELEEYIN/Class_web> |
| 分支 | `main` |
| 线上地址 | Cloudflare 后台 → Workers & Pages → `class-web` → Deployments 里看（`*.workers.dev` 域名国内被墙，见下） |
| 计划域名 | `leeyin.xyz` —— 接入步骤见 [`DOMAIN_SETUP.md`](./DOMAIN_SETUP.md) |

> `workers.dev` 的子域名默认由 Cloudflare 按账号名自动生成，会带上一串数字标识。
> 如果不想让它出现，可以在 Cloudflare 后台把 **Workers 的账户子域** 改成别的名字
> （Settings → Account → Workers Subdomain，每个账号只能改一次）。

### 每次改动后

```powershell
cd "D:\DeepSeek Harness\Class_web"
git add .
git commit -m "更新内容"
git push
```

Cloudflare 检测到推送会自动重新部署，无需手动操作。

### 🔔 一次性配置：给通知栏绑上 KV（强烈建议，5 分钟）

不绑也能用（通知退化成只读的 `site/data/hosts.json`），但绑了之后才能在 `/admin.html` 里随时发布。

**做法 A：命令行（推荐，一次搞定）**

```powershell
cd "D:\DeepSeek Harness\Class_web"

# 1. 登录 Cloudflare（会弹浏览器，授权一次即可）
npx.cmd --yes wrangler@latest login

# 2. 建一个 KV 命名空间
npx.cmd --yes wrangler@latest kv namespace create NOTIFY
#    输出里会有一行：id = "abcdef0123456789..."

# 3. 把那个 id 填进 wrangler.jsonc 的 kv_namespaces（文件里已经写好注释模板，去掉注释即可）

# 4. 本地确认配置没问题（不会真的部署）
npx.cmd --yes wrangler@latest deploy --dry-run
```

改完 `wrangler.jsonc` 之后 push 一次，Cloudflare 部署时会自动把 KV 绑上去。

**做法 B：只在 Cloudflare 后台点**

`Workers & Pages` → `class-web` → `Settings` → **Bindings** → `Add` → **KV Namespace**，
Variable name 填 **`NOTIFY`**，选一个命名空间（没有就点 `Create` 建一个），保存后重新部署一次。

## 十二、关于域名与访问

**换域名的成本极低，因为这个项目没有和任何域名绑定。**
`site/` 里所有资源都用相对路径引用，没有一个地方写死了域名，换域名**不需要改任何代码**。

Cloudflare 官方机制（[Custom Domains 文档](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)）：

| 事实 | 说明 |
|---|---|
| 一个 Worker 可绑**多个**自定义域名 | 旧新域名能并存，过渡期不用担心断档 |
| 加/删自定义域名不用改代码 | Cloudflare 自动创建 DNS 记录、自动签发 HTTPS 证书 |
| 用 **Custom Domain**，不要手动加 A 记录 | 手动加会缺证书，反而更麻烦 |
| 证书**不会**随域名一起删除 | 删域名后要手动去 `SSL/TLS → Edge Certificates` 清掉 |

`leeyin.xyz` 的接入步骤、当前卡在哪一步，全部写在 [`DOMAIN_SETUP.md`](./DOMAIN_SETUP.md)，
配好之后跑一下 `check-domain.ps1` 就知道通没通。

> ⚠️ **`workers.dev` 在国内被墙**（DNS 污染 + SNI 阻断，实测见 `DOMAIN_SETUP.md`）。
> 这不是部署失败——Cloudflare 后台能看到站点健康运行，只是国内直连打不开。
> 挂上自定义域名后通常就好了，但也**不保证**，需要实测。

## 十三、已知限制

- **个人数据不能跨设备同步**：课表、待办都在各自浏览器里，换设备要走「导出 / 恢复」。
  能跨设备的只有通知栏和公共事务这两块共享内容。
- **通知栏依赖 Worker 与 KV**：没绑 KV 时只能用 `site/data/hosts.json`，改一次要 push 一次。
- **通知最多保留 40 条**，KV 免费额度每天 1000 次写（正常发通知远远用不到）。
- **自动抓取依赖教务系统的页面结构**。学校改版后书签脚本可能要跟着改
  （`site/js/import.js` 里的 `buildBookmarklet()` 和 `buildLoginBookmarklet()`）。
  抓不到就退回「上传文件」或「复制粘贴」，这两条路不依赖页面结构。
- **保存教务系统密码有风险**：它是明文存在你自己的浏览器里的。公用电脑上不要存。
- **看番记录依赖第三方数据源**：Bangumi 官方没有 CORS、国内也常连不上，所以页面走
  「本站 Worker 中转 → 公共中转站 `bgmapi.anibt.net`」这两条路。**那个中转站不是官方的**，
  哪天它挂了就看番页搜不到番剧（已导入的记录不受影响，因为存在本地）。
  想更稳就自己搭一个中转，然后把 `site/anime.html` 里的 `BGM_UPSTREAM` 换掉。
- **通知栏 / 看番中转都用 Cloudflare KV**（绑了的话）：KV 免费额度每天 1000 次写。
  看番的条目缓存 7 天，正常使用远远用不到上限。
- **天气需要联网**访问 `api.open-meteo.com`。取不到会显示「天气获取失败」和重试按钮，不影响其它功能。
  （通知栏读的是本站自己的 `/api/notice`，不受影响。）
- **桌面通知需要页面保持打开**（浏览器标签页在后台也算）。想要真正的手机推送，用导出的 `.ics` 交给系统日历。
- **`.xlsx` 解析依赖浏览器的 `DecompressionStream`**（Chrome 80+ / Edge / Safari 16.4+ / Firefox 113+）。
  浏览器太旧会提示改用 `.xls` 或 `.csv`——而教务系统导出的正是 `.xls`。
- **地图图片体积**：校园总览压缩后约 840 KB，5 张楼层图各约 70–85 KB。首次打开地图时按需加载。

**改动这一页时别踩的五个坑：**

1. **图表全是手绘内联 SVG，不要引 Chart.js。** `/acm/*` 的 CSP 是 `connect-src 'self'`，
   `script-src` 也不含 CDN，外链脚本会被直接拦掉。那张增长曲线图是按对数坐标算好采样点、
   **直接写死在 HTML 里**的（纵轴 10⁰–10¹²，横轴 10⁰–10⁶）。
2. **SVG 的配色一律走 CSS 类，不要写 `fill="var(--x)"`。** `var()` 在 SVG 展示属性里不生效，
   必须写成 `.k-log{stroke:rgb(var(--ok-rgb))}` 这种规则，才能自动跟随深浅色切换。
3. **代码块用 `<script type="text/x-cpp">` 存原文**（与手册同一套机制），由页面脚本填进 `<pre><code>`。
   注意 `<script>` 内是 **raw text**：里面的 `<` `>` `&` 要写**原样**，写成 `&lt;` / `&amp;`
   会原样显示出来。对照一下「1.3 数据规模对照表」里那段——它在 `<p>` 里，就必须用实体。
4. **SVG 是 XML，文本节点里的 `<` `>` `&` 必须转义。** 图表里凡是出现 `INT_MAX < 2³¹` 这种对比，
   写成裸 `<` 会让**整张图解析失败、浏览器直接不渲染**（其他图不受影响，所以不容易发现）。
   `<desc>` / `<title>` 里同理。改完用「按 XML 解析每张 `<svg>`」的方法自检一遍最省事。
5. 改完记得把 `site/sw.js` 的 `VERSION` 加一。
